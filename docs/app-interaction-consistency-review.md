# 전 화면 조작 일관성 및 커스텀 오버레이 사용성 개선 명세

- 작성일: 2026-10-17
- 상태: 기획 확정. 공통 조작 순서와 현재 적용 프리셋 자동 저장을 사용자 승인받았다.
- 목적: 기존 기능을 보존하면서 같은 조작을 같은 이름과 순서로 찾고, 적용/저장 상태를 오해하지 않게 한다.
- 범위: 통합 후 기본 기능 화면 13개와 첫 사용 안내/자동설정/투어/영역 확인/문의 등 보조 흐름.
- 조사 기준: 사용자 첨부 통합 화면과 원격 main `3d9e2d9773ff914e908a3a8c00bcebf7cc4d3ccc`의 소스.
  해당 시점에는 도르카/투아림 화면이 분리되어 있었다. 이후 작업본 전체나 Windows 실게임을 검증한 결과가 아니다.
- 관련 명세: [탐색 구조](navigation-structure-spec.md), [도르카·투아림 통합](dorcha-tuarim-integration-spec.md).
  이 문서는 공통 조작과 커스텀 저장 정책에 우선 적용하며, 개별 기능의 판독·알림·권한 정책은 보존한다.

## 1. 목적과 적용 원칙

- 같은 의미의 조작은 화면이 바뀌어도 같은 이름과 순서에서 찾을 수 있어야 한다.
- 도르카·투아림의 승인한 바 모양과 독립 사용 선택은 유지하고 설정 순서를 정리한다.
- 버프/디버프, 자원 표시, 메모, 계산기, 파티 모집을 같은 양식으로 만들지는 않는다.
  같은 의미의 조작만 통일하고 업무 흐름이 다른 기능은 차이를 유지한다.
- 커스텀은 현재 적용 중인 프리셋을 편집 대상으로 삼고 변경을 자동 저장한다.
- 사용자가 목록에서 선택만 한 대상, 현재 적용 중인 프리셋, 시작 시 자동 불러오기 대상을 구분한다.

## 2. 제외 범위와 유지할 동작

- 화면을 읽는 범위를 유지하며 게임 입력이나 메모리 조작은 추가하지 않는다.
- 기존 판독 기준, 알림 조건, 전면 표시, 클릭 통과 및 전체 일시정지 정책을 변경하지 않는다.
- 새로운 첫 사용 설정 마법사, 사이드바, 3단 탭 및 테마 교체는 추가하지 않는다.
- 계정 접근 조건, 일반/베타 기능의 경계 및 저장된 설정을 유지한다.

## 3. 공통 조작 기준

### 3.1 화면 계열별 구조

판독 기반 오버레이/알림 화면은 다음 순서를 기준으로 한다.

1. 기능 제목과 사용할 동작 선택.
2. 판독 영역 등록 및 등록 상태.
3. 원본 캡처와 현재 판독값 확인. 확인할 필요가 있는 기능에만 제공.
4. 표시 모양과 위치/크기/잠금 조절. 표시 기능에만 제공.
5. 알림 조건과 소리. 알림 기능에만 제공.
6. 진단/수집/호환성 등의 고급 조작.

- 단계별 설정 마법사를 새로 만들라는 뜻이 아니다. 기존 한 화면에서 관련 항목을 같은 순서로 찾게 한다.
- 버프/디버프는 이 순서를 이유로 좌우 목록/선택 항목 설정을 위아래로 쌓지 않는다.
  영역과 공통 배치는 상단, 개별 항목 설정은 오른쪽이라는 기존 편집 흐름을 유지한다.
- 영역이 없어도 표시 예시를 확인할 수 있는 기능은 미리보기를 허용한다. 영역 등록을 모든 조작의 강제 선행 조건으로 만들지 않는다.
- 도르카·투아림의 세 사용 체크는 그대로 유지한다. 일관성을 이유로 전체 사용 체크 하나에 묶지 않는다.

### 3.2 용어와 조작 위치

| 의미 | 표현과 동작 |
|---|---|
| 게임 원본에서 읽을 위치 | 판독 영역. 도르카 숫자/투아림 %/버프 목록처럼 대상을 명시 |
| 수동으로 읽을 영역 설정 | 직접 지정. 대상 행/제목에서 의미를 구분 |
| 현재 화면에서 후보 검색 | 자동 찾기. 승인 전 기존 영역을 덮어쓰지 않음 |
| 저장된 원본 위치 표시 | 지정 영역 보기 |
| 오버레이 이동 방지와 클릭 통과 | 위치 잠금. 단일 대상의 현재 잠금 상태가 드러나는 토글 |
| 여러 대상에 잠금 명령 | 선택 잠금/선택 잠금 해제, 전체 잠금/전체 잠금 해제. 일부만 잠긴 상태를 단일 참/거짓으로 오인 표시하지 않음 |
| 표시 확대/축소 | 표시 배율. 원본 영역 크기나 Windows 배율 변경과 구분 |
| 원본을 읽는지 확인 | 원본 미리보기와 현재 판독값 |
| 새로 그린 모양 확인 | 표시 미리보기 |
| 실제 경고 모양 시험 | 알림 미리보기. 설정 저장/실제 경고 발생과 구분 |

- 영역 행의 명령은 자동 찾기/직접 지정/지정 영역 보기 순서를 기준으로 배치한다.
  자동 찾기가 없는 기능은 해당 명령을 추가하지 않는다. 폭이 부족하면 순서를 유지해 줄바꿈한다.
- 버튼을 빈 공간 전체로 늘려 한 명령만 과도하게 크게 만들지 않는다. 같은 의미는 비슷한 크기와 위치를 사용한다.
- 색상만으로 등록/실패/접근 불가를 구분하지 않고 짧은 상태명도 유지한다.
- 기존 테마/버튼 체계를 새 라이브러리로 바꾸지 않는다.

### 3.3 상태와 접근 조건

- 기능 사용, 영역 등록, 현재 판독, 표시 여부, 소리 사용 및 전체 일시정지를 서로 구분한다.
- 영역 등록됨은 저장된 위치가 있다는 뜻이다. 정상 작동 또는 현재 정렬 검증 완료로 표현하지 않는다.
- 현재 판독 불가는 실제 0과 구분한다. 판독 실패의 원인을 모르면 가림/영역 오류/게임 종료라고 단정하지 않는다.
- 일반 기능과 베타 조작을 구분해 비활성화하며, 사용할 수 없는 이유와 로그인 진입 경로가 찾기 쉬워야 한다.
- 투아림 알림처럼 기존 일반 기능을 공통 양식 때문에 로그인 필수로 바꾸지 않는다.
- 변경 즉시 저장되는 설정에는 별도 적용/저장 버튼을 새로 요구하지 않는다.
- 저장 실패는 기존 값과 현재 화면 상태의 차이를 알 수 있게 안내한다. 매 조작마다 성공 토스트를 만들지 않는다.

## 4. 도르카·투아림 화면

첨부 화면의 표시 모양과 독립 사용 체크는 유지하고 설정 순서를 다음처럼 정리한다.

```text
도르카·투아림
  도르카 표시 / 투아림 % 표시 / 투아림 알림 사용

판독 영역
  도르카 숫자: 등록 상태 + 자동 찾기 / 직접 지정 / 지정 영역 보기
  투아림 %:   등록 상태 + 자동 찾기 / 직접 지정 / 지정 영역 보기
  필요한 원본 미리보기와 현재 판독값

표시·배치
  표시 배율 / 위치 잠금
  기존 승인한 도르카·투아림 표시 미리보기

투아림 알림
  첫 알림 / 추가 알림 / 각각의 소리

진단
  투아림 판독 진단 등 기존 도구
```

- 원본을 확인하기 위해 큰 표시 미리보기 아래까지 내려가야 하는 흐름을 줄인다.
- 같은 영역 조작의 이름/순서/베타 설명을 맞추되 실제 접근 조건의 차이는 유지한다.
- 현재 판독값과 표시 미리보기에 같은 숫자가 나오는 것 자체를 금지하지 않는다.
  입력 검증과 출력 모양 확인이라는 차이를 구분하고 의미 없는 중복 상태 줄만 줄인다.
- 두 판독 영역의 정상/실패가 독립적이라는 기존 통합 명세를 유지한다.
- 세부 폭/간격과 기본 환경에서 한 화면에 들어오는지는 실제 제품 렌더로 확인한다.

## 5. 커스텀 오버레이 자동 저장

### 5.1 편집 대상과 정상 흐름

- 현재 적용 중인 프리셋 이름과 자동 저장 상태를 표시한다. 목록 선택 표시와 구분한다.
- 프리셋 A를 불러오면 A가 현재 편집 대상이 된다. 추가/삭제/이동/배율/잠금 등 구성 변경은 A에 자동 저장한다.
- 목록에서 B를 선택만 한 상태에서 편집해도 A에 저장한다. B를 불러와 적용했을 때만 편집 대상이 B로 바뀐다.
- 기존의 별도 저장 버튼을 눌러야 현재 프리셋 변경이 반영되는 흐름을 제거한다.
- 원본을 유지하면서 변형하려면 먼저 다른 이름으로 저장한다. 성공하면 새 이름의 프리셋이 편집 대상이 되며 이후 변경은 그 대상에만 저장한다.
- 다른 이름으로 저장을 취소하거나 실패하면 편집 대상과 기존 파일을 바꾸지 않는다. 같은 이름이 이미 있으면 확인 없이 덮어쓰지 않는다.
- 시작 시 자동 불러오기 대상은 별도 설정이다. 목록 선택/편집 대상 변경/다른 이름으로 저장만으로 바뀌지 않는다.

### 5.2 상태 전환과 안전 조건

| 조건 | 기대 동작 |
|---|---|
| 적용 중인 프리셋이 없음 | 기존 현재 구성 자동 저장을 유지한다. 목록 선택 항목에 임의 연결하지 않는다. 이름을 부여해 저장하는 명령은 제공한다. |
| A에서 B로 불러오기 | A의 편집을 보존한 뒤 B를 적용한다. B를 화면에 적용하며 발생한 변경을 A에 저장하지 않는다. |
| 다른 이름으로 저장 성공 | 현재 구성을 새 이름으로 보관하고 편집 대상을 새 이름으로 전환한다. 원본은 저장 직전 상태를 유지한다. |
| 사용자가 구성을 비움 | 삭제도 편집에 포함한다. 이후 불러오기에서 삭제 전 항목이 자동 저장 누락 때문에 되살아나지 않아야 한다. |
| 프리셋 삭제 | 기존 삭제 확인을 유지한다. 삭제된 대상에 지연 저장하여 프리셋을 재생성하지 않는다. 목록 선택만으로 다른 프리셋을 삭제하지 않도록 대상을 명시한다. |
| 저장 실패 | 성공으로 표시하지 않는다. 현재 편집 내용과 마지막 정상 저장본을 보존하고 저장 실패 상태를 알린다. 전환/종료 과정에서 편집 내용을 조용히 버리지 않는다. |
| 정상 종료/재실행 | 완료된 편집을 저장한다. 기존 시작 자동 불러오기 설정을 유지하고, 해당 프리셋을 다시 불러오면 저장된 편집이 반영된다. |
| 비정상 종료/저장 중 중단 | 마지막 정상 저장본이 손상되지 않아야 한다. 저장 완료 전 변경까지 복구된다고 보장하거나 표시하지 않는다. |

- 시작 시 무엇을 자동 복원하는지는 기존 정책을 유지한다. 자동 저장과 시작 시 자동 불러오기를 혼동하지 않는다.
- 기존 데이터에서 활성 프리셋을 확실히 알 수 없으면 목록 선택/이름 추정으로 연결하거나 덮어쓰지 않는다.
- 실패 시 재시도/복구 조작의 세부 배치는 구현 시안에서 확인하되, 다른 프리셋 덮어쓰기와 편집 유실을 방지해야 한다.
- 드래그의 매 픽셀이나 캡처 매 프레임마다 저장하지 않는다. 완료된 편집을 묶어 저장할 수 있으나 전환/정상 종료 시 미반영 변경을 놓치지 않는다.
- 숨김/전체 일시정지 같은 일시 상태를 사용자 구성 삭제로 저장하지 않는다.

## 6. 화면별 적용 및 보존 기준

통합 후 기본 화면 13개를 기준으로 한다. 구현 시 적용할 요구사항이며 구현 완료 판정이 아니다.

| 화면 | 맞출 부분 | 유지할 차이/주의 |
|---|---|---|
| 버프 | 공통 영역 명령/잠금/배율 용어, 원본 등록과 현재 감지 상태 구분 | 목록 왼쪽/개별 설정 오른쪽 유지. 등록 기준 버프와 일반 버프의 설정 차이 유지 |
| 디버프 | 버프와 같은 영역/배치 조작, 자동 보스 확인과 진단 상태 구분 | 미적용 디버프를 보여주는 의미와 숨겨진 진단 방식 유지. 진단 방식을 일반 사용자 선택으로 다시 꺼내지 않음 |
| 보스 패턴 알림 | 영역 확인 후 표시·알림 조절, 원본 미리보기와 경고 미리보기 이름 구분 | 경고와 남은 패턴 목록의 독립 위치/잠금 유지. 공유 보스 영역을 다른 기능 토글로 덮어쓰지 않음 |
| 체력바 | 영역/현재 판독/표시·배치/알림 순서, 위치 잠금 명령 통일 | 세 자원의 개별 표시와 보스전 저값 경고 조건 유지. 정상/저값 시각 효과는 변경하지 않음 |
| 도르카·투아림 | 4절 구조 및 같은 영역 명령 이름, 세 사용 선택과 권한 명확화 | 승인된 바 모양, 두 원본 영역/실패 분리 및 알림 독립 동작 유지 |
| 단축바 | 원본 첫 칸 등록과 오버레이 배치 분리, 배율/잠금 명칭 정리 | 12개 그룹과 빈 슬롯 숨김, 원본 격자/표시 배율의 차이 유지 |
| 커스텀 오버레이 | 현재 적용 프리셋/선택/시작 자동 불러오기 구분, 저장 모델 및 삭제 대상 명확화 | 영역 추가와 프리셋/오버레이 관리의 고유 흐름 유지. 캡처 호환 모드는 고급 도구로 검토 |
| 메모 | 위치·너비 지정과 판독 영역을 다른 의미로 유지, 잠금과 결과 미리보기 명확화 | 원본 판독/자동찾기 행을 억지로 추가하지 않음. 내용 자동 저장과 편집/렌더 보기 유지 |
| 파티 모집 | 서버/조회/알림/제외 상태 구분, 같은 등록/삭제 명령 패턴 | 게임 캡처나 위치 잠금 기능을 넣지 않음. 키워드와 파티장 제외의 다른 효과 유지 |
| 분배 계산기 | 입력 단위와 계산 결과의 기준을 확인, 입력 변경 후 이전 결과의 구분 검토 | 외부 시세를 조회하는 명시 계산/엔터 흐름 유지. 단순 일관성을 위해 매 입력마다 조회하지 않음 |
| 구슬 분배 계산기 | 입력/자동 결과 구역, 실제 구슬 수와 계산상 두 배 수량 구분 | 로컬 계산의 입력 즉시 재계산 유지. 실행 버튼을 불필요하게 추가하지 않음 |
| 환전비율 계산기 | 선택 던전/조회 중/조회 결과/실패/시세 기준 구분 | 던전 목록과 재조회 흐름 유지. 매물 없음과 호출 실패를 알 수 있는 범위에서 구분 |
| 설정 | 일반/게임창/계정/지원 도구의 찾기 쉬운 순서 검토, 저장/재시작 필요 범위 구분 | 백업 파일 내보내기와 설정 즉시 저장은 다른 동작. 가져오기/초기화의 기존 확인과 재시작 정책 유지 |

마우스 하이라이트는 이번 고정 main의 기능 목록에서 확인되지 않았다. 별도 기획/작업본이 있으면
같은 배율/색상/미리보기 용어를 대조하되, 이번 검수에서 실제 화면까지 확인했다고 보고하지 않는다.

### 보조 화면과 동선

- 첫 사용 안내: 기능 선택과 등록 상태의 의미를 유지하고 개별 화면의 사용 체크와 같은 설정을 쓴다.
- 일괄 자동설정: 선택한 기능의 미등록 영역만 찾고, 찾은 후보와 저장 완료 상태를 구분한다.
- 영역 승인: 개별/일괄에서 대상 이름과 승인/거절의 의미가 같아야 한다. 취소하면 기존 설정을 유지한다.
- 앱 투어: 새 위치와 실제 조작을 강조한다. 투어를 보기만 해도 설정이 바뀌어서는 안 된다.
- 기능 이동: 예전 투아림/도르카 경로는 통합 탭의 올바른 구역을 연다. 체력바 경로는 체력바 탭을 유지한다.
- 문의/백업/초기화: 보내기·파일 저장·가져오기와 일반 설정의 즉시 저장을 다른 명령으로 유지한다.
- 진단: 일반 조작 아래에 두거나 접어서 제공하는 안을 검토하되 기존 수집/제보 도구를 제거하지 않는다.

## 7. 개발 및 화면 확인 순서

1. 도르카·투아림과 체력바 두 화면으로 공통 조작 배치를 렌더해 사용자에게 보여준다.
2. 커스텀은 현재 프리셋/다른 이름으로 저장/저장 실패 상태를 렌더해 확인한다.
3. 버프/디버프와 나머지 화면에 같은 의미의 조작만 적용한다. 모든 화면에 같은 대형 패널을 복제하지 않는다.
4. 첫 사용 안내/투어/개별 이동/백업 복원의 연결을 확인한다.
5. 화면별 시각 확인과 기존 기능 회귀를 거친 뒤 배포한다. 명칭 수정만으로 동작 검증을 대체하지 않는다.

이번 검토를 이유로 승인된 2단 가로 탭을 좌측 목록이나 3단 탭으로 다시 바꾸지 않는다.
본창 확대, 전체 테마 변경, 폰트 축소 및 기존 기능 삭제도 자동 승인된 범위가 아니다.

## 8. Acceptance Criteria

| ID | 검증 기준 |
|---|---|
| UX-01 | 동일한 원본 영역 조작은 대상 이름을 제외한 명령/순서가 같고 지정 영역 보기가 현재 판독 성공을 의미하지 않는다. |
| UX-02 | 단일 대상의 위치 잠금 상태와 선택/전체 잠금 명령이 구분되며 실제 클릭 통과/편집 동작은 기존과 같다. |
| UX-03 | 도르카·투아림의 세 사용 조합과 두 판독 영역의 독립 실패가 유지되고 일반 투아림 알림의 권한이 바뀌지 않는다. |
| UX-04 | 원본 캡처/읽은 값/표시 예시/알림 시험이 구분된다. 현재 값을 확인하려다 필요 없는 대형 미리보기 때문에 조작을 찾지 못하는 배치가 없는지 시안에서 확인한다. |
| UX-05 | 현재 적용 프리셋과 목록 선택/시작 자동 불러오기 대상이 서로 구분되며 선택만 바꾸어 저장 대상이 몰래 바뀌지 않는다. |
| UX-06 | A를 불러온 뒤 추가/이동/배율/잠금/삭제를 변경하고 B로 전환했다가 A를 다시 불러오면 변경이 유지된다. 정상 종료 후 A를 다시 불러와도 동일하다. 별도 저장 클릭이 필요하지 않다. |
| UX-07 | 기본 창/글꼴에서 버프·디버프의 좌우 편집 배치가 유지되고 공통 조작을 맞추기 위해 본문 폭/높이를 불필요하게 줄이지 않는다. |
| UX-08 | 큰 글꼴/높은 DPI/작은 작업 영역에서도 필수 조작과 상태를 읽고 선택할 수 있으며 제작자 얼굴이 상시 가리지 않는다. |
| UX-09 | 계산/시세 조회/메모 저장/프리셋 저장/백업 파일 저장의 차이가 유지되고 형식 통일 때문에 외부 요청이나 저장 작업이 매 입력/프레임마다 발생하지 않는다. |
| UX-10 | 기존 설정을 가진 사용자가 재등록 없이 이용할 수 있고 변경 후 사용 체크/영역/위치/배율/소리/메모/프리셋이 보존된다. |
| UX-11 | 안내/투어/영역 승인/로그인 진입/기능 이동이 새 조작 위치와 일치하고 화면 소개만으로 사용 설정을 바꾸지 않는다. |
| UX-12 | 전환/편집 반복 및 앱 종료 후 오버레이/워커/타이머가 누적되지 않고 기존 판독·알림 정책이 유지된다. |
| UX-13 | A 적용 중 B를 목록에서 선택한 뒤 편집해도 A만 갱신된다. B 불러오기가 A를 B 구성으로 덮어쓰지 않는다. |
| UX-14 | A를 다른 이름 C로 저장한 뒤 편집하면 C만 바뀐다. 이름 입력 취소/저장 실패 시 A가 편집 대상으로 유지되고 원본이 손상되지 않는다. |
| UX-15 | 저장 실패를 주입하면 실패 상태가 표시되고 마지막 정상 저장본과 현재 편집 내용이 유지된다. 전환/종료가 실패를 숨긴 채 편집 내용을 버리지 않는다. |
| UX-16 | 빈 구성 저장 후 재불러오기에서 삭제 전 항목이 되살아나지 않으며, 삭제한 프리셋을 예약 저장이 재생성하지 않는다. |
| UX-17 | 활성 프리셋을 알 수 없는 기존 설정을 가져와도 임의의 프리셋에 연결하지 않는다. 다른 이름으로 저장 및 적용 대상 변경이 시작 자동 불러오기 대상을 임의 변경하지 않는다. |

## 9. 구현 시 확인할 항목

- 승인한 시안의 개발 내용과 실행 증거는 [개발 기록](app-interaction-consistency-implementation.md)에
  별도로 기록한다. 개발 검증과 후속 독립 QA/Windows 실기기 검증을 구분한다.

- 공통 조작 순서와 자동 저장 정책은 확정되었다. 이 문서를 개발 및 독립 QA 세션에 전달할 수 있다.
- 정확한 컨트롤 폭/간격, 미리보기 크기와 진단 접기 범위는 실제 화면 렌더로 사용자 확인을 받는다.
- 최신 통합 작업본의 실제 접근 조건/설정 항목을 대조하고, 기존 독립 명세의 미검증 사항을 임의 확정하지 않는다.
- 전체 화면의 실행 확인, 높은 DPI/작은 작업 영역, Windows 실게임 검증은 개발 및 QA에서 수행한다.
  이 문서의 기획 확정은 해당 검증의 완료를 뜻하지 않는다.
