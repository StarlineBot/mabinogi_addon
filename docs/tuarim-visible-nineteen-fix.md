# 투아림 넓은 입력의 19% 오독 수정

- 날짜: 2026-10-18 (Asia/Seoul).
- 근거: `docs/qa/투아림_19퍼센트_9오독_QA_20261018.md`.
- 원본: `tests/data/스크린샷 2026-10-18 124011.png`, 등록 영역 `(1265,85,42,16)`.

## 원인 및 재현

원본 QA 스크립트를 변경 없이 실행해 2 failed, 4 passed (2.11초)를 확인했다.
실제 리더와 실제 탭의 원시/안정화/통합 표시가 모두 19 대신 9였다.
좁은 입력의 얇은 1 보완과 달리 이 입력은 `%` 정렬을 하는 `_read_padded` 경로다.
가장 확실한 일의 자리 9 정렬에서 십의 자리는 잉크 3개, 기존 분류 최고 점수 약
0.509로 불확실하지만, 이전에는 이를 부재로 취급하고 9를 확정했다.

## 수정

- 넓은 경로의 가장 확실한 일의 자리 정렬을 기준으로 십의 자리 잉크를 확인한다.
  잉크 없음과 분류 불확실을 구분하고, 잉크가 있는데 읽지 못하면 None으로 보류한다.
  셀 외곽에만 남는 하이라이트는 글자 내부의 근거와 구분해 기존 실제 7% 판독을 유지한다.
- 희미한 1은 일의 자리 점수 0.85 이상 및 같은 정렬의 십의 자리 1 근거가 있어야 한다.
  기존 분류가 실패하면 새 원본에서 추출한 13x8 native 표본과 NCC 0.90 이상일 때만
  10대를 채택한다. 다른 십의 자리나 고값으로 승격하는 폴백은 추가하지 않는다.
- `scripts/build_tuarim_thin_one.py`는 원본 blob 해시/크기를 확인하고 V 채널 셀을
  추출한다. 원본과 기존 refs.npz는 변경하지 않는다. 새 표본이 없거나 손상되면 보류한다.
- 기존 숫자 분류 임계값·100% 보류·좁은 입력·트래커 재무장 기준·표시 안정화·설정은 유지한다.
- v0.4.88 노트에 사용자용 설명을 추가한다. 도르카 장식 수정과 별도 원인이다.

## 검증

- 새 원본의 리더→안정화→실제 오버레이 19와 기존 밝은 원본 19를 확인한다.
- 표본 유실/불일치/잘못된 크기, 일의 자리 저신뢰는 None이며, 희미한 십의 자리를
  잘못 9로 분류해도 99로 채택하지 않는 대조를 포함한다.
- 실제 한 자리의 여백 입력은 잘못된 십의 자리가 붙지 않아야 하고, 90~99의 여백 입력은
  정확한 두 자리를 유지해야 한다. None도 허용하는 한 자리 대조는 새 보수적 검증이며
  기존 정상 판독/알림 assertion을 완화하지 않았다.
- 기존 2926장 세션과 여백을 추가한 2926장 세션 모두 `[90,95]`만 발화하는지 검사한다.
  추가로 19% 지속을 저값 재무장 근거로 쓰지 않는지 확인한다.
- 중간 실행: 원본 QA+기존 투아림/저구간 62 passed (6.54초),
  통합 표시 포함 98 passed (22.14초), 새 여백/세션 대조 29 passed (7.14초).
  묶음 간 중복이 있어 고유 실행 수로 합산하지 않는다.
- 네이티브 원본까지 확장한 중간 실행에서 143 passed/1 failed였다. 기존 밝은 배경의
  7%가 None으로 보류되는 회귀를 발견했고, 원본의 십의 자리 셀 외곽 하이라이트와
  19%의 글자 내부 잉크를 분리해 수정했다. 기존 7 기대값은 그대로 유지한다.
- 최종 실행: 144 passed (53.14초). 원본/새 대조/기존 투아림/저구간/네이티브 원본 재생/
  설정 폭/자원 통합/노트 검사이며, 실제 Windows 네이티브 API 검사가 아니다.
- 최종 명령:

```bash
OPENCV_FOR_THREADS_NUM=1 QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest tests/test_tuarim_visible_nineteen.py tests/test_tuarim.py tests/test_tuarim_low_range_display.py tests/test_tuarim_native_autofind.py tests/test_tuarim_settings_width.py tests/test_resource_integration.py tests/test_release_notes.py -q --tb=short --maxfail=3
```

`git diff --check`와 변경 Python 파일의 `compileall`도 통과했다. 전체 저장소 재검사는
이번 범위에 포함하지 않았고, 실패 skip/기존 기대값 완화 없이 위 묶음을 통과했다.

Linux 원본 재생/Qt offscreen/명시적 캡처·게임·소리 격리 결과다. 실제 Windows
프레임 변화·DPI·장시간 알림·네이티브/exe는 미검증이다. 일반 푸시의 Windows Actions
중단 정책을 유지한다. 태그·릴리즈는 진행하지 않고 수정본을 후속 QA에 전달한다.
