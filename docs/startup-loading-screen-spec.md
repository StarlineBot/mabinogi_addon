# 단일 시작 로딩 화면과 타이핑 대사

- 작성일: 2026-10-20
- 상태: 사용자 요청에 따라 동작 방향 및 A안 화면 구성 확정. 개발·독립 QA 전달용.
- 소스 확인 기준: 원격 `main`의 `71e4ca1a28156a3d70fc4e51381125318ee58fd2`.
- 화면 승인과 실제 Windows EXE 검증은 별개다. 타이핑 속도·유지 시간은 아래 시안값으로 시작해 실제 실행에서 확인한다.

## 1. 목적과 범위

EXE 압축 해제 중 오래 보이는 첫 화면부터 다양한 상황극 대사를 보여주고, 앱 초기화 때 크기와 위치가 다른 로딩 창으로 바뀌는 경험을 없앤다. 앱 이름이 들어간 로고와 대사 중심의 간결한 A안으로 통합한다.

대상은 Windows 배포 EXE의 최초 실행 준비 화면부터 본 앱 진입까지다. 첫 사용 안내와 앱 사용 중 제작자 잡담 기능은 별도 기능으로 유지한다. 초기 실행에서 수행하는 업데이트 상태 표시를 포함한다. 2026-10-20 후속 사용자 확정으로 본 앱의 '지금 업데이트' 화면도 A안 디자인으로 통일한다. 수동 업데이트는 타이핑 없이 실제 상태와 퍼센트만 표시하며, 다운로드·교체·재실행 로직의 재설계는 포함하지 않는다. 최신 추가 범위와 검증 기준은 11절을 따른다.

## 2. 화면 구성

- 기본 시안 크기는 논리 크기 `440 × 240`이다. 지원 DPI에서 물리 크기가 달라질 수 있으나 단계 전환 때문에 크기가 달라져서는 안 된다.
- 위쪽 중앙에는 승인한 합성 로고 이미지를 배치한다. 매듭 가운데를 `섯다라인 애드온` 글자가 가로지르는 이미지이며, 글자와 매듭의 비율을 임의로 바꾸지 않는다.
- 아래쪽 중앙에는 민트색 `섯다라인은 지금…`을 고정 표시하고, 그 아래 한 곳에서 상황극 대사 또는 실제 진행 상태를 보여준다.
- 제작자 얼굴, 별도 제작자 이름 줄, 말풍선 테두리·꼬리, 타자 소리, 깜빡이는 커서는 넣지 않는다.
- 진행바는 이번 A안에서 사용하지 않는다. 기존 정적 이미지에 그려진 채워진 막대도 최종 로딩 배경에 남기지 않는다. 실제 다운로드 진행은 해당 상태 문구로 안내한다.
- 전체 배경과 테두리 등은 승인 목업을 기준으로 한다. 민트색 테두리는 `#00B894`, 고정 문구는 `#00D1A7`이다.
- 로고·고정 문구·대사의 자리는 고정한다. 글자가 추가되거나 대사가 바뀌어도 로고 위치, 창 크기, 문구 영역 높이가 흔들리지 않는다.
- 긴 대사는 정해진 문구 영역 안에서 줄바꿈할 수 있다. 글자를 잘라내거나 창을 늘리지 않는다. 번들 대사 전체가 해당 영역에 들어가는지 개발 때 확인한다.

## 3. 단일 창 유지

- 최초 로딩 창이 표시된 뒤 압축 해제, 실행 준비, 초기 업데이트 확인 및 앱 초기화가 이어지는 동안 그 로딩 창 하나를 유지한다.
- 압축 해제가 끝났다는 이유로 로딩 창을 닫고 다른 로딩 창을 열지 않는다. 크기와 모양이 같은 두 창을 교체해 전환을 감추는 방식도 이 요구사항의 완료로 인정하지 않는다.
- 같은 실행 흐름에서 창의 식별자, 위치와 크기가 유지되어야 한다. 모니터 구성·DPI가 실제로 바뀌면 화면 밖으로 사라지지 않도록 필요한 위치·크기 보정은 허용한다.
- 메인 앱 화면은 별도 창이다. 앱 진입 시 로딩 창을 닫는 것은 정상 전환이다.
- 로딩 화면을 만들기 위한 최소 구성 요소 준비 시간까지 없애는 요구사항은 아니다. 첫 로딩 창이 표시된 시점부터 대사 기능을 시작하며, 앱 코드 실행 후에만 대사를 시작하는 것으로 대체하지 않는다.
- 로딩 화면이 준비되기 전에 새로운 창이나 빈 창을 잠깐 보여주는 단계를 추가하지 않는다.

## 4. 상황극 대사

### 4.1 압축 해제 중 표시

- 첫 로딩 창이 표시되면 동봉된 유효 대사 중 하나를 무작위로 골라 타이핑 표시를 시작한다. 압축 해제 중에도 글자 추가와 대사 교체가 계속 동작해야 한다.
- 최초 범위에서는 기존 로딩 대사 목록을 사용한다. 대사 콘텐츠를 새로 확대하거나 앱 내부 제작자 잡담의 외부 공급 체계를 통합하지 않는다.
- 이 구간에 필요한 대사·로고는 배포본에 포함한다. 압축이 모두 풀리거나 인터넷 조회가 끝나야 대사를 사용할 수 있는 구조로 만들지 않는다.
- 대사 목록은 실행 시 사용하는 고정된 콘텐츠다. 표시 애니메이션 때문에 디스크·네트워크를 계속 조회하지 않는다.

### 4.2 타이핑과 교체

1. 고정 문구 `섯다라인은 지금…`은 처음부터 완성된 형태로 보인다.
2. 아래 대사는 빈 상태에서 시작해 한글 한 글자씩 추가한다. UTF-8 바이트나 한글 자모가 분리된 중간 상태를 보여주지 않는다.
3. 완성된 대사를 잠시 유지한 뒤 다음 대사를 무작위로 고른다.
4. 이전 대사를 한 번에 지우고 다음 대사를 타이핑한다. 지우는 애니메이션은 추가하지 않는다.
5. 앱이 준비될 때까지 반복한다. 작업 단계가 바뀔 때마다 이유 없이 대사를 처음부터 재생하지 않는다.

시안값:

| 항목 | 시작 시안값 | 확인 기준 |
|---|---|---|
| 글자 추가 간격 | 60ms | 앞서 제안한 50~70ms 범위의 시작값. 한글을 읽을 수 있고 지나치게 느리지 않은지 실제 실행에서 확인 |
| 완성 후 유지 | 2초 | 대사를 끝까지 읽을 여유가 있는지 확인 |

위 두 수치는 실사용 조정값이지 고정된 최종 체감 품질 판정값은 아니다. 조정 때문에 개발을 보류할 필요는 없으며, 초기 검증 결과에 실제 값을 기록한다. 로딩을 일부러 늘려 대사를 읽히는 방식으로 해결하지 않는다.

## 5. 상태와 전환

| 상태 | 표시와 기대 동작 |
|---|---|
| 압축 해제 | 단일 창에서 상황극 대사 타이핑·교체 |
| 일반 앱 초기화 | 같은 창과 대사 흐름 유지 |
| 실제 업데이트 확인·다운로드·적용 | 상황극 대신 실제 상태를 즉시 표시. 다운로드 중에는 기존 실제 진행률을 문구에 포함 |
| 업데이트 실패 후 현재 버전으로 진행 | 기존 실패 처리·기록 정책 유지. 실패 상태 표시 중 타이핑이 문구를 덮지 않으며, 일반 초기화로 돌아오면 상황극 재개 가능 |
| 앱 준비 완료 | 타이핑이나 유지 시간이 남아도 기다리지 않고 기존 앱 진입 흐름 실행 |
| 중복 실행으로 종료 | 해당 실행의 로딩 창과 대사 갱신 작업 정리. 기존 실행 중 앱에는 영향 없음 |
| 종료·실행 실패 | 타이핑이 오류 안내를 덮지 않도록 중지. 기존 오류 처리·로그 유지 및 해당 로딩 창 정리 |

- 실제 업데이트·오류 등 중요한 상태는 타이핑하지 않고 완성된 문장으로 즉시 표시한다. 상황극용 갱신이 늦게 도착해 그 상태를 덮지 않아야 한다.
- 실제 상태를 표시하는 동안에는 고정된 `섯다라인은 지금…` 아래에 해당 상태를 표시한다. 별도 두 번째 로딩 창을 열지 않는다.
- 압축 해제 파일명이나 내부 디버그 메시지가 상황극 대사를 덮어쓰지 않게 한다. 대사가 실제 압축 진행률을 뜻하는 것처럼 안내하지 않는다.
- 업데이트 적용으로 EXE를 교체하고 새 프로세스로 재실행하는 경우는 별도 실행이다. 이전 프로세스의 창을 새 프로세스까지 그대로 넘기는 것은 범위 밖이다. 각 실행 내부에서는 창 하나를 유지한다.
- 본 앱 준비 완료 시에는 기존 첫 사용 안내·설정된 초기 탭·업데이트 안내 등 진입 정책을 따른다. 로딩 화면 변경을 이유로 진입 대상을 바꾸지 않는다.

## 6. 유지할 기존 동작과 예외

- 기존 업데이트 확인·다운로드·교체·재실행과 실패 시 현재 버전으로 계속 실행하는 정책을 유지한다. 대사 효과를 위해 앱 실행 전 네트워크 요청을 추가하지 않는다.
- 트레이로 시작할 때 메인 창을 열지 않는 기존 정책을 유지한다. 기존에 보이는 초기 압축 화면을 일괄 억제하는 기능까지 추가하지 않으며, 트레이 시작 여부를 확인한 뒤 불필요한 후속 로딩 창을 새로 띄우지 않는다. 기존에 생략하던 초기 업데이트 확인을 새로 강제하지 않는다.
- 기존 관리자 권한 요청, 중복 실행 검사, 창 활성화·최상단 정책을 이번 범위에서 변경하지 않는다. 타이핑을 이유로 앱을 반복 활성화하지 않는다.
- 대사·효과 처리 실패가 앱 초기화를 막거나 추가 대기·재시작을 유발해서는 안 된다. 같은 창에서 완성된 기본 대사나 `시작하는 중`으로 안전하게 대체할 수 있어야 한다.
- 유효한 대사가 없으면 기본 상태 문구를 사용한다. 빈 목록에서 무작위 선택을 반복하거나 오류를 내지 않는다.
- 대사 표시 장애와 압축 해제·부트로더 자체의 치명적 실패를 구분한다. 후자까지 로딩 화면에서 복구하는 기능은 추가하지 않는다.
- 개발 실행처럼 배포용 첫 화면이 없는 환경은 같은 디자인의 대체 로딩 화면을 사용할 수 있다. Windows 배포본의 압축 해제 중 동작 검증을 이 대체 화면으로 대신하지 않는다.

## 7. 성능과 생명주기

- 타이핑·대사 교체를 위한 대기 때문에 압축 해제나 앱 초기화가 순차적으로 멈추지 않아야 한다. 애니메이션을 완료하기 위한 최소 노출 시간을 추가하지 않는다.
- 짧은 주기로 계속 도는 무제한 반복 처리, 대사별 신규 창·스레드 누적, 같은 효과의 중복 실행을 만들지 않는다.
- 실제 상태 표시로 전환하거나 로딩 창을 닫으면 기존 대사용 예약 작업을 취소하거나 무효화한다. 종료 후 문구를 갱신하거나 창을 다시 열지 않는다.
- 처음 로딩 창이 만들어지는 순간부터 타이핑을 시작하되 대사 기능 때문에 첫 화면 표시를 의도적으로 늦추지 않는다.

## 8. 구현 검토와 검증 경계

- Windows 단일 EXE의 압축 해제 중 독립적으로 동작하는 로딩 화면 구조를 확인했으며, 해당 화면의 동작을 확장하는 구현 경로가 있다. 기본 옵션만 켜면 자동으로 타이핑이 제공되는 것은 아니다.
- 특정 Windows API·화면 라이브러리·스레드 구조를 요구사항의 정답으로 고정하지 않는다. 기존 패키징을 활용하되 3절의 실제 단일 창과 4절의 압축 해제 중 표시 조건을 충족해야 한다.
- 개발은 실제 Windows EXE에서 압축 해제 중 대사 타이핑·교체와 창 유지부터 작은 검증으로 확인한다. 성공하면 업데이트 상태와 본 앱 진입까지 연결한다. 기본 이미지 교체나 Qt 목업만으로 완료 처리하지 않는다.
- PyInstaller 버전을 올릴 때는 첫 화면의 생성·텍스트 갱신·종료와 압축 해제 중 효과를 회귀 확인한다. 내부 확장 지점이 바뀐 경우에만 필요한 부분을 수정한다. 매 실행이나 일반 앱 업데이트마다 수작업이 필요한 요구사항은 아니다.
- 개발 시 사용한 PyInstaller 버전과 패키징 결과를 기록한다. 현재 문서 작성만으로 동작·성능·Windows 호환성이 검증된 것으로 간주하지 않는다.

## 10. 결정 상태

- 개발을 시작하기 위해 추가 사용자 결정이 필요한 핵심 미결 사항은 없다.
- 타이핑 속도와 완성 후 유지 시간은 명시한 시안값으로 실제 실행에서 확인한다. 시각적 구성 승인을 체감 속도 검증으로 대신하지 않는다.
- 압축 해제 중 효과와 단일 창 유지가 검증되지 않으면 미완료로 보고한다. 앱 초기화 이후만 동작하는 효과나 두 창 교체로 요구사항을 조용히 축소하지 않는다.
- 이 문서는 기획과 참조 이미지 정리다. 문서 확정을 제품 구현·실행 검증·배포 완료로 해석하지 않는다.

## 11. 후속 확정: 수동 업데이트 화면도 A안으로 통일

2026-10-20 사용자가 '새 디자인으로 통일하되 수동 업데이트는 타이핑 없이 실제 상태와 퍼센트만 표시'하는 방향을 승인했다. 최초 1절의 수동 다운로드 화면 제외 범위를 표시 부분에 한해 확장한다. 기존 진행률 소실 회귀는 별도 수정으로 복구됐으며, 이 절은 그 결함을 다시 보고하는 것이 아니라 추가 사용자 요구다.

### 화면과 상태

- 앱 실행 중 '지금 업데이트'를 누르면 시작 화면과 같은 A안 로고·배경·색상·고정 문구·배치를 사용한다. 논리 크기는 `440 × 240`이며 로고·문구 영역은 2절과 같다.
- 제작자 얼굴, 별도 이름 줄, 진행바는 제거한다. 대신 실제 다운로드 콜백 값으로 `새 버전 v0.8.0 받는 중 37%`처럼 숫자 퍼센트를 반드시 표시한다. 버전은 실제 업데이트 대상 버전이다.
- 수동 업데이트에서는 상황극 무작위 선택·타이핑·완성 후 유지·다음 대사 교체를 하지 않는다. 첫 표시부터 상태 문구를 완성형으로 즉시 보여준다. 상태·퍼센트가 바뀌어도 창과 로고 위치·크기는 고정한다.
- 다운로드 완료 후 실제 적용 단계로 넘어갈 때 `업데이트 적용 중`을 표시한다. 타이머로 진행률을 추정하거나 작업보다 먼저 완료·적용 상태를 표시하지 않는다.
- 시작 시 자동 업데이트도 같은 A안에서 실제 상태와 퍼센트를 즉시 표시하는 기존 정책을 유지한다. 일반 시작의 상황극과 수동 업데이트의 상태 전용 모드는 명확히 구분한다.
- '같은 디자인'은 시작 때 닫은 부트로더 창을 수동 업데이트까지 재사용하라는 뜻이 아니다. 앱 실행 중 수동 다운로드는 별도 Qt 창이어도 된다. 종료된 부트로더 IPC에 다시 연결하거나 시작 대사를 재개하지 않는다.

### 유지할 동작과 구현 경계

- 기존 확인 창에서 거절하면 다운로드·화면 생성을 하지 않는다. 승인 뒤 메인 창 숨김, 기존 비동기 다운로드·교체·재실행, 성공 시 종료와 실패 시 메인 복원·오류 안내를 유지한다.
- 창 디자인을 맞추는 작업 때문에 실제 다운로드·파일 검증·권한·재실행 정책을 바꾸거나 추가 네트워크·폴링·대기·워커를 만들지 않는다. 새 취소 기능을 추가하는 요구도 아니다.
- 기존 공통 자산과 표시 도구를 우선 사용하되, 공통 화면 생성 때문에 수동 업데이트에서 잠깐이라도 상황극이 보이거나 타이머가 살아 있지 않아야 한다. 특정 상속 구조나 클래스 통합 자체를 완료 조건으로 삼지 않는다.
- 다운로드·적용 작업의 UI 갱신은 Qt의 스레드 경계를 지킨다. 작업 스레드에서 위젯을 직접 조작하지 않는다. 닫힌 화면의 늦은 콜백은 화면을 다시 열거나 다른 상태를 덮지 않아야 한다.
- 기존 수동 업데이트 회귀의 성공/다운로드 실패/적용 실패/거절/신호 정리 검사를 유지한다. 기존 `440×208`·진행바 존재 assertion은 새 승인 배치·실제 숫자 표시 검증으로 교체하되, 생명주기·실패 처리 검증은 약화하지 않는다.
