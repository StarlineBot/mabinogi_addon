## 1. 개요

마비노기(공식 API 없음)의 화면을 실시간으로 분석해서

- **버프**: 상태목록창에서 등록한 버프를 찾아 남은 시간을 읽고, 지정한 위치에 오버레이로 가로 나열한다. 연장이 필요한 시점에 알림을 준다.
- **디버프**: 보스 체력바 위 디버프 줄에서 등록한 디버프를 찾아, **아직 걸리지 않은 디버프만** 오버레이로 보여준다.

화면을 **읽기만** 한다. 키 입력·클릭 자동화, 메모리 읽기는 하지 않는다 (넥슨 보안 모듈 탐지 대상).

## 2. 게임 화면 구조 (스크린샷 분석 결과)

### 2.1 버프 상태목록창 (화면 오른쪽)

- 한 행 = `[아이콘] 이름 ......... 남은시간`. 아이콘·이름은 왼쪽 정렬, 시간은 오른쪽 정렬.
- 목록이 **그룹으로 나뉘고 그룹 사이에 구분선·여백**이 있다 → 행 높이로 균등 분할 불가.
  - 위 그룹: 시간 없음 / 가운데 그룹: 시간 있음 / 아래 그룹: 시간 없음
- 시간 표기: `일 / 시간 / 분 / 초` 한글 단위 혼합. 예) `1분 20초`, `1시간 46분 59초`, `5일 21시간 34분`
- 시간 글자색: 흰색, 임박 시 빨간색.
- **30초 이하에서 아이콘이 점멸 + 반투명**해진다. 그 전에는 아이콘 투명도 없음.
- 창 배경이 반투명 → 뒤 게임 화면이 비친다.
- 맵 이동·스킬 이펙트로 화면이 순간적으로 까매지거나 하얘지는 경우가 잦다.
- **"프리미엄 배틀 멤버십"** 버프는 항상 존재하고 지속시간이 없다 (점멸 안 함) → 앵커로 사용.

### 2.2 보스 디버프 (화면 하단, 보스 체력바 바로 위)

- 작은 아이콘이 가로로 나열되고, 아이콘 아래에 시간 (`4M`, `2M`, `19`, `43` …: 분은 M, 초는 단위 없음).
- 디버프가 걸리고 풀릴 때마다 가로 위치가 바뀐다.
- 보스 체력바 위치는 고정.

## 3. 기능 명세

### 3.1 버프 트래커

| 항목 | 내용 |
|---|---|
| 입력 | 사용자가 지정한 상태목록창 영역 |
| 탐지 | 아이콘 열(x 고정, 세로 띠)에서 등록 아이콘을 템플릿 검색 → 매칭된 y의 오른쪽 시간 영역을 판독 |
| 표시 | 등록 순서대로 **매칭된 버프만** 빈칸 없이 왼쪽부터 가로 나열 |
| 표시 아이콘 | 등록한 표시 아이콘 → 없으면 매칭 아이콘(또는 처음 매칭 시 캡처본) |
| 지속시간 | 버프별 표시 여부 선택. 켜면 아이콘 아래 표기 |
| 알림 | 버프별 사용 여부·기준 초(기본 30초)·점멸·소리 |
| 앵커 | 버프 하나를 앵커로 지정(기본: 프리미엄 배틀 멤버십). 오버레이에는 표시 안 함 |

표시 예) 등록 `A B C D E F G`
- `A B E F` 켜짐 → `[A][B][E][F]`
- `C D G` 켜짐 → `[C][D][G]`

지속시간 표기 (축약):

| 남은 시간 | 표기 |
|---|---|
| 1일 이상 | `5d` |
| 1시간 이상 | `1h46m` |
| 1분 이상 | `3:28` |
| 1분 미만 | `28s` |

#### 3.1.1 즐겨찾기 칸 읽기 (2026-10-28 사용자 결정)

- 배경: 마비노기 버프 애드온은 아래 목록만 읽는 것과 즐겨찾기(고정) 칸만 읽는 것 두 종류가 있다. 이 앱은 아래 목록 방식이라,
  즐겨찾기를 쓰는 사람은 즐겨찾기를 모두 해제해야 했다. 두 칸을 함께 읽어 모드 선택 없이 양쪽 사용자를 지원한다.
- 게임 동작(사용자 확인 + tests/data 2026-10-16~26 스크린샷 8장): 상태목록창 위쪽, 구분선 위가 즐겨찾기 칸이다.
  즐겨찾기한 버프는 **아래 목록에서 빠져 위 칸으로 옮겨지고**, 줄 위치·순서가 고정이다. 켜지면 아래 목록과 같은 모양(밝은 아이콘·이름, 오른쪽 남은 시간)이고,
  꺼지면 줄이 남은 채 **회색(흐림)** 처리된다. 그래서 두 칸을 함께 읽어도 같은 버프가 두 번 잡히지 않는다.
- 영역(2026-10-28 수정 — 별도 영역 없음): 즐겨찾기를 늘리면 칸이 **아래로** 늘고 구분선이 내려간다(사용자). 그래서 즐겨찾기 칸을 고정 사각형으로 두지 않고,
  기존 버프 영역을 **상태목록창 맨 위(즐겨찾기 칸 포함)부터** 지정하게 한 뒤 매 판독(또는 변화 감지 때) **구분선을 찾아 선 위 = 즐겨찾기, 선 아래 = 목록**으로 나눈다.
  구분선이 없으면 전체를 목록으로 읽는다(즐겨찾기를 안 쓰는 사람·기존 영역 그대로 호환). 즐겨찾기가 늘어 구분선이 내려가도 목록 쪽으로 흐린 줄이 섞이지 않는다.

  영역 버튼 아래 인식 줄: 없으면 `즐겨찾기 칸 없음 — 구분선이 없으면 전체를 목록으로 읽어요`, 있으면 `즐겨찾기 칸 N줄 · 등록한 버프 M개: 이름(켜짐) · … — 구분선 아래는 목록으로 읽어요`.

- 높이를 저장하지 않는다(사용자 질문: 자동설정 때 즐겨찾기 높이 300px로 잡았다가 즐겨찾기를 늘려 340px이 되면?): 저장하는 것은 **바깥 영역 하나**뿐이고,
  위쪽은 상태목록창 맨 위(창을 옮기지 않으면 움직이지 않음), 아래쪽은 지금처럼 **화면 끝까지**(`status_panel.locate_status_region` — 버프가 늘어 아래로 길어져도 안 놓치게 상한 없음).
  즐겨찾기 칸 높이·목록 시작 위치는 저장값이 아니라 **매번 구분선 위치에서 계산**한다. 그래서 즐겨찾기를 늘려 선이 40px 내려가도 위 칸은 그만큼 길어지고 목록은 그만큼 아래에서 시작할 뿐, 다시 지정할 필요가 없다.
  기존 사용자처럼 영역 위쪽을 즐겨찾기 아래(`목록 맨 위`)로 잡아 둔 경우에도, 즐겨찾기를 늘려 선이 영역 안으로 들어오면 선 위 줄은 즐겨찾기로 처리돼 흐린 줄을 켜진 버프로 오인하지 않는다.
- 경계 판단(사용자 지적 — 위에서부터 줄 밝기로 즐겨찾기 끝을 정하면, 목록 맨 위 버프가 30초 이하 **점멸·반투명**일 때 흐린 즐겨찾기 줄로 오인): 
  즐겨찾기 칸의 끝은 **구분선 자체**로만 정한다(영역 너비 대부분을 가로지르는 얇은 가로선). 줄 밝기·아이콘으로 경계를 추정하지 않는다.
  구분선을 먼저 찾고 **선 위의 줄만** 즐겨찾기로 본다. 선 아래 줄은 흐려도 목록 규칙(기존 점멸 처리 포함)으로만 판단한다.
  구분선 위치는 기억해 두고, 그 자리에서 선이 안 보일 때만 다시 찾는다. 위치를 옮기는 것은 여러 프레임 연속으로 같은 새 위치가 확인될 때만(맵 이동·이펙트로
  화면이 순간 까매지거나 하얘지는 프레임에 흔들리지 않게). 회귀 자료에 목록 맨 위 버프가 점멸 중인 장면을 넣는다(없으면 실게임 수집).
- 판독: 지정(또는 다시 지정) 때 칸을 줄 단위로 나누고 줄마다 아이콘을 등록 버프와 맞춰 `줄 → 버프`를 기억한다(등록 안 된 줄은 무시).
  이후 매 판독은 기억한 줄의 **켜짐(밝음)/꺼짐(회색)** 만 판단한다 — 반투명 배경 영향을 줄이려 이름 글자 색(흰색/회색)을 우선 근거로 쓴다.
  켜진 줄은 기존 시간 판독기로 오른쪽 남은 시간을 읽는다. 표시·지속시간·종료 알림은 아래 목록 버프와 같다.
- 기준 버프(프리미엄 배틀 멤버십)가 즐겨찾기 칸에 있어도 정상으로 본다(`기준 버프 미검출` 경고를 띄우지 않음).
- 순서는 사용자가 게임에서 바꿀 수 있지만 드물다(사용자). 그래서 처음 한 번 읽은 `줄 → 버프`를 계속 쓰고, 줄 아이콘이 기억과 맞지 않으면
  **구분선 위 줄을 자동으로 다시 맞춘다**(사용자 조작 없음, app.log에만 기록). 다시 맞춰도 영역에서 즐겨찾기 줄을 못 찾을 때만
  상태 줄에 `즐겨찾기 칸을 찾지 못했어요 · 영역을 다시 지정해 주세요`.
- 성능: 줄별 픽셀 평균 몇 번 + 켜진 줄 시간 판독뿐이라 탐지 5ms 목표 안. Python 픽셀 반복문 금지 규칙 유지.
- 회귀: tests/data 스크린샷 8장(즐겨찾기 7줄, 켜짐 `환생시 체형 유지` 등/꺼짐 혼재, 밝은 사막·어두운 맵 배경)으로 켜짐/꺼짐 판정 테스트.
  시간 있는 버프를 즐겨찾기한 켜짐 장면은 아직 자료가 없어 실게임에서 확인한다.
- 화면: 기획 세션 렌더 목업(버프 탭 한 영역 + 인식 줄, 즐겨찾기 없음/인식 2상태) 기준.

### 3.2 디버프 트래커

| 항목 | 내용 |
|---|---|
| 입력 | 사용자가 지정한 디버프 줄 영역 (가로는 체력바 폭만큼 넉넉히) |
| 탐지 | 영역 안에서 등록 아이콘을 가로 검색 |
| 표시 | 등록 순서대로 **매칭되지 않은 디버프만** 가로 나열. 오버레이는 항상 표시 |
| 앵커 | 없음 (보스가 없으면 "전부 안 걸림"으로 보이는 게 의미상 맞음) |
| 안정화 | 숨김은 즉시, **다시 표시는 1.5~2초 연속 미감지일 때만** |
| 지속시간·알림 | 없음 |

### 3.3 알림 (버프 연장 타이밍)

- 별도의 "버프 연장" 기능이나 수동 TTL 입력은 만들지 않는다. **연장이 필요한 시점에 알림만** 준다.
  - 마비노기에서 "다시 걸기"와 "연장"은 같은 의미(지속시간을 늘림)로 쓰이므로, 알림 문구는 "연장"으로 통일한다.
- 조건: 내부 시계 기준 남은 시간 ≤ 버프별 기준값 → **아이콘 점멸 + 알림음 1회**.
- 남은 시간 증가 감지 = 연장 성공 → 알림 자동 해제.
- 2026-10-15 추가 승인: 시간 증가 후보를 확인하는 동안 기존 시계의 1차/2차 알림은
  최초 후보부터 최대 200ms만 보류한다. 정상 판독으로 돌아오면 즉시 해제하고,
  확인되지 않거나 후보가 계속 바뀌어도 기한을 갱신하지 않는다. 연장 확정 후 다음 임박 알림은 유지한다.
- 버프 사라짐 = 연장 실패 → 점멸 종료, 표시 제거.
- Windows 토스트 알림은 쓰지 않는다 (게임 중 방해 금지 모드로 묻힘).
- 지속시간 표시를 끈 버프는 알림 설정 불가.
- 확장 여지: 단계별 알림(예: 30초 점멸, 10초 점멸+소리).

#### 알림음 방식 (버프별 등록 사운드)

> **결정 변경**: TTS는 과하다고 판단해 폐기. 대신 **버프마다 미리 준비한 사운드 파일**을
> 재생한다. 사운드가 등록된 버프에만 "소리"/"2차 알림" 옵션이 노출되고(없으면 숨김),
> 소리 없는 버프는 점멸만 쓴다(점멸은 임박 구간 내내 지속되므로 2차 알림은 무의미).

- buff_id → 사운드 파일 매핑(`ui/notifier.py`의 `DEFAULT_SOUNDS`). 파일이 실제로 있는
  버프만 "소리 있음"으로 취급.
- 재생은 `SoundNotifier`(QtMultimedia `QMediaPlayer`). mp3 지원, 백엔드 없으면 조용히 무음.
  탐지 스레드가 아니라 메인 스레드(알림 콜백)에서 재생.
- 2차 알림: 더 가까운 시점에 같은 사운드를 한 번 더(놓침·오독 대비). 소리 있는 버프 전용.
- (향후 아이디어) 사용자가 버프별로 직접 사운드 파일을 넣어 알림음을 추가하게 할 수 있음.
- 배포 시 사운드도 패키지 자산으로 번들.

### 3.4 오버레이

- 항상 위, 배경 투명, **클릭 통과**(`WS_EX_TRANSPARENT | WS_EX_LAYERED`), 포커스 안 뺏음(`WS_EX_NOACTIVATE`).
- 위치 편집 모드에서만 드래그 이동 가능.
- 버프/디버프 각각 **배율 50~300%**. 표시에만 적용, 탐지와 무관.
- 아이콘 확대 방식 기본값: Nearest (작은 아이콘을 선명하게). Bilinear 선택 가능.
- 지속시간 글자는 폰트로 직접 그린다.
- **마비노기가 포그라운드일 때만 표시**. 자기 프로그램 창(설정 창, 편집 모드 오버레이)도 활성으로 간주.

### 3.5 파티모집현황 + 키워드 알림

섯다라인 디스코드 봇의 "인게임 파티모집현황 / 키워드 알림" 기능을 이 앱으로 옮긴 것.
버프/디버프와 달리 **화면 캡처가 아니라 넥슨 공식 오픈 API를 읽는다** → "읽기만 한다" 규칙에 부합하고,
맥에서도 테스트 가능하다(네트워크만 있으면 됨).

#### 데이터 출처

- 넥슨 오픈 API 거뿔(월드 외침) 기록:
  `GET https://open.api.nexon.com/mabinogi/v1/horn-bugle-world/history?server_name=하프`
  헤더 `x-nxopen-api-key: {키}`. 응답 `horn_bugle_world_history[]`: `message`, `character_name`, `date_send`.
- **서버는 하프 고정.**
- **API 키는 앱이 제공한다**(사용자가 입력하지 않는다). 파티모집현황은 앱이 주는 기능이므로,
  키는 앱에 귀속된다. 개발·본인용은 `.env`의 `NEXON_API_KEY`로 쓰고 git에 커밋하지 않는다
  (`.env.example`만 커밋). 배포 시엔 빌드 단계에서 `.env` 또는 CI secret으로 번들한다.
  키 탐색 순서: `.env`/환경변수 → `config.local.json`(개발 편의용 폴백).
  - ⚠️ 보안: exe에 키를 번들하면 추출될 수 있다(문자열/디컴파일). 노출을 피하려면 중계 서버를
    두고 앱은 그 서버를 호출하는 방식이 안전하다. 배포 규모에 따라 번들/중계 중 선택(추후 결정).
- 폴링 주기 약 5초. 백그라운드 스레드에서, UI를 막지 않는다.

#### 파티모집 파싱

- 파티모집 = `message`가 `"{character_name} : #"`로 시작하는 외침.
- 형식: `"{캐릭명} : #[채널N] 내용 [현재/모집명]완?"`
  - `채널N` = 채널 번호, `내용` = 제목(채널·인원·완 제거), `[현재/모집]` = 인원, `완` 또는 현재==모집 → 완료.
- 현황 리스트: **파티장(캐릭)별 최신 1건**만 묶고(같은 사람이 인원 채우며 반복 외친 중복 제거), 모집 중인 파티장은 **최신순으로 전부** 표시(상한 없음). `listSize`를 주면 그 수로 자를 수 있다(기본 무제한).

#### 파티 탭 (신설)

- 리스트 한 행 = `채널 | 파티장 | 제목 | 인원`. **인원은 오른쪽 정렬.** 완료 파티는 표시(✅) 또는 흐리게.
- 키워드 등록/삭제 UI(1인용이라 목록 하나). 매칭 대상은 **제목(내용)**.
- **파티장 제외** 목록: 등록한 캐릭터명(파티장)의 모집은 **현황 리스트·키워드 알림 양쪽에서 숨긴다**. 캐릭명 완전 일치.

#### 키워드 매칭 → 토스트 알림

- 폴링마다 **최근 5분 이내** 신규 모집에서, 제목에 등록 키워드가 포함되면 알림.
- 중복 억제: **5분 슬라이딩 TTL + 서명(채널 + 숫자·캐릭명 제거한 내용)** → 파티당 1회. (봇의 `partyAlerts` 로직 그대로)
- **시작 시 프라이밍**: 앱 켠 직후 첫 폴링은 지금 떠 있는 모집을 '이미 봄'으로 기록만 하고 토스트를 띄우지 않는다. 그 뒤 폴링부터 **새로 올라온 모집만** 알림(시작 시 최근 몇 분치가 한꺼번에 뜨는 것 방지).
- **토스트**: 직접 그리는 프레임리스 창(네이티브 Windows 토스트 아님 → 위치·지속·최상위를 완전히 제어, 집중지원 모드에 안 묻힘).
  - 위치 **화면 우측 하단**, **항상 최상위**, **5초 후 자동 소멸**.
  - **클릭하면 즉시 닫는다**(dismiss). 할 동작이 없으므로 수동으로 치울 수 있게만 한다.
- 참고: 3.4의 "Windows 토스트 안 씀"은 **전투 중 버프 만료 알림** 맥락이다. 파티 알림은 전투 중이 아니므로 토스트를 쓴다(별개 규칙).
- (옵션, 봇에 있음) 알림 받을 **시간대 설정** — 추후 확장.

### 3.6 커스텀 오버레이(미러링)

화면의 특정 영역(예: 단축바, 쿨다운 바)을 드래그로 지정해, 실시간으로 **다른 위치에
미러링(PiP)** 해서 보여준다. 화면을 **읽기만** 하므로 "읽기 전용" 규칙에 부합한다.
탭 이름은 "커스텀 오버레이", 복제된 개별 항목을 **오버레이**, 오버레이 묶음을 **프리셋**
이라 부른다.

| 항목 | 내용 |
|---|---|
| 소스 | 드래그로 지정한 화면 영역(여러 개 가능) |
| 오버레이 | 복제 창(드래그 이동·고정·클릭 통과). 라벨 = `오버레이N (캡처한 프로그램)` |
| 프리셋 | 오버레이 묶음 저장 → 캐릭터별로 불러오기로 전환 |
| 저장 범위 | 각 오버레이의 소스 영역 + 띄운 위치 + 고정 상태 (config `customOverlay`) |

**UI (탭)**: `[복제할 영역 추가]` → 적용 중 프리셋/자동 저장 상태/`[다른 이름으로 저장]`
→ 프리셋 목록(`[불러오기] [선택 프리셋 삭제]`) → 시작 시 자동 불러오기 선택
→ 현재 오버레이 표(이름/원본 영역/표시 배율/위치 잠금) → 선택/전체 잠금·잠금 해제·삭제
→ 접힌 캡처 호환성. 삭제 버튼은 빨강. 적용 대상과 목록 선택, 시작 대상은 서로 독립이다.
현재 구성을 편집하면 적용 중 프리셋에 자동 저장하며, 전환/종료 전에 반영한다.
원본을 보존하는 변형은 다른 이름으로 저장한 뒤 편집한다. 저장 실패 시 편집 내용과
마지막 정상 파일을 보존하고 재시도를 제공한다. 상세 전환 조건은 사용성 개선 명세 5절을 따른다.

**캡처(개수 확장성 핵심)**: 공유 캡처로 **전체 프레임 1회 grab**(mss) → 각 오버레이가
자기 소스 영역만 crop. 미러 개수와 무관하게 캡처 비용 일정(12개도 grab은 1회).
단일 타이머 + **fps 15~20 캡**으로 갱신 비용 상한. 캡처는 `MirrorManager`, 창은
`MirrorOverlay`.

**구현 결정 — 창 N개 (vs 단일 캔버스)**: 당초 "투명 캔버스 1개" 안을 검토했으나,
**미러별 클릭 통과**가 단일 창에선 사실상 불가(창 단위 WS_EX_TRANSPARENT, SetWindowRgn은
paint까지 클립)하다. v1은 **오버레이 창 N개**(각자 클릭통과 독립)로 가고, **캡처만 공유**
(1 grab + crop)해 핵심 비용을 억제한다. DWM 합성 비용이 문제되면(수십 개) 단일 캔버스+
히트테스트로 재검토. 재사용 부품: `RegionSelector`(영역 지정, 돋보기), `clickthrough`.

**미연결/후속**: 시작 시 자동 복원은 하지 않음(현재 세션에서 추가·불러오기). 배율(크기
조절)은 v1 1:1 고정. (아이디어) 드래그 시 격자 스냅.

## 4. 탐지 설계

### 4.1 파이프라인

```
FrameSource(캡처) → Detector(이미지 → 판정) → Tracker(상태 머신 + 내부 시계) → Overlay / Notifier
```

- `FrameSource` 인터페이스로 캡처를 분리한다.
  - `FileFrameSource`: 스크린샷 폴더 (맥 개발)
  - `VideoFrameSource`: 플레이 영상 (맥 개발)
  - `LiveCaptureSource`: dxcam 영역 캡처 (Windows)
- `WindowWatcher` 인터페이스로 포그라운드 감지를 분리한다.
  - `WindowsWatcher`: `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` 이벤트 방식
  - `AlwaysActive`: 맥 개발용

### 4.2 아이콘 매칭

- `cv2.matchTemplate` + `TM_CCOEFF_NORMED` (밝기·대비의 선형 변화에 강함 → 반투명, 단색 배경 대응).
- 템플릿은 시작 시 한 번만 전처리해서 메모리에 올린다.
- 등록과 탐지가 같은 좌표 규칙으로 아이콘을 자르도록 한다 ("상태창에서 가져오기").

### 4.3 시간 판독

- 범용 OCR(Tesseract/EasyOCR) 사용 안 함.
- 숫자 0~9와 단위(`일`, `시간`, `분`, `초`) 템플릿 매칭. 디버프용 `M`도 필요 시 추가.
- 밝기 기준 이진화 후 매칭 (흰색·빨간색 글자 모두 대응).
- 매칭된 행에서만, 1초 주기로 판독.

### 4.4 프레임 판정 3상태

| 결과 | 조건 | 처리 |
|---|---|---|
| 감지 | 아이콘 매칭 | 활성 유지, 시간 갱신 |
| 미감지 | 정상 프레임인데 아이콘 없음 | 사라짐 후보 카운트 |
| 판정 불가 | 앵커 미검출, 게임 비활성 | 상태 동결, 내부 시계만 진행 |

보조 판정 불가 조건: 영역 밝기 극단값(블랙아웃·화이트 플래시), 여러 버프 동시 소멸.

### 4.5 버프 상태 머신

```
[없음] ──N프레임 연속 감지──▶ [활성] ──남은시간 ≤ 기준──▶ [만료임박: 점멸+소리 1회]
  ▲                              │  ▲                          │
  └── 사라짐 판정 ───────────────┘  └── 시간 증가(연장) ────────┘
```

- **점멸 대응**: 최근 1~1.5초 프레임의 매칭 점수 중 **최고값**으로 판정. 캡처 주기는 점멸 주기보다 충분히 짧게(0.1~0.2초), 에일리어싱 주의.
- **추적 유지**: 이미 추적 중인 버프는 같은 행 시간 글자가 정상적으로 줄어들면 생존으로 본다. 목록이 당겨질 수 있으므로 기억한 y 주변을 재검색, 화면 복귀 후엔 아이콘 열 전체 재검색.
- **내부 시계**: 마지막 정상 판독값 − 경과 시간으로 계속 카운트다운. 알림은 내부 시계 기준이라 화면이 안 보여도 울린다. 판독값이 크게 늘면 연장으로 보고 보정.
- **사라짐 판정**:
  1. 내부 시계 ≤ 0 이고 정상 프레임에서 미감지 → 만료
  2. 내부 시계는 남았는데 정상 프레임에서 2초 이상 연속 미감지, 다른 버프는 보임 → 중간 해제
  - 판정 불가 구간만으로는 사라짐 처리하지 않는다.

### 4.6 앵커

- 앵커 매칭 = 정상 프레임, 실패 = 판정 불가.
- 앵커는 설정에서 변경 가능(`anchor: true`, 하나만).
- 앵커가 30초 이상 안 보이는데 다른 버프는 매칭되면 "앵커 미검출" 경고 (멤버십 만료 대비).

### 4.7 게임 비활성 시

| 항목 | 동작 |
|---|---|
| 화면 탐지 | 정지 (판정 불가) |
| 내부 시계 | 계속 진행 |
| 오버레이 | 숨김 |
| 소리 알림 | 울림 (설정으로 끌 수 있음) |

```
┌─ 마비노기 버프 트래커 ─────────────────────────────────────────────┐
│ [버프] [디버프] [설정]                                 ● 실행 중 ■ │
├────────────────────────────┬───────────────────────────────────────┤
│ [ 버프 영역 지정 ]          │  이름                                 │
│  영역: 1770,400 220×550 ✔  │  [ 마법 대미지 증가          ]        │
│ ┌────────────────────────┐ │  매칭 아이콘                          │
│ │ ⚓ 배틀 멤버십 (앵커)   │ │  [▣]  [ 상태창에서 가져오기 ]         │
│ │ ▣ 마법 대미지 증가     │ │  보여줄 아이콘                        │
│ │ ▣ 골렘의 의지          │ │  [▣]  [ 파일 선택 ] [ 초기화 ]        │
│ │ ⚠ 새 버프 (아이콘 없음) │ │   └ 비워두면 매칭 아이콘 사용        │

│                            │  ☐ 앵커로 사용 (항상 있는 버프)        │
└────────────────────────────┴───────────────────────────────────────┘
```

- `+` 맨 끝에 추가 후 선택, `-` 삭제(확인), `▲▼` 순서 이동, 드래그 앤 드롭 지원.
- 기본 순서 = 등록 순서. 순서는 설정 파일 **배열 순서**로 저장 (별도 order 필드 없음).
- 변경 즉시 자동 저장 + 오버레이 반영.
- 디버프 탭: 이름, 매칭 아이콘("영역에서 가져오기"), 보여줄 아이콘만.

### 5.2 영역 지정

- 버튼 → 전체화면 반투명 오버레이 → 드래그 → 좌표 저장. ESC 취소.
- Windows에서는 시작 시 DPI 인식(`SetProcessDpiAwareness(2)`)을 켜서 모든 좌표를 실제 픽셀로 통일.
- 확장: 마비노기 창 기준 상대 좌표로 저장 (창 이동 대응).

### 5.3 설정 탭

```
[일반]
 ☑ Windows 시작 시 자동 실행
 ☑ 실행 시 트레이로 시작
 ☑ 닫기(X) 버튼을 누르면 트레이로 최소화
 ☑ 게임 비활성 중에도 소리 알림
[오버레이]
 버프 배율 [150%]  디버프 배율 [100%]  아이콘 확대 방식 [Nearest]
 [ 오버레이 위치 편집 ]
[게임]
 마비노기 창 식별 [ ... ] [ 자동 찾기 ]
```

- 자동 실행: `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`에 `"<exe 경로>" --tray`. 실행할 때마다 현재 exe 경로로 갱신.
- 트레이 메뉴: 열기 / 탐지 시작·정지 / 오버레이 위치 편집 / 종료. 더블클릭으로 창 열기.
- **중복 실행 방지**: 이미 실행 중이면 새 프로세스는 종료하고 기존 창을 띄운다 (`QLocalServer` 또는 named mutex).

## 7. 비기능 요구사항 (성능)

| 항목 | 목표 |
|---|---|
| CPU | 평균 2% 안팎(1~2% 이하 목표), **최대 5%**, 게임 비활성 시 거의 0%. 앱이 실행하는 하위 프로세스(블랙박스 `ffmpeg` 등)를 포함한 합계(2026-10-25 사용자 재확인) |
| 메모리 | 80~150MB |
| 탐지 1회 | 5ms 이하 |

- 지정 영역만 캡처.
- 주기: 버프 아이콘 0.2초 / 시간 판독 1초 / 디버프 0.3~0.5초 / 비활성 시 정지.
- `cv2.setNumThreads(1)`, `OMP_NUM_THREADS=1` (작은 이미지에서 멀티스레드는 오히려 CPU 스파이크).
- 탐지는 백그라운드 스레드 1개, 오버레이는 상태가 바뀔 때만 다시 그림. 점멸 타이머는 알림 중일 때만.
- 프로세스 우선순위 BELOW_NORMAL.
- `opencv-python-headless` 사용 (일반판은 PySide6와 Qt 충돌).
- 프레임 이미지는 보관하지 않고 점수만 링버퍼에 보관. 캡처 버퍼 재사용.
- 설정 탭에 숨김 디버그 패널 (처리 시간 ms, fps, CPU %, 메모리).

## 11. 미확인 사항

1. 상태창 투명도 옵션 유무
2. 점멸 시 시간·이름 글자도 같이 점멸하는지, 점멸 주기
3. 빨간 글씨가 몇 초 이하부터인지
4. 디버프 아이콘도 점멸하는지, 같은 디버프가 여러 개 뜰 수 있는지
5. 디버프가 많을 때 체력바 폭을 넘거나 두 줄이 되는지
6. 상태목록창이 넘칠 때 스크롤되는지
7. 같은 아이콘을 쓰는 다른 버프가 있는지
8. 게임 UI 배율 옵션 유무
9. 마비노기 창 제목·프로세스 이름

## 12. 보스 패턴 경고 (DBM 스타일) — 설계 초안

와우 DBM처럼, 보스 HP%가 특정 패턴 진입점에 다다르면 화면 중앙에 큰 경고를 띄운다.
패턴 데이터(보스 이름 + 임계%별 문구)는 **제작자가 미리 만들어 번들**로 넣고, 런타임은
보스 이름을 자동 인식해 해당 패턴셋을 쓴다. 새 보스는 업데이트로 추가. (읽기 전용 원칙 유지)

### 12.1 화면 근거 (실측: tests/data/스크린샷 2026-10-09 18*.png, 2560×1440)
- 보스 HP바는 **화면 하단 중앙에 고정**. 왼쪽=보스 이름(흰 굵은 글씨), 오른쪽=`XX.XX %`(숫자).
- **바 색은 HP%에 따라 변한다** → 색 기반 자동탐지는 불가.
- 이름은 **페이즈마다 바뀐다**: 예) `레넨의 미이르` → `레넨의 미이르 : 회한`. 패턴셋은 "보스:페이즈" 단위.
- 보스 디버프 아이콘은 이 바 '바로 위'에 뜬다(디버프 트래커와 인접).

### 12.2 판독 방식 (핵심: 밝기 임계 이진화) — 실측 검증됨
- HP바는 **길이로 % 표시 안 함**(길이 고정, 뒤 색만 변함) → 막대 길이 측정 불가. **숫자 판독 필수**.
- 글자(이름/숫자)는 **흰색**이라, 영역을 그레이스케일 후 **밝은 픽셀만 임계(≈200)**로 남기면 바 배경색(보라/파랑 등)과 무관하게 글씨만 깨끗이 분리된다(보라/파랑 둘 다 흰비율 0.03로 일정, 검증 완료).
  - (주의: 기존 `binarize`는 밝은 배경에서 폴라리티가 뒤집힌다 → HP바 전용 밝기 임계를 쓴다.)
- **이름 식별**: 임계화한 이름 영역을 번들 이름 템플릿과 매칭(가장 잘 맞는 보스:페이즈, 임계 미달이면 '미식별').
- **HP% 판독**: 임계화한 % 영역을 0~9 숫자 템플릿으로 판독. 숫자가 커서(≠버프 7px) 폰트 달라도 리스크 낮음. `.` 앞 **정수부만** 쓰면 충분.
- **숫자/이름 템플릿은 이 HP바 전용으로 수집.** 실측 데이터 확보: 숫자 0~9 (tests/data 100%의 '1','0' + 2026-10-09 19* 7장의 98.34/97.45/94.93/93.34/92.52/90.89/96.35).

### 12.3 영역 (수동 지정 최소화)
- 바가 화면 고정이므로 **해상도 기준 기본 위치**(하단 중앙 앵커)를 계산해 기본값으로 쓴다 → 표준 UI면 수동 지정 불필요.
- 게임 UI 배율/해상도가 특이하면 **수동 미세조정**(기존 영역 지정 재사용)으로 폴백.
- 색 기반 자동탐지는 쓰지 않는다(색 변동).

### 12.4 패턴 데이터 (번들, 제작자 관리) — 임계값만 입력
```
assets/boss/<boss_id>/
  name.png        # 이진화 전 원본(로드 시 이진화) — 이름 식별 템플릿(페이즈별 별도 id)
  patterns.json   # {"name": "고목의 페타크", "thresholds": [85, 35]}
```
- 제작자는 **보스 이름 + 임계% 목록만** 입력한다. 패턴 설명/문구는 없음.
- **각 임계값 T마다 HP 감소 방향으로 2번 경고**(오프셋은 앱 고정 기본값 +5 / +1):
  - **1차 예고**: HP가 `T+5`% 도달(85→90%) → 소리 **010**
  - **2차**: HP가 `T+1`% 도달(85→86%) → 소리 **026**
  - 각 1회. 페이즈 리셋 등으로 HP가 그 위로 다시 오르면 재무장.
- **문구는 자동**: `"<보스이름> <T>% 진입 준비"` (1·2차 동일). 예: "고목의 페타크 85% 진입 준비".
- 알림음: `010`=1차(예고), `026`=2차. (tests/data의 universfield-*-010/*-026)
- 오프셋(+5/+1)·문구 형식은 기본값이며 차후 설정화 가능.

### 12.5 경고 표시
- 화면 중앙 **큰 글씨 오버레이**(클릭 통과, 항상 최상위) + 소리. 수 초간 표시 후 사라짐.
- 세부(글씨 크기/색/지속/점멸)는 기본값 두고 설정에서 조정 가능하게(차후).

### 12.6 제작자 워크플로 (새 보스 추가)
- 앱의 "보스 등록" 모드 또는 `scripts/` 등록 도구: 이름 영역 캡처 → 임계% 목록 입력 → `assets/boss/`에 저장 → 번들 커밋.

### 12.7 단계
- **Phase 1**: HP바 영역(기본 위치) → HP% 판독 → 패턴셋(수동 선택 또는 단일) → 2단계 중앙 경고. (이름 자동식별 없이)
- **Phase 2**: 이름 템플릿 매칭으로 보스 자동 식별 → 패턴셋 자동 전환.
- **Phase 3**: 제작자 등록 UI + 번들 보스 DB 축적.

### 12.8 미확인/결정 필요
- HP%가 페이즈 전환으로 '리셋'될 때(다시 100%로) 경고 재무장 규칙 — HP가 임계+오프셋 위로 오르면 재무장으로 처리.
- 다중 보스(동시 2마리 이상) — 당장은 단일 HP바 가정.
- 경고 지속시간·글씨 크기/색 기본값(오프셋 +5/+1은 확정).

복구 기록이 남아 있어도 비제작자/로그아웃 상태에 복구 전용 탭이나 설정 버튼을 노출하지 않는다.
제작자로 다시 확인되면 같은 최적화 탭에서 명시적으로 복구한다. 로그아웃/종료 시 CPU 자동 원복과
소유 FPS 수집 정리, 미복구 네트워크 기록 보존은 유지한다. 네트워크 원복 안내/실행은 탭의 원복 버튼에서
진행하며 탭 밖 자동 팝업으로 대체하지 않는다. 앞선 비제작자 복구 예외 시안보다 이번 사용자 정정이 우선한다.
