독립 재현은 `scripts/qa_tracker_stability.py`이며 둘 다 수정하지 않았다.

## 재현과 수정

- 원본 독립 재현: **2 failed, 13 passed (0.46초)**.
- `STAT-STABILITY-QA-01`: 진단용 부분 띠의 잠정 이름을 실제 HP/MP/STA로 사용했다.
  판독기에 `require_complete=True`를 추가해 정확히 세 띠일 때만 정체를 확정한다.
  실행 표시/알림, 수집 파일명, 자동찾기 검증에 같은 조건을 적용한다. 진단용 기본 API의
  부분 띠 결과는 유지하고 이름이 잠정 순서임을 명시했다. 고정 색상 식별로 바꾸지 않았다.
  불완전하면 잘못된 값으로 덮어쓰지 않고 바를 숨기며 상태는 `현재 값: —`로 표시한다.
  첫 캡처부터 불완전해도 기본 100% 바를 보여주지 않는다. 정상 세 띠가 돌아오면 재개한다.
- `STAT-STABILITY-QA-02`: 캡처 실패/비활성/영역 없음/기능 중단 때 연속 저값 확인 시각을
  비운다. 기능 끄기/일시정지/영역 재지정/종료도 같은 보류 상태를 정리한다.
  `_alert_armed`는 미관측만으로 바꾸지 않는다. 정상 회복이 관측되어야 재무장한다.
- 세 바 중 어느 바를 가려도 남은 값을 다른 자원으로 표시하지 않는 것, 네 띠 거부,
  캡처 실패·비활성·일시정지·사용 해제·영역 없음·보스 해제 후 새 0.4초 확인,
  이미 발화한 뒤 같은 미관측 구간을 거쳐도 재발화하지 않는 것과 실제 회복 후 재발화를
  실제 PNG/탭/오버레이에 주입하는 회귀로 추가했다.

  검사가 함께 포함된다. 원본 QA의 확정 결함 두 재현도 수정 없이 통과했다.

## 범위 구분

- 보스 경고 `BOSS-STABILITY-QA-01`은 조건부 상승 입력에서 기존 재무장 경로가 있다는
  위험 보고다. 실제 HP 회복도 지원해야 하므로 근거 없이 상승 무시/새 임계를 추가하지 않았다.
  독립 재현의 조건부 경로와 실제 리셋/정상 감소 검사를 함께 유지한다. 라이브 상승 오독이
  확인되면 해당 연속 입력으로 정책을 정한다.
- 연속 진단 기록 제안은 새로운 기능 범위이며 이번 수정에서 무제한 로깅/상시 캡처를
  추가하지 않았다. `stat-bar-shake-warning-spec.md`는 확인했지만 이번 QA 수정과 별개다.
  흔들림 효과와 움직임 수치는 구현/확정하지 않았다.
- 제작자 잡담 개발 커밋과 함께 반영한다. Windows 실제 캡처/게임/혼합 DPI/장시간 검증을
  Linux 테스트 통과로 대체하지 않으며 새 푸시 SHA의 Windows 자동 검증은 별도 확인한다.
