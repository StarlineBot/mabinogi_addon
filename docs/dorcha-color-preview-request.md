# 도르카 숫자 가독성 비교 시안 요청

- 날짜: 2026-10-16.
- 상태: **비교 시안 요청, 최종 색상 정책 미확정**. 먼저 실제 렌더를 보여주고 사용자 선택을 받는다.
- 배경: 사용자는 빨간색으로 저잔량임을 알아도 정작 몇 개인지 읽기 어려울 수 있다고 지적했다.
  가장 중요한 것은 정확한 현재 잔량을 빠르게 읽는 것이며 색상 경고는 보조 정보다.
- 이 문서는 이전 QA 전달의 '채운 칸과 N/15를 모두 단계색으로 변경' 추천을 대체한다.
  N만 색을 바꾸는 추천도 확정안으로 구현하지 않는다.

## 모든 시안의 공통 조건

- 채워진 칸은 **도르카 컨셉의 보라색**, 빈칸은 어두운 회색으로 유지한다.
  1/15일 때는 첫 칸만 채워지고 뒤의 14칸은 그대로 비어 있어야 한다.
- 15칸과 5칸 묶음 구분, 숫자 위치, 크기, 간격은 기존과 동일하게 유지한다.
- 같은 값/배경/배율/글자 크기로 비교한다. 특정 안만 글자를 키우거나 배경을 어둡게 하지 않는다.
- 숫자는 검은 외곽선 등 현재 대비 처리를 유지한다. 진한 빨강처럼 명도가 낮은 글자색은 피한다.
- 점멸·소리·흔들림·잔량 추정이나 판독 방식 변경을 이 시안에 섞지 않는다.

## 비교할 세 가지 안

| 안 | 숫자 표현 | 단계색 위치 | 비교 목적 |
|---|---|---|---|
| A: 가독성 우선 추천 | N/15 전체 흰색 + 검은 외곽선 | 숫자 옆 작은 고정 크기 상태 표시 | 숫자 명도는 유지하고 잔량 단계는 보조 표시로 구분 |
| B: 전체 숫자 색상 | N/15 전체 밝은 단계색 + 검은 외곽선 | 숫자 전체 | 경고색을 쓰면서 숫자 덩어리가 한 번에 읽히는지 확인 |
| C: 현재 값만 색상 | N만 밝은 단계색, /15는 고정된 밝은 회색 + 검은 외곽선 | 현재 값 N | 숫자가 시각적으로 분리돼 오히려 읽기 어려워지는지 비교 |

세 안 모두 바는 보라색이다. A의 상태 표시는 숫자를 가리거나 바와 겹치지 않아야 하며
값 전환으로 나타났다 사라지며 숫자/바 위치를 밀지 않도록 공간을 고정한다.
상태 표시의 정확한 모양과 크기는 시안으로 확인하며 아직 승인된 UI 요소가 아니다.

## 값과 단계 예시

- 한 화면에서 같은 값의 A/B/C를 나란히 보여준다. 대표 값은 **1/15, 5/15, 8/15, 15/15**다.
- 비교 시안의 임시 구간은 0~5 빨강 / 6~10 노랑 / 11~15 녹색이다.
  **구간 경계와 색상값은 최종 확정이 아니라 비교용 가정**이며 사용자 확인 후 명세에 반영한다.
- 별도로 **0/15와 --/15**를 보여준다. 0은 실제 값, --는 판독 불가다.
  미판독을 빨간 저잔량으로 표현하지 않고 상태 표시는 중립 회색으로 한다. 두 경우 모두 채움은 없다.

## 개발 세션이 보여줄 예제

1. 기존 Qt 오버레이 렌더 경로를 활용해 세 안을 **실제 PNG로 렌더**한다. 텍스트 설명이나 색상 코드만 전달하지 않는다.
2. 저장소의 실제 게임 원본 중 밝은 배경과 어두운 배경 위에서 비교한다.
   앱 설정의 미리보기 패널 안에서만 잘 보인다는 이유로 판단하지 않는다.
3. 우선 현재 사용 중인 기본 150% 배율에서 대표 값 네 개의 비교표를 보여준다.
   이미지 축소로 판단이 흐려지지 않도록 **한 자리/두 자리 숫자의 실물 크기 원본 크롭**도 함께 제공한다.
4. 사용자가 안을 고르면 작은 배율, 0/9/10/15 전환 및 최대 배율에서도 잘림/겹침/위치 이동이 없는지 검증한다.
5. 사용자의 시안 확인 전에는 특정 안을 최종 정책으로 확정하거나 앱에 일괄 적용하지 않는다.

## 확인 질문과 완료 기준

- 빨강을 보고 '낮다'고 아는 것뿐 아니라 **1인지 5인지 곧바로 읽히는가?**
- /15까지 함께 읽히는가, N만 강조한 안은 읽는 흐름을 방해하지 않는가?
- 흰색 숫자와 비교해 밝은 단계색 숫자의 선명도가 떨어지지 않는가?
- 배경이 바뀌어도 숫자와 보라색 채움의 경계가 유지되는가?
- 추가 상태 표시의 이점이 있는가, 좁은 오버레이를 불필요하게 복잡하게 만들지는 않는가?

완료는 **시안 이미지 제시 및 사용자 선택**이다. 이 문서 갱신은 시안 제작 완료나
제품 변경·독립 QA 통과·라이브 검증 완료를 뜻하지 않는다.
