# 판독 영역을 게임 창 기준으로 저장 (창 모드에서 창 이동 대응)

- 결정일: 2026-10-31. QA 요청(방식 결정)에 사용자가 결정했다. [기획서](기획서.md) 5.2 '확장: 마비노기 창 기준 상대 좌표로 저장'을 확정한 것이다.
- 버전: 새 기능 → **0.33.0**(2026-10-31 사용자 결정: 0.32.0은 버프·디버프 오버레이 창 보이기). 같은 차수의 [그림대화](sketch-chat-spec.md)와 함께 나가면 한 번호로 묶는다.
- 선택: **A안**. 게임 화면(클라이언트 영역) 왼쪽 위를 기준으로 한 상대 좌표로 저장하고, 창 이동을 따라간다.
  - B안(창 이동 때 '다시 찾을까요?' 안내)과 C안(게임 창 자체 캡처)은 채택하지 않았다.

## 1. 동작

- **저장** = 영역의 화면 좌표 − 게임 화면 안쪽 왼쪽 위(`ClientToScreen(hwnd, (0,0))`, 물리 픽셀). 창 테두리·제목줄이 아니라 **클라이언트 영역** 기준이다.
- **읽기** = 지금 게임 화면 원점 + 저장값.
- 상태 타이머(0.7초)에서 게임 창 원점을 함께 읽는다. 원점이 바뀌면 각 기능의 캡처 영역을 새 좌표로 갱신하고, 사용자에게 알리지 않는다.
- 전체 화면·테두리 없는 창은 원점이 모니터 왼쪽 위라 결과가 지금과 같다.

## 2. 세부 결정 (QA 제안 채택)

1. **창 크기 변경은 대응하지 않는다**(사용자 결정).
   - 마비노기는 창을 줄이면 게임 안 창이 크기는 그대로인 채 가장자리로 밀리고, 다시 키워도 밀린 자리에 남는다. 게임 안 창을 사용자가 옮긴 것과 같아 계산으로 맞출 수 없다.
   - 크기 변경 안내나 자동 찾기를 하지 않는다. 판독이 안 되면 사용자가 지금처럼 다시 지정하거나 자동 찾기를 한다.
2. **오버레이 표시 위치는 따라가지 않는다.** 게임 밖에 두는 사용자가 있어서다. 판독 영역만 따라간다.
3. **메모 표시 위치·너비는 따라가지 않는다.** 판독이 아니라 표시 위치이므로 2항과 같게 한다.
4. **단축바 원본(anchor)과 각 기능의 자동 찾기 결과**도 같은 규칙(상대 좌표)으로 저장한다.
5. **게임 창을 못 찾을 때**(게임 미실행·등록 창 없음): 마지막으로 알던 원점으로 계산하고, 저장값은 건드리지 않는다.
6. **최소화 중**(`IsIconic`): 원점을 갱신하지 않는다. Windows는 최소화된 창 위치를 (-32000, -32000)으로 알려 주므로, 그대로 쓰면 영역이 화면 밖으로 튄다.
7. **좌표 단위**는 기존 블랙박스·오버레이처럼 물리 픽셀로 통일한다.

## 3. 대상 영역

`ui/region_registration.REGIONS`의 판독 영역이 대상이다.
- 버프·디버프 판독
- 공유 보스 체력바
- 전투 제한 시간(헤일로)
- 체력·마나·스태미나
- 단축바 원본(anchor)
- 도르카, 투아림

메모(표시 위치·너비)는 3항에 따라 대상이 아니다.

## 4. 기존 사용자 이관 (한 번만)

| 사용자 | 이관 결과 |
|---|---|
| 전체 화면·테두리 없는 창 | 원점이 모니터 왼쪽 위라 **값이 그대로**. 체감 변화 없음 |
| 창 모드, 지정한 뒤 창을 안 옮김 | 정확히 변환됨. 이후부터 창 이동을 따라감 |
| 창 모드, 지정한 뒤 창을 옮겨서 **이미 어긋나 있음** | 어긋난 채로 변환됨. 지금과 같은 상태이며 다시 지정하면 해결되므로 새 문제는 아님 |

- **시점**: 새 버전에서 게임 창(클라이언트 영역)이 처음 잡힐 때 **9종을 한 번에** 변환한다(0.24.0 아이콘 이관과 같은 일회성).
  - 앱이 게임보다 먼저 켜지는 경우(자동 실행)에는 게임 창이 잡힐 때까지 기다리고, 그동안은 기존 화면 좌표로 지금처럼 읽는다.
  - 최소화 중에는 변환하지 않는다.
- **이전 버전 호환**: 상대 좌표는 **새 키**에 저장하고, 기존 화면 좌표 키는 지우지 않는다.
  - 이전 버전으로 되돌려도 이전 버전은 기존 키를 그대로 읽으므로 깨지지 않는다.
  - 새 버전에서 다시 지정하면 새 키만 바뀐다. 이전 버전에서는 그 전 값이 보이는데, 이는 감수한다.
- **두 번 돌지 않게** 이관 완료 표시를 저장한다. 변환은 순수 함수로 두고 왕복 테스트로 확인한다.
- **설정 내보내기/가져오기(zip)**: 새 키가 없는 이전 형식 zip을 가져오면 같은 이관 규칙을 다시 적용한다.

## 5. 알려진 한계 (사용자 안내·도움말용)

- 창 크기 변경, 최대화↔이전 크기 전환, 게임 안 창 이동, 해상도·UI 크기 변경 → 다시 지정이 필요하다(지금과 같음).
- 판독은 주 모니터만 대상이다(`capture/shared_live` — dxcam 기본 출력, mss `monitors[1]`). 게임 창을 다른 모니터로 옮기면 지금처럼 판독되지 않는다. 이번 변경으로 달라지지 않는다.

## 6. 개발 제약과 검증 (QA 요청 반영)

- 창 위치 읽기는 `system/`에 둔다(기존 `window_capture.registered_game_target`, `dialogue_visibility`의 `ClientToScreen` 재사용). 좌표 계산은 순수 함수로 두어 맥에서 테스트한다. 화면과 창은 읽기만 한다.
- **테스트**:
  - 저장↔복원 왕복
  - 원점 (0,0)에서 기존과 같은 결과
  - 이관 한 번만(두 번 실행해도 같음), 9종 일괄
  - 이전 키 보존
  - 가짜 창 위치를 주입했을 때 창 이동에 따라 각 영역이 갱신되는지
  - 창 미검출·최소화(-32000) 때 원점 유지와 저장값 보존
- **실화면(사용자)**: 창 모드에서 창을 옮긴 뒤 버프·디버프·보스바 판독이 유지되는지. 전체 화면 사용자는 업데이트 후 변화가 없는지.
