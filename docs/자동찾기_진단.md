# 자동찾기 진단

자동찾기는 검출기에 전달하는 BGR 원본 프레임을 실행마다 따로 보관한다. 실패 후에 다시
캡처하지 않는다. 설정의 **자동 찾기 진단**에서 최근 실행을 선택하고 **ZIP 저장**으로
내보낸다. 별도 스크린샷이나 Git 업로드는 필요 없다. 저장은 로컬 파일 생성이며 서버나
Discord로 자동 전송하지 않는다.

## 기록과 보관

- `input.png`: 원본 크기와 픽셀을 유지한 PNG. 캡처 실패 시 없다.
- `metadata.json`: 실행 ID, UTC 시작/종료 시각, 앱 버전, 검출 성공 여부와 실패 단계,
  캡처 대상과 백엔드, 프레임 크기와 물리좌표 오프셋, 모니터별 Qt 배율/DPI와 Windows
  유효 DPI, 관련 설정, 검색 영역/변환/임계값/검출 좌표와 제공 가능한 후보 정보.
- `anchor.png`, `digit_*.png`: 해당 실행이 사용한 템플릿. 로컬 설정이나 현재 템플릿에
  의존하지 않고 재실행하기 위한 데이터다.
- `logs.txt`: 해당 실행의 로그와 실행 전후의 일반 앱 로그. 다른 자동찾기 실행의
  로그는 제외한다. 설정과 로그에서 토큰/API 키/웹훅/인증 정보 및 URL을 제외한다.
- 원본 화면에 보이는 채팅·캐릭터 이름 등은 지우지 않는다. 공유 전 직접 확인해야 한다.

저장 위치는 사용자 데이터의 `autofind_diagnostics/`다. 디스크는 최근 **20회·256MiB**,
대기/저장 실패 시 메모리 원본은 **128MiB**, I/O 대기열은 **3개**로 제한한다. PNG 인코딩과
ZIP 저장은 단일 백그라운드 워커에서 실행한다. 상한 초과로 원본을 보관하지 못하면
`input_error`에 이유를 남긴다. 폴더 저장에 실패해도 메모리에 남은 같은 입력으로 다른
위치에 ZIP을 저장할 수 있다. 임시 기록/ZIP을 완성한 뒤 정식 파일명으로 변경하며, 재실행 시
저장 중 끊긴 임시 기록을 정리한다.

검출 성공은 영역 적용 여부와 별개다. 사용자가 확인 창에서 취소하거나 버프 위 경계를
조정하더라도 기록의 `result`는 **원본 입력에 대한 검출기 반환 좌표**다. 프레임 내 물리좌표와
전역 물리좌표를 둘 다 기록한다. 현재 앱의 논리좌표 변환은 주 모니터 배율을 사용하는
기존 동작이며, 진단에 그 방법을 명시한다. 진단 추가 자체가 혼합 DPI 변환을 고치는 것은 아니다.

## 재실행

ZIP을 받은 개발 환경에서 동일 앱 버전으로 실행한다. ZIP 외에 사용자 설정/추가 캡처는
필요 없다. 기록된 PNG SHA-256을 확인한 뒤 원본과 템플릿을 읽고 같은 검출기를 호출한다.

```bash
uv run python -m mabinogi_addon.autofind_replay "진단.zip"
```

`replayed`, `matches_recorded`, `same_app_version`과 재실행 좌표/진단 정보를 출력한다.
캡처 실패나 PNG 저장 실패로 입력/필수 템플릿이 없으면 `replayed: false`와 실패 정보를 반환한다.

필수 템플릿은 로드된 이름 목록과 별도로 검사한다. 버프는 `anchor`, 보스/디버프는
0~9 각 숫자에 최소 한 개의 템플릿이 있어야 한다. 처음부터 누락됐으면 실행을
`detector_setup` 실패로 기록하고 `missing_required_assets`에 누락 항목을 남긴다.
검출기를 호출하지 않지만, 해당 실행에서 캡처한 원본 PNG와 로그는 계속 보존한다.
재실행은 `replayed: false`, `failure_stage: detector_setup`과 원인을 반환한다.
정상 로드한 템플릿이 PNG 저장 중 누락된 경우는 `diagnostic_assets`로 구분한다.
예전 ZIP의 `asset_names=[]`도 필수 입력 검사에서 제외되지 않는다. 정상 템플릿으로
검출한 결과가 `None`인 경우에만 정상적인 미검출 재현으로 판단한다.

현재 제품 연결은 버프, 디버프, 보스, 체력바, 투아림, 단축바 자동찾기다.
투아림/단축바는 원본 장식·조작부 PNG와 가변 내용을 제외한 마스크를 필수 자산으로 기록하고
`autofind_replay.run_detector()`에 등록했다. 기존 숫자 판독기는 위치 검출을 대신하지 않는다.
새 검출기의 입력 PNG·템플릿·마스크·후보 점수·변환·좌표를 기존 보관 상한과 ZIP 경로로 저장한다.

두 새 탭은 `perform_autofind(confirm=...)`으로 검출 이후 확인을 연결한다.
메타데이터의 `success`, `result`, `failure_stage`는 원본 입력의 검출 결과다.
별도 `confirmation.status`에 `not_offered`, `applied`, `cancelled`, `cancelled_shutdown`,
`unsupported_grid`, `save_failed`, `error`를 기록하고 가능한 경우 `region_logical`을 남긴다.
사용자가 취소해도 성공한 검출 결과를 실패로 바꾸지 않으며 ZIP 재실행은 확인 창이나 설정 저장
없이 검출 결과만 비교한다. 확인 처리 오류도 검출 성공을 덮어쓰지 않는다.
기존 네 자동찾기의 승인 흐름은 이 변경에 포함하지 않았다.
최근 실행 목록의 성공/실패는 검출 기준이며 실제 적용 여부는 `confirmation`에서 구분한다.
투아림 위치 검출 성공은 기존 숫자 판독기의 세 자리/100% 판독 성공을 뜻하지 않는다.

## 검증

2026-10-14 AUTO-DIAG-01은 독립 QA에서 수정 확인했다. Linux 오프스크린 Qt에서 제품
진단 60개와 독립 재현 8개, 관련 회귀 83개로 **서로 다른 151개가 통과**했다. 개발 세션의
전체 회귀 **519 passed, 5 warnings**는 별도 실행 기록이며 독립 QA의 전체 실행 결과가 아니다.

같은 앱 소스의 `v0.4.63` Windows 릴리즈 CI는 **25 failed, 413 passed, 81 skipped,
3 warnings in 110.77s**로 테스트 게이트에서 실패했다. 테스트 코드의 한글 이미지 경로
읽기 실패 23건, UTF-8 진단 로그를 기본 CP1252로 읽는 실패 1건, 한글 임시 설정을 기본
CP1252로 쓰는 실패 1건이다. 앱의 동일 기능 결함으로 단정하지 않으며, Linux 통과를
Windows 통과나 배포 완료로 해석하지 않는다. exe 빌드와 배포 단계는 실행되지 않았다.
원인·코드 위치·재현 및 재검증 기준은 [독립 QA 보고서](qa/자동찾기_진단_검토.md)에 있다.

2026-10-14 개발 세션에서 위 테스트 입력 결함을 수정했다. 이미지 파일 I/O는 유니코드
안전 공용 함수를 사용하고 로그·임시 설정은 UTF-8을 명시한다. 실패 조건을 주입한 Linux
재현과 일반 전체 회귀 결과는 보고서의 **Windows CI 입력 결함 개발 수정** 절에 기록한다.
후속 독립 QA에서 수정본 `0a300a3`의 Windows 전체 게이트를 실제 로그로 확인했다.
이전 25개 입력 결함은 통과했지만 **521 passed, 2 failed, 1 skipped, 3 warnings in 134.00s**로
디버프 벤치마크의 CP1252 콘솔 한글 출력이 실패했다(CI-WIN-04). exe 빌드는 실행되지 않았고
배포 완료 상태가 아니다. 유일한 skip은 비-Windows DWM 폴백 검증의 플랫폼 조건이다.
Linux 관련 회귀·독립 재현 280개는 통과했고, 콘솔을 CP1252로 바꾸면 같은 두 실패가
재현되며 UTF-8 콘솔에서는 두 테스트가 통과한다. 자세한 근거와 전달 사항은 QA 보고서의
**Windows 입력 수정 독립 QA와 재실행** 절에 기록한다.

후속 개발 세션에서 CI-WIN-04 출력 경계를 수정했다. CP1252 콘솔이 표현할 수 없는 문자만
이스케이프하고 UTF-8 콘솔의 한글 출력과 검출 assertion은 유지한다. 출력 바이트 회귀와
수정 전후 실행은 보고서의 **콘솔 출력 결함 개발 수정** 절에 기록한다.
수정본 `33e89a0`은 독립 QA에서 기존 CP1252/UTF-8 콘솔 재현과 관련 회귀 291개를 통과했다.
실제 Windows 게이트도 **525 passed, 1 skipped, 3 warnings in 84.21s**로 통과했고 exe 빌드는
성공했다. 유일한 skip은 비-Windows DWM 폴백 검증의 플랫폼 조건이다. 전체 수동 실행이
실패로 표시된 것은 Actions 아티팩트 저장 quota 초과로 exe 업로드가 막혔기 때문이다.
exe를 내려받아 라이브 실행하거나 정식 Release를 게시한 것은 아니며, 자세한 근거와
남은 범위는 QA 보고서의 **콘솔 출력 수정 독립 QA 완료** 절에 있다.

위 결과는 당시 0.0.0 수동 빌드 기록이다. 현재 수동 후보 검증은 확정 버전을 주입하며
게시 시 같은 exe를 사용한다. 진단 버전과 함께 소스 SHA/Actions 실행 번호를 전달한다.
업데이트/노트도 실제 버전 동작이며 설정·데이터 폴더는 정식 exe와 동일하다.
현행 절차는 [검증·승격 분리](windows-validation.md)를 따른다.

전체 회귀 실행 명령은 다음과 같다.

```bash
QT_QPA_PLATFORM=offscreen uv run pytest -q
```

`tests/test_autofind_diagnostics.py`에서 폴더 권한 오류, 영역의 필수 키/타입/크기 오류,
캡처 실패, PNG 저장 실패, 부분 수집 안내와 창 복원, PNG 픽셀/ZIP 추출 바이트 동일성,
연속/동시 실행의 로그·입력 분리, 기존 4개 검출기의 ZIP 재실행, 비밀값 제거, 보관 상한,
UI 이벤트 처리/종료 중 콜백 차단, 저장 도중 프로세스 강제 종료 후 복구를 검증한다.

독립 QA의 로컬 실행 환경은 Linux 오프스크린 Qt이며, Windows에서는 위 CI 실패와 수정 후 통과를 실제
실행 로그로 확인했다. 한글/공백/특수문자 경로 저장과 음수 오프셋·다른 배율 메타데이터
보존은 Linux 자동 테스트로 확인했다. **Windows의 실제
한글 사용자 경로와 혼합 DPI 캡처/좌표는 아직 검증하지 않았다.** 릴리즈 전 Windows에서:

1. 한글 사용자 경로에서 앱을 실행하고 주 모니터 100%, 보조 모니터 150%로 설정한다.
2. 게임 창을 두 모니터로 옮기며 자동찾기를 각각 실행하고 각 기록을 한글 경로에 저장한다.
3. ZIP 원본 화면/크기, `mss_monitors`, `qt_screens`, `windows_monitors`의 배율/DPI,
   `offset_physical`, `result_global_physical`을 실제 위치와 비교한다.
4. 각 ZIP을 같은 앱 버전에서 재실행하고 기록 좌표와 일치하는지 확인한다.
5. 진단 폴더/ZIP 목적지 쓰기 권한을 차단해 오류 안내와 창 복원을 확인한다.
