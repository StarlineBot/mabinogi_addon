- 범위: 첫 사용 설정 동선, 커스텀 오버레이 조작 안내, 위험 동작 스타일 및 기능 설명 보완, 디버프·도르카/투아림·메모·설정 일반의 읽기 흐름 정리.

## 1. 목적과 적용 우선순위

현재 탭 구성과 주요 화면 배치를 유지하면서 첫 설정에서 막히는 동선과 조작 방법의 발견성을 개선한다. 로그인 없이 사용할 수 있는 기본 기능의 일괄 자동설정은 일반 공개한다.

이 문서는 이전 공개 정책의 **일괄 자동설정 로그인 필수 조건**에 우선한다. 개별 자동찾기, 수집·진단 및 개별 기능의 알파·베타 접근 조건은 변경하지 않는다. 과거 공개 정책 문서를 근거로 다른 기능의 현재 공개 단계를 되돌리지 않는다.

## 2. 일괄 자동설정 일반 공개

### 2.1 공개 범위

| 대상 | 기대 동작 |
|---|---|
| 일반 공개 기능의 일괄 자동설정 | Discord 로그인 없이 기능 선택, 탐색, 후보 확인 및 등록 가능 |
| 각 기능 탭의 개별 자동찾기 | 이번 변경으로 공개 범위를 확대하지 않고 기존 권한 유지 |
| 수집·진단 도구 | 기존 기능별 접근 조건 유지 |
| 알파·베타 전용 기능 | 일괄 자동설정에서도 해당 기능의 기존 접근 조건 유지 |
| Discord 로그인 구간 | 베타 기능을 먼저 사용할 수 있다는 기존 짧은 안내 유지 |

일괄 자동설정의 공개와 개별 자동찾기의 접근 정책은 별개다. 일반 공개 기능을 일괄 설정하는 데 개별 자동찾기 버튼의 로그인 조건을 적용하지 않는다. 반대로 일괄 자동설정 공개를 이유로 개별 버튼이나 제한 기능을 전부 허용하지 않는다.

### 2.2 사용 흐름

1. 사용자가 첫 사용 안내 또는 설정의 자동설정 진입점에서 설정할 기능을 선택한다.
2. 게임창 등록과 선택한 기능의 미등록 영역을 확인한다.
3. 보스 체력바가 필요한 미등록 영역이 실행 대상에 있으면, 실행 전에 연습 모드 등에서 보스 체력바를 띄워야 한다는 준비 안내를 보여준다.
4. 현재 사용자에게 허용된 대상만 순서대로 찾는다. 이미 등록된 영역은 기존 건너뛰기 정책을 유지한다.
5. 찾은 영역과 기존 기능별 안내를 보여주고 사용자의 승인 또는 취소를 받는다.
6. 승인한 영역만 등록한다. 취소하거나 찾지 못한 영역은 기존 등록값을 유지한다.
7. 결과를 항목별로 표시하고, 미등록 항목은 직접 설정으로 이어갈 수 있게 한다.

기능 선택 체크는 이번 자동설정 대상을 고르는 값이다. 선택하거나 해제했다는 이유로 이미 등록된 영역과 표시·알림 옵션을 변경하지 않는다.

### 2.3 실행 전 보스 체력바 준비 안내

- 첫 사용 안내에서 보스 체력바가 필요한 미등록 영역이 자동설정 대상에 포함되면, 실행 버튼 근처에 아래 안내를 표시한다. 실패한 뒤에만 안내하거나 도움말 안에만 숨기지 않는다.

  `보스 체력바를 찾으려면 연습 모드에 입장해 체력바가 보이는 상태에서 자동설정해 주세요. 지금 준비하기 어렵다면 다른 기능부터 설정하고 나중에 다시 시도할 수 있습니다.`

- 보스 패턴 알림뿐 아니라 디버프 등에서 함께 설정하는 공유 보스 체력바도 준비 안내의 대상으로 포함한다. 기능 이름만으로 결정하지 않고 실제로 이번에 찾을 미등록 영역을 기준으로 한다.
- 필요한 보스 체력바가 이미 등록되어 이번 탐색에서 건너뛰거나, 해당 영역을 사용하는 대상을 선택하지 않았다면 이 안내를 반복하지 않는다.
- 연습 모드는 보스 체력바를 띄우는 준비 방법이다. 실제 전투 등 다른 상황에서 대상 체력바가 보이는 경우의 기존 설정 가능성을 제한하지 않는다.
- 안내 확인을 위한 추가 필수 팝업이나 게임 모드 확인 단계를 만들지 않는다. 앱이 게임 입장이나 입력을 대신 수행하지 않는다.
- 지금 체력바를 띄우기 어렵다면 해당 대상을 선택에서 제외하고 다른 기능부터 설정하거나 나중에 설정할 수 있다. 체력바가 없다는 이유만으로 다른 대상의 자동설정까지 막지 않는다.
- 안내 이후 실행했지만 보스 체력바를 찾지 못하면 해당 항목의 실패 결과와 직접 설정·재시도 경로를 제공한다. 미등록 상태와 기존 설정은 유지한다.

### 2.4 상태 변화와 예외

- 로그아웃 상태라는 이유만으로 버튼을 무반응 처리하거나 Discord 로그인 화면으로 이동시키지 않는다.
- 진입뿐 아니라 탐색, 후보 승인, 등록 단계에서도 일반 공개 대상에 로그인 조건을 다시 요구하지 않는다.
- 일반 공개 대상 처리 중 로그인 또는 로그아웃이 발생해도 그 사실만으로 작업을 취소하지 않는다.
- 제한 기능의 접근 권한은 실행·승인 시에도 유효해야 한다. 권한이 없거나 처리 중 사라지면 해당 대상을 제외하고 등록하지 않는다. 일반 공개 대상의 처리에는 영향을 주지 않는다.
- 제한 기능이 기존 정책에 따라 숨겨져 있다면 계속 숨긴다. 노출된 선택 대상이 권한 때문에 제외되면 기능명과 제외 이유를 결과에 표시한다.
- 게임창이 미등록이면 등록이 필요하다는 이유와 등록 경로를 제공한다. 등록 없이 성공 상태로 진행하지 않는다.
- 선택한 기능이 없거나 설정할 미등록 영역이 없으면 그 이유를 화면에 표시한다. 로그인과 관계없는 조건을 로그인 문제로 안내하지 않는다.
- 대상 UI가 없거나 가려짐, 캡처·탐색 실패, 저장 실패를 성공으로 표시하지 않는다. 확인 가능한 원인을 안내하고 불명확한 원인을 단정하지 않는다.
- 중단 또는 앱 종료 후 늦게 완료된 탐색으로 영역을 등록하거나 창을 다시 열지 않는다. 이미 승인·저장한 영역은 유지하고 승인하지 않은 후보는 반영하지 않는다.
- 기존 기능별 후보 승인 방식과 도르카·투아림 공동 탐색, 공유 영역의 갱신 규칙을 유지한다.

### 2.5 첫 사용 안내 배치

- 상단은 공통 제목 `첫 사용 안내`, 현재 단계 제목, 해당 단계의 설명 순서로 배치한다. 현재 단계 제목은 `게임창 등록`, `전투 기능 설정`, `추가 기능 설정`을 유지한다.
- 단계 번호와 `게임창 등록 → 전투 기능 → 추가 기능 → 앱 둘러보기` 표시는 본문 상단이 아니라 하단의 `시작할 때 이 화면 다시 보지 않기` 체크박스 바로 위에 둔다.
- 현재 단계 번호와 해당 단계 이름을 굵게 강조하고 다른 단계 이름은 일반 굵기로 표시한다. 단계 이동에 따라 강조 대상을 갱신한다.
- 게임창 등록 단계에서는 `게임창 등록 필요` 상태를 한 줄로 표시하고 그 바로 아래에 `[게임창 등록 시작]` 버튼을 왼쪽 정렬한다. 상태와 버튼을 화면 양끝으로 벌리지 않는다. 등록 후에도 같은 위치에서 등록 상태를 확인할 수 있게 한다.
- 기능 선택 목록과 등록 결과 목록의 역할·그룹 구분은 유지한다. `설정 필요`, `등록된 설정`, `이번 설정에서 제외`를 이번 변경에서 하나의 목록으로 합치지 않는다.
- 각 결과 구간 높이는 실제 표시할 행과 문구에 맞춘다. 한 항목만 있는 구간을 남은 화면 높이만큼 늘리지 않으며, 모든 행이 들어갈 여유가 있으면 불필요한 내부 스크롤을 만들지 않는다.
- 결과 구간이 차지하지 않는 공간은 목록 바깥의 여백으로 남긴다. 단계 표시·다시 보지 않기·이전/나중에 설정/다음 버튼은 하단에 유지한다.
- 화면 높이가 부족하거나 글꼴이 커져도 본문과 하단 조작이 겹치지 않아야 한다. 필요한 기존 스크롤은 유지하고 목록을 줄이기 위해 행이나 안내를 잘라내지 않는다.
- 게임창 등록 단계의 빈 공간을 채우기 위한 장식이나 새 설명을 추가하지 않는다. 기존 단계와 마지막 앱 둘러보기 동작을 유지한다.

화면 참조 자료는 실제 위젯을 바탕으로 만든 목업이다. 등록·실패 결과와 좌표는 예시이며 비로그인 공개 기능이 구현되었다는 증거가 아니다.

## 3. 자동찾기 결과에서 직접 설정으로 이동

- 단계별 첫 사용 안내의 설정이 필요한 결과 행에 `[직접 설정]`을 제공한다. 자동찾기 실패·후보 취소 후에도 사용할 수 있다.
- 버튼을 누르면 해당 기능의 기존 설정 탭을 연다. 직접 설정에 새 로그인 조건을 추가하지 않고 기존 기능별 권한을 따른다.
- 도르카와 투아림은 기존 통합 화면, 보스 체력과 헤일로는 각각에 맞는 하위 화면으로 연결한다.
- 안내를 종료하지 않고 설정 화면 하단에 기존 `[첫 사용 안내로 돌아가기]` 경로를 제공한다.
- 돌아오면 같은 안내 단계를 유지하며 실제 저장된 영역을 기준으로 등록 상태를 갱신한다. 기능 선택과 다른 항목의 결과를 불필요하게 초기화하지 않는다.
- 영역 등록은 등록 상태일 뿐 판독 정확성을 자동 인증한 상태가 아니다. `정상 동작` 등의 검증 완료 문구로 바꾸지 않는다.
- 자동설정 진행 중에는 직접 설정을 동시에 시작하지 않는다. 작업 완료 또는 중단 후 이용할 수 있다.

## 4. 커스텀 오버레이 조작 안내

- 현재 프리셋 선택, 불러오기, 현재 오버레이 목록 및 프리셋 관리 배치를 유지한다.
- 현재 프리셋의 자동 저장과 원본 보존을 위한 다른 이름으로 저장 동작을 유지한다.
- 현재 오버레이 목록 근처에 다음 문구를 상시 표시해 도움말을 열지 않아도 크기 조절 방법을 알 수 있게 한다.

  `잠금을 해제한 오버레이에서 마우스 휠로 크기를 조절할 수 있습니다.`

- 안내는 앱의 목록이 아니라 실제 복제 오버레이 위에서 조작한다는 의미가 명확해야 한다.
- 목록의 표시 배율은 기존과 같이 현재 값을 표시한다. 이번 범위에서 배율 숫자 입력란을 추가하지 않는다.
- 목록, 잠금·삭제 명령과 자동 저장 상태가 안내 때문에 가려지거나 겹치지 않게 한다. 기존 도움말은 유지한다.

## 5. 스타일 및 설명 문구

### 5.1 설정 초기화

- `[설정 초기화]`에 기존 삭제·지정 해제 버튼과 동일한 공통 위험 동작 색상 규칙을 적용한다.
- 설정 백업 그룹 안에서 내보내기·가져오기와 간격 또는 구분선으로 시각적으로 구분한다.
- 기존 초기화 확인과 취소 동작을 유지한다. 버튼 클릭만으로 즉시 초기화하지 않는다.
- 초기화 범위, 백업·가져오기 기능 자체 및 초기화 후 재시작 정책은 변경하지 않는다.

### 5.2 알림 목소리

- 설정의 설명을 다음과 같이 맞춘다.

  `버프·투아림 알림에 쓸 목소리 팩입니다. 고르면 미리듣기가 재생되고 바로 적용됩니다.`

- 파티 알림이 목소리 팩 변경 대상인 것처럼 안내하지 않는다.
- 실제 알림 소리 선택·재생 범위는 이번 문구 수정으로 변경하지 않는다. 파티 알림의 고정 소리도 유지한다.

### 5.3 1분 헤일로

- 게임 내 통용 명칭인 `1분 헤일로`와 `1분 헤일로 알림`을 유지한다.
- 본문 제목은 `믿음의 균열의 1분 헤일로 알림`으로 표시한다.
- 명칭과 무관하게 현재 시간 판독, 63초 주기 및 5초 전 경고 기준을 변경하지 않는다.
- 현재 기능 공개 범위와 판독·알림 동작은 변경하지 않는다.

### 5.4 편린 시세 조회

- 대상 화면은 `편의기능 > 던전 입장 계산기 > 믿음의 균열`이다.
- 경매장 조회를 지원하는 다른 화면과 같은 새로고침 아이콘을 유지한다.
- 아직 시세를 조회하지 않은 상태에서는 다음 문구를 표시한다.

  `오른쪽 위 새로고침 버튼을 눌러 편린 시세를 조회하세요.`

- 조회 중, 조회 성공 시각, 매물 없음, 조회 실패 등의 기존 상태 안내와 버튼 툴팁을 유지한다. 위 문구를 오류 메시지 대신 표시하지 않는다.
- 조회는 사용자가 버튼을 누를 때 실행한다. 자동 조회를 추가하거나 계산·가격 기준을 변경하지 않는다.

## 6. 유지할 기존 구성

- 상위·하위 탭 구성과 각 기능 화면의 주요 레이아웃을 유지한다. 첫 사용 안내의 소폭 배치 변경은 2.5절, 네 화면의 내부 정보 재배치는 7절을 따른다.
- 게임창 등록은 첫 사용 안내에서 유도하고, 설정 화면에서는 현재 최하단 배치를 유지한다.
- 문의하기는 현재 설정 상단 배치를 유지한다.
- 문의·진단 도구의 배치를 임의로 재정렬하거나 진단 도구를 새로 접지 않는다.
- 영역 지정 버튼의 공통 순서, 기존 잠금 색상·문구, 체력바의 개별 잠금 및 전체 잠금·해제를 유지한다.
- 기준 버프 전용 역할 안내와 기능별로 필요한 조작 차이를 유지한다.
- 등록 영역·아이콘·프리셋·위치·배율·잠금·알림 설정을 이 변경의 이관 과정에서 초기화하지 않는다.
- 자동설정 화면의 시작 노출 및 다시 보지 않기 정책은 변경하지 않는다.

## 7. 화면별 읽기 흐름 정리

### 7.1 공통 기준과 승인 범위

- 사용자가 비교 목업을 확인하고 네 화면의 시각적 정리 방향을 승인했다. 아래 배치와 문구는 개발 전달 기준이며, 실제 사용성 검증을 마쳤다는 의미는 아니다.
- 기능을 추가하거나 줄이지 않고 제목, 관련 정보의 묶음, 설명 위치와 중복 문구를 정리한다. 첫 사용 안내의 큰 제목 구성을 모든 기능 탭에 일괄 적용하지 않는다.
- 영역 등록·해제, 자동찾기, 판독, 표시·알림, 배율·잠금, 저장 및 접근 권한의 기존 동작을 유지한다. 화면 재배치 때문에 저장 설정을 초기화하지 않는다.
- 현재 상태·실패·미등록·미판독 안내는 실제 상태에 맞게 유지한다. 등록만으로 정상 판독을 보장하는 문구를 만들지 않는다.
- 짧은 조작 안내는 관련 버튼이나 설정 근처에 두고, 기존 도움말은 유지한다. 필수 동작 설명을 단순히 삭제하거나 도움말 안으로만 숨기지 않는다.
- 목업의 핵심은 정보 순서와 묶음이다. 정확한 픽셀, 폰트나 색상 값은 새 전용 규칙으로 고정하지 않고 앱의 공통 스타일과 테마를 따른다. 지정 해제 등 의도적으로 오른쪽에 배치된 명령을 전부 왼쪽으로 옮기지 않는다.

### 7.2 디버프

- 버프와 같은 기존 좌우 배치를 유지한다. 왼쪽은 판독 영역·보스 확인·목록, 오른쪽은 선택한 아이콘과 표시 설정이다.
- 상단 영역 제목은 `판독 영역 · 디버프 줄`로 표시한다. 미등록 상태 문구는 `디버프 영역 미등록`으로 짧게 표시하고, 등록 시에는 기존 등록 정보와 상태를 유지한다.
- 영역 조작 버튼 아래에 다음 두 줄을 표시한다.

  `자동 찾기: 디버프 줄과 보스 체력바를 함께 등록`

  `직접 지정·보기·해제: 디버프 줄만 변경`

- 위 문구는 기존 공동 자동찾기와 개별 조작의 차이를 설명한다. 이번 정리로 자동찾기를 두 번 실행하게 만들거나 직접 지정의 대상을 바꾸지 않는다.
- 공유 보스 영역의 등록·미등록 및 감시 상태는 상단 디버프 등록 구간이 아니라 `보스 확인 · 자동` 제목 아래에 배치한다. 개별 조정 진입과 목록은 유지한다.
- 오른쪽 표시 그룹에서 반복하는 '아직 걸리지 않은 디버프' 설명은 제거한다. 같은 의미의 페이지 상단 설명과 실제 표시 동작은 유지한다.

### 7.3 도르카·투아림

- 공통 영역 등록 구간 아래를 `판독 확인` → `표시` → `투아림 알림` 순서의 동등한 그룹으로 나눈다. 그룹 안에 다른 그룹을 중첩하지 않는다.
- `판독 확인`에는 기존 도르카·투아림 원본 영역 이미지, 현재 판독값과 최근 확정값을 옮긴다. 원본 영역 확인과 표시 미리보기를 같은 의미로 취급하지 않는다.
- `표시`에는 기존 도르카 표시·투아림 % 표시·투아림 알림 사용 옵션, 배율·위치 잠금, 오버레이 표시 미리보기를 유지한다. 이번 범위에서 옵션의 의미나 제어 대상을 바꾸지 않는다.
- `투아림 알림`에는 기존 첫 알림·추가 알림 기준과 소리 옵션을 유지한다. 진단·수집 진입도 유지한다.
- 기존 개별 영역 조정과 원본 미리보기를 제거하지 않는다. 공통 영역을 한 번 설정하는 동작과 부분 등록 상태도 유지한다.
- 미판독 값은 기존의 `--` 등으로 표시하며 `0`이나 정상으로 치환하지 않는다. `현재 판독`과 `최근 확정`의 의미·갱신 기준은 변경하지 않는다.
- 투아림 % 표시 등 제한 기능은 기존 접근 조건에 따라 노출한다. 목업에 옵션이 보인다는 이유로 일반 공개하거나 기본 체크 상태를 바꾸지 않는다.

### 7.4 메모

- 영역 미등록 상태는 `영역 미지정`으로 짧게 표시한다. 등록 시의 기존 좌표·상태 정보는 유지한다.
- 영역 조작 버튼 바로 아래에 다음 안내를 배치한다.

  `위치와 너비를 지정하세요. 높이는 내용에 맞춰 자동으로 조절됩니다.`

- 위치 잠금과 잠금 해제 시 이동 방법은 기존 표시 그룹에서 해당 조작 가까이에 유지한다.
- 입력란 하단 안내는 다음과 같이 정리한다.

  `작성 내용은 자동 저장됩니다. 표시 미리보기에서 실제 모양을 확인할 수 있습니다.`

- 화면 최하단의 중복된 표시·이동·잠금 설명 문단은 제거한다. 기존 도움말과 입력 도구, 표시 미리보기 버튼은 유지한다. 세부 이동·너비 조절·클릭 통과 동작 자체는 변경하지 않는다.
- 중복 안내를 줄여 확보한 높이는 메모 입력란이 활용할 수 있게 한다. 빈 공간을 채우기 위한 새 설명이나 장식은 추가하지 않는다.

### 7.5 설정 > 일반

- 바깥 `일반` 그룹과 현재 항목 순서를 유지하고, 그룹 안에 다음 소제목과 간격을 추가한다. 별도의 중첩 그룹이나 새 접기 기능은 추가하지 않는다.

| 소제목 | 포함 항목 |
|---|---|
| 실행·종료 | Windows 시작 시 자동 실행, 트레이로 시작, 닫기 버튼의 트레이 최소화 |
| 오버레이 배치 | 격자 맞춤, 격자 크기와 관련 설명 |
| 알림 | 토스트 위치·테스트, 알림 목소리와 관련 설명 |
| 안내 다시 보기 | 자동설정 다시 열기, 사용법 투어 다시 보기, 업데이트 노트 보기 |

- 구분을 위해 전체 높이가 조금 늘어날 수 있다. 높이를 억지로 맞추기 위해 항목을 숨기거나 글자를 축소하지 않으며, 기존 스크롤로 전체 항목에 접근할 수 있어야 한다.
- 문의하기 상단 및 게임창 등록 최하단 배치는 유지한다. 알림 목소리 설명은 5.2절을 함께 적용하며, 비교 목업에 담긴 기존 설명을 최종 문구로 다시 채택하지 않는다.

### 7.6 승인 목업 및 실제 사용 확인

아래 자료는 동일한 소스와 샘플 상태에서 만든 오프스크린 비교 목업이며 왼쪽은 현재, 오른쪽은 승인한 개선 방향이다. 빈 원본 이미지와 `--` 값은 실제 게임 판독 결과가 아니다. 설정 이미지는 `일반` 그룹만 확대 비교한 것으로 전체 페이지 재배치를 뜻하지 않는다.

- [도르카·투아림 비교](images/readability-20261020/resource-comparison.png)

개발 후 실제 앱에서 다음을 확인한다. 확인 전까지 화면 목업 승인과 실사용 검증 완료를 구분한다.

- 디버프: 공동 자동찾기와 직접 지정의 대상 차이를 찾을 수 있는지, 공유 보스 상태와 목록이 혼동되지 않는지.
- 도르카·투아림: 게임 원본 판독과 출력 미리보기를 구분할 수 있는지, 새 그룹 때문에 알림 설정 접근이 지나치게 멀어지지 않는지.
- 메모: 중복 문단을 줄인 뒤에도 영역 지정·잠금·자동 저장·표시 미리보기를 발견할 수 있는지.
- 설정: 소제목이 항목 탐색에 도움이 되는지, 늘어난 길이로 하단 설정 접근이 불편해지지 않는지.
- 공통: 미등록·등록·미판독·권한 제한 상태, 긴 상태값, 라이트·다크·큰 글꼴·작은 화면에서 잘림과 겹침이 없는지.

사용 후 세부 보완 가능성은 남지만 개발을 막는 미결정 사항은 아니다. 기능 의미나 조작 흐름의 추가 변경은 별도로 확인한다.

## 8. Acceptance Criteria

| ID | 조건과 성공 기준 |
|---|---|
| AC-01 | 로그아웃 상태에서 게임창을 등록하고 일반 공개 기능의 미등록 대상을 선택하면 일괄 자동설정이 실행된다. 로그인 요구나 무반응 종료가 발생하지 않는다. |
| AC-02 | 비로그인 사용자가 후보를 승인하면 해당 영역이 저장된다. 취소하면 해당 영역의 기존 값이 유지된다. |
| AC-03 | 탐색부터 승인·등록까지 진행하는 동안 로그인 상태가 바뀌어도 일반 공개 대상은 그 이유만으로 중단되지 않는다. |
| AC-04 | 권한이 없는 알파·베타 기능은 일괄 자동설정으로 등록·활성화되지 않는다. 그 과정에서 일반 공개 대상까지 일괄 차단하지 않는다. |
| AC-05 | 개별 자동찾기와 수집·진단 도구의 기존 접근 제한은 유지된다. 일괄 공개를 위해 제한 검사를 일괄 허용하지 않는다. |
| AC-06 | 선택 없음, 게임창 미등록, 미등록 대상 없음 상태에서 실행하면 실제 원인에 해당하는 안내가 나온다. |
| AC-07 | 자동찾기에 실패하거나 후보 등록을 취소한 항목에서 직접 설정 화면으로 이동할 수 있다. 돌아오면 원래 단계와 기능 선택을 유지하고 저장된 등록 상태를 갱신한다. |
| AC-08 | 탐색 중 중단·종료하면 미승인 후보가 저장되지 않고 늦은 완료 결과가 화면을 다시 열지 않는다. 기존 저장 영역은 유지된다. |
| AC-09 | 커스텀 오버레이 도움말을 열지 않아도 목록 근처에서 휠 조절 방법을 확인할 수 있다. 대상은 잠금 해제된 실제 오버레이임이 명확하다. |
| AC-10 | 커스텀 프리셋 불러오기·자동 저장·다른 이름으로 저장, 목록과 잠금·삭제 명령은 기존과 동일하게 동작한다. |
| AC-11 | 설정 초기화 버튼은 다른 위험 동작과 같은 색상 규칙으로 구분된다. 확인창에서 취소하면 설정을 변경하지 않는다. |
| AC-12 | 알림 목소리 설명에는 버프·투아림이 표시되며 파티 소리 변경을 약속하지 않는다. 실제 소리 동작은 기존과 동일하다. |
| AC-13 | 헤일로 하위 탭의 통용 명칭은 유지하고 본문 제목은 지정한 문구와 일치한다. 시간 계산 기준은 변경되지 않는다. |
| AC-14 | 편린 시세 미조회 상태에서 조회 위치 안내가 표시된다. 새로고침 아이콘은 유지하며 조회 결과·실패 안내는 해당 상태에 맞게 표시된다. |
| AC-15 | 설정의 문의하기 상단·게임창 등록 최하단 배치, 기존 사용 설정, 첫 안내 시작 정책이 유지된다. |
| AC-16 | 라이트·다크 및 앱이 지원하는 큰 글꼴·작은 화면 조건에서 새 문구와 버튼이 겹치거나 잘리지 않는다. 필요한 경우 기존 세로 스크롤로 접근할 수 있다. |
| AC-17 | 보스 체력바가 필요한 미등록 항목을 선택하면 자동설정 실행 전에 연습 모드 입장·체력바 표시 준비 안내가 보인다. 디버프와 공유하는 보스 체력바도 포함한다. |
| AC-18 | 해당 영역이 이미 등록되어 탐색 대상이 아니거나 관련 대상을 선택하지 않으면 보스 체력바 준비 안내를 반복하지 않는다. 다른 기능만 먼저 설정하는 흐름은 차단되지 않는다. |
| AC-19 | 체력바가 보이지 않는 상태로 실행해 탐색에 실패해도 다른 설정 결과와 기존 영역은 유지되며, 실패한 항목에서 직접 설정 또는 추후 재시도로 이어갈 수 있다. |
| AC-20 | 각 설정 단계에서 상단은 첫 사용 안내·현재 단계 제목·설명 순서이며, 단계 번호와 전체 흐름은 하단 체크박스 위에 표시된다. 이동 시 현재 단계 번호와 이름만 굵게 강조된다. |
| AC-21 | 게임창 등록 상태와 버튼이 왼쪽에서 위아래로 이어진다. 결과가 한 개뿐인 그룹은 행 내용에 맞는 높이를 사용하며, 남는 공간은 목록 밖 여백으로 남는다. 다른 행이나 하단 조작은 잘리지 않는다. |
| AC-22 | 디버프 영역 조작 근처에 공동 자동찾기와 개별 직접 지정·보기·해제의 대상 차이가 표시된다. 실제 조작 대상은 기존과 동일하며, 공유 보스 상태는 보스 확인 제목 아래에서 확인할 수 있다. |
| AC-23 | 디버프의 상단 기능 설명은 유지되고 오른쪽 표시 그룹의 중복 설명만 제거된다. 아이콘 편집·표시·사라짐 경고와 목록 조작은 그대로 이용할 수 있다. |
| AC-24 | 도르카·투아림 화면은 판독 확인·표시·투아림 알림 순서로 구분되며, 기존 원본 이미지·현재 판독·최근 확정값과 출력 미리보기를 모두 확인할 수 있다. 미판독 값을 0 또는 정상으로 대체하지 않는다. |
| AC-25 | 도르카·투아림의 공통/개별 영역 조정, 표시·알림 옵션, 잠금·배율 및 진단 기능이 유지된다. 접근 권한이 없는 투아림 % 표시를 새 배치로 노출하거나 활성화하지 않는다. |
| AC-26 | 메모의 영역 버튼 아래에서 위치·너비·자동 높이 안내를, 입력란 아래에서 자동 저장·미리보기 안내를 볼 수 있다. 중복 최하단 문단은 없으며 작성·서식·미리보기·잠금·기존 이동 동작은 유지된다. |
| AC-27 | 설정 일반에서 네 소제목 아래에 해당 항목이 기존 순서로 표시된다. 문의하기·게임창 등록의 바깥 배치는 변하지 않고 스크롤을 통해 모든 항목에 접근할 수 있다. |
| AC-28 | 네 화면을 이동하거나 앱을 재실행해도 기존 영역·옵션·메모가 재배치 때문에 초기화되지 않는다. 지원 테마·글꼴·화면 조건에서 새 그룹과 안내가 조작을 가리지 않는다. |

## 9. 개발 및 검증 경계

- 추가 사용자 결정이 필요한 핵심 미결 사항은 없다. 위 범위로 개발 및 독립 QA에 전달할 수 있다.
- 문서 작성 당시 확인된 것은 기존 소스와 오프스크린 UI 검토다. 비로그인 일괄 실행이 구현·검증되었다고 간주하지 않는다.
- 개발에서는 일괄 설정의 진입·공동 자원 탐색·후보 승인·저장·로그인 상태 변경 처리를 함께 확인한다. 일반 공개 대상의 허용과 제한 기능의 권한 검사를 구분한다.
- 일괄 비로그인 실행의 실제 Windows 캡처·후보 승인·저장 및 접근 제한 회귀는 변경 후 검증한다. 기존 테스트 통과만으로 변경 후 검증을 대신하지 않는다.
- 새 안내 문구와 직접 설정 진입 버튼은 실제 앱 렌더링으로 확인한다. 대규모 화면 재설계는 범위에 포함하지 않는다.
- 제품 코드 변경, 버전 번호 변경, 커밋·푸시 및 배포는 이 문서 작성에 포함하지 않는다.
