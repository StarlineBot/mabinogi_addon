# 배포 가이드 (운영 메모)

> 릴리즈할 때 참고. 이 문서는 **비공개 저장소 전용**(개발용)이며 공개 저장소/릴리즈엔 영향 없다.

## TL;DR — 릴리즈하는 법

릴리즈는 **태그 푸시**가 전부다. (Claude 클라우드 세션은 권한 때문에 태그 푸시를 못 하니 **직접 한다.**)

명령 세 줄은 **하나의 코드 블록에 묶어 한 번에 복사**할 수 있게 제공한다.
명령별로 블록을 나누지 않고, `&&` 없이 줄바꿈으로 구분한다.

```bash
git fetch origin
git tag vX.Y.Z origin/main
git push origin vX.Y.Z
```

- 태그는 반드시 `origin/main`에 단다(로컬 브랜치가 뒤처져 있을 수 있음).
- 버전은 **태그에서** 뽑는다(`vX.Y.Z` → `src/mabinogi_addon/version.py` + exe 버전 리소스).
- `main` 에 그냥 push 하면 **빌드 안 함**. `v*` 태그 push 때만 릴리즈가 돈다.
- 이미 쓴 태그는 재사용 불가 → 항상 **새 버전 번호**로.

## 릴리즈 때 자동으로 일어나는 일 (`.github/workflows/release.yml`)

전체 Windows pytest 게이트를 먼저 실행한다. 실패하면 아래 빌드·배포 단계는 실행하지 않는다.

1. exe 빌드 (PyInstaller, onefile). 관리자 권한 매니페스트·스플래시·아이콘·버전·탐지 템플릿·보이스팩 포함.
2. **비공개** 저장소 Release 에 exe 첨부.
3. `version.json` 생성(버전·다운로드 URL·sha256·크기).
4. 릴리스 노트 `notes.md` 생성(아래 "노트 규칙").
5. **공개** 저장소(`StarlineBot/mabinogi_addon-releases`) `main` 에 커밋:
   - `version.json` (앱 자동 업데이트가 raw 로 확인)
   - `CHANGELOG.md` (버전마다 맨 위로 누적)
   - `README.md` (템플릿 + CHANGELOG 자동 렌더)
6. **공개** 저장소 Release 에 exe + version.json 첨부.
7. **Discord 포럼** 공지(웹훅): 제목 `vX.Y.Z`, 본문 = notes.md + 다운로드/릴리스 링크.

## 배포 전 체크리스트

- [ ] 코드가 `origin/main` 에 다 올라갔나 (`git fetch origin` 후 `git rev-parse HEAD origin/main` 비교)
- [ ] 테스트 통과 (`QT_QPA_PLATFORM=offscreen uv run pytest`)
- [ ] Windows 테스트 게이트·exe 빌드 통과 (이전 CI가 실패했다면 아래 수동 검증부터)
- [ ] 공개 **소개/기능 문구**를 바꿀 거면 `packaging/releases_README.md` 먼저 수정·푸시
- [ ] 새 버전 번호 결정 (이전 태그보다 높게)

### 실패한 Windows CI 재검증

수정 코드를 `main`에 푸시한 뒤 GitHub Actions의 `release` 워크플로에서
`Run workflow`를 누르고 **main**을 선택한다. 수동 실행은 전체 Windows 테스트,
exe 빌드와 아티팩트 업로드만 수행하며 Release·자동 업데이트·Discord 공지를 게시하지 않는다.
`main` 푸시만으로는 이 검증이 실행되지 않는다.

Windows 테스트 통과와 skip 사유, 빌드 성공을 확인하기 전에는 새 릴리즈 태그를 안내하지 않는다.
Linux 통과나 CP1252/한글 경로 실패 주입 테스트는 Windows 검증을 대체하지 않는다.
이미 존재하는 실패 태그(`v0.4.63` 등)는 삭제·이동·재사용하지 않는다.

### main 수동 빌드와 앱 버전

`Run workflow`에서 **main**을 선택하면 태그 없는 검증 빌드다.

- 내부 버전과 exe 파일 속성: `0.0.0`. 앱 창 제목의 버전 표시는 `개발`이다.
- 트래커/자동찾기 기능 코드는 최신 소스로 실행한다. 개발 버전이라고 이 기능들을 끄지는 않는다.
- 자동 업데이트 확인과 시작 시 업데이트 노트 표시는 건너뛴다. 정식 배포/업데이트 테스트용은 아니다.
- frozen exe의 설정·사용자 데이터는 정식 exe와 같은 `%LOCALAPPDATA%/StarlineMabinogiAddon`이다.
  별도 테스트 데이터 폴더가 아니므로 수동 빌드에서 변경한 설정도 유지된다.
- 진단 ZIP의 앱 버전도 `0.0.0`이다. 빌드를 구분하려면 대상 소스와 Actions 실행 번호를 기록한다.
- 새 태그·Release·공개 `version.json`·Discord 공지는 `main` 수동 실행에서 생성하지 않는다.

검증 목적의 수동 실행은 **main**을 선택한다. 현재 게시 단계의 조건은 태그 ref 여부이므로,
태그 ref를 선택한 수동 dispatch까지 게시가 차단된다고 가정하지 않는다.

최근 검증 `38570646885`는 Windows **525 passed, 1 skipped**와 exe 빌드가 성공했다.
이후 아티팩트 업로드가 Actions 저장 quota 초과로 실패한 것은 코드/빌드 실패와 구분한다.
기존 아티팩트 정리나 저장 공간 정책 변경은 별도 판단 사항이며 사용량 재계산에는 6~12시간이
걸릴 수 있다. 태그 push 릴리즈는 수동 검증용 아티팩트 단계를 건너뛰고 Release 자산으로
업로드하는 다른 경로지만, 이번 수동 검증으로 정식 게시·자동 업데이트 성공까지 확인한 것은 아니다.

## 노트(변경 내역) 규칙 — README·Discord 공용

`notes.md` 는 이렇게 자동 결정된다:

1. **앱 코드(`src/mabinogi_addon/`)가 바뀌었으면** → 직전 태그 이후 **커밋 제목 목록**
   → 그래서 **커밋 메시지를 사용자 눈높이로** 쓰면 그대로 좋은 노트가 된다.
2. **앱 코드 변화가 없으면**(배포/내부 정비만) → **위트 문구 랜덤**
   ("섯다라인이 애드온 내부를 청소했어요" 등)

노트를 **직접 다듬고 싶으면**: 공개 저장소의 `CHANGELOG.md` 를 직접 수정(기존 항목은 안 덮어씀, 유지됨).
단, 공개 `README.md` 는 다음 릴리즈 때 다시 렌더되니 **직접 쓰지 말고 `CHANGELOG.md`** 를 고친다.

## 웹훅(디스코드 공지) URL 바꾸기

**다른 포럼으로 보내고 싶을 때**: 비공개 저장소
**Settings → Secrets and variables → Actions → `RELEASE_WEBHOOK_URL`** 값만 바꾸면 된다.
(코드 수정 불필요. 다음 릴리즈부터 적용.)

- 반드시 **포럼 채널**의 웹훅이어야 "제목(thread_name)" 방식이 동작한다.
- 포럼이 "글 작성 시 태그 필수"면 웹훅이 거부될 수 있음 → 포럼에서 태그를 선택사항으로.
- 시크릿을 비워두면 공지 단계는 **건너뜀**(릴리즈 자체는 정상).

## 시크릿 목록 (전부 **비공개** 저장소 Actions Secrets)

| 이름 | 용도 |
|---|---|
| `NEXON_API_KEY` | 넥슨 API. 빌드 때 exe 에 주입(`_bundled.py`) |
| `INQUIRY_WEBHOOK_URL` | 문의/버그 신고 전송. exe 에 주입 |
| `CONFIG_WEBHOOK_URL` | 설정 백업 전송. exe 에 주입 |
| `RELEASES_TOKEN` | **공개** 저장소에 쓰기용 Fine-grained PAT (Contents: R/W) |
| `RELEASE_WEBHOOK_URL` | 디스코드 포럼 공지 웹훅 |

- **공개** 저장소엔 시크릿 **없음**(실행되는 워크플로가 없음).
- `GOOGLE_TTS_API_KEY` 는 배포와 무관 — 보이스팩 생성 스크립트(`scripts/gen_tts.py`) **로컬 실행용**(`.env`).

## 공개 저장소 구조 (`mabinogi_addon-releases`)

- 소스 코드 없음. **exe + version.json + README + CHANGELOG** 만 올라가는 창고.
- Release 의 "Source code (zip/tar.gz)" 는 GitHub 자동 생성물 → 안에 든 건 위 몇 개 파일뿐(앱 소스 아님).
- 공개 문구 소스: `packaging/releases_README.md`(템플릿) + `CHANGELOG.md`(이력).

## 파일별 "공개에 영향 있나"

| 파일 | 공개 반영? |
|---|---|
| 루트 `README.md` | ❌ 개발용. 영향 없음 |
| `packaging/releases_README.md` | ✅ 공개 README 소개/기능 |
| `packaging/CHANGELOG.md` | ✅ 공개 이력 **시드**(최초 1회) |
| 공개 저장소 `CHANGELOG.md` | ✅ 실제 누적 이력(여기서 직접 수정) |

## 자잘한 함정

- **자동 업데이트 테스트**: 상위 버전을 **하나 더 배포**해야 배너가 뜬다(현재 버전과 같으면 "새 버전 없음"이 정상).
- **맥에선 exe 실행·업데이트 테스트 불가** — Windows 전용. (파일 다운로드만 가능)
- **SmartScreen 경고**(서명 안 된 개인 배포): "추가 정보 → 실행".
- **exe 에 시크릿이 박혀 배포**됨 → exe 를 **완전 공개**로 아무나 받게 하면 디컴파일로 추출될 수 있음. 공개 범위는 신중히.
- 자동 실행은 배포본에서 **작업 스케줄러**(관리자 권한)로 등록된다.
