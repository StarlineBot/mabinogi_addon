# 배포 가이드

Windows 전체 테스트·네이티브 검사·exe 빌드를 먼저 수동 검증하고 사용자 승인으로
보관된 동일 산출물을 게시한다. 일반 푸시·태그만으로 검사나 배포가 시작되지 않는다.

명령, 버전/태그 정책, 1일·2개·200MiB 보관, 실패 복구와 해시 확인은
[Windows 검증·승격 절차](windows-validation.md)를 따른다.
이미 사용한 태그는 실패한 태그도 재사용하지 않는다.

## 공개 데이터와 비밀값

- 공개 저장소: `StarlineBot/mabinogi_addon-releases`.
- Release: 검증된 exe + version.json + candidate.json. 두 저장소 초안 업로드 파일 해시를 확인한 뒤 공개한다.
- 공개 main: version.json, CHANGELOG, README. `data/dialogues.json`은 최초에만 시드하고 작성자 변경을 보존한다.
- 노트 원본: 검증 SHA의 `assets/release_notes.md` 해당 버전. 커밋 제목/랜덤 문구를 게시하지 않는다.
- README 소개 템플릿: `packaging/releases_README.md`; 기존 공개 CHANGELOG 내용은 보존한다.
- 비공개 Actions secrets: `NEXON_API_KEY`, `INQUIRY_WEBHOOK_URL`, `CONFIG_WEBHOOK_URL`은 검증 빌드 때 주입한다.
  `RELEASES_TOKEN`은 공개 저장소 Contents R/W, `RELEASE_WEBHOOK_URL`은 선택 Discord 포럼 공지다.
  비밀값을 로그/문서/증명 파일에 쓰지 않는다. 공지 실패는 게시 실패와 구분한다.
- exe에 주입된 값은 역분석으로 추출될 수 있다. 이 기존 구조를 비밀 저장소로 간주하지 않는다.
- 후보 exe는 실제 버전이며 정식 exe와 동일한 사용자 데이터 폴더를 쓴다.
- 번들 Secrets도 검증 시점에 고정된다. 검증 이후 Secrets 변경을 exe에 적용하려면 새 후보를 검증한다.

과거 기록은 [이전 가이드](deployment-history.md)에 보존했다. 현재 명령으로 사용하지 않는다.
