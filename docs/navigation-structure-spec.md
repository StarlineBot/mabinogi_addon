# 앱 탭 및 기능 탐색 구조 정리 명세

- 작성일: 2026-10-17
- 상태: 2단 가로 탭 시안 승인 및 개발 진행. 기본 버프/디버프 좌우 편집 배치를 보존한다.
- 시안 승인: 2026-10-17. 기존 창 폭/본문 폭을 유지한 기능 탭 한 줄과 작은 구분선을 사용한다.
- 대상: 앱 본창의 상위 탭, 전투 보조 기능 탐색, 편의기능 분류 및 기존 진입 경로.
- 목적: 늘어난 기능을 목적에 따라 정리하되, 기존 탭형 탐색과 설정 화면의 편집 공간을 유지한다.
- 개발 및 독립 QA 전달용이다. 앱 구현이나 실게임 검증 완료를 뜻하지 않는다.
- 이번 변경은 기능의 진입 구조 정리이다. 각 기능의 판독, 알림 및 게임 오버레이 동작을 재설계하지 않는다.
- 도르카·투아림의 통합 및 독립 사용 정책은 [통합 명세](dorcha-tuarim-integration-spec.md)를 따른다.
- 2026-10-21 후속 확정: 제작자 전용 알파 최적화를 편의기능 다음·설정 앞 상위 탭으로 제공하고, 최적화/FPS 본문도 공통 헤더와 기능별 영역으로 구분한다. 아래 초기 4탭 구조보다 [통합 개발 전달문](qa/Windows검증장기정체_최적화탭통합_개발전달_20261021.md)의 최신 요구가 우선한다. 구현·목업 승인 완료를 뜻하지 않는다.

## 1. 분류 원칙

- 상위 분류는 기능의 주목적으로 결정한다. 게임 위에 표시한다는 이유만으로 모든 기능을 같은 분류에 넣지 않는다.
- 전투 중 효과 확인, 알림, 자원 표시 및 직접적인 화면 배치는 전투 보조에 둔다.
- 정보 조회, 계산 및 콘텐츠별 가이드는 편의기능에 둔다.
- 한 기능에 조회와 오버레이가 함께 있으면 주목적에 따라 한곳에 둔다. 같은 기능의 설정을 여러 분류로 나누지 않는다.
- 새 분류를 선택한다고 기능이 켜지거나, 해당 분류의 모든 기능을 사용하도록 설정되지 않는다.

## 2. 상위 탭

왼쪽부터 다음 순서를 사용한다.

```text
전투 보조 | 파티 모집 | 편의기능 | 설정
```

- 기존 트래커 상위 탭은 전투 보조로 변경하고, 기존 트래커와 편의기능의 화면 표시 기능을 함께 배치한다.
- 파티 모집과 설정은 독립된 상위 탭을 유지한다.
- 편의기능이라는 이름은 유지한다. 계산기로 이름을 좁히지 않는다.
- 별도의 메인 상위 탭은 추가하지 않는다. 기존 단계별 첫 사용 안내 및 설정에서 다시 여는 구조는 유지한다.

### 2026-10-21 최적화 알파 탭 추가

제작자에게는 `전투 보조 | 파티 모집 | 편의기능 | 최적화 | 설정` 순서로 표시한다.
설정 버튼에서 별도 창을 여는 대신 본창의 최적화 탭에서 최적화/FPS 화면을 제공한다.
일반 사용자에게 알파를 공개하는 변경은 아니며, 접근 해제 뒤에도 기존 복구 전용 동선을 보존한다.
탭 선택만으로 시스템 변경이나 측정을 시작하지 않는다. 제목·설명·구분선뿐 아니라 기능별 본문 영역도
다른 탭과 통일한다. 세부 배치·안내의 고정 탭 인덱스 제거·접근 전환 검사는 위 통합 전달문을 따른다.

## 3. 전투 보조 내부 구조

상위 탭 아래에 개별 기능의 가로 탭 한 줄을 둔다. 상위 탭과 기능 탭의 2단 구조이다.
좌측 탐색 목록이나 그룹 선택용 중간 탭은 추가하지 않는다.

```text
상위: 전투 보조 | 파티 모집 | 편의기능 | 설정
하위: 버프 | 디버프 | 보스 패턴 알림 | 체력바 | 도르카·투아림 | 커스텀 오버레이 | 단축바 | 메모
```

하위 탭 순서는 다음 세 묶음을 따른다. 묶음은 분류 원칙이며 추가 탐색 단계가 아니다.

| 개념상 묶음 | 기능 순서 |
|---|---|
| 효과·알림 | 버프, 디버프, 보스 패턴 알림 |
| 자원 표시 | 체력바, 도르카·투아림 |
| 화면 배치 | 커스텀 오버레이, 단축바, 메모 |

- 묶음 경계는 탭 사이의 작은 간격 또는 구분선으로만 표현한다. 별도 그룹 제목 줄이나 그룹 선택 탭을 만들지 않는다.
- 그룹을 먼저 선택하지 않아도 원하는 기능 탭을 한 번 눌러 바로 진입할 수 있다.
- 탭에는 현재 선택한 기능을 구분할 수 있는 선택 상태를 표시한다.
- 기능 탭을 고르면 아래 본문에 해당 설정이 표시된다. 별도 시작/소개 화면을 끼우지 않는다.
- 기존 기능 화면의 설정 항목, 편집 기능 및 사용 체크를 유지한다.
- 기능 탭 선택과 기능 사용 체크는 서로 다른 동작이다.
- 이번 범위에 기능 검색, 즐겨찾기, 사용자별 탭 재정렬 및 그룹 접기 기능을 추가하지 않는다.
- 현재 실행 중 다른 상위 탭을 다녀와도 전투 보조에서 선택했던 기능으로 돌아온다.
  앱 재실행 시 마지막 기능을 새로 저장/복원하는 기능을 추가하는 요구는 아니다.

## 4. 편의기능

현재 제공할 항목의 순서는 다음과 같다.

1. 분배 계산기
2. 구슬 분배 계산기
3. 환전비율 계산기

- 메모, 커스텀 오버레이, 단축바, 체력바 및 도르카는 전투 보조로 옮긴다.
- 현재 계산기 세 개만을 위해 계산기라는 중간 그룹을 추가하지 않는다.
- 편의기능의 내부 선택도 기존 하위 가로 탭을 유지한다. 좌측 탐색 목록이나 중간 그룹 탭을 추가하지 않는다.
- 계산식, 시세 조회, 입력값 및 결과 표시 의미는 변경하지 않는다.

### 향후 요리 기능의 분류

- 요리 기능은 향후 구현 시 편의기능에 둔다.
- 요리명/재료/능력치 검색, 카테고리 탐색, 레시피 상세 및 비율 가이드 오버레이 설정을 요리 안에서 함께 제공한다.
- 비율바가 게임 위에 표시되더라도 화면 배치에 요리 설정을 별도로 분리하지 않는다.
- 요리의 주목적은 레시피 조회와 요리 가이드이며, 오버레이는 그 가이드를 사용하는 수단이다.
- 이번 탐색 구조 변경에 요리 개발을 포함하지 않는다. 미구현 요리를 빈 메뉴나 사용 불가능한 탭으로 노출하지 않는다.
- 요리 기능의 세부 동작과 개발 재개는 별도 기획을 따른다. 기존 초안을 이 문서로 확정하지 않는다.

### 도르카·투아림 명칭과 순서

- 탐색 항목의 이름은 도르카·투아림이며 `(베타)`를 붙이지 않는다.
- 하위 탭에서 체력바 다음에 바로 도르카·투아림을 둔다. 독립 투아림 탭은 제거한다.
- 도르카 사용 및 개별 자동찾기의 Discord 로그인 접근 조건은 유지한다.
  기존 일반 투아림 알림까지 로그인 필수로 변경하지 않는다. 세 사용 체크와 설정 이전은 통합 명세를 따른다.
- 기능 화면 안의 접근 안내도 실제 접근 정책과 일치하게 유지한다. 다른 기능의 베타 명칭을 일괄 제거하지 않는다.

## 6. 기존 진입 경로와 동작 보존

- 기존에 버프 화면으로 시작하던 조건에서는 전투 보조 > 버프를 연다.
- 단계별 첫 사용 안내의 표시 조건, 다시 보지 않기 및 설정에서 다시 여는 동작은 유지한다.
- 안내/자동설정에서 개별 기능을 열면 새 위치의 해당 기능을 정확히 선택한다.
- 파티 알림 또는 관련 진입 동작으로 파티 모집을 열 때 기존과 같은 목록 화면을 표시한다.
- 앱 둘러보기의 트래커/편의기능 안내와 하이라이트 대상은 새 명칭과 실제 위치에 맞게 수정한다.
- 투어를 맞추기 위해 기존 기능의 사용 체크, 영역 등록, 자동설정 순차 승인 또는 다시 보지 않기를 초기화하지 않는다.
- 설정, 도움말 및 기능 이동 버튼에서 안내하는 탐색 경로가 이전 위치를 가리키지 않게 한다.
- 숫자 인덱스가 바뀌었더라도 다른 기능으로 잘못 이동하거나 해당 기능의 설정을 덮어쓰면 안 된다.
- 상위/하위 탭 전환은 그 기능을 켜고 끄는 동작이 아니다. 기존 기능별 활성 상태에 따른
  판독/편집 미리보기 정책은 유지하고, 새 부모 구조에서 실제 선택 화면 여부를 정확히 판단한다.
- 반복 전환만으로 새 캡처 작업, 오버레이, 타이머 또는 네트워크 조회가 중복 생성되지 않아야 한다.

### 6.1 단계별 첫 사용 안내 이후의 투어

단계별 게임창 등록/전투 기능 선택/추가 기능 선택과, 이후 앱 화면을 어둡게 하여 위치를
안내하는 앱 둘러보기를 구분한다. 앞의 설정 단계는 유지하고 마지막 앱 둘러보기만 새 메뉴에 맞춘다.
첫 사용 안내 전체의 마지막 단계인 '4 / 4'와 투어 내부 단계 수를 혼동하지 않는다.

탭 명칭, 기능 이동 및 탐색 방식에 연결된 투어 대상도 함께 변경한다.
아래는 구조 변경 시 함께 점검할 연결 기준이며 현재 배포본의 확정 버그 목록이 아니다.

| 현재 연결/설명 | 새 구조에서 필요한 조정 |
|---|---|
| 첫 단계가 기존 트래커 하위 탭 바를 강조 | 전투 보조를 연 뒤 현재 기능 탭 줄을 강조 |
| 편의기능에서 체력바/단축바/메모/커스텀과 계산기를 함께 소개 | 편의기능은 계산기와 향후 정보 조회·가이드용 공간으로 설명 |
| 투아림이 트래커 탭에 있다고 안내 | 전투 보조 > 도르카·투아림의 실제 위치로 안내 |
| 개별 기능 설정 단계가 앞 단계의 편의기능 화면 위에 남음 | 전투 보조의 예시 기능을 명시적으로 열고 해당 설정 영역을 보여줌 |
| 위치 잠금 단계가 특정 기능으로 이동하지 않는 중앙 설명 | 잠금 설정이 있는 예시 기능을 열고 실제 컨트롤을 화면 안에 보이게 한 뒤 안내 |
| 기능 열기가 기존 트래커/편의기능의 고정 하위 인덱스 사용 | 이동 후 실제 기능 탭을 정확히 선택 |
| 단계 진입은 기존 부모/탭 이동에 의존 | 이전/다음 어느 방향으로 들어가도 해당 단계의 화면과 대상을 먼저 준비 |

다음은 시안에서 확인할 7단계 투어 구성안이다. 모든 기능을 한 단계씩 설명하거나
첫 사용 안내에서 선택한 기능의 등록 성공을 투어 진행 조건으로 요구하지 않는다.

| 순서 | 제목 | 진입 및 강조 대상 | 안내 내용 |
|---|---|---|---|
| 1 | 전투 보조 | 전투 보조의 버프를 선택한 뒤 기능 탭 줄 | 버프·디버프·투아림과 자원 표시, 화면 배치 기능을 아래 탭에서 선택할 수 있어요. |
| 2 | 편의기능 | 편의기능을 열고 현재 계산기 선택 영역 | 분배금과 구슬 분배금, 구슬 교환 효율을 계산할 수 있어요. |
| 3 | 개별 기능 설정 | 전투 보조 > 버프를 열고 영역 지정/자동 찾기 조작 영역 | 아직 등록하지 않은 영역은 각 기능에서 찾거나 직접 지정할 수 있어요. |
| 4 | 오버레이 위치 잠금 | 버프 설정에서 위치 잠금 조작 영역 | 오버레이를 옮긴 뒤 잠그면 클릭이 게임으로 통과해요. |
| 5 | 전체 일시정지 | 상단 전체 일시정지 컨트롤 | 사용 중인 오버레이를 잠시 멈췄다가 다시 사용할 수 있어요. |

| 7 | 사용 안내 종료 | 화면 중앙 종료 안내 | 남은 설정은 각 기능에서 이어서 진행할 수 있어요. |

- 미구현 요리를 투어에서 현재 사용할 수 있는 기능으로 소개하지 않는다.
- 버프를 예시로 열어도 사용 체크, 영역 등록, 잠금 및 전체 일시정지 값을 실제로 바꾸지 않는다.
- 안내 중 로그아웃해도 접근할 수 없는 버튼을 강조하거나 베타 기능 사용을 강제하지 않는다.
  단계별 안내에서 시작한 투어의 접근 해제 처리는 기존 로그인 정책을 유지한다.
- 대상이 스크롤 밖에 있으면 먼저 보이게 한다. 대상의 숨겨진 전체 사각형을 강조하여
  다른 기능이나 화면 밖을 가리키지 않는다.
- 실제 표시된 탭/컨트롤의 화면상 영역을 기준으로 강조한다. 탐색 구조에 없는 좌측 목록이나 그룹 선택 단계를 안내하지 않는다.
  설명 카드가 읽는 데 필요한 대상과 핵심 투어 버튼을 가리지 않는지 렌더로 확인한다.
- 이전/다음을 반복해도 같은 단계에서는 같은 기능과 대상을 보여준다.
- 투어가 열려 있는 동안 제작자 말풍선을 닫고 기존 투어 중 잡담 제외 정책을 유지한다.
- 건너뛰기/완료, 안내 다시 열기, 트레이 숨김 또는 앱 종료로 투어를 닫을 때 암전 창과
  이벤트 연결이 남거나 종료 후 화면이 다시 나타나지 않아야 한다.
- 투어 완료/건너뛰기 기록과 영역 설정 완료 여부, 시작 시 다시 보지 않기 설정을 혼동하지 않는다.
  투어를 봤다는 이유로 미등록 영역을 등록 완료로 바꾸지 않는다.

### 6.2 투어 종료 후 화면 복귀 (승인)

2026-10-17 사용자 선택으로 아래 복귀 방식을 승인했다. 설정을 소개한 화면에 그대로 남기지 않는다.

- 단계별 첫 사용 안내에서 이어진 투어는 완료/건너뛰기 후 전투 보조 > 버프로 이동한다.
- 설정에서 명시적으로 다시 연 투어는 완료/건너뛰기 후 시작 직전의 상위 탭/기능 선택으로 돌아간다.
- 기능의 사용 여부, 저장 영역 및 일시정지 상태는 복귀 위치와 관계없이 그대로 유지한다.
- 해당 화면이 더 이상 접근 가능하지 않으면 가능한 화면으로 복귀하되 접근 조건을 무시해 실행하지 않는다.
- 앱 종료나 트레이 숨김 때문에 닫힌 투어는 위 복귀를 이유로 창을 다시 표시하지 않는다.

## 7. 화면 폭과 기존 배치

- 기존 2단 탭형 화면과 같은 본문 가로 공간을 유지한다. 기능 탐색을 위한 상주 사이드바를 두지 않는다.
- 기본 창 크기와 기본 글꼴에서 버프/디버프의 '목록 왼쪽, 선택 항목 설정 오른쪽' 배치를 유지하는 것이 핵심 승인 기준이다.
- 탐색 구조 변경만을 이유로 위아래 편집 배치로 전환되거나, 기존에 동시에 보이던 목록과 설정 사이를 스크롤해야 해서는 안 된다.
- 본문 위에 그룹 탭/제목 줄을 추가해 3단 탭으로 만들거나 기존보다 탐색 줄의 높이를 늘리지 않는다.
- 기존 기능을 좁은 폭에 잘라 넣거나 입력칸·글꼴·아이콘을 축소해 좌우 배치를 형식적으로 유지하지 않는다.
- 기존 입력칸·버튼·목록·미리보기의 의미와 조작을 유지하면서 읽고 누를 수 있게 배치한다.
- 큰 글꼴이나 작은 작업 영역으로 원래 두 열이 들어가지 않던 환경에서는 기존 반응형 배치와 세로 스크롤을 유지한다.
  이 예외가 기본 크기/기본 글꼴에서의 좌우 배치 보존 조건을 대체하지는 않는다.
- 여덟 기능 탭이 기본 창 폭과 기본 글꼴에서 한 줄로 보이는지 실제 치수로 확인한다.
  기본 환경에서 일부 탭이 넘침 화살표 뒤에 숨으면 시안을 다시 조정하고 사용자에게 확인받는다.
- 큰 글꼴 등 탭 폭이 부족한 환경의 넘침 처리에서는 모든 기능으로 이동할 수 있어야 한다.
  가로 탭 자동 줄바꿈으로 새 탐색 줄을 만들거나, 이름을 설명 없이 임의 축약하지 않는다.
- 탭 사이 구분선/간격은 실제 표시 여유 안에서 적용한다. 시각 구분 때문에 탭이나 본문 접근성을 희생하지 않는다.
- 기능 이름이 잘리지 않고 긴 보스 패턴 알림/커스텀 오버레이도 식별 가능해야 한다.
- 화면이 작거나 DPI/글꼴이 커도 모든 기능과 설정 조작에 접근할 수 있어야 한다.
- 제작자 얼굴과 말풍선 정책은 유지한다. 버프/디버프의 하단 활용과 작은 화면 예외도
  새 선택 구조에서 기능별로 판단하며, 부모 변경 때문에 얼굴이 설정을 상시 가리지 않게 한다.

## 8. 저장 설정 및 예외

- 기능을 옮기기 위해 기존 설정 파일을 초기화하거나 사용자에게 재등록을 요구하지 않는다.
- 영역, 기능 사용, 개별 아이콘/소리, 임계값, 잠금, 위치, 배율, 메모, 프리셋 및 계산기 입력을 보존한다.
- 재실행 시 복원하는 기존 기능별 설정과 이번 실행에서의 화면 선택 상태를 구분한다.
- 로그인/로그아웃과 전체 일시정지 후에도 탐색 항목의 선택 상태와 실제 접근 권한이 일치해야 한다.
  이름에 베타가 없다는 이유로 권한 없는 기능을 실행하지 않는다.
- 숨김/비활성 항목으로의 오래된 진입 요청은 접근 조건을 확인하고 안내한다.
  유효하지 않은 요청 때문에 앱을 종료하거나 임의의 다른 기능을 실행하지 않는다.
- 게임 실행/종료, 창모드 전환, 캡처 실패 등의 처리는 기존 기능의 책임으로 유지한다.
  이번 분류 변경 때문에 게임 상태 판정이나 자동찾기 알고리즘을 바꾸지 않는다.

## 11. 개발 전달과 시안 확인

1. 이 문서를 메뉴 분류와 이동 대상의 최종 기준으로 사용한다. 이전 문서의 기능 설명에서
   예전 탭 경로가 나오면 위치만 본 문서 기준으로 갱신하며 기능 동작은 해당 기능 명세를 유지한다.
2. 기본 버프, 디버프, 도르카, 커스텀 오버레이, 편의기능 및 큰 글꼴/좁은 작업 영역 시안을 공유한다.

   6.1절 투어의 새 문구/강조 대상과 6.2절 복귀안을 함께 확인받는다.

   기존 기능 컨트롤 삭제 또는 좌측 탐색 목록/3단 탭으로의 변경을 확정하지 않는다.
4. 새 경로로 이동하는 모든 내부 진입점과 접근 권한, 현재 선택 여부 판정을 검증한다.
5. 정상 동작을 소스 검토나 문서 상태만으로 주장하지 않는다. UI 렌더와 자동 검증 및 실제 Windows 확인 결과를 구분한다.

현재 참고 소스는 `ui/main_window.py`의 탭 생성/초기 진입/기능 이동/투어/파티 진입,
`ui/dorcha_tab.py`의 베타 접근과 선택 화면 판정, `ui/creator_dialogue.py`의 화면별 하단 배치이다.
이는 기존 연결 지점 안내이며 특정 UI 클래스나 프레임워크 구조를 강제하지 않는다.


2026-10-21 사용자 후속 정정: 최적화 알파는 **제작자에게만 상위 최적화 탭을 노출**한다.
복구 기록이 남아 있어도 비제작자/로그아웃 상태에 복구 전용 탭이나 설정 버튼을 노출하지 않는다.
제작자로 다시 확인되면 같은 최적화 탭에서 명시적으로 복구한다. 로그아웃/종료 시 CPU 자동 원복과
소유 FPS 수집 정리, 미복구 네트워크 기록 보존은 유지한다. 네트워크 원복 안내/실행은 탭의 원복 버튼에서
진행하며 탭 밖 자동 팝업으로 대체하지 않는다. 앞선 비제작자 복구 예외 시안보다 이번 사용자 정정이 우선한다.

## 12. 홈 화면 (2026-10-29 사용자 결정, 0.28.0)

- 기준 이미지: [`docs/qa/assets/home_draft_20261029/home.png`](qa/assets/home_draft_20261029/home.png)(창 800),
  [`home_creator.png`](qa/assets/home_draft_20261029/home_creator.png)(제작자 잡담 켜짐, 창 864). 사용자가 준 디자인 시안을 지금 앱 기능·창 크기에 맞춰 손본 것(사용자: "앱에 맞게 하려면 이정도가 최선").
- 목적: 개별 화면에서 설정을 마치면 개별 화면은 볼 일이 적다(0.27.0 영역 접기와 같은 관점). 홈에서 **잘 돌고 있는지 확인하고 켜고 끈다**.

### 12.1 진입과 나가기
- **상위 탭으로 넣지 않는다**(2절 "메인 상위 탭 추가 안 함" 유지). 앱 화면 상태 줄 **왼쪽**에 `홈` 버튼(직접 그린 집 아이콘 + `홈`, 이모지 금지)을 두고, 누르면 홈이 앱 창 전체(상태 줄·탭 포함)를 덮는다.
- 홈 오른쪽 위 `전체 메뉴 ›`를 누르면 홈을 닫고 앱 화면(마지막으로 보던 탭)으로 간다.
- **앱을 새로 띄우면 홈부터** 보인다. 첫 사용 안내가 떠야 하는 경우(`needs_start_screen`)는 안내가 먼저이고, 안내를 마치거나 `나중에 설정`하면 홈. 트레이에서 창을 다시 열 때는 마지막으로 보던 화면을 유지한다.

### 12.2 화면 구성(위에서 아래, 창 790×800에 스크롤 없이)
1. 위 줄: 왼쪽 앱 로고, 오른쪽 `전체 메뉴 ›`.
2. **상태 카드**: 왼쪽 원형 상태 아이콘(체크) + 제목 + 요약, 오른쪽 `전투 보조` 스위치(상단 `● 전투 보조: 켜짐/일시정지`와 같은 동작·동기화).
   - 제목: `마비노기 실행 중 · 화면을 읽고 있어요` / 게임 비활성 `마비노기를 기다리는 중` / 일시정지 `전투 보조 일시정지`(아이콘도 상태 아이콘 B안 계열로).
   - 요약: `전투 보조 N개 동작 중 · M개 설정 필요`(설정 개수 기반, 판독 값 아님. M=0이면 뒤쪽 생략).
3. **`설정이 필요한 기능 M개`** 경고 상자(주황): 사용자가 쓰기로 고른 기능 중 영역이 없는 것만, 줄마다 `<기능명>  판독 영역을 지정해야 동작해요  [영역 지정]`.
   `영역 지정`은 홈을 닫고 그 기능 화면의 영역 지정 상자(0.27.0)로 이동. **M=0이면 상자 자체를 숨긴다.**
4. **전투 보조** 묶음(제목 오른쪽 `전투 보조 탭 열기`), 2열 10줄: 버프 · 디버프 / 보스 패턴 알림 · 1분 헤일로 / 체력바 · 도르카 표시 / 투아림 알림 · 커스텀 오버레이 / 단축바 · 메모.
5. 아래 한 줄 3칸(중요도·자주 보는 순, 사용자 결정): **최적화**(게임 최적화, FPS 표시) · **블랙박스**(최근 영상 보관) · **파티 모집**(키워드 알림).

### 12.3 줄의 규칙
- 줄 = 이름(굵게) + 상태 점·한 줄 + (스위치) + `›`. 줄이나 `›`를 누르면 홈을 닫고 해당 화면으로.
- **스위치는 지금 앱에 켜고 끄는 설정이 있는 기능에만**: 체력바(표시), 도르카 표시, 투아림 알림(사용), 커스텀 오버레이(사용), 게임 최적화(아래 C안), FPS 표시, 블랙박스(사용).
  버프·디버프·보스 패턴·1분 헤일로·단축바·메모·키워드 알림은 `›`만(영역이 있으면 항상 동작 — 새 끄기 기능을 만들지 않는다). 스위치는 해당 화면의 설정과 같은 값이며 양쪽이 동기화된다.
- **상태는 판독 값 없이**(오독이 홈에 크게 노출되는 것 방지, 사용자 결정): 초록 `추적 중`·`표시 중`·`감시 중`·`적용 중`·`보관 중` / 회색 `대기 중 · …`(예: `보스가 보이면 동작`, 최적화 `게임 대기`)·`꺼짐` /
  노랑 `영역 지정 필요`(칸은 영역이 없으면 고르지 않은 기능도 노랑, 경고 상자·`M개 설정 필요`는 첫 사용 안내에서 고른 기능만 — 안내·도움말 명세 13절 7항). 숫자(버프 개수, %, 도르카 값, 보관 시간 등)는 쓰지 않는다. 상태 판단은 각 화면의 상태(0.27.0 요약 줄·기존 상태 줄)를 그대로 쓰고 홈에서 새로 판독하지 않는다.
- **게임 최적화 스위치 = C안 `최적화 사용`**(사용자 결정): 켜면 자동 적용(최적화 명세 13.10) 켜기 + 게임 실행 중이면 바로 적용, 끄면 자동 적용 끄기 + 지금 적용분 바로 원복.
  상태 `게임 대기` / `적용 중` / `보류`. 패스트핑(네트워크)은 홈 스위치로 바꾸지 않는다(13.10 원칙, 최적화 탭에서 적용).
