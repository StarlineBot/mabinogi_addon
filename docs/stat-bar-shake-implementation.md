# 체력바 흔들림 개발 검증

## 범위와 승인

- 기준: [저값 경고 명세](stat-bar-shake-warning-spec.md)의 SB-01~12.
- 실제 체력바 그림으로 만든 6초 비교 시안과 실행 가능한 HTML을 공유했고 사용자가
  B안(100% 배율에서 좌우 3px, 0.4초 동안 2회 왕복, 1.4초 휴지)을 승인했다.
- 미리보기 재생성: `PYTHONPATH=src QT_QPA_PLATFORM=offscreen python scripts/render_stat_shake_preview.py --gif`.
  `--gif`만 ffmpeg가 필요하다. 기본 출력은 `/tmp/stat-shake-preview/index.html`이다.
- 마우스 하이라이트, 보스전 외 경고 확대, 음원 변경 및 새 조절 옵션은 구현하지 않는다.

## 구현

- `StatBarsTab`은 기존의 완전한 세 바 판독과 보스 존재 조건을 공유한다. 표시 가능한
  바에 대해 별도로 연속 저값 시간을 확인하고 0.4초 이후 시각 경고를 켠다.
  기존 소리 무장/회복 정책과 시각 경고 상태를 분리하여 효과 반복이나 숨김/복귀가
  소리를 재무장하거나 재생하지 않는다. 소리 OFF는 시각 경고에 영향을 주지 않는다.
- `StatBarOverlay`의 창 위치는 애니메이션 동안 고정이다. 기존 색·수치·채움 비율을
  같은 그림 경로로 그리며, 그리기 좌표만 이동한다. 좌우 투명 여백은 이동 최대치에
  맞춰 확보하고 `base_position`/`move_base`로 예전 저장 좌표와 드래그/격자 기준을 보존한다.
- 바별로 하나의 단발 QTimer만 소유한다. 움직이는 구간은 약 30fps로 갱신하고,
  휴지 구간은 다음 움직임 또는 판독 유효기간에 맞춰 예약한다. 정상/숨김/중단 상태에서는
  효과 타이머를 정지한다. 새 캡처·판독·스레드는 추가하지 않는다.
- 유효 판독 없이 효과만 남는 것을 막기 위해 마지막 세 바 판독에서 0.65초 이상 지나면
  효과와 확인 대기를 해제한다. 원래 200ms 판독 주기는 유지하고, 긴 공백 후에는 새로
  0.4초 확인한다. 절전 중 놓친 애니메이션을 재생하거나 이전 위상을 복원하지 않는다.
- 회복, 일부 판독 실패, 캡처 실패, 보스 조건 해제, 경고/표시/기능 OFF, 로그아웃,
  전체 일시정지, 비활성 숨김, 원본 영역 재지정과 종료에서 중단한다.
  임계값·경고 변경은 아직 유효한 캐시만 재평가하며 새 캡처나 소리를 발생시키지 않는다.

## 검증

- 집중 검사: **50 passed (2.75초)**. 기존 저값 원본 PNG 안정성 검사 18건을 포함한다.
- 150% Qt 배율 집중 검사: **50 passed (3.13초)**. Windows 혼합 DPI 검증과 구분한다.
- 전체 격리 회귀: **1009 passed, 4 deselected, 3 warnings (208.25초)**.
  제외는 별도 Windows 네이티브 검사 4건, 경고는 기존 QMouseEvent API 사용이다.
  Discord 로컬 서버 검사는 서버 바인딩이 허용된 권한으로 실행했으며 장치 대체와
  QThread 누수 검사는 유지했다. `git diff --check`도 통과했다.
- 새 검사는 임계값 동등 경계/짧은 저값/세 바 동시 경고/회복의 독립성/반복 중 위상 유지,
  무음, 판독 오류, 숨김·로그아웃·영역 변경·종료, 최신성 만료와 새 확인 지연을 실행한다.
- 실제 Qt 타이머로 그림이 움직이고 숨김 후 갱신이 멈추는 것을 확인한다. 500회 실제 탭
  틱에서도 캡처 500회, 오버레이 3개, 효과 타이머 각 1개로 유지된다. 장시간 실측을 대신하지 않는다.
- 배율 50/100/150/300%의 양끝 이동에서 RGBA 픽셀 합 보존·경계 투명 여백을 검사한다.
  음수 좌표에서 배율/잠금/저장·격자 ON/OFF 드래그를 거쳐 저장 기준 위치를 확인한다.
- Windows 게임 동시 실행, 실제 클릭 통과/포커스, 혼합 DPI, 모니터 연결, 잠금/절전 및
  장시간 CPU·핸들 사용은 Linux offscreen 결과로 통과를 주장하지 않는다.
- main 푸시 전 사용자 확인을 받는다. 푸시 후 해당 SHA의 Windows 회귀·네이티브·exe
  빌드 성공을 별도로 확인하며, 릴리즈·태그는 진행하지 않는다.
