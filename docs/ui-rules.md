# 화면 규칙 모음

새 화면이나 화면 변경을 만들 때 **이 문서를 먼저** 본다. 지금까지 사용자가 결정한 화면 규칙을 한곳에 모았다.

- 원본은 각 명세에 있고, 여기에는 **결론만** 적는다. 이유와 예외의 근거는 링크한 절을 본다.
- 규칙이 바뀌면 원본 명세와 이 문서를 함께 고친다. 두 곳이 어긋나면 날짜가 늦은 사용자 결정이 우선이다.
- 화면을 만들거나 바꾸면 렌더해서 사용자에게 확인받는다([CLAUDE.md](../CLAUDE.md) '화면(UI) 개발').

## 1. 화면 틀 (탭 한 장의 순서)

1. **머리**: `FeatureHeader`(`ui/widgets.py`)로 둔다.
   - 제목, 회색 요약 1~2문장(`feature_copy.DESCRIPTIONS`), 구분선을 넣는다.
   - 필요한 화면만 오른쪽 위에 `?` 도움말 버튼을 둔다.
   - 근거: [안내 명세 2절](app-copy-help-combat-controls-spec.md#2-문구-원칙), [10절](app-copy-help-combat-controls-spec.md#10-화면-다듬기-원칙-2026-10-28-사용자-결정--5절-도움말-구성본문의-대상-목록에-우선)
2. **영역 지정**: 판독이 필요한 기능만 둔다. 11절 접기 규칙을 따른다(아래 3절).
3. **평소 쓰는 조작**: 표시, 위치 잠금, 배율, 불투명도, 알림.
4. **세부 설정**
5. **맨 아래**: 지원 목록 같은 참고 정보, 그다음 **진단·수집은 항상 맨 아래 접힌 `진단 · …`**.
   - 단, 영역이 잘 됐는지 보는 판독 미리보기와 상태는 사용 정보라 제자리에 둔다([10절](app-copy-help-combat-controls-spec.md)).

**그 밖의 틀 규칙**
- 탭 내용 왼쪽 여백은 **12px**로 모든 탭이 같다.
- **`?` 도움말은 중요하고 어려운 화면에만** 둔다. 기능을 추가할 때마다 넣지 않는다.
  - 있음: 버프, 디버프, 보스 패턴, 1분 헤일로, 체력바, 도르카·투아림, 커스텀 오버레이, 단축바, 블랙박스, 최적화, FPS 측정, 마우스 커서
  - 없음: 메모, 파티 모집, 계산기, 설정
  - 도움말 본문 순서는 `어떤 기능인가요? → 설정하는 방법 → 알아두세요`이다.
- **긴 설명은 도움말로** 옮기고 화면에는 한 줄만 남긴다. 단, 중요한 제약을 도움말로만 옮기지는 않는다.

## 2. 탭 단계

| 단계 | 예 | 선택된 탭 색 |
|---|---|---|
| 1단(상위 탭) | 전투 보조, 편의기능, 최적화 | 강조색 + 밑줄 |
| 2단(기능 탭) | 버프, 디버프, 계산기 … | 연한 강조색(`accent-soft`) + 밑줄 |
| 3단 | 보스 `체력별 패턴 / 1분 헤일로`, 계산기 안 4종 | 회색(`_tertiary_qss`) |

- 모양은 바꾸지 않고 **색만 단계별로** 다르게 한다. 근거: [14절 1항](app-copy-help-combat-controls-spec.md#14-탭-단계-색fps-정리기능-켜기-스위치-2026-10-30-사용자-결정-0290--0282-전체-렌더-재검토-렌더-목업-확인).
- 상위 탭을 늘리지 않는다. 새 기능은 성격이 맞는 2단 탭에 넣는다(예: 마우스 커서는 최적화 2단).

## 3. 영역 지정 화면 (설정을 마친 영역은 접는다)

- **지정 전**: 맨 위 `영역 지정` 상자로 구성한다.
  - 주황 `● 아직 지정 안 됨 — 지정하면 …`
  - 버튼 `자동 찾기 · 직접 지정 · 지정 영역 보기 · 지정 해제`
  - 안내 **한 줄**
  - 판독 미리보기
- **지정 후**: 한 줄 요약 `✓ 영역 지정됨 · <현재 판독 값>`과 접힌 `영역 다시 지정 ▸`로 구성한다. 버튼, 안내, 판독 확인은 접힌 안에 넣는다.
- 자동 찾기를 끈 동안 10초 넘게 읽지 못한 안내는 접힌 본문 밖, 등록 요약 아래에 표시한다. 평소 판독 값과 분리하고 정상 판독 회복·자동 찾기 설정 변경 시 해제한다.
- 지정을 막 마친 직후에는 그 세션 동안 펼쳐 둔다. 다음에 탭을 열 때부터 접는다.
- 용어는 `영역 미지정`으로 쓴다(`미등록` 쓰지 않음).
- 근거: [11절](app-copy-help-combat-controls-spec.md#11-설정을-마친-영역은-접는다-2026-10-29-사용자-결정--렌더-목업-확인)

## 4. 조작 모양 (무엇을 어떤 위젯으로)

| 종류 | 모양 | 예 | 근거 |
|---|---|---|---|
| **기능 켜기·끄기**(사용) | **스위치**(`widgets.switch`, `feature_switch`). 홈 스위치와 같은 값 | `블랙박스 사용`, `FPS 표시`, `커서 표시`, `최적화 사용`, `자동 찾기 사용`, 첫 사용 안내 3단계 | 13.8, 14.5 |
| **위치 잠금** | 상태형 버튼(`settings_layout.lock_button`). 켜짐 = 강조색 `위치 잠금됨`, 꺼짐 = 회색 `위치 잠금` | 각 오버레이, `전체 위치 잠금(됨)` | 13.1, 13.8 |
| **세부 옵션**(표시·소리·항목) | 체크박스 | `표시`, `소리 알림`, `생명력/마나/스태미나` | 13.8 |
| **바로 실행하는 동작** | 일반 버튼 | `자동 찾기`, `직접 지정`, `알림 미리보기` | 13.8 |
| **지우기·초기화** | 일반 버튼 + 위험색 글자(`danger_style`) | `선택 삭제`, `－ 삭제` | 14.6 |
| **추천 설정 바로 적용** | 상태형 버튼(`style_toggle`, 적용 중 = 강조색). 스위치 아님 — 관리자 권한·패스트핑을 포함한 '지금 적용' 동작이라서 | `추천 설정으로 최적화` | 14.5 |

- 같은 줄에 스위치 두 개를 붙이지 않는다.
- 상태를 버튼 색으로 보여주는 것은 **위치 잠금뿐**이다. "초록 버튼 = 잠금" 규칙이 깨지지 않게 하기 위해서다.
  예외로 하나 남은 상태형 버튼은 최적화의 `추천 설정으로 최적화`(바로 적용 동작, 14.5)이다. `블랙박스 사용`·`FPS 표시`는 0.29.0부터 스위치다.
  `settings_layout.lock_style`·`style_toggle` 주석의 옛 예(FPS·블랙박스)는 이 규칙보다 앞선 기록이다.
- 이모지 대신 글자나 직접 그린 아이콘을 쓴다. 예외로 유지하는 것: 파티 모집 종(🔔/🔕), 디버프 `⚙`.
- **미정**: "여러 개 중 하나 고르기"는 아직 통일되지 않았다. 분할 버튼(마우스 커서 모양·꼬리)과 라디오(계산기 수수료)가 섞여 있다. 새 화면을 만들 때 사용자에게 확인한다.

## 5. 버튼 크기

- **높이**: 모든 버튼은 **일반 버튼 기본 높이**(`settings_layout.plain_button_height()`)를 쓴다.
  - 상태형 버튼(위치 잠금, `추천 설정으로 최적화`)도 `style_toggle`로 같은 높이에 맞춘다.
  - 굵기는 보통이다(굵게 하지 않음).
- **폭**
  - 일반 버튼은 **글자에 맞춘 폭**을 쓰고 왼쪽에 정렬한다. 전체 폭으로 늘리지 않는다.
  - 예외: 한 줄에 같은 무게의 버튼을 나란히 둘 때(예: 영역 버튼 4개)는 같은 폭으로 맞춘다.
  - **위치 잠금은 같은 종류끼리 같은 폭**(`lock_width`)이다. 일반 `위치 잠금(됨)`과 `전체 위치 잠금(됨)`의 폭이 서로 다르다.
  - 같은 폭은 **같은 상자 안에서만** 맞춘다. 화면끼리 버튼 위치를 맞추지는 않는다.
- **버프·디버프 잠금 줄**은 `위치 잠금 │ 표시 배율 │ 불투명도` 한 줄 세 칸이다([15절](app-copy-help-combat-controls-spec.md)). 이 줄 때문에 화면이 두 칸에서 한 칸으로 접히면 안 된다(0.31.0 버그).
- 근거: [13.1](app-copy-help-combat-controls-spec.md#13-화면-마무리-다듬기-2026-10-29-사용자-결정-0281--0280-실화면-피드백-렌더-목업-확인), [13.9](app-copy-help-combat-controls-spec.md), status 0.28.2 B안

## 6. 줄 맞춤·간격

- 한 상자 안 여러 줄의 이름 칸은 **가장 긴 이름 폭**에 맞춘다(`settings_layout.name_label`). 그래서 상자 안 잠금 버튼이 같은 세로선에 선다.
- `라벨 → 옆 조작` 간격은 6~9px로 모든 화면이 같다.
- 숫자 입력은 짧은 칸으로 둔다(`SuffixSpinBox`, 단위 `px`·`%`·`초 전`은 칸 안에).

## 7. 글자

- **말투**: 설명은 `~해요`, 부탁은 `~해 주세요`로 쓴다. `~합니다` 체는 쓰지 않는다. 문서 문자열·로그·예외·진단 기록은 예외다.
- **제목·버튼·짧은 상태**는 문장으로 늘리지 않는다. 예: `직접 지정`, `등록됨`, `찾는 중…`.
- **안내 문구는 회색**(`hint_label`, 이름 색 `muted`)으로 쓴다. 꼭 알아야 할 제약만 `callout`(주황 상자)으로 승격한다.
- **구역 제목**은 `section_label`(굵기 600)로 쓴다.
- **용어**
  - `자동설정`은 첫 사용 안내의 일괄 설정, `자동 찾기`는 기능별 탐색이다. 서로 바꿔 쓰지 않는다.
  - `위치 잠금`(이동 막고 클릭 통과), `영역 미지정`, `생명력`(자원명. 기능명 `체력바`와 보스 `체력`은 유지), `디스코드`(앱 화면 표기)
  - 구현 용어를 쓰지 않는다(앵커, 렌더, 게이팅, 미러 등). 기능명 `커스텀 오버레이`는 유지한다.
  - 앱 화면에 `알파`·`베타`라는 말을 쓰지 않는다.
- 경로 표기는 화면 이름 그대로 쓴다. 예: `설정 › 일반`, `전투 보조 › 도르카·투아림`.
- 근거: [안내 명세 2절](app-copy-help-combat-controls-spec.md#2-문구-원칙), 14절 2·3항

## 8. 색 (이름 색 8가지)

화면 코드는 값이 아니라 **이름**만 쓴다(`ui/palette.color(name)`). 개인화 테마에서 값이 바뀌기 때문이다.

| 이름 | 쓰는 곳 |
|---|---|
| `accent` | 1단 탭, 잠금됨, 스위치, 링크 |
| `on-accent` | 강조색 버튼 안 글자 |
| `accent-soft` | 2단 탭 선택 글자 |
| `muted` | 안내 문구, 선택 안 된 탭, 꺼짐·대기 |
| `ok` | 켜짐, 등록됨, 추적 중 점 |
| `warn` | 영역 지정 필요, 경고 상자 |
| `danger` | 일시정지, 삭제·초기화 |
| `brand` | 제작자 캐릭터 테두리 |

- 값을 직접 쓰지 않는 대상 밖: 게임 위 오버레이 색, 메모 글씨 색
- 상태 점은 `● 상태` 형식(색 + 글자)으로 쓴다. 색만으로 의미를 전하지 않는다.
- 근거: [14절 6항](app-copy-help-combat-controls-spec.md), [테마 개인화 명세](theme-personalization-spec.md)

## 9. 오버레이 공통

- **위치 잠금** = 이동 막기 + 클릭 통과. 잠금을 풀면 드래그로 옮기고, 격자 맞춤(`ui/grid`)을 따른다.
- **배율**은 `표시 배율` 칸이다. **불투명도**는 그 옆에 `불투명도 100%`(기본)~`20%`, 10%씩 둔다([15절](app-copy-help-combat-controls-spec.md)).
  - 지금 불투명도가 있는 곳: **버프·디버프만**(0.31.0).
  - 후속(같은 규칙, [TODO](TODO.md)): 체력바·도르카·단축바·FPS·커스텀 오버레이.
  - 대상 아님: 메모(글자 크기를 씀), 경고류(보스 패턴 경고·1분 헤일로·투아림 알림).
- 우리 오버레이는 판독 캡처에서 빼야 한다(`CaptureGuard` / 캡처 제외). 우리 창이 판독 영역을 가리면 안 된다.
- **언제 보이나**(버프 오버레이 `_apply_visibility` 기준):
  - 일시정지 중이거나 `오버레이 창 보이기`를 끄면 항상 숨긴다.
  - 게임이 앞에 있으면 보인다(표시할 것이 있을 때. 잠금을 푼 편집 중이면 빈 자리라도 보임).
  - **잠금을 푼 편집 중에는 우리 앱이 앞에 있어도 보인다** — 위치를 옮길 수 있어야 하기 때문(메모 포함).
  - 그 밖(잠금 상태 + 게임이 뒤)에는 숨긴다.
  - **미리보기**(`알림 미리보기` 등)는 사용자가 누른 동작이라 게임이 뒤에 있어도 잠깐 보인다.
  - 새 오버레이도 이 규칙을 따른다.

## 10. 목록

- 순서가 있는 목록은 **끌어서 순서 바꾸기 + ▲▼ 버튼**을 함께 둔다(`settings_layout.enable_drag_reorder`). 끌기 안내 문구는 두지 않는다. 기준 항목은 맨 위에 고정한다([15절](app-copy-help-combat-controls-spec.md)).

## 11. 홈

- 기능 줄은 `이름 / ● 상태 | 스위치 | ›`이다. 스위치는 탭 안의 켜기 스위치와 같은 값이다.
- `영역 지정 필요`는 고르지 않은 기능이라도 줄에 표시한다(13.7).
- 근거: [탐색 구조 명세 12절](navigation-structure-spec.md)
