# 판독 불가 체력바 표시 수정

## 대상과 재현

- 기준: [판독 불가 깜빡임 QA](qa/체력바_판독불가_깜빡임_QA.md)의 `STAT-VIS-QA-01`.
- 원본 QA 문서와 `scripts/qa_stat_overlay_invalid_frame_flicker.py`는 수정하지 않는다.
- 원본 재현을 직접 실행해 수정 전 **8 failed, 2 passed (0.62초)**를 확인했다.
  고정 검정/부분 가림/업로드 PNG의 원본 좌표 ROI에서 반복 Show/Hide가 발생하며,
  캡처 None은 최초 기본 바 또는 이전 표시를 유지했다. 업로드 ROI를 당시 라이브 캡처와
  동일하다고 단정하지 않으며 결함 재현은 고정 검정/부분 가림에도 독립적으로 성립한다.

## 원인과 수정

- 기존 틱은 판독 전에 `_apply_visibility()`로 창을 보인 뒤, 실패할 때 숨겼다.
  다음 틱도 실패 이력을 확인하지 않아 Show/Hide를 반복했다. None 경로는 숨김도 빠져 있었다.
- `_display_valid`는 시작 시 False이며, 세 바 모두 유효하게 판독된 후에만 True가 된다.
  각 수치를 모든 오버레이에 먼저 적용하고 나서 표시 정책을 실행한다.
- 검정/불완전/잘못된 비율/캡처 None은 유효성을 해제하고 숨김을 유지한다.
  기존 수치를 0으로 바꾸거나 판독 임계값·완전성 검사를 완화하지 않는다.
- 기능 OFF/전체 정지/로그아웃/비활성/영역 없음과 영역 재지정은 유효성을 폐기한다.
  조건 복귀만으로 창이 나타나지 않고 새 정상 캡처를 기다린다. 표시 체크와 잠금 변경도
  유효 판독이 없는 기본/직전 바를 다시 표시하지 않는다.
- 판독 불가 중에는 위치 편집을 위한 기본 바도 표시하지 않는다. 정상 판독 후 기존
  잠금 해제/드래그/격자/위치 저장은 유지한다. 별도의 가짜 판독 또는 편집 미리보기를 추가하지 않는다.
- 소리 무장/회복 정책과 시각 경고의 0.4초 확인·실패 중단·저장 기준 좌표는 유지한다.
  캡처 주기, 판독기, 효과 타이머와 워커는 변경하지 않는다.

## 검증

- 수정 후 원본 재현 10건, 흔들림/기존 PNG 회귀 50건, 독립 흔들림 8건을 함께 실행해
  **68 passed (7.39초)**. 원본 재현의 기존 assertion은 그대로다.
- 새 정규 회귀 `tests/test_stat_visibility.py` 20건과 흔들림/기존 PNG 검사:
  **70 passed (3.65초)**. 최종 숨김뿐 아니라 틱 중간의 Show 이벤트와 그 순간의 값을 검사한다.
- 150% Qt 배율에서 새 표시 검사 20건·QA 원본 10건·독립 흔들림 8건:
  **38 passed (5.85초)**. 실제 Windows 혼합 DPI 검사와 구분한다.
- 전체 격리 회귀: **1029 passed, 4 deselected, 3 warnings (211.26초)**.
  제외는 별도 Windows 네이티브 4건, 경고는 기존 QMouseEvent API다.
  로컬 서버 바인딩 권한으로 실행했고 장치 대체와 QThread 누수 검사는 유지했다.
  `git diff --check`도 통과했다.
- 검정/부분 가림/업로드 ROI/None의 최초·정상 후 상태, 정상 복구, 반복 정상 입력,
  표시/일시정지/기능/로그인/포커스/영역/잠금 왕복을 확인한다. 새 판독 이전의 표시를 금지하며
  복구 Show 시의 세 수치가 원본 판독과 일치하는지 확인한다.
- 흔들림 단위 시험의 판독 입력 도우미도 실제 틱과 같이 수치 적용 후 유효 표시 상태를
  전달하도록 변경했다. 기존 효과·좌표·소리 assertion은 삭제하거나 완화하지 않았다.
- 실제 Windows 맵 이동·잠금·DPI·게임 compositor는 Linux offscreen에서 확인하지 못한다.
  새 커밋의 자동 Windows 회귀·네이티브·exe 빌드 결과는 푸시 후 별도로 확인한다.
- 수정 푸시는 후속 독립 QA 통과 또는 실제 게임 라이브 검증을 의미하지 않는다.
  릴리즈 명령·태그·배포는 진행하지 않는다.
