- 기존 설정과 사용자가 등록한 영역·프리셋을 초기화하거나 재등록을 요구하지 않는다.

## 3. 공통 버튼과 위치 잠금

### 3.1 단일 대상

- 잠금 해제 상태는 `위치 잠금`, 잠금 상태는 `위치 잠금됨`인 토글 버튼으로 표시한다.
- 잠긴 토글은 민트색 계열의 선택 상태로 통일한다. 일반 명령 버튼과 구별되며 밝은/어두운 테마 모두 읽을 수 있어야 한다.
- 보스 경고와 목록처럼 대상이 여럿이면 `경고 위치 잠금(됨)`, `목록 위치 잠금(됨)`처럼 대상 이름을 포함한다.
- 초기 로드, 화면 재진입, 다른 조작으로 잠금 변경 시 실제 상태와 문구·색이 일치해야 한다.
- 실제 이동 가능 여부와 클릭 통과 등 기존 잠금 동작을 유지한다.

### 3.2 여러 대상에 대한 명령

- `전체 잠금`, `전체 잠금 해제`는 서로 별개의 일반색 명령 버튼으로 유지한다. 상태 토글로 바꾸지 않는다.
- `일부 잠금`, `전체 잠금됨` 등의 종합 상태나 잠긴 개수 표시는 추가하지 않는다.
- 체력바에는 생명력·마나·스태미나 각각의 잠금 토글을 제공한다. 전체 명령도 함께 제공한다.
- 단축바에는 개별 그룹 목록이나 그룹별 잠금 조작을 새로 만들지 않는다. 기존 전체 명령으로 충분하다.
- 커스텀은 현재 목록의 잠금 정보와 선택/전체 대상 명령을 유지한다. 다른 화면과 맞추기 위해 목록에 새 토글 열을 강제하지 않는다.

### 3.3 기타 명령

- 자동찾기·직접 지정·영역 보기·추가·불러오기 등의 일반 명령은 기본 중립색을 사용한다.
- 지정 해제·삭제 등 파괴적 명령은 보조 위치와 붉은 글자 등으로 구별하되 넓은 강한 경고색 면을 반복하지 않는다.
- 대상이 없는 명령은 비활성화한다. 비활성 삭제 버튼이 활성 경고색처럼 보이지 않아야 한다.
- 네이티브 체크박스와 라디오까지 일괄 재색칠하는 작업은 요구하지 않는다.

## 4. 버프

### 4.1 기준 버프를 선택했을 때

- 왼쪽 목록과 오른쪽 상세의 기존 2열 구성을 유지한다.
- 기준 버프 선택 시 오른쪽은 일반 설정 폼 대신 기준 버프의 역할을 설명하는 전용 화면으로 전환한다.
- 이름과 아이콘을 보여주고 다음 내용을 명시한다.
  - 버프 트래커가 상태목록 위치를 찾는 데 사용하는 기준 버프다.
  - 판독 영역에 이 기준 버프가 포함되어야 한다.
  - 일반 버프처럼 오버레이에 표시하거나 개별 알림을 설정하는 대상이 아니다.
- 비활성 일반 설정 폼을 그대로 보여주어 사용자가 편집할 수 있다고 오해하게 하지 않는다.
- 일반 버프를 다시 선택하면 기존 아이콘·표시·알림 편집 화면으로 돌아온다.
- 기준 버프의 기존 편집·삭제·순서 변경 제한을 유지한다.

### 4.2 상태 전환과 안내

- 기준 버프/일반 버프/선택 없음 전환으로 다른 항목의 설정이 바뀌거나 잘못 저장되어서는 안 된다.
- 판독 영역 근처에 기준 버프 포함, 고정 즐겨찾기 영역 제외 등 등록에 필요한 조건을 짧게 안내한다.
- 기존 버프별 표시·지속시간·알림 옵션과 활성 조건은 유지한다.

## 5. 디버프

### 5.1 한 번의 자동찾기 유지

- 기존처럼 한 번의 자동찾기와 한 번의 후보 승인으로 디버프 영역과 공유 보스 체력바 영역을 함께 등록한다.
- 디버프와 보스 영역을 별도로 자동찾기하게 만들지 않는다.
- 디버프 판독 영역은 기존처럼 아이콘 줄과 보스 체력바를 포함한다. 아이콘 줄만 선택하도록 잘못 안내하지 않는다.
- 기본 판독 영역 구간에서 디버프와 공유 보스 영역의 등록 여부를 구별해 보여준다.
- 보스 체력바가 보이는 상태에서 자동찾기해야 한다는 조건과 두 영역을 함께 설정한다는 설명을 버튼 근처에 둔다.

### 5.2 수동 조작의 대상

- 기본 구간의 `직접 지정`, `지정 영역 보기`, `지정 해제`는 디버프 영역 대상이다. 자동찾기의 공동 등록 범위와 혼동되지 않게 설명한다.
- 공유 보스 영역의 수동 조정은 `공유 보스 영역 개별 조정`으로 접어 둔다. 두 번째 기본 자동찾기 버튼을 만들지 않는다.
- 공유 보스 영역을 변경·해제할 때는 대상과 보스 패턴 알림 등 공유 기능에 미치는 영향을 알린다. 기존 공유 영역 확인 규칙을 유지한다.
- 기존 모드와 권한에 따른 표시/접근 조건을 유지한다. 진단용 조작을 일반 사용의 필수 단계로 만들지 않는다.
- 자동찾기 취소·실패 시 기존 영역을 보존한다. 승인 시 두 후보는 기존 공동 저장 흐름을 유지한다.

## 6. 보스 패턴 알림

- 판독 대상과 등록 상태는 독립된 줄, 명령은 그 아래 줄에 배치한다.
- 판독 미리보기, 경고 표시, 남은 패턴 목록을 각각 구분된 그룹으로 유지한다.
- 경고와 목록의 위치 잠금은 각각 자신의 대상에만 적용된다. 공통 토글 문구와 민트색을 적용한다.
- 이름과 체력 수치가 보이는 보스 체력바가 필요하다는 안내를 판독 영역 가까이에 둔다.
- 수집/진단은 접을 수 있게 두고 지원 보스 안내는 하단에 둔다. 실제 지원 보스와 임계값 데이터는 변경하지 않는다.

## 7. 체력바

- 2026-10-19 개발 중 추가 사용자 요청: 앱 내부 표시 미리보기에는 가로 스크롤이 생기지
  않도록 예시 크기를 가용 폭에 맞춘다. 실제 게임 오버레이 배율과 기존 저장값은 유지한다.
  앞선 명세의 원래 크기/내부 가로 스크롤 유지 규칙보다 이 추가 요청을 우선한다.
- 판독 영역 정보와 버튼 줄을 분리하고 표시·낮은 수치 알림·진단 그룹을 유지한다.
- 표시 그룹 상단에 배율·정렬 및 `전체 잠금`/`전체 잠금 해제`를 둔다.
- 생명력·마나·스태미나의 각 표시 미리보기와 연결된 위치에 해당 바의 개별 잠금 토글을 둔다.
- 개별 잠금은 다른 바에 영향을 주지 않는다. 전체 명령은 기존처럼 세 바를 대상으로 하며 숨긴 바도 기존 잠금 정책을 따른다.
- 표시 여부, 경고 여부와 위치 잠금은 별개 설정이다. 잠금 변경으로 표시/경고 여부를 바꾸지 않는다.
- 판독 영역에는 세 자원 바를 포함하고 경험치 바는 제외한다는 안내를 가까이에 둔다.
- 보스전 조건 등 낮은 수치 알림의 기존 동작 조건은 해당 알림 그룹에서 확인할 수 있게 한다.

## 8. 도르카·투아림

- 기본 공통 자동찾기/직접 지정 진입과 기존 두 판독 영역 저장 구조를 유지한다.
- 기본 상태는 둘 다 등록됨/도르카만 등록됨/투아림만 등록됨/미등록을 구별한다. 세부 좌표는 기존 개별 조정이나 보조 정보에서 확인 가능하게 한다.
- 공통 설정이 별도 세 번째 판독 영역이나 사용 필수 조건이 되어서는 안 된다.
- 기존 `개별 영역 조정`은 유지한다. 부분 성공·공통/개별 지정 해제 범위는 앞선 공통 영역 명세를 따른다.
- 도르카 표시, 투아림 % 표시, 투아림 알림 사용은 독립적으로 유지한다. 표시를 꺼도 알림만 사용할 수 있다.
- 앱 내부 표시 미리보기의 기존 노출·내용·배율 규칙을 유지한다. 두 표시를 모두 껐다는 이유로 미리보기 구간을 새로 숨기거나 접지 않는다.
- 판독값과 실제 오버레이 예시의 의미를 구별하고 기존 미확정/최근 확정값 표현을 유지한다.
- 원형 자원 UI와 우측 아래 퍼센트를 공통으로 설정한다는 설명을 판독 영역 가까이에 둔다.
- 일반 투아림 알림에 표시 기능의 로그인/베타 조건을 새로 적용하지 않는다.
- 잠금 문구·색과 안내 배치 외에 판독 안정화·100% 처리·실패 시 값 처리·미리보기 알고리즘을 변경하지 않는다.

## 9. 커스텀 오버레이

### 9.1 화면 배치

- 위쪽 프리셋 선택은 `프리셋 [선택 목록] [불러오기] [프리셋 관리]`의 간결한 줄로 구성한다.
- 중앙의 주요 편집 대상은 현재 오버레이 목록이다. 현재 적용 프리셋 이름, 저장 상태, 다른 이름으로 저장, 복제 영역 추가, 목록 및 선택/전체 명령을 가까이 배치한다.
- 현재 편집 중인 프리셋 이름을 인접한 제목마다 중복 표시하지 않는다.
- 프리셋 관리에는 선택 프리셋 삭제와 시작 시 불러오기 대상을 둔다. 기본 화면에서는 접을 수 있다.
- 캡처 호환성 고급 설정은 기존처럼 아래에서 접어 둔다.

### 9.2 선택·적용·저장

- 프리셋 선택 목록을 바꾸는 것만으로 적용하지 않는다. `불러오기`를 눌러야 현재 편집 대상이 바뀐다.
- 선택 목록의 대상, 현재 적용/편집 대상, 시작 시 자동 불러오기 대상은 서로 독립적으로 구별한다.
- 현재 적용 프리셋 자동 저장과 저장 실패·재시도·보류 중 변경 처리 규칙을 유지한다. 별도의 수동 저장을 다시 필수로 만들지 않는다.
- 원본을 남기고 수정하려면 먼저 다른 이름으로 저장한다는 안내를 현재 편집 영역 가까이에 둔다.
- 프리셋 삭제는 선택 목록의 대상, 오버레이 삭제는 현재 목록의 대상을 삭제한다. 확인 안내에 실제 대상 이름을 표시한다.
- 커스텀의 기존 전체 사용 체크는 유지한다. 목록/관리 배치 정리를 이유로 사용 조건을 바꾸지 않는다.

### 9.3 대상 없는 명령

- 현재 목록이 비어 있으면 선택/전체 잠금·해제·삭제 명령을 비활성화한다. 복제 영역 추가는 가능해야 한다.
- 목록은 있으나 항목을 선택하지 않았으면 선택 명령만 비활성화한다. 전체 명령은 사용할 수 있다.
- 불러오기와 프리셋 삭제도 해당 프리셋을 선택할 수 없는 상태에서는 비활성화한다.
- 추가·선택 변경·삭제·불러오기 직후 명령의 활성 상태를 갱신한다.
- 단순 화면 열기, 프리셋 선택 목록 탐색, 관리 접기/펼치기는 편집 변경이나 자동 저장 사유가 아니다.

## 10. 단축바와 메모

### 10.1 단축바

- 판독 영역과 표시 그룹의 간결한 구성을 유지한다. 다수 그룹을 새 목록으로 펼치지 않는다.
- 기존 전체 잠금/해제와 기본 배치 프리셋 동작을 유지한다. 개별 그룹 잠금 UI를 추가하지 않는다.
- 원본 첫 칸 지정 조건은 판독 영역 가까이, 빈칸 숨기기 등 기존 우클릭 조작 안내는 표시 구간 가까이에 둔다.

### 10.2 메모

- 표시 영역 등록을 사용 조건으로 하고 별도 메모 전체 사용 체크를 두지 않는 기존 승인 정책을 유지한다.
- 메모의 영역은 판독 원본이 아니라 표시 위치와 폭을 정하는 영역임을 명확히 한다. 높이가 내용에 따라 정해지는 기존 동작도 안내한다.
- 위치 잠금 토글은 공통 문구와 색을 적용한다.
- 마크다운 편집·미리보기·내용 저장 동작을 유지한다. 자동 저장 안내는 내용 편집 가까이에 둔다.

## 11. 안내와 화면 대응

- `?` 상세 도움말은 유지하되 등록에 필요한 조건, 현재 조작 대상, 사용 불가 사유는 관련 조작 가까이에 짧게 노출한다.
- 필수 조건을 마우스 올리기나 도움말 클릭만으로 알 수 있게 하지 않는다. 긴 전체 설명을 모든 그룹에 반복하지 않는다.
- 영역 등록 여부와 현재 판독 성공 여부를 혼동시키지 않는다. 등록만으로 정상 판독을 보증하지 않는다.
- 실제 앱의 기본 창 크기와 고배율에서 정보·버튼이 겹치지 않고 필수 문구를 읽을 수 있어야 한다. 필요한 줄바꿈과 기존 스크롤을 활용한다.
- 이 개선만을 위한 새 팝업, 투어 단계 또는 안내 타이머는 추가하지 않는다.
- 화면 전환·미리보기 표시를 이유로 별도 상시 판독, 중복 타이머, 새 캡처 루프를 추가하지 않는다.

## 12. Acceptance Criteria

1. 기준 버프 선택 시 오른쪽에 역할·등록 조건이 표시되고 일반 편집 폼은 나타나지 않는다. 일반 버프 재선택 시 해당 버프의 실제 설정으로 돌아오며 전환만으로 데이터가 바뀌지 않는다.
2. 단일 위치 잠금은 잠긴 상태에서 민트색과 `잠금됨` 문구를 보여준다. 로드/탭 재진입 후에도 실제 잠금과 일치하며 해제하면 기존 이동 동작이 가능하다.
3. 전체 잠금/해제는 두 일반 명령 버튼으로 보인다. 혼합 잠금 상태에서도 종합 상태나 잠금 개수 표시는 추가되지 않는다.
4. 체력바 하나의 잠금 변경은 나머지 바에 영향을 주지 않는다. 전체 명령은 세 바 모두에 적용되며 표시 여부·경고 설정·전체 일시중단은 변경되지 않는다.
5. 단축바에는 새 개별 그룹 목록이나 개별 잠금 조작이 생기지 않는다.
6. 디버프 자동찾기 한 번의 승인으로 디버프와 공유 보스 영역이 함께 저장된다. 취소/실패 시 이전 값이 보존되며 기본 화면에서 별도 보스 자동찾기를 요구하지 않는다.
7. 디버프 기본 직접 지정/보기/해제의 대상이 디버프임을 알 수 있다. 공유 보스 영역 조작은 별도 조정 구간에 있고 공유 영향 확인 규칙을 지킨다.
8. 도르카와 투아림 표시를 모두 꺼도 앱 내 표시 미리보기 구간의 기존 노출 동작을 유지한다. 투아림 알림만 켠 상태의 동작과 기존 접근 조건이 보존된다.
9. 커스텀에서 프리셋 선택만 바꾸면 현재 목록과 자동 저장 대상은 바뀌지 않는다. 불러온 후에만 편집 대상이 바뀌며 시작 시 불러오기 선택은 독립적으로 유지된다.
10. 커스텀의 실제 변경은 기존 정책대로 자동 저장된다. 다른 이름으로 저장한 뒤 새 편집본을 수정하면 이전 프리셋은 보존되고, 저장 실패 시 성공으로 표시하지 않는다.
11. 빈 목록/선택 없음에서 대상 없는 명령이 비활성화되고 추가·선택·삭제 후 즉시 갱신된다. 프리셋 삭제와 오버레이 삭제의 실제 대상이 서로 구별된다.
12. 등록 조건과 사용 불가 사유를 도움말을 열지 않고 해당 조작 가까이에서 확인할 수 있다. 기본 창 크기, 고배율, 밝은/어두운 테마에서 문구와 컨트롤이 겹치거나 잘리지 않는다.
13. 화면 열기·안내 보기·그룹 접기만으로 영역, 프리셋, 사용/알림 설정이 바뀌지 않는다. 기존 게임 전면 노출 조건·일시중단·설정 보존·권한 제한이 유지된다.

## 13. 개발·검증 전달

- 미결정된 핵심 기획 사항은 없다. 이 문서와 승인 목업을 함께 개발 세션에 전달한다.
- 구현 후 실제 앱의 각 상태와 Windows 환경에서 위 기준을 검증한다. 정적 목업 확인은 해당 검증을 대체하지 않는다.
- 동작이나 저장 범위를 바꾸어야만 구현할 수 있는 경우에는 이 문서의 배치 개선에 포함시키지 말고 별도 확인한다.
