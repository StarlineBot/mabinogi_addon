# 도르카 새 원본 검출 및 이동 후 재탐색

- 날짜: 2026-10-16.
- 근거: `docs/qa/도르카_이동후_미판독_자동찾기실패_20261016.md`.
- 수정 전 원본 QA 재현을 직접 실행하여 **3 failed, 2 passed (4.03초)**를 확인했다.
- QA 보고서·실패 재현·스크린샷 원본은 변경하지 않았다. 커밋 이력은 조회하지 않았다.

## 분리한 원인

1. 새 원본 `234015`는 실제 숫자 15가 판독 가능하지만 장식 점수가 0.9384로
   합격 기준 0.97에 미달했다. 이는 이전 좌표를 기억해서 생긴 문제가 아니다.
2. 기존 판독 루프는 승인 좌표만 읽었다. 이전 정상 장식도 다른 곳으로 이동하면
   자동찾기 함수는 새 위치를 찾지만 탭은 이전 좌표만 반복 캡처했다.

## 검출 수정

- 도르카 전용 장식 표본을 추가했다. 원본 Git blob은
  `fafa4d8bd995c6e2c0b476ca70e73b3b23a158a4`, 크롭은 `(569,106,45,57)`이다.
  `scripts/build_dorcha_anchor.py`가 원본 해시를 확인하고 기존과 같은 grayscale 변환만 한다.
- 기존 표본을 유지하고 같은 위치의 중복 후보를 합친다. 서로 다른 위치의 복수 후보는 거절한다.
- 공용 합격 기준 0.97과 지원 배율은 그대로다. 투아림/단축바의 표본·합격 기준을 낮추지 않았다.
- 장식 후보가 유일해도 안쪽 숫자가 0~15로 확정되지 않으면 거절한다.
- 숫자 확인의 입력도 재현 가능하도록 원래 숫자 표본 17개를 PNG 이진 마스크로 진단 ZIP에
  함께 보존한다. ZIP 재실행은 설치된 전역 숫자 참조 대신 해당 PNG를 사용한다.
  숫자 표본이 없거나 손상되면 필수 자료 누락으로 실패한다.

## 이동 재탐색

- 정상일 때는 기존 작은 영역을 200ms 간격으로 읽는다. 미판독이면 등록된 게임 실행파일의
  창 전체를 캡처해 별도 QThread 하나에서 검출한다. 창을 숨기거나 포커스를 바꾸지 않는다.
- 게임 창 미등록/미발견/잘못된 크기에서는 전체 데스크톱으로 폴백하지 않는다.
- 한 번에 작업 하나만 실행하며 대기열은 없다. 프레임은 워커 전용 복사본 하나를 소유하고
  종료 시 해제한다. 전체 캡처는 16,777,216픽셀 이하로 제한한다. 이 한도를 넘는 구성은
  재탐색하지 않으며 정상 ROI 판독은 계속한다.
- 첫 실패에는 즉시 시도하고 연속 실패 재시도는 2/4/8/10초로 늘린다. 완료 후에는 추가로
  직전 검출 벽시계 시간의 20배 이상을 대기해 비싼 탐색을 200ms마다 반복하지 않는다.
  따라서 가림이 길거나 탐색이 비싼 환경에서는 복구가 늦어질 수 있다. 고정 최대 지연을 주장하지 않는다.
- 시작/완료 시 게임 활성, HWND·PID·물리 창 경계를 확인한다. 중지/로그아웃/기능 OFF/
  재등록/게임 변경/종료 후 늦은 결과는 적용하지 않는다. 취소는 배율 탐색 사이에서 확인한다.
- 결과를 적용하기 전에 현재 좌표를 다시 캡처해 판독한다. 과거 프레임의 숫자나 추정값은
  표시하지 않는다. 재탐색 좌표는 물리 좌표로만 메모리에 두고 승인 영역이나 다른 기능 설정에 저장하지 않는다.
  ‘영역 보기’는 추적 중 실제 영역을 표시하며 오버레이 자체 위치는 바꾸지 않는다.
- UI 객체는 워커에서 접근하지 않는다. 종료 시 중단을 요청하고 워커를 회수한다.
  UI 스레드의 화면 캡처 자체 및 실제 Windows 종료 지연은 별도 검증 대상이다.

## 검증

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest tests/test_dorcha_tracking.py tests/test_dorcha_reader.py tests/test_dorcha_autofind.py tests/test_dorcha_tab.py -q --tb=short
.venv/bin/python scripts/bench_dorcha_reacquire.py
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q -m 'not windows_integration'
```

- 관련 검사 **117 passed (38.14초)**. 새 원본 전체/주변 입력, 기존 0~15 표본,
  이동→가림→재등장, 여러 위치, 음성 배경, 장식만 있고 숫자 없는 입력, 복수 위치 거절을 포함한다.
- 한 작업 실행 중 100틱을 보내도 전체 캡처/워커는 하나다. 캡처/검출 예외가 매 틱 재시도를
  만들지 않는지, 이전 ROI의 판독 회복과 중지/종료 경합, 음수 화면 오프셋 및 저장 불변성을 검증했다.
- 원래 이동 재현은 등록된 게임 캡처 대상 경계를 명시적으로 대체해 다시 실행한다.
  현재 PySide QTest.qWait의 긴 대기가 Python 워커를 지연시켜 그대로 실행하면 2초 관측이 실패했다.
  실제 앱과 같은 QEventLoop를 같은 200ms 동안 실행하면 원래 10틱 및 기대값이 통과한다.
  원본 QA 스크립트를 수정하거나 시간을 늘리거나 assertion을 완화하지 않았다.
- 진단 ZIP 재실행 시 전역 숫자 참조를 제거해도 같은 결과가 나오는 검사를 추가했다.
- 로컬 오프라인 2560x1440 검출 비용: 이전 정상 화면 벽시계/CPU 약 0.710/0.709초,
  새 화면 0.735/0.734초, 검은 화면 1.950/1.950초 (각 1회, OpenCV 1스레드).
  마지막 경우 실제 비용 대기는 약 39초다. 이는 Linux 표본 실행이며 Windows 게임 FPS나
  장시간 평균 CPU 사용량을 측정한 결과가 아니다.
- 전체 회귀 **1,195 passed, 4 deselected, 3 warnings (248.94초)**.
  이후 추가한 Windows 조회 경계 6건과 숫자 자료 손상 2건을 포함해 최종 도르카 관련
  **125 passed (37.52초)**를 재실행했다. 두 실행 건수는 중복되며 더해서 총 검사 수로 세지 않는다.
- 원격에 v0.4.78이 이미 있어 사용자용 변경 노트는 다음 버전 v0.4.79에 분리했다.
- 푸시한 SHA의 Windows 테스트·exe 빌드는 별도 확인한다.
  Windows API가 차단되면 검증 대기로 남기며 완료/릴리즈 가능을 주장하지 않는다.

## 별도 요청

사용자가 색상 변경을 보류하고 판독 문제를 우선하도록 답했다. 색상·탭 순서·제작자 툴팁은
이번 판독 수정에 섞지 않았다. 앞선 QA의 공개 공지 경로 위험도 이번 변경 범위 밖이다.
Windows 실게임 이동 영상, 혼합 DPI, 장시간 리소스, 추가 명암/배율은 후속 검증이 필요하다.
