# 설정 그룹화·공통 자원 지정·메모 등록 기반 사용 구현

- 날짜: 2026-10-18 (Asia/Seoul).
- 기준: `settings-grouping-common-resource-spec.md`와 채팅에서 승인한 여섯 화면.
- 추가 승인: 메모 사용 체크 제거, 영역 등록=사용, 단일 위치 잠금은 상태 토글 버튼.

## 화면

보스는 판독 미리보기/경고/남은 목록, 체력바는 원본/표시/보스전 알림, 자원은
공통 등록/표시/투아림 알림, 커스텀은 편집/프리셋, 단축바는 원본/표시,
메모는 표시 영역/표시/내용으로 묶었다. 지원 보스 목록은 진단 아래로 이동했다.
정보 줄은 버튼 줄과 분리하며 기본 폭·20px 글꼴에서 페이지 가로 넘침을 검사한다.
기존 테마·창 크기·두 단계 탭·개별 출력 설정은 유지한다.

단일 잠금은 `위치 잠금`/`위치 잠금됨` 버튼이며 보스의 경고/목록은 대상명을 포함한다.
보스와 메모의 이동/클릭 통과 안내는 실제 상태에 맞춘다. 커스텀 표는 잠금 상태를
텍스트로 표시하고 선택/전체 잠금 버튼을 유지한다. 프리셋 선택·현재 편집·시작 대상을
구분하며 저장 오류/재시도/자동 저장 로직은 바꾸지 않는다.

원본 확인과 출력 예시는 구분한다. 출력은 기존 오버레이 위젯을 그대로 쓰며 배율을
임의 변경하지 않는다. 체력바/자원 예시의 빈 전체 폭 틀과 불필요한 가로 스크롤을
줄였으며 내용이 실제 가용 폭을 넘으면 해당 미리보기만 가로 스크롤한다.
단축바 원본 보기는 기준 첫 칸과 12개 그룹 전체를 별도 이름으로 잠깐 강조하고 정리한다.

## 공통 자원 설정

- 기본 자동찾기와 직접 지정 진입을 하나씩 제공한다. 개별 직접 지정/보기/해제는 접어 둔다.
- 한 번 캡처한 입력에 기존 도르카/투아림 검증기를 각각 실행한다. 숫자 검증/오른쪽 구조
  확인을 없애지 않는다. 두 결과의 원형 장식 원점·배율이 맞는 경우만 한 쌍으로 제시한다.
  복수 후보나 서로 다른 원점은 거절하고, 한쪽만 유효하면 그쪽만 승인할 수 있다.
- 저장은 도르카 box와 투아림 box라는 기존 두 키를 사용한다. 표시/알림 조건인 제3의
  공통 영역을 추가하지 않는다. 일괄 승인/해제는 한 번의 원자 저장 후 메모리에 반영한다.
- 취소·저장 실패·확인 중 다른 등록·세대 변경·로그아웃·종료는 이전 영역을 유지한다.
  공통 해제는 두 영역, 개별 해제는 한 영역만 지우며 다른 세부 옵션은 보존한다.
- 직접 지정은 선택한 원본 범위에서 두 내부 영역을 검증한다. 자유 사각형만으로 임의
  비율을 가정해 좌표를 저장하지 않는다. 확인할 수 없으면 개별 보정을 안내한다.
- 일반 투아림 알림과 개별 수동 보정의 접근 조건은 유지한다. 로그인하지 않은 공통 직접
  지정에서는 투아림만 적용하며 도르카 설정을 바꾸지 않는다. 자동찾기/도르카 표시는 베타다.
- 실행 중 타이머를 잠깐 정지하고 검출은 Python 백그라운드 작업으로 수행한다. UI 대기
  폴링은 해당 실행에만 존재하고 종료 시 신호를 해제·정리한다. 중복 실행/큐 누적을 막고
  취소된 실행은 뒤늦게 완료돼도 UI나 설정에 적용하지 않는다.
- 첫 사용 안내에는 도르카 대상을 추가했다. 도르카/투아림을 함께 선택하면 미등록 대상만
  공통 흐름 한 번으로 설정한다. 투아림만 선택하면 기존 독립 경로를 유지한다.
- 진단 기능명은 `resources`이며 입력 PNG, 두 모델, 후보별 추적, 물리/논리 좌표를 기록한다.
  직접 지정은 원본 캡처의 크기/오프셋과 잘라낸 물리 영역도 남긴다. ZIP만으로 재현한다.

## 메모

`memoTracker.captureRegion`이 표시 조건이다. 옛 memo.enabled=False로 차단하지 않으며
기존 enabled 값 자체를 임의로 켜 쓰지 않는다. 게임/앱 활성·잠금·전체 일시정지 조건은
별도로 적용한다. 등록/해제 때도 전체 일시정지를 임의 해제하지 않는다.

해제는 영역만 지우고 메모 내용·글자 크기·잠금을 보존한다. 저장 성공 뒤 즉시 숨긴다.
늦은 선택과 이동 콜백은 해제 상태를 되살리지 않는다. 종료/설정 교체 시 표시를 중단하고
메모 타이머 정지는 다른 상태 저장 성공에 의존하지 않는다. 메모 선택기도 종료 시 닫는다.

## 검증 준비 중 확인한 문제

초기 새 검사에는 fixture 누락/불완전한 로그인 샘플/들여쓰기 오류가 있어 준비 단계에서
실패했다. 기존 잠금 버튼의 고정 문구와 메모 미등록=사용 기대값은 승인한 새 정책에
맞춰 바꿨으며 잠금 상태·설정 불변성 assertion은 유지했다.

동일 QApplication에서 여러 MainWindow를 반복 구성하고 쓰기 거절 주입을 종료 저장까지
유지한 새 검사에서는 Qt/PySide 네이티브 종료 및 가상 메서드 호출 오류가 있었다.
최종 검사는 독립 자원 화면과 새 프로세스의 실제 MainWindow에서 같은 계약을 확인한다.
거절 동작의 디스크/메모리 불변성을 검사한 뒤 오류 주입을 복구하고 창을 정리한다.
이 결과를 실제 Windows의 쓰기 금지 상태 종료 성공이나 제품 크래시 해결로 집계하지 않는다.
기존 QThread 누수/외부 장치 경계/정리 검사는 유지한다.

## 제한

Linux Qt offscreen과 명시적 캡처/게임/소리 대체 결과다. 실제 Windows 캡처·혼합 DPI·
게임 전환·권한 오류가 지속되는 종료·장시간 CPU/메모리/핸들·exe는 미검증이다.
일반 푸시 Windows Actions 중단 정책을 유지하며 태그·릴리즈는 진행하지 않는다.
