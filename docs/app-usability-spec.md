# 앱 사용성 개선 기획

- 상태: 개발 진행 중. 2026-10-15 사용자가 작업 시작을 요청했고 아래 시작 화면 배치와 순차 승인 흐름을 렌더로 확정했다. 나머지 문구·재배치 제안은 개별 적용 여부를 구분한다.
- 작성일: 2026-10-15
- 대상: 현재 앱의 일반 화면과 베타 기능.
- 범위: 메인 설정 화면, 일괄 자동설정 중 항목별 영역 확인, 각 화면의 안내 문구 및 첫 실행 사용 안내. 등록 후 상시 미리보기는 추가하지 않는다.
- 기존 안내 문구 초안을 이 문서로 통합했다. 이 문서를 검토 기준으로 사용한다.
- 구현·검증 범위는 `docs/app-usability-implementation.md`에 기록한다. 독립 QA 및 Windows 실게임 검증 완료를 뜻하지 않는다.

## 1. 메인 설정 화면

사용자 구상은 다음과 같다.

- 설정이 필요한 항목을 위에, 등록한 항목을 아래에 보여준다.
- 상단 '자동설정'은 미등록 영역을 순서대로 찾고, 사용자가 승인한 영역만 등록한다.
- 개별 탭의 '자동 찾기'는 해당 기능 하나의 영역을 찾는다.
- 필요한 설정이 모두 등록된 사용자는 기존처럼 트래커 > 버프로 진입한다.
- 보스바처럼 화면에 떠야 찾을 수 있는 대상은 그 조건을 안내한다.
- 자동설정 중 찾은 영역과 확인 설명을 항목별로 보여주고, 사용자가 직접 확인해 승인한다.

### 1.1 목적과 상태의 의미

이미 설정한 사용자의 동선을 유지하면서 초기 설정과 자동설정 중 영역 확인을 한 화면에 모은다. 등록 여부는 정확성의 자동 판정과 구분한다.

| 구분 | 의미 | 권장 표시 |
|---|---|---|
| 미등록 | 필요한 좌표가 저장되지 않음 | 설정 필요 |
| 등록 | 좌표가 저장되어 있음. 현재 유효함까지 확인한 것은 아님 | 영역 등록됨 |
| 찾은 영역 | 자동설정 진행 중 사용자가 확인하는 후보. 승인 전에는 미등록 | 찾은 영역 확인 |

- 저장된 영역이 있는데 보스바가 지금 보이지 않는다는 이유만으로 '미등록'으로 되돌리지 않는다.
- '현재 위치 확인됨', '정상 동작', '검증 완료' 등의 자동 판정 표현을 사용하지 않는다.
- 모두 등록되면 메인을 첫 화면에서 건너뛴다. 필요하면 설정의 '자동설정 다시 열기' 버튼으로 연다. 별도 상위 메인 탭은 추가하지 않는다.
- '필요한 항목'은 사용자가 체크한 기능을 기준으로 한다. 메인과 개별 탭의 기능 사용 체크는 동일한 설정이며 양방향으로 반영한다. 별도의 사용 의향 설정을 만들지 않는다.
- 버프/디버프의 기능 전체 사용 여부와 개별 버프/디버프의 표시 여부는 구분한다. 메인 체크를 개별 아이콘 표시 설정으로 대체하지 않는다.
- 게임창 인식은 선행 설정으로 표시한다. 미등록이면 먼저 등록하고 영역 자동설정을 진행하는 동선을 권한다.
- '자동설정'은 저장된 설정이 없는 항목을 처리하는 동작으로 설명한다. 재실행해도 등록된 항목은 건너뛰고 미등록 항목만 다시 찾는다.

### 1.2 첫 화면과 구성

2026-10-15 렌더 피드백으로 확정한 배치:

- 제목 아래에 짧은 설명과 '게임창 등록 → 기능 선택 → 자동설정 → 영역 확인' 순서를 표시한다.
- 게임창 등록을 기능 선택보다 먼저 배치한다.
- 사용할 기능은 세로 스크롤 목록으로, 처음에는 네 항목이 보인다. 체크한 순서를 기억한다.
- 목록 바로 아래에 전체 너비의 '자동설정' 버튼을 배치한다.
- '사용할 기능', '설정 필요', '등록된 설정', '사용 안 함'은 각각 분리된 스크롤 박스다.
- 화면 내부에 별도의 자동설정 후보/확인 패널을 두지 않는다. 기존처럼 화면 위 영역 지정·확인으로 승인하고, 승인할 때마다 등록 상태 목록을 갱신한다.

- 사용할 기능을 선택할 수 있고, 해당 기능에 필요한 설정을 보여준다.
- 선택한 기능의 필수 설정이 미등록이면 메인을 먼저 보여준다.
- 선택한 기능의 필수 설정이 모두 등록되면 기존처럼 트래커 > 버프로 시작한다. 현재 화면에 대상이 보이지 않는다는 이유만으로 메인으로 보내지 않는다.
- 하단 '시작할 때 이 화면 다시 보지 않기'를 선택하면 미등록 항목이 있어도 이후에는 트래커 > 버프로 시작한다. 이는 사용자가 이후 설정을 직접 관리한다는 뜻이며, 앱이 자동으로 등록을 끝낸다는 뜻이 아니다.
- 설정에 '자동설정 다시 열기' 버튼을 두어 시작 화면에서 건너뛴 경우에도 메인을 열 수 있게 한다. 이 버튼은 화면을 여는 동작이며, 즉시 영역 탐색을 시작하지 않는다.
- 게임창 등록이 필요한 경우 별도 시작 팝업 대신 메인의 '설정 필요' 구역에서 강조한다.
- 미등록 항목은 위쪽 '설정 필요', 등록된 항목은 아래쪽 '등록된 설정'에 표시한다.
- 상단 버튼의 이름은 '자동설정'이다. 개별 탭의 '자동 찾기'와 구분한다.
- 사용하지 않기로 선택한 기능은 설정 필요 수에 포함하지 않는다. 게임창 등록처럼 공통 선행 설정은 따로 표시한다.

### 1.3 일괄 자동설정

1. 사용자가 기능을 선택하고 '자동설정'을 실행한다.
2. 공통 선행 설정과 선택한 기능의 미등록 영역을 확인한다.
3. 이미 등록된 영역은 유지하고, 체크한 순서대로 미등록 영역만 현재 게임 화면에서 찾는다.
4. 영역을 찾으면 기존 자동찾기처럼 화면 위 민트색 점선과 확인 창에서 위치를 확인한다. 버프는 기존 목록 위 경계 선택을 유지한다.
5. '이 영역으로 등록'을 누르면 해당 영역을 저장하고 등록된 항목으로 갱신한 뒤 다음 항목으로 이동한다. '등록하지 않기'를 누르면 저장하지 않고 다음 항목으로 이동한다. 찾았다는 사실만으로 등록하지 않는다.
6. 못 찾으면 대상과 재시도 조건을 해당 화면에 안내한 뒤 다음 항목으로 진행한다. 확인할 수 있는 원인이 있을 때만 그 원인을 명시하고, 보스 부재/가림/인식 실패 등을 추측해 단정하지 않는다.
7. 마지막에는 '등록 완료 / 등록하지 않음 / 찾지 못함'을 구분해 결과를 모아 보여준다.
8. 사용자는 해당 기능의 개별 탭으로 이동해 직접 지정/자동찾기를 실행하거나, 대상 UI가 보이는 상태에서 메인의 자동설정을 다시 실행한다. 다시 실행해도 승인해 등록한 항목은 건너뛴다.

- 보스바는 실제 보스 체력바가 떠 있어야 찾을 수 있음을 해당 항목에 안내한다.
- 게임 미실행/캡처 실패처럼 전체 시도가 어려운 경우와 특정 UI 미발견을 구분해 안내한다.
- 일괄 자동설정이 기능의 사용 여부, 알림 임계값, 소리, 잠금 또는 오버레이 배치를 임의로 변경하지 않는다.
- 공유 보스바는 보스 패턴 알림과 디버프가 함께 사용하는 설정이다. 한쪽에서 등록된 공유 영역은 다른 쪽에서도 등록 여부에 반영한다. 디버프 줄 등 별도 영역이 있으면 그 필요 여부는 따로 판단한다.
- 커스텀 오버레이의 임의 영역, 메모의 표시 위치 등 사용자 의도가 필요한 영역을 자동찾기 대상으로 간주하지 않는다.
- 기존의 같은 확인 구역 권장안은 사용자 피드백으로 변경했다. 기능별 화면 위 영역 확인을 마친 뒤 다음 선택 항목으로 진행한다.

확인 화면 문구 예시:

```text
버프 트래커 · 찾은 영역 확인
[찾은 영역의 캡처 또는 민트색 영역 표시]
추적할 버프의 아이콘과 남은 시간이 들어오나요?
기준 버프인 프리미엄 배틀 멤버십도 포함되는지 확인하세요.
[등록하지 않기] [이 영역으로 등록]
```

미발견 안내 예시:

```text
디버프 트래커
현재 화면에서 기준이 되는 보스 체력바를 찾지 못했습니다.
보스 체력바가 보이는 상태에서 다시 시도해 주세요.
```

### 1.4 자동설정 중 항목별 영역 확인

체크한 순서대로 기존 화면 위 영역 지정·확인을 진행한다. 메인 내부에 후보 확인 패널을 만들지 않는다. 등록된 모든 기능의 캡처/판독 결과를 나열하거나, 등록 후 항목 선택으로 상시 판독 미리보기를 제공하는 화면도 추가하지 않는다.

```text
[게임창 등록]
[사용할 기능 선택 · 네 항목 표시 · 나머지 스크롤]
[자동설정                                         ]

설정 필요
  투아림              영역 미등록          [개별 설정]

등록된 설정
  보스 패턴 알림      영역 등록됨          [개별 설정]

사용 안 함
  선택하지 않은 기능

(각 목록은 독립된 스크롤 박스)
(후보 확인은 화면 위의 기존 영역 확인 창에서 진행)
```

| 대상 | 자동설정 확인 자료 | 사용자 확인 안내 |
|---|---|---|
| 투아림 | 숫자와 %가 포함된 영역 | 숫자와 %가 모두 들어오는지 확인하세요. 실제 판독값은 적용 후 기존 투아림 탭에서 확인할 수 있습니다. |
| 보스 패턴 알림 | 보스 체력바 영역 | 보스 이름과 체력 비율이 모두 들어오는지 확인하세요. |
| 버프 | 찾은 상태목록 영역 | 기준 버프와 추적할 버프의 아이콘·남은 시간이 들어오는지 확인하세요. |
| 디버프 | 찾은 디버프 영역 | 보스바 위 디버프 줄이 들어오는지 확인하세요. 디버프 아이콘이 현재 없다는 이유만으로 잘못된 영역으로 판단하지 않습니다. |
| 체력바 | 세 바가 포함된 영역 | 생명력·마나·스태미나가 들어오고 경험치 바는 빠졌는지 확인하세요. |
| 단축바 | 원본 복제 대상 영역 | 첫 칸부터 마지막 그룹까지 잘리지 않았는지 확인하세요. |

- 투아림/보스바 등 개별 탭의 기존 캡처·판독 미리보기는 유지한다. 메인에 별도의 상시 미리보기를 복제하지 않는다.
- 자동설정 중 숫자 판독 성공을 필수로 요구하지 않는다. 필요한 정보가 영역에 포함됐는지 사용자가 확인한다.
- 확인 화면은 현재 처리 중인 후보를 보여준다. 이전 항목의 캡처를 다음 항목의 결과처럼 표시하지 않는다.
- 메인 진입만으로 기능 사용 여부나 전체 일시정지를 바꾸지 않는다. 메인에서 사용자가 직접 기능 체크를 변경한 경우에는 같은 개별 탭 사용 설정에 반영한다.
- 체크하지 않은 기능은 자동설정과 판독 대상에서 제외하고 '사용 안 함'으로 표시한다. 별도의 미리보기 전용 판독은 만들지 않는다.
- 사용자 확인 완료 체크를 새로 요구하지 않는다. 등록 승인은 '이 영역으로 등록' 버튼으로 처리한다.

### 1.5 이번 범위에서 제외하는 자동 검증

이전 대화의 '자동정렬검증'은 목록 정렬이나 UI 자동 배치가 아니다. 앱이 저장된 캡처 영역의 위치/크기가 실제 게임 UI와 맞는지 자동 판정하는 기능을 뜻했다. 오해를 피하려면 '등록 영역의 위치·크기 자동 검증'이라고 부른다.

예를 들어 앱이 투아림 숫자의 잘림 여부나 단축바 마지막 그룹까지의 정렬을 확인하고, 잘못되었으면 등록 무효 또는 재탐색을 결정하는 동작이다. 이번 메인은 이 자동 판정을 요구하지 않는다. 사용자가 자동설정 단계에서 찾은 영역·설명을 직접 확인하며, 나중에 영역이 어긋나면 개별 설정에서 다시 지정한다.

이 제외는 개별 자동찾기가 후보를 고르는 기존 매칭 조건까지 없앤다는 뜻이 아니다. 새로 저장된 영역이 계속 맞는지 판정하는 추가 검증 체계만 이번 메인 범위에서 제외한다.

## 2. 문구 원칙

- 버튼은 실행할 행동, 상태는 현재 사실, 도움말은 자세한 방법을 표현한다.
- 설정 등록 여부, 기능 사용 여부, 현재 감지 여부와 전체 일시정지를 한 상태로 섞지 않는다.
- 자동찾기 미발견을 대상이 없다는 확정 사실이나 앱 오류로 표현하지 않는다.
- 실험 기능에 '가장 정확', '정상 작동 보장' 같은 검증 범위를 넘는 표현을 사용하지 않는다.
- 공통으로 '자동 찾기', '직접 지정', '지정 영역 보기'를 사용하고 기능별 대상 이름을 덧붙인다.
- 베타 안내는 해당 기능에만 적용한다. 자동찾기가 베타인 탭에서 기존 일반 기능까지 로그인 필요라고 오해하게 하지 않는다.
- 상단 안내는 짧게 두고 상세 수동 지정 방법은 도움말 또는 해당 버튼 툴팁으로 옮기는 것을 제안한다. 문구 초안 승인만으로 레이아웃 변경까지 승인된 것으로 간주하지 않는다.

- Discord 계정 설명: '로그인하면 베타 기능을 사용할 수 있고 문의 답변을 DM으로 받을 수 있습니다.'
- '자동 찾기 진단' 보조 설명: '자동찾기에 실패한 실행을 선택해 진단 ZIP으로 저장할 수 있습니다.'
- '설정 초기화' 확인: '저장된 설정을 초기화할까요? 초기화할 항목과 유지되는 항목을 확인하세요.' 실제 보존 정책을 그대로 반영하고 '모든 정보 삭제'로 일반화하지 않는다.

### 별도 레이아웃 검토 제안

게임창 등록과 Discord 계정을 상단에, 문의/제작자/진단은 지원 구역으로 배치하는 안을 권한다. 메인 화면이 생기면 게임창 등록 현황은 메인에서도 보여주고 설정에서도 접근 가능하게 한다. 설정에 '자동설정 다시 열기' 버튼을 제공하며, '사용법 투어 다시 보기'와는 서로 다른 동작으로 유지한다. 이 문구 초안만으로 설정의 전체 재배치를 구현하지 않는다.

## 8. 향후 메인 화면 문구 예시

이 절은 아직 없는 기능의 화면 예시이다. 현재 화면의 문자열 교체로 구현할 수 없다.

| 위치 | 초안 |
|---|---|
| 제목 | 사용 준비 |
| 주요 버튼 | 자동설정 |
| 버튼 툴팁 | 사용할 기능 중 아직 등록되지 않은 영역을 현재 화면에서 찾습니다. |
| 선행 설정 | 게임창 등록 필요 |
| 미등록 구역 | 설정 필요 |
| 저장된 구역 | 등록된 설정 |
| 미등록 행 | 보스 체력바 · 영역 미등록 |
| 보스 조건 안내 | 보스 체력바가 보이는 상태에서 자동설정을 실행하세요. |
| 등록 행 | 투아림 · 영역 등록됨 |
| 이번 실행 미발견 | 현재 화면에서 보스 체력바를 찾지 못했습니다. 보스 체력바가 보이는 상태에서 다시 시도해 주세요. |
| 개별 설정 이동 | 보스 패턴 알림 설정 열기 |
| 설정에서 메인 열기 | 자동설정 다시 열기 |
| 후보 승인 버튼 | 이 영역으로 등록 |
| 후보 거절 버튼 | 등록하지 않기 |
| 일괄 실행 결과 예시 | 등록 완료 [개수] / 등록하지 않음 [개수] / 찾지 못함 [개수] |

일괄 실행은 항목별 확인/승인 방식으로 정한다. 등록 영역 자동 검증을 먼저 구현해야 메인을 만들 수 있다는 선행 조건은 두지 않는다. 자동설정이 이미 켜 둔 기능의 사용 여부·소리·잠금·프리셋을 변경한다는 의미로 설명하지 않는다.

## 9. 첫 실행 사용 안내 개선

### 9.1 현재 안내에서 개선할 내용

- 현재 안내는 수동 버프 영역 지정, 버프 추가, 위치 잠금, 준비 끝의 4단계이다.
- 실제 영역 지정 여부를 확인하지 않아도 마지막에 '준비 끝'이라고 표시한다.
- 기본 버프가 제공되는데도 새 버프 추가가 필수처럼 보이며, 디버프/투아림도 같은 순서라는 설명은 각 기능의 실제 사용법과 맞지 않는다.
- 자동찾기, 기능 선택, 등록 상태와 캡처/판독 결과 비교를 반영하지 않는다.
- 어두운 배경과 대상 강조, 이전/다음/건너뛰기 및 설정에서 다시 보기 기능은 유지하는 방향이다.

### 9.2 메인 화면 도입 후 안내 순서 제안

| 단계 | 강조 대상 | 안내 문구 초안 |
|---|---|---|
| 1 | 사용할 기능 선택 | 사용할 기능을 선택하세요. 선택한 기능에 필요한 설정을 모아서 보여줍니다. |
| 2 | 설정 필요 구역 | 아직 등록하지 않은 항목입니다. 보스 체력바처럼 해당 UI가 보여야 찾을 수 있는 항목도 있습니다. |
| 3 | 자동설정 | 미등록 영역을 순서대로 찾습니다. 영역과 설명을 확인하고 승인하면 등록됩니다. 등록된 영역은 유지합니다. |
| 4 | 찾은 영역 확인 | 각 기능의 영역과 설명을 확인하고 '이 영역으로 등록'을 누르세요. 등록하지 않고 다음 항목으로 넘어갈 수도 있습니다. |
| 5 | 개별 설정 이동 | 못 찾았거나 위치가 맞지 않는 항목은 해당 설정에서 다시 찾거나 직접 지정하세요. |
| 마지막 | 안내 종료 | 사용 안내를 마쳤습니다. 실제 등록 여부는 메인에서 확인하고, 세부 동작은 각 기능에서 설정하세요. |

- 사용법 소개와 설정 완료를 구분한다. '다음'을 끝까지 누르거나 건너뛰었다고 영역 등록/검증 완료로 처리하지 않는다.
- 투어를 보았는지 기록하는 기존 값과 영역 등록 상태를 구분한다.
- 사용할 기능에 따라 알림 설정과 오버레이 배치/잠금 방식이 다르므로 '모두 같은 순서'라고 안내하지 않는다.
- 일반 사용자에게 사용할 수 없는 베타 동작을 필수 단계로 안내하지 않는다. 베타 공개 조건에 맞춰 설명을 분기한다.
- 긴 설명이 안내창 안에서 잘리지 않는지 렌더해 확인한다. 이번 Linux 렌더에서 본 일부 잘림을 Windows에서도 동일한 현상이라고 단정하지 않는다.
- 이 제안은 메인 도입 후 흐름이다. 메인 구현 전 문구만 먼저 바꾼다면 현재 존재하는 버튼/화면만 안내한다.

## 10. Acceptance Criteria 초안

| ID | 사용자 관점의 성공 기준 |
|---|---|
| U-01 | 다시 보지 않기를 선택하지 않았고 선택한 기능에 필요한 미등록 설정이 있으면 시작 시 메인이 열리며, 미등록 항목이 등록된 항목보다 먼저 표시된다. |
| U-02 | 선택한 기능의 필수 설정이 모두 등록되어 있으면 기존처럼 트래커 > 버프로 시작한다. 보스바가 현재 안 보인다는 이유로 미등록으로 바꾸지 않는다. |
| U-03 | 자동설정 실행은 선택한 기능의 미등록 영역만 대상으로 한다. 다시 눌러도 이미 등록된 영역은 변경하지 않는다. |
| U-04 | 찾은 영역은 사용자 승인 전 저장하지 않는다. 승인/거절 후 다음 항목으로 진행하고, 미발견은 안내 후 다음 항목으로 진행한다. 마지막에 등록 완료/등록하지 않음/찾지 못함을 구분하며 개별 설정 또는 메인 재시도로 이어갈 수 있다. |
| U-05 | 자동설정 확인 단계에서는 현재 항목의 찾은 영역과 설명을 함께 보여준다. 등록 후 모든 기능의 상시 미리보기를 추가하지 않고, 기존 개별 탭 미리보기는 유지한다. |
| U-06 | 확인 중 이전 후보의 캡처를 현재 항목의 결과처럼 표시하지 않는다. 숫자 판독 성공을 등록의 필수 조건으로 요구하거나 판독 없음만으로 저장된 설정을 삭제하지 않는다. |
| U-07 | 게임창 미등록 안내는 메인에 표시하고 시작 시 별도 게임창 등록 팝업을 중복해서 띄우지 않는다. |
| U-08 | 메인 열기와 자동설정은 기존 알림/잠금/배치/프리셋을 임의로 변경하지 않는다. 사용자가 메인/개별 탭의 기능 사용 체크를 바꾸면 양쪽에 같은 값이 반영되고, 체크하지 않은 기능은 실행하지 않는다. |
| U-09 | 첫 실행 안내는 존재하는 화면과 사용할 수 있는 동작을 소개하며, 안내 종료를 실제 설정 완료로 표시하지 않는다. |
| U-10 | 설명·버튼·툴팁은 해당 기능의 실제 동작과 베타 접근 조건에 맞고, 790x800 기준 화면에서 잘리거나 다른 조작을 가리지 않는다. |
| U-11 | 시작 시 다시 보지 않기를 선택하면 이후 미등록 항목이 있어도 트래커 > 버프로 진입한다. 저장된 설정은 유지하고 나중에 메인에서 설정할 수 있다. |
| U-12 | 상위 메인 탭을 추가하지 않는다. 설정의 '자동설정 다시 열기'로 메인을 열 수 있고, 버튼 클릭만으로 탐색이 시작되지 않는다. |

개별 기능의 검출 정확도나 Windows 환경 QA를 이 사용성 기준의 통과만으로 대신하지 않는다.

## 11. 결정 사항 및 개발 확인 범위

| 항목 | 결정 |
|---|---|
| 기능 사용 설정 | 메인과 개별 탭은 같은 설정을 사용한다. 개별 아이콘 표시 설정과 기능 전체 사용 여부는 구분한다. |
| 영역 확인 | 자동설정 중 기능별로 하나씩 확인하고 승인한다. 등록 후 상시 미리보기는 추가하지 않는다. |
| 메인 재진입 | 상위 탭을 추가하지 않고 설정에 '자동설정 다시 열기' 버튼을 둔다. |

앞서 남겨 둔 세 가지 선택은 해소되었다. 추가 기능 결정을 요구하는 항목은 남겨 두지 않는다. 최초 기능 미선택 안내, 구체적인 배치와 문구 길이는 기능 선택 후 자동설정을 진행하는 흐름에 맞춰 렌더링으로 검토한다. 구현 중 합의한 동작이나 범위를 바꿔야 한다면 그 변경만 사용자에게 확인한다.

기획 확정 시 결정된 내용만 남긴 독립 명세로 정리한다. 현재 문서를 구현 완료된 기능이나 확정된 전체 요구사항으로 표시하지 않는다.

### 문구 및 화면 검토 기준

- 문구 변경만으로 가능한 개선과 화면/상태 기능 변경을 나누어 검토한다.
- 긴 문구는 실제 790x800 화면에서 다시 렌더해 버튼 폭, 줄바꿈 및 핵심 동작의 노출을 확인한다.
- 베타/일반 사용자에게 해당하지 않는 안내는 조건에 맞춰 표시한다.
- 모든 설명을 상시 노출하는 것이 목표가 아니다. 짧은 안내와 버튼명만으로 다음 행동이 분명한지 우선 확인한다.
