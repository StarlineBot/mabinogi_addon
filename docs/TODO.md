    CPU = 가장 바쁜 논리 코어 사용률(병목 코어), 메모리 = 게임 프로세스 전용 메모리(작업 관리자 세부 정보 '커밋 크기', 누수 확인용).
    이름만 보면 작업 관리자 전체 값과 비교하게 되는 것이 문제. 공개 전 결정할 안:
    A(QA 권장) 값 유지·이름만 `CPU 최대 코어`·`게임 메모리` / B 작업 관리자 기준(전체 CPU%·시스템 메모리)으로 변경 /
    C 둘 다 항목으로 제공(오버레이 길어짐). 오버레이 변경이라 렌더 확인 후 반영. 기록: `docs/status.md` e9ff1a3.
    - CPU 값의 한계(사용자 질문 "코어가 매번 바뀌지 않나, 그 코어에 마비가 있다는 보장이 있나", Confirmed 코드):
      1초마다 `Processor(*)` 16개 논리 코어 중 그 1초 동안 가장 높은 값을 보여준다(어느 코어인지는 추적하지 않음, 매초 바뀔 수 있음).
      시스템 전체 기준이라 **마비노기의 코어라는 보장이 없다**(Discord·브라우저·블랙박스 인코더·앱 자신일 수 있음, 7+1에서는 백그라운드 코어일 수도).
      또 Windows가 게임 주 스레드를 1초 안에 여러 코어로 옮기면 각 코어 값이 나뉘어 **포화를 낮게 보일 수 있다**.
    - D(검토 제안): 게임 프로세스의 가장 바쁜 스레드 사용률(`\Thread(<게임>/*)\% Processor Time` 최댓값, PDH 읽기 전용·게임 핸들 불필요).
      마비노기 주 스레드가 100% 근처면 CPU 한계라는 뜻이 되고, 코어 이동·다른 프로그램 영향이 없다. 단, Thread 개체는 시스템 전체 스레드를
      모으므로 수집 부하를 실측(성능 목표 CPU 1~2%)해야 하고, 게임 프로세스 이름 인스턴스 매칭(같은 이름 여러 개) 처리 필요.
