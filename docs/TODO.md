## UI

- [~] **버튼 스타일 (민트 토글/인셋) — 보류(현재 불필요)**
  - **원래 목적**: 테마 붙이기 전 Windows 기본 버튼의 **그라데이션**이 모노톤 앱과 안 맞아
    "버튼도 통일하자"였음.
  - **결론(2026-10)**: 테마(`setColorScheme`) 적용 후 라이트/다크 둘 다 버튼에 그라데이션이
    없어 **원래 문제가 해결됨** → 재디자인 이득 없음. 게다가 커스텀 '떠 있는 선'을 전면
    적용하면 스핀박스·콤보·체크박스 등 **네이티브 컨트롤과 톤 충돌** 위험 + 커스텀 페인트
    유지비. → **하지 않기로.**
  - **혹시 재발 시 폴백**(어떤 윈도우 환경에서 버튼 그라데이션이 보이면): 커스텀 말고
    **`app.setStyle("Fusion")` 한 줄**로 앱 전체 버튼 평평화(싸고 안전).
  - 디자인 검토 산출물(참고용 보존): `docs/button-spec.md` + 세션 목업들.
  - 토글 상태는 지금 `#00B894 checked`로 충분히 동작 중.

- [ ] **계산기 통합** — 분배 / 구슬 분배 / 환전비율 계산기 3개를 한 탭으로 묶기(검토).
- [ ] **3단 탭 구성** 검토(보류).

- [ ] **블랙박스 반복 채움 기준점 보정 — 할지 말지 결정 대기** (2026-10-24 사용자: 결정 항목으로 남김).
  - 0.15.1 실측: 1분마다 반복 채움 +약 720칸(3600칸 중 20%), 서로 다른 화면 약 48FPS. 사용자 체감은 '부드러움'.
  - 원인 모형 `scripts/qa_0151_blackbox_fill_jitter.py`: 60Hz 도착 시각 ±7ms 흔들림에서 18%·49.8FPS(±4ms는 0%).
    60FPS 칸 격자의 원점이 첫(흔들린) 프레임 시각이라 반 칸 허용이 실효로 줄어 '채움 1 + 다음 프레임 버림' 쌍이 생김.
  - 하면: 원점 보정(첫 N프레임 평균) 또는 가장 가까운 칸 배정. 근거·기록: docs/status.md 128bbd6.

- [ ] **알파 화면 통일 정리 (최적화·FPS·블랙박스) — 나중에 한 번에** (2026-10-24: 블랙박스 부분은 0.16.0 공개 작업으로 넘김 — 최적화·FPS 부분만 남음) (2026-10-23 기획 검수, 사용자 결정:
      둘 다 알파라 지금은 목록만 정리하고 공개 전 일괄 처리). 렌더 비교에서 기존 탭과 다른 점:
  - 도움말 `?` 버튼 없음 (다른 기능은 모두 있음)
  - 버튼이 전체 폭으로 늘어남: `최적화 시작`/`중단 · 원복`, `요약 저장`/`폴더 열기`, `저장 내역·복구`
    (기존: 글자 크기만큼, 왼쪽 정렬)
  - 보조 안내가 검정색 여러 줄 (기존: 회색), 블랙박스는 회색·검정 혼용
  - FPS 위치 잠금이 체크박스 (기존: 잠그면 민트색이 되는 토글 버튼), 배율 스핀박스가 전체 폭
  - 블랙박스 보관 시간이 자유 입력칸 (기존: 단위가 붙은 스핀박스), 입력 오류가 먼 아래쪽에 표시
  - 내부 용어·원문 노출: `TcpAckFrequency`, `CPU 배치 · 적용됨 131개`, `P99 아님`, `변동계수`,
    `encoder exited 1: …`(영어 원문 오류), `검증용 단축키 · 실게임 미검증`
  - 블랙박스 결과 한 줄을 저장 결과·오류·단축키 반응·입력 오류가 0.1초마다 덮어씀 → 상태·오류와 최근 저장 결과 분리
  - 최적화 탭 왼쪽 여백이 약간 좁고 제작자 얼굴 배지 없음 (사소)
  - 비교 렌더: 오프스크린 렌더(값은 샘플)로 기존 체력바·도르카·커스텀 오버레이·계산기·설정 탭과 비교
  - 최적화 결과가 '이미 목표값'일 때 표시 (2026-10-23 사용자 의견): CPU 배치를 끄고 패스트핑만 켠 채 시작하면 TCP 3항목이 모두
    '기존 값 일치·변경 없음'으로 끝나고 버튼이 바로 `최적화 시작`으로 돌아와 "눌렀는데 왜 안 됐지?"로 보인다.
    → 선택한 항목이 이미 목표값이면 '이미 최적화 값이에요(바꾼 것 없음 · 원복할 것 없음)'처럼 **설정됨**으로 보여주기
    (상단 배지·결과 첫 줄). 원복 대상이 없으므로 `중단 · 원복`은 계속 비활성. 렌더 확인 후 반영.
  - 공개 전환 때 결과 표시 방향 (2026-10-23 사용자 의견): 알파는 항목별 상세(무엇이 안 됐는지)를 그대로 노출, 공개 때는 결과를
    한 줄 요약('최적화 완료' 등)으로 먼저 보여주고 상세는 접어 두기. 사용자 비유: PT 상담에서 "뱃살만 빼는 운동은 없습니다"만 말하면
    등록하지 않는다 — 전체 과정으로 안내해야 한다. QA 메모: 요약 문구는 '설정이 목표 상태로 맞춰짐'(사실)을 말하고 '성능 향상'은
    측정 근거 전까지 단정하지 않기(명세 '측정되지 않은 배치를 최적으로 표시하지 않는다'와 충돌 방지). 공개 기획 때 문구 확정.
  - FPS 오버레이 추가 지표 이름 (2026-10-23 사용자 의견, 알파는 현재 그대로 사용하기로 결정): 0.13.4 실사용에서 `CPU` 70%대가
    작업 관리자 약 20%와, `메모리` 3.0이 시스템 20.0/31.1GB(64%)와 달라 이상하게 보였다. 값은 정의대로(FPS 명세 8.4) —
    CPU = 가장 바쁜 논리 코어 사용률(병목 코어), 메모리 = 게임 프로세스 전용 메모리(작업 관리자 세부 정보 '커밋 크기', 누수 확인용).
    이름만 보면 작업 관리자 전체 값과 비교하게 되는 것이 문제. 공개 전 결정할 안:
    A(QA 권장) 값 유지·이름만 `CPU 최대 코어`·`게임 메모리` / B 작업 관리자 기준(전체 CPU%·시스템 메모리)으로 변경 /
    C 둘 다 항목으로 제공(오버레이 길어짐). 오버레이 변경이라 렌더 확인 후 반영. 기록: `docs/status.md` e9ff1a3.
    - CPU 값의 한계(사용자 질문 "코어가 매번 바뀌지 않나, 그 코어에 마비가 있다는 보장이 있나", Confirmed 코드):
      1초마다 `Processor(*)` 16개 논리 코어 중 그 1초 동안 가장 높은 값을 보여준다(어느 코어인지는 추적하지 않음, 매초 바뀔 수 있음).
      시스템 전체 기준이라 **마비노기의 코어라는 보장이 없다**(Discord·브라우저·블랙박스 인코더·앱 자신일 수 있음, 7+1에서는 백그라운드 코어일 수도).
      또 Windows가 게임 주 스레드를 1초 안에 여러 코어로 옮기면 각 코어 값이 나뉘어 **포화를 낮게 보일 수 있다**.
    - D(검토 제안): 게임 프로세스의 가장 바쁜 스레드 사용률(`\Thread(<게임>/*)\% Processor Time` 최댓값, PDH 읽기 전용·게임 핸들 불필요).
      마비노기 주 스레드가 100% 근처면 CPU 한계라는 뜻이 되고, 코어 이동·다른 프로그램 영향이 없다. 단, Thread 개체는 시스템 전체 스레드를
      모으므로 수집 부하를 실측(성능 목표 CPU 1~2%)해야 하고, 게임 프로세스 이름 인스턴스 매칭(같은 이름 여러 개) 처리 필요.

## 기능

- [ ] **요리 (편의기능 탭)** — '편의기능'에 요리 관련 기능 추가(세부 스펙 미정).
- [x] **체력바 경고 알림** — 생/마/스 각각 on/off + 각각 임계%(직접 설정, 기본 30%), ≤일 때
      1회 경고, 소리 체크. (커밋 `2a68872`, v0.4.58)
- [ ] **체력경고 소리 종류 결정** — 현재 `체력바 경고.mp3` 없으면 시스템 비프로 동작 중.
      추천: **짧은 3음 비프(생=낮게/마=중간/스=높게)를 코드로 생성해 넣기**(TTS 아님).
      비프 vs 효과음 vs TTS 중 택1 → 정하면 구현.
- [x] **버프 사라짐 경고 지연** — 점검 결과 판정(0~0.4초)은 빠르고 확정 대기(3초)가 지연
      원인. 결론: **현상유지(전부 견고 3초)**. 단단함=거짓경고 없음이고, 시간 버프는 1·2차
      경고 후 빠진 거라 어차피 손실이라 빠를 필요 없음. 즉시종료형(마나실드) 빠른 확정은
      커스텀 버프라 하드코딩이 부적절 + 버프별 설정까진 과해서 **안 하기로.**
- [x] **2차(막차) 목소리 mp3 생성/푸시** — 완료. 세 팩에 `OOO 연장2.mp3` 5개씩 생성·푸시
      (Google Chirp3 백엔드, `--backend google`). edge-tts는 MS 403으로 막혀 Google 사용.
      급박도 조절은 gen_tts 맨 위 `URGENT_GOOGLE_RATE_MULT`(현재 1.15). (v0.4.58)
- [ ] **체력바 숫자 OCR** — 채움 비율뿐 아니라 '현재/최대' 수치까지 읽어 표시(`stat_overlay` 주석의 '추후 수치').
