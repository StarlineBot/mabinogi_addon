# 도르카 재시작 시 옛 숫자 영역 오인 보완

> 아래는 `1b7c8a4` 당시 수정·검증 기록이다. 자체 창 가림 후속 구현과 Windows 검증 상태는
> [자체 창 가림 복구 보완](dorcha-self-capture-fix.md)에 구분해 기록한다.

## 범위

- 통합 작업 중 원격 `e69a1f3`의 추가 QA와 재현 코드를 확인해 함께 반영했다.
- 근거: `qa/도르카_이동후_재시작_재인식_QA_20261017.md`,
  원본 `scripts/qa_dorcha_restart_after_move.py`.
- 원본 재현은 수정 전 **2 failed, 3 passed (8.57초)**였다. 옛 승인 영역 A에 다른 0이
  나타나면 실제 도르카가 B로 이동했어도 A의 0을 채택하고 재탐색을 생략했다.
- 실제 사용자가 본 --/15의 원인과 이 0 오인을 같다고 단정하지 않는다.
  커스텀 사용 관련 고정 제보와도 구분한다.

## 수정

- 등록된 게임 문맥이 확인될 때, 실행 중 검증된 위치가 없는 옛 저장 영역은 먼저 주변의
  작은 사각형에서 실제 도르카 장식과 숫자를 확인한다. 숫자만 읽힌다고 신뢰하지 않는다.
- 문맥 검증에 실패하면 옛 숫자는 표시하지 않고 기존 게임 한정 재탐색/backoff로 넘어간다.
  검출된 위치에서도 현재 픽셀을 다시 읽은 뒤에만 값을 게시한다.
- 현재 실행에서 사용자가 직접 승인한 영역은 그때의 게임 대상과 묶인 임시 증거로 구분한다.
  명시적 승인 직후 가려진 장식을 다시 요구해 기존 수동 복구가 실패하는 회귀를 막는다.
  중단/게임 대상 변경/재시작 시 이 신뢰를 보존하지 않는다.
- 승인 영역 A는 자동으로 B로 저장하지 않는다. 오버레이 표시 위치/잠금 및 기존 % 표시와
  투아림 알림도 변경하지 않는다. 게임 창 등록이 없는 기존 수동 영역 경로는 유지한다.
- 검증은 초기 문맥에 한 번만 수행한다. 안정된 100회 관측은 작은 문맥 캡처 1회와 숫자
  영역 캡처 100회이며 전체 게임 캡처/매 틱 재탐색을 추가하지 않는다.
  경계 밖 영역은 여전히 읽지 않고 크기 제한/취소/늦은 결과 거부도 유지한다.
- 기존 두 회귀의 정확한 캡처 목록은 새 최초 문맥 캡처를 포함하도록 변경했다.
  전체 화면 캡처 금지나 반복 횟수 assertion은 유지했다.

## 검증 및 미해결

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest scripts/qa_dorcha_restart_after_move.py tests/test_dorcha_restart.py tests/test_dorcha_tracking.py tests/test_dorcha_roi_context.py tests/test_dorcha_game_target.py tests/test_resource_integration.py -q --tb=short
```

- **1 failed, 85 passed (89.63초)**. 원래 숫자 오인 재현, 빈 옛 영역 및 수동 자동찾기 복구,
  기존 게임 대상/이동/종료/backoff와 통합 8조합 검사를 포함한다. 실패를 숨기거나 skip하지 않았다.
- 남은 실패는 `runtime-recovery`: 앱 소유 창이 원형 장식을 가린 합성 입력이다.
  가리지 않은 대조군과 명시적 자동찾기 복구 대조군은 통과했다.
- **DORCHA-RESTART-SELF-CAPTURE-QA-02는 미해결**이다. 실행 중 복구는 여전히 화면 사각형을
  직접 캡처하며, 명시적 자동찾기는 자체 창을 잠깐 숨긴다. 이 캡처 정책 차이는 이번 수정으로
  해결했다고 주장하지 않는다. Windows 실캡처에서 당시 제보의 원인이었는지도 미확인이다.
- 현재 원본 QA 스크립트의 알려진 실패는 그대로 남고, 확정된 저장 영역 오인 3조건을
  `tests/test_dorcha_restart.py`의 일반 회귀에 편입했다. 나머지 합성 조건을 통과로 집계하지 않는다.
- 이 합성 테스트는 Windows HWND/GDI 캡처를 대체하므로 자체 창 제외 방식의 실제 Windows
  동작·실패 시 복구·게임/앱 포커스 및 성능을 확인해야 한다. 위치 저장이나 숫자 기준 완화로
  가리지 않는다. 이번 수정본을 모든 QA 해결/릴리즈 준비 완료로 보고하지 않는다.
