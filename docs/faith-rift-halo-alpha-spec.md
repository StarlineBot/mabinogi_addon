## 2026-10-19 라이브 후속 승인: 현재 우선 적용

- 사용자는 앱 시간 판독·알림 자체는 정상이라고 확인했다. 실제 게임 헤일로 등장 시각 01:15/00:13 관측을 앱 오판독으로 취급하지 않는다. 자료만으로 63초 주기를 임의 보정하지 않는다.
- 회한 보스를 최초 확인한 같은 전투에서 타이머가 유효하게 감소하면 패턴 중 보스바가 일시 미식별이어도 표시·예정 경고를 유지한다. 이전의 매번 최근 보스 식별 요구는 최초 확인과 유지 조건을 구분하도록 보완한다.
- 헤일로 판독·표시·경고의 베타 공개가 승인됐다. 기존 Discord 베타 조건에 연결하며 원본 수집/스냅샷은 별도 공개 승인 전까지 제작자 전용을 유지한다. 투아림 등 다른 알파 기능의 접근 조건은 변경하지 않는다.
- 설정은 기존 체력별패턴의 그룹과 버튼 규칙에 맞춘다. 헤일로 두 표시만 기존 보스 경고보다 조금 작고 덜 강조하며 기본 상하 순서는 카운트다운 위, 5초 전 경고 아래다. 저장된 개별 위치와 기존 보스 표시 자체는 보존한다.
- 사용자가 추가한 `tests/data/universfield-new-notification-014-363678.mp3`를 헤일로 5초 전 경고음으로 연결한다. 제품 sounds 리소스로 포함하고 소리 옵션 ON에서 유효한 회차당 한 번만 재생한다. 카운트다운 갱신마다 재생하거나 기존 다른 알림음을 교체하지 않는다. 이전 미연결 소리 옵션은 이번 승인 범위에서 실제 연결한다.
- 상세 개발 지시, 시간 자료 검토와 독립 재현은 [라이브 후속 개발 전달](qa/헤일로_라이브후속_개발전달_20261019.md)을 따른다. 아래 초기 알파 접근·보스 식별 조건과 충돌하면 이 최신 승인 절을 우선한다.

## 2026-10-19 개발 단계 승인

- 후속 배치 승인: `전투 보조 → 보스 패턴 알림 → [체력별패턴] [1분 헤일로]`의 3차 탭으로 분리한다. 헤일로 탭은 제작자만 보이며 하단 연결 배치를 대체한다. `1분 헤일로`는 화면 이름이며 실제 계산 주기는 기존 63초 요구를 유지한다.
- 제작자는 Discord 숫자 ID로 구별하며 표시 이름을 쓰지 않는다. 일반 로그인은 제작자 권한이 아니다.
- 사용자 승인에 따라 이번 개발 범위는 **직접 영역 지정·원본 미리보기·수집**이다. 시간 판독·내부 시계·카운트다운·실제 사전 알림은 자료 검증 뒤 별도 개발한다.
- 수집은 앱 실행마다 OFF, 초당 최대 1장, 세션당 900장 또는 100MiB 한도이며 저장 실패 시 중단한다.
- 밝고 채도가 낮은 숫자 모양 변화로 중복을 억제한다. OCR 성공 여부를 저장 조건으로 쓰지 않는다. 배경 변화 포함·작은 변화 누락 가능성이 있어 제작자 실게임 검증이 필요하다.
- 아래 전체 알림 기능 요구와 미확정 동기화 조건은 유지한다. 수집 단계 구현을 전체 헤일로 기능 완료나 베타 공개 승인으로 보지 않는다.

## 1. 사용자 요청 및 확인된 기준

- 브리레흐 4관은 이 기능에서 말하는 믿음의 균열이다.
- 게임 상단 타임어택은 15분부터 시작한다.
- 첫 헤일로 시각은 남은 시간 `14:53`이다. 이후 발생 간격은 63초다. 아래 일정은 사용자 확인된 게임 규칙을 계산한 것이며 이번 세션에서 전투 영상으로 검증한 결과는 아니다.
- 각 헤일로 5초 전에 알린다.
- 기존 왼쪽 체력 기준 패턴 목록과 다른 표시 영역에 다음 헤일로까지 남은 초를 보여준다.
- `15:00` 시작을 확인해 내부 시계를 시작하고, 이후 내부 시계로 안내한다. 분 단위로 게임 시간과 일치하는지 확인한다.
- 초기 공개 단계는 알파이며 제작자 본인에게만 보이게 한다. 일반 사용자와 일반 베타 사용자는 대상이 아니다.
- 체크로 켜는 수집모드를 제공하고 시간이 바뀔 때마다 자료를 저장한다. 제작자가 시간 수집·판독이 정상이라고 판단한 이후 베타 공개를 검토한다.
- 자동 베타 전환은 요구하지 않는다. 판독 성공률이나 일정 시간이 지났다는 이유만으로 공개 범위를 넓히지 않는다.

## 2. 알림 일정과 계산 의미

회차 `k`는 1부터 센다.

```text
시작 기준: 남은 시간 900초
k회차 헤일로: 남은 시간 893 − 63 × (k−1)초
k회차 사전 알림: 헤일로 남은 시간 + 5초
다음 헤일로까지: 현재 남은 시간 − 다음 헤일로의 남은 시간
```

| 회차 | 헤일로 시각 | 5초 전 알림 시각 |
|---|---|---|
| 1 | 14:53 | 14:58 |
| 2 | 13:50 | 13:55 |
| 3 | 12:47 | 12:52 |
| 4 | 11:44 | 11:49 |
| 5 | 10:41 | 10:46 |
| 6 | 09:38 | 09:43 |
| 7 | 08:35 | 08:40 |
| 8 | 07:32 | 07:37 |
| 9 | 06:29 | 06:34 |
| 10 | 05:26 | 05:31 |
| 11 | 04:23 | 04:28 |
| 12 | 03:20 | 03:25 |
| 13 | 02:17 | 02:22 |
| 14 | 01:14 | 01:19 |
| 15 | 00:11 | 00:16 |

- 첫 회차 주의: 첫 알림은 시작 2초 후, 첫 헤일로는 시작 7초 후다. 첫 알림까지 제공하려면 `14:58` 이전에 시작 동기화가 완료되어야 한다.
- 63초 주기라고 해서 첫 헤일로를 시작 63초 후로 계산하지 않는다.
- 내부 시계는 갱신 처리 횟수가 아니라 실제 경과 시간에 따라 진행해야 한다. 반복 갱신 지연을 매 주기 누적하지 않는다.
- 분 단위 동기화 확인은 분 숫자만 비교하는 뜻이 아니다. 게임의 `분:초` 전체와 내부 남은 시간을 비교한다.
- 같은 회차의 사전 알림은 중복 발화하지 않아야 한다. 새 전투에서는 회차 상태를 다시 시작해야 한다.

기존 설정 아래에 헤일로 구간을 이어 붙인 목업을 사용자 확인받았다. 화면이 긴 점은 현재 배치를 유지한 채 추후 개선하기로 했다.

목업의 판독값·동기화 상태·수집 장수는 샘플이며 실제 구현 결과가 아니다. 좌표·치수도 새 기본값으로 고정하지 않는다.

- 전용 상위 탭이나 설정 대상 셀렉트를 추가하지 않는다. 기존 보스 패턴 알림 설정 하단에 구분선과 `믿음의 균열 헤일로 알림` 제목으로 별도 구간을 둔다.
- 창을 세로로 늘리지 않고 같은 화면의 세로 스크롤로 이어지게 한다. 이번 단계에서 길이를 줄이기 위한 재배치나 새 선택 UI를 추가하지 않는다.
- 헤일로 제목 아래 설명은 공개용으로 `게임의 남은 시간을 기준으로 다음 헤일로까지 표시하고, 발생 5초 전에 알립니다.`를 사용한다.
- 헤일로 기능 제목·기본 설명에는 제작자 전용/알파 안내나 알파 배지를 넣지 않는다. 알파는 내부 공개 단계로 관리하며 화면 안내 문구와 분리한다. 이는 제작자 전용 접근 제한을 없애거나 일반 사용자에게 노출한다는 뜻이 아니다.
- 다른 기능 설명의 베타 표기도 같은 원칙으로 정리한다. 화면별 대상과 권한 보존 기준은 [기능 설명의 공개 단계 표기 정리](feature-description-copy-spec.md)를 따른다.
- 체력 기준 알림과 시간 기준 알림을 같은 판독 영역이나 임계값 설정으로 묶지 않는다.
- 타임어택 판독 영역은 보스 체력바 판독 영역과 별도로 등록한다. 시간 기능 설정이 공유 보스 체력바나 디버프 영역을 덮어쓰지 않는다.
- 초기 시간 영역 등록은 직접 지정으로 시작하는 방향을 제안한다. 시간 영역 자동찾기와 전투 시작 자동 판정은 이번 알파의 필수 범위로 확정하지 않는다.
- 다음 헤일로 표시는 기존 체력 패턴 목록과 독립된 이동·잠금 대상으로 두고, 기존 오버레이의 이동·잠금·클릭 통과·노출 정책을 따른다.
- 기존 체력 패턴 목록의 위치·내용·잠금·설정은 유지한다. 새 표시 때문에 위치를 초기화하지 않는다.
- 다음 헤일로 안내는 일정표에 따른 예상이다. 실제 패턴이 화면에서 발생한 것을 검출했다는 뜻으로 표시하지 않는다.

표시 예:

```text
다음 헤일로
23초 전
```

사전 알림의 화면·소리 조합, 문구, 유지 시간과 위치는 기존 경고 조작을 참고해 목업에서 확인한다. 5초 전이라는 기준 외 세부값을 임의로 확정하지 않는다.

## 4. 제작자 전용 알파 접근

### 4.1 필요한 동작

- 제작자에게만 알파 설정·판독 미리보기·수집모드·헤일로 표시/알림을 제공한다.
- 다른 사용자는 일반 베타 로그인을 했더라도 이 알파 기능을 사용할 수 없어야 한다.
- 메뉴를 숨기는 것만으로 끝내지 않는다. 비대상 사용자에게는 저장된 설정이 있더라도 이 기능의 판독·알림·자동 수집을 시작하지 않는다.
- 계정 변경·로그아웃·권한 확인 실패로 제작자 조건이 사라지면 이 기능의 알림·표시·수집을 중단하는 방향을 제안한다. 기존 다른 기능의 접근 조건은 바꾸지 않는다.
- 알파로 배포한 뒤에도 수집 자료는 자동 업로드하거나 다른 사용자에게 공유하지 않는다.

### 4.2 현재 소스와 차이

- 현재 보스/투아림 수집 도구의 조건은 기본적으로 디스코드 로그인 여부다. 이를 그대로 적용하면 제작자 전용 요구를 충족하지 못한다.
- 현재 디스코드 로그인에서 사용자 ID를 얻는 경로는 있다. 제작자 식별 기준은 구현 전에 확인해야 한다. 표시 이름만으로 본인 여부를 판단하지 않는다.
- 구체적인 인증 방식, 계정 ID 값 또는 개발자 전용 빌드 방식은 이 문서에서 임의로 지정하지 않는다.

## 5. 시간 판독·수집모드

### 5.1 검증 목적

- 저장소 [14:57 타이머 원본](../tests/data/스크린샷%202026-10-09%20185247.png)에서 상단 `전투 제한 시간`과 `분:초` 표기를 확인했다. 간단한 범용 OCR 시험은 일부 샘플만 정확하게 읽었고 다른 배경에서는 실패했다. 이는 수집·개선 필요성의 근거이지 제품 판독기 선정이나 안정성 검증 결과가 아니다.
- 타이머 숫자와 구분자를 다양한 값·배경·이펙트에서 모아 판독에 사용할 자료를 확보한다.
- 정상 판독 예시뿐 아니라 오독·판독 불가 장면도 남겨 원인을 확인할 수 있어야 한다.
- 수집 성공은 이미지 저장 성공이며, 해당 이미지의 판독값이 정답이라는 뜻이 아니다.
- 시간 수집은 헤일로 알림의 최초 동기화나 정상 알림 발생에 종속되지 않아야 한다. 아직 판독이 되지 않아도 자료 수집을 시작할 수 있어야 한다.
- 사용자 추가 결정(2026-10-19): 수집 모드를 켜도 실제 저장은 기존 보스 판독기에서 `lenen_miir_hoehan`이 최근 식별된 동안만 수행한다. 일반 미이르·다른 보스·미식별에서는 대기하며 수동 스냅샷에도 같은 조건을 적용한다. 판독 성공 시 시간 값이 바뀌었을 때 저장하고, 판독 불가 자료는 숫자 모양 변화 기준으로 계속 수집한다.

### 5.2 사용자 흐름

1. 제작자가 게임 상단 타이머 영역을 지정한다.
2. 앱에서 실제 지정 영역 이미지와 현재 원시 판독값을 확인한다.
3. 수집 체크를 켜고 게임을 진행한다.
4. 타이머의 표시 시간이 변하면 해당 원본 영역을 저장한다.
5. 저장 위치와 성공한 저장 장수를 확인하고 폴더에서 자료를 검토한다.
6. 수집 체크를 끄면 자동 저장을 중단한다.

기존 수집 도구와 유사하게 `스냅샷 저장`, `폴더 열기`, `수집 모드` 체크 및 저장 위치/장수를 제공하는 구성을 제안한다.

### 5.3 저장 대상과 변화의 의미

- 저장 대상은 게임에서 실제 캡처한 타이머 영역 원본이다. 내부 시계의 숫자를 새로 그린 이미지를 원본 자료처럼 저장하면 안 된다.
- 판독 성공값만 바뀔 때 저장하는 조건으로 제한하지 않는다. 오독이나 판독 실패 상태에서도 실제 숫자가 변한 화면은 수집 대상이다.
- 반대로 배경·이펙트가 바뀐 모든 캡처 프레임을 시간 변경으로 간주해 무제한 저장하지 않는다.
- 동일 표시 시간을 중복 저장하지 않는 것이 목적이나, 판독 결과만으로 실제 동일 시간을 보장할 수 없다. 숫자 변화 판정과 중복 억제의 정확한 기준은 알파 수집 방식 확인 항목이다.
- 원시 판독값을 남기는 경우 정답이 아닌 판독 결과로 표시하고, 못 읽은 값은 실패/미판독으로 구별한다. 내부 예상값으로 원시 판독값을 채우지 않는다.
- 파일은 기존 수집 도구처럼 원본 PNG를 사용하는 방향을 제안한다. 최소한 수집 순서, 캡처 시점, 원시 판독값/실패 여부를 원본과 대응시킬 수 있어야 한다. 구체적인 파일명·부가 기록 형식은 구현 세부사항이다.
- 수집 세션·재실행으로 같은 이름의 이전 자료를 덮어쓰지 않아야 한다.
- 기본 저장 범위는 지정 타이머 영역으로 제안한다. 전체 화면 자동 수집은 현재 요청에 포함하지 않는다.

### 5.4 실패·중단과 자원 관리 제안

- 시작 시 수집은 꺼진 상태로 두고 앱 재실행 후 자동 재개하지 않는 방향을 제안한다.
- 영역 없음, 캡처 실패, 저장 경로 접근 불가, 디스크 쓰기 실패는 성공 저장과 구별해 표시한다. 저장 실패한 이미지를 성공 장수에 포함하지 않는다.
- 쓰기 실패가 반복될 때 프레임마다 팝업을 띄우거나 저장 작업을 무제한 쌓지 않는다. 중단/재시도 정책과 저장량 한계는 알파 시작 전에 결정한다.
- 영역 변경·지정 해제·제작자 접근 해제·앱 종료 시 이전 영역을 계속 수집하지 않는다. 영역 변경 후 새 수집 세션으로 구분하는 방향을 제안한다.
- 게임 이외 화면을 타이머로 저장하지 않도록 기존 게임창/포그라운드 캡처 조건을 따른다. 숨겨진 게임 화면 수집을 새로 추가하지 않는다.
- 자료 자동 삭제·외부 전송·자동 Git 커밋/푸시는 하지 않는다. 필요한 자료를 제작자가 직접 검토해 공유한다.
- 수집용 추가 캡처·저장 때문에 게임 또는 기존 판독/오버레이가 눈에 띄게 지연되지 않아야 한다. 폴더 열기나 저장 실패가 앱 종료를 막지 않아야 한다.

## 6. 동기화와 생명주기: 알파 검증 항목

```text

내부 시계 안내 중: 약 1분마다 게임 분:초와 비교 → 일치 확인 또는 동기화 문제 표시
```

- 시작 대기·동기화됨·게임 시간 확인 불가·시간 불일치를 구별해 검증할 수 있어야 한다.
- 수집 켜짐/꺼짐은 이 상태와 독립적이다. 수집을 끄는 것 자체가 알림 설정을 끄는 뜻은 아니다.
- 사용자 추가 결정(2026-10-19): `15:00`을 놓쳐도 감소하는 현재 시간을 연속 확인하여 중간 동기화한다. 이미 지난 회차의 알림은 몰아서 울리지 않는다.
- 한 번의 오독으로 시계를 즉시 재시작하거나 알림 회차를 되감지 않는다. 시간 오차 허용 범위와 재확인 조건은 수집 결과를 보고 결정한다.

## 7. 알파에서 베타로 진행하는 순서

1. 기능의 목표 동작과 알파 접근·수집 조건을 확인한다.
2. 제작자 전용 알파에 영역 지정, 원본/판독 미리보기와 수집모드를 먼저 준비해 자료를 확보한다. 알림이 아직 정상 동작하지 않아도 수집할 수 있어야 한다.
3. 수집한 원본에 제작자가 정답 시간을 확인하고, 시간 판독을 개선·검증한다. 내부 예상 시간을 정답 라벨로 자동 확정하지 않는다.
4. 내부 시계 동기화, 실제 63초 일정과의 일치, 5초 전 알림, 독립 카운트다운을 제작자 실게임 환경에서 검증한다.
5. 제작자가 결과를 확인하고 명시적으로 베타 공개를 승인한다. 시간 판독 자료만 정상이라는 이유로 알림·생명주기 검증 완료까지 간주하지 않는다.
6. 승인 후 기존 베타 접근 정책에 연결한다. 베타 공개 범위와 수집모드 공개 범위는 같은 것으로 간주하지 않으며 별도 확인한다.

알파 검증 시 최소한 다음을 확인한다.

- 실제 플레이에서 등장한 숫자·분/초 자리올림·밝고 어두운 배경·공지나 이펙트 겹침의 판독 결과.
- 읽히지 않은 화면도 원본으로 남는지, 배경 변화 때문에 저장량이 급증하지 않는지.
- 시작 직후 `14:58` 알림 준비 가능 여부 및 이후 회차의 실제 패턴 시점과 알림 오차.
- 같은 회차 중복 알림, 오독으로 인한 갑작스러운 시간 이동, 반복 동기화로 인한 주기 누적 오차 여부.
- 재도전·앱 재실행·포커스 전환·절전 복귀 후 잘못된 전투 시계가 이어지지 않는지.
- 제작자 이외 사용자에게 설정/수집/알림이 실행되지 않는지.

고정된 정답률·허용 오차 수치는 아직 정하지 않았다. 개발자가 임의의 성공률로 베타 전환을 선언하지 않는다. 제작자 화면 통과가 다른 해상도·배율의 검증 완료를 뜻하지도 않는다.

## 8. Acceptance Criteria

### 8.1 사용자 확인된 기능 기준

1. 알파 단계에서 제작자 이외 사용자에게 기능 설정이 노출되지 않으며 일반 베타 로그인만으로 판독·수집·알림이 시작되지 않는다.
2. 시작 시간이 15:00이고 첫 헤일로가 14:53인 기준으로 계산하며 이후 63초 간격의 일정은 2절 표와 일치한다.
3. 정상 동기화된 경우 각 일정의 5초 전에 알리고 같은 전투·같은 회차에 중복 알림을 내지 않는다. 예를 들어 두 번째 알림 기준은 13:55이고 패턴 기준은 13:50이다.
4. 다음 헤일로까지 남은 초를 기존 체력 패턴 목록과 다른 표시 영역에서 확인할 수 있다. 다음 패턴의 체력 퍼센트처럼 표시하지 않는다.
5. 내부 시간은 갱신 지연을 누적하지 않고 실제 경과에 맞춰 진행한다. 분 단위 검증은 게임의 분:초 전체와 비교한다.
6. 수집 체크가 켜져 있을 때 실제 시간 표시가 변한 원본 타이머 영역을 수집할 수 있다. 판독 실패 화면도 수집 가능하며 알림 동기화 성공을 수집 시작 조건으로 삼지 않는다.
7. 수집 체크를 끄면 새 자동 저장이 중단된다. 저장 실패는 성공 저장으로 집계되지 않고 기존 원본 자료를 덮어쓰지 않는다.
8. 기존 보스 패턴 알림·디버프의 영역과 알림/목록 설정이 새 기능의 설정이나 수집 때문에 바뀌지 않는다.
9. 제작자의 명시적 공개 결정 전에는 기능이 일반 베타 사용자에게 공개되지 않는다.

### 8.2 확정 후 추가할 검증 기준

- 제작자 식별 방식, 대상 던전 확인/시작 조건, 알파 접근 변경 시 중단 동작.
- 수집 변화 판정·중복 제한·저장 한도·쓰기 실패 후 동작과 기본 수집 상태.
- 시작을 놓친 경우, 동기화 오차·장시간 실패·복귀 후 알림 처리.
- 알림 표현·유지 시간, 베타 공개 시 수집모드 접근 범위. 기본 화면 배치는 3절 승인 내용을 따른다.

## 9. 남은 확인 사항

개발자가 선택해도 되는 라이브러리나 클래스 구조가 아니라, 구현 결과가 달라지는 다음 조건을 확인한다.

1. 제작자 접근 식별: 기존 디스코드 계정 식별을 사용할지 별도 개발자용 배포로 제한할지. 현재 소스의 로그인 여부만으로는 부족하다.
2. 수집 동작: 판독 실패도 저장하되 배경 변화의 과다 저장을 막을 기준, 기본 꺼짐/재실행 비재개, 저장 한도와 실패 시 중단·재시도 제안 승인.
3. 알림 동작: 15:00을 놓친 중간 동기화, 5초 전을 놓친 알림, 시간 불일치·복귀 시 동작 및 믿음의 균열 대상 확인 방식.
4. 알림: 화면·소리 경고의 세부 표현과 유지 시간 확인. 설정 화면의 하단 구간 배치는 승인됐으며 화면 길이 개선은 후속 작업으로 분리한다.

알파 수집만 먼저 개발할 경우에도 1~2번은 착수 전에 정한다. 알파 수집 단계가 준비됐다는 것과 전체 헤일로 알림 기획/구현이 완료됐다는 것은 구별한다.
