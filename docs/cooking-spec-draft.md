# 요리 조회 및 비율 가이드 기획 초안

- 상태: 검토용 초안. 사용자의 명시적인 '기획 확정' 전까지 최종 명세가 아니다.
- 작성일: 2026-10-14
- 대상: Windows용 mabinogi_addon의 편의기능 > 요리
- 목적: 개발 세션과 독립 QA 세션에서 기능 범위와 기대 동작을 검토할 수 있는 요구사항 문서.
- 이 문서의 '반영 사항'은 대화에서 합의한 방향이다. '제안'과 '미정'은 구현자가 임의로 확정하지 않는다.

## 1. 목적 및 MVP 범위

사용자가 요리를 카테고리로 탐색하거나 요리명, 재료, 능력치로 검색하고, 선택한 요리의 재료, 조리방법, 능력치 및 혼합 비율을 한 화면에서 확인한다.

게임 위에 목표 혼합 비율을 색상 바와 점선으로 표시한다. 사용자가 게임 요리 미니게임의 실제 바와 직접 위치와 크기를 맞춰 재료 입력을 멈출 지점을 확인한다.

### 반영 사항

- 편의기능에 요리 화면을 추가한다.
- MVP는 오버레이의 수동 배치와 마우스 휠 크기 조절을 제공한다.
- 요리 미니게임에서 누르는 버튼과 실제 재료 입력은 사용자가 직접 조작한다.
- 요리창 자동찾기는 기존 트래킹/오버레이의 자동찾기가 마무리된 이후 별도 검토한다.
- 바는 선택한 레시피의 목표 비율을 보여준다.

### 별도 요구 또는 후속 검토가 필요한 범위

- 실제 투입량 감지, 목표 도달 판정 및 진행 상태 추적.
- 클릭 또는 키 입력 자동화. 기존 프로젝트는 게임 입력 자동화와 게임 메모리 읽기를 금지한다.
- 자동찾기, 게임 요리창 이동에 대한 자동 추종.

## 2. 참고 자료와 데이터 범위

### 확인한 자료

- 봇 명령: https://github.com/StarlineBot/discord_bot/blob/main/commands/cookingInfo.js
- 실제 요리 데이터: https://github.com/StarlineBot/discord_bot/blob/main/modules/cookings.js
- 국내 레시피 원본: https://github.com/StarlineBot/discord_bot/blob/main/scripts/korean_recipes.json
- 게임 UI 배경: https://github.com/StarlineBot/discord_bot/blob/main/static/img/mabi_cook2_ver2.png
- 비율 이미지 생성: https://github.com/StarlineBot/discord_bot/blob/main/scripts/pregen_images.js
- 사용자 제공 팬사이트 이미지: 감자계란샐러드 50:75:15, 모둠생선회 44:33:33. 원문의 퍼센트 표기를 상대 비율로 해석한다는 설명이 포함되어 있다. 원본 URL은 제공되지 않았다.

### 반영 사항

- 요리 목록 범위는 현재 봇의 검색 대상과 동일하다.
- 봇의 검색 대상 조건은 `isCatering === true`이다.
- 요리명, 조리방법, 재료 순서, 레시피 원문, 능력치 및 썸네일을 참고한다.
- 국내 레시피 원본의 모든 항목을 별도 합의 없이 목록에 추가하지 않는다.

### 현황과 제한

- 확인 시점의 실제 데이터는 471개이며, 봇 검색 대상은 466개이다. 숫자는 버전별로 바뀔 수 있으며 고정된 요구사항이 아니다.
- 전체 데이터에서 레시피가 있는 항목은 392개, 없는 항목은 79개이다. 레시피가 없는 79개는 봇 검색 대상에도 포함된다.
- 레시피 합계가 100이 아닌 항목은 87개이다. 상대 비율 데이터이므로 합계만으로 오류라고 판단하지 않는다.
- 봇은 Discord 출력 제한 때문에 결과를 최대 20개 전송한다. 데스크톱에서도 이 제한을 유지할지는 미정이다. 목록 범위와 결과 개수 제한을 구분한다.
- 데이터의 배포 포함 방식, 갱신 방식, 썸네일 외부 접근 조건은 미정이다. 특정 기술이나 런타임 네트워크 의존성을 이 문서에서 고정하지 않는다.

## 3. 화면 및 탐색

### 3.1 공통 화면

- 상단: 검색 종류 선택 및 종류에 맞는 검색 조건 입력.
- 하단 오른쪽: 선택한 요리 상세 영역.
- 상세 영역의 위치와 크기는 기본 탐색과 검색 결과 표시 사이에서 유지한다.
- 상세에서 재료, 원문 비율, 환산 비율 바 및 능력치를 확인한다.
- 봇의 게임 UI 이미지를 참고하여 버튼 위치와 바의 관계를 한눈에 비교할 수 있는 미리보기를 제공한다.
- 조리방법과 썸네일의 구체적인 배치, 오버레이 표시 제어의 형태는 화면 검토에서 정한다.

### 3.2 기본 탐색

```text
[검색 종류] [검색 조건]
[카테고리 목록] [해당 카테고리 요리 목록] [요리 상세]
```

- 1차 카테고리를 선택하면 해당 조리방법에 속하는 요리만 2차 목록에 표시한다.
- 요리를 선택하면 오른쪽 상세를 갱신한다.
- 첫 실행 및 재실행은 검색 전 초기 화면으로 시작한다.
- 초기 카테고리와 요리를 자동 선택할지는 미정이다.

카테고리는 다음 순서로 고정한다.

| 순서 | 조리방법 |
|---:|---|
| 1 | 혼합 |
| 2 | 굽기 |
| 3 | 삶기 |
| 4 | 반죽 |
| 5 | 끓이기 |
| 6 | 면 만들기 |
| 7 | 튀기기 |
| 8 | 볶기 |
| 9 | 파스타 만들기 |
| 10 | 잼 만들기 |
| 11 | 파이 만들기 |
| 12 | 찌기 |
| 13 | 피자 만들기 |
| 14 | 발효 |
| 15 | 수비드 |
| 16 | 저미기 |

카테고리가 없는 요리, 알려지지 않은 조리방법을 가진 요리의 표시 위치는 미정이다.

### 3.3 검색 결과

```text
[검색 종류] [검색 조건]
[검색 결과 요리 목록                 ] [요리 상세]
```

- 검색을 실행하면 카테고리 영역을 숨기고, 검색 결과에 해당하는 요리를 바로 선택할 수 있는 목록을 표시한다.
- 결과에서 요리를 선택하면 오른쪽 상세를 갱신한다.
- 검색 결과가 없으면 목록에 '검색 결과 없음'을 표시한다.
- 검색 조건의 변경이나 결과 없음 자체는 표시 중인 오버레이를 변경하지 않는다.
- 검색 해제 시 검색 전 카테고리 및 목록을 복원하는 방향은 합의했다.
- 검색 해제 때 복원하는 요리 선택과 마지막 검색 결과 선택의 관계는 9절에서 추가 결정한다.
- 검색 결과에 조리방법을 함께 표시하는 것은 제안이다.

## 4. 검색과 정렬

| 검색 종류 | 입력 방법 | 실행 시점 | 대상 | 정렬 |
|---|---|---|---|---|
| 능력치 | 2차 선택창에서 능력치 선택. 자유 입력하지 않음 | 능력치 선택 즉시 | 해당 능력치를 포함한 요리 | 선택한 능력치 수치 내림차순 |
| 재료 | 재료명 직접 입력 | Enter 또는 검색 버튼 | 레시피에 해당 재료명이 포함된 요리 | 요리 이름순 |
| 요리명 | 키워드 직접 입력 | Enter 또는 검색 버튼 | 이름에 키워드가 포함된 요리 | 요리 이름순 |

능력치 선택 항목은 봇과 동일하게 생명력, 마나, 스태미나, 체력, 지력, 솜씨, 의지, 행운, 최소대미지, 최대대미지, 마법공격력, 방어, 보호, 마법방어, 마법보호를 참고한다.

### 미정

- 능력치 수치가 같은 경우의 보조 정렬: 이름순 제안.
- 기본 카테고리 탐색의 요리 정렬: 이름순 제안.
- 빈 검색어, 앞뒤 공백, 띄어쓰기 차이 및 검색 종류 전환 시 기존 입력의 처리.
- 검색 결과 갱신 때 자동으로 첫 요리를 선택할지 여부. 자동 선택은 오버레이를 변경할 수 있으므로 명시적으로 결정한다.

## 5. 비율 바와 점선

### 반영 사항

- 원문 값은 상대 비율로 사용한다. 합계가 100이 아니어도 각 값을 합계로 나누어 전체 바를 채운다.
- 재료 순서는 원문 레시피와 동일하게 유지한다.
- 원문 숫자를 전체 바의 퍼센트로 그대로 사용하거나 마지막 재료만 임의로 나머지로 바꾸지 않는다.
- 각 재료 구간을 색으로 구분한다.
- 내부 재료 경계에서 위로 점선을 올려, 게임 농도 조절 버튼의 어느 위치에 해당하는지 직접 확인할 수 있게 한다.
- 오버레이에는 비율 바와 점선만 표시한다. 버튼 이미지, 요리 시작/취소 버튼 또는 전체 상세 패널을 게임 위에 표시하지 않는다.
- 앱 상세의 미리보기와 게임 위 오버레이는 동일한 목표 경계를 나타낸다.

### 계산 예시

| 원문 비율 | 전체 바에 대한 각 구간 | 내부 점선 위치 |
|---|---|---|
| 30:40:30 | 30%, 40%, 30% | 30%, 70% |
| 44:33:33 | 40%, 30%, 30% | 40%, 70% |
| 50:75:15 | 약 35.71%, 53.57%, 10.71% | 약 35.71%, 89.29% |
| 50:20:40 | 약 45.45%, 18.18%, 36.36% | 약 45.45%, 63.64% |

### 제안 및 미정

- 제안: 바와 점선은 반올림 전 비율로 배치하여 표시 숫자의 반올림 때문에 경계가 누적해서 어긋나지 않게 한다.
- 숫자 표시 자릿수, 색상, 바 높이, 점선 높이/굵기/색상 및 양 끝점의 가이드는 미정이다.
- 단일 재료, 두 재료, 0인 재료 비율의 표시 규칙은 미정이다.
- 제안: 양수 값의 합계가 있는 한 단일 재료는 100%, 두 재료는 하나의 내부 경계로 표현한다.
- 합계 0, 음수, 누락 또는 해석할 수 없는 레시피에서는 임의의 비율을 생성하지 않는다. 구체적인 표시와 오버레이 처리 정책은 8절의 제안을 검토한다.

## 6. 오버레이 동작과 수명

### 반영 사항

- 기존 오버레이와 동일한 포그라운드 판정에 따라 표시한다. 이 기능만을 위한 별도 게임 실행/포커스 판정을 정의하지 않는다.
- 다른 앱이 포그라운드가 되어 표시 조건을 벗어나면 숨긴다. 표시 조건으로 돌아오면 사용자가 켜 둔 오버레이를 다시 표시한다.
- 잠금 해제 상태에서 사용자가 위치를 이동하고, 마우스 휠로 크기를 조절할 수 있다.
- 잠그면 클릭이 게임으로 통과한다.
- 표시 중 다른 요리를 선택하면 상세 비율 바와 오버레이 비율을 즉시 갱신한다.
- 위치를 맞춘 뒤에는 현재 앱 실행 중 해당 위치를 유지한다. 게임 요리창 이동에 자동으로 따라가지 않는다.
- 앱 재실행 시 검색과 이전 요리 선택을 복원하지 않고 초기 화면으로 시작한다. 요리 오버레이는 꺼진 상태로 시작한다.
- 오버레이 위치도 재실행 시 초기 위치로 돌아간다. 이전 실행에서 사용자가 이동한 위치를 복원하지 않는다.

### 크기 및 초기 위치 기준

- 사용자가 저장소에 첨부했다고 설명한 실제 요리창 스크린샷을 기본 크기의 기준으로 삼는다.
- 초기 위치는 해당 스크린샷의 게임 비율 바에 최대한 가깝게 정한다.
- 현재 확인한 앱 저장소의 전체 화면 스크린샷 35장에서는 요리창을 찾지 못했다. 봇의 잘라낸 UI 배경만으로 화면상의 위치를 확정하지 않는다.
- 기준 이미지 경로, 기본 바 너비/높이, 초기 좌표 및 기준 화면 해상도/DPI는 미정이다.
- 다른 해상도/DPI 및 멀티모니터에서 기준 위치를 어떻게 적용할지 미정이다. 자동으로 게임 바와 일치한다고 보장하지 않는다.
- 재실행 시 배율도 기본값으로 초기화할지는 미정이다. 위치 초기화와 배율 초기화를 같은 결정으로 간주하지 않는다.

### 기존 크기 조절의 참고 동작

현재 커스텀 오버레이는 잠금 해제 상태에서 휠로 크기를 바꾸고 잠금 상태에서는 휠 조절을 받지 않는다. 기본 배율 복귀용 더블클릭, 배율 범위 및 단계의 요리 오버레이 적용 여부는 미정이다.

## 7. 상태와 전환

탐색 상태, 선택한 요리, 오버레이 사용 상태 및 잠금 상태를 구분한다. 검색 결과가 없다는 사실과 오버레이 표시 조건을 동일한 상태로 취급하지 않는다.

| 발생 조건 | 기대 동작 | 상태 |
|---|---|---|
| 앱 최초 실행/재실행 | 검색 전 초기 화면. 이전 요리 및 검색 복원 없음. 오버레이 꺼짐, 이전 위치 복원 없음 | 반영 |
| 카테고리 선택 | 해당 카테고리 요리 목록 표시 | 반영 |
| 검색 실행 | 검색 결과 구성으로 전환 | 반영 |
| 요리 선택 | 상세 및 표시 중인 오버레이 비율 갱신 | 반영 |
| 검색 결과 없음 | 빈 결과 안내. 검색 결과 없음만으로 기존 오버레이 변경 없음 | 반영 |
| 검색 해제 | 검색 전 카테고리/목록 복원. 상세/선택/오버레이 처리 추가 결정 | 일부 미정 |
| 포그라운드 표시 조건 해제 | 오버레이 숨김 | 반영 |
| 포그라운드 표시 조건 복귀 | 켜 둔 오버레이 다시 표시 | 반영 |
| 잠금 | 게임으로 클릭 통과 | 반영 |
| 잠금 해제 | 수동 이동 및 휠 크기 조절 가능 | 반영 |
| 게임 요리창 이동 | 오버레이 위치 유지. 사용자가 다시 맞춤 | 반영 |
| 앱 정상/비정상 종료 후 재실행 | 이전 요리, 검색, 위치 복원 없음 | 반영 |

오버레이 켜기/끄기 제어, 최초 표시 시 잠금 상태, 같은 실행 중 껐다 켤 때의 위치/배율 유지 및 요리 변경 시 위치/배율 유지 정책은 미정이다.

## 8. 예외, 환경 변화 및 기존 기능과의 관계

### 기존 기능과 공유하는 조건

- 포그라운드 판정, 전체 오버레이 일시정지 및 중복 실행 방지는 기존 앱 동작을 참고한다.
- 새 요리 기능이 기존 트래커, 소리 알림, 파티 조회, 다른 오버레이의 설정이나 표시 상태를 변경하지 않아야 한다.
- 요리 미니게임이 닫혀도 자동 감지로 오버레이를 끄는 요구는 없다. 자동 감지 범위는 후속 검토 대상이다.
- 게임 종료/비정상 종료/재실행에 따른 표시는 기존 포그라운드 조건과 연계한다. 기존 판정과 다른 독립적인 게임 생명주기 동작이 필요하면 추가 합의한다.

### QA에서 확인할 환경

- Alt+Tab 및 빠르게 반복되는 포커스 전환: 숨김/표시와 잠금 상태가 일관되는지 확인한다.
- 창 모드, 테두리 없는 창 모드, 전체화면: 지원하는 환경에서는 바와 점선이 표시되고 게임 조작을 방해하지 않아야 한다. 독점 전체화면의 표시 가능 여부는 검증 전 확정하지 않는다.
- 게임창 이동, 해상도/DPI 변경, 모니터 구성 변경: 수동으로 다시 맞출 수 있는지 확인한다. 화면 밖 위치 복구 정책은 미정이다.
- Windows 잠금/잠금 해제, 절전/복귀: 기존 앱의 표시 조건과 충돌하거나 숨긴 오버레이가 잘못 노출되는지 확인한다. 위치/배율의 복귀 정책은 추가 결정이 필요하다.
- 관리자/일반 권한: 기존 오버레이와 동일한 조건에서 표시 및 클릭 통과가 가능한지 확인한다. 독립적인 권한 상승 요구는 정하지 않는다.

### 오류 처리 제안

아래 내용은 사용자 확인 전 제안이다.

- 레시피 없는 요리: 목록과 확인 가능한 상세 정보는 표시하되 비율 미리보기 및 오버레이 적용은 사용할 수 없게 한다.
- 비율을 계산할 수 없는 요리: 추측한 바를 표시하지 않고 해당 요리의 비율 정보를 사용할 수 없음을 표시한다.
- 사용할 수 없는 레시피로 선택을 바꾸었을 때 기존 오버레이를 숨길지, 이전 요리를 유지하며 구분할지는 미정이다. 새 요리 정보와 이전 비율이 혼동되지 않아야 한다.
- 썸네일 접근 실패: 재료, 능력치, 비율 조회까지 실패시키지 않는다.
- 요리 데이터 없음/손상: 다른 편의기능은 계속 사용할 수 있게 하고 요리 조회 실패를 표시한다.
- 설정 없음/손상/이전 버전: 이전 검색/선택/위치 복원에 의존하지 않는다. 기존 설정 복구 동작과 새 설정 항목의 관계는 개발 시 검토한다.

### 리소스 요구사항

- 데이터만 조회하거나 목표 비율을 표시하는 동안 게임 화면을 지속적으로 감지해야 하는 요구는 없다.
- 검색과 선택, 휠 조절 때문에 앱 조작이 멈추지 않아야 한다.
- 처리 시간, CPU/메모리 수치 및 저사양 기준은 미정이다. 기존 트래커의 탐지 성능 수치를 요리 기능의 합격 기준으로 임의 적용하지 않는다.

## 9. 미결정 사항

| 항목 | 결정할 내용 또는 제안 |
|---|---|
| 기준 스크린샷 | 파일 경로, 바 크기/좌표, 기준 화면 해상도와 DPI. 이미지 확보 전 수치 보류 |
| 초기 탐색 | 최초 선택 카테고리/요리, 또는 미선택 상태 |
| 검색 해제 | 이전 요리 선택 복원과 마지막 직접 선택 유지 사이의 결정. 제안: 카테고리/목록만 복원하고 상세/오버레이는 마지막 직접 선택 유지 |
| 자동 선택 | 검색/카테고리 변경 때 첫 요리 자동 선택 여부 |
| 검색 입력 | 빈 입력, 공백 처리, 검색 종류 전환 시 입력 처리 |
| 결과 개수 | 봇의 최대 20개 제한을 데스크톱에도 적용할지 |
| 정렬 보조 기준 | 능력치 동률과 기본 탐색: 이름순 제안 |
| 데이터 예외 | 레시피 없음, 잘못된 비율, 미분류 요리 처리 |
| 시각 기준 | 각 재료 색상, 숫자 자릿수, 점선 치수, 끝점 가이드, 상세 배치 |
| 오버레이 제어 | 켜기/끄기 형태, 최초 잠금 상태, 껐다 켤 때와 요리 변경 시 위치/배율 유지 |
| 배율 | 기본 배율, 범위/단계, 재실행 초기화, 더블클릭 복귀 여부 |
| 화면 환경 | 초기 위치의 다른 모니터/해상도/DPI 적용, 화면 밖 복구 및 절전 복귀 정책 |
| 데이터 제공 | 배포/갱신 방식, 외부 이미지 실패 시 표시 |

핵심 사용자 동작과 성공/실패 판정에 영향을 주는 미결정 사항은 기획 확정 전에 해결하거나 명시적으로 보류 범위를 정한다.

## 10. Acceptance Criteria 초안

아래 기준은 반영된 방향을 검증 가능한 형태로 정리한 초안이다. 미정 항목을 충족했다고 간주하거나 구현자가 임의로 기준을 채워 넣지 않는다.

| ID | 조건 및 성공 기준 |
|---|---|
| AC-01 | 편의기능에서 요리 화면을 열면 검색 제어와 기본 탐색/상세 영역을 사용할 수 있다. |
| AC-02 | 카테고리는 3.2절의 16개 순서로 표시된다. 혼합을 선택하면 혼합 요리만 해당 목록에 표시된다. |
| AC-03 | 능력치 검색을 선택하면 자유 입력이 아닌 2차 능력치 선택이 가능하다. 마나를 선택하면 마나 항목이 있는 요리만 표시되고 마나 수치 내림차순으로 정렬된다. |
| AC-04 | 재료명을 입력하고 Enter 또는 검색 버튼을 실행하면 해당 재료명이 포함된 요리만 이름순으로 표시된다. |
| AC-05 | 요리명 키워드를 입력하고 Enter 또는 검색 버튼을 실행하면 해당 키워드가 이름에 포함된 요리만 이름순으로 표시된다. |
| AC-06 | 검색 실행 후 카테고리는 숨겨지고 검색 결과에서 요리를 직접 선택할 수 있다. 오른쪽 상세 영역의 위치와 크기는 기본 탐색과 같다. |
| AC-07 | 요리를 선택하면 그 요리의 재료와 원문 비율, 능력치, 환산 비율 미리보기가 서로 일치한다. 레시피 없는 항목은 예외 정책 결정 후 별도로 검증한다. |
| AC-08 | 44:33:33은 40%:30%:30%로 표시되고 내부 점선은 바 시작점에서 전체 너비의 40%, 70%에 위치한다. 허용 픽셀 오차는 화면 치수 결정 후 정의한다. |
| AC-09 | 50:75:15는 약 35.71%:53.57%:10.71%로 전체 바를 채운다. 앞 두 원문 수치를 50%, 75%로 그대로 배치하지 않는다. |
| AC-10 | 오버레이에는 목표 비율 바와 위쪽 점선만 표시되고 게임 버튼 이미지 및 상세 정보 패널은 표시되지 않는다. |
| AC-11 | 오버레이 표시 중 유효한 다른 레시피를 직접 선택하면 화면 전환이나 별도 적용 명령 없이 새 비율로 갱신된다. 연속 선택 후에는 마지막 선택의 상세와 바가 일치한다. |
| AC-12 | 검색 조건 변경 또는 결과 없음만으로 기존 오버레이의 요리가 변경되거나 표시가 해제되지 않는다. 결과 목록은 결과 없음을 나타낸다. |
| AC-13 | 기존 포그라운드 표시 조건을 벗어나면 오버레이가 숨겨지고 조건 복귀 후 켜 둔 오버레이가 다시 표시된다. |
| AC-14 | 잠금 해제 상태에서 드래그 이동과 휠 크기 조절이 가능하다. 잠금 후 해당 영역에서의 클릭은 게임에 전달된다. |
| AC-15 | 게임 요리창을 이동해도 오버레이가 자동 추종하지 않는다. 사용자는 잠금을 풀어 새 위치에 맞출 수 있다. |
| AC-16 | 앱을 종료하고 재실행하면 이전 검색/요리 선택이 복원되지 않고 요리 오버레이는 꺼져 있다. 다시 표시하는 오버레이는 이전에 이동한 위치가 아닌 정의된 초기 위치를 사용한다. 배율의 재실행 정책은 별도 결정한다. |
| AC-17 | 요리 검색/선택/오버레이 조작이 기존 트래커 및 다른 편의기능의 설정과 상태를 임의로 변경하지 않는다. |
| AC-18 | 목록의 포함 대상은 기준 데이터에서 봇의 검색 대상 조건과 일치한다. 데이터 전체 개수나 Discord 메시지 개수만을 목록 범위로 사용하지 않는다. |

## 11. 확정 및 전달

- 사용자가 초안을 검토하고 명시적으로 기획을 확정하기 전에는 구현 착수용 최종 요구사항으로 취급하지 않는다.
- 확정 시 사용자 결정만 반영한 독립적인 최종 명세를 작성한다.
- 최종 명세에서는 검토 과정, 폐기된 아이디어 및 제안과 결정의 혼재를 제거한다.
- 별도 보류 항목이 있으면 구현/QA 범위에서 제외되는 항목과 이유를 명시한다.
