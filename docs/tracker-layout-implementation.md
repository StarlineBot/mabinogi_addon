# 트래커 하단 활용 개발 기록

- 기준: `tracker-layout-spec.md`. 2026-10-16 제품 렌더 확인 후 사용자가
  "괜찮은거 같아 계속 진행"으로 배치를 승인했다.
- 충분한 작업 영역에서 버프/디버프 왼쪽 목록·순서 버튼·안내를 64px 하단 공간까지
  확장한다. 오른쪽 설정에는 같은 높이의 하단 여백을 두어 기존 상단 위치를 유지한다.
  목록 행 높이·아이콘·폰트·추적·알림·설정 로직은 바꾸지 않는다.
- 두 탭에서만 하단 컨테이너를 전체 폭 레이아웃에서 분리하고, 기존 얼굴 자리의
  76×64px 영역으로 제한한다. 왼쪽 확장 영역을 투명 컨테이너가 덮지 않는다.
- 파티/커스텀/메모/환전 및 다른 탭에서는 기존 전체 폭 전용 하단 공간으로 복귀한다.
  설정은 기존 사진만 사용하고 안내/투어 제외 정책은 유지한다. 컨테이너/타이머를
  전환마다 생성하지 않으며 레이아웃 항목의 중복 추가도 피한다.
- 작은 작업 영역에서 오른쪽 설정을 스크롤해야 한다면 얼굴이 그 위에 상시 겹칠 수
  있으므로 기존 전용 하단 공간으로 복귀한다. 현재 높이/글꼴/안내의 필요 높이와
  viewport를 비교하며 모든 환경에 확장을 강제하지 않는다. 큰 영역으로 돌아오면 다시 확장한다.
- 중앙 영역의 resize에서 떠 있는 얼굴 위치를 맞추며, 종료 시 본창·중앙·두 트래커의
  이벤트 필터를 해제한다. 초기 렌더에서 확인한 Qt 객체 파괴 뒤 중앙 위젯 접근 오류도
  함께 수정했다. 같은 탭에서 안내문 길이가 바뀌어도 필요 높이를 재평가한다. 모드가
  실제로 바뀔 때만 재배치하므로 단순 레이아웃 요청은 말풍선을 닫지 않는다.
- 말풍선은 실제 얼굴/말풍선 두 영역만 가려짐 검사에 전달한다. 왼쪽 확장 공간을
  검사 대상으로 넓히지 않으며 표시/닫기/잡담 사용 체크로 목록 크기를 바꾸지 않는다.

## 검증

- 제품 렌더 도구: `QT_QPA_PLATFORM=offscreen uv run python -m scripts.render_creator_dialogue`.
  `/tmp/creator-dialogue-preview/`에 기준/일반 버프, 디버프 off/band/percent, 긴 안내,
  작은 버프/디버프, 파티·커스텀·메모·환전·설정 화면을 저장한다.
- 신규 테스트는 같은 제품 위젯을 이전 전용 하단 배치와 비교한다. 정상 작업 영역에서
  목록 높이 +64px, 같은 행 높이·오른쪽 설정 상단/너비·얼굴 위치를 검사한다.
- 다른 탭/설정 반복 전환 후 선택과 높이/얼굴 위치 보존, 잡담 토글/표시 중 크기 유지,
  작은 화면에서의 전용 공간 복귀와 재확장, 왼쪽 Qt 자식 hit-test도 검사한다.
  offscreen 실제 화면 밖 위치에서는 전역 `widgetAt`을 사용하지 않는다.
- 긴 안내를 동적으로 넣는 회귀 테스트에서 전용 하단 공간으로 전환되지 않는 실패를
  재현한 뒤 트래커의 LayoutRequest 처리로 수정했다. 안내 복구 시 재확장도 검사한다.
- 관련 회귀 `tests/test_tracker_layout.py tests/test_creator_dialogue.py tests/test_setup.py`:
  190개 통과. `QT_SCALE_FACTOR=1.5`에서 신규 배치 테스트 10개 통과.
  이는 Qt 배율 모사이며 Windows 혼합 DPI 실기기 검증은 아니다.
- 최종 전체 회귀: `QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q
  -m 'not windows_integration'` 결과 870개 통과, Windows 통합 4개 제외,
  기존 QMouseEvent 폐기 예정 API 경고 3개. 테스트의 외부 장치 경계와 워커 누수 검사는
  유지했다. 렌더 도구도 정상 종료했으며 `git diff --check` 통과.
- Windows 실제 클릭/휠·포커스·혼합 DPI·작업 영역 전환은 아직 미검증이다. Qt 오프스크린
  결과를 Windows 실제 통합 성공으로 해석하지 않는다. 새 푸시 SHA의 자동 Windows 회귀,
  네이티브 통합과 exe 빌드 확인은 별도 완료 조건이다.
- 이번 개발에서 릴리즈/태그는 실행하지 않는다. 원격 기존 `v0.4.72`를 확인하여 공개
  노트는 다음 `v0.4.73`에만 추가하고 이전 버전 내용은 보존했다.

## 독립 QA 후속 수정

- `c549222`의 [독립 QA](qa/트래커_하단_확장_독립_QA.md)를 확인했다.
  TRACKER-LAYOUT-CI-01은 제품의 고정 화면 높이 정책이 아니라 테스트의 조건 구성 오류다.
  기존 730px 조건에 9px 글꼴을 넣자 같은 `not _floating_footer` assertion에서
  실제로 1개 실패, 13/18px 2개 통과를 재현했다.
- 복귀 테스트는 긴 안내를 넣고 `필요 높이 > viewport + 64`를 먼저 검증한다.
  그 뒤 기존의 전용 공간 복귀, 얼굴과 viewport 분리, 큰 화면 재확장과 목록 높이의
  정확한 복원 assertion을 유지하며 9/13/18px 각각 4회 반복한다.
  QLabel 양쪽 내용의 배치 이벤트를 처리한 뒤 반복 비교 기준을 잡는다.
- 별도 6개 사례로 두 트래커의 9/13/18px 작은 화면을 검사한다. 안전하게 들어가면
  스크롤 없이 오른쪽 설정과 얼굴이 겹치지 않아야 하고, 부족하면 전용 공간이 분리되어야 한다.
  실패 시 실제 필요 높이/viewport/프레임/글꼴/하단 좌표를 출력한다.
- 신규 글꼴 검사에서 18px 디버프의 숨겨진 가로 스크롤 범위는 1px이었다.
  `_scrolled`의 기존 AlwaysOff 정책상 이는 표시되는 가로 스크롤바가 아니다.
  새 검사는 실제 정책과 비표시를 확인하며 기존 테스트의 가로 범위 0 assertion은 유지한다.
- 독립 재현 8개와 수정된 제품 배치 18개는 26개 통과했다. 독립 보고서와 원본 재현은
  변경하지 않았다. 이번 수정은 테스트/개발 기록에 한정하며 제품 소스와 공개 노트는 그대로다.
- 후속 최종 전체 격리 회귀는 **878 passed, 4 deselected, 3 warnings (172.60초)**다.
  일반 배율 집중 검사 **26 passed (14.58초)**, 150% Qt 배율 검사 **26 passed (14.89초)**다.
  제외 4개는 별도 Windows 통합이며 경고 3개는 기존 QMouseEvent API다.
- QA가 기록한 Windows 실패 실행 `38837676444`는 회귀 실패로 네이티브와 exe 빌드를
  실행하지 못했다. 이를 성공으로 재사용하지 않는다. 테스트만 수정한 자동 실행은 exe를
  생략할 수 있으므로 별도의 exe 성공 확인도 남아 있다. 현재 개발 세션 Actions API는
  `Forbidden`이며 새 SHA의 Windows 성공을 확인하기 전까지 검증 대기로 유지한다.

## 가로 범위 후속 QA 반영

- `ed5b5dd`의 후속 QA를 확인했다. TRACKER-LAYOUT-CI-02는 Windows 18px/80줄 안내
  사례에서 내부 가로 범위가 170px이어서 실패했다. 이것만으로 실제 폼 잘림이나 정상
  동작을 단정하지 않는다. 이전 API 제한 때문에 확인하지 못했던 실패 로그는 QA의
  자동 실행 `38839364387`과 수동 실행 `38840035105` 기록을 근거로 삼았다.
- 원본 독립 가로 경계 검사는 수정 없이 실행하여 세 글꼴에서 3개 통과했다.
  Linux에서도 DejaVu Sans 범위 2px, Noto Serif CJK KR 22px이 남았지만 실제 오른쪽
  컨트롤은 viewport 안에 있었다. 범위와 실제 컨트롤 잘림은 별도 검증해야 한다.
- 작은 화면 복귀의 `range == 0`은 오른쪽 폼의 모든 표시 중인 버튼·입력·체크·콤보·
  수치 입력 컨트롤 가로 경계 검사로 교체했다. 정책/스크롤바 숨김만으로 통과시키지 않는다.
  각 컨트롤 좌표와 visibleRegion, inner/viewport 폭, range/value, 글꼴/프레임을
  실패 메시지에 담고 잘림 시 테스트 임시 폴더에 창 PNG도 저장한다.
  기존 복귀/공간 부족/목록 높이 정확한 복원 검사는 유지한다.
- 추가 역검증은 스크롤바가 숨겨진 상태에서 입력창을 강제로 viewport 밖에 두고,
  경계 검사가 실패하며 진단 PNG도 생성되는지 확인한다. 숨겨진 스크롤바로 실제
  잘림을 통과시키는 테스트가 아님을 실행으로 검증한다.
- 테스트 전용 수정 후에도 앞선 제품의 빌드가 미검증으로 남는 공백을 제거했다.
  `windows_ci.needs_build`는 이제 `tests/`, `scripts/`, `pytest.ini`도 대상으로 삼는다.
  자동 Windows 검증이 실행되는 변경은 모두 exe 빌드를 요구한다. 문서만 바뀌면
  기존과 같이 자동 실행하지 않는다. 관련 단위 테스트와 개발 지침도 함께 갱신했다.
- 현재 수정은 테스트·CI 계획·개발 문서에 한정한다. Windows 실제 컨트롤 경계는
  새 SHA의 자동 검증으로 판정해야 한다. 경계 검사가 실패하면 실제 좌표를 기준으로
  제품 배치를 수정해야 하며, Linux 통과로 Windows 위험을 해소했다고 주장하지 않는다.
  릴리즈/태그는 실행하지 않는다.
- 최종 로컬 검증: 전체 격리 회귀 **882 passed, 4 deselected, 3 warnings (175.57초)**.
  배치·CI 계획·두 독립 UI 재현·독립 가로 경계 집중 검사 **50 passed (17.42초)**.
  150% 배율의 배치·두 독립 UI 재현/경계 검사 **30 passed (17.06초)**.
  원본 독립 가로 경계 3개도 별도 실행해 통과했다. 제외와 경고는 기존 Windows 통합
  4개와 QMouseEvent API 경고 3개다. `git diff --check` 통과.
