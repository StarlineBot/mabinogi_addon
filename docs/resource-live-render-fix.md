## 투아림 작은 숫자

58x28 전체를 13px 높이로 축소하던 대신, 원본의 8px 숫자 행을 % 기호로 정렬한다.
작은 숫자 전용 참조는 실제 원본을 보고 지정한 0~9 글리프에서 만들었다.
파일명 `v04`는 값 4를 뜻하는 라벨로 사용하지 않는다.

- 참조 생성: `python -m scripts.build_resource_live_refs`.
  입력 ZIP 식별자를 확인하며 멤버/원본 SHA256/값/픽셀 좌표를 `small_sources.json`에 기록한다.
- 색상·높이·간격·경계·점수·차점과의 차이를 검증한다. 한 픽셀 수평 정렬은 잉크를
  버리지 않는 패딩 안에서만 비교하며 점수 기준을 낮추지 않는다.
- 이 렌더로 인식했지만 숫자가 불확실하면 기존 판독기로 재시도해 그럴듯한 4를 만들지 않는다.
  큰 수동 지정 영역에서 작은 렌더가 없으면 기존 여백 정렬 경로를 사용한다.
- 100%는 기존 계약대로 None이다. 100%/가림/00%가 새 주기 재무장의 근거가 되지 않도록 검사한다.
- 새 모델에 사용하지 않은 원본 14/38/45/49/28%도 사람이 읽은 라벨로 검사했다.
  전체 1242장의 정답을 확인한 것은 아니므로 전체 정확도나 모든 DPI 지원을 주장하지 않는다.

## 도르카 및 공용 자동찾기

새 원본의 장식 모델과 도르카 0의 전체 단어 참조를 추가했다. 기존 17개 참조는 유지한다.
같은 원본에서 추가 확인한 투아림 오른쪽 버튼도 기존 모델 점수가 약 0.927로 거부되어,
새 버튼의 불투명 내부 모델을 추가했다. 게임 배경·도르카 숫자·%는 버튼 판정에 사용하지 않는다.

- 장식·오른쪽 구조의 0.97 기준과 숫자의 기존 점수/차점 기준은 유지한다.
- 새 원본 결과: 도르카 `(534,122,28,23)` -> 0, 투아림 `(560,150,42,16)` -> 0.
  좌표는 3840x2160 입력 프레임 기준이다. 실제 Windows DPI 변환을 검증한 결과는 아니다.
- 오른쪽 버튼 가림, 도르카 숫자 제거, 도르카 복수 위치는 거부한다.
- 새 자산은 진단 ZIP에 명시적으로 들어가며 설치 자산을 로드하지 못하게 한 재현도 검사한다.
  이전 ZIP은 당시 자산만으로 재현하므로 옛 실패를 그대로 재현하는 것이 정상일 수 있다.
- 예전 자산과의 정확한 집합 동등성 테스트는 새 자산의 명시적 추가와 기존 자산의
  픽셀 동일성을 검사하도록 갱신했다. 원본 독립 QA 스크립트는 그대로 보존한다.

## 설정 폭 및 Windows 진단

투아림에서 검증한 경로 라벨을 공용 `CapturePathLabel`로 옮겨 보스·체력바에도 적용한다.
공통 안내 라벨 전체를 바꾸거나 버튼/글꼴을 축소하지 않는다. 원문/툴팁은 유지한다.
기존 투아림 전용 문서의 구현·로그 설명은 당시 수정 기준이며 이 문서가 후속 범위를 설명한다.

새 20px 글꼴 회귀는 긴 한글 경로와 3가지 논리 작업 영역에서 전투 보조 9개 화면을
모두 방문한 뒤 가로 범위 0과 실제 버튼의 viewport 포함 여부를 검사한다.
`NAVIGATION_WIDTH_DIAGNOSTICS` JSON은 표시된 각 화면의 viewport/내용/최소 폭/실제 폰트와
버튼·입력의 위치를 기록한다. 첫 실패만 기록하던 검사를 대체하지 않고 추가한다.
원래 scrollbar 객체와 판정값을 그대로 반환하며 assertion 완화나 실패 skip을 추가하지 않았다.

별도 전후 재현에서 같은 20px 글꼴과 Windows runner 형식의 긴 경로를 사용했다.
보스·체력바 모두 기존 `hint_label` 방식은 최소 폭 816px/viewport 776px/가로 범위 40px,
수정 후 각각 최소 폭 560px·565px/viewport 776px/가로 범위 0이었다(4조건 통과).
이는 Linux의 실제 Qt 실행 결과이며 앞선 Windows 실패와 동일 원인이라고 단정하지 않는다.
두 화면의 실제 렌더와 모든 경로 줄의 폭·전체 높이도 확인했다(2조건 통과).

## 검증 및 한계

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest scripts/qa_new_resource_samples.py -q --tb=short
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest tests/test_resource_live_samples.py tests/test_tuarim_button_background.py tests/test_autofind_mvp.py tests/test_navigation_all_widths.py tests/test_tuarim.py tests/test_dorcha_reader.py tests/test_tuarim_settings_width.py -q --tb=short
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q -m 'not windows_integration'
```

원본 재현 7건과 9화면 폭 검사 3건은 **10 passed (4.03초)**다.
Windows runner 형식의 긴 경로를 추가한 9화면 폭 검사 3건도 **3 passed (2.14초)**다.
새 원본 판독·독립 홀드아웃·tracker 재무장·가림·복수 위치·설치 자산 없는 새 ZIP 재현은
**21 passed (10.65초)**다. 기존 버튼 배경/배율/픽셀 위상 및 자산 회귀를 포함한 별도 실행은
**108 passed (41.08초)**였다. 이 실행들은 겹치므로 고유 총계로 합산하지 않는다.
최종 제품 소스의 전체 격리 회귀는 **1,379 passed, 5 deselected, 3 warnings (391.70초)**다.
5건은 별도 Windows 네이티브 검사이며 경고는 기존 QMouseEvent 사용 경고다.
기존 워커 누수 검사를 유지했고 새 실패 skip은 추가하지 않았다.

신규 원본 판독/새 모델 진단 ZIP 재현은 Linux/OpenCV에서 실행했다.
실제 캡처·오디오·게임·Windows 혼합 DPI·한글 경로의 실제 파일 저장·장시간 실행은 별도 검증이다.
논리 작업 영역 모사나 Linux 테스트로 Windows 실행을 대체하지 않는다.
main 푸시 후 해당 SHA의 Windows 회귀·네이티브·exe 결과가 확인되기 전에는 완료/QA 준비로
보고하지 않는다. API가 Forbidden이면 확인 대기로 명시한다. 릴리즈/태그는 하지 않는다.
