# 프라가라흐 디버프 식별 후속 수정

- 기준: 원격 `cd89a40`의 QA 문서와 원본 크롭 자료. 커밋 이력은 조회하지 않았다.
- 원격 태그 조회에서 `v0.4.73` 태그가 이미 존재함을 확인했다. 기존 0.4.73 노트는 보존하고
  이번 사용자 변경은 미사용 다음 버전 `v0.4.74`에 기록한다. 태그를 생성/이동하지 않는다.
- 트래커 배치의 `1c0c874`는 QA가 정확한 Windows 실행 `38846458828`에서 회귀
  884 passed/1 skipped, 네이티브 4 passed, exe 123,605,918 bytes 및 전체 success를 확인했다.
  배치 실패는 해결됐지만 새 `DEBUFF-NATIVE-QA-01`은 별도 디버프 식별 결함이다.

## 재현과 원인

- 자료 검증 도구 `docs/qa/assets/debuff_native_20261016/rebuild.py --check`를 제품 수정 전에
  실행해 원본 SHA/픽셀/비교 자료 검증 PASS를 확인했다. 이 PASS는 버그 해결이 아니다.
- 원본 16px 프라가라흐 마법/물리 한 종류만 입력했다. 기본 28px 이미지와 후보 16px
  이미지 각각에서 반대 종류까지 숨기는 회귀 테스트가 **4개 모두 실패**했다.
- 기존 컬러 점수도 공통 무늬의 상관성이 높아 두 종류가 독립적으로 임계를 넘었다.
  원본 후보 일괄 교체나 전역 임계 상향으로 해결하지 않는다.

## 수정 범위

- 두 프라가라흐 ID가 모두 엔진 템플릿에 있을 때, 해당 아이콘의 각 위치 후보를 같은
  위치의 상대 템플릿과 비교한다. 상대보다 더 잘 맞는 후보만 식별 증거로 사용한다.
  서로 다른 위치의 최고점끼리 비교하지 않으므로 두 종류가 동시에 있을 수도 있다.
- 같은 크기의 후보끼리만 비교한다. 동일한 사용자 이미지 등으로 구분할 수 없는 동점은
  어느 종류의 확정 증거로도 쓰지 않는다. 상대가 등록되지 않은 단일 템플릿은 기존 동작이다.
  종횡비가 다른 사용자 템플릿까지 식별 문제를 해결했다는 주장은 하지 않는다.
- 이력 임계/0.3초 검출 확인/0.4초 재표시/보스 게이트/사라짐 경고 정책은 유지한다.
  상대 종류로 바뀌면 식별에서 탈락한 이전 종류의 raw 판정이 해제되어 이력 래치가 남지 않는다.
- `best_scores()`는 계속 식별 경쟁 전 원시 상관 점수다. 진단 점수 자체가 확정 상태를
  뜻하지 않는다. 실제 tick 판정에만 위치별 식별 경쟁을 적용한다.
- 원본 캡처를 축소하지 않고, 후보 검색 4회 상한도 유지한다. 상대 비교도 각 후보의
  16px 패치에 한정하며 추가 화면 전체 검색을 하지 않는다. 두 ID는 최대 컬러 비교 16회,
  그 외 ID는 기존 경로다. 장시간 CPU/실게임 FPS는 새로 실측하지 않았다.
- 기본/사용자 이미지·카탈로그·설정과 QA 원본/manifest/metrics는 변경하지 않았다.
  공격력 감소/마기그래프를 기본 배포에 추가하거나 이름 미확정/반투명 자료를 채택하지 않는다.

## 검증과 한계

- `tests/test_debuff_identity.py`: **36 passed (2.09초)**. 두 이미지 라이브러리,
  마법/물리 단독, 여백 포함, off/band/percent, 두 종류 동시 존재, 종류 전환과 빈 입력,
  동일 사용자 이미지, 상대 미등록 및 후보 컬러 비교 횟수 상한을 검사한다.
- manifest의 이름이 확인된 다른 원본 화면에서도 전체 아이콘 줄과 개별 프라가라흐 슬롯을
  실제 엔진에 넣어 양성 유지와 반대 종류 비적용을 검사했다. 자기 원본에서 점수 1.0을
  정확도 개선 근거로 사용하지 않는다.
- 버프·디버프 관련 제품 회귀와 원래 라이브/깜빡임/버프 연장 독립 재현은

  제외는 별도 Windows 네이티브 4개, 경고는 기존 QMouseEvent API 3개다.
  다음 버전 노트 파서 검사도 **7 passed (0.25초)**이며 `git diff --check` 통과.

  과거 결과를 덮어써서 자료 도구의 비교를 억지로 통과시키지 않는다.
- 새 수정 SHA의 Windows 회귀·네이티브·exe 성공과 후속 QA는 별도 조건이다.
  이전 트래커 수정의 Windows 성공으로 이 변경까지 통과했다고 판단하지 않는다.
