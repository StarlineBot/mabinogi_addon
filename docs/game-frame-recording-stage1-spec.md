# 프레임 기록·분석 자료 수집 1단계 개발 전달

- 날짜: 2026-10-21 (한국 시간)
- 상태: 사용자 요청에 따른 후속 개발 요구 정리. 목적·기본 흐름·기록/공유 범위는 이번 대화 기준이며, 화면 배치와 저장 상한 등 세부 수치는 개발 제안·검증으로 정한다. 구현·QA 완료 문서가 아니다.
- 대상: 제작자 전용 알파. [0단계 FPS 계측](game-optimization-alpha-stage0-spec.md)와 [CPU·TCP·RSS 적용/복구](game-optimization-cpu-tcp-rss-alpha-spec.md)를 확장하되 기존 기능과 권한은 유지한다.

## 1. 목적과 현재 상태

사용자가 게임 중 FPS 숫자를 계속 지켜보고 튀는 순간을 기억해 제보하는 방식으로 성능 자료를 모으지 않는다. **기록을 시작하고 평소처럼 게임한 뒤, 기록을 종료해 파일을 전달하면 프레임 지연과 당시 설정을 분석할 수 있어야 한다.** FPS 오버레이는 보조 표시다.

현재 0단계는 PresentMon의 제출 프레임 이벤트를 받아 실시간 FPS를 계산·표시한다. 사용자도 화면 표시를 확인했지만 이것은 세션 기록 저장, 변경 전후 비교 또는 정확도·성능 향상 검증의 완료를 뜻하지 않는다. 현재 보관·내보내기가 없는 것은 0단계에 없던 후속 범위이며, 그 사실만으로 원래 0단계의 새 확정 버그로 분류하지 않는다.

이 문서는 0단계 명세 3·11절의 기록 단계를 구체화한다. 과거 기록까지 이미 수집됐다고 안내하지 않으며, 앞으로 명시적으로 기록을 시작한 구간부터 저장한다.

## 2. 사용자 흐름

1. 기존 제작자 FPS 측정 화면에서 `기록 시작`을 선택한다. 기존 계측을 공유하거나 계측을 준비하되 같은 게임에 수집기·ETW 세션을 중복 생성하지 않는다.
2. 대상과 수집 상태를 확인한 뒤 사용자는 평소처럼 전투·이동한다. FPS를 눈으로 감시하거나 끊김마다 버튼을 누를 필요가 없다.
3. `기록 종료`로 남은 데이터를 마무리하고 세션 요약을 저장한다. 유효 데이터 없음·부분 저장·실패는 정상 완료와 구분한다.
4. 종료한 기록의 요약을 확인하고 `ZIP 저장`으로 해당 세션의 원본 기록·상태·설정·요약을 함께 전달한다. 채팅 파일 첨부로 공유할 수 있으며 Git 업로드를 필수로 요구하지 않는다.
5. 설정 변경 전과 후에 같은 방식으로 별도 기록을 남겨 비교한다. 앱 안의 큰 비교 대시보드 없이도 내보낸 두 세션으로 분석할 수 있어야 한다.

기록 시작은 CPU·TCP·RSS를 자동 적용하거나 원복하지 않는다. 기록 종료 역시 최적화 종료/네트워크 재연결 명령이 아니다. 사용자가 원하지 않는 시스템 변경을 계측 흐름에 끼워 넣지 않는다.

## 3. 기록과 내보내기

다음은 데이터의 필수 의미다. CSV/JSON 파일명과 직렬화 구조는 기존 진단 패턴에 맞춰 정하되 형식 버전을 둔다.

| 구분 | 필요한 내용 |
|---|---|
| 프레임 원본 | 등록 게임의 실행 식별자, 렌더링 대상, 원본 QPC와 주파수, 세션 상대 시각, 원본 프레임 간격 및 사용 지표/단위 |
| 구간·품질 | 시작/종료·중단 이유, 활성/비활성·잠금/복귀·대상 변경, 관측 누락/역전/수집기 오류, 유효·무효 구간과 개수 |
| 설정 근거 | 앱/수집기/형식 버전, CPU 구조, 당시 CPU 배분·TCP·RSS의 요청값과 실제 적용 확인값 또는 미확인/실패 상태, 기록 중 설정 전환 시점 |
| 요약 | 유효 관측 시간·프레임 수, 평균 FPS, 프레임 간격 분포와 최댓값, 지연 발생 시각·지속시간·횟수 및 계산 정의 |
| 공유 ZIP | 선택한 세션의 원본·메타데이터·구간·요약을 포함하고 타인 PC에서 분석할 수 있는 상대 경로 구성 |

- 평균 FPS는 제출 이벤트 수와 유효 시간에 근거해 계산하고 화면 FPS의 단순 평균을 대신 쓰지 않는다. 평균/분위수 등은 원본으로 재계산할 수 있어야 한다.
- P99·1% Low를 제공한다면 정확한 정의와 단위·표본 수·정렬/반올림 방식을 명시한다. 이름만 같은 서로 다른 계산을 섞지 않는다. 긴 프레임을 표시할 기준값도 요약에 남기며 아직 합의하지 않은 임계값을 최적값으로 고정하지 않는다.
- 제출 프레임 지표는 실제 표시 FPS·입력 지연·서버 응답/통신 지연이 아니다. TCP 설정의 효과를 FPS만으로 증명하지 않는다.
- CPU/TCP/RSS 설정의 요청·선택과 실제 적용 성공을 구분한다. 권한/장치 오류로 미적용이면 그대로 기록하고 적용된 프로파일의 측정 결과로 표시하지 않는다. 설정 읽기 실패는 기록 전체를 불필요하게 중단하는 대신 미확인 근거를 남긴다.
- 그래픽·CPU·네트워크 설정이 다른 두 기록을 같은 조건의 A/B 실험으로 자동 판정하지 않는다. 불확실한 환경에서 특정 설정의 성능 향상을 단정하지 않는다.
- 화면 이미지·게임 메모리·패킷·다른 프로세스의 이벤트·전체 개인 설정·토큰·웹훅·사용자 절대 경로는 수집에 필요하지 않다. ZIP에는 필요한 최소 데이터만 포함한다.

## 4. 원본 기록과 표시 버퍼 분리

현재 `optimization/frames.py`의 `FrameStream`은 최근 표시 구간과 stale/경계 처리를 위한 메모리 버퍼다. 해당 스냅샷만 주기적으로 CSV에 저장하거나 FPS 숫자를 몇 초마다 저장하는 것으로 프레임 기록을 구현하지 않는다.

- 게임별 수집 이벤트를 검증하고, 표시를 위해 최근 구간을 자르거나 초기화하기 전에 필요한 원본과 품질 상태를 기록 경로에 전달한다. 잘못된 PID·손상 입력을 정상 프레임으로 저장하지 않는다.
- 긴 프레임과 수집 누락은 구분한다. 표시용 stale·구간 초기화 때문에 실제 긴 프레임 원본이 사라지지 않아야 한다. 해당 간격을 유효 성능 통계에 넣을 수 없다면 원본 근거와 무효 사유를 보존한다.
- Alt+Tab·로딩·잠금·절전·대상 전환·게임 재실행을 경계로 표시한다. 전환 공백을 하나의 정상 프레임으로 이어 계산하지 않는다. 로딩은 무조건 삭제하지 않으며 비교 목적에 따른 포함/제외 근거를 남긴다.
- 이벤트 손실을 보간해 매끄러운 FPS로 만들지 않는다. 원본의 부재·누락·부분 세션을 인식할 수 있어야 한다. PresentMon의 화면 표시 여부를 뜻하는 dropped 필드와 수집기 이벤트 손실도 혼동하지 않는다.
- 전투 보조 일시정지는 기존처럼 FPS 표시만 숨긴다. 기록 중이면 기록 여부를 별도로 명확히 하며 표시 숨김을 기록 종료로 간주하지 않는다.

## 5. 실패·수명·부하

- 수집/쓰기 큐·세션 크기/시간·총 보관량에 상한을 둔다. 구체 수치는 개발에서 실제 부하와 함께 제안하고 명시한다. 한도 도달 시 이유와 부분 저장을 알리고 안전하게 마감하며 이전 기록을 조용히 삭제하거나 덮지 않는다.
- UI/캡처 스레드에서 프레임마다 동기 디스크 쓰기·압축을 하지 않는다. 제한된 큐와 묶음 쓰기를 사용하고 큐 적체·디스크 부족·권한 오류는 데이터 손실/중단으로 기록한다. 메모리로 무한히 밀어 넣지 않는다.
- 앱 정상 종료·제작자 접근 해제·계측 중단은 기록을 안전하게 마감하고 전용 워커를 정리한다. 강제 종료 후 읽을 수 있는 완결된 부분은 복구 가능하게 하고 미완료 상태를 구분한다.
- PID 재사용·게임 재실행·계측 재연결 후 이전 데이터와 새 실행을 하나의 연속 간격으로 합치지 않는다. 파일/세그먼트 정책과 종료 상태를 명시한다.
- 로컬 사용자 데이터의 별도 기록 폴더에 저장한다. 일반 설정 내보내기/가져오기에 대용량 기록을 섞지 않는다. 기록과 ZIP을 자동으로 Git/Actions 아티팩트/Release에 올리지 않는다. 공유는 사용자 선택이다.
- 켜지 않은 기록은 저장하지 않는다. 앱 재실행으로 자동 시작하지 않으며 FPS 표시만 사용하는 기존 동작을 보존한다. FPS 표시·계측·디스크 기록 각각의 추가 부하를 구분해 검증한다.

## 6. 개발·QA 완료 기준

1. 기록을 켜고 일반 플레이한 뒤 숫자를 지켜보거나 수동 제보 시각을 적지 않아도, ZIP에서 프레임 지연 시각과 그때의 설정을 확인할 수 있다.
2. 50/60 FPS 등 알려진 합성 원본과 의도적으로 긴 간격을 넣은 입력으로 원본·요약을 재계산할 수 있다. 원본은 느린 프레임을 숨기지 않으며 누락·무효 구간은 통계와 구분된다.
3. 설정 변경 전후 두 ZIP에 비교 가능한 지표·구간·환경 근거가 있고 다른 조건·자료 부족은 미확인으로 남는다. 자동 최적 설정 추천은 이번 범위가 아니다.
4. 기록 중 FPS 표시 숨김·빠른 시작/종료·Alt+Tab·게임 종료/재실행·접근 해제·앱 종료/강제 종료·쓰기 실패·큐/용량 상한을 검사한다. 중복 수집기·스레드·핸들 누적, UI 정지, 기존 전투 알림/CPU 원복 방해가 없어야 한다.
5. 실제 Windows에서 기록 유무의 CPU/메모리/디스크 부하와 유효성·손실 상태를 확인한다. 합성 테스트·원본 형식 일치만으로 실게임 계측 검증이나 성능 향상을 선언하지 않는다.
6. 기능 화면은 기존 제작자 FPS 화면과 조작 패턴에 통합하는 방향으로 렌더를 공유하고 배치를 확인한다. 새 공개 범위·종합 모니터링·벤치마크 자동화로 확대하지 않는다.

이 단계의 개발·독립 QA·Windows 검증은 아직 수행하지 않았다. 기존 [네트워크 라이브 실패](qa/최적화네트워크_관리자실행실패_QA_20261021.md)는 별도로 수정해야 하며, 기록 기능 추가가 그 결함 해결을 대신하지 않는다.
