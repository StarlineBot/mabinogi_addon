# FPS 구간 요약·수집 모드 1단계

- 갱신: 2026-10-22. 사용자는 매 프레임 파일 기록보다 평균·최대·1% low와 프레임 안정성의 자동 집계를 우선 요청했다.
  기존 문서의 매 프레임 원본/ZIP 필수 계획은 이번 **구간 요약 JSON 중심 범위**로 대체한다.
- 블랙박스 변경과 같은 릴리스가 목표다. 패키징/CI 정책 변경·원격 푸시·배포 승인은 아니다.
- 제작자 전용이며 기존 [0단계](game-optimization-alpha-stage0-spec.md)의 PresentMon 제출 이벤트를 재사용한다.
  GPU/CPU/TCP 최적화 동작 개선은 별도 후속 범위다. 수집 시작/중단이 설정 적용/원복을 호출하지 않는다.
- 개발·독립 QA 결과와 현재 승인 상태는 [status.md](status.md)에 기록한다. 실제 Windows 검증은 별개다.

## 1. 사용자 흐름과 UI

게임 중 숫자를 계속 감시하지 않아도 나중에 구간을 골라 성능 수준과 변동을 확인한다.
기존 FPS 측정 시작으로 메모리 집계를 함께 시작하고, 중단해도 해당 측정의 요약은 앱 안에 남는다.
다음 측정을 명시적으로 시작하면 새 측정 ID로 초기화한다. 자동 재시작·자동 최적화는 하지 않는다.
게임 실행 변경은 같은 측정 안의 별도 구간으로 남긴다.

다른 탭의 수집 모드를 따른다. `stat_bars_tab`, `boss_tab`, `tuarim_tab`은
저장 버튼 → 폴더 열기 → 수집 모드 체크 → 저장 위치·개수의 공통 패턴이다.
`halo_capture_section`도 같은 조작을 별도 줄로 나눠 사용한다. FPS는 기존 FPS 탭 아래에 다음을 추가한다.

- `요약 저장`: 현재 측정의 구간/전환/품질 요약을 JSON으로 저장한다. 자동수집을 켜지 않아도 명시적으로 저장 가능하다.
- `폴더 열기`: 앱 로컬 사용자 데이터의 `frame_summaries` 폴더를 연다.
- `수집 모드(구간 요약 자동 저장)`: 켜면 기존 측정을 공유하거나 시작한다. 중복 수집기를 만들지 않는다.
  켠 이후 완결된 구간마다 요약 파일을 저장한다. 해제 시 해당 구간을 마감하며 FPS 측정/메모리 집계는 계속한다.
- `현재 구간 / 이전 구간 선택`: 평균·최대·1% low·유효 표본·측정 시간·변동·긴 간격·설정 근거를 표시한다.
- 파일은 사용자가 폴더에서 선택해 전달할 수 있다. 업로드/공유는 자동으로 하지 않는다.

수집 모드는 재실행 후 자동으로 켜지지 않는다. 보조 기능의 표시 일시정지는 FPS 오버레이만 숨기며 집계를 중단하지 않는다.
2026-10-22 사용자가 FPS 샘플 렌더를 확인하고 “1(이대로 진행)”로 추가 영역 배치를 승인했다.
동일 배치를 다시 확인하지 않는다. 이 승인은 패키징/워크플로/원격 푸시/배포 승인으로 확대하지 않는다.

## 2. 지표 정의

모든 지표는 선택한 게임 실행·swapchain의 **게임 제출 Present 이벤트** 기준이다.
실제 화면 표시 FPS, 입력 지연, 서버 응답/통신 지연을 측정하지 않는다.
검증된 인접 QPC 차이를 간격(초)으로 사용하며 PresentMon의 간격과 일치하는지 확인한다.
오차는 QPC 2tick 또는 2µs 중 큰 값까지만 허용한다. 경계의 첫 이벤트는 연결할 이전 이벤트가 없어 표본이 아니다.

| 지표 | 정의 |
|---|---|
| 유효 표본 N | 검증된 프레임 간격 수. 원시 이벤트 개수와 구분 |
| 측정 시간 T | 유효 간격 합(초). 비활성/설정 전환 등 제외 구간의 벽시계 시간을 더하지 않음 |
| 평균 FPS | N / T. 오버레이 FPS 숫자의 평균이 아님 |
| 1% low | k=ceil(N/100). 느린 상위 k개 간격의 산술평균의 역수. N≥100부터 표시. P99의 역수와 혼용하지 않음 |
| 최대 FPS | 구간 시작에 고정된 연속 **완전한 1초 창 (시작,끝]**의 제출 이벤트 개수 중 최대. 미완성 마지막 창 제외. 완전한 창이 없으면 자료 부족 |
| 중앙값/최장 간격 | 유효 간격 중앙값/최댓값(ms). 최장/최단 단일 간격의 역수를 최대 FPS로 부르지 않음 |
| 간격 변동계수 | 모집단 표준편차 / 평균 간격 ×100(%). 낮을수록 해당 구간의 간격 변동이 작다는 관측치 |
| 상대적 긴 간격 | 해당 구간 중앙값의 2배를 **초과**한 간격 수·합계 시간·최장 8개 간격의 상대 시각. 연속된 지연 에피소드 수와 다름 |

기존 오버레이는 최근 약 1초 구간의 이벤트수/관측시간으로 갱신된다. 최대값은 같은 제출 이벤트율을
완전한 고정 1초 창에서 센 값이다. 오버레이의 0.25초 초기 값이나 단일 간격 역수를 최대값으로 저장하지 않는다.
1% 꼬리 표본 수·꼬리 평균·측정 시간·완전한 1초 창 수·계산 정의를 JSON에 남긴다.
100표본은 꼬리 최소1개를 위한 표시 조건이며 충분한 통계 신뢰도나 안정성 합격 기준이 아니다.
원본 프레임 전체는 저장하지 않아 모든 분포를 사후 재계산하는 원본 기록 도구는 아니다.

## 3. 성능 수준과 안정성의 분리

평균/최대 FPS는 성능 수준, 1% low/변동계수/긴 간격은 지연·변동을 함께 보는 자료다.
임의 절대 기준으로 정상/최적화 성공을 판정하지 않는다. CPU 제한으로 느려졌지만 일정해진 구간을 개선으로 칭찬하지 않는다.
직전 구간 대비 평균/최대 FPS가 떨어지고 변동계수 또는 긴 간격 비율이 줄면 **성능 하락과 변동 감소의 절충**을 명시한다.
표본 부족·완전한 1초 창 부재·수집 오류/누락으로 종료된 구간은 비교를 보류한다.

다른 대상·설정·게임 장면·측정 길이를 동일 조건 실험으로 간주하지 않는다. UI에는 비교 주의를 항상 표시하고
JSON에는 기록된 대상/설정 근거를 남긴다. 전체 측정의 최대값 하나만 비교하거나 구간별 1% low를 평균해
전체 1% low로 제시하지 않는다. TCP 효과나 특정 코어 수의 최적성을 이 결과만으로 입증하지 않는다.

## 4. 구간과 수집 품질

- PID+프로세스 생성 식별자, swapchain 자동/수동 선택, 복수 대상, Alt+Tab/최소화/잠금·복귀,
  시계/폴링 공백, 측정 재시작, 설정 요청/적용 확인/원복을 구간 경계로 둔다.
- 창 활성 상태는 기존 controller의 250ms 관측 경로다. 정확한 OS 포커스 이벤트 시각을 보장하지 않는다.
  관측된 경계 이전의 대기 이벤트를 새 구간에 넣지 않는다. 실제 Windows에서 경계 오차를 확인해야 한다.
- 역순·누락·손상·다른 PID·늦은 전달은 유효 표본으로 보간하지 않는다. 거부 개수와 최대8개 사례,
  구간 종료 이유를 남긴다. ETW 손실 카운터/수집기 오류는 측정을 중단한다.
- 긴 간격 자체를 stale 오류로 버리지 않는다. 같은 대상에서 QPC 차이와 보고 간격이 일치하는 실제 긴 간격은
  포함한다. 이벤트가 오지 않는 동안은 과거 자료/대기 상태로 표시하며 안정 상태라고 해석하지 않는다.
- 최적화 요청값과 journal의 적용 확인/실패/원복 상태를 구분한다. journal 잠금 중에는 비확정 전환으로
  집계를 쉬며 UI에서 OS 작업을 기다리지 않는다. 해당 변경 이후 새 경계로 재개한다.
- 적용값은 **마지막 journal 확인 근거**이며 매 프레임 OS 설정을 다시 읽은 값이 아니다. 외부 도구의 모든 변경이나
  실제 장면 동등성을 보증하지 않는다. 앱/collector SHA256/QPC 주파수도 기록한다.

## 5. 자원·저장 한도

다음은 v1의 명시적 자원 보호 수치이며 성능 합격/최적화 효과 임계값이 아니다.

- 구간 목표60초(완결 이벤트에서 마감), 최대16,384간격. 한 측정 최대128구간/512전환.
  한도 도달 시 기존 요약을 보존하고 측정을 중단한다. 이전 구간을 조용히 버리지 않는다.
- 요약 표시는 최대 초당1회 계산한다. 각 구간에는 최대8개의 최장 간격만 남긴다.
- 프레임별 디스크 쓰기 없음. 요약 JSON만 worker 큐8개/결과8개로 처리한다.
  파일당512KiB, 폴더512항목/16MiB 상한. 파일/부분 파일을 임의 삭제하거나 기존 클립·다른 자료를 덮어쓰지 않는다.
- 새 고유 파일을 fsync 후 create-only hard link로 완료한다. 지원하지 않는 파일시스템은 저장 실패로 남긴다.
  완료 후 partial 정리만 실패하면 완료 경로와 정리 경고를 함께 보존한다.
- 큐/디스크 한도·쓰기 실패는 수집 모드를 중단하고 메모리 요약을 보존한다. 정상 종료는 접수된 쓰기와
  결과 인수를 기다린다. 강제 종료 직전의 메모리 구간 복원은 보증하지 않는다.
- 측정·수집·요약 저장은 제작자만 시작한다. 접근 해제는 측정을 마감하며 접수된 요약은 보호한다.
- JSON에 화면/다른 프로세스 경로/개인 전체 설정/토큰/웹훅을 넣지 않는다. 일반 설정 가져오기와 분리한다.

## 6. 검증과 공동 배포 조건

합성 원본으로 수학 정의, 1% ceil 경계, 1초 불완전 창, CPU 제한 절충, 게임/설정/누락 경계,
자료 부족, 큐·파일 상한, 완료/정리 오류, 권한 해제·종료를 개발 및 독립 QA로 검사한다.
로컬 CSV 집계 비용/최대 표본 요약 비용/메모리를 측정하되 Windows ETW와 게임 부하 검증으로 대체하지 않는다.
실제 Windows에서는 같은 게임 장면의 기본/측정/수집 모드 간 CPU·메모리·프레임타임과
PresentMon 이벤트 무결성·활성 상태 경계·최적화 전환 근거를 확인한다.

FPS UI 렌더 배치는 승인됐다. 공동 배포 전 Windows PresentMon 검증과 블랙박스 네이티브/패키징 준비가 필요하다.
기존 릴리스 승인 절차를 유지하며 원격 푸시·Actions·태그·Release와 패키징 정책 변경은 별도 승인 전 수행하지 않는다.
