## 재현과 원인

변경 전 독립 재현은 2 failed, 1 passed (11.34초)였다. 정확한 숫자 영역의 7은
기존 판독기로 읽지만, 전체 찾기와 실제 컨트롤러의 저장 좌표 재검증은
`anchor_not_found`로 실패했다. 재시도 대기 시간이나 숫자 템플릿 문제가 아니다.

기존 세 장식 표본으로는 이번 화면의 장식을 승인 기준 0.97 이상으로 찾지 못한다.
숫자 판독 성공만으로 과거 좌표를 신뢰하도록 바꾸지 않고, 이 장식의 원본 표본을 추가했다.

## 수정 범위

- `scripts/build_resource_seven_anchor.py`는 원본 blob 해시와 크기를 검증하고
  `(1229,38,45,57)`을 회색조 PNG로 추출한다. 원본은 변경하지 않는다.
- `resource_anchor`에 `anchor_seven`을 추가한다. 기존 표본·마스크·스케일·0.97 기준은
  그대로다. 내부 글자는 기존 마스크로 제외하고 위치 확인 뒤 현재 숫자를 검증한다.
- 복수 장식 거절, 현재 대상/창 경계, 캡처·재시도 간격, 부하 제한, 설정 저장 정책은 유지한다.
  컨트롤러/숫자 판독기/시간 간격/워커 코드는 바꾸지 않았다.
- 공유 자산으로 투아림에도 전달하고, ZIP에 해당 PNG를 포함해 설치 자산 없이 재현한다.
  기존 진단에 새 표본이 없으면 기존 자산만 사용한다. 기존 표본 파일을 덮어쓰지 않는다.
- 새 자산이 생기므로 자산 목록 assertion에 정확한 이름을 추가했다. 폴백 취소 검사는
  표본 개수에 의존하는 13회 호출 대신 실제 네이티브 폴백의 세 번째 경계에서 취소한다.
  폴백 진입·취소 사유·빈 결과 assertion은 유지하고 정확한 세 번 확인도 추가했다.
- 배포된 v0.4.87 노트는 유지하고 다음 v0.4.88에 사용자용 변경 설명을 추가한다.

## 검증과 제한

새 회귀는 원본 전체·올바른 저장 좌표·7 판독, 정확한 표본 추출/내부 마스크,
복수 장식, 실제 화면에서 장식 제거, 장식은 있지만 숫자 제거, 독립 투아림 영역,
설치 자산 없는 ZIP 재현을 검사한다. 원본 QA 스크립트와 원본 PNG는 유지한다.

실제 Windows 캡처·당시 라이브 저장 좌표·혼합 DPI·장시간 성능·exe는 미검증이다.
일반 푸시 Windows Actions 중단 정책을 유지한다. 새 표본으로 각 검색의 비교 횟수는
증가하므로 Linux 기능 회귀를 Windows CPU/프레임 지연 측정으로 주장하지 않는다.
태그·릴리즈는 진행하지 않으며 후속 독립 QA로 전달한다.
