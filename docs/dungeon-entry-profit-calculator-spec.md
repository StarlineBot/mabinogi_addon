# 던전 입장 비용·누적 순이익 계산기

- 작성일: 2026-10-19
- 상태: 사용자 확인된 계산 기준과 던전 순서, 2026-10-19 승인된 목업 기준의 구현 범위를 기록한다. 초기 논의 기록과 현재 승인 범위를 구분한다.
- 대상: 편의기능 계산기. 앱 구현과 로컬 검증을 진행했으며 실제 외부 시세 조회·실게임 검증은 수행하지 않았다.
- 목적: 유료 입장을 순서대로 구매해 모두 클리어했을 때의 누적 비용 또는 누적 순이익을 비교한다.

## 2026-10-19 화면 승인 및 구현 범위

- 사용자가 실제 앱 탭을 유지한 목업을 확인하고 개발을 승인했다. 편의기능의 기존 세 계산기를 유지하고 `던전 입장 계산기`를 추가한다.
- 왼쪽 던전 목록, 오른쪽 계산표, 최대 이익·최초 적자 안내 배치를 적용한다.
- 초기 표는 목업처럼 1~11차를 표시한다. 실제 게임의 입장 상한은 확정하지 않았으며 안내로 구분한다. 계산 함수는 12차 이후에도 매회 5천만 규칙을 지원한다.
- 최초 구현의 믿음의 균열은 새로고침 수동 조회였다. 2026-10-20 후속 사용자 요청으로 **선택 시 자동 조회·10분 세션 메모리 캐시 재사용**으로 변경한다. 주기 자동 조회·가격 영구 저장은 추가하지 않는다. 조회 중·실패·매물 없음·키 없음에는 소모량을 유지하고 가격/비용은 미확인으로 구분한다. 아래 7절의 최신 범위를 우선한다.
- 초기 선택은 크롬바스 심연이다. 던전 선택과 조회 가격은 저장하지 않는다.
- 아래 4~5절은 승인 전 논의 기록이다. 현재 적용 범위는 이 절과 개발 검증 문서를 따른다. 실제 API·Windows 검증은 아직 수행하지 않았다.

1. 크롬바스 심연
2. 브리레흐
3. 믿음의 균열
4. 탈라가흐

| 던전 | 입장 비용 기준 | 매회 클리어 골드 | 계산 결과 |
|---|---|---:|---|
| 크롬바스 심연 | 차수별 통행증 구매가 | 500,000 | 누적 수표 보상에서 누적 구매 비용을 뺀 금액 |
| 브리레흐 | 차수별 통행증 구매가 | 1,300,000 | 동일 |
| 믿음의 균열 | 균열의 편린 최저 개당가 × 소모 개수 | 계산하지 않음 | 차수별·누적 입장 비용만 표시 |
| 탈라가흐 | 차수별 통행증 구매가 | 1,700,000 | 누적 수표 보상에서 누적 구매 비용을 뺀 금액 |

- 무료입장, 보유 통행증, 기타 드랍, 소모품 비용은 계산에서 제외한다.
- 계산은 유료 구매 1회차부터 시작한다. 수표 보상은 해당 차수까지 매번 클리어한 경우의 금액이다.
- 클리어 골드는 사용자가 제시한 고정 금액을 그대로 사용한다. 파티 인원으로 나누거나 경매장 판매 수수료를 차감하지 않는다.
- 실제 입장 횟수나 클리어 여부를 게임에서 추적하는 기능은 이 요구 범위에 포함하지 않는다.

## 2. 통행증 구매 던전의 계산

크롬바스 심연·브리레흐·탈라가흐에 같은 가격표를 적용한다. 다음 가격은 누적 가격이 아니라 해당 구매 회차 한 장의 가격이다.

| 구매 차수 | 해당 차수 통행증 가격(골드) |
|---|---:|
| 1 | 100,000 |
| 2 | 200,000 |
| 3 | 400,000 |
| 4 | 700,000 |
| 5 | 1,000,000 |
| 6 | 2,000,000 |
| 7 | 3,000,000 |
| 8 | 5,000,000 |
| 9 | 7,000,000 |
| 10 | 10,000,000 |
| 11 이상 | 매회 50,000,000 |

`n`차까지의 누적 구매 비용을 `C(n)`, 매회 클리어 골드를 `R`이라 한다.

```text
C(n) = 1차부터 n차까지의 통행증 구매가 합계
누적 수표 보상 = n × R
누적 순이익 = n × R − C(n)
```

- 표의 열 순서는 `차수 | 통행증 구매가 | 누적 순이익`이다.
- 요청에서 말한 누적수익은 구매 비용을 차감한 금액이다. 수표 총액과 혼동하지 않도록 이 문서에서는 누적 순이익으로 구별한다.
- 손실이 나면 음수 그대로 계산한다. 0으로 보정하거나 손실 행을 계산에서 제외하지 않는다.
- 브리레흐 2차는 구매 비용 30만, 보상 260만, 누적 순이익 230만이다. 두 번째 차수의 20만만 비용으로 빼면 안 된다.

### 2.1 계산 검증표

단위는 만 골드다. 아래 11차까지의 표는 계산 검증용이며 앱에서 11차까지만 표시한다는 결정이 아니다.

| 차수 | 구매가 | 누적 구매 비용 | 크롬바스 심연 누적 순이익 | 브리레흐 누적 순이익 | 탈라가흐 누적 순이익 |
|---|---:|---:|---:|---:|---:|
| 1 | 10 | 10 | 40 | 120 | 160 |
| 2 | 20 | 30 | 70 | 230 | 310 |
| 3 | 40 | 70 | 80 | 320 | 440 |
| 4 | 70 | 140 | 60 | 380 | 540 |
| 5 | 100 | 240 | 10 | 410 | 610 |
| 6 | 200 | 440 | -140 | 340 | 580 |
| 7 | 300 | 740 | -390 | 170 | 450 |
| 8 | 500 | 1,240 | -840 | -200 | 120 |
| 9 | 700 | 1,940 | -1,490 | -770 | -410 |
| 10 | 1,000 | 2,940 | -2,440 | -1,640 | -1,240 |
| 11 | 5,000 | 7,940 | -7,390 | -6,510 | -6,070 |

12차 누적 구매 비용은 129,400,000골드다. 11차부터 매회 5,000만 골드라는 규칙을 적용한 계산이며, 실제 입장 상한을 의미하지 않는다.

### 2.2 계산으로 확인되는 이익 구간

| 던전 | 누적 순이익 최대 | 누적 적자 시작 |
|---|---|---|
| 크롬바스 심연 | 3차, 80만 골드 | 6차, -140만 골드 |
| 브리레흐 | 5차, 410만 골드 | 8차, -200만 골드 |
| 탈라가흐 | 5차, 610만 골드 | 9차, -410만 골드 |

- 최대 누적 순이익과 누적 적자 시작은 서로 다르다. 최대점을 지난 다음 회차를 돌아도 이전 이익 때문에 누적 금액은 양수일 수 있다.
- 위 값은 합의된 가격·보상에서 도출되는 계산 결과다. 별도 강조 표시 방식은 4절의 제안 사항이다.

## 3. 믿음의 균열 계산

- 입장 재료는 `균열의 편린`이다.
- 경매장의 최저 개당가를 기준으로 한다. 묶음 총액을 개당가로 취급하지 않는다.
- 차수별 소모량은 `1 → 1 → 2 → 3 → 4 → 5…`다.
- `n`차 소모량은 `max(1, n−1)`개, 누적 소모량은 `1 + n(n−1)/2`개다. 실제 입장 가능한 최대 차수는 아직 확인되지 않았다.

최저 개당가를 `P`라 할 때:

```text
해당 차수 비용 = P × 해당 차수 소모량
누적 비용 = P × 누적 소모량
```

| 차수 | 해당 차수 소모량 | 누적 소모량 | 누적 비용 |
|---|---:|---:|---:|
| 1 | 1 | 1 | P |
| 2 | 1 | 2 | 2P |
| 3 | 2 | 4 | 4P |
| 4 | 3 | 7 | 7P |
| 5 | 4 | 11 | 11P |
| 6 | 5 | 16 | 16P |

- 클리어 골드나 기타 보상을 넣지 않는다. 비용을 순이익처럼 표시하지 않는다.
- 같은 표의 모든 행은 같은 조회 기준 가격 `P`로 계산해야 한다. 행마다 다른 시점의 가격을 섞지 않는다.

## 4. 화면·조회 동작 제안: 확인 필요

이 절은 사용자가 아직 명시적으로 확정하지 않은 화면·세부 동작 제안이다. 합의된 계산식과 혼동해 확정 요구사항으로 취급하지 않는다.

- 기존 환전비율 계산기와 유사하게 왼쪽 던전 선택, 오른쪽 해당 던전 계산표를 배치한다.
- 믿음의 균열은 최저 개당가·조회 시각·새로고침을 제공한다. 기존 앱의 경매장 조회 흐름과 시세 지연 안내를 따르는 방향을 제안한다.
- 믿음의 균열의 표는 `차수 | 소모 개수 | 해당 차수 비용 | 누적 비용`을 제안한다.
- 나머지 세 던전은 고정 가격표만으로 계산하며 외부 시세 조회나 API 키가 없어도 결과를 볼 수 있는 방향을 제안한다.
- 최대 누적 순이익 차수와 최초 누적 적자 차수를 서로 다른 의미로 강조한다. 최대 순이익을 지났다는 이유만으로 해당 행을 적자로 표시하지 않는다.
- 다른 던전으로 바꿨을 때 이전 던전의 결과나 늦게 도착한 시세 응답을 현재 던전 결과처럼 표시하지 않는다.
- 시세 조회 중, 매물 없음, 조회 실패, API 키 미설정을 성공한 가격과 구별한다. 가격을 모르면 0골드로 계산하지 않는 방향을 제안한다.
- 가격을 받지 못해도 소모량 정보는 볼 수 있게 하고, 과거 시세를 남길 경우에는 과거 조회값임을 명시한다. 과거값 유지 여부는 구현 전 화면 확인에서 결정한다.
- 조회는 앱 화면을 멈추지 않게 하고, 다른 고정 보상 던전으로 이동하는 데 방해되지 않게 한다. 자동 주기 조회는 현재 요청에 포함하지 않는다.
- 기존 트래커·오버레이·계산기 설정과 동작을 변경하지 않는다. 저장 범위나 최초 선택 던전은 아직 정하지 않았다.

## 5. 아직 결정되지 않은 사항

1. 믿음의 균열의 실제 최대 차수, 각 던전 표의 표시 범위. 11차 이후를 안내 한 줄로 끝낼지 추가 행을 계산할지 미정이다. 화면 표시 범위를 게임의 입장 제한으로 간주하지 않는다.
2. 4절의 배치·조회·강조 방식 승인. 특히 늦은 응답·조회 실패 시 화면은 실제 목업에서 확인한다.

계산 기준 자체를 다시 논의할 필요는 없다. 위 항목 확인 전에는 전체 기획 확정 또는 UI 개발 준비 완료로 표시하지 않는다.

## 6. Acceptance Criteria: 합의된 계산 기준

1. 던전 목록이 크롬바스 심연, 브리레흐, 믿음의 균열, 탈라가흐 순서로 표시된다.
2. 세 통행증 구매 던전의 각 차수 구매가는 2절 가격표와 일치하고, 마지막 열은 해당 차수까지의 구매 비용 전부를 차감한 결과다.
3. 브리레흐 1차와 2차 누적 순이익은 각각 1,200,000골드와 2,300,000골드다.
4. 크롬바스 심연은 3차 800,000골드, 6차 -1,400,000골드이며, 브리레흐는 5차 4,100,000골드, 8차 -2,000,000골드다.
5. 탈라가흐는 5차 6,100,000골드, 8차 1,200,000골드, 9차 -4,100,000골드다.
6. 11차 이후를 계산하는 경우에도 통행증 한 장당 50,000,000골드를 계속 더한다. 12차 누적 구매 비용은 129,400,000골드다.
7. 편린 개당가 10,000골드를 사용하면 믿음의 균열 1~6차 누적 비용은 10,000 / 20,000 / 40,000 / 70,000 / 110,000 / 160,000골드다.
8. 편린 개당가가 바뀌면 같은 계산표의 각 행은 새 가격을 일관되게 적용한 비용으로 계산된다. 믿음의 균열에 클리어 보상이나 순이익을 임의로 추가하지 않는다.
9. 모든 던전에서 무료입장·보유 통행증·기타 드랍·소모품 비용을 임의로 가감하지 않는다. 손실 금액은 음수로 보존한다.

UI와 오류 흐름의 최종 Acceptance Criteria는 4~5절 확인 후 추가한다. 계산 예시는 순수 산술 검산 결과이며 실제 API 조회나 앱 구현 검증 결과가 아니다.

## 7. 2026-10-20 후속 확정: 균열 선택 시 시세 자동 조회

- 믿음의 균열을 선택하면 새로고침 없이 기존 API로 비동기 시세 조회를 시작한다. 유효한 10분 세션 메모리 캐시는 즉시 표시한다. 기존 새로고침은 명시적 강제 조회로 유지한다.
- 다른 고정 가격 던전과 최초 선택은 그대로다. 앱 시작 선조회·주기 조회·가격 영구 저장은 추가하지 않는다.
- 중복 요청 차단·캐시 만료·키 없음·오류/매물 없음·늦은 응답·종료와 기존 산술 회귀 기준은 [통합 개발 전달문](qa/배포시간단축_균열시세자동조회_화면헤더통일_개발전달_20261020.md)의 5~6절을 따른다.
- 이는 수동 전용 조회 조건의 최신 변경이다. 기존 코드가 이미 이 동작을 제공한다거나 새 동작의 QA가 끝났다는 뜻은 아니다.

선택 자동 조회·10분 캐시·강제 새로고침·오류/종료 경계는 후속 소스에 구현했다. [개발 검증](qa/후속요구_개발검증_20261020.md#시세-조회의-상태-경계)을 참조한다. 실제 외부 API/Windows 실행 또는 독립 QA 통과를 대신하지 않는다.

## 8. 계산기 상단 표시 통일 (2026-10-20 후속 요청)

- 사용자가 제공한 v0.9.0 두 화면을 기준으로 던전 입장 계산기 우측 상단의 `단위: 골드` 문구를 제거한다. 다른 고정 가격 던전에서도 같은 헤더를 사용한다. 표의 금액·개수·콤마·계산식·가격 안내는 변경하지 않는다.
- 환전비율·던전 입장 계산기의 새로고침은 같은 아이콘만 있는 버튼으로 통일한다. 같은 아이콘 자산/표준 도구·크기·스타일·상단 우측 정렬을 사용하고 환전 쪽의 버튼 내 '새로고침' 글자만 없앤다. 툴팁과 접근 가능한 이름은 유지한다.
- 새로고침의 강제 조회·진행 중 정책, 선택 자동 조회·10분 캐시·API 지연/오류/매물 없음 안내와 고정 던전에서의 버튼 숨김은 보존한다. 단위 제거를 이유로 환전 쪽에 새 단위 라벨을 추가하거나 본문 금액 표기를 일괄 변경하지 않는다.
- 도움말 유무에 따른 기능 제목 행 높이·기준선 차이도 공통 헤더에서 확인한다. 글꼴/스타일을 강제로 재설정하는 진단 렌더만으로 첫 표시의 일관성을 통과 처리하지 않는다.
- 이 절은 개발 전달용 후속 요구이며 아직 제품에 반영한 결과가 아니다. 상세 관측·재현·검증 기준은 [통합 QA의 상단 UI 후속](qa/헤일로개발과_잡담로그_통합QA_20261020.md#계산기-버튼단위와-기능-제목-후속-요청)을 따른다. 작은 UI 수정은 다음 필요한 수정과 모아 배포하며 문서만으로 버전/Windows workflow를 실행하지 않는다.

8절의 단위/새로고침 통일과 공통 제목 행 보완은 소스에 반영했고 실제 첫 표시 렌더 공유 후 사용자 “이 배치 유지”로 승인받았다. [개발 검증과 범위](qa/잡담소리_포그라운드_상단UI_개발_20261021.md)를 참조한다. Windows 실제 glyph/합성이나 후속 독립 QA 완료를 대신하지 않는다.
