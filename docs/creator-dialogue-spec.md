# 제작자 얼굴 및 랜덤 말풍선 기능 명세

- 상태: 2026-10-21 사용자 후속 승인 반영. 확인된 가림은 차단하고, 불확실 합성의 표시 시도는 15절·소리 허가는 앱 본창 포그라운드를 조합하는 16절을 따른다. 16절은 개발 전달이며 아직 구현/QA 완료가 아니다.
- 확정일: 2026-10-15. 최신 표시 기준은 3~6절 및 15절, 최신 소리 허가 기준은 이에 우선하는 16절(2026-10-21)이다. 이전 정책/검증 기록과 현재 요구를 구분한다.
- 대상: 앱 본창의 제작자 얼굴, 자동/클릭 대사, 공개 GitHub 대사 갱신.
- 이 문서는 개발과 독립 QA에 전달하는 요구사항이다. 구현 또는 Windows 검증 완료를 뜻하지 않는다.
- GitHub 등록 절차와 개발 전달문: [대사 등록 안내](creator-dialogue-publishing.md).
- 초기 대사 데이터: [dialogues.json](examples/creator-dialogues/dialogues.json). 이 JSON 형식과 12개 샘플 항목으로 시작하고 이후 문구를 보충한다.

## 1. 목적

실용적인 게임 보조 앱에 제작자의 개성을 더한다. 앱을 볼 때 제작자가 가끔 혼잣말하거나,
사용자가 얼굴을 눌러 짧은 대사를 볼 수 있게 한다. 실시간 대화 상대나 기능 안내 도우미가 아니다.

대사는 뜬금없는 생각, 게임/개발 관련 농담 등으로 구성한다. 앱의 실제 오류·경고·판독 결과와
혼동되는 상태 알림으로 사용하지 않는다. 대사와 조합 재료를 추가하면 앱 재배포 없이 내용을
보충할 수 있어야 한다.

## 2. 표시 위치 및 범위

| 화면 | 얼굴 및 말풍선 |
|---|---|
| 트래커의 버프/디버프/투아림/보스 패턴 알림 | 공통 하단 공간의 오른쪽에 얼굴 표시 |
| 파티 모집 | 동일 |
| 전투 보조의 커스텀 오버레이/단축바/체력바/도르카/메모 및 편의기능의 각 계산기 | 동일. 기존 베타 접근 조건은 유지 |
| 설정 | 기존 제작자 사진을 대사 진입점으로 사용. 하단 얼굴을 중복 표시하지 않음 |
| 첫 사용 안내, 사용 준비/자동설정, 하이라이트 투어, 영역 지정/후보 승인 | 잡담 표시 대상에서 제외 |
| 게임 위 오버레이, 트레이, 별도 토스트 | 제작자 얼굴이나 잡담을 추가하지 않음 |

- 본창의 세로 크기를 늘려 얼굴용 공통 하단 공간을 확보한다. 기존 탭 콘텐츠 높이를 줄여
  얼굴을 끼워 넣거나 버튼·입력창 위에 얼굴을 상시 겹치지 않는다.
- 버프·디버프는 얼굴이 있는 오른쪽 아래 공간을 유지하면서 왼쪽 목록 패널만 추가 하단까지
  확장한다. 다른 탭의 공통 하단 공간은 유지한다. 세부 기준은 [트래커 화면 정리](tracker-layout-spec.md)를 따른다.
- 하단은 대사가 항상 흐르는 전광판이나 큰 제작자 소개 바가 아니다. 평상시에는 작은 얼굴만 보인다.
- 말풍선은 얼굴에 연결되어 기존 콘텐츠 위로 잠시 펼쳐진다. 일부 설정·목록을 가리는 것은
  허용된 연출이며, 모든 화면에 말풍선 크기의 빈자리를 따로 확보하지 않는다.
- 설정에서는 기존 사진을 기준으로 표시한다. 사진이 스크롤 밖에 있으면 그 사진을 기준으로
  자동 대사를 표시하지 않는다.
- 얼굴 크기, 추가 높이, 말풍선 폭과 세부 배치는 렌더로 확인한다. 기존 목업의 수치는 확정값이 아니다.
- 테마·DPI·작업 영역 변화에서도 얼굴·대사가 잘리거나 핵심 화면 접근이 불가능해지지 않아야 한다.

## 3. 자동 대사의 노출 가능 조건

다음 조건을 모두 만족할 때만 자동 대사를 표시한다.

1. 본창이 표시 중이며 최소화/트레이 숨김 상태가 아니다.
2. 현재 화면이 2절의 표시 대상이다.
3. 현재 얼굴과 표시 예정 말풍선 영역이 앱 및 모니터 영역 안에 있으며 확인된 불투명 가림이 없다. 불확실한 합성은 15절에 따라 무음 표시를 시도한다.
4. 표시할 유효한 대사가 있다.
5. 설정의 잡담 사용 옵션이 켜져 있다.

- 키보드 포커스나 Windows 포그라운드 여부만으로 제한하지 않는다.
- 듀얼모니터에서 한쪽으로 게임을 조작하고 다른 쪽에 앱을 띄운 경우에도 위 조건을
  만족하면 자동 대사를 표시할 수 있다.
- 얼굴·표시 예정 말풍선이 가려졌으면 클릭·자동 모두 표시·소리를 차단한다. 앱의 다른 부분만 가려진 경우는 제외하지 않는다. 다른 창 위로 말풍선을 올리거나 별도 최상위 창을 만들지 않는다.
- 이 요구는 앱을 강제로 항상 위로 올리거나 게임에서 포커스를 가져오라는 뜻이 아니다.
- 비활성과 실제 가림을 구별하며, 투명 합성 창을 불투명 덮개로 오판해 미표시를 되살리지 않는다. 이름/클래스 예외 목록이나 기능 전체의 포그라운드 전용 제한으로 해결하지 않는다. 불확실한 판정을 실제 노출 확인으로 단정하지 않는다. 불확실한 합성의 표시/추첨은 15절, 본창 포그라운드를 조합하는 소리 허가는 16절을 따른다.
- 최소화·숨김·잠금·절전·화면 밖 또는 해당 확인 API 실패에서는 클릭·자동 모두 표시하지 않는다. 오류를 기존 트래커·설정으로 전파하지 않는다.

## 4. 추첨 시점

- 앱 실행 후 처음으로 노출 가능한 상태가 되면 한 번 바로 추첨한다. 무조건 대사를 표시하는 것이 아니라 40% 확률로 추첨한다.
- 앱 재실행 시 마지막 추첨 시각과 최근 자동 표시 횟수 기록을 초기화한다. 이전 실행에서 놓친 추첨을 이어서 실행하지 않는다.
- 노출 가능한 상태에서 마지막 자동 추첨으로부터 2분 이상 지났을 때 다음 추첨을 수행한다.
- 추첨에 실패해 대사가 나오지 않아도 추첨 시각을 갱신한다. 실패 직후 다시 추첨하지 않는다.
- 노출 불가에서 가능으로 바뀌면, 마지막 추첨으로부터 2분 이상 지났을 경우 한 번 바로 추첨한다.
- 마지막 추첨 이후 2분 이내에는 포커스·탭·창의 가림 상태를 반복해서 바꿔도 추가 추첨하지 않는다.
- 최소화·숨김·잠금·다른 창 가림 등 노출 불가 상태에서는 추첨하지 않는다. 표시 전 차단은 자동 표시 횟수에 넣지 않으며 예약·누적 재생도 하지 않는다.
- 오래 숨겨졌다가 돌아와도 놓친 주기를 몰아서 실행하지 않고, 조건에 맞으면 한 번만 추첨한다.
- 실제 표시 직전에 노출 조건을 다시 확인해 표시 대상이 사라진 곳에 대사를 띄우지 않는다.
- 말풍선이 이미 표시 중이면 자동 추첨을 생략한다. 자동 요청으로 현재 대사를 교체하거나 다음 대사를 예약하지 않는다.

## 5. 확률과 최근 표시 횟수

| 추첨 시점의 최근 10분간 자동 대사 표시 횟수 | 이번 추첨의 등장 확률 |
|---|---|
| 0~2회 | 40% |
| 3회 이상 | 20% |

- 최근 10분은 고정 구간이 아닌 추첨 시각 기준의 이동 구간이다.
- 현재 시각을 t라고 할 때 t-10분보다 이후에 실제 표시된 자동 대사를 센다. 정확히 10분 전
  기록은 제외한다. 이번 추첨으로 표시할 대사는 이번 확률 계산에 미리 포함하지 않는다.
- 확률은 현재 횟수로 매 추첨마다 결정한다. 오래된 기록이 구간 밖으로 나가 3회 미만이 되면 40%로 돌아온다.
- 3회는 횟수 상한이 아니다. 3회 이후에도 20%로 추가 대사가 나올 수 있다.
- 노출 조건을 통과해 실제 표시한 자동 대사만 집계한다. 추첨 실패·가림 등 표시 전 조건 탈락·클릭 요청 대사는 집계하지 않는다. 표시 후 가려지면 기존 기록은 유지한다.
- 실제 표시 후 사용자가 바로 닫아도 표시된 자동 대사 1회로 센다.

## 6. 얼굴 클릭 및 말풍선 수명

- 표시 대상 화면의 얼굴을 누르면 자동 추첨 확률·2분 간격과 관계없이 대사를 요청할 수 있다.
- 클릭 대사는 자동 대사 빈도 감소를 위한 최근 10분 집계에 포함하지 않는다.
- 말풍선은 표시 후 3초간 유지하고 자동으로 닫힌다.
- 표시 중 얼굴을 다시 누르면 새 대사로 교체하고 그 시점부터 3초를 다시 계산한다. 여러 말풍선을 쌓지 않는다.
- 사용자가 말풍선을 누르면 즉시 닫힌다. 이 클릭으로 뒤에 가려진 버튼·입력창이 동시에
  눌리거나 선택되어서는 안 된다.
- 잡담 때문에 앱이나 게임의 포커스를 강제로 전환하지 않는다.
- 입력·드래그·편집 여부를 감지해 자동 발화를 억제하는 조건은 추가하지 않는다.
- 말풍선을 읽는 동안에도 기존 앱 기능은 계속 동작한다. 화면 전환 시 제외 화면으로 잡담을 가져가지 않는다.
- 대사는 3초에 읽기 좋은 짧은 1~2줄 중심으로 작성한다. 긴 내용은 글자를 계속 줄이거나
  스크롤해야만 읽을 수 있는 말풍선으로 내보내지 않는다.
- 최소화·잠금·절전·다른 창 가림으로 노출이 중단되면 현재 말풍선과 전용 소리를 중단한다. 복귀 시 이전 대사나 남은 표시 시간을 복원하지 않는다.
- 복귀 후 자동 대사의 기회는 4절의 일반 추첨 조건을 따른다. 잠금·절전 중의 추첨을 몰아서 실행하지 않는다.
- 설정에 잡담 사용 옵션을 제공하며 기본값은 켜짐이다. 꺼 둔 동안 자동/클릭 대사를 표시하지 않고 현재 말풍선도 닫는다.

### 대사 선택과 직전 문장 반복 방지

- 자동 대사와 클릭 대사는 같은 초기 JSON 목록을 사용한다.
- 실제 완성된 문장이 직전에 표시한 문장과 같으면 연속 표시하지 않는다. 문장 틀이 같아도 완성 문장이 다르면 표시할 수 있다.
- 직전 문장 비교는 탭별로 나누지 않고 이 기능 전체에서 공유한다.
- 다른 유효 문장을 만들 수 없으면 반복 대사를 강제로 내보내거나 무한히 재시도하지 않고 이번 표시를 생략한다.

## 7. 상태 및 정상 흐름

| 상태 | 의미와 기대 동작 |
|---|---|
| 표시 대상 아님 | 설정 전용 안내·영역 지정 등. 제작자 잡담 없음 |
| 잡담 사용 꺼짐 | 자동/클릭 대사 없음. 기존 앱 기능은 유지 |
| 대상 화면이지만 노출 불가 | 최소화, 숨김, 잠금, 화면 밖, 얼굴/말풍선의 가림 또는 판정 불확실. 자동 추첨/표시·소리 없음 |
| 노출 가능·간격 대기 | 얼굴을 표시하고 다음 자동 추첨 가능 시각을 기다림 |
| 노출 가능·추첨 가능 | 최근 자동 표시 횟수로 40%/20%를 정해 한 번 추첨 |
| 말풍선 표시 | 짧은 대사를 표시하고 3초 만료 또는 클릭으로 닫음 |
| 외부 목록 갱신 중 | 현재 유효 대사로 이용 가능. 네트워크를 기다리며 UI를 막지 않음 |

정상적인 자동 흐름은 노출 가능 판단 → 간격 확인 → 횟수 확인 → 추첨 → 유효 대사 선택/조합
→ 노출 조건 확인 → 말풍선 표시 → 자동 표시 횟수 기록 → 3초 만료 또는 클릭 닫기이다.
추첨에 실패하면 말풍선 없이 다음 간격을 기다린다.

## 8. 대사 공급과 GitHub 갱신

- 기존 공개 릴리즈 저장소 `StarlineBot/mabinogi_addon-releases`의 `main` 브랜치에
  `data/dialogues.json`을 두고 읽는다. 전체 대사가 공개되어도 된다. 별도 대사 저장소는 만들지 않는다.
- 릴리즈 첨부파일이나 개별 태그가 아닌 갱신 가능한 브랜치의 Raw 파일을 이용한다.
  대사만 추가할 때는 앱 릴리즈·태그 생성이 필요하지 않다. 배포 자동화는 이 파일을 보존한다.
- 앱 소스 저장소까지 공개할 필요는 없다. 배포 앱에 GitHub 비공개 접근 토큰을 넣지 않는다.
- 작성자가 대사 파일을 수정하면 앱 재배포 없이 후속 수신에서 반영할 수 있어야 한다.
- 앱 시작 시 백그라운드에서 한 번 대사 목록을 수신한다. 클릭·탭 이동·포커스 복귀마다 다시 수신하지 않는다.
- 실행 중 주기적인 원격 재수신은 이번 범위에 포함하지 않는다. 외부 수정은 앱을 다음에 실행해 정상 수신하면 반영된다.
- 초기 데이터 형식은 첨부 JSON의 `schemaVersion: 1`, `language: ko-KR`, `format: choice-parts-v1`을 사용한다.
- `entries`의 각 항목은 고유 `id`와 `parts`를 가진다. `parts`의 문자열은 그대로 이어 붙이고,
  문자열 배열에서는 후보 하나를 골라 이어 붙인다. 문자열 하나로 된 `parts`는 고정 대사이다.
- 초기 내장 기본 데이터도 첨부한 12개 샘플을 사용한다. 데이터 형식 설명은 대사 등록 안내를 따른다.
- 완성 문장과 조합형 문장 재료를 관리할 수 있게 한다. 선택할 문장/소재/말투는 작성자가 준비한다.
- 문장 생성 도구가 스스로 새 농담 소재를 공급하거나 무한히 창작한다고 가정하지 않는다.
- 대사를 표시할 때마다 GitHub 요청을 보내지 않는다. 외부 갱신과 로컬 대사 표시는 분리한다.
- 통신 실패 시 마지막 정상 목록을 이용하고, 정상 목록이 없으면 기본 내장 대사를 이용한다.
- 잘못된 형식·지원하지 않는 데이터나 표시할 수 없는 대사 때문에 기존 정상 목록을 잃지 않는다.
- 외부 데이터는 대사와 제한된 조합 규칙으로 취급한다. 임의 JavaScript/Python, 명령어,
  외부 스크립트나 데이터가 지정한 임의 함수는 실행하지 않는다.
- 대사 수신에 게임 화면·판독값·설정 파일·사용자 개인정보를 첨부하지 않는다.
- 예정 Raw 주소는 `https://raw.githubusercontent.com/StarlineBot/mabinogi_addon-releases/refs/heads/main/data/dialogues.json`이다.
  파일 등록과 실제 접근 성공 여부는 13절의 배포 준비 항목이다.

## 9. 기존 기능과의 관계

- 버프·디버프·투아림·보스 판독/알림과 오버레이 표시·잠금·클릭 통과 동작을 변경하지 않는다.
- 기존 파티 모집 토스트와 제작자 말풍선을 혼합하지 않는다. 제작자 말풍선은 앱 내부 표시이다.
- Discord 로그인이나 자동찾기 성공 여부를 이 기능의 이용 조건으로 추가하지 않는다.
- 일반 기능 화면에서도 잡담이 보일 수 있지만, 첫 사용/자동설정/영역 확인에는 설정 안내만 표시한다.
- 설정의 기존 제작자 사진·소개·문의하기는 유지한다.

## 10. 오류 및 리소스 기준

- GitHub 미연결, 파일 없음/손상, 캐시 읽기 실패, 조합 실패는 기존 앱 기능의 실패로 전파하지 않는다.
- 유효 대사를 만들 수 없으면 원시 조합 기호나 오류 문구를 잡담으로 출력하지 않는다.
- 외부 통신이나 가려짐 확인 때문에 앱 UI와 게임 캡처·판독을 지연시키지 않는다.
- 2분 간격 판정을 위해 고속 전체 화면 캡처나 지속적인 이미지 분석을 새로 수행하지 않는다.
- 탭 전환·클릭·가림 반복으로 타이머·말풍선·통신 요청이 계속 추가되지 않아야 한다.
- 앱 종료 후 대사 전용 창·타이머·외부 갱신 작업을 남기지 않는다.

## 13. 구현·배포 확인사항

기능 동작은 위 내용으로 확정했다. 아래는 추가 기획 승인을 기다릴 동작 선택지가 아니라

## 13. 제작자 잡담 알림음 (2026-10-20 사용자 요청)

- 업로드한 알림음 중 제품 sounds 자산과 해시가 일치하지 않는 유일한 미사용 파일은
  `tests/data/universfield-bright-notification-352449.mp3`다. 이 원본을 그대로
  `assets/sounds/제작자 잡담.mp3`로 포함한다.
- 하단 얼굴 클릭·설정 사진 클릭·자동 잡담이 노출 조건을 통과해 실제 말풍선 표시까지 성공한 뒤 한 번 재생한다. 앱 내부 show 성공만으로 타 창에 가려지지 않았다고 판단하지 않는다.
  표시가 거절되거나 선택 가능한 문장이 없으면 소리를 내지 않는다. 자동 추첨 주기와 횟수는 유지한다.
- 전용 비동기 재생기를 재사용하고 `QAudioOutput` 볼륨을 `0.5`(50%)로 설정한다.
  원본 MP3 자체를 다시 인코딩하거나 기존 다른 알림의 음량·재생기를 변경하지 않는다.
- 설정의 '제작자 잡담 사용' 옆 같은 줄에 '잡담 소리 사용' 체크를 둔다.
  기본값은 켜짐이며 `general.creatorDialogueSound`에 저장한다. 사용자에게 실제 Qt 렌더를
  공유했고 2026-10-20 '이 배치 유지'로 확정받았다.
- 소리를 끄면 진행 중 재생을 중단하고 이후 잡담은 무음으로 표시한다. 다시 켰을 때는
  다음 새 표시부터 재생하며 이전 문장의 소리를 다시 시작하지 않는다.
- 제작자 잡담을 끄면 소리 체크를 비활성화하되 저장한 소리 선호는 보존한다.
  잡담 자체를 다시 켜면 이전 소리 선택으로 복구한다.
- 말풍선을 닫거나 창이 가림/숨김/최소화/잠금 상태로 전환되거나 앱을 종료하면 전용 재생도 중단한다.
  누락된 파일·오디오 장치/백엔드 실패가 말풍선 표시나 다른 알림을 막지 않는다.
- 이 변경은 앱 내부 잡담의 알림음 추가이며, 게임 위 별도 알림·TTS를 추가하지 않는다.

[개발·검증 기록](creator-dialogue-implementation.md#잡담-알림음-추가-2026-10-20).

## 14. 가림 차단 복구와 미표시 회귀 방지 (2026-10-20 후속)

- 최신 사용자 요구: 가려진 잡담이 표시되거나 알림음이 울리지 않아야 한다. 이전 가림 허용 요구/테스트보다 이 기준이 우선한다. 사용자 조작 문제로 취급하지 않는다.
- 변경 전 `display_available(check_occlusion=False)`는 이 후속 요구를 만족하지 않았다. 독립 API 모델에서 불투명 가림 중 자동/클릭의 소리 콜백과 자동 횟수 소비를 확인했다. Windows 실제 청취/합성 확인은 별도다.
- 이전 엄격 판정으로 단순 복귀해서 NVIDIA 등 투명 합성 창 때문에 보이는 잡담이 전혀 안 나오는 회귀를 허용하지 않는다. WS_EX_TRANSPARENT는 시각적 투명성의 증거가 아니며 Win32 직사각형만으로 모든 per-pixel 합성을 정확히 알 수 있다고 보장하지 않는다.
- 확인된 가림·노출·판정 불확실을 구분한다. 불확실하면 보이지 않는 소리를 내지 않으며, 실제 보이는 클릭·자동이 영구 차단되는 경우도 해결 완료로 보지 않는다. 남은 제약을 보고하고 표시 조건을 몰래 완화하지 않는다.
- 기존 1초 확인과 이벤트를 활용해 표시 중 가림을 다음 정상 확인 주기까지 중단한다. 새 고속 폴링·지속 캡처·포커스 전환·최상위 창·무한 로그를 추가하지 않는다. 다른 모니터에서 보이는 비활성 앱은 계속 지원한다.
- 구현/회귀/Windows 확인 기준은 [통합 개발 전달문 8절](qa/배포시간단축_균열시세자동조회_화면헤더통일_개발전달_20261020.md#8-가려진-잡담의-표시알림음)을 따른다. 문서 갱신은 제품 수정 완료를 의미하지 않는다.

후속 소스는 가림 검사를 연결하고 노출/가림/불확실 진단을 구별한다. 표시·소리 차단과 다음 1초 tick의 중단은 API 모델로 검증했으나 NVIDIA per-pixel 합성 미표시 제약은 해결하지 못했다. [개발 결과와 미해결 범위](qa/후속요구_개발검증_20261020.md#가림-차단과-기술-제약)를 따른다. 실제 Windows 합성 확인 및 후속 독립 QA는 별도다.

## 15. 불확실한 가림의 무음 표시 시도 (2026-10-20 사용자 승인)

이 절의 불확실 합성 표시·추첨 정책은 유지하되, 소리를 항상 차단하던 조건은 16절로 보완한다.

사용자는 “가림을 판정할 수 없으면 말풍선은 표시를 시도하고 소리는 끄며, 가려진 동안에도 자동 추첨·횟수가 소모될 수 있다”는 변경에 **“그렇게”**로 승인했다. 이 절은 14절 및 이전 불확실 상태 차단 조건보다 우선한다.

- 확인된 노출: 기존 클릭·자동 표시 및 소리 설정/50% 음량을 유지한다.
- 확인된 불투명 가림: 클릭·자동 표시·소리·추첨·표시 횟수를 차단한다.
- 대상과 겹치는 창의 합성/alpha/region 증거가 불확실: 앱 내부 말풍선 표시를 시도하고 소리는 재생하지 않는다. 실제 가림은 Windows 합성에 맡긴다. 자동 추첨은 기존 2분·40%/20% 정책을 유지하며, 성공한 내부 표시는 최근 횟수에 반영한다. 실제 가려진 상태에서도 기회/횟수를 소모할 수 있음을 승인받았다.
- 불확실한 창을 만났어도 Z 순서의 나머지 창을 확인한다. 다른 확실한 불투명 창을 건너뛰어 표시/소리를 허용하지 않는다.
- 말풍선 표시 중 판정이 불확실해지면 기존 확인 주기에서 전용 소리만 중단하고 문장은 원래 3초 수명까지 유지한다. 확실한 가림이면 둘 다 닫는다. 노출이 확인돼도 이전 소리를 재생하지 않으며 다음 새 표시부터 소리 설정을 적용한다.
- 잠금·입력 데스크톱 확인 실패·최소화·숨김·화면 밖·부족한 배치 공간·투어/영역 지정·창 열거 실패/대상 HWND 미확인은 계속 차단한다. 모든 API 오류를 표시 허용으로 바꾸는 요구가 아니다.
- CD-04/CD-11/CD-19의 가림 차단은 위 확정 가림 기준이며, 불확실한 합성에서는 이 절의 무음 시도가 예외다. 진단은 노출/가림/불확실 구별을 유지한다.
- 포커스 이동·최상위 창·프로그램 이름 예외·새 캡처/고속 폴링·타이머/재생기 누적은 추가하지 않는다. 실제 Windows 합성 픽셀을 정확히 측정하는 기능을 구현했다고 주장하지 않는다.

개발 결과와 후속 확인 범위는 [무음 표시 개발 기록](qa/잡담_불확실가림_무음표시_개발_20261020.md)을 따른다.

## 16. 앱 포그라운드를 조합한 잡담 소리 허가 (2026-10-21 후속 승인)

사용자는 게임창처럼 앱의 포그라운드도 구분하자는 방안을 제안했고, 아래 조합 기준 설명 후 '그거까지 작성'으로 개발 전달에 포함하도록 요청했다. 직접 클릭만 예외로 하는 안을 별도로 채택한 것이 아니다. 이 절은 자동·클릭에 공통으로 적용하며 앞선 unknown 전부 무음 조건보다 우선한다.

### 우선순위와 상태표

1. 잡담 제외 화면·잡담 사용 OFF·배치 불가·최소화·트레이 숨김·잠금·절전·화면 밖 및 입력 데스크톱/창 열거 실패·대상 HWND 미확인은 기존처럼 표시와 소리를 차단한다. 앱 포그라운드가 이 경계를 우회하지 않는다. '잡담 소리 사용' OFF만인 경우에는 기존처럼 말풍선은 유지하고 소리만 차단한다.
2. 얼굴/말풍선의 **확인된 불투명 가림**은 앱이 포그라운드여도 표시·소리를 차단하고 진행 중이면 중단한다.
3. 나머지는 아래 표로 소리 허가를 판단한다. 허가는 '잡담 소리 사용' 체크와 실제 표시 성공 등 기존 조건을 모두 만족할 때만 유효하며 전용 50% 음량을 유지한다.

| 노출 판정 | 앱 본창 포그라운드 | 말풍선 | 소리 |
|---|---|---|---|
| 확인된 노출 | 확인됨/비활성/포그라운드 확인 불가 | 기존 표시 | 기존 설정대로 허용 |
| 합성/alpha/region 불확실 | 본창 포그라운드 확인됨 | 기존 앱 내부 표시 시도 | 새 표시의 소리 허용 |
| 합성/alpha/region 불확실 | 본창 비활성 또는 포그라운드 확인 불가 | 기존 앱 내부 표시 시도 | 무음/진행 중 소리 중단 |
| 확인된 가림 또는 1번 경계 탈락 | 무관 | 차단/중단 | 차단/중단 |

- **포그라운드와 실제 노출은 다른 정보다.** 본창 위에도 최상위 창이 덮일 수 있으므로 '앱 활성=모든 픽셀이 보임'으로 바꾸거나 가림 검사를 전부 제거하지 않는다. 불확실 합성에서 본창 포그라운드는 사용자가 앱을 보고 있는 상황의 소리 허가 기준으로만 사용한다. 모든 투명/최상위 합성 환경에서 실제 노출을 완벽히 보장하는 방법은 아니다.
- 앱 비활성=가림도 아니다. 다른 모니터에서 게임을 조작하면서 보이는 앱은 노출이 확인되면 계속 자동/클릭 소리를 허용한다. 앱 포그라운드 전용으로 기능 전체를 제한하지 않는다.
- 클릭 자체를 가림의 증거로 해석하지 않는다. 다만 내부 request 호출이나 클릭 신호만으로 본창 포그라운드 확인을 대신하지도 않는다. 포그라운드를 강제로 바꾸지 않고 현재 상태만 읽는다.

### 기존 감지 재사용과 실패 경계

- 기존 `system/window_watcher.py`의 Windows 포그라운드 감지/`is_self_active()` 경로를 우선 검토한다. `is_active()`는 게임 OR 자기 앱이고 실패 시 게임 활성으로 보는 경계도 있으므로 잡담의 본창 소리 허가로 그대로 사용하지 않는다.
- 현재 `is_self_active()`는 같은 PID의 창을 포함한다. 편집 오버레이만 활성이고 본창은 가려진 경우까지 '본창 활성'으로 인정하지 않도록 실제 foreground HWND와 현재 본창의 관계를 확인한다. 기존 모달/팝업/투어 제외도 유지한다. 게임/트래커의 기존 포그라운드 정책은 변경하지 않는다.
- HWND/PID와 소유 창 관계를 현재 요청에서 확인하며 오래 저장한 HWND/PID만으로 허가하지 않는다. 포그라운드 조회 실패·0/무효 HWND·권한/API 오류는 '앱 포그라운드 확인됨'으로 승격하지 않는다. 이미 확인된 노출까지 무음으로 낮추는 요구는 아니다.
- 새 표시/소리 직전에 노출과 본창 포그라운드를 다시 확인한다. 자동·직접 클릭 모두 같은 정책을 사용하며, 직접 클릭에만 소리를 되살리고 자동의 지속 무음을 남긴 채 완료하지 않는다.
- 표시 중 소리 허가가 사라지면 기존 이벤트/다음 정상 1초 확인 주기에서 전용 재생을 중단한다. unknown 상태의 문장은 원래 3초 수명을 유지하고, 확정 가림에서는 닫는다. 포그라운드/노출이 돌아와도 이전 소리는 재개하지 않고 이후 새 표시부터 판단한다.
- 자동 주기·확률·횟수(unknown의 내부 표시 성공 집계 포함)·소리 체크 저장·다른 알림 재생기는 유지한다. 새 캡처·고속 폴링·포커스 탈취·최상위 창·이름 예외·타이머/구독/재생기 누적을 추가하지 않는다.

### 후속 검증 기준

- 자동/클릭 각각에서 unknown+본창 활성은 표시·소리 1회, unknown+게임/다른 창 활성은 표시 시도·소리 0회를 확인한다.
- 확정 노출+비활성/듀얼모니터는 정상 소리, 확정 불투명 가림+본창 활성은 표시·소리 0회, 같은 PID의 편집 오버레이만 활성+본창 unknown은 무음을 확인한다.
- 입력 데스크톱/열거/owner 실패·잠금·최소화·숨김·제외 화면은 기존 표시/소리 차단, 소리 OFF는 소리만 차단을 유지한다. 포그라운드 API 실패/0/오래된 핸들이 unknown의 허가를 만들지 않아야 한다.
- 표시 직전 활성→비활성, 표시 중 노출/포그라운드 변화, 복귀 시 재생 없음, 새 클릭/새 자동 표시만 재생, 반복 전환·종료의 리소스 정리를 검증한다.
- 요청별 진단에서 클릭/자동·노출 판정·본창 포그라운드 확인·최종 소리 허가/차단 이유와 음원 재생 요청/실패를 구별한다. 매초 같은 로그를 쓰거나 외부 창 제목/화면을 수집하지 않는다. NVIDIA를 실제 원인으로 미리 확정하지 않는다.
- API 모델과 실제 Windows 합성/청취·듀얼모니터·포커스·장시간 결과를 구분한다. 문서만으로 소리 문제의 원인 확정·수정 완료·릴리즈 QA 통과를 선언하지 않는다.
