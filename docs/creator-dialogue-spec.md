# 제작자 얼굴 및 랜덤 말풍선 기능 명세

- 상태: 기획 확정. 개발 착수를 위한 추가 동작 결정은 없으며, 13절은 구현·배포 확인사항이다.
- 확정일: 2026-10-15
- 대상: 앱 본창의 제작자 얼굴, 자동/클릭 대사, 공개 GitHub 대사 갱신.
- 이 문서는 개발과 독립 QA에 전달하는 요구사항이다. 구현 또는 Windows 검증 완료를 뜻하지 않는다.
- GitHub 등록 절차와 개발 전달문: [대사 등록 안내](creator-dialogue-publishing.md).
- 초기 대사 데이터: [dialogues.json](examples/creator-dialogues/dialogues.json). 이 JSON 형식과 12개 샘플 항목으로 시작하고 이후 문구를 보충한다.

## 1. 목적

실용적인 게임 보조 앱에 제작자의 개성을 더한다. 앱을 볼 때 제작자가 가끔 혼잣말하거나,
사용자가 얼굴을 눌러 짧은 대사를 볼 수 있게 한다. 실시간 대화 상대나 기능 안내 도우미가 아니다.

대사는 뜬금없는 생각, 게임/개발 관련 농담 등으로 구성한다. 앱의 실제 오류·경고·판독 결과와
혼동되는 상태 알림으로 사용하지 않는다. 대사와 조합 재료를 추가하면 앱 재배포 없이 내용을
보충할 수 있어야 한다.

## 2. 표시 위치 및 범위

| 화면 | 얼굴 및 말풍선 |
|---|---|
| 트래커의 버프/디버프/투아림/보스 패턴 알림 | 공통 하단 공간의 오른쪽에 얼굴 표시 |
| 파티 모집 | 동일 |
| 전투 보조의 커스텀 오버레이/단축바/체력바/도르카/메모 및 편의기능의 각 계산기 | 동일. 기존 베타 접근 조건은 유지 |
| 설정 | 기존 제작자 사진을 대사 진입점으로 사용. 하단 얼굴을 중복 표시하지 않음 |
| 첫 사용 안내, 사용 준비/자동설정, 하이라이트 투어, 영역 지정/후보 승인 | 잡담 표시 대상에서 제외 |
| 게임 위 오버레이, 트레이, 별도 토스트 | 제작자 얼굴이나 잡담을 추가하지 않음 |

- 본창의 세로 크기를 늘려 얼굴용 공통 하단 공간을 확보한다. 기존 탭 콘텐츠 높이를 줄여
  얼굴을 끼워 넣거나 버튼·입력창 위에 얼굴을 상시 겹치지 않는다.
- 버프·디버프는 얼굴이 있는 오른쪽 아래 공간을 유지하면서 왼쪽 목록 패널만 추가 하단까지
  확장한다. 다른 탭의 공통 하단 공간은 유지한다. 세부 기준은 [트래커 화면 정리](tracker-layout-spec.md)를 따른다.
- 하단은 대사가 항상 흐르는 전광판이나 큰 제작자 소개 바가 아니다. 평상시에는 작은 얼굴만 보인다.
- 말풍선은 얼굴에 연결되어 기존 콘텐츠 위로 잠시 펼쳐진다. 일부 설정·목록을 가리는 것은
  허용된 연출이며, 모든 화면에 말풍선 크기의 빈자리를 따로 확보하지 않는다.
- 설정에서는 기존 사진을 기준으로 표시한다. 사진이 스크롤 밖에 있으면 그 사진을 기준으로
  자동 대사를 표시하지 않는다.
- 얼굴 크기, 추가 높이, 말풍선 폭과 세부 배치는 렌더로 확인한다. 기존 목업의 수치는 확정값이 아니다.
- 테마·DPI·작업 영역 변화에서도 얼굴·대사가 잘리거나 핵심 화면 접근이 불가능해지지 않아야 한다.

## 3. 자동 대사의 노출 가능 조건

다음 조건을 모두 만족할 때만 자동 대사를 표시한다.

1. 본창이 표시 중이며 최소화/트레이 숨김 상태가 아니다.
2. 현재 화면이 2절의 표시 대상이다.
3. 현재 얼굴과 표시 예정 말풍선 영역이 화면에 보이며 다른 창에 가려지지 않는다.
4. 표시할 유효한 대사가 있다.
5. 설정의 잡담 사용 옵션이 켜져 있다.

- 키보드 포커스나 Windows 포그라운드 여부만으로 제한하지 않는다.
- 듀얼모니터에서 한쪽으로 게임을 조작하고 다른 쪽에 앱을 띄운 경우에도 위 조건을
  만족하면 자동 대사를 표시할 수 있다.
- 앱 전체가 조금이라도 가려졌는지가 아니라 얼굴과 말풍선의 표시 영역을 기준으로 판단한다.
- 이 요구는 앱을 강제로 항상 위로 올리거나 게임에서 포커스를 가져오라는 뜻이 아니다.
- 단순한 창의 표시 플래그만으로 가려짐을 판정하지 않는다. 구현 방식은 고정하지 않으며,
  다중 모니터와 창 겹침에서 요구 조건을 실제로 판정할 수 있는지 Windows 검증이 필요하다.
- 가려짐 판정 실패 또는 노출 불가 상태에서는 자동 대사를 표시하지 않는다. 판정 오류로
  트래커·설정 등 기존 기능을 중단하지 않는다.

## 4. 추첨 시점

- 앱 실행 후 처음으로 노출 가능한 상태가 되면 한 번 바로 추첨한다. 무조건 대사를 표시하는 것이 아니라 40% 확률로 추첨한다.
- 앱 재실행 시 마지막 추첨 시각과 최근 자동 표시 횟수 기록을 초기화한다. 이전 실행에서 놓친 추첨을 이어서 실행하지 않는다.
- 노출 가능한 상태에서 마지막 자동 추첨으로부터 2분 이상 지났을 때 다음 추첨을 수행한다.
- 추첨에 실패해 대사가 나오지 않아도 추첨 시각을 갱신한다. 실패 직후 다시 추첨하지 않는다.
- 노출 불가에서 가능으로 바뀌면, 마지막 추첨으로부터 2분 이상 지났을 경우 한 번 바로 추첨한다.
- 마지막 추첨 이후 2분 이내에는 포커스·탭·창의 가림 상태를 반복해서 바꿔도 추가 추첨하지 않는다.
- 노출 불가 동안에는 추첨하지 않는다. 숨겨진 시간만큼 추첨이나 대사를 예약·누적하지 않는다.
- 오래 숨겨졌다가 돌아와도 놓친 주기를 몰아서 실행하지 않고, 조건에 맞으면 한 번만 추첨한다.
- 실제 표시 직전에 노출 조건을 다시 확인해 표시 대상이 사라진 곳에 대사를 띄우지 않는다.
- 말풍선이 이미 표시 중이면 자동 추첨을 생략한다. 자동 요청으로 현재 대사를 교체하거나 다음 대사를 예약하지 않는다.

## 5. 확률과 최근 표시 횟수

| 추첨 시점의 최근 10분간 자동 대사 표시 횟수 | 이번 추첨의 등장 확률 |
|---|---|
| 0~2회 | 40% |
| 3회 이상 | 20% |

- 최근 10분은 고정 구간이 아닌 추첨 시각 기준의 이동 구간이다.
- 현재 시각을 t라고 할 때 t-10분보다 이후에 실제 표시된 자동 대사를 센다. 정확히 10분 전
  기록은 제외한다. 이번 추첨으로 표시할 대사는 이번 확률 계산에 미리 포함하지 않는다.
- 확률은 현재 횟수로 매 추첨마다 결정한다. 오래된 기록이 구간 밖으로 나가 3회 미만이 되면 40%로 돌아온다.
- 3회는 횟수 상한이 아니다. 3회 이후에도 20%로 추가 대사가 나올 수 있다.
- 실제 표시된 자동 대사만 집계한다. 추첨 실패, 표시 전 조건 탈락, 클릭 요청 대사는 집계하지 않는다.
- 실제 표시 후 사용자가 바로 닫아도 표시된 자동 대사 1회로 센다.

## 6. 얼굴 클릭 및 말풍선 수명

- 표시 대상 화면의 얼굴을 누르면 자동 추첨 확률·2분 간격과 관계없이 대사를 요청할 수 있다.
- 클릭 대사는 자동 대사 빈도 감소를 위한 최근 10분 집계에 포함하지 않는다.
- 말풍선은 표시 후 3초간 유지하고 자동으로 닫힌다.
- 표시 중 얼굴을 다시 누르면 새 대사로 교체하고 그 시점부터 3초를 다시 계산한다. 여러 말풍선을 쌓지 않는다.
- 사용자가 말풍선을 누르면 즉시 닫힌다. 이 클릭으로 뒤에 가려진 버튼·입력창이 동시에
  눌리거나 선택되어서는 안 된다.
- 잡담 때문에 앱이나 게임의 포커스를 강제로 전환하지 않는다.
- 입력·드래그·편집 여부를 감지해 자동 발화를 억제하는 조건은 추가하지 않는다.
- 말풍선을 읽는 동안에도 기존 앱 기능은 계속 동작한다. 화면 전환 시 제외 화면으로 잡담을 가져가지 않는다.
- 대사는 3초에 읽기 좋은 짧은 1~2줄 중심으로 작성한다. 긴 내용은 글자를 계속 줄이거나
  스크롤해야만 읽을 수 있는 말풍선으로 내보내지 않는다.
- 가림·최소화·잠금·절전으로 표시가 중단되면 현재 말풍선을 닫는다. 복귀 시 이전 대사나 남은 표시 시간을 복원하지 않는다.
- 복귀 후 자동 대사의 기회는 4절의 일반 추첨 조건을 따른다. 잠금·절전 중의 추첨을 몰아서 실행하지 않는다.
- 설정에 잡담 사용 옵션을 제공하며 기본값은 켜짐이다. 꺼 둔 동안 자동/클릭 대사를 표시하지 않고 현재 말풍선도 닫는다.

### 대사 선택과 직전 문장 반복 방지

- 자동 대사와 클릭 대사는 같은 초기 JSON 목록을 사용한다.
- 실제 완성된 문장이 직전에 표시한 문장과 같으면 연속 표시하지 않는다. 문장 틀이 같아도 완성 문장이 다르면 표시할 수 있다.
- 직전 문장 비교는 탭별로 나누지 않고 이 기능 전체에서 공유한다.
- 다른 유효 문장을 만들 수 없으면 반복 대사를 강제로 내보내거나 무한히 재시도하지 않고 이번 표시를 생략한다.

## 7. 상태 및 정상 흐름

| 상태 | 의미와 기대 동작 |
|---|---|
| 표시 대상 아님 | 설정 전용 안내·영역 지정 등. 제작자 잡담 없음 |
| 잡담 사용 꺼짐 | 자동/클릭 대사 없음. 기존 앱 기능은 유지 |
| 대상 화면이지만 노출 불가 | 최소화, 가림, 화면 밖 또는 판정 실패. 자동 추첨/표시 없음 |
| 노출 가능·간격 대기 | 얼굴을 표시하고 다음 자동 추첨 가능 시각을 기다림 |
| 노출 가능·추첨 가능 | 최근 자동 표시 횟수로 40%/20%를 정해 한 번 추첨 |
| 말풍선 표시 | 짧은 대사를 표시하고 3초 만료 또는 클릭으로 닫음 |
| 외부 목록 갱신 중 | 현재 유효 대사로 이용 가능. 네트워크를 기다리며 UI를 막지 않음 |

정상적인 자동 흐름은 노출 가능 판단 → 간격 확인 → 횟수 확인 → 추첨 → 유효 대사 선택/조합
→ 노출 조건 확인 → 말풍선 표시 → 자동 표시 횟수 기록 → 3초 만료 또는 클릭 닫기이다.
추첨에 실패하면 말풍선 없이 다음 간격을 기다린다.

## 8. 대사 공급과 GitHub 갱신

- 기존 공개 릴리즈 저장소 `StarlineBot/mabinogi_addon-releases`의 `main` 브랜치에
  `data/dialogues.json`을 두고 읽는다. 전체 대사가 공개되어도 된다. 별도 대사 저장소는 만들지 않는다.
- 릴리즈 첨부파일이나 개별 태그가 아닌 갱신 가능한 브랜치의 Raw 파일을 이용한다.
  대사만 추가할 때는 앱 릴리즈·태그 생성이 필요하지 않다. 배포 자동화는 이 파일을 보존한다.
- 앱 소스 저장소까지 공개할 필요는 없다. 배포 앱에 GitHub 비공개 접근 토큰을 넣지 않는다.
- 작성자가 대사 파일을 수정하면 앱 재배포 없이 후속 수신에서 반영할 수 있어야 한다.
- 앱 시작 시 백그라운드에서 한 번 대사 목록을 수신한다. 클릭·탭 이동·포커스 복귀마다 다시 수신하지 않는다.
- 실행 중 주기적인 원격 재수신은 이번 범위에 포함하지 않는다. 외부 수정은 앱을 다음에 실행해 정상 수신하면 반영된다.
- 초기 데이터 형식은 첨부 JSON의 `schemaVersion: 1`, `language: ko-KR`, `format: choice-parts-v1`을 사용한다.
- `entries`의 각 항목은 고유 `id`와 `parts`를 가진다. `parts`의 문자열은 그대로 이어 붙이고,
  문자열 배열에서는 후보 하나를 골라 이어 붙인다. 문자열 하나로 된 `parts`는 고정 대사이다.
- 초기 내장 기본 데이터도 첨부한 12개 샘플을 사용한다. 데이터 형식 설명은 대사 등록 안내를 따른다.
- 완성 문장과 조합형 문장 재료를 관리할 수 있게 한다. 선택할 문장/소재/말투는 작성자가 준비한다.
- 문장 생성 도구가 스스로 새 농담 소재를 공급하거나 무한히 창작한다고 가정하지 않는다.
- 대사를 표시할 때마다 GitHub 요청을 보내지 않는다. 외부 갱신과 로컬 대사 표시는 분리한다.
- 통신 실패 시 마지막 정상 목록을 이용하고, 정상 목록이 없으면 기본 내장 대사를 이용한다.
- 잘못된 형식·지원하지 않는 데이터나 표시할 수 없는 대사 때문에 기존 정상 목록을 잃지 않는다.
- 외부 데이터는 대사와 제한된 조합 규칙으로 취급한다. 임의 JavaScript/Python, 명령어,
  외부 스크립트나 데이터가 지정한 임의 함수는 실행하지 않는다.
- 대사 수신에 게임 화면·판독값·설정 파일·사용자 개인정보를 첨부하지 않는다.
- 예정 Raw 주소는 `https://raw.githubusercontent.com/StarlineBot/mabinogi_addon-releases/refs/heads/main/data/dialogues.json`이다.
  파일 등록과 실제 접근 성공 여부는 13절의 배포 준비 항목이다.

## 9. 기존 기능과의 관계

- 버프·디버프·투아림·보스 판독/알림과 오버레이 표시·잠금·클릭 통과 동작을 변경하지 않는다.
- 기존 파티 모집 토스트와 제작자 말풍선을 혼합하지 않는다. 제작자 말풍선은 앱 내부 표시이다.
- Discord 로그인이나 자동찾기 성공 여부를 이 기능의 이용 조건으로 추가하지 않는다.
- 일반 기능 화면에서도 잡담이 보일 수 있지만, 첫 사용/자동설정/영역 확인에는 설정 안내만 표시한다.
- 설정의 기존 제작자 사진·소개·문의하기는 유지한다.

## 10. 오류 및 리소스 기준

- GitHub 미연결, 파일 없음/손상, 캐시 읽기 실패, 조합 실패는 기존 앱 기능의 실패로 전파하지 않는다.
- 유효 대사를 만들 수 없으면 원시 조합 기호나 오류 문구를 잡담으로 출력하지 않는다.
- 외부 통신이나 가려짐 확인 때문에 앱 UI와 게임 캡처·판독을 지연시키지 않는다.
- 2분 간격 판정을 위해 고속 전체 화면 캡처나 지속적인 이미지 분석을 새로 수행하지 않는다.
- 탭 전환·클릭·가림 반복으로 타이머·말풍선·통신 요청이 계속 추가되지 않아야 한다.
- 앱 종료 후 대사 전용 창·타이머·외부 갱신 작업을 남기지 않는다.

## 11. 범위 밖

## 12. Acceptance Criteria

| ID | 검증 가능한 성공 기준 |
|---|---|
| CD-01 | 일반 기능 탭에서 기존 콘텐츠 영역을 줄이지 않고 추가 하단 공간에 얼굴이 보이며, 상시 얼굴이 기존 버튼·표·입력창을 덮지 않는다. |
| CD-02 | 설정에서는 기존 제작자 사진을 눌러 대사를 요청할 수 있고 별도 하단 얼굴이 중복되지 않는다. |
| CD-03 | 첫 사용 안내, 사용 준비/자동설정, 투어와 영역 지정/후보 승인 중에는 자동/클릭 잡담이 나타나지 않는다. |
| CD-04 | 앱에 포커스가 없어도 다른 모니터에서 얼굴·말풍선 영역이 가려지지 않으면 자동 표시 대상이 된다. 대상 영역이 가려졌거나 최소화 상태이면 자동 대사가 나오지 않는다. |
| CD-05 | 추첨 직후 2분 이내에 포커스나 가림을 반복 변경해도 추가 추첨하지 않으며, 추첨 실패도 같은 간격 제한을 적용한다. |
| CD-06 | 마지막 추첨 후 2분 이상 지난 상태에서 앱이 다시 노출 가능해지면 한 번만 추첨하고, 숨겨진 동안의 주기를 몰아서 실행하지 않는다. |
| CD-07 | 시간과 난수를 통제한 검증에서 최근 10분 자동 표시 0~2회이면 40%, 3회 이상이면 20%로 추첨한다. 유한 번의 실제 실행에서 등장 횟수가 정확히 40%/20%일 것을 요구하지 않는다. |
| CD-08 | 현재 추첨 직전 최근 횟수로 확률을 정하며, 정확히 10분 전 기록은 제외한다. 횟수가 3회 미만으로 줄면 40%로 복귀한다. |
| CD-09 | 얼굴 클릭은 추첨 실패 직후에도 대사를 요청할 수 있고 최근 10분 자동 표시 횟수를 늘리지 않는다. |
| CD-10 | 말풍선은 표시 후 3초에 닫히며, 중간 클릭 시 즉시 닫히고 가려진 컨트롤의 동작이 실행되지 않는다. |
| CD-11 | 자동 추첨에 당첨되었어도 표시 직전 대상 영역이 가려지거나 제외 화면으로 바뀌면 표시하지 않고 자동 표시 횟수도 늘리지 않는다. |
| CD-12 | 말풍선이 기존 콘텐츠 일부를 잠깐 가릴 수 있으나 입력 중이라는 이유만으로 별도 억제하지 않고, 앱/게임의 포커스를 강제로 가져오지 않는다. |
| CD-13 | 공개 GitHub 대사 파일 변경이 후속 정상 수신에서 앱 재배포 없이 반영되며, 얼굴 클릭마다 외부 요청을 보내지 않는다. |
| CD-14 | 통신/데이터 오류가 발생해도 마지막 정상 목록 또는 내장 대사로 이용할 수 있고, 원시 조합식이나 실행 코드가 표시/실행되지 않는다. |
| CD-15 | 각 일반/베타 탭, 설정의 스크롤 상태, 다중 모니터와 DPI 조건에서 얼굴·말풍선 배치를 확인한다. Windows 실제 가려짐 판정은 오프스크린 렌더 통과로 대체하지 않는다. |
| CD-16 | 반복 탭 전환과 대사 요청 후에도 말풍선·타이머·통신 작업이 누적되지 않으며, 기존 판독·알림과 종료가 유지된다. |

| CD-19 | 표시 도중 가림·최소화·잠금·절전이 발생하면 말풍선이 닫힌다. 복귀 시 이전 말풍선을 되살리거나 숨겨진 동안의 추첨을 몰아서 실행하지 않는다. |

## 13. 구현·배포 확인사항

기능 동작은 위 내용으로 확정했다. 아래는 추가 기획 승인을 기다릴 동작 선택지가 아니라
개발·배포 과정에서 확인할 항목이다. 검토 결과 확정 요구사항 변경이 필요하면 먼저 사용자와 협의한다.

| 구분 | 확인할 항목 |
|---|---|
| 외부 등록 | 정해진 공개 저장소/경로에 대사 파일을 등록하고 로그인 없이 Raw 접근 가능한지 확인 |
| 통신·데이터 보호 | 기존 앱 패턴에 맞는 유한 타임아웃, 파일 크기·대사 길이·조합 시도 상한을 설정하고 실패/비정상 입력으로 앱을 막지 않는지 검증 |
| 기술 선택 | 문장 생성 라이브러리는 필수가 아니다. 도입한다면 확정 JSON을 지원하고 배포 라이선스를 검토. RiScript의 GPL-3.0 조건도 확인 |
| 화면 검토 | 실제 제작자 이미지로 확인할 얼굴 크기/추가 높이/말풍선 크기. 작은 작업 영역과 높은 DPI에서 창이 잘리지 않는 배치 |
| Windows 판정 | 듀얼모니터, 포커스 없는 노출, 창 겹침, 잠금·절전과 복귀에서 가려짐/표시 수명 조건을 실제 검증 |

기획 확정과 코드 구현, 공개 데이터 등록, Windows 검증 완료는 별개다. 본 문서 저장이나
푸시만으로 이들 작업까지 완료되었다고 해석하지 않는다.
