# 투아림 자동 찾기 버튼 배경 혼입 수정

- 근거: `docs/qa/투아림_자동찾기_오른쪽구조_배경혼입_QA_20261017.md`의
  P2 `TUARIM-RIGHT-MASK-QA-01`.
- 실제 v0.4.80 진단 ZIP의 무변형 입력으로 수정 전 **1 failed, 6 passed (4.81초)**를 재현했다.
  도르카 5와 투아림 0%가 보이는 입력이며 기대 좌표는 `(603,151,42,16)`이다.
- 원본 QA, 재현 스크립트, ZIP, 모델 PNG와 임계값은 수정하지 않는다.

## 원인과 범위

공용 원형 장식은 찾았지만 기존 전체 마스크에서 왼쪽 45열만 제거한 오른쪽 구조 검사에
버튼 바깥 게임 배경이 남았다. 구조 점수 0.9247이 기존 기준 0.97을 넘지 못했다.

`detect/tuarim_anchor.py`에서 원형 기준 x=47:71, y=33:44의 불변 버튼 내부만
기존 마스크와 교차해 별도 검사한다. 먼저 원본 크기의 마스크를 제한한 다음 배율을 적용한다.
비정수 배율에서는 면적 보간 결과가 255인 완전 내부 픽셀만 사용해 바깥 배경과 섞인 경계를
제외한다. 단순 nearest 마스크에서는 75% 밝은 배경에서 같은 문제가 재현됐으며 이 처리로 해결했다.

- 구조 검사는 삭제하지 않고 BGR 정규화 점수와 합격 기준 0.97을 유지한다.
- 공용 원형 탐색, 도르카 판독/상태/설정과 단축바 구현은 변경하지 않는다.
- 투아림 숫자를 읽어야 위치를 찾을 수 있는 의존성을 추가하지 않는다.
- 기존 전체 후보, 버튼 없는 화면 거부, % 영역 잘림, 복수 실제 위치 거부와 승인 흐름을 유지한다.
- 기존/신규 ZIP은 저장된 모델 PNG에서 마스크를 계산한다. 자산 형식이나 원본 픽셀을 바꾸지 않는다.
- 진단 ZIP을 새 코드로 재실행하면 과거의 실패와 다른 성공 결과가 나오는 것이 정상이다.
  원래 기록의 실패를 성공으로 바꾸지 않는다.

## 검증

```bash
PYTHONPATH=src:. QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest tests/test_tuarim_button_background.py -q --tb=short
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q -m 'not windows_integration'
```

- 새 회귀 **49 passed (12.67초)**. 원본 QA 7건을 변경 없이 가져온다.
- 추가 40건은 버튼 밖을 검정/흰색으로 대체한 대조 입력에 75/100/125/150/200% 배율과
  x/y 각각 0/1픽셀 이동을 적용하고 예상 좌표를 정확히 비교한다. 실제 혼합 DPI 캡처 검사는 아니다.
- 새 실제 입력을 한글 경로의 새 ZIP으로 저장한 후 설치 자산을 차단해도 같은 좌표로 재실행한다.
- 과거 두 자산만 있는 ZIP 형식에서도 버튼을 지운 입력은 거부한다.
- 전체 격리 회귀 **1,310 passed, 5 deselected, 3 warnings (331.08초)**.
  5건은 별도 Windows 네이티브 검사이며 경고는 기존 QMouseEvent 사용 경고다.
  기존 0~99/100% 판독, 이전 98% 누락 원본, 도르카 이동/재탐색, 단축바/진단 ZIP,
  설정/알림 회귀를 포함한다. assertion 완화나 실패 skip은 추가하지 않았다.
- 푸시한 SHA의 Windows 테스트·exe 빌드는 별도 확인한다. 이 개발 환경에서는 이전
  Actions API 조회가 `Forbidden`이었으므로 조회 실패를 Windows 통과로 대신하지 않는다.
- 실제 Windows 혼합 DPI, 장시간 게임 동시 실행과 포커스/자원 영향은 이번 Linux 검사로
  확인하지 않았다. 새 타이머/워커/반복 캡처를 추가한 변경은 아니다.

원격 v0.4.80이 이미 있으므로 변경 노트는 v0.4.81로 분리한다. 태그/릴리즈는 실행하지 않는다.
새로 올라온 음원 파일은 이 버그 수정에서 교체하거나 음량을 바꾸지 않는다.
