# 도르카 베타 및 이면을 보는 눈 교체

## 범위와 승인

- 기준: [도르카 명세](dorcha-overlay-spec.md), 사용자 요청 및 렌더 승인.
- 편의기능의 독립 베타 탭을 추가하고, 기존 탭 인덱스·투아림·체력바·보스 설정은 보존한다.
  새 기능은 로그인 조건과 별도 사용 체크를 가지며 기본 OFF다.
- 기존 체력바 225px 표시와 도르카 약 338px 표시를 나란히 렌더했고 사용자가 현재 배치를 승인했다.
  실제 설정 탭도 `/tmp/dorcha-preview/integrated-settings.png`로 렌더 확인했다.
- 이면을 보는 눈은 사용자 요청에 따라 QA 원본 `eye_native_20261016/boss.png`를
  번들 `assets/debuff/icon/이면을 보는 눈.png`에 그대로 복사했다. 16x16 픽셀을 재압축 변형하거나
  크기를 늘리지 않았다. 원래 검출 임계값은 바꾸지 않는다.

## 판독과 자동찾기

- `dorcha_reader`는 중앙 정렬을 포함한 0~15 전체 단어를 비교한다. 글자별 결과를 합쳐
  잔량을 추측하지 않으며, 점수 0.88/다음 후보와의 차이 0.10에 못 미치면 None이다.
  이전 탐색에서 13의 부분 가림이 1/3으로 바뀌던 입력을 회귀로 검사한다.
- 원본 17개로 0~15 참조를 생성한다. 0은 래스터가 다른 2종류를 보존했다.
  `scripts/build_dorcha_refs.py`와 `detect/templates/dorcha/sources.json`에 파일·좌표·SHA256을
  기록한다. 참조 자체의 재검사와 참조로 쓰지 않은 이전 원본 검사를 구분한다.
- 기존 투아림 % 리더나 앵커를 변경하지 않는다. 도르카 자동찾기는 원형 장식만 사용하고
  내부 숫자와 오른쪽 %를 제외한다. 밝은 배경에서 축소 검색이 놓치면 원본 해상도에서
  동일한 0.97 기준으로 재검색한다. 임계값을 낮추거나 숫자값으로 위치를 추측하지 않는다.
- 후보 여러 개/자산 누락/캡처 실패에서는 기존 등록을 유지한다. 기존 확인·승인/취소 흐름과
  실행별 원본 PNG·자산·로그·관련 설정 보존 및 진단 ZIP 재실행에 연결한다.

## 표시와 생명주기

- 15칸과 오른쪽 위 숫자는 하나의 값으로 함께 그린다. 실패는 `--/15`와 빈칸이며 실제 0과 다르다.
  같은 값에서는 불필요한 다시 그리기를 하지 않고, 값 전환 때문에 크기·칸·숫자 기준점이 변하지 않는다.
- 등록 후 사용 중인 활성 상태에서 200ms마다 지정 영역만 mss로 읽는다. 판독·표시는 UI 스레드에서
  기존 소형 영역 패턴을 따르며, 새 워커나 소리·흔들림·점멸을 추가하지 않는다.
  이 주기는 구현값이지 실게임 지연/CPU 목표의 통과 수치가 아니다.
- 사용 OFF/일시정지/로그아웃/영역 없음/비활성은 숨기고 이전 값을 폐기한다.
  복귀 시 현재 캡처로 결정한다. 최초와 재실행에서 과거 자원값을 저장/복원하지 않는다.
- 원본 영역 변경은 저장 성공 후에만 적용한다. 표시 설정 저장 실패는 현재 세션과 재실행 상태가
  다를 수 있음을 안내하고 같은 실패를 반복해 알림 창을 쌓지 않는다.
- 수동 영역 지정 중에는 읽기를 멈추고 취소/완료 후 원래 타이머 상태를 복구한다.
  종료 중 완료 콜백은 타이머를 다시 시작하지 않는다. 종료 시 캡처·선택창·확인창·오버레이를 정리한다.
- 잘못된 도르카 설정은 해당 항목만 기본값으로 읽으며 다른 기능을 초기화하지 않는다.
  기존 패키징의 `detect/templates` 전체 포함 경로로 새 NPZ/출처 JSON도 번들된다.

## 검증과 한계

- 도르카·교체 아이콘·기존 종료/동일 아이콘 구분·자동찾기 진단 집중 회귀: **202 passed (31.38초)**.
- 150% Qt 배율: 도르카 탭·오버레이·자동찾기 **43 passed (13.70초)**.
- 최종 전체 격리 회귀: **1120 passed, 4 deselected, 3 warnings (230.67초)**.
  제외는 별도 Windows 네이티브 검사 4건, 경고는 기존 QMouseEvent API 사용이다.
  로그인 로컬 서버 바인딩 권한으로 실행했고 장치 대체와 QThread 누수 검사는 유지했다.
- 원본 렌더 도구 정상 종료, 28px 시스템 글꼴의 설정 최소 너비 712px/실제 너비 760px,
  `git diff --check` 통과를 확인했다. 실제 Windows 접근성·혼합 DPI 통과로 대신하지 않는다.
- 새로 받은 16장 전부에서 원 내부 숫자 좌표를 찾고 실제 도르카 값과 일치하는지 검사한다.
  참조 검사도 포함하므로 독립 QA 정확도나 전 환경 성공률로 해석하지 않는다.
- 이전 실제 원본의 0/3/7/8/9/10/11/13/15, 한쪽/상하 가림, 빈·흰 입력, 합성 범위 밖 16~19,
  손상 참조, 다중 후보 거부, 저장 실패, 반복 중단/복귀와 독립 설정 보존을 실행한다.
- 실패 진단 ZIP을 추출한 입력과 보존 자산으로 재실행해 원래 자동찾기 결과가 같음을 확인한다.
- 이면을 보는 눈 교체본은 원본과 픽셀 동일하며 중앙 참고 크롭과의 점수는 0.968216이다.
  off/auto 실제 엔진에서도 적용 확정을 확인한다. 같은 한 장의 두 위치이며 전 장면 검증은 아니다.
- 실제 Windows 게임/클릭 통과/혼합 DPI/전체화면/잠금·절전·장시간 CPU·핸들은 미검증이다.
  같은 글꼴 픽셀이 반복되는 자료와 합성 배율 검사는 실게임 변화 영상 측정을 대신하지 않는다.
- 특히 현재 좌표 변환은 기존 `ui/dpi.py`의 주 화면 배율 방식을 재사용하므로 혼합 DPI 지원을
  새로 검증했다고 주장하지 않는다. 다른 실제 UI 배율의 실패는 값 추측 대신 판독 불가로 처리한다.
- 푸시 전 사용자 확인을 받고, 해당 SHA의 Windows 회귀·네이티브·exe 빌드 결과를 확인한다.
  릴리즈·태그는 진행하지 않는다.
