## P2 / Confirmed Bug: 화면 렌더 테스트의 Linux 전용 출력 경로

- 관련 코드: `tests/test_registration_render.py:21`~`:22`.
  `output = Path('/tmp/region-registration-implemented')`, `output.mkdir(exist_ok=True)`.
- 조건: `/tmp`에 해당하는 부모 디렉터리가 없는 Windows 호스티드 러너에서 테스트 실행.
  WindowsPath의 드라이브 루트 기준 `\\tmp\\region-registration-implemented`로 해석되고,
  부모를 만들지 않는 mkdir에서 FileNotFoundError / WinError 3이 발생한다.
- 실제 실패: `test_registered_commands_fit_the_actual_window[False]`와 `[True]` 두 조건.
  버튼/스크롤/스크린샷 검증에 도달하기 전에 테스트 준비가 실패했다.
- 사용자 영향: 이번 태그의 Windows 검사 실패로 새 exe를 만들거나 배포하지 못한다.
  이 로그가 앱 자체의 실행 크래시나 UI 기능 실패를 입증하는 것은 아니다.
- 재현: 위 실행의 Windows 실제 로그에서 두 번 같은 WinError 3을 확인했다.
  Linux에서 해당 테스트가 통과한 기존 결과와 Windows 실패를 혼동하지 않는다.

## 개발 전달

- 테스트 출력은 pytest의 `tmp_path` 아래 전용 하위 폴더로 바꾼다. 함수 인자로 fixture를
  받고 `tmp_path / 'region-registration-implemented'`를 사용하는 식이면 Windows/Linux
  경로를 분리해 하드코딩할 필요가 없으며 병렬 실행 간 파일 충돌도 피할 수 있다.
- screenshot 저장, 큰 글꼴, 뷰포트/버튼 접근성 assertion은 그대로 유지한다.
  테스트 skip/삭제/기대값 약화, 러너에 임의의 C:\\tmp를 만드는 우회로 통과시키지 않는다.
- 이번 단계는 독립 QA이므로 기존 테스트와 앱 구현은 수정하지 않았다. 앱 로직 수정이
  필요하다는 근거도 이번 실패 로그에는 없다. 수정본 푸시 후 해당 테스트와 관련 회귀를 확인한다.
- 기존 v0.4.86 태그를 삭제/이동하지 않는다. 수정 후 QA에서 다음 원격 태그 번호와 노트를
  확인하고 새 릴리즈 명령을 준비한다. 실패한 태그의 단순 재실행은 현재 권고하지 않는다.
