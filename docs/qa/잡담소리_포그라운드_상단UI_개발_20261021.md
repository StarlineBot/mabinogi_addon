기준 소스 `ee946a0`. [통합 QA의 추가 전달](헤일로개발과_잡담로그_통합QA_20261020.md),
[잡담 명세 16절](../creator-dialogue-spec.md#16-앱-포그라운드를-조합한-잡담-소리-허가-2026-10-21-후속-승인),
[계산기 명세 8절](../dungeon-entry-profit-calculator-spec.md#8-계산기-상단-표시-통일-2026-10-20-후속-요청)을 구현했다.
개발 검증이며 후속 독립 QA/Windows 통과와 구분한다.

## 잡담 소리

| 노출 판정 | 본창 포그라운드 | 표시 | 새 소리 |
| --- | --- | --- | --- |
| 확인된 노출 | 무관/조회 실패 | 기존 표시 | 기존 설정대로 |
| 불확실한 합성 | 현재 본창 확인 | 내부 표시 시도 | 설정에 따라 50% |
| 불확실한 합성 | 다른 창/조회 실패 | 내부 표시 시도 | 무음 |
| 확정 가림/기존 제외 경계 | 무관 | 차단/중단 | 차단/중단 |

기존 `WindowsWatcher.is_self_active()`는 같은 PID의 모든 창을 허용하고 `is_active()`는 게임 활성도 포함한다.
이를 잡담 허가에 그대로 사용하면 편집 오버레이만 활성인 경우를 본창으로 오인한다.
같은 `system/window_watcher.py`에 `is_main_window_foreground(hwnd)`를 추가해 현재 foreground HWND와
요청 시의 본창 HWND가 같은지, 두 핸들이 유효한지, PID가 현재 프로세스인지 확인한다.
foreground/PID를 재확인하며 오래 저장한 ID·제목·실행파일 이름을 사용하지 않는다. 실패/0/무효/재사용 의심은 false다.
기존 게임/편집 오버레이 watcher의 허용 정책은 변경하지 않았다. Windows API 연속 호출 사이를 원자적으로 보장하지는 않는다.

매 표시 전 노출 확인에서 unknown일 때만 본창 foreground를 조합한다. 확인된 노출은 다른 모니터의 비활성 앱도 소리가 허용된다.
확정 가림·잠금·최소화·숨김·배치/화면/모달·입력 데스크톱/창 열거 실패·owner 미확인은 기존 차단이 우선한다.
자동/클릭은 같은 정책이다. 클릭 이벤트 자체를 노출/foreground 증거로 쓰지 않는다.
unknown에서 본창 비활성으로 바뀌면 기존 1초 확인에서 전용 소리만 중단하고, 문장은 기존 3초 수명까지 유지한다.
복귀만으로 과거 소리를 재개하지 않는다. 이후 새 클릭/2분 후 새 자동 표시에서 다시 허가한다.
소리 OFF, 50% 음량, 자동 확률/기록, 다른 알림 재생기는 유지한다. 캡처·포커스 전환·최상위 창·새 타이머/폴링은 추가하지 않았다.

## 요청 진단

실제 `request()`당 info 기록 하나에 mode, visibility, foreground, foreground_error,
sound_allowed/reason, audio_stage, result와 유효 대사 수를 남긴다. `_eligible()`/매초 tick 자체에는 새 로그를 쓰지 않는다.
음원 없음·재생기 준비·백엔드 미준비·재생 요청·동기 실패를 구별하며 제출 성공을 실제 청취 성공이라고 기록하지 않는다.
기존 수동 거절의 배치/노출 이유와 유효 대사 수는 통합 기록에 유지했다. 이전 두 로그 중복을 제거했다.
최신 요청별 자동/클릭 진단 요구에 따라 실제 자동 요청의 최종 거절도 기록하되, 추첨 전에 거절된 매초 상태는 기록하지 않는다.
대사 원문·외부 창 제목/화면·전체 경로는 새로 수집하지 않는다.

## 최초 제목 행과 계산기

QA 재현을 그대로 실행해 **1 failed / 1 passed**, 첫 표시 제목 높이 **21px 대 26px**를 확인했다.
공통 헤더에 도움말과 같은 논리 높이 기준을 적용하고 세로 여유가 제목 행에 임의 배분되지 않도록 했다.
제목 글꼴은 기존 본문 대비 14/12 비율이며 글꼴/DPI가 커지면 font metrics도 최소 높이에 반영한다.
도움말 버튼과 헤더가 같은 상수를 사용하고 긴 제목/설명은 줄바꿈한다. 화면별 개별 보정값은 넣지 않았다.

입장 계산기의 `단위: 골드`를 제거하고 환전/입장 계산기의 새로고침을 같은 표준 reload 아이콘·32×32 논리 크기로 통일했다.
각 툴팁과 공통 접근 가능한 이름을 유지한다. 강제 조회·캐시·진행 중/숨김 정책·계산식은 변경하지 않았다.
사용자에게 실제 앱 첫 표시 렌더를 공유했고 **“이 배치 유지”**로 확정받았다.

- [승인한 계산기 비교](assets/foreground_header_followup_20261021/convenience-comparison.png)
- [첫 표시 측정](assets/foreground_header_followup_20261021/headers.json)
- [두 테마·네 배율 측정](assets/foreground_header_followup_20261021/render-matrix.json)

`--native-font` 렌더는 모든 위젯의 setFont/제목 `_fit_title()` 수동 호출을 하지 않는다.
각각 별도 Qt 프로세스에서 light/dark × QT_SCALE_FACTOR=1/1.25/1.5/2, 전체 14개 화면(헤일로 하위 포함)을 렌더했다.
도르카/커스텀의 실제 font family/크기/굵기, 제목 높이·설명 위치·구분선·헤더 높이가 같음을 대조했다. 기본 제목은 두 화면 모두 14 논리 px/700, 제목 행 26px, 헤더 61px였으며 각 프로세스의 devicePixelRatio는 1/1.25/1.5/2였다.
오프스크린의 OS 색 전환 한계 때문에 팔레트는 진단에서 명시 주입하며 실제 Windows glyph/font fallback을 입증하지 않는다.
큰 글꼴/작은 작업영역의 본문 조작 도달 및 가로 넘침은 기존 탐색 회귀를 유지한다.

## 회귀 위치와 실행

- `tests/test_window_watcher.py`: 본창/같은 PID 오버레이/다른 창, 0/무효, PID/foreground 오류, 확인 도중 foreground/PID 변경.
- `tests/test_dialogue_display_policy.py`: 자동/클릭 × clear/unknown/opaque × 본창/오버레이/조회 불가, 최종 확인 변화, 소리 중단/복귀/새 자동 표시, 설정 OFF, 요청 로그와 폴링 무로그.
- `tests/test_creator_dialogue.py`: 원래 배치·표시·소리 assertion 유지, 요청당 한 로그로 최신 정책 반영, 음원 없음/준비·재생 실패 진단 강화.
- `tests/test_navigation_all_widths.py`: 글꼴을 고치지 않은 최초 제목/헤더 높이 회귀 추가. 원래 QA의 글꼴/행 높이 두 조건을 함께 검사한다.
- 최초 관측 코드는 `test_support/regressions/feature_header.py`로 공유하고 역사 QA 진입점 두 개는 그대로 실행 가능하다. CI에서는 정식 회귀만 수집하므로 중복 실행하지 않는다.

```bash
PYTHONPATH=src:.:tests QT_QPA_PLATFORM=offscreen uv run pytest scripts/qa_feature_header_initial_font_20261020.py -q -s --tb=short
QT_QPA_PLATFORM=offscreen uv run pytest tests/test_window_watcher.py tests/test_dialogue_display_policy.py tests/test_creator_dialogue.py tests/test_navigation_all_widths.py tests/test_calculator_result_state.py -q
PYTHONPATH=src:. QT_QPA_PLATFORM=offscreen QT_SCALE_FACTOR=1.25 uv run python scripts/render_feature_headers_20261020.py --native-font --sample-calculators --all-pages --theme dark --output /tmp/headers-125
QT_QPA_PLATFORM=offscreen uv run pytest --collect-only -q --test-inventory=/tmp/foreground-followup-inventory.json
QT_QPA_PLATFORM=offscreen uv run pytest -n 2 -q -m 'not windows_integration' --junitxml=/tmp/foreground-followup-full.xml
```

첫 관련 검사 4개가 새 요청 로그와 과거 '자동 거절은 무로그' 기대 충돌로 실패했다. 중복 수동 로그를 하나로 통합하고 최신 요청별 진단 기준으로 갱신했다.
그 뒤 관련 **163 passed / 59.45초**, 기존 QA 재현 **17 passed / 12.22초**, 마지막 추가 검사 **6 passed / 6.49초**를 확인했다. 첫 전체 실행은 **1 failed / 2,347 passed / 446.28초**였다. 남은 실패는 `test_dialogue_transparent_occlusion.py`의 과거 자동 요청 무로그 기대였으며, 최신 요청 진단 요구로 갱신하고 실제 자동 tick 20회에는 로그 0개임을 추가 확인했다. 이 파일은 **20 passed / 1 deselected / 2.34초**로 통과했고, 제외는 원래 Windows 네이티브 표식이다. 전체 게이트를 다시 실행한 최종 결과는 아래에 기록한다.

## 버전·미검증 범위

비공개/공개 저장소에 v0.9.0 태그가 이미 존재함을 확인했다. v0.9.1 태그는 없었다.
새 기능 릴리즈 이후의 문제 수정·작은 UI 정리로 다음 패치 **0.9.1** 노트를 준비하고 이미 사용한 0.9.0 섹션은 보존했다.
태그/Release/workflow는 실행하지 않았다. 실제 Windows/NVIDIA 합성·장치 청취·듀얼모니터·절전/장시간 리소스는 미검증이다.
foreground가 실제 픽셀 노출을 완벽히 입증한다는 주장이 아니며, 승인된 소리 허가 기준을 구현한 것이다.
