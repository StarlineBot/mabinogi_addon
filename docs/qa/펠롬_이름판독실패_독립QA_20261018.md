## 1. Confirmed Bug / P2: 정확한 영역에서도 이름 미식별

- 발생 조건: 추가 5장의 펠롬 글자처럼 표시된 화면을 등록된 보스바 영역에서 읽는다.
- 사용자 영향: 보스 식별, HP 상태, 패턴 경고 추적이 시작되지 않는다.
  기존 펠롬 추적이 있었다면 이름 미식별이 계속돼 상태가 오래된 채 유지되다가 해제될 수 있다.
  크래시나 다른 보스 전체의 실패를 의미하지 않는다.
- 원인: `assets/boss/pellom/name.png`는 28x15 이진 이미지, 흰 픽셀 **30개**다.
  예전 원본 `2026-10-09 195115`의 밝기 이진 결과에는 점수 약 **1.0**으로 맞지만,
  새 원본 글자는 32x17, 흰 픽셀 **186개**의 선명한 획이다. 고정 크기 단일 템플릿의
  `TM_CCOEFF_NORMED` 최고 점수는 0.394343으로 채택 기준 0.6보다 낮다.
  단순히 보라색 바여서 실패한다고 단정하지 않는다. 확인된 것은 글자 이진 패턴 불일치다.
- 실행 경로: `detect/boss_name_matcher.py:23-80`에서 밝기 200 이진화 후 단일 템플릿 비교.
  `ui/boss_tab.py:416-446`은 `identify`가 None이면 HP 판독/확정 분기를 실행하지 않는다.
- 재현: 아래 스크립트의 이름 5조건, 실제 BossTab 신규 화면 조건.
  실제 `_tick()` 4회에서 캡처/좌표 경계만 대체하고 이름·HP·tracker 코드는 그대로 사용했다.
  예전 화면과 새 화면에 **동일한 저장 영역 (1018,1248,521,37)**을 사용한다.
- 검증: 예전 원본은 `pellom`, stable HP 47, tracker 있음으로 정상 대조군 통과.
  새 원본 001216은 독립 HP 판독 **87**인데 `_cur_boss=None`, `_last_raw_hp=None`,
  `_stable_hp=None`, tracker 없음으로 실패했다. 자동찾기는 이 실제 루프 재현에서 호출하지 않는다.
- 수정 검토 방향: 기존 흐린 글자와 새 선명한 글자 양쪽을 지원하는 템플릿/정규화를 검토하고,
  기존 보스·회한 접두어와 미등록 보스를 식별하지 않는 대조군을 유지해야 한다.
  전역 기준을 0.394 이하로 낮추거나 마지막 보스를 무조건 유지하는 우회는 권장하지 않는다.

## 2. Confirmed Bug / P2: 8.49% 원본의 저HP 숫자 판독 누락

- 발생 조건: 마지막 원본의 **위쪽 펠롬 HP바**를 정확하게 잘라 판독한다.
- 사용자 영향: 이름 판독을 고쳐도 이 원본은 정수 HP 8을 읽지 못한다.
  해당 프레임의 HP 갱신이 누락된다. 단일 정지 화면 결과이므로 저HP 전체 실패라고 확대하지 않는다.
- 원인: 저채도 마스크가 회색 배경까지 포함해 flooded 판정되고 밝기 보조 경로로 들어간다.
  보조 경로의 최선 값은 실제 정답 **8**, 점수 **0.417870**이지만 기준 **0.45** 미만으로 거부된다.
  `detect/boss_hp_reader.py:173-184,202-218`.
- 재현/검증: `test_upper_boss_hp_is_read[001801-8]`가 None != 8로 실패.
  이름 판독을 대체하지 않은 독립 숫자 판독이며, 다른 4개 HP 조건은 통과했다.
- 수정 검토 방향: 이 선명한 한 자리 숫자/저HP 배경을 회귀에 추가하고 전처리와 숫자 샘플을 검토한다.
  잘못 읽은 값을 허용하는 무조건 임계 하향으로 처리하지 않는다.

## 3. 별도 조건의 Confirmed Bug / P2: 저HP 중 자동찾기 오선택

이 항목은 **저HP 상태에서 사용자가 자동찾기를 실행할 때만**의 별도 결과다.
이미 올바르게 지정된 영역을 계속 읽는 이번 제보의 원인으로 사용하지 않는다.

- 조건/영향: 마지막 장에서 자동찾기를 실행하면 위 HP바 대신 아래 `어둠의 에르그`를 선택한다.
  잘못된 영역이 저장될 수 있다. 평상시 자동으로 영역을 바꾼다는 뜻이 아니다.
- 원인: `detect/boss_bar.py:26-70,155-200`의 긴 고채도 가로줄 후보와
  일반 이름 글자+퍼센트 검사에는 에르그 바 배제 조건이 없다.
  위쪽 바는 후보가 되지 못하고 아래 바는 검사를 통과한다.
- 재현/검증: `locate_boss_bar(image, make_validator())` -> `(1016,1280,521,37)`.
  실제 위쪽 `(1016,1246,521,37)`보다 세로 중심이 **34px** 낮다.
  `test_low_hp_autofind_never_selects_erg_bar`가 실패했다.
- 범위: 모듈 설명은 고HP 최초 설정을 가정하지만 실제 기능은 저HP 실행을 차단하지 않는다.
  찾지 못한다는 안전한 실패와 무관한 바를 성공으로 선택하는 것은 구분해야 한다.
  미등록 보스 지원은 유지하면서 이 보조 바를 배제할 방법을 검토한다.

## 한계와 전달

원본 정지 화면과 실제 판독 루프 재현이며 Windows 실게임 캡처, 소리 출력,
장시간 게임 진행과 사용자의 당시 저장 설정 전체는 실행하지 않았다.
그 제약과 별개로 정확한 ROI에서도 펠롬 이름 판독 실패와 HP 추적 미시작은 실행으로 확인했다.
사용자가 영역을 잘못 잡았거나 자동찾기를 반복하지 않아서 생긴 문제로 분류하지 않는다.
개발 세션은 1번을 우선 수정하고 2번의 독립 HP 실패도 확인해야 한다. 3번은 별도 실행 조건이다.
수정 후 이 스크립트와 기존 관련 회귀를 다시 실행한다. 현재 펠롬 QA를 통과로 보고하지 않는다.
