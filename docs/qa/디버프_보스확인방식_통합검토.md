# 디버프 보스 확인 방식 1~3차 통합 검토

- 검토일: 2026-10-16 (Asia/Seoul)
- 검토 소스: `2abc5f229b3f41548c83e20fbb750fbc92e3c090`
- 사용자 설명: 1차는 보스패턴알림이 없던 시기에 체력바 없이 항상 감시하도록 개발됐다.
  이후 보스 확인 수단이 추가되어 비교용으로 2~3차를 남긴 것이다.
- 상태: **설계 검토/개발 제안**이다. 새 요구사항 확정이나 통합 구현을 완료한 문서가 아니다.

## 1. 결론과 시점

세 방식은 서로 다른 디버프 식별기가 아니다. 같은 이미지 판독기에 보스 유무 판단만
다르게 붙인 것이므로, 일반 사용자가 계속 1~3차를 선택해야 할 제품상 이유는 약하다.
보스패턴알림이 추가됐다는 이유로 1차의 체력바 비의존 경로를 삭제해서는 안 된다.

**프라가라흐 숨김/재구성 잔여 문제를 정리한 뒤, 다음 베타에서 사용자 선택을 '자동'으로
통합하는 작업을 시작할 수 있다.** 모든 방법을 없애고 3차만 강제하는 통합은 권하지 않는다.
내부에서는 1차 아이콘 감시를 호환 경로로 유지하고, 가능한 보스 확인 정보를 보조로 활용한다.

사용자 본인의 평소 실전 테스트에서 아래 상태 전환을 확인하면 일반 화면의 1~3차 선택을
제거해도 된다. 날짜/릴리즈 횟수나 다른 다수 테스터 확보를 필수 조건으로 삼지 않는다.
보통 한두 번의 정상 전투 세션에 필요한 전환을 포함해 확인할 수 있으나 횟수 자체가
정확성 보증은 아니다. 자동 모드를 노출하기 전부터 긴 안정화 기간을 강제하지 않는다.

## 2. 현재 구조에서 확인한 것

| 방식 | 현재 의미 | 통합 후 역할 제안 |
| --- | --- | --- |
| off / 1차 | 보스 확인 없이 아이콘 감시 | 보스 영역 없음/자료 불확실 시 호환 경로 |
| band / 2차 | 디버프 ROI의 체력바 모양으로 부재 확인 | 기본적인 저비용 보스 상태 근거 |
| percent / 3차 | 공유 HP바 ROI의 숫자와 배경 상태 확인 | 유효한 영역이 있을 때 추가 확정 근거 |

- `tracker/debuff_engine.py:332`의 `_gate_absent()`는 숫자를 못 읽는 것과 보스 부재를
  같게 보지 않는다. 검은 바/애매한 상태에서는 아이콘 감시를 계속하는 보호가 있다.
- 보스바를 한 번도 확인하지 못했거나 3차의 별도 캡처가 `None`이면 현재도 1차처럼 동작한다.
- `ui/main_window.py:1370`의 디버프 시작은 보스패턴 기능 ON을 조건으로 삼지 않는다.
  3차는 공유 좌표를 사용하지만 자체 바 캡처를 만들므로 보스패턴알림 없이도 동작한다.
- `config.py:833`의 공유 좌표는 `bossPattern.box` 하나다. 좌표 공유와 보스패턴 기능
  활성화/대상 보스 식별은 서로 다른 조건이다.
- 현재 베타 로그인 조건 때문에 선택한 2/3차가 실제로는 1차로 실행될 수도 있다.
  `ui/debuff_tab.py:272`의 `effective_gate_mode()`를 고려해야 하며, 통합 후 진단에는
  선택값뿐 아니라 실제 사용 근거와 호환 동작 이유를 남겨야 한다.
- 보유 표본 비교는 2/3차 모두 보스 인식 9/9, 배경 4개에서 오탐 없음이었다.
  이 제한된 표본으로 3차가 더 우수하다고 결론 내릴 수는 없다.

## 3. 자동 모드의 판단 원칙 제안

1. **영역이 없다고 디버프를 끄지 않는다.** 보스패턴알림 OFF, 미지원/미식별 보스,
   보스바 미등록과 기존 아이콘 줄만 저장된 설정에서도 디버프 추적을 유지한다.
2. 유효한 체력바 모양이나 퍼센트가 보이면 보스 존재의 근거로 사용한다. 퍼센트 판독이
   아이콘 식별을 대신하거나, 알려진 보스 이름/패턴 목록에 있어야만 동작하도록 하지 않는다.
3. 숫자를 못 읽음, 캡처 실패, 검은 바, 전환, 영역 검증 미완료는 '불명'이다.
   이 이유만으로 적용된 항목을 전부 미적용으로 초기화하지 않는다. 아이콘 자체의
   감지/해제는 기존 안정화 규칙대로 계속 처리하며 무기한 상태 고정을 뜻하지 않는다.
4. 유효한 영역에서 보스 부재가 연속 확인됐을 때만 유예 후 리셋한다.
   별도 HP바는 배경인데 디버프 ROI에는 정상 바/아이콘이 보이는 등 근거가 충돌하면,
   '3차가 더 최신'이라는 이유로 일괄 리셋하지 말고 좌표/캡처 상태를 재확인한다.
5. 판단이 애매할 때 두 방식을 계속 갈아타며 엔진을 재생성하지 않는다.
   하나의 상태 관리 안에서 근거를 갱신해 검출 확인/재표시 타이머와 사라짐 경고를 보존한다.
6. 세 모드의 전체 이미지 검색을 매 틱 세 번 수행하지 않는다. 현재 단일 아이콘 검색과
   가벼운 바 확인을 유지하고 숫자 판독은 필요한 주기로 제한한다. 보스패턴 결과를 공유한다면
   동일 게임 창/현재 영역/유효 시점의 결과만 사용하고, 해당 기능이 꺼져도 독립 동작한다.

## 4. 통합 전 확인 조건

| 조건 | 필요한 검증 |
| --- | --- |
| 기존 설정 유지 | off/band/percent 및 예전 `debuffBarGating` 설정을 읽을 수 있음. 영역/순서/숨김/사용자 아이콘 보존 |
| 보스패턴알림 OFF | 디버프 단독으로 정상 동작. 보스패턴을 켜라는 필수 설정 추가 금지 |
| HP바 미등록 | 기존 수동 디버프 영역으로 계속 인식. 자동찾기 재등록 강요 금지 |
| 체력바/숫자 정상 | 기존 2/3차와 동등한 배경 오탐 방어. 같은 후보의 중복 검색 금지 |
| 낮은 HP/검은 바/가림 | 숫자 판독 실패만으로 미적용 전체 표시 또는 허위 사라짐 경고 발생하지 않음 |
| 보스 종료/교체/재등장 | 이전 보스 상태가 남지 않고 새 상태 확인. 일시 실패와 실제 종료를 구분 |
| 캡처 실패와 복귀 | `None`/예외/영역 변경 후 중복 워커·타이머 없이 복구 |
| 앱 재시작/기능 OFF-ON | 표시 설정과 디버프 종류 판정이 바뀌지 않음. 이번 숨김 재구성 재현도 통과 |
| Alt+Tab/복귀 | 게임 밖 사라짐 알림 억제 유지, 복귀 직후 허위 경고 없음 |
| 부하 | 기존 한 번의 검색 흐름 유지. 추가 반복 캡처/전체 영역 OCR/로그 폭증이 없음 |

오프라인에서는 저장된 원본과 위 상태 전환 재현, 관련 회귀, 정확한 수정 SHA의 자동 Windows
테스트/빌드를 확인한다. 실전에서는 사용자 본인의 정상 설정으로 보스 진입, 지속 적용,
낮은 HP, 종료/재진입, Alt+Tab 복귀와 보스패턴알림 OFF를 우선 확인하면 된다.
장시간 게임 FPS/리소스와 다양한 DPI는 남은 환경 범위를 명시하고 베타 위험에 비례해 확인한다.

## 5. 적용 순서

1. 이번 식별 수정의 숨김/재구성 문제를 수정하고 후속 QA를 받는다.
2. 다음 별도 변경에서 자동 판단을 구현한다. 1차 호환 경로와 진단용 기존 모드 강제 선택은
   내부/고급 영역에 잠시 남겨 비교와 복구가 가능하게 한다. 일반 사용자는 자동을 사용한다.
3. 자동 기능을 화면에 노출해 사용자 본인이 테스트할 수 있게 한다. 이미 영역을 세팅했다는
   이유로 새 베타 진입을 숨기지 않는다. 선택값과 실제 판단 근거는 진단에 기록한다.
4. 위 오프라인/실전 전환에서 문제가 없으면 일반 화면의 1~3차 선택을 제거한다.
   오래된 설정 값은 계속 읽되, 자동으로 옮기는 정책과 과거 선택 보존 여부를 명시한다.
5. 1차 아이콘 감시 자체는 오래된 코드라는 이유로 삭제하지 않는다. 고급 모드 선택을
   나중에 제거해도 보스바 불명/미등록에서의 비의존 동작은 유지한다.

이번 QA는 통합 코드를 구현하거나 해당 UI 변경을 승인한 것이 아니다. 보스 정보의 사용은
독립적인 디버프 감시를 보완하는 방향이며, 기능 간 강제 의존성으로 바꾸는 작업이 아니다.
