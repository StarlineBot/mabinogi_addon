## Confirmed Bug: DORCHA-QA-01

- 심각도: **P2**, 기능이 앱 재시작 전까지 갱신되지 않는 상태. 앱 전체 크래시로 확인한 것은 아니다.
- 조건: 도르카 수동 영역 지정 창을 열고 `QWidget.close()`에 해당하는 일반 창 닫기로 종료한다.
  Windows에서는 Alt+F4 등의 창 닫기 경로를 추가 확인해야 한다. 정상적인 창 닫기를 사용자 오조작으로 취급하지 않는다.
- 기대: 취소와 동일하게 이전 영역을 유지하고 판독을 재개한다.
- 실제 사용자 영향: 판독 타이머가 멈춰 도르카가 숨겨진 채 갱신되지 않는다.
  기능 OFF/ON 및 영역 창 재진입 후 Escape로도 복구되지 않았다.
- 기술적 원인: `ui/dorcha_tab.py:206`에서 실행 상태를 기억하고 `:207`에서 타이머를 정지한다.
  `:210`/`:211`의 selected/cancelled 연결에서만 재개하며, 공용 `ui/region_selector.py`에는
  일반 closeEvent를 cancelled로 전달하는 처리가 없다. `:214`의 Escape 경로만 취소 신호를 낸다.
  재진입하면 이미 멈춘 상태를 다시 기억하므로 이후 Escape도 타이머를 시작하지 못한다.
- 재현 방법: 아래 스크립트를 실행한다. 실제 RegionSelector 위젯의 closeEvent·Escape·QTimer를 사용한다.
  사용자 설정 저장과 실제 데스크톱 캡처만 격리했다.
- 검증 결과: **3 failed, 3 passed (최종 기준 0.40초)**.
  일반 닫기 / 닫기 후 OFF·ON / 닫기 후 재진입·Escape 3건 실패.
  최초 Escape 취소 / 정상 선택 / 종료 후 늦은 취소가 타이머를 살리지 않는 대조군 3건 통과.
- 검증 한계: Linux Qt offscreen에서 일반 closeEvent를 실제 실행했다.
