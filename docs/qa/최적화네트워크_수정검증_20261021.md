# 최적화 네트워크 라이브 QA 후속 수정·개발 검증

2026-10-21. 수신 QA `0daf55b`, 제품 기준 `4ca6763`.
[독립 QA](최적화네트워크_관리자실행실패_QA_20261021.md)의 GUID 계약 결함과 오류 정보 유실을 수정했다.
라이브 PC에서 실패한 최종 원인을 직접 관측한 것은 아니며 Windows 실사용 해결 확인과 구분한다.

## 재현과 수정

수정 전 원본 명령에서 **2 failed, 2 passed** (0.07초)를 직접 확인했다.
중괄호 포함 GUID와 서로 다른 명령 실패가 구분되지 않는 assertion이 실패했다.

- 목록의 GUID는 기존대로 UUID로 검증·정규화한다. 후속 PowerShell 조회도 `[guid]::TryParse`로
  장치 GUID를 구조적으로 파싱하여 같은 `[guid]` 값과 비교한다. 표시 이름·첫 장치로 대체하지 않는다.
  잘못된 입력은 거부하며 선택 장치 없음·중복 일치는 구분하여 실패한다. 목록 중복도 거부한다.
- TCP/RSS 읽기·쓰기·재연결은 같은 `_adapter()`를 공유한다. schema 1 복구 기록을 유지하며
  기존 원본 값 부재도 명시적 복구 시 복원한다. 기록 삭제나 전체 관리자 강제 실행은 추가하지 않았다.
- Windows 명령 오류는 작업/항목·오류 분류·프로세스 반환 코드·가능한 네이티브 코드/HRESULT와
  제한된 오류 지문으로 전달한다. PowerShell의 catch는 불변 분류와 숫자만 출력한다.
  장치 없음/중복·명령 없음·권한 부족·미지원·일반 실패·시간 초과·응답 형식 오류를 구분한다.
  네이티브 레지스트리 오류도 경로를 제거한 분류/코드로 전달한다.
- UTF-8 출력과 BOM/UTF-16 stderr를 처리한다. 공개 예외에 원문·스크립트·장치명·GUID·사용자 경로를
  넣지 않는다. 원문 보관 대신 최대 64 KiB 입력으로 12자리 SHA256 지문만 계산한다.
  이 지문은 같은 안전 진단을 대조하기 위한 것이며 원본 Windows 상세 문장을 복원하는 로그는 아니다.
- 복구 계층은 원본 조회·적용값 확인·원복 전/후 확인 단계를 오류에 붙인다. 일부 실패 뒤에도
  autotuning이 이미 일치했는지 또는 적용값을 확인했는지 따로 표시한다. 중단 후에도 결과를 보존한다.
  실패를 전체 성공으로 표시하거나 게임/접근/중단 보호를 제거하지 않았다.
- 원격에서 `v0.10.0` 사용을 확인했으므로 수정 노트는 미사용 `v0.10.1`로 준비했다.
  태그·워크플로·Release·웹훅은 실행하지 않았다.

## 재현 이관과 회귀

- 원본 QA의 GUID 사례 3개 → `test_support/regressions/optimization_network.py`와
  `tests/test_optimization_network.py`. 원본은 **제거된 문자열 조건만** 평가하는 제한 모델이며
  조건이 바뀌면 실패하도록 명시돼 있었다. 그 정규식을 새 계약에도 통과시키지 않고,
  정규화 입력/구조적 비교/선택 개수 거부 조건을 검사하는 계약으로 교체했다.
  실제 PowerShell 의미는 아래 Windows 실행 검사로 별도 검증한다. 기존 QA의 실패 기록은 유지했다.
- 오류 구분 사례 1개 → 같은 공통 회귀로 이관하여 원본 구분 assertion을 유지했다.
- `scripts/qa_optimization_network_identity_20261021.py`는 호환 실행 진입점이다.
  정식 CI는 `tests/`만 수집하여 역사 진입점과 중복하지 않는다.
- 추가 회귀: 복수/중복/잘못된 GUID, 모든 네트워크 경로의 동일 선택 기준, v0.10.0 journal 원복,
  UTF-8/UTF-16 오류, 개인 정보 비노출, timeout/실행 실패/손상 출력, 레지스트리 권한 오류,
  원본/확인/원복 실패 단계와 기록 보존, TCP 부분 실패와 autotuning 별도 결과.
- `tests/windows/test_native_optimization.py`에 실제 Windows PowerShell로 합성 장치의
  중괄호/대소문자·없음·중복·교체·잘못된 GUID를 판정하는 검사를 추가했다.
  실제 물리 어댑터 목록 → 선택 GUID 조회도 추가했다. 장치 변경/재시작은 실행하지 않는다.

## 미검증과 후속

Linux 환경에 PowerShell이 없어 실제 Windows 셸 검사는 여기서 실행하지 않았다.
실제 게임/네트워크 적용·권한·재연결·부분 실패·원복·장시간 동작과 exe 빌드도 미실행이다.
Windows 검사는 추가한 소스만 검토했으며 통과로 보고하지 않는다.
수정 푸시 후 후속 독립 QA에서 재현과 새 진단을 확인해야 한다. 이번 단계에서 배포 명령을 제공하지 않는다.
