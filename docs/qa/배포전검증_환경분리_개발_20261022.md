# 배포 전 검증 환경 분리 개발 기록

## 요청과 확인된 현상

- 사용자는 완성 배포 파일의 라이브 확인은 직접 하되, 그 전의 일반 검증은 개발 PC의
  OS·장치·권한에 영향받지 않고 실행하기를 요청했다.
- `39701216844`, 소스 `5cce8893261f51225c8d8417c62a1ee0081fc256`에서
  Isolated regression이 장기 정체됐고 exe 빌드는 시작하지 못했다.
  사용자가 취소했으며 API에서도 `completed/cancelled`를 확인했다.
- 내부 25분/단계 28분 상한이 지난 시점에도 API가 실행 중을 보고했다.
  취소 후에도 job 로그 API는 BlobNotFound(404)였다. 정확한 정체 사례/원인은 미확정이다.
  이전에 소스로 재현한 콘솔 포화/오류 통지 결함을 이번 정체의 확정 원인으로 쓰지 않는다.

## 구현

1. `windows.yml`의 일반 전체 회귀를 Ubuntu 24.04·Python 3.12·잠금 의존성의
   `regression` 작업으로 옮겼다. 기존 전체 `not windows_integration` 수집과 2-worker,
   외부 경계·임시 설정·종료/누수 assertion은 보존한다. 기능 묶음 선택/실패 skip은 없다.
2. Linux 전체 성공과 깨끗한 소스 검사를 통과한 JUnit을 같은 run/attempt 이름으로 저장한다.
   Windows 2022 `validate`는 이 작업에 의존하고 같은 실행의 보고서만 가져온다.
3. Windows 필수 경로에는 실제 windows Qt의 메인 창 최소 기동/렌더/종료 검사와 exe 빌드를 둔다.
   새/기존 사용자 설정을 임시 경로에 격리하고 장치/통신을 대체한다. 추적/폴링은 시작하지 않는다.
   **소스 창 기동 검사이며 완성 exe 실행·장치 통합 검사가 아니다.**
4. 기존 `windows_integration` 전체 사례는 변경/삭제하지 않고 `windows-native.yml`에서
   수동 실행하도록 보존한다. 게시를 하지 않으며 OS/API 변경 때 선택 실행할 수 있다.
5. 배포 게이트가 `regression`/`validate` 각각의 필수 단계를 확인하도록 변경했다.
   한 작업의 성공 단계로 다른 작업의 누락을 덮지 못한다. 실패/생략/중복 작업도 차단한다.
6. 후보 schema 2와 `linux-regression-windows-smoke-v1` 프로필로 이전 후보와 구분한다.
   파일 목록·각 해시·SHA·attempt·버전·승인·만료/용량 정책·초안 재다운로드 검증은 유지한다.
   `windows-results.xml`은 이제 최소 창 기동 결과다. 이전 후보는 새 방식에서 재검증해야 한다.
7. `verify-only` 무배포와 사용자 한 번 승인 뒤 동일 exe 자동 게시 흐름은 유지한다.
   앱 소스·버전·릴리즈 노트는 변경하지 않는다. 에이전트가 배포 workflow를 실행하지 않는다.

## 제한과 비용

- Linux 회귀 내부 전체 900초/단계 17분/작업 20분, Windows 최소 기동 90초/단계 3분,
  빌드 단계 20분/작업 30분, 선택 네이티브 내부 600초/단계 12분/작업 15분이다.
- 러너 배정·취소 전파·GitHub API 장애는 애플리케이션 코드로 제거할 수 없다.
  개발 PC와의 분리이지 모든 외부 환경 장애가 사라진다는 보장이 아니다.
- 대규모 회귀의 Windows 분량을 줄이고 캐시는 추가하지 않았다. 중간 JUnit/진단은 1일,
  후보는 기존 1일·최대 2개·각 200MiB다. 계정 무료 한도 미초과는 보장하지 않는다.
- 실제 Actions 연결, Windows Qt/빌드, 배포, 실게임, 소요 시간 개선은 아직 실행하지 않았다.
  후속 독립 QA 통과 보고가 아닌 수정 개발 기록이다.

## 개발 검증

- Linux 표적 검사: 분리 구조·출처/승인·기동 검사 198건 통과(후속 부정 사례 추가 전).
- 추가 부정 사례: 작업 누락/중복/실패/단계 이동, 구형 schema/다른 프로필/프로필 누락을 차단한다.
- 전체 Linux 격리 회귀: **2,559건 통과, 495.65초**, 감독 exit 0. 기존 toast Qt API 사용에
  대한 DeprecationWarning 3건이 남았고 실패/오류/skip은 0건이다.
- 전체 수집 뒤 마지막에 추가한 workflow-게시 계약 일치 검사 1건을 포함해 최종 표적 검사
  **213건 통과, 11.29초**. 두 실행의 고유 실행 사례 합계는 현재 일반 회귀 2,560건과 일치한다.
- 최종 수집 2,588건 중 기존 선택 네이티브 28건은 그대로 보존했다. 정확 중복은 0건이다.
- 실행 명령(저장소 루트, Linux):

  ```bash
  PYTHONPATH=src:.:tests QT_QPA_PLATFORM=offscreen uv run --frozen python -m scripts.run_regressions --diagnostics /tmp/ci-split-full-20261022 --case-timeout 180 --session-timeout 900 -- -n 2 -q -m 'not windows_integration' --durations=15 --tb=short --test-inventory=/tmp/ci-split-inventory-20261022.json --junitxml=/tmp/ci-split-results-20261022.xml
  PYTHONPATH=src:.:tests QT_QPA_PLATFORM=offscreen uv run --frozen python -m pytest tests/test_startup_smoke.py tests/test_release_candidate.py tests/test_windows_ci.py -q --tb=short
  ```

  실제 실행은 준비된 `.venv/bin/python`으로 수행했다. Windows 최소 기동/빌드와
  Actions의 두 OS 작업 연결·실제 게시·단축 소요 시간은 이 Linux 결과로 대체하지 않는다.

## 안내 지침 후속

사용자 요청에 따라 `AGENTS.md`/`CLAUDE.md`에 다음 행동 안내를 명시했다.
상태만 보고 끝내지 않고, 사용자 조작이 필요하면 조작 후 알려줄 내용과 그 뒤 에이전트가
수행할 일을 함께 안내한다. 답이 필요 없으면 직접 수정/검증을 계속하고 사용자의 추가 행동이
없음을 알린다. 취소 요청 뒤 보고가 필요한지 모호하게 남겨두지 않는다.
