## Confirmed Bug: DORCHA-REACQUIRE-QA-03

### 심각도와 조건

- 심각도 **P2**. 실제 자원과 다른 값을 현재 잔량으로 표시하는 상태 오류다.
  앱 크래시나 입력 방해로 확인한 문제는 아니다.
- 조건: 재탐색으로 도르카 위치를 찾은 뒤 게임 창이 다른 곳으로 이동하고, 게임 밖이 된 옛
  숫자 위치에 판독 가능한 별개의 글자가 남는다. 새 게임 화면의 정상 도르카도 보이는 상태다.
- 게임 창을 옮긴 조작은 재현 조건이며 사용자 과실로 취급하지 않는다.

### 기대와 실제 사용자 영향

- 기대: 현재 게임 창의 식별/범위와 맞지 않는 추적 영역은 무효화하고 새 게임 영역에서 다시 찾는다.
  옛 위치의 게임 밖 숫자를 현재 자원으로 표시하지 않는다.
- 실제: 현재 게임의 도르카가 **0**인데 앱은 게임 밖 옛 위치의 **15**를 표시한다.
  옛 위치가 판독 가능한 동안 재탐색 진입도 하지 않아 잘못된 잔량이 유지될 수 있다.

### 재현과 결과

`scripts/qa_dorcha_stale_game_roi.py`는 원본의 실제 장식/숫자 크롭으로 가상 데스크톱을 구성한다.
실제 DorchaTab/숫자 판독/앵커 검출/QThread/Qt 이벤트 루프를 실행하며 캡처와 OS 대상 조회만 대체한다.

1. 게임 창 `(0,0,260,180)`에서 내부 숫자 `(150,90)`의 도르카 15를 재탐색으로 찾는다.
2. 같은 게임 창을 오른쪽 `(300,0,260,180)`으로 옮긴다. 새 내부 숫자 위치는 `(450,90)`, 값은 0이다.
3. 새 게임 화면 전체에 실제 검출기를 직접 실행해 새 위치와 숫자 0이 검출됨을 먼저 확인한다.
4. 옛 `(150,90)`에는 **장식 없이 숫자 15 글자만** 남긴다. 이는 실제 이동 후 화면을 촬영한 것이 아니라
   다른 내용이 옛 영역에 남는 조건을 명시적으로 구성한 입력이다.
5. 판독 루프를 3회, 회당 200ms Qt 이벤트 처리와 함께 실행한다.


- 새 결함 재현 1건 실패, 빈 옛 위치 대조군 1건 통과.
  기존 이동 재현의 애플리케이션 이벤트 루프 어댑터 1건과 합동 실행은 **1 failed, 2 passed (4.62초)**다.
