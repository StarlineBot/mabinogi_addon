# 배포 시간·균열 자동 조회·공통 헤더·잡담 가림 개발 검증

대상은 [통합 전달문](배포시간단축_균열시세자동조회_화면헤더통일_개발전달_20261020.md)의 네 요청이다.
기준 소스 `9e5d14f` 위에서 개발했다. 이 문서는 개발 검증이며 후속 독립 QA 또는 Windows 통과 보고가 아니다.
공개된 v0.8.0은 유지하고 새 사용자 기능을 포함하는 미공개 v0.9.0 노트를 준비했다. 태그·배포·Windows workflow는 실행하지 않았다.

## 구현과 남은 확인

| 항목 | 이번 변경 | 남은 확인 |
| --- | --- | --- |
| 배포 시간 | 기존 Windows 격리 회귀만 pytest-xdist 2개 worker. 네이티브·빌드·승격 순서와 실패 게이트 유지 | 같은 Windows 실행의 전체 시간·메모리·불안정 실패. 공개까지 15분 목표는 미확인 |
| 균열 시세 | 선택/만료 후 재클릭 자동 조회, 성공·정상 매물 없음 10분 세션 캐시, 강제 새로고침 | 실제 Windows UI/API 응답 확인 |
| 공통 헤더 | 승인된 제목 → 회색 설명 → 구분선, 기존 도움말 우측 정렬 | Windows 실제 DPI/테마 확인 |
| 잡담 가림 | 확인된 가림 및 불확실 노출에서 표시·소리·추첨 차단, 표시 중 가림은 기존 1초 확인에서 중단 | **NVIDIA 등 불확실한 per-pixel 합성 창 때문에 보이는 잡담이 막히는 제약은 미해결** |

## 시세 조회의 상태 경계

`DungeonCostTab._select()`만 자동 요청을 판단한다. 초기 크롬바스 심연 및 고정 가격 세 던전에는 요청하지 않는다.
같은 항목의 선택/클릭 중복 이벤트, 조회 중 이탈·복귀, 새로고침 연타는 진행 중 요청 하나를 공유한다.
수신 시각의 monotonic 기준 600초 미만인 성공/정상 빈 결과만 재사용한다. 만료 후 클릭 또는 새로고침으로 다시 조회한다.
새 요청은 이전 캐시·가격을 비우고, 키 없음/오류는 캐시하지 않는다. 응답 처리나 렌더에서 자동 재시도하지 않는다.
늦은 응답은 균열 캐시에 반영하되 현재 고정 가격 표/선택은 유지한다. 기존 비동기 작업·30초 제한·취소 플래그를 유지하며 종료 뒤 수신은 무시한다.
API 키·가격을 새로 영구 저장하거나 주기 조회하지 않는다. 기존 개당가 산술과 모든 행의 동일 가격 기준을 보존한다.

기존 실제 worker 반복·종료 검사를 유지하고 `tests/test_dungeon_cost.py`에 fake worker/시계로
599.999초/600초 경계, 강제 조회 후 실패, 키 없음 복구, 매물 없음 캐시, 중복/늦은 응답, 종료 경계를 추가했다.
기존 오류 뒤 재선택 기대는 최신 자동 재조회 요구에 맞췄으며 고정 가격·소모량·계산·정리 assertion은 유지했다.

## 승인 배치와 전체 적용 목록

대표 실제 위젯 비교 렌더 공유 뒤 사용자 답변 **“이 기준으로 적용”**을 받아 전체에 적용했다.
공통 `ui/widgets.py:FeatureHeader`와 기존 `tab_header()`를 사용한다. 본문 대비 제목 크기는 14/12 비율이며
설명은 테마의 PlaceholderText, 선은 Mid 역할을 따른다. 기존 도움말 동작·본문 값·스크롤·설정 저장을 보존한다.

| 범위 | 적용 |
| --- | --- |
| 전투 보조 | 버프, 디버프, 보스 패턴, 보스 하위 1분 헤일로, 체력바, 도르카·투아림, 커스텀 오버레이, 단축바, 메모 |
| 편의기능 | 분배, 구슬 분배, 환전비율, 던전 입장 계산기 |
| 파티 모집 | 기능 제목·요약·구분선과 기존 도움말 |
| 예외/기존 경로 | 설정의 제작자·문의·계정 전용 배치 유지. 숨겨진 기존 투아림 탭은 공통 tab_header 경로. 별도 커서 오버레이 탭은 현재 탐색 구조에 없음 |

기존 체력바/커스텀 등의 독립 제목과 선을 중복하지 않는다. 경고·영역 조건·API 지연·실시간 상태 안내는 본문에 유지한다.
헤더 반영 후 기존 작은 화면 접근성 검사에서 하단 얼굴이 창 밖으로 밀리는 결함을 확인했다.
원인은 `CreatorDialogue.refresh()`가 레이아웃 재계산 중 중앙 폭을 고정 저장한 것이었다.
일반 하단 영역의 폭을 레이아웃에 맡기고, 기존 부유 얼굴 76px 배치는 유지했다. 얼굴 접근성 assertion을 완화하지 않았다.

## 가림 차단과 기술 제약

`display_available()`이 기존 native 노출 검사를 사용하고 진단에 exposed/occluded/unknown을 구별한다.
불투명 가림과 불확실 합성은 모두 표시 허가를 주지 않는다. alpha 0·cloaked·대상 밖 region 등 확인 가능한 비가림은 허용한다.
포그라운드를 요구하거나 옮기지 않으므로, 다른 모니터에서 보이는 비활성 앱도 확인된 노출이면 동작한다.
새 캡처·고속 폴링·창 이름 예외·타이머·로그 반복을 추가하지 않았다. 기존 GDI region 해제를 유지한다.
표시 중 가림은 기존 1초 tick에서 말풍선과 전용 50% 재생을 중단하며, 복귀 때 지난 문장/소리를 재생하지 않는다.

**가림 차단만으로 NVIDIA 문제까지 해결했다고 판단하지 않는다.** 현재 Win32 경로가 타 프로세스의
모든 per-pixel 합성 투명도를 확인할 수 없으므로, 투명하지만 판정이 불확실한 창이 겹치면 보이는 클릭/자동 잡담도 막힐 수 있다.
이 부분은 이번 소스에서 해결되지 않았고 실제 Windows/NVIDIA 조건 검증도 실행하지 않았다.
이 제약을 숨겨 완료 처리하거나 불확실한 노출에서 소리를 허용하지 않는다.

기존 정책 검사의 가림 허용 기대를 최신 요구로 갱신했다. 비활성·포커스 비간섭·수명 검사는 확인된 alpha 0에서 유지하고,
불투명/불확실 × 클릭/자동, RNG/횟수/소리 0회, 다음 tick 중단, 무음 복귀, 대상 밖 가림을 추가했다.
기존 QA 재현 `scripts/qa_dialogue_covered_sound_20261020.py`의 4개 사례는 같은 조건을 유지한 최신 수락 검사다.
원래 독립 QA의 실패 관찰 기록은 수정하지 않는다.

## 병렬화·검사 보존·실행 결과

개발 의존성에 pytest-xdist를 추가했다. 격리 pytest 명령만 `-n 2`이며 네이티브는 직렬이다.
worker별 프로세스·tmp_path와 기존 외부 경계/설정 복구/QThread 누수 검사를 사용한다.
전체 Windows 게이트에 기능별 선택 옵션이나 추가 skip/retry를 넣지 않았다. 새 Windows matrix/job·캐시/산출물 증가는 없다.

동일 Linux 환경의 관련 4개 파일 직렬/2-worker 비교는 [측정 JSON](assets/feature_headers_20261020/related-benchmark.json)에 남긴다.
두 JUnit의 `(classname, name)` 목록을 정렬 대조하고 중복 없이 같은 사례 hash인지 확인했다.
최종 같은 대상 85개는 두 방식 모두 통과했고 프로세스 시작부터 종료까지 직렬 18.64초, 2-worker 11.06초였다. 사례 hash는 두 실행 모두 `a8151610c0e036649d2196a9a97c23375c3307f87bf30ada486f91c5fc4ed2ea`다. Linux 측정은 Windows 시간 보장이나 Windows 네이티브/빌드 성공 증거가 아니다.

관련 검사 위치: `test_dungeon_cost.py`, `test_dialogue_display_policy.py`, `test_navigation_all_widths.py`, `test_windows_ci.py`.
새 독립 QA 파일을 CI에 중복 등록하지 않고 기존 기능 묶음에 추가했다. 기존 회귀 삭제/skip/assertion 약화는 없다.
최종 전체 수집·실행 결과는 아래에 별도로 기록한다.

- 전체 Linux offscreen 회귀: **2,300 passed, 3 warnings, 453.72초**. 경고는 기존 `test_toast.py`의 QMouseEvent 생성자 deprecated 3건이다.
- `--test-inventory` 전체 수집은 2,315개, Windows 네이티브 표식은 15개다. 나머지 2,300개와 전체 JUnit 사례를 대조해 누락·중복·추가 0개를 확인했다. [수집 대조 요약](assets/feature_headers_20261020/full-inventory-check.json).
- 전체 실행을 시작한 후 팔레트/글꼴 검사와 native API 실패 진단을 보강했다. 변경 관련 33개는 별도로 다시 통과했고 최종 관련 직렬/병렬 비교에도 포함했다. 헤일로 기존 제목도 유지했다.
- 기존 가림 재현의 최신 수락 검사 4개 통과. Windows 실제 청취를 수행한 결과는 아니다.
- workflow actionlint 및 `git diff --check` 통과. Windows 네이티브 15개·exe 빌드·배포는 실행하지 않았다.
- 전체 실행 중 진단 렌더/관련 검사도 수행했으므로 이 전체 Linux 시간은 성능 전후 비교 자료로 사용하지 않는다. 관련 직렬/병렬 비교는 별도 실행했다.

```bash
QT_QPA_PLATFORM=offscreen uv run pytest -n 2 -q -m 'not windows_integration' --junitxml=/tmp/followup-full.xml
QT_QPA_PLATFORM=offscreen uv run pytest --collect-only -q --test-inventory=/tmp/followup-inventory.json
QT_QPA_PLATFORM=offscreen PYTHONPATH=src:.:tests uv run pytest scripts/qa_dialogue_covered_sound_20261020.py -q
# 아래 동일 대상에서 N=0과 N=2의 JUnit 사례 목록·중복·시간을 각각 비교한다.
QT_QPA_PLATFORM=offscreen uv run pytest tests/test_dungeon_cost.py tests/test_dialogue_display_policy.py tests/test_navigation_all_widths.py tests/test_windows_ci.py -n N -q --junitxml=/tmp/related-N.xml
```

후속 독립 QA에는 이 네 변경과 얼굴 폭 수정, 캐시/오류 전환을 확인하고 실제 Windows/NVIDIA 제약을 별도 판정하도록 전달한다.
현재 개발 결과만으로 NVIDIA 미표시 해결 또는 배포 준비 완료를 선언하지 않는다.
