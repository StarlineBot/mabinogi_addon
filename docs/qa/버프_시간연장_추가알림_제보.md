# 버프 시간 연장 시 추가 알림 제보

검증일: 2026-10-15. 소스: `c6ef92605ba8852816e49d8831835f3e7569aaf3`.
커밋 이력은 조회하지 않았다. 현재 버프 엔진, 상태 머신, 컨트롤러의 로컬 파일이
해당 원격 트리와 동일한 Git blob임을 대조했다. 제품 코드는 수정하지 않았다.

## 제보와 현재 판단

- 다른 테스터가 버프 **연장(갱신/재시전 아님)** 때 알림이 한 번 더 울린다고 제보했다.
- 대표 테스터인 사용자는 예전 수정 이후 같은 현상을 겪지 않았다.
- 사용자는 연장 대상이 전장의 서곡, 비바체, 행진곡 셋 중 하나일 것으로 설명했다.
  정확히 어느 버프인지는 제보자에게 듣지 못했다. 특정 연장 스킬을 사용했다고 단정하지 않는다.
- 정확한 버프 이름, 연장 수단, 버전, 연장 전후 남은 시간, 1차/2차 알림 설정,
  추가 알림이 연장 직후인지 연장 후 다음 임박 시점인지는 아직 확인되지 않았다.
- 사용자 구분을 존중한다. 코드에서 시간 증가를 `EXTENDED`로 처리한다고 해서 실제
  게임에서의 시간 추가와 재시전을 같은 조작이라고 간주하지 않는다.
- **제보된 라이브 버그는 미확정**이다. 기존 방어가 사라졌다는 근거도 없다.
  아래 제한된 알림 경계 조건만 독립 입력으로 재현했으며 제보 원인으로 확정하지 않았다.

## 실제 확인 결과

실제 `BuffEngine`과 `BuffStateMachine`을 사용했다. 아이콘은 고정 테스트 패턴을
실제 매칭하고 시간 판독 반환값만 주입했다. 게임 캡처/OCR 정확도나 Windows 음성
재생을 재현한 것은 아니다. 버프를 없애거나 다시 걸지 않고 남은 시간에 60초를 더했다.

1. 40초 시작 -> 30초에서 1차 알림 -> 남은 28초에 60초 추가 -> 88초:
   연장 직후 추가 알림 없음. 이후 연장된 시간이 30초에 도달하면 정상적으로 다시 알림.
2. 기존 분 단위 유실 방어 시나리오(30초 알림 후 28 -> 30 -> 실제 90초로 복구):
   즉시 중복 알림 없음. 기존 방어 경로가 현재도 작동함.
3. 연장된 시간을 처음 읽은 틱과 알림 기준 교차가 겹치는 경우:
   새 시간 확정 대기 중 이전 시계로 알림 요청을 생성함. 아래 위험 항목에 해당.

## Potential Risk / P2 / BUFF-EXTEND-QA-01

### 조건과 사용자 영향

게임이 포그라운드이고 유효 프레임이며 아이콘도 계속 보인다. 1차/2차 기준은 30/10초.
실제 연장으로 남은 시간이 늘어난 첫 판독이 1차 또는 2차 기준에 도달하는 틱과 겹친다.
사용자는 연장이 이미 됐는데 종료 임박 소리를 들을 가능성이 있다.

### 재현한 요청 순서

| 앱 시각 | 공급한 남은 시간 | 내부 시계/후보 | 생성된 요청 |
|---:|---:|---|---|
| 0.0 | 40 | 정상 시작 | 없음 |
| 0.2 | 39.8 | 정상 시계 확인 | 없음 |
| 10.0 | 30 | 30 | 1차 |
| 29.8 | 10.2 | 10.2 | 없음 |
| 30.0 | 70 | 이전 시계 10.0, 연장 후보 70 | **2차** |
| 30.05 | 69.95 | 연장 확정, 시계 69.95 | 없음 |

동일하게 첫 알림 경계에서 40초 버프가 30 -> 90초로 연장돼도, 첫 후보 틱에는
이전 30초 시계로 1차 요청이 나온다. 이는 '이미 소비한 1차를 무조건 재무장해서
즉시 두 번 울림'과는 다르다. 특히 표의 추가 요청은 기존 1차의 복제가 아닌 2차다.

### 기술적 원인과 위치

- `src/mabinogi_addon/tracker/buff_state.py`의 `_anchor`: 상향 판독을 두 번 확인하기
  전에는 기존 시계를 유지한다. 단발 상향 오독을 방어하는 동작 자체는 필요하다.
- 같은 파일의 `_on_detected` / `_check_alert`: 상향 후보 대기 중에도 기존 시계로 1차 판단.
- 같은 파일의 `check_second_alert`: 상향 후보 여부를 보지 않고 기존 시계로 2차 판단.
- `src/mabinogi_addon/tracker/engine.py`의 `tick`: `observe` 직후 `check_second_alert` 호출.
- `src/mabinogi_addon/ui/buff_controller.py`의 `_Worker._tick_once`: 결과의 `alerts`와
  `alerts2`를 각각 시그널로 전달. 실제 앱은 버프 추적을 50ms 간격으로 시작한다.

### 분류 제한

위 요청 생성 경로는 실제 실행으로 확인했다. 다만 제보의 버프/임계/입력/버전을 모르고,
첫 상향 판독을 확정 전까지 어떻게 취급해야 하는지의 지연 허용 정책도 명확하지 않다.
따라서 라이브 제보를 `Confirmed Bug`로 분류하거나 과거 수정의 재발로 단정하지 않는다.
일반 연장 후 다음 임박에서 다시 울리는 정상 재알림과도 구분해야 한다.

## 후속 확인

버프 이름/연장 수단과 연장 전후 시간, 추가 알림의 시점, 2차 알림 사용 여부가 있으면
위 경계 조건인지 다른 판독/상태 문제인지 좁힐 수 있다. 사용자에게 초기화나 재설정을
요구하지 않는다. 수정 시 연장 후보 때문에 정상 만료 알림을 계속 미루지 않는지,
단발 상향 오독과 정상 연장 후 다음 알림이 보존되는지 함께 검증해야 한다.

Windows 실제 소리 횟수, 제보자의 배포본/설정, 라이브 연장 입력과 장시간 실행은 미검증이다.
이 문서는 추가 제보의 예비 분석이며 전체 앱 QA 통과 또는 릴리즈 승인 자료가 아니다.
