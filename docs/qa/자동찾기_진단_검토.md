## AUTO-DIAG-01 / Confirmed Bug / P2

**처음부터 필수 템플릿이 없는 실행을 ZIP 재실행 완료로 표시한다.**

- 발생 조건: 버프 앵커 로드가 실패해 `anchor_template()`이 `None`을 반환하거나,
  보스/디버프 숫자 템플릿이 비어 있는 상태에서 자동찾기 -> ZIP 저장 -> 재실행을 수행함.
- 사용자 영향: 검출 준비 실패를 정상적인 미검출 재현으로 해석할 수 있다. 템플릿 누락을
  해결하기 전에 검출 점수나 화면 조건을 분석하게 만들 수 있다.
- 기술적 원인: `detector_assets()`가 빈 dict를 반환하면 기록의 `asset_names=[]`가 된다.
  `replay()`는 이 이름 목록에 있는 이미지의 누락만 검사하므로 검사를 통과한다.
  검출 반환값과 기록 값이 모두 `None`이면 `replayed=true`, `matches_recorded=true`가 된다.
- 요구사항: [자동찾기 진단 문서](../자동찾기_진단.md)의 재실행 절은 입력 또는 필수
  템플릿이 없으면 `replayed:false`를 반환하도록 정의한다.
- 재현 방법: 실제 화면 `tests/data/스크린샷 2026-10-09 190901.png`가 정상 템플릿으로
  검출되는지 먼저 확인한다. 동일 화면에서 앵커 로드를 `None`으로 또는 숫자 템플릿을
  `{}`로 구성한다. 실제 기록 -> 저장 -> ZIP 내보내기 -> `replay()`를 실행한다.
- 검증 결과: 버프·보스·디버프 세 경우에서 모두 재현했다. 정상 템플릿에서는 결과가
  있었고, 누락 상태에서는 `asset_names=[]`, `replayed=true`, `matches_recorded=true`였다.
  버프 trace는 `missing_anchor_template`, 보스/디버프는 실제 보스 후보의
  `percent_unreadable`을 표시했다.
- 코드 위치: [autofind_replay.py](../../src/mabinogi_addon/autofind_replay.py)의
  `detector_assets()`(19행), `replay()`의 누락 검사(84행)와 결과 반환(91행),
  [autofind_diagnostics.py](../../src/mabinogi_addon/autofind_diagnostics.py)의
  템플릿 수집 및 이름 기록(346행).
- 수정 방향: 기능별 필수 템플릿을 기록과 재실행 경로에서 별도로 검증한다. 실제로
  로드한 템플릿 이름만으로 필수 입력 충족 여부를 판단하지 않는다. 누락은 검출 준비/
  템플릿 오류로 기록하고, 재실행 불가 및 원인을 반환한다.
- 회귀 기준: 처음부터 누락된 템플릿과 정상 로드 후 PNG 저장에 실패한 템플릿을 구분해 검증한다.

### CI-WIN-01 / Confirmed Bug / P1 (릴리즈 차단)

**테스트가 한글 경로의 게임 스크린샷을 직접 `cv2.imread()`로 읽어 실패한다.**

- 발생 조건: Windows에서 한글 파일명을 가진 `tests/data` 이미지를 해당 OpenCV 호출로 읽음.
- 사용자 영향: 이미지 기반 회귀 23건이 검출·판독 검증에 도달하지 못하고 배포가 차단된다.
  이 결과만으로 실제 게임의 버프·디버프·체력바·시간 판독이 실패한다고 판단할 수 없다.
- 기술적 원인: 테스트는 파일 존재 검사 이후에도 한글 경로를 직접 OpenCV에 전달한다.
  읽기가 `None`을 반환한 뒤 배열 슬라이싱에서 `TypeError`가 나거나 로드 확인에서 실패한다.
  제품에는 Python 바이트 읽기와 `cv2.imdecode()`를 사용하는 `image_io.imread()`가 있다.
- 재현 방법: 해당 소스와 샘플을 Windows에 준비하고 아래의 이미지 회귀 테스트를 실행한다.

### CI-WIN-02 / Confirmed Bug / P1 (릴리즈 차단)

**동시 실행 진단 테스트가 UTF-8 로그를 시스템 기본 인코딩으로 읽는다.**

- 발생 조건: CP1252가 기본인 Windows에서 앞선 실행의 한글 로그가 포함된 진단을 읽음.
- 사용자 영향: 동시 실행의 로그·입력 분리 검증이 중단되고 배포가 차단된다.
  실제 앱의 로그 분리가 잘못됐다는 증거는 아니다.
- 기술적 원인: 제품은 `logs.txt`를 UTF-8로 저장하지만 테스트는 `read_text()`의 인코딩을
  생략한다. CP1252로 디코딩하다 `UnicodeDecodeError`가 발생한다.
- 재현 방법: UTF-8 모드가 꺼진 CP1252 Windows에서 진단 테스트 파일 전체를 실행한다.
  단독 테스트에서는 앞선 한글 로그가 없어 같은 실패가 나타나지 않을 수 있다.
- 검증 결과: CI의 `test_concurrent_runs_have_separate_context_and_images`에서
  `encodings/cp1252.py`, byte `0x90` 디코딩 실패를 확인했다.
- 코드 위치: `tests/test_autofind_diagnostics.py:531`;
  제품 저장: `src/mabinogi_addon/autofind_diagnostics.py:218`.
  같은 테스트 파일의 `read_text()` 인코딩 생략 지점도 함께 점검해야 한다.

### CI-WIN-03 / Confirmed Bug / P1 (릴리즈 차단)

**메모 잠금 회귀 테스트가 한글 임시 설정을 기본 인코딩으로 저장한다.**

- 발생 조건: CP1252 Windows에서 테스트용 JSON의 `메모`를 `ensure_ascii=False`로 저장함.
- 사용자 영향: 앱의 메모 복원 동작에 도달하기 전에 회귀 테스트가 실패해 배포가 차단된다.
  실제 앱의 설정 저장 실패나 메모 잠금 회귀를 확인한 것은 아니다.
- 기술적 원인: 테스트의 임시 JSON 쓰기·읽기와 대체 설정 함수에 UTF-8이 명시되지 않았다.
  실제 설정 저장·읽기는 UTF-8을 명시하지만 테스트용 대체 경로는 CP1252를 사용한다.
- 재현 방법: 같은 Windows 환경에서 `tests/test_memo_lock_persist.py`를 실행한다.
- 검증 결과: `_tmp_config()`에서 `UnicodeEncodeError`가 발생했다.
- 코드 위치: `tests/test_memo_lock_persist.py:31,44,48,61,65,69`;
  제품 설정 읽기/쓰기: `src/mabinogi_addon/config.py:50,69`.

### 개발 세션 전달과 재검증

앱 구현을 임의로 바꾸지 않고 다음 수정과 검증을 요청한다.

1. 위 이미지 테스트가 저장소의 유니코드 안전 공용 로더를 사용하도록 수정한다.
2. 테스트의 진단 로그·설정 JSON 읽기/쓰기에 `encoding="utf-8"`을 명시한다.
3. CP1252 환경과 한글 사용자/파일 경로에서 재검증하고 전체 Windows 테스트 게이트를 실행한다.
   실패 테스트를 skip하거나 샘플을 빼서 통과시키지 않는다. UTF-8 모드만 강제해 테스트의
   암묵적 인코딩 의존성을 숨기는 것으로 완료하지 않는다.
4. 수정 후 Windows CI 결과와 81개 skip 사유를 확인한다. 테스트 게이트와 exe 빌드가
   성공하기 전에는 릴리즈 완료로 보고하거나 다음 배포 명령을 정상 상태로 안내하지 않는다.

Windows PowerShell에서 저장소 루트 기준 재현/재검증 명령:

```powershell
uv sync --group build --group dev
$env:QT_QPA_PLATFORM = "offscreen"
$env:PYTHONUTF8 = "0"
uv run python -c "import locale, sys; print(sys.version); print(locale.getencoding()); print(sys.flags.utf8_mode)"
uv run pytest -q tests/test_catalog.py tests/test_debuff_engine.py tests/test_debuff_fp_latch.py tests/test_debuff_momo_fp.py tests/test_stat_bars.py tests/test_time_reader.py
uv run pytest -q tests/test_autofind_diagnostics.py
uv run pytest -q tests/test_memo_lock_persist.py
uv run pytest -q
```

`PYTHONUTF8=0`만으로 한국어 Windows의 코드페이지가 CP1252로 바뀌지는 않는다. 두 텍스트
실패의 동일 조건 재현은 기본 인코딩이 CP1252인 Windows CI/환경에서 확인한다.
수정 후에는 한글 Windows에서도 정상 동작해야 한다. 위 명령은 프로세스가 참조할 현재
PowerShell 환경에만 적용되며 사용자 설정 파일을 변경하지 않는다.

기존 `v0.4.63` 태그는 이미 존재한다. 이 QA 문서 갱신만으로 실패한 릴리즈가 다시 실행되거나
배포되지 않는다. 태그를 임의로 삭제/이동하지 않으며, 코드 수정과 Windows 검증 후 사용자의
명시적 릴리즈 요청에 맞춰 새 태그·릴리즈 노트 버전·대상 소스를 다시 확인한다.
