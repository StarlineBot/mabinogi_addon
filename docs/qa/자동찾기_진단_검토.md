# 자동찾기 진단 QA 검토

검토일: 2026-10-14 (Asia/Seoul)

검토 대상: `main` 소스 `fe8c24e993b40b9e1a82a1697304052c527916c0`.
커밋 메시지나 이력은 읽지 않고 현재 소스와 요구사항을 검증했다. 앱 구현은 수정하지 않았다.

후속 개발 수정과 검증 결과는 문서 하단의 **개발 수정 검증** 절에 기록했다.
최신 독립 재검증 대상은 `a9fb662dcfee6ce7f64d609dad22e23f2e679e9e`이며,
AUTO-DIAG-01은 **수정 확인 완료**다. 독립 실행 결과와 남은 검증 범위는 문서 마지막 절에 있다.

## AUTO-DIAG-01 / Confirmed Bug / P2

**처음부터 필수 템플릿이 없는 실행을 ZIP 재실행 완료로 표시한다.**

- 발생 조건: 버프 앵커 로드가 실패해 `anchor_template()`이 `None`을 반환하거나,
  보스/디버프 숫자 템플릿이 비어 있는 상태에서 자동찾기 -> ZIP 저장 -> 재실행을 수행함.
- 사용자 영향: 검출 준비 실패를 정상적인 미검출 재현으로 해석할 수 있다. 템플릿 누락을
  해결하기 전에 검출 점수나 화면 조건을 분석하게 만들 수 있다.
- 기술적 원인: `detector_assets()`가 빈 dict를 반환하면 기록의 `asset_names=[]`가 된다.
  `replay()`는 이 이름 목록에 있는 이미지의 누락만 검사하므로 검사를 통과한다.
  검출 반환값과 기록 값이 모두 `None`이면 `replayed=true`, `matches_recorded=true`가 된다.
- 요구사항: [자동찾기 진단 문서](../자동찾기_진단.md)의 재실행 절은 입력 또는 필수
  템플릿이 없으면 `replayed:false`를 반환하도록 정의한다.
- 재현 방법: 실제 화면 `tests/data/스크린샷 2026-10-09 190901.png`가 정상 템플릿으로
  검출되는지 먼저 확인한다. 동일 화면에서 앵커 로드를 `None`으로 또는 숫자 템플릿을
  `{}`로 구성한다. 실제 기록 -> 저장 -> ZIP 내보내기 -> `replay()`를 실행한다.
- 검증 결과: 버프·보스·디버프 세 경우에서 모두 재현했다. 정상 템플릿에서는 결과가
  있었고, 누락 상태에서는 `asset_names=[]`, `replayed=true`, `matches_recorded=true`였다.
  버프 trace는 `missing_anchor_template`, 보스/디버프는 실제 보스 후보의
  `percent_unreadable`을 표시했다.
- 코드 위치: [autofind_replay.py](../../src/mabinogi_addon/autofind_replay.py)의
  `detector_assets()`(19행), `replay()`의 누락 검사(84행)와 결과 반환(91행),
  [autofind_diagnostics.py](../../src/mabinogi_addon/autofind_diagnostics.py)의
  템플릿 수집 및 이름 기록(346행).
- 수정 방향: 기능별 필수 템플릿을 기록과 재실행 경로에서 별도로 검증한다. 실제로
  로드한 템플릿 이름만으로 필수 입력 충족 여부를 판단하지 않는다. 누락은 검출 준비/
  템플릿 오류로 기록하고, 재실행 불가 및 원인을 반환한다.
- 회귀 기준: 처음부터 누락된 템플릿과 정상 로드 후 PNG 저장에 실패한 템플릿을 구분해 검증한다.

## 문서와 구현 확인

- 검출에 전달한 동일 프레임을 검출 전에 복사해 실행별로 보존한다.
- 원본 PNG, 사용 템플릿, 메타데이터와 해당 실행 로그가 ZIP에 포함된다.
- 원본 픽셀과 ZIP에 포함된 PNG 바이트의 동일성을 확인했다.
- 제한된 단일 I/O 워커, 기록 개수·디스크·메모리·대기열 상한이 구현되어 있다.
- 설정의 진단 목록/ZIP 저장과 버프·디버프·보스·체력바 자동찾기 연결이 확인됐다.
- 투아림/단축바 자동찾기 검출기는 아직 없고, 문서도 추가 등록 조건을 명시한다.
- 주 모니터 배율 기반의 기존 좌표 변환과 Windows 미검증 범위가 문서에 명시돼 있다.

## 재현 실행


```powershell

uv run pytest -q -s scripts/qa_autofind_missing_assets.py
```

[재현 스크립트](../../scripts/qa_autofind_missing_assets.py)는 파일 위치에서 저장소를 찾는다.
현재 디렉터리에 의존하지 않으며 사용자 설정 대신 임시 JSON/저장 폴더를 사용한다.
파일명이 `test_*.py`가 아니므로 일반 pytest 수집에 포함되지 않는다.

검토 대상 소스의 예상 결과는 **5 passed, 3 failed**다. 실패 세 건은 AUTO-DIAG-01의
기능별 재현이다. 수정 후에는 이 세 건이 통과해야 한다. Windows에서는 Unix 폴더 권한
검증 한 건을 건너뛰므로 예상 결과가 **4 passed, 3 failed, 1 skipped**다. 실제 NTFS ACL은
Windows 라이브 테스트에서 별도로 확인한다.

## 개발 수정 검증 (2026-10-14)

사용자의 수정 요청에 따라 AUTO-DIAG-01을 개발 세션에서 수정했다. 위 내용은 기존
`fe8c24e`에 대한 독립 QA 결과로 유지한다. 아래는 후속 수정의 개발 검증이며 Windows
실기 검증이나 별도 독립 QA 완료를 의미하지 않는다.

- 로드된 템플릿 이름과 독립적으로 버프 앵커, 보스/디버프의 0~9 숫자 템플릿을 검사한다.
- 초기 누락은 `detector_setup` 실패와 누락 목록/원인을 기록하고 검출기를 호출하지 않는다.
  해당 실행의 원본 PNG와 로그는 보존하고 ZIP 재실행은 `replayed:false`를 반환한다.
- 정상 로드 후 PNG 저장에 실패한 경우는 `diagnostic_assets`로 구분한다.
- 예전 ZIP의 `asset_names=[]`도 기능별 필수 입력 검사에서 누락으로 판정한다.
- 일반 회귀 테스트에 초기 누락 3건, 예전 ZIP 3건, 숫자 한 종류 누락 2건,
  숫자 템플릿 PNG 저장 실패 2건을 추가했다. 기존 정상 검출/미검출 재실행 테스트도 유지한다.
- 수정 전 독립 재현은 **5 passed, 3 failed**였다. 동일 스크립트를 바꾸지 않고
  수정 후 **8 passed**를 확인했다. 제품 진단 테스트 **60 passed**, 합계 **68 passed**.
- 이번 개발 환경의 전체 회귀는 **519 passed, 5 warnings in 93.62s**, 종료 코드 0을
  확인했다. 앞선 독립 QA의 오디오 초기화 멈춤 기록과 Windows 미검증 범위는 유지한다.


## 독립 QA 재검증 (2026-10-14)

**AUTO-DIAG-01: 수정 확인 완료. 이번 변경 범위에서 추가 결함은 발견하지 못했다.**
