## 확인한 변경

필수 배포 경로는 Linux 전체 격리 회귀 → Windows 최소 창 기동/종료 → exe 빌드/후보 보관이다. Windows 장치·오디오·DWM 통합 검사는 선택 수동 `windows-native.yml`로 보존됐다. 후보 schema 2와 검증 프로필, 같은 run/SHA/attempt의 두 작업별 필수 단계 검증을 확인했다. 이 구조를 기존 Windows 전체 회귀 필수 경로로 설명하지 않는다.

수정 전 최신 환경 분리 관련 검사 `test_startup_smoke.py`, `test_release_candidate.py`, `test_windows_ci.py`를 직접 실행해 **213 passed, 10.52초**를 확인했다. 개발 기록의 전체 Linux 통과 결과를 이번 실행 결과로 대신하지 않았다.

## Confirmed Bug: 강제 종료 후 기동 진단 누락

- 영향: 중간 / CI 진단 자료 누락. 정상 기동 검사 성공이나 제품 기능 실패를 재현한 것은 아니다.
- 조건: 새 기동 검사는 `test-diagnostics/smoke/run-*`에 기록하지만 `collect(test-diagnostics)`는 직속·unit·native 경로만 찾았다. 감독의 정상 finally 수집은 동작하지만 감독이 단계 제한 등으로 종료되면 후속 `always()` 수집이 smoke 자료를 가공하지 못한다.
- 재현: 임시 `smoke/run-example/worker.json`을 만든 후 최상위 `collect(root)`를 호출하면 반환은 True지만 public 파일은 없었다. 실제 러너 강제 종료를 실행했다고 주장하지 않는다.
- 정식 회귀: 기존 경로/가공 검사를 직속·unit·native·smoke의 4개 매개변수로 확장했다. 수정 전 **1 failed, 3 passed**였고 smoke에서 가공된 stack 파일이 없음을 확인했다. 기존 경로 assertion은 유지했다.
- 수정: `scripts/run_regressions.py`의 고정 수집 경로에 smoke를 추가했다. 재귀적인 임의 디렉터리 탐색이나 원시 자료 업로드로 넓히지 않았다. 실행 수/파일 수/공개 2MiB 제한과 경로 가공을 보존했다.
- 운영 문서: `docs/windows-validation.md`의 이전 전체 job 45분 문구를 현재 Linux 20분·Windows 30분 작업 제한으로 정정했다.
