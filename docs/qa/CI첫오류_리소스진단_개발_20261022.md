# CI 첫 오류·리소스 진단 보완 개발

## 범위와 확인된 사실

- 사용자 요청으로 이 세션에서 Linux regression 진단 3항목을 구현했다. 독립 QA 보고가 아닌
  개발·수정 기록이다. 앱 소스·버전·공개 릴리즈 노트는 변경하지 않는다.
- `39708369037`에서 사용자 제공 실시간 로그로 여러 기능의 연속 ERROR를 확인했다.
  API에서는 회귀 작업이 25분 뒤 cancelled로 완료됐고 Windows 빌드는 실행되지 않았다.
  로그 다운로드는 취소 후에도 BlobNotFound(404)였다. 직접 원인은 아직 미확정이다.
- #86/#88/#89/#90의 공통 증상과 로컬 통과 수/시간은 사용자가 제공한 조사 근거다.
  이 작업에서 각 실행의 원시 로그나 동일 테스트 집합을 새로 확인했다고 주장하지 않는다.
  러너 응답 상실을 OOM이나 무료플랜 차단으로 단정하지 않는다.

## 변경

1. `windows.yml`의 Linux 회귀에 `--maxfail=3 --tb=short`를 적용한다. 실패 후보를 계속
   실행하지 않되 정상 후보의 전체 수집/실행은 유지한다. xdist 진행 중 사례는 더 끝날 수 있다.
2. 기존 pytest 결과 훅에서 controller만 첫 실패 3건의 traceback을 즉시 출력한다.
   setup/call/teardown 외 collection/internal 오류도 처리하고 worker 중복 출력을 막는다.
   캡처 stdout/stderr·지역 변수·환경 변수를 추가하지 않으며 원문은 비공개 CI 콘솔 전용이다.
   각 traceback은 처음/끝 약 32KiB, 전송 단위 8KiB, 기존 유한 큐와 최대 0.2초 flush로 제한한다.
3. 회귀 앞에서 별도 프로세스 그룹의 30초 샘플러를 실행한다. UTC·메모리·디스크·RSS 상위
   15개 프로세스·cgroup 메모리 현재값/제한/OOM 카운터를 출력한다. 명령 인자 대신 comm을 쓰며
   명령별 3초·출력량 제한을 적용한다. 측정 불가 시 unavailable을 출력한다.
4. 같은 Bash 단계의 EXIT/INT/TERM 처리에서 샘플러 소유 그룹을 종료/회수하고 원래 회귀
   종료 코드를 유지한다. 항상 실행되는 후속 단계까지 살아남아야만 정리되는 구조가 아니다.
5. 필수 단계 이름·배포 승인·출처/해시·후보 보관 정책은 바꾸지 않는다. 에이전트가 Actions,
   태그나 Release 게시를 실행하지 않는다.

## 재현·개발 검사

- 수정 전: setup 실패 뒤 다른 xdist 테스트가 멈추면 외부 감독이 종료해도 ERROR 상태 문자와
  감시 메시지만 있고 첫 traceback은 없었다. 새 재현 검사 1 failed(5.46초)로 확인했다.
- 수정 후: setup/call/teardown의 첫 실패 → 다른 테스트 무한 대기 → 감독 timeout 순서를
  serial/xdist에서 구성했다. 각 경우 첫 오류 원문/단계가 감독 종료 메시지보다 먼저 출력된다.
- 오류 3건 중단·중복/크기 제한·잘린 traceback의 마지막 예외 보존·샘플 불가/timeout·cgroup
  경로 이탈 차단·샘플러 그룹 정리/회귀 성공·실패 코드 보존을 검사했다.
- 초기 표적 검사 **48 passed, 29.61초**. 이후 collection/internal 경로와 진단 파일 쓰기보다
  traceback을 먼저 출력하는 순서 검사를 추가했다.
- 전체 Linux 회귀: **1 failed, 2,578 passed, 501.85초**, 감독 종료 코드 1. 실패는 이번에
  추가한 `test_ci_resources.py`의 `read_text()` 2곳에 인코딩을 명시하지 않은 규칙 위반이었다.
  이 실패 원문도 새 실시간 훅을 통해 세션 종료 요약 전에 출력됐다. 과거 CI 정체와 별개다.
- 해당 테스트의 읽기/생성 코드에 UTF-8을 명시했다. 규칙 검사나 실패 assertion은 완화하지 않았다.
  마지막 기록 순서 보완·인코딩 수정을 반영한 최종 표적 재검사: **271 passed, 32.04초**,
  외부 감독 종료 코드 0, 오류/skip 0. 감독·즉시 오류·샘플러·프로세스 정리·CI 계약·게시 차단·
  Unicode 검사를 포함한다. 전체 8분 검사는 이 작은 최종 보완 후 재실행하지 않았다.
- 두 실행에서 통과를 직접 확인한 고유 사례는 합계 2,580건이다. 이를 최종 스냅샷의 전체 단일
  실행이 모두 녹색이었다고 표현하지 않는다. 실제 Actions/Windows 실행도 수행하지 않았다.
- 실제 로컬 샘플에서 메모리·디스크·상위 프로세스·cgroup 메모리 제한/이벤트 출력을 확인했다.
  이는 개발 머신의 측정이며 실패한 Actions 러너의 리소스 증거로 사용하지 않는다.

## 남은 확인과 다음 행동

실제 Actions에서 첫 오류와 마지막 리소스 샘플을 확보해야 근본 원인을 좁힐 수 있다.
이번 변경은 진단 보완이지 원래 CI 정체를 해결했다고 입증한 수정이 아니다. 러너 소실/SIGKILL
때 마지막 로그 전송과 cleanup의 실행을 보장하지 않는다.

작업 중 사용자가 이번 달 지출 $4.56/예산 $5/통지 시점 잔여 $0.44를 알렸으므로, **수정 푸시 후
바로 Actions를 재실행하라는 안내는 중단한다.** 이 세션은 로컬 수정/검증과 문서 푸시만 수행한다.
청구 자료 경로 `/tmp/claude-0/-home-user-mabinogi-addon/1d28b5c2-08d3-5ba5-aafd-75f9e27061d3/scratchpad/calc.py`
는 이 실행 환경에 없었다. 사용자 집계를 독립 재계산했다고 주장하지 않는다.

다음 외부 실행은 예산 도달 시 사용 중지 옵션과 예상 비용을 확인하고 사용자에게 별도 승인을
받은 뒤 결정한다. 이미 제공된 금액을 다시 요구하지 않는다. 승인된 실행이 생기면 해당 URL의
첫 `[ci-first-error]`와 `[ci-resources]`를 분석하며, 로그 API 404 시 해당 화면 로그만 요청한다.
진단 실행도 배포 승인과 구분한다. 원인 증거 없이 같은 소스를 반복 실행하거나 제한 시간/예산을
늘리는 방식으로 넘기지 않는다. 저장소 공개 전환 또한 비밀값·이력·진단 자료 점검 없이 권하지 않는다.
