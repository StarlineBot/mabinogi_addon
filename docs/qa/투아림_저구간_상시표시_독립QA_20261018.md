## 최신 사용자 판단: 수정 범위와 우선순위

1. **100%는 현재처럼 None/`--%`를 유지해도 된다.** 표시 완성을 위해 기존 알림 안전성을 바꾸지 않는다.
2. 10%대의 틀린 숫자 노출은 개선 대상이지만, 모든 구간의 완벽한 판독을 목표로 범위를 확대하지 않는다.
3. 기존 90%대/알림/실제 초기화 재무장을 해치지 않는 작은 수정이 가능하면 그 범위에서 수정한다.
4. 저구간 수정으로 다른 구간의 오탐 위험이나 구현·검증 비용이 더 커지면 **투아림 % 상시 표시만
   숨기거나 노출하지 않는 대안**을 허용한다. 도르카 수치와 기존 투아림 알림은 유지한다.
5. 현재 출력값 10~19만 숨기는 방법은 해결책이 아니다. 16을 6으로 읽으면 그 조건 밖으로 빠진다.
   표시 정책 때문에 공통 원판독값을 0으로 바꾸거나 모든 저값 관측을 알림에서 없애지도 않는다.
6. 이 QA는 특정 수정안을 구현/검증한 것이 아니다. 수정의 안전성이나 다른 구간의 추가 오탐률은
   아직 확정할 수 없다. 위험이 더 크다고 미리 단정해 기능을 강제로 없애지도 않았다.

## 100%: 버그로 분류하지 않으며 변경 대상에서 제외

- `docs/dorcha-tuarim-integration-spec.md:84-86`은 전 구간 개선 완료를 주장하지 않고
  기존 100% 안전 보류를 임의로 바꾸지 않도록 명시한다. 구현 문서도 100%는 None 전달이다.
- `tuarim_reader.py:143-148,162`와 작은 렌더 경로는 확인된 100%를 None으로 보류한다.
  DorchaTab과 DorchaOverlay 역시 유효 숫자를 0~99로 제한해 None을 `--%`로 그린다.
- 실제 100% 전체 화면 `2026-10-09 185117`의 기존 42x16 영역으로 None -> `--%`를 재현했다.
- 최신 사용자 판단에 따라 이 동작은 유지한다. None은 100% 외에도 판독 실패·가림을 뜻하므로
  None을 100으로 바꾸거나 마지막 고값을 100으로 표시하면 안 된다.
- 100% 숫자 지원과 관련 가드 삭제를 이번 저구간 수정의 필수 작업으로 만들지 않는다.

## 왜 기존 검증은 통과했는가

`tests/test_tuarim.py:16-21`은 목적이 90%대 알림임을 명시하고 90~99와 경계 판독을 검사한다.
전체 세션 재생은 알림이 90/95에서 각각 한 번 울리는지를 검사한다. 모든 프레임 숫자의
수동 정답과 비교하는 검사가 아니다. 16과 6은 모두 알림 기준 아래여서 이 오독이 있어도
해당 알림 횟수 검사는 통과할 수 있다. 상시 표시에서는 같은 오독이 사용자에게 직접 노출된다.
