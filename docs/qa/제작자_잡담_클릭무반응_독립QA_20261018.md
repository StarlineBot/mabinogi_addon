## 실행 재현

`scripts/qa_dialogue_transparent_occlusion.py`의 대체 경계는 Z-order, HWND, DWM 경계,
실제 알파 조회 값(0, 0, LWA_ALPHA), 모니터 및 잠금 해제 상태를 명시한다.
가림 함수 자체와 실제 Qt 본창/얼굴 버튼/말풍선/세션 코드는 그대로 실행한다.

1. 투명 창이 없거나, 숨김/cloak/비중첩이면 노출 가능이다. 불투명 중첩 창은 정상적으로 차단한다.
2. 같은 중첩 창을 전역 알파 0으로 두면 여전히 False다. **기대 True → 실제 False**.
3. 실제 얼굴 버튼 `.click()`과 자동 추첨을 각각 실행해도 말풍선이 나타나지 않는다.
   자동은 RNG를 성공으로 고정하여 확률과 구분한다.
4. 데이터/설정/화면을 바꾸지 않고 투명 창만 목록에서 빼면 같은 버튼 클릭으로 즉시 표시된다.

- 결과: **3 failed, 6 passed, 1 skipped**. 실패는 투명 노출/클릭/자동 세 조건이다.
- skipped는 실제 Windows에서 알파 0의 HWND를 생성하는 선택적 네이티브 재현이다.
  Linux에서 실행하지 못했으므로 성공이나 실제 Windows 재현으로 집계하지 않는다.
- 기존 검사 실행은 **1 failed, 62 passed (16.99초)**였다. 실패는 QTcpServer localhost
  listen의 환경 권한 제한이었다. 해당 검사만 네트워크 권한을 부여해 다시 실행해
  **1 passed (1.50초)**로 완료했다. skip/기대값 변경 없이 최종 고유 63개 통과다.
  실제 외부 GitHub 통신 성공을 뜻하지 않으며 로컬 서버 200회 수신/취소 경로 검사다.
- QA 코드 첫 수집의 pytest 예약 인자명 오류는 mode로 바로잡았다. 제품 결함으로 집계하지 않는다.

## 개발 전달 및 남은 확인

- 명백히 완전 투명한 창과 실제로 가리는 창을 구분해야 한다. WS_EX_TRANSPARENT는 입력
  통과일 뿐이고 WS_EX_LAYERED도 불투명일 수 있으므로 그 플래그만으로 모두 무시하면 안 된다.
  픽셀별 투명/색상 키/창 region도 전역 알파 0과 같다고 단정하지 않는다.
- 클릭과 자동의 공통 판정은 재검토하되 첫 사용/영역 지정/투어/설정 OFF/잠금 및 절전 억제,
  기존 포커스/게임 비간섭/단일 수신/타이머·말풍선 수명 정책은 유지한다.
- 현재는 모든 거절 경로가 조용히 False를 반환한다. 실제 원인을 구분할 수 있도록 클릭 시
  거절 사유, 유효 대사 수, 차단 HWND/클래스/경계/알파 등 제한된 진단을 남길 필요가 있다.
  매초 창 목록을 로그에 무한 적재하지 않는다. 이 진단은 개선 제안이며 이번 QA에서 추가하지 않았다.
- 사용자 앱의 가림 판정 결과/차단 창/실제 대사 수는 미확인이다. 데이터 수신 실패,
  다른 노출 조건, API 오류 등 나머지 경로가 실제 원인이 아님을 증명한 것은 아니다.
- Linux Qt offscreen/API 모델 검증이며 실제 Windows 클릭/투명 합성/혼합 DPI/장시간 부하와
  실제 사용자 캐시는 미검증이다. Windows Actions 실행이나 앱 릴리즈는 요청/시작하지 않았다.
- 이번 제보는 미해결이다. 개발 세션에서 조건부 결함 수정과 거절 사유 진단을 함께 검토한 뒤
  원래 재현 및 실제 PC의 무반응 경로를 확인해야 한다. 임의로 제품을 수정하거나 릴리즈하지 않는다.
