# 투아림 동일 주기 반복 알림 QA

- 검증일: 2026-10-14
- 기준 소스: `main`의 `b99983271f66707b4ccf7d50e07b24cc16f68b1f`
- 제보: 90~95 판독 수정 후 배포본 라이브 테스트에서 95~98 구간 알림이 반복됨.
  사용자 확인 조건은 **1차 90 / 2차 95, 게이지 리셋 없는 동일 주기**이며,
  98%에서 약 세 번 들림. 해당 실행의 원시 캡처·시간별 판독 기록은 아직 없음.
- 독립 QA만 수행. 앱 소스와 기존 제품 테스트는 수정하지 않음.

## 기대 동작 및 근거

90/95 설정이면 한 주기에서 각 기준이 한 번씩 울리고, 실제 게이지가 초기화되기 전에는
98%에서도 추가 알림이 없어야 한다. 정상 조작과 화면 변화는 재현 조건이며 사용자 과실로
간주하지 않는다.

`docs/기획서.md` 3.3은 버프 알림 요구사항으로, 투아림 전용 상세 요구사항은 없다.
따라서 이를 투아림의 완전한 사양으로 간주하지 않고 사용자 조건, 투아림 탭 안내,
`tracker/tuarim.py`의 주기당 1회·지속적인 저값 재무장 계약을 함께 기준으로 삼았다.

## TUARIM-QA-01: Confirmed Bug / P2

**이전 확정값이 새 판독 증거처럼 반복 입력되어 거짓 리셋·재알림 발생.**

- 발생 조건: 이미 90/95가 발화한 상태에서 낮은 값이 두 번 연속 읽힌 뒤,
  판독 실패(`None`) 또는 서로 다른 고값(96/97)이 번갈아 나와 새 확정값을 만들지 못함.
  이후 98이 안정적으로 읽힘. 설정 변경, 기능 토글, 타이머 중복 등록은 필요 없음.
- 사용자 영향: 실제 새 주기가 아닌데도 이미 울린 알림 기준이 다시 울릴 수 있음.
  소리 경고를 신뢰하기 어려워지고 반복 음성이 게임 플레이를 방해함.
- 기술적 원인: `_tick()`은 표시용 `_stable_value`를 유지하면서 그 값을 매 틱
  `observe()`에 전달한다. 확정된 저값 5가 `None`이나 불안정한 고값 동안에도 유지되어
  `_low`가 증가한다. 새로운 저값 판독이 없어도 20틱에 도달하면 `_fired`가 지워진다.
  트래커 자체의 `observe(None)` 건너뛰기는 UI가 `None` 대신 5를 전달하므로 작동하지 않는다.
- 관련 코드: `src/mabinogi_addon/ui/tuarim_tab.py:321` (확정값 유지),
  같은 파일 `:341` (유지값 관측 전달),
  `src/mabinogi_addon/tracker/tuarim.py:52` (`None` 처리), `:56` (저값 카운트·재무장).

### 재현 방법 및 실제 결과

`scripts/qa_tuarim_repeat_alert.py`는 실제 `TuarimTab`을 생성해 `_tick()`을 호출한다.
캡처·게임 활성 여부·설정 저장만 격리하고 `_play()` 경계에서 요청을 기록하여
오디오 장치 없이도 UI 안정화와 트래커 상태 전환을 검증한다.

1. 89→90→95→98을 각 값이 확정되도록 입력: 알림 요청 `[90, 95]`.
2. 원시값 5를 두 번 입력, 이후 `None`을 20틱 입력: 새로운 저값은 없지만 `_low=21`.
3. 98을 세 틱 입력: 요청이 `[90, 95, 90, 95]`로 증가.
4. 두 번의 5 이후 `96/97`을 번갈아 20틱 입력해도 같은 실패가 발생.
5. 짧은 저값+판독 실패 구간을 두 번 반복하면 `[90, 95, 90, 95, 90, 95]`.

알림 요청을 세는 재현이며, Windows에서 들리는 음성 횟수를 재현했다고 주장하지 않는다.
`ui/tuarim_tab.py:374`는 두 기준에 같은 사운드 키를 사용하고,
`ui/notifier.py`의 `SoundNotifier.play()`는 단일 `QMediaPlayer`에 즉시 재생을 요청한다.
동시에 요청된 두 알림은 겹치거나 재생이 재시작될 수 있어 제보의 '약 세 번'과
위 요청 횟수가 일대일로 대응한다고 단정할 수 없다.

## 실행 결과와 한계

실행 환경: Linux, Python 3.12, PySide6 offscreen. 관련 소스 5개, 레퍼런스 뱅크,
기존 세션 ZIP의 Git blob 해시가 기준 원격 소스와 일치함을 확인했다.

```bash
PYTHONPATH=src QT_QPA_PLATFORM=offscreen python -m pytest -q tests/test_tuarim.py
PYTHONPATH=src QT_QPA_PLATFORM=offscreen python -m pytest -q scripts/qa_tuarim_repeat_alert.py
```

- 기존 제품 테스트: **36 passed**, 1.43초.
- 독립 QA: **3 failed, 3 passed**, 2.61초. 세 실패는 위의 동일 결함을 검증하는 경우이며
  서로 다른 세 버그가 아니다. 수정 후에는 이 세 경우도 통과해야 한다.
- 대조군: 안정적인 95~98 및 일시적인 흔들림은 주기당 `[90, 95]`만 요청.
- 대조군: 실제 저값이 충분히 지속되면 다음 주기에 `[90, 95]`가 정상 재발화.
- 기존 `raw_7603.zip` 2,926장을 프레임당 두 틱으로 재생(기존 테스트와 동일한 가정):
  원시값→트래커 경로와 실제 UI 경로 모두 `[90, 95]`만 요청, 중복 없음.
- 기존 전체 세션 제품 테스트는 원시값을 트래커에 바로 넣으므로 UI 확정값 유지에 의한
  카운트 증가는 검사하지 않는다. 기존 캡처 세션 자체도 이번 조건을 재현하지 않았다.
- **오늘 제보의 정확한 원인은 미확정.** 위 상태 결함은 실제 코드 실행으로 확인됐지만,
  해당 라이브 실행에 두 번의 저값 오독과 이후 불확정 구간이 있었는지는 확인할 수 없다.
  Windows 게임 캡처·음성 재생·실제 타이머 간격은 여기서 실행 검증하지 않았다.

## 개발 세션 전달 사항

- 표시용으로 유지한 이전 값과 알림 판정에 쓸 새 관측 증거를 분리한다.
  오래된 저값을 새 저값 프레임으로 반복 계산해 재무장하지 않도록 수정한다.
- 독립 QA 세 실패, 기존 36개 테스트, 실제 UI 경로의 세션 재생을 모두 확인한다.
  저값 판독 오류를 억제하면서 실제 새 주기에서는 다시 울리는 동작도 유지해야 한다.
- 현장 원인 확정을 위해 제한된 크기의 진단 기록에 시간, raw/stable 값, `_low`,
  `_fired`, 발화 기준 및 상태 초기화 사유를 함께 남기는 방안을 검토한다.
  단일 진단 PNG는 시간에 따른 재무장 과정을 보여주지 못한다.
  기존 수집 모드도 영상 변화 시만 저장하므로 동일 영상의 지속 틱 수를 정확히 복원하지 못한다.
- 추가 자료가 확보되면 원본 PNG들을 ZIP 파일로 첨부받아 시간별 판독 기록과 함께 재생한다.
  채팅 이미지 미리보기나 수동 Git 업로드를 선행 조건으로 삼지 않는다.
- 현 상태는 이 결함이 미해결이므로 투아림 반복 알림 QA 통과로 판단하지 않는다.
