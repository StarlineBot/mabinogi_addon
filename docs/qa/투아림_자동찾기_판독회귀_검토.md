## Confirmed Bug: TUARIM-AUTO-01

- 심각도: P1, 주요 기능의 판독 정확도 회귀. 앱 크래시 문제는 아니다.
- 조건: `스크린샷 2026-10-12 000512.png`의 실제 55% 화면에서 자동찾기를 승인한다.
- 사용자 영향: 숫자와 %가 점선 안에 완전히 들어가도 표시값이 틀린다. 55%를 1%로 처리해
  실제 주기와 상태가 어긋날 수 있다. 사용자의 승인이나 정상 조작을 원인으로 취급하지 않는다.
- 재현: 원본의 `(740,919,42,13)` 영역은 실제 판독기에서 `55`다.
  실제 자동 검출기의 `(740,918,42,16)` 영역은 같은 판독기에서 `1`이다.
  이는 사용자가 과거 저장한 좌표를 확보했다는 뜻이 아니라, 같은 원본에서 읽히는 대조 영역을
  구성해 영역 변경만으로 정확한 판독이 깨짐을 확인한 것이다.
- 원인: 자동 검출기는 앵커의 고정 오프셋/크기만으로 영역을 반환한다.
  기존 판독기는 입력 전체 높이를 13으로 정규화하고 고정 8px 셀을 비교하므로,
  여백과 높이 변경이 글자 크기·정렬을 바꾼다. 글자 포함 여부와 판독 호환성은 동일하지 않다.
- 코드: `detect/tuarim_anchor.py:13`, `detect/tuarim_reader.py:74`,
  `ui/tuarim_tab.py:267`, `ui/tuarim_tab.py:340` (모두 `src/mabinogi_addon/` 아래).

## Confirmed Bug: TUARIM-AUTO-02

- 심각도: P1, 실제 초기화 없이 주기별 발화 억제가 해제되는 상태 오류.
- 조건: 100% 유지 화면의 자동 영역이 저값으로 안정 오독되는 상태가 약 3초 이상 이어진다.
- 사용자 영향: 이미 울린 90/95 알림이 다음 높은 판독 때 다시 울릴 수 있다.
  확정한 것은 잘못된 재무장 상태이며, 실제 Windows 라이브에서 중복 소리가 난 횟수는 미검증이다.
- 재현 입력: `스크린샷 2026-10-09 185117.png`의 `(742,920,42,16)`과
  `스크린샷 2026-10-14 000646.png`의 `(967,976,42,16)`은 글자 전체가 포함된 실제 100%지만
  판독 결과가 모두 `0`이다. 100을 읽지 못하면 `None`으로 보류하는 것과 다르다.
- 실제 탭 재현: 트래커에 98을 두 번 넣어 `{90,95}` 발화 완료 상태를 만들고 자동 영역을 적용한다.
  적용 직후 상태는 보존된다. 첫 원본 100%를 그대로 반환하는 캡처 경계로 `_tick()`을 21회 호출하면
  실제 판독기·2연속 안정화·20회 저값 재무장 로직을 거쳐 `_fired`가 빈 집합이 된다.
  게이지 초기화 입력은 전혀 없으며 소리 호출도 이 구간에는 없다.
  실제 시계로 3초 대기한 시험이 아니라 기본 150ms 타이머의 21틱 실행 순서를 구성한 재현이다.
- 원인: 판독기의 한 자리 fallback이 100%에서 저값을 반환하며 현재 자동 영역에도 이 경로가 남는다.
  탭은 같은 잘못된 raw가 연속되면 확정 관측으로 인정하고 트래커는 이를 실제 초기화 증거로 사용한다.
  이전 stale stable 값 수정과 달리 이번에는 매 틱 새 raw 자체가 잘못 읽힌다.
- 코드: `detect/tuarim_reader.py:143`, `ui/tuarim_tab.py:340`,
  `tracker/tuarim.py:55`, `tracker/tuarim.py:73` (같은 소스 루트).

## 기존 테스트가 놓친 범위

최초 186개 통과 사실은 유지하지만 이 입력을 검증한 결과가 아니다.
`tests/test_autofind_mvp.py:136`의 90/95/98/99 검증은 기존 13x28 숫자 이미지를 34x16으로
다시 늘려 새 자동 영역에 붙인 합성 시험이다. 실제 앵커와 숫자의 상대 위치·크기에서
자동 영역이 기존 판독기와 호환되는지는 증명하지 못한다.
처음 확인한 100% 한 장이 `None`이었다고 해서 다른 배경의 100%도 안전하다고 일반화할 수 없다.
위 오류가 모두 새 코드에서 처음 만들어졌다는 뜻은 아니다. 기존 판독기의 제약을
새 자동 영역에 연결하면서 발생하는 현재 통합 결함이며, 수동 설정에서도 일부 오독은 가능하다.

## 개발 전달 및 한계

- 기존의 읽히는 원본 픽셀을 변형하지 않은 상태로 자동 영역 전후 판독을 검증한다.
- 단순히 높이 숫자를 교체하면 해결된다고 단정하지 않는다. 한 자리/두 자리/100%, 배경 변화,
  현재 MVP 배율에서 글자 포함과 판독 정확도/안전한 보류를 함께 회귀 검증한다.
- 알림 억제를 보존하는 초기화만으로는 지속 저값 오독에 의한 재무장을 막지 못한다.
- 구현 의도상 100% 직접 판독을 지원하지 않더라도 실제 100%를 초기화로 해석하는 것은 허용하지 않는다.
- 이 검증만으로 90~99%의 모든 실제 자동 영역 판독 실패나 사용자의 이전 라이브 증상과 같은 원인이라고
  단정하지 않는다. 고값 전체 화면/진단 ZIP으로 후속 검증이 필요하다.
- 단축바, 버프/디버프의 새 회귀가 확인됐다는 보고는 아니다. Windows 라이브·DPI·음성은 미검증이다.
- 재현 스크립트는 일반 pytest 자동 수집 대상이 아니다. 테스트를 skip하거나 기존 assertion을 약화하지 않았다.

## 개발 수정 및 재현 재검증 (2026-10-15)

개발 세션에서 최신 `f10fda3`를 받은 뒤 원본 독립 재현 스크립트를 변경 없이 실행했다.
**4 failed, 1 passed in 2.45s**로 55→1, 두 100→0 및 실제 탭의 잘못된 재무장을 확인했다.
아래는 개발 수정 기록이며 최초 독립 QA 판정과 구분한다.

### 수정 내용

- 자동 검출 좌표/42x16 확인 영역은 그대로 유지했다. 높이만 교체하거나 원본 글자를
  시험용으로 늘려 실패를 피하지 않는다. 탭·트래커의 재무장 임계/기간도 바꾸지 않았다.
- 폭/높이가 2.5 이상인 여백 포함 입력에는 `%` 기호로 원래 13px 글자 행을 찾는
  판독 경로를 추가했다. 기존 13px 정규화와 16px 확인 박스 기준 후보를 비교하고,
  기호 기준으로 오른쪽 정렬을 좁게 탐색한다. 불확실한 정렬은 None으로 보류한다.
- 기존 고값/저값 자료의 `%`를 두 기호 템플릿으로 사용했다. 생성 경로는
  `scripts/build_autofind_anchors.py`, 자산은 `detect/templates/tuarim/percent*.png`다.
  새 숫자 학습 자료를 만들거나 기존 `refs.npz`를 바꾸지 않았다.
- 기존 십의 자리 뱅크에는 0이 없다. 전체 숫자 뱅크와 7/8px 자리 피치로 1·0·0의
  증거를 검사해 None으로 보류하고, 이를 한 자리 0으로 내리지 않는다. 100 직접 판독이나
  모든 배경의 오독 방지 보장으로 표현하지 않는다.
- 기존 좁은 13x28 판독은 기존 경로를 유지한다. 사용 가능한 기호 자산이 없거나
  정렬을 확정할 수 없으면 넓은 입력은 저값으로 추측하지 않고 보류한다.
  기호 자산이 모두 없어도 좁은 기존 입력은 계속 읽는다.

### 실제 검증

- 최초 독립 스크립트 5개를 변경하지 않고 회귀로 실행했다. 원본 55%는 55,
  원본 100% 두 장은 None, 21틱 유지 중 발화 억제는 그대로 유지된다.
- `tests/test_tuarim_native_autofind.py`에 원본 5장(7/55/100 세 장)의 실제 자동 영역,
  추가 100% 두 장의 밝기 변화, 합성 150/200%, 기호 자산 오류, 정상 저값 판독과
  실제 탭의 60틱 100% 유지→정상 초기화→다음 주기 발화를 추가했다.
  원본 재현에서는 원본 픽셀을 그대로 자르며 합성 변형 시험을 명시적으로 분리한다.
- 기존 90~99 판독, 2,926장 세션, 두 번의 저값 오독 후 불확정값, 단축바 미러,
  실제 설정 저장/취소/실패 및 ZIP 재생과 함께 **124 passed in 26.98s**를 확인했다.
- 글자 포함·위치 검출과 판독 정확도는 별개다. 이전 합성 숫자 4개 통과와 100% 한 장의
  보류를 전체 입력의 안전성 증거로 일반화했던 개발 검증 범위가 부족했음을 확인했다.

Windows 실게임·DPI·음성 및 보유하지 않은 고값 전체 화면은 여전히 미검증이다.
