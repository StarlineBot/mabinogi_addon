# 1분 헤일로 자동찾기 미제공

- 확인일: 2026-10-19, 한국 시간.
- 확인 소스: `a72862da989644a11c1061d932271edd89ce94d6`.
- 분류: **Improvement / P3 (수집 사용성)**.
- 상태: 사용자 추가 요청 접수, 개발 미반영. 자동찾기 개발 완료로 간주하지 않는다.

## 확인된 현재 상태

제작자 전용 `보스 패턴 알림 → 1분 헤일로` 화면에는 직접 지정, 지정 영역 보기,
지정 해제만 있고 전투 제한 시간 영역의 자동찾기는 없다.

기존 `docs/faith-rift-halo-alpha-spec.md:13`은 이번 범위를 직접 영역 지정·원본 미리보기·수집으로
한정하고, `:84`는 자동찾기를 필수 범위로 확정하지 않았다. 따라서 과거 확정 요구 위반이나
있던 기능의 회귀로 분류하지 않고, 이번 사용자 피드백에 따른 추가 개발 항목으로 기록한다.
관련 구현은 `src/mabinogi_addon/ui/halo_capture_section.py`의 영역 등록 버튼과 `_pick()`이다.

## 발생 조건과 영향

- 조건: 타이머 자료를 수집하려는데 헤일로 영역이 아직 등록되지 않은 경우.
- 영향: 다른 판독 기능처럼 자동찾기로 영역을 등록할 수 없고 분:초 숫자와 콜론을 직접
  감싸 지정해야 한다. 자료 수집을 시작하기 위한 초기 설정 부담이 있다.
- 원인: 현재 헤일로 등록 화면과 처리 경로에 자동찾기 버튼/검출 연결이 구현되지 않았다.
- 정상적인 사용자 조작 문제로 보지 않는다. 직접 지정은 현재 가능한 임시 수집 경로다.

## 확인 방법과 결과

1. 제작자 계정으로 보스 패턴 알림의 1분 헤일로 탭을 연다.
2. 판독 영역 등록 명령을 확인한다.
3. 직접 지정·지정 영역 보기·지정 해제만 있고 자동찾기는 없는지 확인한다.

최신 원격 소스에서 버튼 생성 및 연결 경로와 기획 범위를 대조해 미제공을 확인했다.
이번 확인에서 실제 Windows 앱 실행이나 자동찾기 성능 검증은 하지 않았다.
앱 구현은 수정하지 않았다.

## 개발 전달 사항

사용자가 영역 좌표를 직접 잡지 않고도 전투 제한 시간 영역을 등록할 수 있도록 자동찾기를 추가한다.
의미는 **사용자가 버튼을 눌렀을 때 게임 화면에서 위치를 찾아 등록하는 것**이다.
상시 전체 화면 탐색이나 이동 위치 자동 추적 요구와 혼동하지 않는다.

개발 후 QA에서 확인할 경계:

- 현재 등록된 게임 화면에서 타이머의 분:초 숫자와 콜론 전체를 포함한 영역을 제안한다.
- 숫자 값이 바뀌어도 찾을 수 있는지 원본 샘플로 검증한다. `15:00`만으로 던전이나 전투 시작을
  확정하지 않는다. 영역 탐색과 실제 시간 판독·헤일로 알림은 별도 기능이다.
- 미검출·가림·복수 후보·취소·캡처 실패 때 기존 승인 영역과 다른 기능 설정을 손상시키지 않는다.
- 직접 지정 대안, 제작자 접근 조건, 게임창/포그라운드/좌표·DPI 조건을 유지한다.
- 영역 변경 중 기존 수집을 안전하게 중단하고 다른 보스/디버프 영역을 덮어쓰지 않는다.
- 신규 자동찾기의 버튼·후보 확인 흐름은 기존 자동찾기 관례에 맞춰 개발한다.

## Windows 후보 검증과 관계

현재 `windows.yml`은 버전 `0.5.2`를 입력받아 수동 검증할 준비가 되어 있다.
`gh workflow run windows.yml --ref main -f version=0.5.2`는 검증·빌드·후보 보관만 하며
Release/공개 업데이트/공지를 게시하지 않는다. 자동찾기 추가는 이 후보에 포함되지 않았다.
이 문서는 Markdown만 추가하므로 기존 후보의 중요 입력 fingerprint를 바꾸지 않는다.
자동찾기 구현이나 관련 테스트가 이후 추가되면 그 입력으로 새 후보 검증이 필요하다.
