# Windows 진단 저널 교체 실패 개발 수정

- 기준 소스: `1f4fe98`, 전달된 [실제 Windows 실패 QA](Windows진단저널_파일교체실패_QA_20261021.md).
- 개발 수정·재현 검증 보고다. 후속 독립 QA나 실제 Windows 통과 보고가 아니다.

## 원인과 재현

Windows 실행 `39617505288`은 진단 저널 `.tmp → .json` 교체의 `PermissionError`가 `pytest_runtest_logreport` 밖으로 전파돼 실패했다. 네이티브 검사·빌드·후보 보관은 실행되지 않았으며 중간의 117 passed는 전체 성공이 아니다. QA의 명시 재현 스크립트를 수정 전 실행해 같은 경로의 **1 failed, 1 passed**를 확인했다.

감독 reader와 writer의 파일 공유 충돌은 유력한 발생 경로지만 실제 오류 순간의 핸들 소유자를 확보한 것은 아니다. 이전 실행 `39601019874`의 50분 이상 정체 원인으로 소급하지 않는다.

## 수정 내용

`test_support/progress.py`의 저널 저장·초기화·이벤트 기록/회전·스택 파일 갱신을 유한 I/O 경계로 감쌌다. 교체에는 기존 `os.replace`를 유지해 부분 JSON을 공개하지 않는다. 최대 8회 시도, 간격 10/20/40/80/160/160/160ms로 총 예약 대기는 0.63초다. Windows 시간 제한이나 검사 선택을 완화한 수정이 아니다.

- 일시적인 거부 후 성공하면 정상 진행한다. 실패한 읽기를 진행으로 기록하지 않는다.
- 계속 거부되면 해당 Journal을 실패 상태로 고정하고 추가 저장/가짜 진행 시각 갱신을 멈춘다. pytest hook에서 처리하지 않은 OSError를 던지지 않는다.
- 파일 교체와 별개인 일회성 `.error` 파일 및 표준 오류 메시지로 감독에 실패를 알린다. 내용은 worker/PID/연산/예외 종류/오류 번호로 제한하며 경로나 예외 원문을 넣지 않는다.
- 감독은 오류 파일과 별도 stderr 전달 스레드를 감시해 진단 인프라 실패를 코드 3으로 종료하고 소유 트리를 정리한다. 디스크 오류로 별도 파일 기록이 불가능한 경로도 명시 stderr 신호로 확인했다. 이 합성 사례는 캡처를 끈 자식 프로세스에서 검사한다.
- pytest 세션 종료와 자식 실행 반환에서도 Journal 실패를 확인해 정상 코드 0을 반환하지 않는다. 이미 결정된 테스트 실패 코드와 시간 초과 코드는 진단 수집 오류가 덮어쓰지 않는다.
- 감독의 JSON 읽기가 계속 실패하면 진행 시각을 갱신하지 않고 별도 읽기 인프라 실패로 중단한다.
- 진단 수집은 개별 읽기/출력 실패 후에도 다른 자료를 보존하고 누락 건수를 기록한다. 수집 자체가 실패하면 성공한 테스트를 배포 성공으로 취급하지 않으며, 기존 비정상 종료 코드는 보존한다.

기존 외부 watchdog, 시간 상한, JSON/스택/저널/공개 산출물 크기 제한, 소유 프로세스 정리, 필수 전체 회귀·네이티브·빌드 게이트를 유지했다. assertion/누수 검사 완화, 실패 skip, 관리자 권한 실행 권유, 새 의존성 추가는 하지 않았다. 제품 UI·공개 기능은 변경하지 않아 릴리즈 노트와 준비 버전도 변경하지 않았다.

## 검증 사례와 실행

정식 회귀는 `tests/test_regression_watchdog.py`에 추가했다. 일회성 교체 거부는 실제 report hook으로 검사하고, 영구 거부는 snapshot 교체/임시 파일 쓰기/event append/회전 읽기/회전 쓰기/stack 갱신/전체 쓰기 거부를 나눠 검사한다. 실패 고정 후 추가 진행이 없는지, 7회 대기 후 끝나는지, 오류 메시지 가공, 파일 통지 불가 시 종료 실패, 읽기 실패, 다른 진단 자료 보존과 종료 코드 보존도 확인한다.

`tests/test_windows_journal_contention.py`는 Windows 전용 필수 네이티브 마커 검사다. 실제 `CreateFileW`로 목적지 읽기 핸들을 삭제 공유 없이 열어 둔다. 실제 `os.replace` 거부가 발생함을 확인한 뒤 (1) 재시도 도중 읽기 핸들을 해제해 저장 성공, (2) 계속 유지해 유한 실패와 별도 통지를 각각 검사한다. **이 두 사례는 Linux mock 통과로 대체하지 않으며, 여기서는 실행하지 못했다.** 새 플랫폼 검사는 기존 실패 테스트를 skip한 것이 아니다.

```bash
PYTHONPATH=src:.:tests QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q scripts/qa_progress_replace_failure_20261021.py --tb=short
PYTHONPATH=src:.:tests QT_QPA_PLATFORM=offscreen .venv/bin/python -m scripts.run_regressions --diagnostics /tmp/journal-fix-final-full --case-timeout 180 --session-timeout 1500 -- -n 2 -q -m 'not windows_integration' --durations=15 --tb=short --test-inventory=/tmp/journal-fix-final-full-inventory.json
```

원래 QA 재현 스크립트는 수정 후 **2 passed, 0.04초**다. 첫 전체 검사는 **1 failed, 2523 passed, 3 warnings, 475.71초**로 끝났으며 새 테스트 한 곳의 `read_text()` 인코딩 미지정이 유일한 실패였다. 테스트에 `encoding='utf-8'`을 명시해 수정했고 인코딩 검사 **5 passed, 1.39초**를 확인했다. 제품/진단 구현을 바꾸거나 assertion을 약화하지 않았다.

최종 수정본의 전체 격리 회귀를 외부 감독·xdist 2-worker 경로로 다시 실행해 **2524 passed, 3 warnings, 463.13초**, 감독 종료 코드 **0**을 확인했다. 경고 3건은 기존 toast 검사에서 사용하는 Qt 마우스 이벤트 생성자의 DeprecationWarning이다. Windows 전용 마커 검사를 제외한 Linux 실행이며 실제 Windows 통과를 대신하지 않는다.

실제 Windows reader/writer 경합, 중첩 Job, 네이티브·exe 검사는 미검증이며 workflow/태그/게시를 실행하지 않았다. 수정 후 후속 독립 QA를 먼저 진행하고, 이전 실패 workflow를 그대로 반복하라는 배포 명령은 제공하지 않는다.

추가된 블랙박스 기획 `docs/game-blackbox-spec.md`도 확인했다. 이번 변경은 확인된 진단 코드 결함 수정이며 블랙박스 녹화 구현 완료를 포함하지 않는다.
