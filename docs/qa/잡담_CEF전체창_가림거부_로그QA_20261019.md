## P2 / Highly Likely Bug: 전체 화면 레이어드 경계를 실제 가림으로 과대 평가

- 발생 조건: 앱보다 위에 있는 위 클래스의 레이어드 창이 화면 전체 경계를 가지며,
  전역 알파 사용이 확인되지 않는다. 사용자는 얼굴을 클릭해도 잡담을 볼 수 없다고 제보했다.
- 영향: 클릭/자동의 공통 노출 판정이 막혀 잡담이 계속 표시되지 않을 수 있다.
  기존 트래커의 크래시/정지나 대사 데이터 손상을 확인한 것은 아니다.
- 기술 근거: 현재 `dialogue_visibility.exposed()`는 전역 알파 0 외에는 실제 window region,
  대상 지점의 픽셀별 투명/합성 노출 등을 확인하지 않고 전체 사각형을 가림으로 남긴다.
  명세의 얼굴/말풍선 실제 노출 판정과 차이가 생길 가능성이 높다.
- 분류 한계: **차단 창과 코드 경로는 실제 로그로 확정**했지만, 대상 영역이 시각적으로
  투명하다는 Windows 합성 증거까지 얻은 것은 아니다. 따라서 가림 오판 자체를 새

## 개발 전달

- 이번 live 실패의 우선 조사 경로를 무관한 cloak API 오류에서 **전체 화면 레이어드 창의
  실제 대상 노출 판정**으로 변경한다. 유효 대사 수나 클릭 확률을 다시 원인으로 삼지 않는다.
- 필요하면 수동 거부 시 차단 창의 PID/소유 실행 파일 식별자, 실제 확장 스타일, window region
  및 대상 영역의 노출 근거를 제한적으로 확인한다. 창 제목/전체 경로/전체 화면을 불필요하게
  수집하지 않고, 현재 HWND가 다른 실행에서 재사용될 수 있다는 점도 고려한다.
- 창 클래스 이름 고정 예외, alpha=0만 보고 flags 무시, WS_EX_LAYERED 또는 입력 통과
  플래그만으로 모두 보인다고 가정하는 수정은 피한다. 실제 불투명 가림/잠금/화면 밖 억제는 유지한다.
- 대상 지점/영역의 실제 노출 판정을 검토하되 중심 한 점만으로 말풍선 전체가 보인다고
  보장하지 않는다. 포커스 이동/키·마우스 자동화, 전체 화면 캡처 폴링 또는 무제한 동기
  타 프로세스 호출로 게임/UI에 부담을 주지 않는다.
- 이번 자료로 차단 창/조건을 이미 좁혔다. 동일한 로그를 다시 요청하기보다 해당 조건을
  지원하는 판정 개선과 필요한 최소 진단을 검토한다. 실제 프로그램 소유자나 투명도를 확인하기
  전에는 특정 오버레이 프로그램을 확정 원인이나 사용자 설정 실수로 지목하지 않는다.
