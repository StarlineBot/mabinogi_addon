## 1. 설정 내보내기

### UI 정지

- 실제 SettingsTab과 실제 `config._write_bundle()` 압축을 실행했다. 파일 선택/결과 메시지와 릴레이 전송만 대체하고 개인 설정·실제 키·외부 통신을 사용하지 않았다.
- 독립 추가 스크립트 `scripts/qa_settings_export_followup_20261021.py`: 일반 파일은 허용 아이콘 경로의 비압축성 합성 24MiB, DM은 앱 예산 안의 4MiB를 사용했다. sleep으로 압축을 인위적으로 늘리지 않고, worker 내부의 실제 압축 전후와 UI 5ms heartbeat를 측정했다.
- 일반 파일: 압축 **0.679초**, UI thread 아님, 압축 동안 heartbeat **135회**. DM: **0.113초**, UI thread 아님, heartbeat **22회**. 둘 다 작업 완료·버튼 복귀·ZIP의 필요한 자산 존재를 확인했다. 이는 이 Linux 실행의 관측값이지 Windows 지연 시간/프레임 방해 없음의 보장 수치가 아니다.
- 변경 전 원본 UI 재현은 최소 QWidget stub을 대상으로 하며 새로운 실제 설정 탭/워커 인터페이스와 호환되지 않는다. 그 stub에서 AttributeError가 나오는 것을 제품 회귀로 보고하거나 assertion을 약화하지 않았다. 현재 호환 진입점과 별도로 실제 SettingsTab 기반 독립 검사를 추가해 **UI 스레드 외 압축/압축 중 UI 이벤트 진행**의 원래 요구를 검사했다.

### 비밀값·복원

- `9b9856e`의 재현 원문을 별도 임시 파일에 그대로 보존해 `.bak` 비밀값 사례만 실행했다. **1 passed, 2 deselected (0.15초)**. 제외한 2건은 위에서 실제 UI로 다시 검사한 기존 stub 사례다.
- 추가 독립 검사에서 설정/사용자 데이터가 같은 폴더인 배포판 배치를 사용했다. 자동 `.bak`, `.tmp`, 이름을 바꾼 JSON과 3종 합성 비밀값을 넣어 내보냈다. ZIP은 sanitized `config.json`과 필요한 아이콘만 포함했고 키/문의 웹훅/설정 릴레이 웹훅 값은 모든 멤버에서 제외됐다.
- 해당 ZIP을 다른 임시 사용자 폴더에 복원하여 기존 로컬 비밀값 보존, 일반 설정과 사용자 아이콘 복원을 확인했다. 복구용 `.bak` 자체 삭제로 문제를 회피하지 않았다.
- 소스에서 전체 사용자 폴더 재귀 압축 대신 카탈로그 PNG 경로만 허용하고, 원본/ZIP/항목/시간 상한·협력적 취소·임시 파일 원자 교체·이전 목적지 보존을 검토했다. 앱의 8MiB DM 예산은 모든 Discord의 영구 제한으로 설명하지 않는다.
- 릴레이 접수와 실제 DM 전달은 분리해 안내한다. 실제 Discord나 봇 전달 성공을 이 QA에서 확인한 것은 아니다.

## 2. 네트워크 수정과 FPS 표시

- `_adapter()`는 저장값과 Windows 장치값을 `[guid]`로 구조적으로 비교한다. 중괄호/대소문자 차이를 처리하며 없는 장치·중복 장치에서 첫 장치를 임의 선택하지 않는다. TCP/RSS 조회·쓰기·재연결은 공통 경로를 사용한다.
- 이전 GUID 재현의 제거된 문자열 비교에 대한 제한 정규식은 새 구조적 조건의 PowerShell 해석기로 재사용할 수 없다. 원본 실패 근거는 보존하고 새 계약 검사·관련 회귀와 Windows 전용 검사를 구분했다. **실제 Windows PowerShell 의미/실제 물리 장치 연결 검사는 추가되어 있으나 여기서는 실행하지 않았다.**
- 오류는 단계/항목/분류/반환 코드와 제한된 지문으로 구분하며 원문 장치명·GUID·스크립트·경로·웹훅을 노출하지 않는 경계를 확인했다. 실패 내용을 버리던 원본 오류 구분 assertion은 현행 호환 재현에서 통과한다.
- 기존 게임 시작/중단/접근 해제 시 네트워크 변경·재연결 보류, CPU 독립 처리, 부분 적용 기록 보존, 복구 호환성 회귀를 재실행했다. Linux 대체 API 결과를 사용자 PC의 권한/장치/RSS 원복 성공으로 확대하지 않는다.
- 전용 FPS 위젯을 50/100/150/300%에서 실제 Qt 렌더했다. 흰색 Bold/검은 글자 외곽선 속성, 숫자와 `FPS` 한 줄, 문서 줄 수 1 및 비투명 픽셀 존재를 확인했다. 임시 렌더 `/tmp/qa-fps-100.png` 등을 육안으로 확인했다. Windows 게임 합성/클릭 통과는 미검증이다.
- 이번 수정은 FPS 표시 정리이며, 앞서 작성한 **프레임 기록 파일/세션 요약/ZIP 분석 자료 1단계는 아직 구현한 것이 아니다.**

## 4. Windows·배포 조건

- 실제 Windows의 대용량/느린 디스크·파일 교체/reparse, 사용자 상태·Discord 릴레이/DM·실제 네트워크 적용·재연결/복구·FPS 게임 합성·장시간 부하·exe는 이번 Linux 환경에서 실행하지 않았다.
- 조회 시 최신 Windows 검증/배포 성공은 v0.10.0 소스 `3a6d253`의 `39581238503`/`39583089543`이었다. 이번 수정본의 Windows 통과가 아니다.
- 개발/공개 저장소에서 `v0.10.1` 태그가 없는 것과 공개 노트 맨 위 `v0.10.1` 일치를 확인했다. 사용자 선택으로 아래 한 번을 실행하면 **이번 소스의 전체 Windows 격리·네이티브 검사와 exe 빌드가 성공한 경우에만 동일 파일을 게시**한다. QA는 실행하지 않았다.

```powershell
gh workflow run windows.yml --repo StarlineBot/mabinogi_addon --ref main -f version=0.10.1 -f mode=validate-and-publish
```

이전 v0.10.0에서 만든 ZIP까지 비밀값이 제거되는 것은 아니다. 과거 ZIP을 공개 공유하지 않는 주의는 유지한다. 실제 사용자 ZIP/키를 열어 유출 여부를 확인하거나 실제 키 폐기를 요구하지 않았다.
