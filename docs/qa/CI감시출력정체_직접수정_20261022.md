## 1. 과거 실행에서 확인한 범위

Windows 실행 `39626898265`의 validate job `119314535499`는 2026-10-22 00:34:52~01:29:52(한국 시간), 약 55분 뒤 취소됐다. 단계 메타데이터는 격리 회귀 실행 중 상태를 남겼으며 네이티브·빌드·후보는 시작하지 못했다.

종료 후에도 job 로그 다운로드는 `404 BlobNotFound`이며, 보관 자료에는 release-request만 있고 회귀 진단이 없었다. **지난 55분 정체의 정확한 테스트·스택·러너 상태는 아직 미확정**이다. 아래에서 직접 재현한 감독 코드 결함을 과거 실행의 유일한 원인으로 단정하지 않는다.

## 2. 수정 전 재현

### 콘솔이 가득 차면 감독도 종료하지 못함

실제 검사 자식이 4MiB를 stdout으로 쓰고, 외부 소비자는 파이프를 읽지 않도록 구성했다. 감독의 사례 제한은 2초, 외부 관측 상한은 6초였다. 검사 자식이 출력에서 멈춘 뒤 감독도 실패 문구를 같은 stdout에 동기 출력하다 막혔다. **6초 안에 종료되지 않아 테스트가 실패**했다. 제한 시간을 판단한 뒤에도 소유 트리 정리와 진단 수집에 도달하지 못하는 경로를 실제로 확인했다.

### 파일 통지 불가·기본 출력 캡처에서 오류 구분 지연

기존 영구 쓰기 거부 재현을 기본 pytest fd 캡처로 실행했다. `.error` 파일도 만들지 못하면 stderr 통지가 캡처에 가려, 즉시 코드 3으로 끝나야 하는 조건이 **일반 timeout 코드 124**로 끝났다. 기존 `-s` 검사만으로는 이 조건을 검증하지 못한다.

수정 전 관련 선택 검사 결과는 **2 failed, 3 passed (12.75초)**였다. timeout/누수 assertion을 완화하거나 실패를 xfail/skip 처리하지 않았다.

## 3. 코드 수정

- `scripts/run_regressions.py`: 감독의 안내·stderr 전달을 고정 크기 큐와 daemon의 raw descriptor 출력으로 분리했다. 콘솔 backpressure가 감시/정리 경로를 막지 않는다. 실패 JSON을 먼저 쓰며 종료 시 콘솔 대기는 0.2초로 제한한다. 큐는 최대 32건·건당 8KiB이며 포화 시 진행 출력만 생략한다.
- `test_support/diagnostic_signal.py`: 실행별 loopback 오류 채널을 추가했다. Windows/Linux 공통 표준 socket을 사용하고 `127.0.0.1`에만 바인딩한다. 사용자 비밀값·파일 내용은 전송하지 않고 실행별 임시 토큰만 전달한다. 채널은 닫을 때 receiver thread/socket을 정리한다.
- `test_support/progress.py`: 영구 Journal 실패 시 파일·stderr 기록 전에 위 채널로 알린다. 환경의 실행 루트가 Journal 루트와 일치할 때만 통지해 중첩 실행이나 의도적으로 실패시키는 합성 Journal이 외부 감독을 잘못 중단하지 않게 했다.
- `.github/workflows/windows.yml`: 회귀 단계 자체의 28분/네이티브 12분 제한을 추가했다. 내부 전체 상한 1,500/600초, 사례 180초와 전체 job 45분을 유지한다. Python 감독 밖에서도 종료 경계를 둔다.
- `tests/test_regression_watchdog.py`: 기본 캡처/`-s`와 marker 가능/불가의 조합, 읽지 않는 stdout/stderr 파이프에서 제한·소유 트리 종료·진단 보존을 검사한다. 기존 사례를 제거하지 않았다.
- `tests/test_diagnostic_signal.py`: 실행 루트·토큰 불일치 무시, 중첩 실행 분리, receiver 정리, 잘못된 환경 입력, 채널 생성 실패 시 무감시 검사 시작 금지를 검사한다.

이 채널은 CI 도구에만 쓰이며 앱의 인터넷 접근이나 Windows 설정을 변경하지 않는다. 원래 파일 교체의 유한 재시도/원자성, 공개 진단 크기/보관 제한, QThread 누수 검사, 전체 회귀→네이티브→exe→동일 산출물 게시 게이트를 유지한다.

- 감독/오류 채널/CI 계약/이전 독립 재현 묶음: **70 passed (26.13초)**. 이후 stderr backpressure 사례도 추가해 전체 실행에 포함했다.
- 최종 전체 격리 회귀: **2,532 passed, 3 warnings (483.14초 / 8분 03초)**. 새 감독의 종료 코드 0, JUnit 생성과 진단 수집을 확인했다. 기존 toast의 Qt 마우스 이벤트 DeprecationWarning 3건이며 실패/오류는 없었다. 네이티브 마커 검사는 이 Linux 실행에서 제외했다.

## 5. 남은 검증

실제 Windows의 Job/pipe/CRT fd 처리, loopback 오류 전달, 파일 공유 경합·네이티브·exe 빌드는 여기서 실행하지 못했다. 이번 코드가 과거 55분 정체의 정확한 원인을 제거했다고 단정하지 않는다. 러너 자체 단절·파일 시스템 전체 I/O 정체·강제 종료에서는 업로드 보장이 없다.

수정·회귀 통과를 후속 독립 QA/배포 성공으로 대신하지 않는다. 이 세션은 workflow/태그/Release를 실행하지 않았다. 검증 없이 이전 실패 실행을 반복하거나 배포 게이트를 우회하지 않는다.
