# v0.5.0 전체 회귀 실패 수정 후 독립 QA

- 검증일: 2026-10-19
- 개발 대상: `6126026652e11ae039a065a6631507a699247352`
- 선행 보고: [Windows 전체 회귀 실패 분석](Windows_v0.5.0_전체회귀_실패분석_20261019.md).
- 결론: 앞선 36개 실패의 세 원인은 해결됐다. 이번 검증 범위에서 추가 결함은 확인하지 못했다. 실패 태그 보존 후 v0.5.1 릴리즈 명령 제공 가능.

## 소스 확인

정확한 소스 트리를 비교했으며 커밋 이력/메시지는 조회하지 않았다. 개발 변경은 테스트 fixture/추가 회귀 및 문서 6개 파일이다. 제품·접근 권한·판독기·설정 전환·워크플로·공개 노트는 개발 푸시에서 바뀌지 않았다.

- 잡담 fixture는 실제 지원 설정 `skipSetup=true`로 메인 화면을 준비하고 `_pages.currentWidget() is _tabs`를 확인한다. 제품의 `_eligible()`을 완화하거나 항상 참으로 대체하지 않았다. 안내/투어 중 차단 검사도 유지했다.
- 저구간 positive pipeline은 제작자 ID로 준비한다. 실제 최초 전환 완료와 체크 OFF를 확인한 뒤 명시적으로 % 표시를 켜고 요청 상태를 검증한다. 기존 원본 16/19/100 판독·안정화·표시 assertion은 보존했다.
- 새 일반 회귀는 일반 계정/비로그인에서 % 차단, 제작자로 전환 후 16/19 표시와 100% 안전 보류를 검사한다.
- 헤일로 테스트의 metadata JSON 읽기에 UTF-8을 명시했다. 인코딩 계약 검사 자체는 그대로다. 새 skip이나 기존 QThread 누수 검사 삭제는 없다.

## 실행 결과

Linux Qt offscreen에서 기존 장치·네트워크 격리 경계를 사용했다.

```bash
PYTHONPATH=src:. QT_QPA_PLATFORM=offscreen python -m pytest \
  tests/test_creator_dialogue.py tests/test_dialogue_transparent_occlusion.py \
  tests/test_dialogue_window_region.py tests/test_tuarim_low_range_display.py \
  tests/test_tuarim_visible_nineteen.py tests/test_unicode_io_contract.py \
  tests/test_release_050_regressions.py scripts/qa_release_050_gate_20261019.py \
  tests/test_setup.py tests/test_feature_release_policy.py tests/test_halo_capture.py \
  tests/test_resource_integration.py tests/test_tuarim.py \
  -q --tb=short --show-capture=no
```

**397 passed, 1 skipped / 84.07초**, 종료 코드 0. skip 1개는 기존 실제 HWND/DWM/layered-alpha Windows 통합 검사이며 Linux에서 실행하지 않았다. Windows 태그에서는 별도 native 단계 대상이다.

- 기존 실패 36건과 세 원인의 대표 재현이 모두 통과했다.
- 첫 사용 안내·공개 정책/권한·헤일로 원본 수집·자원 통합·일반 투아림 알림 반대 조건을 포함했다.
- Unicode I/O 계약 검사도 통과했다.

새 독립 probe:

```bash
PYTHONPATH=src:. QT_QPA_PLATFORM=offscreen python -m pytest \
  docs/qa/assets/release_051_fixture_20261019/probe.py \
  -q --tb=short --show-capture=no
```

**9 passed / 1.67초**. 수정된 positive pipeline을 사용하지 않고 새 컨트롤러와 실제 원본을 조합했다. 비로그인/일반 계정/제작자 각각에서 16/19/100을 검사했다. 제작자도 최초 전환 뒤 OFF이고, 비대상 계정의 체크 시도는 추가 캡처나 표시를 만들지 않는다. 제작자 명시적 체크 후에는 정확히 3회 판독 요청, 원시/안정/표시 일치와 100% `--%` 보류를 확인했다. 표시가 일반 알림을 켜지 않는 것도 검증했다.

기존 독립 안내 대조:

```bash
PYTHONPATH=src:. QT_QPA_PLATFORM=offscreen python -m pytest \
  docs/qa/assets/release_050_failure_20261019/probe.py -k anonymous_guide \
  -q --tb=short --show-capture=no
```

**2 passed, 3 deselected / 1.26초**. 비로그인 안내 중 잡담 거부와 실제 skip 설정으로 메인 진입 후 표시가 각각 통과했다. 선택하지 않은 3개는 과거 공유 pipeline이 일반 계정으로 시작한다는 초기 가정을 가진 자료다. 현재 positive fixture는 제작자 opt-in으로 바뀌어 그 전제가 더 이상 맞지 않는다. 원본은 보존했으며 새 독립 probe가 권한 상태를 명시적으로 준비해 대체 검증한다. deselected를 통과로 집계하지 않는다.

## 릴리즈 번호 조정

- 원격 최신 태그는 이미 사용한 `v0.5.0`이다. 실패 태그는 삭제·이동·재사용하지 않는다. 기능 추가가 아닌 이번 수정 다음 번호는 `v0.5.1`이다.
- 지속 승인된 최소 노트 버전 조정으로 미공개 최신 헤더만 `v0.5.0`에서 `v0.5.1`로 변경했다. 배포 예정 기능 설명과 v0.4.90 이하 공개 노트는 그대로다. 버전 변경으로 기존 기능을 수정하거나 과거 공개 노트를 재작성하지 않았다.

```bash
PYTHONPATH=src:. QT_QPA_PLATFORM=offscreen python -m pytest \
  tests/test_dungeon_release_note.py tests/test_release_notes.py \
  tests/test_release_notes_trigger.py tests/test_updater.py \
  scripts/qa_dungeon_release_note_20261019.py -q --tb=short --show-capture=no
```

**20 passed / 2.69초**. 별도로 실제 `is_newer('0.5.1','0.5.0')`와 최초 실행/0.4.90/0.5.0에서 0.5.1 노트 선택도 확인했다. 개발 변경의 `git diff --check`도 통과했다.

## 제한 및 완료 조건

- 전체 일반 회귀를 여기서 다시 실행한 것은 아니다. Windows 네이티브·exe·실게임·혼합 DPI·장시간 부하는 미검증이다. 앞선 릴리즈 전체 실패를 이번 Linux 결과로 Windows 성공이라고 바꾸지 않는다.
- 같은 SHA 재실행이나 추가 유료 수동 실행은 요구하지 않는다. 새 태그 릴리즈에서 전체 일반 회귀·네이티브·exe 필수 게이트가 모두 통과해야 게시한다.
- QA 보고서·새 독립 probe·최소 노트 버전 변경만 main에 공유하고 원격 최신 태그/노트/HEAD 재확인 후 v0.5.1 명령을 제공한다. 태그와 릴리즈 실행은 사용자가 직접 한다.
