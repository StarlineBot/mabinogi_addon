## 실제 변경 범위

투아림·단축바용 마스크 앵커 4개, 공통 후보 검색, 두 검출기, 승인/취소 흐름,
탭 연결, 진단/ZIP 재생 등록, 투아림 영역 변경 시 관측 증거 초기화,
가상 데스크톱 점선 및 관련 테스트·문서·v0.4.66 노트를 확인했다.

시작/종료의 기존 핵심 경로, thread/hook/IPC, Windows 캡처 백엔드, 네이티브 의존성,
빌드 workflow는 변경되지 않았다. 새 확인 창의 종료·타이머 처리는 관련 테스트로 검증했다.
요리 기획, 전체 자동설정, UI 이동의 상시 자동 추종은 이번 구현 범위가 아니다.

최신 제품 Python 소스·테스트와 4개 앵커/마스크 **183개 파일**을 원격 blob과 대조했다.
번들 자산은 제공된 생성 스크립트로 재생성했으며 4개 PNG 모두 원격 바이트 해시와 일치했다.
아래 원본 두 장 및 이전 독립 QA 스크립트 3개도 원격 해시와 일치했다.

### 원본 위치와 렌더

| 기준 PNG | 투아림 물리 영역 | 단축바 물리 영역 |
|---|---|---|
| `스크린샷 2026-10-10 190116.png` | `(742,920,42,16)` | `(2,12,1168,89)` |
| `스크린샷 2026-10-12 200511.png` | `(965,974,42,16)` | `(0,10,1168,89)` |

제공된 렌더 스크립트로 두 탭과 기준 검출 영역을 생성해 직접 확인했다.
7%와 100% 글자 전체가 숫자 영역에 들어가며 원 내부 숫자는 포함되지 않는다.
단축바는 원본 12개 그룹을 포함하고 오른쪽 추가 단축바/중앙 미러를 원본으로 지정하지 않는다.
탭 760px 렌더에서 새 버튼 위치도 확인했다. 이 PNG의 실제 Windows DPI·작게 보기 설정은 미확인이다.

100% 영역 포함과 기존 판독 정확도는 구분했다. 기준 7%는 `7`, 기준 100%는 `None`이며,
자동찾기가 기존 두 자리 판독기를 세 자리 판독기로 바꾼 것으로 보고하지 않는다.
이전 투아림 반복 알림과 디버프 깜빡임 재현도 최신 코드에서 계속 통과했다.

### 독립 실행으로 확인한 경로

- 실제 한국어/공백 경로의 JSON에 기존 설정을 저장하고 실제 검출→탭 승인/거절→
  원자 설정 저장→진단 ZIP 내보내기→재생을 두 기능 모두 실행했다.
- 승인하면 해당 `box`/`anchor`만 달라진다. 취소·캡처 실패·검정 화면에서는 설정이 유지된다.
  사용 여부·임계값·소리, 12개 그룹 위치/잠금/숨김/셀 선택·출력 배율을 보존했다.
- 최종 `os.replace` 실패를 주입했다. 이전 JSON을 `.bak`에서 읽을 수 있고, 탭의 이전 영역을
  유지하며 `confirmation=save_failed`를 기록했다. 해당 실행을 적용 성공으로 보고하지 않는다.
- 승인한 단축바 앵커로 실제 `_tick()`을 실행해 요청 좌표를 확인하고, 표시되는 11개 그룹의
  활성 33셀 픽셀을 원본 대응 영역과 비교했다. 숨긴 그룹과 해제한 셀은 계속 숨겨졌다.
  제품 회귀는 48개 원본 셀 전체도 비교한다.
- 투아림 승인 전 이미 울린 `{90,95}` 상태는 보존하고 이전 영역의 raw/stable·연속 판독 증거를
  비운다. 실제 저값 지속 뒤 다음 주기 발화는 기존 회귀로 확인했다.
- 두 기능 각각 50회 확인 거절을 반복했다. 타이머 활성 상태 복원, busy 해제,
  임시 점선 참조 해제 및 DeferredDelete 처리 후 점선 창 부재를 확인했다.
  이 반복은 확인 UI를 분리한 시험이며 실제 50회 화면 캡처의 성능 시험은 아니다.
- 선언된 PyInstaller 자산 디렉터리를 공백 경로에 모사해 두 anchor/mask가 원본과 같은 픽셀로
  로드되는지 확인했다. 실제 새 exe를 빌드/실행했다는 뜻은 아니다.
- 기존/신규 제품 테스트로 중복 실행 방지, 확인 중 종료, 저장 실패, 누락 자산,
  합성 이동·내부 숫자/스킬 교체·복수 후보·가림·미지원 크기·음수 좌표·합성 150%를 확인했다.

### 호출 비용과 자원

기준 2560x1440 입력, OpenCV 1 thread, 기능별 3회 순수 검출 비용:

- 투아림: 413.56 / 369.65 / 584.41ms.
- 단축바: 416.72 / 567.25 / 467.65ms.

자동찾기는 GUI 스레드의 요청 시 1회 검색이며 그동안 UI 처리가 대기할 수 있다.
실제 캡처 숨김 대기 250ms·확인창·저장 시간은 위 수치에 포함되지 않는다.
상시 탐지의 5ms 성능이나 Windows 게임 FPS를 확인한 수치가 아니다.
새 상시 polling/타이머/별도 worker는 추가되지 않았고 기존 두 타이머와 공통 진단 worker를 사용한다.
진단의 큐·메모리·보관 상한·종료/예외 회귀도 통과했다. Windows GDI/핸들/GPU 및 장시간
리소스 증가를 실측하지 않았으므로 누수가 전혀 없다는 판정은 하지 않는다.

## 남은 범위와 기존 문제

- 새 확정 버그·크래시는 위 검증에서 발견하지 못했다. 실제 게임, Windows native 창·
  포커스/클릭 통과·DPI·전체화면/Alt+Tab·음성·장치 변경·장시간 실행은 미검증이다.
- 혼합 DPI는 기존 `dpi.screen_scale()`의 주 모니터 기준 변환 한계가 남아 있다.
  가상 데스크톱 점선 변경만으로 서로 다른 DPI의 정렬이 검증됐다고 하지 않는다.
- 4K·다른 게임 UI 배율·작게 보기 및 사용자의 현재 모드에서 모든 셀이 맞는지는 별도 라이브 확인이다.
  합성 150%나 두 기준 PNG의 성공을 환경 전체 지원으로 일반화하지 않는다.
- 새 소스 `26d9a95`의 Windows CI 실행은 확인 시 없었다. 마지막 태그 빌드는
  `38590345014`의 v0.4.65 소스 `4164311`에서 성공했다. 이를 새 코드의 Windows 통과로 표시하지 않는다.
  이번 변경은 기존 캡처/빌드 경로를 사용하는 일반 기능 추가이며 제한된 베타 기준에 따라
  별도 수동 사전 CI를 반복 요구하지 않고 태그 CI의 전체 테스트·exe 빌드 게이트를 유지한다.
- **기존 NOTES-QA-01은 미해결이다.** 이번 전체 변경에 공개 노트 생성 workflow 수정은 없고,
  여전히 원시 커밋 제목을 사용한다. 공개 문서의 v0.4.65 교정과 앱 내 한글 노트는 정상이나,
  다음 공개 문서/공지에 내부 작업이 다시 섞일 가능성은 남는다.
  `docs/qa/공개_릴리즈노트_혼입_검토.md`의 개발 전달 사항을 따른다.
  이 기존 문구 문제를 해결된 것으로 보고하지 않으며 새 기능의 크래시 차단 문제와 구분한다.
