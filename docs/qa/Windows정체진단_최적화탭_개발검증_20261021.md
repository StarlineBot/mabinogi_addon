# Windows 정체 진단·최적화 탭 개발 검증

- 대상: `95a078a`를 바탕으로 한 개발 수정. 독립 QA 완료나 실제 Windows 통과 보고가 아니다.
- 전달 문서: [Windows 검증 장기 정체·최적화 탭 통합](Windows검증장기정체_최적화탭통합_개발전달_20261021.md).
- 사용자 최종 정정: 알파 기능은 제작자 외에는 어디에도 노출하지 않는다. 복구도 최적화 탭에서 진행하며, 비제작자 복구 전용 화면은 사용하지 않는다.

## 확인된 사실과 조사 한계

Windows 실행 `39601019874`, job `119225381365`, SHA `7fa22ab9f8e41c2b21ac72fd6a74f08024c77d48`는 격리 회귀 검사에서 50분 이상 정체한 뒤 취소됐다. 실행 API의 최종 결론은 `completed/cancelled`다. 종료된 실행의 개별 단계에 남은 `in_progress/pending`을 실제 실행 중으로 해석하지 않는다.

원본 로그는 CLI 다운로드 경로의 접근 실패와 연결된 GitHub 도구의 `404 BlobNotFound`로 확보하지 못했다. 마지막 테스트나 스택이 없으므로 **기존 Windows 정체의 근본 원인은 미확정**이다. 특정 테스트·Qt·러너 결함을 단정하거나 이번 수정으로 원래 정체를 해결했다고 주장하지 않는다. 같은 Windows 검증을 무작정 재실행하지 않았고 workflow dispatch·태그·Release 게시도 하지 않았다.

기존 [설정 백업·네트워크 후속 독립 QA](설정백업_네트워크수정_후속독립QA_20261021.md)의 소스 확인 결과를 되돌리지 않는다. 이번에는 진단 없이 오래 기다리던 검사 경로를 보완하고 확정된 UI 요구를 구현했다.

## 정체 진단과 외부 종료 경계

`scripts/run_regressions.py`가 pytest 밖의 별도 프로세스로 전체 검사 트리를 소유한다. Windows는 기존 `ProcessJob`으로 소유 트리만 관리하며, 자식 pytest는 Job 할당 후 시작 게이트가 열릴 때 실행된다. POSIX 검증에서는 별도 프로세스 그룹을 사용한다. 시간 초과는 코드 124로 실패 처리하며 assertion 실패의 원래 종료 코드는 유지한다.

- setup·call·teardown을 합친 사례 시간과 수집/무진행 시간은 180초, 전체 격리 회귀는 1,500초, 네이티브 검사는 600초다. 기존 job 제한과 필수 회귀·네이티브·빌드 게이트를 유지한다.
- worker/PID/저장소 상대 테스트 위치/단계/시각/결과를 저널에 기록한다. 매개변수 내용은 기록하지 않고 사례 식별 해시를 사용한다. 30초마다 활성 위치를 콘솔에 출력한다.
- C 수준 faulthandler가 30초마다 스택을 남긴다. Python GIL을 점유한 네이티브 호출이나 fixture/인터프리터 종료 정체도 외부 감독 프로세스가 제한 시간으로 중단한다.
- 종료 시 해당 실행의 소유 트리만 정리한다. 합성 테스트에서 소유 자손 종료와 별도 sentinel 프로세스 생존을 함께 확인했다.
- `always()` 수집/업로드는 가공된 `public` 파일만 대상으로 하며 보관은 1일이다. 스택의 절대 경로를 저장소 상대 경로 또는 외부 파일명으로 줄이고 프레임 지역 변수는 수집하지 않는다. 파일별 입력 꼬리 256KiB, 실행별 공개 산출물 2MiB와 소형 수집 상태 파일로 제한한다. 저널·원시 스택에도 크기 경계를 둔다.

180초는 Linux 관련 검사에서 관측한 9.31초와 최종 전체 검사 최장 단일 단계 15.50초보다 넉넉한 초기 진단 한계다. 실제 Windows에서 충분한지 아직 확인하지 않았으며, 초과하면 정상 성공으로 넘기지 않고 해당 사례와 스택을 근거로 조사한다. 실패 skip, 기존 assertion 약화, QThread 누수 검사 제거, 새 의존성 추가는 하지 않았다.

## 제작자 최적화 탭

기존 별도 대화상자를 앱 소유 단일 `OptimizationPanel`로 바꾸고 `전투 보조 → 파티 모집 → 편의기능 → 최적화 → 설정` 순서로 삽입했다. 설정의 중복 실행 버튼은 제거했다. 최적화/FPS 하위 탭은 공통 하위 탭 스타일, `FeatureHeader`, `QGroupBox`, 폼과 조작 행을 사용한다.

- 최적화: 환경 확인, CPU 배치, 네트워크, 적용·복구.
- FPS: 대상·측정, 오버레이, 상태·수집 품질.
- 탭 선택만으로 검사·설정 변경·FPS 수집을 시작하지 않는다. 접근 허용→해제→재허용에도 같은 panel/Engine/Collector/timer를 유지한다.
- 제작자 외에는 복구 기록 손상·CPU/네트워크 미복구·재연결 필요 상태에서도 최적화 탭과 설정 진입점이 없다. 제작자로 다시 확인되면 해당 탭에서 복구한다.
- 로그아웃·종료의 CPU 자동 원복, 소유 FPS 정리는 유지한다. 네트워크 복구 기록을 보존하고 원복은 제작자 탭의 명시적 버튼과 확인으로 진행한다. 게임 종료·앱 종료 때 네트워크 복구 팝업을 자동 노출하지 않는다.
- 설정 참조를 `_settings_scroll`로 고정해 제작자 탭 삽입 이후 안내·첫 사용 투어·설정 스크롤 연결이 다른 탭으로 이동하지 않게 했다.

실제 MainWindow 오프스크린 렌더를 공유해 사용자 피드백을 받았다. 최초 복구 전용 화면 제안은 사용자에게 거절됐으며 최종 구현/기획에는 제작자 전용 정책을 반영했다. [렌더 스크립트](../../scripts/render_optimization_tabs.py)는 임시 설정과 가짜 외부 경계를 사용한다.

## 직접 실행한 검증

- 최종 전체 검사 전 관련 UI·정체 진단·CI·탐색 검사: **80 passed, 20.65초**. 이후 공개 진단 크기 한계 사례를 추가해 아래 전체 검사에 포함했다.
- 합성 회귀는 setup/call/teardown 정체, ctypes 네이티브 GIL 점유, 테스트 통과 후 인터프리터 종료 정체, xdist 2-worker 진행/실패 코드 보존, 소유 자손 정리, 경로 가공, 유한 양수 시간 제한, 진단 크기 한계를 다룬다.

최종 소스의 전체 격리 회귀를 CI와 같은 2-worker 모드로 실행한 결과 **2509 passed, 3 warnings, 486.53초**다. 새 외부 감독 경로로 정상 종료 코드 0과 진단 자료 생성을 확인했다. Windows 전용 검사는 아래 마커로 제외한 실행이며 Windows 통과를 뜻하지 않는다.

```bash
PYTHONPATH=src:.:tests QT_QPA_PLATFORM=offscreen .venv/bin/python -m scripts.run_regressions \
  --diagnostics /tmp/ci-tabs-final-full-diagnostics --case-timeout 180 --session-timeout 1500 -- \
  -n 2 -q -m 'not windows_integration' --durations=30 --tb=short \
  --test-inventory=/tmp/ci-tabs-final-full-inventory.json
```

개발 검증 결과를 후속 독립 QA와 실제 Windows 성공으로 대체하지 않는다. 기존 Windows 정체의 원인 조사와 새 감독 경로의 실제 Windows 검증은 남아 있으며, 현재 배포 성공 후보로 안내하지 않는다.
