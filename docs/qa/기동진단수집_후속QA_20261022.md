# 기동 진단 수집 수정 후속 QA

- 대상 소스: `450f0964` (개발 수정). 커밋 이력/메시지가 아니라 현재 소스와
  `1848b39a`의 해당 파일 스냅샷을 비교했다.
- 범위: `collect()`의 고정 탐색 경로, 기존 수집/가공 정책, 감독과 배포 계약 회귀.
  앱 구현·버전·릴리즈 노트·workflow는 QA에서 변경하지 않았다.

## 판정

**확인한 범위에서 새 배포 차단 결함을 발견하지 않았다.**
기존에 누락됐던 `test-diagnostics/smoke/run-*`를 최상위 후속 수집이 처리한다.
직속·unit·native 경로도 유지되며 임의 재귀 탐색으로 넓어지지 않았다.

## 독립 재현

임시 경로의 직속·unit·native·smoke마다 별도 Python 생산자가 스택/JSON과 무관한
`secret.env` 파일을 남긴 뒤 `os._exit(17)`로 종료하도록 구성했다. 새 경로별 수집 결과와
원시 파일 제외·스택의 외부 절대 경로 가공·JSON 보존을 확인했다.

| 기준 | 실제 수집된 경로 |
| --- | --- |
| 수정 전 파일 스냅샷 `1848b39a` | 직속, unit, native (smoke 누락 재현) |
| 수정 후 `450f0964` | 직속, unit, native, smoke |

새 소스에서 모든 경로의 가공된 stack/JSON이 생성됐고, `*.raw`와 `secret.env`는 공개 폴더에
복사되지 않았다. 이 재현의 전체 종료 코드는 0이다. 실제 GitHub 러너나 감독 프로세스를
강제 종료한 실험은 아니며, 갑자기 종료된 생산자가 남긴 자료의 후속 수집을 검증한 것이다.
원래 장기 정체의 원인을 이 재현으로 확정하지 않는다.

- API 확인 당시 새 `450f0964`의 Actions 실행 기록은 없었다. 이전 `39701216844`는 취소,
  후행 게시 workflow는 skipped였다. 새 Windows 최소 기동·exe 빌드·두 OS 보고서 전달·후보 저장,
