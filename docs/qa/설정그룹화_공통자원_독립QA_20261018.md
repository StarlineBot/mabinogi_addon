## P2 / Confirmed Bug: null 자원 설정에서 공통 등록·해제 실패

- 조건: 설정 JSON의 `dorcha` 또는 `tuarim` 항목이 `null`이고 공통 영역 등록을 승인하거나,
  반대쪽에는 유효한 영역이 있는 상태에서 공통 지정 해제를 승인한다.
- 영향: 유효한 후보를 승인해도 영역이 등록되지 않는다. 공통 해제는 `AttributeError`가
  발생해 정상인 다른 쪽 영역도 해제하지 못한다. Python 호출 실패를 확인한 것이며
  배포 exe 전체의 네이티브 크래시나 사용자 데이터 소실을 확인한 것은 아니다.
- 원인: `src/mabinogi_addon/ui/resource_tab.py:272`, `:341`의
  `latest.get(name,{}).get(field)` / `before.get(name,{}).get(field)`는 키가 없을 때만
  빈 dict가 된다. 명시적인 null에는 None이 반환되어 `.get()`이 실패한다.
  `:344`의 `setdefault(name,{})`도 기존 null을 정규화하지 못한다.
- 이 입력을 기존 로더가 모두 거부하는 것은 아니다. `config.load_dorcha()`와
  `config.load_tuarim()`는 null을 영역 미등록으로 처리한다. 공통 등록으로 정상 값을
  복구할 수 있어야 하는데 새 사전 비교에서 저장 단계에 도달하지 못한다.
- 기존 공통 저장/개별 해제는 `setup_state.section()`을 통해 dict가 아닌 설정을
  정규화하는 경계를 사용한다. 같은 경계를 사전 비교/변경에도 적용할 수 있다.
  QA에서는 제품을 수정하지 않았다.

- 등록은 `autofind_diagnostics.perform_autofind()`가 확인 콜백 예외를 기록하고 삼켜
  적용 결과가 `{}`가 된다. 해제는 실제 `_clear_regions()` 호출에서 동일 예외가 전파된다.

  반영하고 실제 설정 로더의 반환을 확인한 뒤 명령을 실행한다. 일반 pytest 수집에 편입하지 않는다.
- 개발 검증 조건: null/키 없음/정상 dict에서 등록·해제를 비교하고, 잘못된 섹션은 안전하게
  복구하되 다른 영역/옵션을 보존한다. 취소/쓰기 실패/동시 변경 및 세대 가드는 유지한다.
