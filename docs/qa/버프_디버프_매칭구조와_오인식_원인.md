# 버프·디버프 매칭 구조와 오인식 원인

검증일: 2026-10-16 (한국 시간).
기준 소스: `185bdc3cd6ceb6b3106bbbb4b06c52b7962eb928`.
요청 범위는 현재 매칭 방법과 오인식 원인을 점검해 설명하는 것이다. 커밋 이력은
조회하지 않았고 제품/기존 테스트/원래 재현 스크립트는 수정하지 않았다.

## 결론

이 앱은 게임의 실제 버프/디버프 상태를 읽지 않는다. 화면의 아이콘을 등록 이미지와
비교해 적용 상태를 추정한다. 같은 OpenCV 함수를 써도 두 경로의 검색 범위, 색상 검증,
임계값과 상태 보정은 다르다. 버프가 비교적 안정적이라고 디버프까지 같은 정확도인 것은 아니다.

이전 실제 사진에서 재현된 디버프 경계 민감성 및 회복 중 가짜 재표시 결함은 수정 후
현재 재현도 통과했다. 모든 남은 라이브 현상을 이펙트/사용자 설정 탓으로 설명하거나,
알려진 두 결함의 수정이 모든 오인식의 해결이라고 확대하지 않는다.

## 공통 매칭의 의미

- `detect/icon_matcher.py:32`는 `cv2.matchTemplate(..., TM_CCOEFF_NORMED)`로 작은
  템플릿을 영상 안에서 이동시켜 가장 상관도가 높은 위치를 고른다. 게임 버프 이름/종류/
  효과를 이해하거나 게임 메모리에서 적용 여부를 얻는 방식이 아니다.
- 점수 0.8은 '이 버프일 확률 80%'가 아니다. 서로 다른 모양·크기·배경에서 확률로
  보정된 신뢰도가 아니라 해당 템플릿과 픽셀 변화 패턴의 상관계수다.
- `catalog.py:246`에서 매칭 이미지를 읽는다. 오버레이 표시 이미지와 매칭 템플릿은
  별개다. 같은 키의 사용자 매칭 이미지는 기본 이미지를 대체할 수 있다. 이것은 경로
  설명이며 사용자의 실제 설정이 잘못됐다는 판단이 아니다.
- 동일하거나 흑백 변환 후 같은 아이콘은 이름만 다르게 등록해도 구분 정보가 늘지 않는다.
  현재 검색은 항목별 독립 판정이어서 같은 위치를 여러 항목이 통과할 수도 있다.

## 버프 경로

1. 저장 영역을 물리 좌표로 캡처한다. 활성 게임에서는 목표 대기 주기 50ms, 비활성에서는
   최소 500ms다. 실제 주기는 캡처/판독 비용도 포함하므로 정확히 20fps를 보장하지 않는다.
2. `BuffEngine` 기본값은 영역 왼쪽 x=0~50의 좁은 아이콘 열을 검색한다.
   `detect/buff_detector.py:30`은 입력/템플릿을 그레이스케일로 바꾸고 기본 0.8 이상을 채택한다.
   버프 이름 글자는 읽지 않고 아이콘의 y 위치를 얻는다.
3. 기본 3회 연속 감지 후 표시한다. 시간 표시 버프는 해당 행 오른쪽의 숫자/시간 단위
   템플릿으로 남은 시간을 읽고 내부 시계를 맞춘다. 일반 구간은 약 1초 간격, 등장 직후와
   알림 기준 근처는 더 자주 읽는다. 큰 시간 점프는 이어지는 판독으로 확인한다.
4. 앵커를 한 번이라도 본 뒤 앵커가 사라지면 화면 기반 판단을 동결한다. 처음부터 앵커를
   못 봤다고 모든 판독이 무조건 중단되는 것은 아니다.
5. 활성 버프의 아이콘이 잠깐 미검출돼도 이전 행의 시간이 내부 시계와 3초 이내로 맞으면
   생존 증거로 보완한다. 연속 미감지 해제 기본값은 0.4초지만 이 보정과 앵커 동결이 함께 작용한다.

관련: `tracker/engine.py:46`, `:115`, `:155`, `tracker/buff_state.py`,
`ui/main_window.py:1288`, `:1309`.

## 디버프 경로

1. 저장 영역 전체를 원본 픽셀 그대로 검색한다. 활성 게임 목표 대기 주기는 150ms다.
2. 등록 템플릿을 화면 높이 16px에 맞춘다. 이번에 확인한 기본 버프 PNG는 14개 모두
   16×16, 기본 디버프 PNG는 15개 모두 28×28이며 후자는 엔진에서 16px로 변환한다.
   '버프 템플릿은 무조건 크고 디버프만 작다'고 설명할 근거는 없다.
3. 흑백 상관 점수로 후보 위치를 최대 4개 찾고 각 위치의 원본 컬러 패치로 최종 검증한다.
   전체 후보 무제한 컬러 검증은 하지 않는다. 현재 입력 영역 자체는 축소하지 않는다.
4. 기본 최초 감지 0.68, 유지 중 해제 0.58이다. 중간 점수는 직전 판정을 유지한다.
   모모·방해 카드는 배경 오탐을 줄이기 위해 각각 0.80/0.70을 쓴다.
5. 처음 적용으로 숨길 때는 0.3초 연속 검출 확인을 한다. 이미 숨겨진 항목은 raw 매칭이
   회복되면 미감지 대기를 취소한다. 실제 미감지가 0.4초 지속되면 미적용으로 다시 표시한다.
6. 버프와 반대로 **적용된 항목은 숨기고 미적용 항목을 표시**한다. 없는 것을 잘못 찾으면
   필요한 아이콘이 사라지고, 있는 것을 놓치면 이미 적용한 아이콘이 다시 나타난다.
7. off/band/percent 보스 확인은 별도 조건이다. 기본 off는 배경도 계속 검색하며, 다른 모드는
   보스 증거와 유예를 사용한다. 게임 디버프 아래 남은 시간을 OCR해 생존 보완하지는 않는다.

관련: `tracker/debuff_engine.py:28`, `:95`, `:197`, `:229`, `:243`, `:381`,
`ui/main_window.py:1403`, `:1435`.

## 과거에 실제로 확인하고 수정한 원인

- `DEBUFF-LIVE-QA-01`: 캡처 전체를 0.625배로 축소하고 템플릿을 별도로 10px로 줄였다.
  영역 시작/크기 반올림에 따라 완전히 같은 실제 아이콘의 재샘플링 격자가 달라졌다.
  사용자 원본의 마법 방어력 보호 감소가 0.64741로 최초 기준 0.68에 못 미치거나,
  프라가라흐(마법)가 인접 영역에서 0.63954로 탈락했다. 이펙트 때문이라고 추측한 문제가 아니다.
  현재는 캡처 무축소/16px 템플릿/후보 컬러 검증으로 원래 재현이 통과한다.
- `DEBUFF-QA-01`: raw 매칭이 회복됐는데 0.3초 재확정 대기를 미감지 시간에 포함했다.
  이미 숨긴 디버프를 0.4초 기준에서 잠깐 보여줬다가 다시 숨겼다. 순수 점수 오류가 아니라
  시간 상태 관리 오류였다. 현재는 회복 시 미감지 타이머를 취소하며 원래 재현이 통과한다.
- 모모·방해 카드 관련 기존 원본 회귀: 단순한 모양이 배경/이펙트와 비슷한 점수를 내고,
  잘못 감지된 이력이 낮은 해제 기준에서 남을 수 있던 경로를 아이콘별 임계와 검출 확인으로
  방어한다. 과거 측정 주석의 점수를 현재 모든 환경의 상한으로 취급하지 않는다.

기존 상세 증거: `디버프_실화면_판독누락_QA.md`, `디버프_깜빡임_검토.md`.

## 현재 남는 구분 한계

**Potential Risk / P2 / MATCH-STRUCTURE-01: 색·이름이 다른 유사 아이콘의 혼동.**

- 조건: 다른 등록 항목의 실제 이미지가 같거나 흑백 변환 후 동일한 패턴이다.
- 영향: 한 위치를 두 버프로 판단하거나 다른 행의 시간을 해당 버프의 시간으로 사용할 수 있다.
- 원인/위치: `buff_detector.py:40`의 흑백 변환과 항목별 독립 최고점 채택. 이름 OCR이나
  한 화면 위치에 하나의 항목만 배정하는 경쟁 판정은 없다. 시간은 생존 보조이지 이름 증명은 아니다.
- 통제 재현: 16×16 체크 패턴의 B 채널 255 아이콘과 R 채널 97 아이콘을 만들고 후자만
  입력했다. 실제 `detect_buffs`는 두 항목 모두 같은 y=0, score=1.0으로 검출했다.
  같은 입력을 디버프의 컬러 검증에 주면 B 아이콘 점수 0.0으로 거절했다.
- 분류 제한: 이미지 정보 손실의 실행 증거다. 특정 실제 기본 버프 쌍의 현재 라이브 오탐이나
  사용자 제보의 원인을 확인한 것은 아니므로 확정 게임 버그로 보고하지 않는다.

**Potential Risk / P2 / MATCH-STRUCTURE-02: 단일 크기·검색 범위·시간 보정의 한계.**

- 조건: 게임의 실제 아이콘 렌더 크기/가림/배경이 등록 자료와 달라지거나 비슷한 패턴이 지속된다.
- 영향: 오탐, 미검출, 디버프의 재표시 및 필요 알림/표시의 오해가 가능하다.
- 원인/위치: 버프는 등록 크기 그대로, 디버프는 16px 한 크기만 쓴다. 디버프는 현재 영역
  전체를 검색하므로 무관한 배경 후보도 생긴다. 최대 4개 후보, 임계/0.3초 확인은 방어이지
  지속적인 오매칭의 증명이 아니다. 미감지 0.4초 뒤 표시는 버프처럼 시간 정보로 보완하지 않는다.
- 재현/검증: 단발 오매칭/회복, 원본 인접 ROI, 물리/마법 색 분리, 디버프가 없는 배경 사례는 이번
  회귀에 포함했다. 새로운 게임 배율/이펙트의 모든 연속 입력은 없어 해당 라이브 원인은 미확정이다.
  오버레이 배율 50~300%는 표시용이며 게임 아이콘 판독 크기를 자동 보정한다는 뜻이 아니다.
- 이펙트는 가능 조건 중 하나다. 현재 남은 제보가 이펙트 때문인지 연속 입력 없이 단정하지 않는다.

임계를 무조건 올리면 거짓 양성은 줄어도 실제 아이콘 누락이 늘 수 있고, 무조건 낮추면
반대가 된다. 특히 0.68/0.58 사이 이력 유지 구간은 최초 감지와 유지 결과가 다를 수 있다.
기획서의 1.5~2초 재표시와 현재 코드의 0.4초 차이는 기존 QA에 기록돼 있다. 최신 승인
정책을 맞춰야 할 문서 공백이지, 수치 차이만으로 새 버그나 사용자 과실을 단정하지 않는다.

## 다음 검증 방향

현재 구조를 모두 갈아엎거나 사용자에게 영역 재설정부터 요구할 근거는 없다. 남은 실패에는
직전 수초의 실제 ROI/원시 점수/후보 위치/확정 상태/타이머/게임 활성 상태를 작은 상한의
순환 진단으로 남겨, 점수 누락인지 상태 관리인지 분리하는 것이 우선이다.

필요하면 아이콘 매칭 띠와 보스바 증거 영역을 내부적으로 분리하고, 유사 아이콘 후보의
경쟁/색·이름 보조 검증, 실제 게임 배율 자료를 평가한다. 이번에 구현한 기능이 아니며
모든 프레임의 무제한 OCR/다중 배율 검색으로 게임 CPU 비용을 늘리자는 제안도 아니다.

이번은 설명 목적의 소스/오프라인 점검이다. 제품 변경이나 새 릴리즈 QA가 아니며 새로운
태그/버전 조정/릴리즈 명령을 만들지 않는다. 실게임 연속 오탐률과 장시간 Windows 게임
실행은 새로 실측하지 않았다. 사용자 조작을 초기 원인으로 삼지 않는다.
