# 배포 시간 단축·균열 시세 자동 조회·화면 헤더·잡담 가림 처리

- 날짜: 2026-10-20 (Asia/Seoul).

## 1. 목표와 작업 순서

1. 전체 테스트의 의미를 보존하면서 Windows 검증·빌드·게시의 총 대기 시간을 줄인다.
2. 던전 입장 계산기에서 믿음의 균열을 선택하면 새로고침을 누르지 않아도 시세 조회가 시작되고 비용이 표시되게 한다.
3. 전투 보조·편의기능·파티 모집 화면의 제목·설명·구분선 유무와 스타일을 공통 기준으로 통일한다.
4. 다른 창에 가려진 잡담의 표시·알림음을 차단하되, 투명 오버레이나 비활성 앱을 잘못 막아 다시 잡담이 전혀 안 나오는 회귀를 방지한다.
5. 개발 중에는 관련 검사로 네 변경을 검증하고, 후속 독립 QA 뒤 Windows 최종 비교·배포를 모아서 수행한다. 배포에 추가 승인 단계나 반복 전체 실행을 요구하는 구조를 만들지 않는다.

## 3. 성능 개선 범위와 안전 조건

### 우선: 같은 러너에서 격리 회귀 병렬화

- 표준 pytest-xdist를 사용해 기존 격리 회귀만 우선 2개 프로세스로 실행하는 안을 검증한다. 예: `pytest -n 2`이며 분배 방식은 fixture 소유 범위와 실제 측정을 보고 선택한다.
- 새 Windows job/matrix를 여러 개 만드는 것이 기본안은 아니다. 같은 러너 안의 2개 worker부터 확인한다. 무료 한도에 부담을 주는 중복 전체 실행과 산출물 증가를 피한다.
- 네이티브 Windows 검사·exe 빌드·후속 게이트·게시 단계는 기존 순서를 유지한다. 창·세션·오디오·실장치를 공유하는 네이티브 검사를 무조건 병렬화하지 않는다.
- worker별 설정·임시 경로·포트·IPC 이름·캐시 쓰기를 격리한다. Qt QApplication·MainWindow·타이머·워커를 서로 공유하지 않는다. 기존 외부 경계 및 QThread 누수 검사는 유지한다.
- 병렬 안전성이 확인되지 않은 사례는 명시적으로 분리해 한 번 실행하되 누락 없이 전체 수집 대상과 대조한다. 실패 후 무조건 재실행해서 녹색을 만드는 방식은 사용하지 않는다.

### 다음: 반복 준비와 대기 비용 정리

- 기존 `--test-inventory`와 사례별 setup/call/teardown 시간을 대조한다. 가장 느린 단일 검사도 약 19초이므로 한 사례만 고치는 것으로 6분 단축을 가정하지 않는다.
- 반복되는 ZIP 해제·이미지 읽기·불변 템플릿 준비를 조사하고, 안전한 읽기 전용 원본만 재사용한다. 변경하는 배열·사전·설정과 위젯은 테스트별로 격리한다. 캐시 크기·수명도 제한한다.
- fixture scope를 무조건 session으로 바꾸거나 MainWindow를 테스트 사이에 재활용해 타이머/구독/상태를 섞지 않는다. 누수·정리 assertion을 제거하거나 빈도를 낮춰 시간을 맞추지 않는다.
- 고정 sleep/qWait가 있다면 완료 조건과 상한으로 바꿀 수 있는 것만 정리한다. 부정 조건 관찰 시간과 늦은 콜백 검증은 보존한다.
- 조건·입력·경계·예상 결과가 같은 중복만 통합하고 원래 사례→새 위치를 기록한다. 다른 라이브 버그의 회귀를 '기능당 대표 테스트 하나'로 축소하지 않는다.
- 설치는 Python 약 8초 + 의존성 약 6초다. 현재 단계에서 설치 캐시 활성화가 주된 해결책이라고 보지 않는다. 캐시를 추가한다면 저장량·키·폐기 정책을 정하고 테스트 결과나 서로 다른 소스의 exe를 재사용하지 않는다.

### 성능 완료 기준

- 기존 전체 검사·네이티브 검사·실패 차단·동일 exe 게시·verify-only 비게시가 유지된다.
- 병렬 전후 대상 목록을 대조해 누락·중복이 없음을 확인하고 새 결함 검사를 포함한다.
- 개발 환경의 동일 조건 비교 후 Windows 최종 실행으로 회귀·네이티브·빌드·게시 각각과 총시간을 비교한다. CPU/메모리 과부하·불안정 실패가 없는지도 확인한다.
- 15분 목표 미달이면 실제 남은 병목과 측정값을 보고한다. 실패를 skip하거나 검증 범위를 몰래 줄여 완료 처리하지 않는다.

## 4. 믿음의 균열이 현재 수동 조회인 이유

- `ui/dungeon_cost_tab.py`는 던전 선택을 `_render()`에 연결하고 새로고침 클릭만 `_request()`에 연결한다. 선택 시에는 표만 바뀌고 API 작업은 시작되지 않는다.
- `ui/exchange_tab.py`는 선택 이벤트 `_on_region()`에서 비동기 조회를 시작하며 지역별 10분 메모리 캐시를 사용한다.
- 두 화면 모두 기존 market/auction 계층과 설정의 넥슨 API 키를 사용한다. 선택 자동 조회를 막는 API 제약이 발견된 것은 아니다. 초기 입장 계산기 명세가 수동 조회였기 때문에 UI 진입 조건이 달랐다.
- 이번 사용자 요청으로 해당 수동 전용 조건을 변경한다. 이전 동작을 사용자 조작 문제나 과거 요구 위반 버그로 분류하지 않는다.

## 5. 선택 자동 조회 요구

- 편의기능 → 던전 입장 계산기에서 **믿음의 균열을 선택하면 조회를 자동 시작**한다. 유효한 메모리 캐시가 있으면 즉시 표시하고 없으면 '시세 조회 중'을 표시한다. API 응답 전 임의 가격을 보여주는 요구는 아니다.
- 최초 선택은 기존 크롬바스 심연으로 유지한다. 앱 초기화 때 모든 탭이 생성된다는 이유로 균열 가격을 미리 요청하지 않는다. 나머지 세 고정 가격 던전 선택에는 API 요청이 없어야 한다.
- 같은 선택/클릭의 중복 이벤트와 새로고침 연타에도 동시에 요청은 하나다. 조회 중 다른 던전으로 갔다 돌아와도 기존 요청을 공유한다.
- 환전비율 계산기의 기존 기준과 맞춰 조회 성공/정상 '매물 없음' 결과를 세션 메모리에서 10분 재사용한다. 디스크에 가격·선택을 영구 저장하거나 주기 자동 갱신을 추가하지 않는다.
- 캐시 만료 후 균열 재선택/동일 항목 재클릭은 새 조회를 시작한다. 새로고침 버튼은 유지하며 유효 캐시도 명시적으로 다시 조회한다. 캐시/요청 시각은 일관된 기준으로 관리한다.
- 요청 실패·키 없음은 가격 0이나 성공 캐시로 저장하지 않는다. 렌더/타이머가 실패를 감지할 때마다 재요청하지 않는다. 새로고침이나 다시 선택하는 명시적 동작으로 재시도할 수 있어야 한다.
- 기존 실패 정책을 유지한다. 새 조회 중·실패·키 없음·매물 없음에서는 비용을 `—`로 구분하고 소모량은 표시한다. 오래된 가격을 새 조회 성공처럼 표시하지 않는다.
- 다른 던전으로 전환한 뒤 늦은 응답이 도착해도 선택을 강제로 되돌리거나 고정 가격 계산표를 균열 결과로 덮지 않는다. 정상 응답은 균열 캐시에만 반영하고 현재 선택을 존중한다.
- 선택 진입 처리에서만 자동 요청 여부를 판단한다. `_render()`·응답 처리·오류 표시가 다시 요청을 시작하는 재귀/무한 재시도 구조를 만들지 않는다.
- 기존 취소 플래그·30초 작업 제한·비동기 경계를 유지하고 UI 스레드를 막지 않는다. 기존 진행 중 결과 수신 외에 상시 폴링·새 워커 누적을 추가하지 않는다. 종료 뒤 응답은 UI·저장 상태를 변경하지 않는다.
- `균열의 편린` 정확명 최저 **개당가** 조회와 기존 산술식을 사용한다. 묶음 총액·클리어 보상·순이익을 섞지 않는다. 기존 API 계층을 재사용하고 API 키를 로그에 노출하지 않는다.
- '새로고침을 눌러야 조회된다'는 수동 전용 안내는 자동 조회 동작에 맞춘다. 기존 API 지연·조회 시각·오류/매물 없음 안내와 아이콘 새로고침은 유지한다.
- 환전비율 계산기의 기존 동작이나 다른 트래커/오버레이를 함께 리팩터링하지 않는다.

## 7. 기능 화면 상단 헤더 통일

### 관측과 원인

- 사용자가 제공한 v0.8.0 화면에서 버프는 기능 제목 없이 회색 설명으로 시작하고, 보스 패턴은 다른 곳보다 큰 제목, 도르카/투아림은 제목과 같은 밝기의 설명, 커스텀 오버레이는 제목과 회색 설명을 사용한다.
- 사용자는 편의기능에는 기능 제목이 모두 없고, 체력바·커스텀 오버레이에는 설명 아래 구분선이 있으나 다른 곳에는 없다고 추가 확인했다. 파티 모집도 제목 없이 구분선이 있다. 단순 문구 차이가 아니라 같은 역할의 시각 계층이 일관되지 않은 문제다.
- 소스에서도 `boss_tab.py`는 14px/700 제목을 직접 지정하고, `resource_tab.py`는 일반 QLabel 설명을 쓰며, 다른 화면은 `hint_label`이나 별도 도움말 행을 사용한다. 공통 feature header 경로가 없다.
- 이번 변경은 기능 상단 표시 규칙의 통일이다. 버프 판독·보스 알림·도르카·커스텀 프리셋·계산 로직의 재설계나 화면 전체 카드화는 포함하지 않는다.

## 8. 가려진 잡담의 표시·알림음

### 독립 확인: Confirmed Bug / P2 (최신 사용자 요구 기준)

- 발생 조건: 앱은 표시 상태지만 다른 불투명 창/게임이 얼굴·말풍선 영역을 덮는다. 잡담 및 소리 설정이 켜져 있고 자동 추첨이 성공하거나 클릭 요청이 처리된다.
- 사용자 영향: 보이지 않는 잡담 소리가 게임 중 재생된다. 자동 표시 횟수도 소비돼 실제 앱을 볼 때 대사를 만날 기회가 줄 수 있다. 사용자 조작 잘못이 아니다.
- 원인: `system/dialogue_visibility.py:129`의 기본 `display_available()`이 `check_occlusion=False`로 호출한다. 창의 표시·최소화·잠금·화면 범위는 검사하지만 타 창 가림은 검사하지 않는다. `ui/creator_dialogue.py:346`은 이 조건을 통과해 내부 `bubble.show()`/횟수 기록 후 소리 콜백을 호출한다. Qt의 내부 `isVisible()`은 다른 프로세스에 실제로 가려지지 않았다는 증거가 아니다.
- 현재 명세·`tests/test_dialogue_display_policy.py`도 다른 창 가림 허용을 명시한다. 이전 미표시 대응에서 완화된 경로와 이번 증상이 일치한다. **최신 사용자 요청은 가려진 상태를 다시 제외하는 것이며 이 요구를 우선한다.** 과거 정책의 테스트 통과를 이번 문제의 해결 증거로 제시하지 않는다.
- 독립 재현: `scripts/qa_dialogue_covered_sound_20261020.py`에서 불투명/완전 투명 덮개 × 자동/클릭 네 경우를 통제했다. 불투명 덮개는 `exposed=False`지만 기본 경로는 허용했고, 자동·클릭 모두 말풍선 내부 표시와 소리 콜백 1회가 발생했다. 자동은 표시 횟수도 1회 증가했다.
- 실행: `PYTHONPATH=src:. QT_QPA_PLATFORM=offscreen python -m pytest scripts/qa_dialogue_covered_sound_20261020.py -q --tb=short` → **4 passed / 2.46초**. 기존 표시 정책 검사까지 함께 실행하면 **23 passed / 9.75초**다. 현재 가림 허용 동작을 관측하는 사전 수정 재현이며, 수정 후 기대 조건은 아래 표로 바꿔야 한다. 이 통과는 수정 완료를 뜻하지 않는다.
- 검증 한계: Linux offscreen + 명시적인 Win32 경계 모델이다. 실제 Windows 합성·NVIDIA per-pixel 투명도·실제 음원 청취는 확인하지 않았다. 소리 콜백 발생을 실제 장치 재생 완료로 확대하지 않는다.

### 수정 요구와 재발 방지

- 가림 기준은 앱 전체가 아니라 **얼굴 및 표시 예정 말풍선 영역**이다. 다른 불투명 창이 이 영역을 가리면 자동 추첨·표시·소리를 하지 않는다. 다른 곳만 덮는 창 때문에 막지 않는다. 클릭 요청도 표시 직전 같은 조건을 확인한다.
- 표시/소리 직전에 유효성을 확인한다. 표시 도중 가려지거나 최소화·숨김·잠금으로 바뀌면 말풍선과 전용 재생을 중단한다. 기존 1초 확인 주기와 이벤트 경계를 활용해 늦어도 다음 정상 확인 주기에 중단하고, 고속 폴링·새 타이머 누적은 추가하지 않는다. 이벤트 사이 극히 짧은 상태 변화까지 원자적으로 감지한다고 보장하지 않는다.
- 표시 전 차단은 자동 표시 횟수에 넣지 않는다. 가려진 동안 추첨·소리를 예약/누적하지 않고, 복귀 시 기존 2분 간격·40%/20% 규칙에 따라 최대 한 번만 기회를 준다. 실제 노출 후 가려진 대사는 기존 표시 기록을 유지하며 복원 재생하지 않는다.
- **앱이 포그라운드일 때만 허용하는 우회는 금지한다.** 다른 모니터에서 게임을 조작해도 앱의 얼굴·말풍선이 보이면 정상 표시·재생해야 한다. 게임 포커스를 가져오거나 앱/말풍선을 최상위로 올리지 않는다.
- 이전 엄격 `exposed()`를 기본값으로 되돌리기만 하고 완료 처리하지 않는다. 투명한 NVIDIA 등 합성 창을 불투명 덮개로 오판했던 기존 미표시가 돌아오지 않는지 확인한다. 창 이름·실행 파일 예외 목록으로 통과시키지도 않는다.
- `WS_EX_TRANSPARENT`/클릭 통과만으로 시각적 투명성을 단정하지 않는다. 확인 가능한 alpha 0·cloaked·대상 밖 영역은 구별한다. per-pixel alpha/region API 오류 등 판정 불확실은 확인된 가림·확인된 노출과 진단상 구별하고 **안 보일 수 있는 소리는 내지 않는다.** 불확실 처리 때문에 실제 보이는 클릭·자동이 계속 막히는 사례는 해결 완료로 보지 않는다.
- Win32 직사각형만으로 모든 타 프로세스 합성 픽셀의 투명도를 정확히 알 수 있다고 주장하지 않는다. 지원할 판정 경로와 미확인 환경을 보고하고, 게임 화면의 지속 캡처·픽셀 비교를 새로 넣지 않는다. 요구를 만족하기 어려우면 표시 조건 완화를 몰래 재도입하지 말고 남은 제약을 먼저 보고한다.
- 필요한 진단은 차단 사유·대상 영역·API 실패 단계 중심으로 제한한다. 매초 동일 로그를 쓰거나 외부 창 제목/개인 화면을 수집하지 않는다. Win32 handle/GDI region은 모든 경로에서 해제한다. 잡담 실패를 트래커·다른 알림의 실패로 전파하지 않는다.
- 설정의 '잡담 소리 사용' 끄기는 임시 완화책일 뿐 수정 완료 기준이 아니다. 전용 50% 음량·설정 저장·다른 알림음을 보존한다.

이번 전달은 소스 경로·사용자 화면·현재 명세·Actions 실제 시간과 잡담 독립 재현에 근거한다. 제품 코드를 수정하지 않았으며 새 병렬 실행·자동 조회·공통 헤더·잡담 가림 수정의 구현/통과 결과는 아직 없다.

위 전달 당시의 관찰·요구는 보존한다. 실제 비교 렌더 공유 후 사용자 “이 기준으로 적용” 승인으로 전체 헤더를 적용했으며, 후속 소스 변경·테스트 보존·측정·NVIDIA 합성 미해결 범위는 [개발 검증 기록](후속요구_개발검증_20261020.md)에 구분했다. 이번 전달문 자체를 구현/독립 QA 완료 보고로 해석하지 않는다.
