# 디버프 실화면 판독 누락 독립 QA

검증일: 2026-10-15. 대상 소스: `4da1be6e02f9b365265fcd2cac53438adcb29038`.
커밋 이력은 조회하지 않았으며 현재 소스, 원본 PNG, 독립 실행 결과를 사용했다.

## 결론

**Confirmed Bug / P2 / DEBUFF-LIVE-QA-01**: 아이콘이 완전히 포함된 영역에서도
영역 경계에 따라 축소 결과가 달라져 실제 적용된 디버프를 미적용으로 표시한다.
자동 등록이 만든 정상 영역에서도 마법 방어력 보호 감소 누락을 실제 재현했다.
프라가라흐(마법) 누락도 아이콘을 자르지 않은 인접 영역에서 재현했다.

이는 공통 디버프 판독 경로의 결함이다. 이번 단계별 자동설정만의 신규 회귀나
제보 당시 현상의 유일한 원인이라고 확정하지 않는다. 제품 코드는 수정하지 않았다.

## 사용자 제보와 증거 범위

- 사용자는 라이브에서 마법 방어력 보호 감소가 미적용처럼 표시됐다고 제보했다.
  일부 순간에는 프라가라흐(마법)도 미적용처럼 표시됐으나 급박하여 촬영하지 못했다.
- 판독 영역은 이번 단계별 자동찾기로 새로 등록한 것은 아닌 것으로 기억한다고 답했다.
  정확한 등록 경로와 당시 저장 좌표는 아직 확인되지 않았다.
- 이번 원본 PNG 두 장의 보스 디버프 줄에는 대상 두 아이콘이 보인다.
  사진은 실제 아이콘의 존재와 입력 픽셀 검증에 사용했다. 사진만으로 앱의 직전
  상태, 당시 저장 영역, 사용자 아이콘 교체 여부, 모든 오버레이 갱신 순간을 복원할 수는 없다.
- 사용자의 조작이나 설정 실수를 초기 원인으로 삼지 않았다. 아래 영역 변화는
  판독기의 입력 경계 민감성을 검증하는 통제 조건이며 사용자 과실의 증거가 아니다.

## Confirmed Bug: DEBUFF-LIVE-QA-01

### 발생 조건과 사용자 영향

실제 게임 아이콘이 있는 원본을 기본 번들 템플릿으로 판독한다. 감지 이력이 없는
상태에서 시작하거나 추적기를 재생성한 상태로 같은 장면을 읽으면, 특정 정상 영역에서
아이콘의 점수가 최초 감지 기준 `0.68`에 못 미쳐 미적용 항목으로 계속 남는다.
사용자는 이미 적용된 디버프를 다시 걸어야 하는 것으로 오해할 수 있다.

### 실제 실행 경로

`SetupFlow.run` -> 실제 `perform_autofind` -> 실제 worker의 `run_detector("debuff")`
-> 실제 보스바 검증 -> 영역 승인 -> 임시 JSON 저장 -> `DebuffEngine.tick`.

캡처만 원본 PNG로 공급하고, 승인은 자동 수락했다. 실제 Windows 캡처나 게임 입력을
자동화하지 않았다. DPI 변환은 명시적으로 100% 시나리오로 고정했다.
사용자의 실제 DPI를 100%라고 가정한 결과가 아니다.

두 사진 모두 보스바 `(1016,1246,521,37)`을 검출하고 디버프 영역
`(1016,1195,521,88)`을 정상 저장했다. 각 새 엔진에 150ms 간격으로 12회 입력했다.
판독 대상은 두 디버프뿐이며 다른 템플릿은 이들의 점수 계산에 관여하지 않는다.

인접 영역에서도 대상 아이콘은 잘리지 않는다. 재현 코드에서 두 아이콘이 들어 있는
공통 내부 픽셀을 `np.array_equal`로 확인했다. 첫 사진의 자동 등록 영역 누락은
`off`, `band`, `percent` 세 방식 모두에서 발생했다. 보스 유무 게이팅만의 문제가 아니다.

### 기술적 원인

`DebuffEngine._scale`은 전체 캡처 영역을 `0.625`배로 줄이되 목표 폭과 높이를 각각
반올림하여 `cv2.INTER_AREA`로 재샘플링한다. 템플릿은 독립적으로 높이 10px로 축소한다.
작은 실제 아이콘의 축소 격자 위치와 실제 축소 비율이 영역 시작점과 크기에 따라 달라진다.
결과적으로 원본의 아이콘이 그대로여도 상관 점수가 감지 경계를 넘나든다.

초기 `_matched=False`인 경우 `0.58 <= score < 0.68`은 감지로 승격되지 않는다.
같은 낮은 점수의 정상 장면을 오래 공급해도 감지 확인 대기가 시작되지 않으며,
`_shown=True`가 유지된다. 단순히 재표시 유예를 늘리는 것으로 이 최초 누락은 해결되지 않는다.

### 기존 깜빡임과의 구분

먼저 좋은 점수로 감지시킨 뒤 동일 원본의 기본 영역으로 바꾸면 두 사진 모두 감지가
유지됐다. `0.64741`이 해제 기준 `0.58`보다 높기 때문이다. 이 반례도 테스트했다.
따라서 이번 정지 사진의 점수만으로 **계속 감지되던 항목이 사라졌다가 돌아오는 전체
라이브 시퀀스까지 재현했다**고 주장하지 않는다. 그 순간의 실제 저장 영역과 연속 입력,
엔진 재생성 여부가 있으면 같은 원인인지 더 좁힐 수 있다. 자료 부족을 사용자 탓으로 돌리지 않는다.

## 독립 재현

저장소 루트에서 실행:

```bash
uv run pytest scripts/qa_debuff_live_detection.py -q --tb=short
```

현 소스 결과: **6 failed, 8 passed (4.95초)**. 실패는 미해결 결함을 드러내는 기대 실패이며
`xfail`이나 `skip`으로 숨기지 않았다. 기본 제품 테스트 수집 대상에 넣지 않았다.

기존 복구 깜빡임 재현과 관련 제품 테스트도 별도 실행했다:

```bash
uv run pytest scripts/qa_debuff_flicker.py tests/test_debuff_engine.py tests/test_debuff_fp_latch.py tests/test_debuff_momo_fp.py -q
```

결과: **49 passed (3.11초)**. 기존 복구 수정 통과가 실제 아이콘 판독 정확성을 보장하지는 않는다.
Fontconfig 캐시 경고는 있었으나 테스트 예외나 결과 누락은 없었다.

## 개발 세션 전달 사항

- 특정 영역 높이를 정답으로 고정하거나 감지 임계만 일괄 낮추기 전에, 원본 아이콘이
  온전히 포함된 영역의 시작점/크기 변화에도 판독이 안정적인지 검증할 것.
- 기본 자동 등록 영역과 기존 직접 지정 영역 모두에서 두 실제 PNG 회귀를 포함할 것.
- 아이콘 띠를 좁히는 경우에도 재샘플링 격자 문제가 사라졌는지 확인하고, 보스바 게이팅과
  사라짐 경고가 동일 영역에 의존하는 기존 동작을 별도로 보존할 것.
- 과소 인식을 고치다가 물리/마법 아이콘 상호 오탐, 모모/방해 카드 배경 오탐이 늘지 않는지
  해당 디버프가 없는 기존 실화면 샘플로 검증할 것.

## 미검증 범위

현재 환경은 Linux/offscreen이다. Windows 배포 exe, 당시 사용자 설정/커스텀 템플릿,
실시간 캡처와 연속 깜빡임, 실제 DPI/멀티모니터, 장시간 자원 사용은 이번 실행으로
검증하지 않았다. 시작 화면 변경이나 전체 릴리즈 QA 완료로 해석하지 않는다.
확인된 판독 결함이 남아 있으므로 이번 조사 결과를 QA 통과나 릴리즈 승인으로 보고하지 않는다.
