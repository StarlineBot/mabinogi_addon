# 최적화 알파 독립 QA 후속 수정·개발 검증

2026-10-21. 제품 기준 `7faf18a`, 수신한 독립 QA `e16e1fa`.
[원본 독립 QA](최적화알파_전투제어_독립QA_20261021.md)의 확정 결함 2건에 대한 개발 수정 기록이다.
이 문서의 개발 회귀 통과는 후속 독립 QA 또는 Windows 검증 통과를 뜻하지 않는다.

## 재현과 수정

수정 전 원본 재현 명령에서 **2 failed, 2 passed**를 직접 확인했다.

1. **P1: 포함 PresentMon의 v1 CSV와 파서 불일치**
   - 포함 도구·실행 인자는 그대로 유지하고 실제 v1 열인 `QPCTime`, `msBetweenPresents`를 읽는다.
     다른 모드의 `TimeInQPC`, `MsBetweenPresents`는 별도 계약으로 구분한다.
   - 원시 QPC를 주파수로 나눠 절대 시각을 구하며 상대 `TimeInSeconds`를 대신 사용하지 않는다.
     알 수 없는 열 조합·중복 열·두 계약이 혼합된 헤더는 계속 거부한다.
   - 고정 버전의 헤더를 `tests/data/presentmon-v2.3.1-v1-qpc.csv`로 보관했다.
     행은 50 FPS 합성 자료이며 Windows 캡처라고 보고하지 않는다. 상대 초와 절대 QPC가
     서로 다르게 설정되어 잘못된 시간 열 사용을 검출한다.
   - Qt 수집 수신기를 통해 해당 CSV를 여러 조각으로 전달하고 실제 앱 파서까지 50 FPS를
     읽는 경로도 확인했다. 일반 시각 오류·누락·stale·대상 구분 검사는 유지한다.

2. **P2: 검사 중 게임이 시작되어도 네트워크 변경·재연결 진행**
   - 원본 조회 전후, 복구 기록 저장 후 실제 쓰기 직전, 각 어댑터 재연결 직전에 게임 상태와
     중단/접근 상태를 다시 검사한다. Windows 레지스트리 경로의 어댑터 조회 후에도 재검사한다.
   - 게임 관측 실패도 변경 보류로 처리한다. 보류를 일반 실패와 구분하여 남은 배치를 중단한다.
   - 이미 적용한 값·원본·재연결 대기는 기록에 유지한다. 자동 원복/재연결로 게임 연결을
     다시 끊지 않으며, CPU 배치/원복은 네트워크 보류와 분리한다.
   - 쓰기 직전 보류되어 변경하지 않은 항목은 불필요한 어댑터 재시작을 예약하지 않는다.
     부분 적용 후에는 기존 재시작 대기를 지우지 않는다. 접근 해제 후에도 명시적 복구는 가능하다.
   - 프로세스 열거, Governor 확인, RSS 사전 조회, 원본 읽기, 기록 저장, 네이티브 준비 단계,
     첫 변경 직후/마지막 변경 직후의 게임 시작·중단·접근 해제를 나눠 회귀로 검증했다.

이미 실행 중인 단일 Windows 명령과 게임 시작을 원자적 트랜잭션으로 묶거나 진행 중 명령을
취소할 수 있다는 보장은 아니다. 실제 OS 명령 경계의 전환·권한·장치 동작은 Windows 검증 범위다.

## 회귀 위치

원본 네 가지 재현의 assertion을 유지하여 `test_support/regressions/optimization_contract.py`로
이관했다. `tests/test_optimization_contract.py`가 정식 회귀로 수집하고 기존
`scripts/qa_optimization_contract_20261021.py`는 같은 검사의 역사 명령 진입점으로 남겼다.
일반 수집에서 두 경로를 중복 실행하지 않는다. 첫 원본 QA의 실패 기록은 변경하지 않았다.

추가 전환 사례는 위 정식 테스트 파일에, 수집기 조각 수신은 `tests/test_optimization_ui.py`에 있다.
