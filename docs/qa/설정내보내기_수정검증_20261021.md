# 설정 내보내기 UI 정지·백업 비밀값 후속 수정·개발 검증

2026-10-21. 수신 QA `9b9856e`, 제품 기준 `115892a`.
[독립 QA](설정내보내기_UI정지_백업비밀값_QA_20261021.md)의 확정 결함 두 가지를 수정한 개발 기록이다.
실제 사용자 ZIP·키·웹훅은 읽거나 전송하지 않았다. 실제 유출 여부와 Windows 응답 없음의 정확한
지연 시간을 관측한 기록이 아니며, 개발 회귀는 후속 독립 QA/실사용 통과와 구분한다.

## 재현과 수정

원본 재현 명령을 수정 전에 실행하여 **3 failed** (1.53초)를 확인했다.
파일과 디스코드 내보내기 모두 ZIP 준비가 UI 스레드였으며 자동 `.bak`에서 합성 비밀값을 발견했다.

- 파일/DM 버튼은 작업 시작 전에 비활성화하고 `ZIP 준비 중…`을 표시한다. 공통 소유 QThread가
  자산 열거·압축·임시 ZIP 쓰기·최종 파일 교체·선택적 전송을 수행한다. UI 객체는 워커에서 다루지 않는다.
  GUI 스레드에서 워커를 기다리거나 워커에서 `processEvents()`를 호출하지 않는다.
- 하나의 내보내기만 진행한다. 진행 중 가져오기/초기화를 버튼과 슬롯 양쪽에서 막으며 설정을 쓰지 않는다.
  계정 ID/이름과 전송 대상은 시작 시 복사한다. 계정 변경은 취소 요청을 보내고 이전 계정의 완료 알림을
  새 상태에 표시하지 않는다. 파일 내보내기도 성공·실패 후 버튼을 복구한다.
- QThread는 앱에 소속되어 UI 파괴로 실행 중 스레드가 파괴되지 않는다. UI 파괴는 취소를 요청하고
  Qt 수신 연결을 해제한다. 실제 앱 종료는 `prepare_close()`로 취소 요청 후 이벤트 루프에서 재확인하며,
  워커가 멈춘 뒤 기존 종료 절차를 진행한다. 작업 완료 후 스레드 객체를 정리한다.
- 내보낼 자산은 카탈로그가 사용하는 `buff/icon/*.png`, `buff/image/*.png`, `debuff/icon/*.png`만이다.
  사용자 폴더 전체를 순회하지 않으며 하위 폴더를 재귀 탐색하지 않는다. 진단·로그·수집/프레임 기록·이전 ZIP·
  설정 사본/임시/복구 파일은 포함하지 않는다. symlink·Windows reparse point·hardlink 자산도 거부한다.
- `config.json`이 유일한 설정 원문이며 비밀값을 제거한다. 기존 Nexon API 키/문의 웹훅에 더해
  같은 설정에서 읽는 `configWebhookUrl`도 제외하고 가져오기/초기화 시 기존 비밀값을 유지한다.
  로컬 `.bak` 자체를 삭제하거나 손상시키지 않는다. 이전 ZIP의 정상 설정·자산은 가져오되 원문 설정 사본이나
  진단 파일은 복원하지 않으므로 예전 ZIP을 가져올 때도 raw 설정이 다시 들어오지 않는다.
- 파일 저장은 목적지 옆 임시 ZIP → flush/fsync → 원자적 교체 순서다. 취소·크기 초과·읽기/쓰기 실패 시
  임시 파일을 정리하고 기존 목적지는 보존한다. 설정 원본/복구 파일 자체를 ZIP 목적지로 덮어쓰지 않는다.
  열거 후 자산이 교체/변경되면 읽기 전 식별자와 읽은 크기·시각을 확인하여 실패 처리한다.
- DM도 동일한 ZIP 생성기를 사용하고, 임시 디스크 파일을 multipart 파일 스트림으로 전송한다.
  ZIP 전체 바이트와 multipart 전체 바이트를 UI/메모리에 겹쳐 만들지 않는다. 임시 디렉터리는 실패 시에도 정리한다.
  성공은 **릴레이 접수**이며 실제 DM 전달은 앱에서 관측할 수 없으므로 별도 확인 문구로 안내한다.

## 제한과 취소 경계

| 항목 | 앱 제한 |
|---|---|
| 설정 원문 | 1 MiB (기존 복구 사본을 사용할 때도 검사) |
| 자산 개수 | 4,096개, 자산 폴더 열거 8,192항목 |
| 일반 파일 백업 | 설정 포함 원본 합계 64 MiB, ZIP 64 MiB |
| ZIP 준비 | 30초, 열거/64 KiB 복사·출력 경계에서 확인 |
| DM 백업 | 원본·ZIP 각 8 MiB의 앱 전송 예산 |
| 작업 수/전송 | 탭당 1개, 전송 소켓 timeout 5초 |

DM의 8 MiB는 보수적인 **앱 예산**이며 모든 Discord/채널의 영구 첨부 한도라고 주장하지 않는다.
생성 전에 원본 합계를 검사하고 출력 중에도 ZIP 크기를 제한한다. 서버의 더 작은 제한/413은 별도 오류로
표시하며 일반 파일 저장을 안내한다. 전송 예산은 `settings_sync.BACKUP_UPLOAD_BUDGET`에서 관리한다.

협력적 취소는 코드가 돌아오는 지점에서 적용한다. 이미 실행 중인 단일 OS 디스크 호출/HTTP 요청을 강제로
되돌릴 수 있다는 보장은 아니며, 릴레이가 이미 접수한 요청을 계정 변경으로 회수할 수도 없다.
준비 마감 시간과 소켓 timeout을 전체 전송의 절대 완료 시한으로 혼동하지 않는다.

## 회귀 이관

원본 QA의 UI 두 사례와 `.bak` 비밀값 사례를 `test_support/regressions/settings_export.py`로 이관했다.
`tests/test_settings_export.py`가 정식 수집하고 `scripts/qa_settings_export_blocking_20261021.py`는
같은 사례의 호환 진입점으로 남겼다. 기존 QA의 실패 기록은 유지했다.

UI 두 사례의 최소 QWidget stub은 변경된 실제 버튼/신호/작업 수명을 검증할 수 없어 실제 SettingsTab으로
교체했다. 원본의 UI 스레드가 아니어야 한다는 assertion과 heartbeat 확인은 유지한다. 스레드 ID는 UI에서
확보한 OS 스레드 ID와 비교한다. 테스트가 `app.thread()`를 호출해 Qt의 실제 메인 스레드 래퍼를 만들면
기존 범용 QThread 누수 assertion이 그 래퍼까지 실행 중 워커로 식별하므로, 누수 검사를 약화하지 않고
검사 코드의 불필요한 메인 QThread 래퍼 생성을 없앴다.

진단 원본은 이제 의도적으로 제외하므로 비압축성 합성 4 MiB를 **허용된 아이콘 경로**에 넣어 실제 압축한다.
압축 워커의 진입/해제 조건 사이에 UI heartbeat와 비활성 버튼을 확인하고 저장된 자산도 검사한다.
`.bak` 사례는 원본의 모든 ZIP 멤버 비밀값 검사 assertion을 유지했다. 일반 CI에서 역사 진입점과 정식
회귀를 중복 수집하지 않는다.

추가 회귀는 명시적 자산 범위/원문 사본 제외/세 번째 웹훅 제외, 기존 ZIP·로컬 비밀값 호환,
개수/설정/원본/ZIP/시간 제한, 압축 전 제한, 열거/복사/교체 직전 취소, 교체 실패·중간 변경,
연결 파일/폴더 모델, 실제 UI 중복/가져오기/초기화 차단, 계정 변경·종료·UI 파괴, 실패 후 버튼 복구,
파일 스트림 요청 길이·소켓 오류·413·크기 초과·전송 전 취소를 포함한다.

## 미검증과 후속

실제 Windows의 느린/가득 찬 디스크·사용자 데이터 규모·외부 프로그램과 동시 파일 교체,
실제 Discord/봇의 릴레이·DM 도착·exe는 실행하지 않았다. 링크/Windows reparse 회귀 일부는 API 모델이다.
후속 독립 QA와 Windows 실사용을 완료하기 전까지 실제 제보가 해결됐다고 단정하지 않는다.
이번 수정 단계에서 Actions·태그·릴리즈·실제 웹훅을 실행하지 않았다. 아직 미사용 `v0.10.1`에 변경을 모았다.
