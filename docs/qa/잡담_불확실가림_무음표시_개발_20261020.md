# 잡담: 불확실한 가림에서 무음 표시 시도

기준 소스는 QA 전달 `a7b12ef`이며 제품 기준은 `41a483e`다. 사용자 답변 **“그렇게”**로
불확실 가림의 표시 차단을 무음 표시 시도로 변경 승인받았다. [명세 15절](../creator-dialogue-spec.md#15-불확실한-가림의-무음-표시-시도-2026-10-20-사용자-승인)이 이전 조건에 우선한다.
이 문서는 개발 검증이며 독립 QA/실제 Windows 합성·청취 통과 보고가 아니다.

## 원인과 변경

QA의 flags=0/region=0 재현은 타당했다. 이전 `display_available()`은 합성 창을 unknown으로 분류해도 false를 반환했고,
클릭·자동이 공통으로 이 반환을 사용해 보이는 말풍선까지 계속 거부할 수 있었다.
alpha=0/flags=0을 투명하다고 확정하거나 클래스 이름으로 예외 처리하는 대신, 승인된 정책으로 표시와 소리 허가를 분리했다.

| 상태 | 말풍선 | 소리 | 자동 추첨·기록 |
| --- | --- | --- | --- |
| 확인된 노출 | 기존 표시 | 설정에 따라 전용 50% 재생 | 기존 2분/40%·20% 정책 |
| 확인된 불투명 가림 | 차단/표시 중이면 닫음 | 차단/중단 | 표시 전이면 추첨·표시 횟수 증가 없음 |
| 겹친 창의 합성/alpha/region 불확실 | 앱 내부 표시 시도 | 차단/진행 중 전용 소리 중단 | 기존 추첨, 내부 표시 성공은 기록. 실제 가려졌어도 소모 가능 |
| 잠금·최소화·숨김·화면 밖·배치 불가·투어/영역 지정 | 차단 | 차단 | 기존 차단 유지 |
| 입력 데스크톱/창 열거 실패·대상 HWND 미확인 | 차단 | 차단 | 기존 차단 유지 |

`system/dialogue_visibility.py`의 기본 `display_available()`은 불확실한 합성에서 true와 `visibility=unknown` 진단을 반환한다.
엄격한 기존 `exposed()`의 기본값은 그대로 false이며 역사 재현/기존 API 경계는 유지한다.
불확실한 창을 만난 뒤에도 Z 순서의 나머지 창을 검사한다. 그 뒤의 확실한 불투명 가림을 발견하면 false다.
각 창의 alpha/region 증거를 분리해 앞선 창의 API 오류가 다음 불투명 창을 unknown으로 바꾸지 않도록 했다.
새 캡처·이름 예외·포커스 변경·최상위 창·고속 폴링·상시 로그·타이머/worker는 추가하지 않았다.

`ui/creator_dialogue.py`는 매 노출 확인에서 소리 허가를 갱신한다. unknown이면 표시 전 재확인도 무음이며,
이미 재생 중인 전용 재생기를 중단한다. 기존 1초 확인과 3초 말풍선 수명을 사용한다.
unknown에서 노출로 복귀해도 이전 소리를 다시 재생하지 않는다. 이후 새 표시만 설정에 따라 재생한다.
다른 알림 재생기/음량·잡담 설정 저장·원격 대사·자동 주기/확률은 유지한다.

## 회귀와 재현 보존

- 기존 `test_dialogue_display_policy.py`에 통합했다. opaque×클릭/자동의 추첨/표시/소리 0회는 유지한다.
- 기존 unknown 차단 기대만 최신 승인으로 바꿨다. flags=0, alpha API 실패, region API 실패, color-key, NOREDIRECTIONBITMAP 각각의 클릭·자동 무음 표시·3초 수명·포커스 비간섭·타이머 불변을 확인한다.
- 표시 중 노출 → unknown → 노출에서 문장 수명 유지, 전용 소리 중단, 복귀 시 재생 없음, 새 클릭만 재생을 확인한다.
- unknown/opaque의 Z 순서 두 경우, unknown 이후 owner 미확인/열거 실패, cloak 조회 실패를 검사한다. 표시 시도가 잠금/화면 경계까지 풀지 않음을 기존 검사로 유지한다.
- 공용 native 모델에 region API의 기본 'region 정보 없음'(0)과 임시 GDI 해제를 명시했다. API가 없어서 우연히 unknown이 되는 모델을 고쳤으며, 실패 검사는 별도로 오류를 주입한다.
- 새 QA 진입점 `scripts/qa_dialogue_ambiguous_composition_20261020.py`는 같은 flags=0/region=0을 사용해 **표시 시도 성공·소리 0회**, 이후 새 노출 요청의 소리 회복을 검증하도록 갱신했다. 본래 독립 QA 관찰은 역사로 보존한다.
- 기존 CEF 로그 probe 6개는 엄격 `exposed()`의 분기 관찰로 그대로 통과한다. 이것을 제품 기본 표시가 계속 차단된다는 증거로 혼동하지 않는다.
- 수동 잡담 만료 후 첫 자동 추첨은 원래 허용된다. 만료 검사에서 새 자동 추첨을 실패하도록 난수를 주입해, 새 자동 표시를 수명 초과로 오인하지 않도록 했다. 제품의 수명/자동 정책을 변경한 것이 아니다.

## 확인 범위

소스/API 모델 기준으로 이전 CEF 입력에서도 무음 표시 경로가 열렸다. 타 프로세스의 실제 투명도를 알아낸 수정은 아니다.
말풍선은 기존 앱의 자식 위젯으로 Windows의 실제 가림을 따른다. 실제 Windows/NVIDIA 합성·오디오 장치·장시간 리소스 검증은 미실행이다.
미공개 v0.9.0 노트에 변경을 반영했다. 버전/태그를 추가로 올리거나 workflow·배포를 실행하지 않았다.
개발 통과는 후속 독립 QA 통과로 대신하지 않는다.
