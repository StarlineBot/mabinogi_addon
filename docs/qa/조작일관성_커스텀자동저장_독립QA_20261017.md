## CUSTOM-AUTOSAVE-REPLACE-QA-01

- 분류/심각도: **Confirmed Bug / P1**, 설정 데이터 덮어쓰기 때문에 배포 차단.
- 조건: 커스텀 프리셋 A를 적용한 상태에서 편집이 저장 대기 또는 저장 실패 상태로 남는다.
  이후 설정 화면의 가져오기(JSON/ZIP)나 초기화를 정상 실행한다.
- 기대: 명시적으로 교체/초기화된 설정을 이전 세션의 예약 저장·종료 저장이 덮어쓰지 않는다.
  교체 전 미반영 편집을 어떻게 보존할지 정하더라도, 교체 성공 이후 이전 세션에서 다시 쓰면 안 된다.
- 실제 영향: 가져온 설정의 현재 구성이 옛 A의 구성으로 돌아간다. 가져온 프리셋 이름도 A면
  **가져온 A 자체의 내용이 소실**되고, 다른 이름이면 삭제된 옛 A가 다시 섞인다.
  초기화에서는 제거됐던 `customOverlay.overlays/presets`가 다시 생성된다.

### 실제 실행 순서

1. 실제 메인 창에서 old-A(원본 x=1)를 적용하고 원본 x=4의 오버레이를 추가한다.
2. 두 경로를 나눈다. 300ms 예약 저장이 남아 있는 경로와, 한 번의 쓰기 실패를 주입하고
   쓰기 권한을 복원한 경로다. 후자는 타이머가 멈춘 dirty 상태여서 빠른 조작 타이밍이 필요 없다.
3. 실제 `SettingsTab._on_import_config` 또는 `_on_reset_config`를 실행한다.
   파일 선택과 확인 메시지만 대체한다. 가져오기/초기화/신호/저장/메인 종료 구현은 실제 코드다.
4. 가져오기는 원본 x=99인 같은 이름 A, 다른 이름 B, 같은 이름 A를 담은 ZIP을 각각 사용한다.
   가져온 직후 실제 파일의 현재 구성/프리셋을 복사해 기준으로 삼는다.
5. 정상 종료하거나 Qt 이벤트 루프에서 450ms 기다린 뒤 실제 파일을 다시 읽는다.
6. 모든 dirty 조건에서 x=99가 x=1/4로 바뀌거나 초기화한 옛 A가 되살아난다.
   반면 예약 저장/오류가 없는 정상 대조군 2조건은 교체된 설정을 유지한다.

```bash
PYTHONPATH=src:. QT_QPA_PLATFORM=offscreen python -m pytest scripts/qa_custom_autosave_import_reset.py -q --tb=short
```

- 최종 결과: **8 failed, 2 passed (5.43초)**. 실패 8개는 가져오기 3종/초기화 × 종료/타이머다.
  같은 원인 한 건의 여러 재현 조건이며 8개의 별도 버그로 세지 않는다.
- 새 재현은 `scripts/qa_*.py`에 두어 일반 `testpaths=tests`에 자동 수집되지 않게 했다.
  통과로 바꾸거나 skip하지 않았고 수정 후에는 같은 기대값으로 전부 통과해야 한다.
