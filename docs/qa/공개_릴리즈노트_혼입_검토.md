## NOTES-QA-01: Confirmed Bug / P2

- 발생 조건: 태그 사이 앱 소스가 변경됐고, 그 사이 영어 또는 내부 작업 제목의 커밋도 포함됨.
- 사용자 영향: 공개 업데이트 내역에 영어·내부 QA/기획 작업이 노출되고 실제 배포 기능 설명과 혼재함.
- 기술적 원인: `.github/workflows/release.yml`의 `Build release notes` 단계는 앱 코드 변경 여부만
  확인한 뒤 해당 범위의 모든 커밋 제목을 `notes.md`로 만든다. 사람이 작성한 앱 내
  `assets/release_notes.md`의 버전별 본문은 사용하지 않는다.
- 관련 위치: `.github/workflows/release.yml:151`의 `git log` 호출과 공개 CHANGELOG/README·
  디스코드 게시 단계. 이 QA에서는 커밋 이력을 조회하지 않고 현재 workflow와 게시 문서만 확인했다.
- 재현 방법: 공개 저장소 `CHANGELOG.md`·`README.md`의 v0.4.65 섹션을 앱 내
  `src/mabinogi_addon/assets/release_notes.md` v0.4.65 섹션과 비교한다.
- 검증 결과: 앱 내 본문은 두 수정 사항만 한글로 설명한다. 공개 문서는 여섯 커밋 제목이며,
  영어 QA 제목과 요리·자동찾기 기획 문서 작업이 포함돼 실제 게시 결과로 확인됐다.
  QA 담당자가 영어 커밋 제목을 작성한 점도 직접적인 원인이며 한국어 작성 지침에 반영했다.

## 공개 문서 교정

- 앱의 기존 `_parse_sections()` 파서로 v0.4.65 본문을 읽어 공개 CHANGELOG·README의
  해당 버전 내용만 같은 한글 설명으로 교정했다. 날짜·이전 버전·README 소개는 보존했다.
- 공개 저장소 교정 커밋: `80c13880324052cb475aa9be2ae76d1a0fa2a525`.
- 두 원격 문서가 교정 결과와 일치함을 확인했다. 앱 소스·exe·태그·`version.json`은 수정하지 않았다.
- 공개 GitHub Release body는 조회 당시 비어 있었다. 위 여섯 줄은 공개 문서에서 확인했다.
- 이미 발송된 디스코드 메시지는 문서 수정으로 자동 갱신되지 않는다. 이 세션에는 메시지 편집
  도구가 없어 해당 공지는 변경하지 않았으며 접근 토큰·웹훅 시크릿을 읽거나 요구하지 않았다.

## 개발 세션 전달

- 다음 릴리즈부터 공개 노트도 사람이 작성한 앱 노트의 **해당 태그 버전 본문**을 사용하도록
  생성 경로를 변경한다. 커밋 제목을 한글로만 바꾸면 내부 작업 혼입은 여전히 남는다.
- 없는 버전·빈 본문·태그와 노트 불일치에서 원시 커밋 목록으로 조용히 폴백하지 않도록 한다.
  실제 기능 설명 없이 배포되는 경우의 처리도 명시적으로 정한다.
- 동일 본문을 CHANGELOG·README·디스코드가 공유하는지, 재실행으로 항목이 중복되지 않는지,
  이전 버전 내용을 보존하는지 검증한다. 기존 앱 노트 파서는 별도 노트 변경 없이 정상이다.
- QA에서는 생성 workflow를 임의로 수정하지 않았다. 현재 게시 문서 교정과 원인 보고는
  완료됐지만 자동 생성 경로의 재발 방지는 개발 수정이 필요하다. 문서 교정에 exe 재배포나
  새로운 Windows 수동 실행·태그를 요구하지 않는다.
