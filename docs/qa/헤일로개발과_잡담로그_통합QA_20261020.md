### Highly Likely Bug / P1: 새 Windows no-region 검사가 정상 API 예외를 실패로 처리

- 조건: `tests/windows/test_dialogue_visibility.py:10`의 shape=None 사례로 명시적 region이
  없는 실제 HWND를 검사한다.
- 영향: unit 통과 뒤 Windows 네이티브 단계가 실패해 exe 후보 생성을 막을 가능성이 매우 높다.
  앱 런타임의 새로운 크래시를 확인한 것은 아니다.
- 원인: GetWindowRgn은 명시적 region이 없으면 ERROR(0)를 반환한다. pywin32의
  int_regiontype typemap은 이를 정수 0으로 돌려주지 않고 win32gui.error를 발생시킨다.
  제품 helper는 예외를 잡고 None과 region_error를 남긴다. 테스트 `:38`은 None을 기대하면서도
  region_error가 없어야 한다고 단정해 실제 계약과 충돌한다.
- 검증: 실제로 추가된 Windows 테스트 함수를 그대로 호출하되 위 pywin32 반환 계약을
  모델링했다. `:38` assertion 실패를 확인했다. Windows OS를 실행한 결과로 부풀리지 않는다.
- 수정 방향: no-region의 정상적인 정보 부재와 예상하지 못한 API 실패를 구분한다.
  정상 부재는 unknown/보수적 차단을 유지하고, 그 상태를 명시적으로 assertion한다.
  실패 사례를 skip하거나 모든 오류를 정상으로 취급하지 않는다.

### Confirmed Bug / P2: 새 Windows shape fixture의 GDI 소유권 이전 누락

- 조건: 같은 테스트 `:27`에서 PyGdiHANDLE region을 만들고 `:29` SetWindowRgn에 전달한다.
- 영향: 테스트 자체가 HWND가 소유하는 region을 조기에 DeleteObject해 shape 검증을
  무효화하거나 비결정적인 네이티브 실패를 만들 수 있다. 제품 helper의 임시 region 누수와 구분한다.
- 원인: SetWindowRgn 성공 후에는 OS가 region을 소유한다. 하지만 `:30`의 region=None은
  PyGdiHANDLE의 자동 DeleteObject를 해제하지 않는다. pywin32는 성공 후 Detach가 필요하다고
  명시하며 PyGdiHANDLE 파괴 시 DeleteObject 호출도 소스에 명시한다.
- 검증: 같은 Windows 테스트 함수에서 소유권 이전/자동 파괴를 기록하는 모델을 실행했다.
  이전한 핸들 1개가 자동 삭제되는 경로를 확인했다. 실제 Windows에서 shape가 어떻게
  손상되는지까지 실행 확인한 것은 아니며, 소유권 계약 위반 자체를 확정한 것이다.
- 수정 방향: 성공 후 region.Detach()로 Python 소유권을 해제하고 실패 시에만 직접 정리한다.
  테스트 종료의 SetWindowRgn(hwnd,None,False)와 창 정리는 계속 수행한다.

두 근거는 upstream [win32gui.i](https://github.com/mhammond/pywin32/blob/main/win32/src/win32gui.i)의
int_regiontype 예외 변환, PyGdiHANDLE.Close 및 SetWindowRgn 소유권 문서와 대조했다.
독립 재현은 **2 failed / 1.30초**이며 실제 Windows 검사의 통과/실패 기록과 구분한다.

```bash
env PYTHONPATH=src:.:tests QT_QPA_PLATFORM=offscreen python -m pytest scripts/qa_dialogue_windows_contract_20261020.py -q --tb=short --show-capture=no
```

### 2. Confirmed Bug / P2: 잡담 가림 판정의 region API 오호출

- 발생 조건: 전체 경계가 얼굴/말풍선과 겹치는 창을 region으로 재확인한다.
- 사용자 영향: 클릭은 전달됐지만 표시를 계속 거부할 수 있다. 자동 잡담도 같은 판정을 쓴다.
- 원인: `system/dialogue_visibility.py:53`의 `win32gui.CreateRectRgn`은 export가 아니다.
  지원되는 생성 함수는 CreateRectRgnIndirect다. AttributeError를 잡고 region 정보를
  모르는 상태로 남겨 전체 사각형 기준 blocked가 유지된다.
- 실제 증거: 로그 시각 2026-10-20 00:38:03~00:38:53의 수동 클릭 보류 **7건** 모두
  유효 대사 52개, CEF-OSC-WIDGET, 전체 화면 경계, region_error=AttributeError다.
  클릭 확률·대사 부재·사용자 조작을 원인으로 볼 근거가 없다.
- 검증: 실제 로그, 현재 소스, upstream pywin32 export를 대조하고 격리 API 계약 재현에서
  같은 AttributeError를 확인했다. Windows 합성을 직접 실행한 테스트로 표현하지 않는다.
- 한계: API 수정 후 실제 CEF 창의 region이 없거나 대상과 겹치면 거부가 계속될 수 있다.
  따라서 이 수정만으로 라이브 해결을 보장하지 않는다. 특정 프로그램의 이름/투명도도 확정하지 않는다.

## 최초 개발 전달 기록

1. 먼저 공통 영역 테스트 3건의 실제 헤일로 연결을 보완해 전체 unit 게이트가 진행되게 한다.
2. 잡담 두 API 오호출과 실제 export를 가리는 fixture를 수정한다. 실제 네이티브 검증을 추가하고
   CEF 대상의 실제 가림 여부가 여전히 불명확하면 추가 판정/최소 진단을 보완한다.
3. 클래스 이름 고정 허용, 전역 flags 무시, 사용자에게 다른 프로그램 종료 요구로 대신하지 않는다.
   실제 가림·잠금·화면 밖 억제, 게임 입력/포커스 비간섭과 자원 정리를 보존한다.
4. 수정·관련 회귀 후 main에 푸시하고 이 통합 보고서 기준으로 후속 독립 QA를 받는다.
   이번에는 알려진 로컬 실패가 있으므로 사용자에게 Windows 수동 실행을 먼저 요청하지 않는다.
5. 수정들을 모아 배포 후보를 정한 뒤 Windows 검증을 한 번 수행한다. 현재는 릴리즈 명령을
   제공하거나 태그/게시하지 않는다. 기존 v0.6.0 산출물로 새 변경을 배포하지 않는다.

QA에서는 제품·기존 테스트를 수정하지 않았다. 통합 문서와 독립 probe만 공유한다.
