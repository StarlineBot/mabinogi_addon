# 헤일로 개발 및 잡담 로그 통합 QA

- 날짜: 2026-10-20 (Asia/Seoul).
- 검증 소스: main `229a7fa69bd69f05b60b4c701bf4f5da6a2765b9`.
  제품 개발은 `8a24ee1adaccae79da7ffa6cf98cb65ab04108fd`이며 이후 QA 자료만 추가됐다.
- 범위: 헤일로 라이브 후속 개발, 자동찾기/자동설정, 베타 접근·수집 분리,
  화면/알림음 변경과 방금 수령한 v0.6.0 잡담 미표시 로그.
- 결론: **헤일로 핵심 변경은 아래 범위에서 통과했지만 전체 QA는 미통과다.**
  공통 테스트 연동 실패 3건과 잡담 API 결함 2건을 개발에서 처리해야 한다.
  이 문서를 이번 전달의 단일 현황으로 사용한다. 이전 상세 문서는 증거/이력으로 연결한다.

## 발견 사항

### 1. Confirmed Bug / P1: 새 영역 항목이 전체 배포 검사를 실패시킴

- 발생 조건: 헤일로 추가 후 기존 `tests/test_region_registration.py`를 전체 수집한다.
- 사용자 영향: 앱 자체 크래시를 재현한 것은 아니다. Windows 검증의 unit 단계가 실패해
  exe 빌드/배포 후보 생성에 도달하지 못한다. 현 소스의 다음 배포를 막는 검사 연동 결함이다.
- 원인: `ui/region_registration.py:17`에 `halo_timer`가 REGIONS로 추가됐다.
  기존 테스트는 REGIONS 전체를 매개변수로 사용하지만 `tests/test_region_registration.py:82`의
  controller는 `halo_timer_tab`을 찾는다. 실제 기능은 `boss_tab.halo_capture`다.
  panels fixture에도 독립 halo_timer_tab은 없다. 성공 해제/취소/쓰기 실패의 3개 사례가
  검증 본문에 들어가기 전에 AttributeError로 실패한다.
- 검증: 공통 경고·보스·영역 해제·선택기 생명주기 묶음 **3 failed, 81 passed / 11.57초**.
  같은 unit 마커로 헤일로 3건만 재실행해 **3 failed, 31 deselected / 0.84초**를 확인했다.
  `.github/workflows/windows.yml:39`가 이 파일을 제외하지 않고 같은 unit 마커로 수집한다.
- 재현:

```bash
env PYTHONPATH=src:.:tests QT_QPA_PLATFORM=offscreen python -m pytest tests/test_region_registration.py -m 'not windows_integration' -k halo_timer -q --tb=short --show-capture=no
```

- 수정 방향: 실제 헤일로 섹션과 clear_btn/_clear 등 실제 조작 경로를 테스트에 연결한다.
  단순 이름 변경만으로 끝내지 말고 기존 영역·세부 옵션 보존과 취소/저장 실패를 확인한다.
  새 항목을 매개변수에서 빼거나 skip/assertion 약화로 통과시키지 않는다.

### 2. Confirmed Bug / P2: 잡담 가림 판정의 region API 오호출

- 발생 조건: 전체 경계가 얼굴/말풍선과 겹치는 창을 region으로 재확인한다.
- 사용자 영향: 클릭은 전달됐지만 표시를 계속 거부할 수 있다. 자동 잡담도 같은 판정을 쓴다.
- 원인: `system/dialogue_visibility.py:53`의 `win32gui.CreateRectRgn`은 export가 아니다.
  지원되는 생성 함수는 CreateRectRgnIndirect다. AttributeError를 잡고 region 정보를
  모르는 상태로 남겨 전체 사각형 기준 blocked가 유지된다.
- 실제 증거: 로그 시각 2026-10-20 00:38:03~00:38:53의 수동 클릭 보류 **7건** 모두
  유효 대사 52개, CEF-OSC-WIDGET, 전체 화면 경계, region_error=AttributeError다.
  클릭 확률·대사 부재·사용자 조작을 원인으로 볼 근거가 없다.
- 검증: 실제 로그, 현재 소스, upstream pywin32 export를 대조하고 격리 API 계약 재현에서
  같은 AttributeError를 확인했다. Windows 합성을 직접 실행한 테스트로 표현하지 않는다.
- 한계: API 수정 후 실제 CEF 창의 region이 없거나 대상과 겹치면 거부가 계속될 수 있다.
  따라서 이 수정만으로 라이브 해결을 보장하지 않는다. 특정 프로그램의 이름/투명도도 확정하지 않는다.

### 3. Confirmed Bug / P3: 잡담 차단 프로세스 진단 API 오호출

- 발생 조건: 수동 클릭 거부 후 차단 창의 실행 파일 이름을 진단한다.
- 사용자 영향: 필요한 소유 프로세스 정보를 남기지 못한다. 표시를 막는 직접 원인과는 별도다.
- 원인: `system/dialogue_visibility.py:84`의 win32process.QueryFullProcessImageName은
  해당 모듈 export가 아니다. 실제 로그 identity_error=AttributeError와 일치한다.
- 검증: 같은 제품 함수를 export 계약 모델로 실행해 재현했다. 열린 프로세스 핸들은 finally로
  닫혔으며 이 경로의 핸들 누수를 확인했다고 주장하지 않는다.
- 수정 방향: 실제 지원 API/기존 QueryFullProcessImageNameW 패턴을 사용하고 서명·핸들 정리,
  PID 재확인과 전체 경로 비공개를 보존한다. 진단 실패는 화면 판정과 분리한다.

잡담 두 사례 재현 결과: **2 failed / 0.05초**. 앞선 보고 이후 최신 개발에서도 그대로다.
기존 테스트가 없는 함수를 가짜 모듈에 추가해 통과한 빈틈은
[상세 로그 QA](잡담_네이티브API_오호출_로그QA_20261020.md)에 기록했다. 이전 독립 QA도
실제 export와 모델의 차이를 놓쳤으며, 기존 통과를 해결 증거로 재사용하지 않는다.

```bash
env PYTHONPATH=src:.:tests QT_QPA_PLATFORM=offscreen python -m pytest scripts/qa_dialogue_native_api_contract_20261020.py -q --tb=short --show-capture=no
```

## 개발 전달 및 다음 단계

1. 먼저 공통 영역 테스트 3건의 실제 헤일로 연결을 보완해 전체 unit 게이트가 진행되게 한다.
2. 잡담 두 API 오호출과 실제 export를 가리는 fixture를 수정한다. 실제 네이티브 검증을 추가하고
   CEF 대상의 실제 가림 여부가 여전히 불명확하면 추가 판정/최소 진단을 보완한다.
3. 클래스 이름 고정 허용, 전역 flags 무시, 사용자에게 다른 프로그램 종료 요구로 대신하지 않는다.
   실제 가림·잠금·화면 밖 억제, 게임 입력/포커스 비간섭과 자원 정리를 보존한다.
4. 수정·관련 회귀 후 main에 푸시하고 이 통합 보고서 기준으로 후속 독립 QA를 받는다.
   이번에는 알려진 로컬 실패가 있으므로 사용자에게 Windows 수동 실행을 먼저 요청하지 않는다.
5. 수정들을 모아 배포 후보를 정한 뒤 Windows 검증을 한 번 수행한다. 현재는 릴리즈 명령을
   제공하거나 태그/게시하지 않는다. 기존 v0.6.0 산출물로 새 변경을 배포하지 않는다.

QA에서는 제품·기존 테스트를 수정하지 않았다. 통합 문서와 독립 probe만 공유한다.
