### Confirmed Bug / P1: 알림음 테스트의 Windows 경로 문자열 비교

- 조건: Windows에서 `tests/test_halo_live.py::test_dedicated_notifier_does_not_interrupt_other_sound` 실행.
- 사용자 영향: 테스트의 잘못된 실패로 전체 검증이 중단돼 배포할 exe 후보가 만들어지지 않는다.
  실제 앱 재생 실패나 알림음 파일 누락을 확인한 것은 아니다.
- 원인/위치: `tests/test_halo_live.py:180`은 QUrl.toLocalFile 결과와 str(Path)를 그대로 비교한다.
  Qt가 반환한 `D:/a/.../sounds/헤일로 알림.mp3`와 Windows Path의
  `D:\a\...\sounds\헤일로 알림.mp3`는 같은 경로지만 문자열은 다르다.
- 검증: 실제 Windows 로그의 유일한 FAILED와 AssertionError를 확인했고 현재 소스와 대조했다.
  PureWindowsPath 모델에서도 raw 문자열 비교 False, 경로 객체 비교 True임을 실행 확인했다.
- Linux에서 놓친 이유: 동일 테스트가 POSIX 경로에서는 양쪽 모두 `/`를 반환해 통과했다.
  이전 Linux 통과로 플랫폼별 경로 표현 동등성까지 확인한 것은 아니었다.
- 수정 방향: 이미 import한 pathlib.Path로 실제 결과를 감싸 경로로 비교한다.
  예: `assert Path(s._notifier._player.source().toLocalFile()) == source`.
  basename만 비교하거나 문자열 포함·exists만 검사하는 방식으로 약화하지 않는다.
  다른 파일/디렉터리가 전달되면 실패하는 대조군과 기존 다른 재생기 독립성·OFF 시 영향 검증을 유지한다.

간단한 플랫폼 독립 재현:

```python
from pathlib import PureWindowsPath
expected = PureWindowsPath('D:/a/app/assets/sounds/halo.mp3')
actual = expected.as_posix()
assert actual != str(expected)
assert PureWindowsPath(actual) == expected
```

임의 수정하지 않았다. 실패한 같은 소스를 지금 재실행하지 않는다.
태그가 아직 생성되지 않았으므로 수정 후에도 미사용 버전 0.7.0으로 새 전체 검증이 가능하다.

### Highly Likely Bug / P1: 새 Windows no-region 검사가 정상 API 예외를 실패로 처리

- 조건: `tests/windows/test_dialogue_visibility.py:10`의 shape=None 사례로 명시적 region이
  없는 실제 HWND를 검사한다.
- 영향: unit 통과 뒤 Windows 네이티브 단계가 실패해 exe 후보 생성을 막을 가능성이 매우 높다.

  제품 helper는 예외를 잡고 None과 region_error를 남긴다. 테스트 `:38`은 None을 기대하면서도

- 검증: 실제로 추가된 Windows 테스트 함수를 그대로 호출하되 위 pywin32 반환 계약을

- 수정 방향: no-region의 정상적인 정보 부재와 예상하지 못한 API 실패를 구분한다.

  실패 사례를 skip하거나 모든 오류를 정상으로 취급하지 않는다.

### Confirmed Bug / P2: 새 Windows shape fixture의 GDI 소유권 이전 누락

- 조건: 같은 테스트 `:27`에서 PyGdiHANDLE region을 만들고 `:29` SetWindowRgn에 전달한다.
- 영향: 테스트 자체가 HWND가 소유하는 region을 조기에 DeleteObject해 shape 검증을
  무효화하거나 비결정적인 네이티브 실패를 만들 수 있다. 제품 helper의 임시 region 누수와 구분한다.
- 원인: SetWindowRgn 성공 후에는 OS가 region을 소유한다. 하지만 `:30`의 region=None은
  PyGdiHANDLE의 자동 DeleteObject를 해제하지 않는다. pywin32는 성공 후 Detach가 필요하다고
  명시하며 PyGdiHANDLE 파괴 시 DeleteObject 호출도 소스에 명시한다.
- 검증: 같은 Windows 테스트 함수에서 소유권 이전/자동 파괴를 기록하는 모델을 실행했다.
  이전한 핸들 1개가 자동 삭제되는 경로를 확인했다. 실제 Windows에서 shape가 어떻게
  손상되는지까지 실행 확인한 것은 아니며, 소유권 계약 위반 자체를 확정한 것이다.
- 수정 방향: 성공 후 region.Detach()로 Python 소유권을 해제하고 실패 시에만 직접 정리한다.
  테스트 종료의 SetWindowRgn(hwnd,None,False)와 창 정리는 계속 수행한다.

두 근거는 upstream [win32gui.i](https://github.com/mhammond/pywin32/blob/main/win32/src/win32gui.i)의
int_regiontype 예외 변환, PyGdiHANDLE.Close 및 SetWindowRgn 소유권 문서와 대조했다.
독립 재현은 **2 failed / 1.30초**이며 실제 Windows 검사의 통과/실패 기록과 구분한다.
