## 소스 확인

커밋 이력/메시지 대신 정확한 소스 트리를 비교했다. 앞선 QA 공유본 `28173a6` 대비 변경은 테스트/테스트 지원 모듈/개발 문서의 8개 파일뿐이다. 제품 코드·공개 노트·권한·설정·워크플로는 동일하다.

- 새 `assert_control_reachable()`는 모든 조상 `QScrollArea`를 안쪽부터 이동하고, 모든 뷰포트에서 가로 스크롤 없음 및 버튼 전체 영역 포함을 검사한다.
- 기존 실패한 두 파일과 내비게이션 폭 검사가 이를 사용한다. 글꼴·Windows 버튼 최소 폭·줄 복원·설정 불변·타이머 개수 등의 기존 assertion을 유지했다. skip이나 단순 assertion 삭제는 없다.
- 새 대조 검사는 안쪽과 바깥쪽 모두 스크롤이 필요한 실제 Qt 계층을 사용한다. 바깥 스크롤 이동을 막으면 반드시 실패하므로 내부만 보는 거짓 통과를 막는다.
- 도르카 테스트의 워커 대기는 `QTest.qWait()` 반복에서 실제 `QEventLoop`로 바뀌었다. 5초 제한 및 워커 종료 assertion은 유지한다. 새 검사도 qWait 호출을 금지한 채 실제 워커 완료와 판독값 15를 확인한다. 제품 워커 코드는 바뀌지 않았다.

## 실행

Linux Qt offscreen에서 다음 명령을 실행했다. 게임·장치·네트워크는 기존 경계로 격리했다.

```bash
PYTHONPATH=src:. QT_QPA_PLATFORM=offscreen python -m pytest \
  tests/test_scroll_visibility.py tests/test_interaction_polish.py \
  tests/test_wrapping_controls.py tests/test_navigation_all_widths.py \
  tests/test_dorcha_tracking.py tests/test_dorcha_roi_context.py \
  tests/test_dorcha_startup_recovery.py scripts/qa_boss_nested_scroll_20261019.py \
  docs/qa/assets/public_halo_20261019/probe.py \
  -q --tb=short --show-capture=no
```

결과: **83 passed / 36.75초**, 종료 코드 0. 재현 스크립트는 기존 검사 3건을 다시 호출하므로 모두 별개의 고유 시나리오라고 합산하지 않는다.

- 이전 밝음/어두움 20px 보스 화면 검사 2건과 Windows 너비 모사 검사 1건 모두 통과했다.
- 도르카 추적·게임 문맥·시작 복구 및 새 대기 헬퍼 검사 모두 통과했다.
- 기존 독립 probe 9개도 원본 그대로 통과했다. 50회 계정 전환의 도르카/알림 상태 보존, 모든 조상 스크롤 접근, 실제 파일 쓰기 중 로그아웃/영역 변경/종료 취소, 음수 좌표·배율 변환 대조를 포함한다.
