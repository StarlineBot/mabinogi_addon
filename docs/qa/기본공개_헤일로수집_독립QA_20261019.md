## Confirmed Bug

- 분류: 테스트/배포 게이트 결함. 실제 보스 설정 버튼이 접근 불가능하다는 결론은 아니다.
- 발생 조건: 글꼴 20px에서 보스 설정을 검사한다. 보스 내용은 새 `QScrollArea` 안에 있지만 기존 두 검사는 바깥 `_combat_pages['boss']`만 `ensureWidgetVisible()`로 이동시킨다.
- 사용자 영향: 기능 조작 실패는 대조 검사에서 재현하지 못했다. 하지만 해당 검사가 태그의 전체 일반 회귀에 포함되므로 현재 소스는 릴리즈 테스트에서 실패할 것으로 예상된다. 실제 Windows CI를 실행해 확인한 결과는 아니다.
- 기술적 원인: 보스 탭을 `[체력별패턴] [1분 헤일로]`로 나누며 각 내용에 내부 스크롤이 추가됐다. `tests/test_navigation_all_widths.py`는 소유 스크롤을 찾도록 갱신됐지만 다른 두 검사는 단일 스크롤 구조를 가정한 채 남았다. 바깥 영역만 이동시켜서는 내부 뷰포트의 숨은 버튼을 드러낼 수 없다.
- 관련 위치:
  - `src/mabinogi_addon/ui/boss_tab.py:237`: 3차 탭 및 각 내부 `QScrollArea` 생성.
  - `tests/test_interaction_polish.py:216`: 바깥 스크롤만 이동. 밝음/어두움의 20px 조건에서 2개 실패.
  - `tests/test_wrapping_controls.py:48`: 같은 단일 스크롤 가정. 보스 조건에서 1개 실패.
  - `.github/workflows/release.yml:42`: 전체 일반 회귀 게이트.
- 실제 관측: 첫 검사는 `진단 · 보스 HP바 수집`의 사각형 `(12,724,219,36)`을 바깥 뷰포트 `(0,0,790,681)`와 비교해 실패했다. 너비 모사 검사도 `(24,675,142,39)`이 같은 뷰포트를 벗어난다고 실패했다.

## 제약과 후속 작업

- 이번 헤일로 개발은 **영역 지정·원본 미리보기·수집 단계**다. 시간 판독·동기화·카운트다운·63초 주기 사전 알림은 미구현이며, 이를 기능 누락 버그나 완료된 알림으로 오해하지 않는다. 승인 범위도 현재 수집 단계다.
- 투아림 %는 제작자 전용이며 정책 최초 적용 시 한 번 OFF로 저장된다. 이후 제작자가 켠 설정은 보존된다. 로컬 Discord ID 기준 공개 대상 구분이며 설정 변조를 막는 서버 인증 보장은 아니다.
- Windows 네이티브/exe·실제 게임 포커스/프로세스/DPI/다중모니터·캡처 비용·장시간 CPU/메모리/핸들/GDI·실제 숫자 변화 수집률은 미검증이다. 최대 100만 픽셀/2Hz 미리보기와 1Hz 저장의 실게임 부하는 실제 환경에서 확인해야 한다. Linux 통과로 대신하지 않는다.
- 파일 호출 자체가 이미 진행 중인 순간의 원자적 취소/강제 중단은 보장하지 않는다. 종료 시 새 완료 자료 확정을 막는 취소 확인 경로와 워커 종료를 제어된 실행 순서에서 검증했다.
- 새 기능이지만 확인 시 `v0.5.0`은 아직 미공개다. 공개 노트도 v0.5.0이므로 버전 정책에 따라 같은 배포 예정 버전으로 묶을 수 있다. 실패 때문에 태그 명령은 이번에 제공하지 않는다.
- 개발 세션은 위 두 기존 검사와 전체 관련 묶음을 수정 후 재실행해야 한다. 로컬에서 재현되므로 Windows 유료 재실행보다 소스의 테스트 수정이 먼저다. 일반 푸시의 Windows 실행은 추가 요청하지 않는다.
- QA는 제품·기존 테스트를 수정하지 않았다. 이 보고서와 독립 검증·실패 재현만 main에 공유한다.
