## 개발 세션 후속 조사

한 종류의 저장 로직만 임의 수정하거나 종료 때 locked=True를 강제하지 않는다.
실제 저장 상태와 런타임 상태를 다음 순서로 비교해 실패 구간을 특정해야 한다.

1. 고정 직후: 저장된 좌표/locked와 실행 중 오버레이의 좌표/locked/버튼 상태를 비교한다.
2. 종료 직후: 같은 설정 파일의 해당 값이 보존됐는지 확인한다.
3. 재실행 직후: 복원 입력과 최종 창 상태를 비교한다. 잠금 값이 참이면 Windows의
   HWND/창 좌표/DPI/WS_EX_TRANSPARENT·WS_EX_LAYERED·WS_EX_NOACTIVATE도 비교한다.
4. 파일 값이 달라졌다면 저장 실패/백업 대체/잘못된 경로/덮어쓰기 순서를 추적한다.
   파일 값이 같다면 Qt 복원·표시·HWND 생명주기와 화면 좌표 변환을 추적한다.

현재 최소 추가 확인은 재실행 후 **버프 탭의 '위치 잠금됨' 표시가 유지되는지**다.
종류가 전체라는 답만으로 저장 손실과 창 스타일 손실을 구분할 수는 없다.

기존 '진단 스냅샷'은 버프/디버프/투아림의 판독 영역 PNG를 저장한다(`ui/diag_capture.py`).
문의용 `diagnostics.header_text()`도 오버레이별 잠금/실제 위치/네이티브 스타일을 담지 않는다.
따라서 이 제보에 자동찾기 ZIP이나 판독 PNG를 다시 요구해도 필요한 증거를 얻지 못한다.
필요 시 오버레이 상태만 허용 목록으로 수집하는 진단을 준비한다. 전체 설정/백업에는
계정·경로·사용자 자산 및 민감한 값이 있을 수 있으므로 원본을 공개 Git에 올리게 하지 않는다.
