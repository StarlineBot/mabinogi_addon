## 결론

**이전 Confirmed Bug 2건은 검증한 경로에서 해결됐다. 추가 배포 차단 결함은 발견하지 못했다.**
최신 제품의 Windows/실게임 통과나 전체 헤일로 기능 완료를 뜻하지 않는다.

| 이전 문제 | 독립 확인 | 판정 |
| --- | --- | --- |
| 설정창을 숨기면 게임 위 카운트다운 없음 | 원래 882/882/881 관측으로 동기화한 뒤 창을 숨겨도 별도 카운트다운이 보임 | 해결 |
| 잠금 해제한 편집 샘플이 다음 틱에 숨겨짐 | 원래 재현 통과. 두 창 모두 편집 상태에서 100회 대기 틱 후 가시성과 잠금 해제 유지 | 해결 |

관련 구현: `src/mabinogi_addon/ui/halo_capture_section.py:151`은 실시간 창만 숨기고,
`:161`은 권한 해제/영역 해제/종료 때 편집 창까지 정리한다. `:241`은 별도 카운트다운을 갱신한다.
공유 `PatternWarningOverlay`의 기본 샘플은 유지하고, 헤일로 인스턴스만 별도 샘플을 사용한다.
기존 보스 경고 호출자와 관련 회귀도 확인했다.

## 추가 독립 검사

`docs/qa/assets/halo_presentation_fix_20261019/probe.py`:

- 실제 `_monitor()`로 동기화해 표시한 카운트다운을 더 갱신하지 않고 Qt 이벤트 루프를 돌렸다.
  실제 표시 타이머가 만료되어 창이 숨겨지고 타이머가 비활성/문구가 비워지는지 확인했다.
  단순 timeout 콜백 직접 호출로 대신하지 않았다.
- 두 편집 창을 잠금 해제한 뒤 100회 정상 대기 틱을 실행했다.
  두 창의 가시성/잠금 상태가 유지되고 최상위 창 집합·소유 타이머 객체가 늘지 않았다.
  shutdown 후 관련 타이머와 창이 모두 정리됐다. 장시간 Windows 자원 계측의 대체는 아니다.
- 경고/카운트다운을 각각 음수 모니터 좌표에 저장하고 새 section을 생성했다.
  독립 위치가 복원되고 자동 배치가 저장 위치를 덮어쓰지 않으며 다른 설정이 바뀌지 않았다.
  실제 혼합 DPI나 모니터 제거 복원을 검증한 것은 아니다.

## 남은 범위와 배포 준비

- 자동찾기 개선 요청은 아직 미완료다. 소리 알림도 비활성/미연결이다.
  이번 수정으로 두 기능까지 완료됐다고 안내하지 않는다.
- 기존 13~14분대 원본의 결과를 한 자리 분/15:00/00:00/분 경계/다른 DPI로 일반화하지 않는다.
- 실제 Windows/게임 캡처·클릭 통과·포커스·혼합 DPI·절전/잠금·장시간 사용은 미검증이다.
  이 QA에서는 전체 일반 회귀나 최신 exe 빌드를 실행하지 않았다.
- 새 헤일로 시간 판독/경고/카운트다운은 기존 마지막 공개 v0.5.1 이후의 기능 추가다.
  사용자 버전 정책에 맞춰 아직 사용하지 않은 다음 기능 버전 **0.6.0**을 후보로 준비했다.
  원격 v0.5.2/v0.6.0 태그가 없음을 확인하고 미공개 노트 헤더만 v0.5.2→v0.6.0으로 바꿨다.
  v0.5.1 이하 공개 노트/개발 버전 파일/기존 테스트는 변경하지 않았다.
- 앞선 Windows 성공 후보 run 39245884765는 이전 SHA 218134b 기준이므로 재사용할 수 없다.
  **배포할 때** 이번 QA 자료까지 반영된 main에서 `Windows validation`, version `0.6.0`을 실행한다.
  검증 성공 후보의 정확한 SHA/run ID/attempt/버전/만료를 확인한 뒤 사용자 태그·수동 승격 명령을 제공한다.
  이전 0.5.2 명령이나 origin/main에 곧바로 태그만 붙이는 구 절차로 대체하지 않는다.
- Windows 검증 성공까지 공개 배포는 하지 않는다. 이번 QA 자료 푸시도 일반 main 푸시여서
  Windows 실행·태그·Release 게시를 자동으로 시작하지 않는다.
