## 완전 첫 실행은 준비 화면용 안내로 분기함

1. 진입점에서 MainWindow 생성과 start()가 끝난 뒤 창을 표시한다.
2. 첫 showEvent가 업데이트 노트를 먼저 처리한다. 노트가 표시된다면 닫은 뒤 안내를 시작한다.
3. `general.tourShown`이 없거나 false이고 현재 스택이 준비 화면이면 준비 화면용 안내를 만든다.
4. 화면을 어둡게 하고 현재 대상만 밝게 뚫어 노란 점선과 설명을 표시한다.
5. 이전/다음으로 안내하며 완료 또는 건너뛰기에 tourShown을 저장한다.
   안내를 끝냈다고 영역을 저장하거나 자동설정을 실행하지 않는다. 준비 화면도 유지한다.

Discord 미로그인 사용자의 5단계:

`사용할 기능 선택 → 설정 필요 → 직접 지정 → 개별 설정 → 사용 안내 종료`

로그인 사용자의 6단계:

`사용할 기능 선택 → 설정 필요 → 자동설정 → 찾은 영역 확인 → 개별 설정 → 사용 안내 종료`

- 자동설정이 아닌 직접 지정도 가능한 기능을 일반 사용자에게 자동설정 필수로 안내하지 않는다.
- 이미 tourShown=true이면 베타의 준비 화면은 계속 기본 표시하지만 안내는 자동 재생하지 않는다.
  준비 화면 표시 정책(skipSetup)과 안내 표시 기록(tourShown)은 별개다.
- skipSetup=true라 처음부터 트래커 탭이 표시되면 기존 버프용 4단계 안내를 사용한다.
- 트레이로 시작했다면 실제 창을 처음 표시할 때까지 안내를 실행하지 않는 소스 경로다.
  실제 Windows 트레이에서 직접 확인한 결과로 표시하지 않는다.

## Confirmed Bug: TOUR-QA-01 / P2

### 설정의 다시 보기에서 새 첫 실행 안내를 재생할 수 없음

- 조건: tourShown=true인 기존 사용자가 준비 화면을 확인한 뒤 설정으로 이동해
  '사용법 투어 다시 보기'를 누른다. 툴팁은 처음 실행 때 나온 단계별 안내를 다시 본다고 설명한다.
- 영향: 준비 화면용 첫 안내가 아니라 버프 영역 지정 안내로 전환된다.
  기존 사용자가 새 준비/자동설정 안내를 다시 보거나 베타 테스트하려는 동선에 맞지 않는다.
  최초 설치자의 자동 안내가 막히거나 앱이 크래시하는 문제는 아니다.
- 원인: `_run_tour()`는 현재 표시 스택이 준비 화면인지로 안내를 선택한다.
  다시 보기 버튼은 일반 탭의 설정 화면에 있으므로 호출 시 항상 버프용 분기로 들어간다.
  첫 버프 단계의 before 콜백은 실제로 트래커 > 버프 탭으로 이동시킨다.
- 재현: 새 준비 화면을 표시하는 실제 MainWindow에서 기존 안내 기록을 true로 둔다.
  설정 탭으로 이동해 실제 `settings_tab.replay_tour` 연결을 실행하면 첫 대상은
  setup_page.selection이 아니라 buff_tab.region_btn이며 제목은 '① 영역 지정'이다.
- 결과: '새 첫 실행 안내를 다시 볼 수 있음'이라는 독립 시험이 실패했다.
  설정 버튼을 거치지 않고 준비 화면 위에서 `_run_tour()`를 직접 호출하는 대조는 통과한다.
- 위치: `src/mabinogi_addon/ui/main_window.py:267`, `:733`, `:776`,
  `src/mabinogi_addon/ui/settings_tab.py:840`.
