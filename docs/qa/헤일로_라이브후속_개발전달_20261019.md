## 1. 실제 헤일로 시각과 앱 오동작을 구분

사용자 후속 설명을 우선한다. 앱의 시간 판독·알림은 정상 동작했다고 확인했다.
`01:15`, `00:13`은 앱의 잘못된 판독값이 아니라 **게임 내부 타이머에서 관측한 마지막 두 번의
실제 헤일로 등장 시각**이다. 각 관측에 약 ±1초 불확실성이 있으며 중반의 정확한 시점은 기억하지 못했다.
이를 사용자 조작 오류나 확정된 앱 시간 드리프트로 바꾸어 기록하지 않는다.

현재 `tracker/halo.py:6`의 일정은 첫 14:53, 이후 고정 63초다. 마지막 두 번은 01:14/00:11이다.
게임 타이머와 내부 시각을 다시 맞추는 기능은 있지만 실제 헤일로 등장 주기를 학습하는 기능은 없다.
두 관측만으로 62초 주기라고 결론 내리거나 모든 회차에 임의 오프셋을 더하지 않는다.

## 2. 시간 보정 검토용 추가 자료

- ZIP CRC와 PNG/JSON **589쌍** 정상, 시퀀스 1~589와 shape 일치.

  이는 재현 일관성이며 584개 전체를 독립 정답으로 검증했다는 뜻은 아니다.

- 정수 판독값과 최초 관측 이후 UTC 경과의 차이는 약 **-0.778~+0.663초**다.

- 타이머 자릿수는 확인한 1분대/0분대 원본에서 01:xx/00:xx처럼 0으로 채워진다.
  다른 폰트·해상도·사용자 화면까지 보장하는 것은 아니다.
- 저장 간격에는 최대 약 22초의 틈이 있다. 변경/미검출/보스 게이트 중 무엇 때문에 생긴 틈인지
  ZIP만으로 확정하지 않는다. 연속 영상으로 취급하지 않는다.
- 원본은 119×42 타이머 부분뿐이다. 실제 헤일로 등장 장면/게임 이벤트 정답은 포함하지 않으므로
  이 ZIP만으로 발생 주기나 실제 패턴 대비 지연을 보정할 수 없다.

### 개발 지시

1. 원본 시간 판독과 캡처 시각을 재실행해 지속적인 오독/누적 오차가 있으면 해당 원인을 보정한다.

3. 실제 패턴 시각과 앱 타이머의 일치 여부는 별도 문제로 남긴다. 63초 일정 변경에는

## 3. 보스바가 사라져도 정상 타이머가 흐르면 표시·알림 유지

### Confirmed Bug / P2: 정상 패턴의 보스바 미표시로 안내 중단

- 발생 조건: 회한 보스가 이미 확인되고 헤일로 시계가 동기화됐다. 같은 게임 창에서 타이머는
  정상 감소하지만 보스 패턴 때문에 보스 이름/HP 바가 잠시 보이지 않는다.
- 사용자 영향: 카운트다운이 사라지고 해당 구간에 도달한 5초 전 경고도 보류/소비된다.
- 기술적 원인: `boss_tab.py:259`, `:463`은 매 틱 context를 None으로 지우고 실제 이름 식별 때만 채운다.
  `halo_capture_section.py:157`은 매번 최근 회한 식별을 요구하고 `:226`은 이를 시계 eligible에 그대로 쓴다.
  None은 게임 타이머가 정상이어도 표시 숨김/알림 보류로 연결된다.
- 검증: 같은 HWND/PID, 제작자 권한, 등록 영역, 정상 감소 타이머를 유지하고 **보스 식별만 None**으로
  바꾸는 실제 Qt 경로를 구성했다. 카운트다운 유지 및 13:55 경고 기대가 각각 실패했다.
  **2 failed / 1.30초**, 하나의 원인에 대한 두 출력 검증이다.
- 재현: `scripts/qa_halo_boss_visibility_20261019.py`.

기존 기획/테스트는 매번 보스 식별이 없으면 숨기는 쪽이었다. 이번 라이브 피드백은
정상 패턴 중 보스바 미표시를 반영한 **후속 요구 변경**이며, 수정 전에 만든 기능이 갑자기 회귀했다고
주장하는 것은 아니다. 최신 요구 기준으로 현재 중단 동작을 개선한다.

### 개발 지시: 최초 확인과 이후 유지 조건을 분리

- 시작: 회한 보스 확인과 유효한 시간 관측으로 현재 전투를 확정한다.
  타이머 숫자만 보고 다른 던전에서 감시를 시작하지 않는다.

  일시 미식별이어도 카운트다운과 예정 경고를 계속 제공한다.
- 중지/재확인: 다른 보스가 명확히 확인됨, 게임 창/프로세스 변경·종료, 타이머 종료,

  단일 오독만으로 새 전투를 확정하거나 이미 알린 회차를 되감지 않는다.

## 4. UI 그룹화 및 버튼 통일

기준은 사용자가 올린 v0.6.0의 `체력별패턴` 화면이다. 현재 `1분 헤일로` 화면은
잠금 버튼/영역 지정/미리보기/수집이 평면적으로 나열돼 있으며 사용자가 **버튼 통일도 함께 요청**했다.
테두리만 덧붙이는 변경으로 완료 처리하지 않는다. 분류: Improvement / P3.

### 배치 순서

| 구간 | 내용/기존 화면 대응 |
| --- | --- |
| 제목·설명 | 현재 제목·목적 유지, 기존 보스 패턴 화면과 같은 간격/타이포그래피 |
| 판독 영역 · 전투 제한 시간 | 등록 상태와 영역 지정 명령을 같은 줄/순서 규칙으로 배치 |
| 판독 미리보기 | 기존 `판독 미리보기` QGroupBox처럼 원본과 실제 판독 시간/동기화 상태를 묶음 |
| 다음 헤일로 표시 | 독립 카운트다운의 위치 잠금 등 표시 조작을 별도 그룹으로 분리 |
| 헤일로 경고 | 경고 위치 잠금과 소리 옵션을 기존 `패턴 경고` 그룹과 같은 방식으로 배치 |
| 시간 자료 수집 | 기존 `진단 · 보스 HP바 수집`과 같은 disclosure 규칙, 저장 장수/경로/스냅샷/폴더를 내부 배치 |

- 그룹은 기존 QGroupBox/settings_layout 계열 헬퍼를 재사용한다. 새로운 카드형 디자인이나
  상위 탭/설정 대상 선택 UI로 바꾸지 않는다. 3차 탭 `[체력별패턴] [1분 헤일로]`는 유지한다.
- 기존 체력별패턴의 판독 영역 줄은 별도 카드가 아니라 영역 명령 구간이다. 헤일로도 같은 구조로 맞춘다.
- 별도 경고 창과 카운트다운 창의 위치/잠금/클릭 통과 및 설정값은 UI 이동 때문에 바뀌지 않는다.

### 버튼 규칙

- 영역 명령의 순서·높이·패딩·간격·줄바꿈은 기존 자동찾기/직접 지정/지정 영역 보기 줄을 따른다.
  자동찾기 미구현 상태에 가짜 동작 버튼을 추가하지 않는다. 별도 자동찾기 QA 항목은 계속 미완료다.
- **지정 해제는 기존처럼 우측의 위험 명령 스타일**로 분리한다. 현재 헤일로의 좌측 일반 버튼과 구분한다.
- 잠금은 기존 LOCK_STYLE과 체크 상태·문구 규칙을 사용한다. 경고/카운트다운 버튼끼리도
  동일한 높이/패딩과 잠금됨·잠금 해제 상태 표현을 사용한다.
- 스냅샷 저장/폴더 열기와 disclosure의 normal/hover/checked/disabled 상태도 공통 헬퍼를 따른다.
  펼친 상태와 접힌 상태의 색 차이를 없애는 식으로 기존 상태 표현을 망가뜨리지 않는다.
- 소리 옵션은 아래 승인된 MP3 연결과 함께 활성화한다. 미연결 상태를 작동하는 설정처럼 보이지 않는다.
- 긴 저장 경로·큰 글꼴에서 명령이 밀리거나 잘리지 않도록 기존 경로 표시/줄바꿈/스크롤 규칙을 적용한다.
  사용자 계정명이나 실제 전체 경로를 공개 QA 자료에 복제하지 않는다.

### 화면 검증

실제 MainWindow에서 게임 없이 샘플 원본/판독 상태를 주입해 렌더하고 사용자에게 확인받는다.
기존 790px 창과 작은 작업 영역, 12/20px 글꼴, 수집 펼침/접힘 모두 확인한다.
가로 넘침·버튼 잘림·텍스트 겹침 없이 각 조작에 접근 가능해야 한다. 안쪽/바깥쪽 스크롤을 모두 확인한다.
UI 정리를 이유로 반복 타이머/이벤트를 새로 만들거나 기존 설정을 초기화하지 않는다.

## 5. 후속 승인: 베타 공개와 헤일로 표시 조정

### 베타 공개

- 사용자가 현재 수준의 헤일로 기능을 베타로 공개해도 된다고 명시적으로 승인했다.
  기존의 제작자만 허용하는 알파 조건을 헤일로 판독·표시·경고에는 더 이상 고정 적용하지 않는다.
- 기존 Discord 베타 접근 정책에 연결한다. 비로그인 일반 공개까지 확대하는 요청으로 해석하지 않는다.
  제작자 ID를 단순히 모든 사용자에게 참으로 바꾸거나 다른 제작자 전용 기능까지 풀지 않는다.
- 탭 노출뿐 아니라 직접 지정/미리보기/실제 판독/시계/카운트다운/경고/위치 조작도 같은 베타 조건으로
  동작해야 한다. UI만 열고 실행은 여전히 제작자 검사에서 막히는 상태를 만들지 않는다.
- 수집 모드 공개 범위는 원래 명세에서도 별도 승인 대상이다. 이번 베타 공개는 기능의
  판독·표시·경고에 적용하고 원본 자동 수집/스냅샷은 제작자 전용을 유지한다.
  저장 경로 직접 호출에도 같은 제한을 둔다. 별도 수집 공개 승인을 임의로 추정하지 않는다.
- 기존 제작자의 영역·위치·잠금·자료를 초기화하지 않고 로그인/로그아웃 전환 때 창·시계·워커가
  올바르게 정리되는지 비로그인/일반 베타/제작자 세 역할로 확인한다.
- 베타 공개 승인은 모든 환경에서 안정성이 확인됐다는 뜻이 아니다. 위 P2 수정과 관련 QA를
  수행한 뒤 사용자가 다음 배포를 승인한다. 이 문서 작성 자체로 공개 배포를 실행하지 않는다.

### 폰트와 강조

- 대상은 **헤일로 카운트다운과 헤일로 5초 전 경고 두 표시**다.
- 기존 보스 패턴 경고보다 한 단계 작고 덜 튀게 한다. 약 10~15% 작은 시안부터 비교하되
  정확한 픽셀/비율은 실제 게임 화면 배경을 포함한 렌더로 확인한다. 글자를 작게 한다는 이유로
  흐리게 만들거나 읽기 어려운 대비로 바꾸지 않는다.
- 공유 PatternWarningOverlay의 기본 크기/샘플을 바꿔 기존 보스 경고까지 줄이지 않는다.
  헤일로 인스턴스에만 크기·강조 조정을 적용한다. DPI/화면 크기별 가독성을 확인한다.

### 표시 순서

- 기본 배치와 위치 편집 샘플 모두 **위: 헤일로 카운트다운 / 아래: 헤일로 5초 전 경고**다.
- 기존 보스 패턴 경고/목록보다 아래에 두는 현재 기준점은 유지하고 헤일로 두 창의 상하 순서만 맞춘다.
- 설정 그룹도 `다음 헤일로 표시`를 먼저, `헤일로 경고`를 다음에 두어 같은 순서로 읽히게 한다.
- 이미 직접 이동해 저장한 두 위치를 강제로 교환하거나 설정을 초기화하지 않는다.
  미저장 위치/새 기본 배치에 새 순서를 적용하고 두 창은 계속 독립적으로 움직이고 잠글 수 있게 한다.
- 폰트 변경 후 실제 창 높이에 맞춰 간격을 계산한다. 배치 함수의 상호 호출을 뒤집다가
  재귀가 생기거나 매 틱 누적 이동하지 않게 한다. 반복 틱·숨김/재표시·재실행에서 위치를 확인한다.

## 6. 후속 승인: 업로드한 헤일로 알림음 연결

- 사용자 지정 원본: `tests/data/universfield-new-notification-014-363678.mp3`.
  추가된 소스는 위 기준 SHA이며 크기 34560 bytes, Git blob은
  `753e73486a49e6d5d4b73679a0f58284237581f4`다. 파일 존재/식별자를 확인했으며
  실제 청취·Windows 재생 품질은 아직 검증하지 않았다.
- 이 파일을 **헤일로 5초 전 경고음**으로 사용한다. 카운트다운 숫자 변경이나 500ms 갱신마다
  재생하지 않는다. 유효한 사전 경고 이벤트가 발생하고 소리 옵션이 켜져 있을 때 회차당 한 번만 재생한다.
  복귀·보스바 재등장·동기화 보정 때 지난 회차를 다시 울리지 않는다.
- 개발에서 기존 `paths.resource_dir()/"sounds"` 패키징 규칙에 맞게 제품 리소스에 포함한다.
  실행 중 `tests/data`나 사용자 PC 절대 경로에 의존하지 않는다. 기존 MP3 재생 경로인
  `ui/notifier.py`의 SoundNotifier/QMediaPlayer와 기본 출력 장치 갱신 패턴을 재사용한다.
  MP3를 WAV 전용 QSoundEffect에 그대로 전달하지 않는다.
- 현재 비활성인 `소리 알림` 체크박스와 `알림음 연결 전입니다.` 툴팁을 실제 연결 상태에 맞춘다.
  헤일로 베타 권한과 소리 OFF, 기존 일시정지·포커스 정책을 지킨다. 설정 저장은 기존 설정 API를
  사용하고 다른 기능의 음소거/사용자 선택을 덮어쓰지 않는다. 새 기본값은 기존 알림 설정 정책을 따른다.
- 다른 보스/버프 알림음과 음성 팩 매핑을 교체하거나 공유 플레이어의 사운드 목록을 덮어쓰지 않는다.
  두 알림이 가까이 발생해도 한쪽 재생을 예기치 않게 끊지 않는지 확인한다.
  반복 틱마다 플레이어·오디오 객체·스레드를 새로 만들지 않고 종료/권한 상실 시 재생 자원을 정리한다.
- 파일 누락·디코더/오디오 백엔드 실패·출력 장치 변경은 크래시나 무한 재시도 없이 처리한다.
  소리 실패 때문에 화면 경고와 시계가 중단되지 않아야 한다. 예기치 않은 시스템 beep로 대체하지 않는다.
- 재생 요청 횟수/옵션 OFF/같은 회차 재동기화/새 전투 재사용/종료를 격리 테스트하고,
  실제 Windows exe에서 MP3 포함·재생·음량·장치 변경을 확인한다. mock 재생 성공은 실제 청취 검증이 아니다.

## 7. 완료 후 독립 QA

개발 세션은 위 최소 변경과 관련 회귀, 명세/개발 문서 갱신 후 main에 푸시한다.
이번 QA 세션에서 보스 미표시 중 카운트다운/경고 유지와 재확인 경계, 판독 재실행,
수집 조건 보존 및 화면·버튼 통일, 세 역할의 베타 접근, 두 표시 크기/순서,
지정 MP3 연결과 소리 ON/OFF·회차당 한 번 재생을 검증한다.
창·타이머·워커 정리와 기존 보스 기능 회귀도 포함한다.
Windows 후보 검증은 배포할 변경을 모아 한 번 실행하며 기존 v0.6.0 산출물을 새 코드 검증으로 재사용하지 않는다.
실제 릴리즈는 사용자 승인으로만 진행한다. 이번 요청으로 제품을 임의 수정하거나 배포하지 않았다.
