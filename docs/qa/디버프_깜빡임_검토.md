## DEBUFF-QA-01: Confirmed Bug / P2

**재검출 확정 대기시간까지 연속 미감지 시간으로 계산해 회복 중 아이콘을 잠깐 재표시함.**

- 발생 조건: 이미 적용으로 확정해 숨겨진 아이콘이 두 틱 미검출된 후 다시 정상 매칭됨.
  재표시 대기(0.4초)보다 짧은 약 0.3초의 탐지 공백만 있어도 발생한다.
  포커스 변경, 보스 이탈, 설정 변경, 추적 재시작은 필요 없다.
- 사용자 영향: 보스에 걸린 디버프를 다시 걸어야 하는 것처럼 아이콘이 잠깐 나타났다 사라짐.
  짧은 탐지 누락이 반복되면 오버레이도 반복해서 깜빡일 수 있다.
- 기술적 원인: `_confirm_detect()`는 raw 매칭이 회복돼도 0.3초 동안 `False`를 돌려준다.
  `tick()`은 그 기간을 미감지로 취급하고 기존 `_absent_since`를 계속 사용한다.
  따라서 이미 매칭이 회복된 프레임에서도 0.4초 재표시 기준에 도달하면 `_shown=True`.
  다음 틱에서 재검출이 확정되면 다시 `_shown=False`가 된다.
- 관련 코드: `src/mabinogi_addon/tracker/debuff_engine.py:97` (재표시 기본값),
  `:235` (검출 확정 대기), `:415` (확정 결과 사용), `:419` (미감지 대기 누적).
  실제 생성 경로는 원격 기준 소스의 `ui/main_window.py:1112`를 읽어 확인했고,
  `reappear_sec`를 덮어쓰지 않으며 `:1144`에서 150ms 주기를 사용한다.

### 재현 및 검증 결과

`scripts/qa_debuff_flicker.py`는 두 아이콘의 실제 번들 PNG를 사용한다.
16px 화면 아이콘과 계속 보이는 보스 바를 모사한 입력을 구성하고,
실제 템플릿 매칭 → `DebuffEngine.tick()` → `BuffController._on_updated()`로 실행한다.
오버레이 창 출력만 항목 수·표시 여부 기록으로 대체하며, 매칭 결과는 모킹하지 않는다.

1. `0.000 / 0.151 / 0.302초`: 아이콘이 보이는 프레임으로 적용 확정, 오버레이에서 숨김.
2. `0.453 / 0.604초`: 아이콘 픽셀이 캡처되지 않은 모의 프레임 두 장 입력.
3. `0.755초`: 아이콘이 다시 보임. 실제 매칭 점수는 마법 방어력 보호 감소 **0.9948**,
   프라가라흐(마법) **0.9949**, 둘 다 raw 매칭 `True`. 확정 대기로 아직 숨김 유지.
4. `0.906초`: 같은 정상 프레임인데 미감지 타이머가 0.453초로 누적되어 아이콘 재표시.
5. `1.057초`: 재검출 확정, 다시 숨김. 회복 구간의 오버레이 항목 수는 `[0, 1, 0, 0]`.

약 0.151초의 가짜 재표시가 엔진·컨트롤러 실행으로 확인됐다.
보스 바는 전체 과정에서 인식되므로 바 게이팅 실패를 재현의 원인으로 사용하지 않았다.
위 시간은 결정적 재현 입력이며 실제 Windows 타이머 간격을 측정한 결과는 아니다.

```bash
PYTHONPATH=src QT_QPA_PLATFORM=offscreen python -m pytest -q tests/test_debuff_engine.py tests/test_debuff_fp_latch.py tests/test_debuff_momo_fp.py
PYTHONPATH=src QT_QPA_PLATFORM=offscreen python -m pytest -q scripts/qa_debuff_flicker.py
```

- 독립 QA: **2 failed, 12 passed**. 실패 둘은 같은 결함을 두 아이콘으로 검증한 것.
- 대조군: 안정적인 적용 상태 100틱, 한 틱만 누락, 실제 지속적인 미감지 재표시 모두 통과.

## 버프와 같은 판독인데 왜 다른가

둘 다 `cv2.matchTemplate(..., TM_CCOEFF_NORMED)`를 쓰지만 동일한 파이프라인은 아니다.

| 구분 | 버프 | 디버프 |
|---|---|---|
| 입력·탐색 | 원본 템플릿, 좁은 아이콘 세로 열 | 화면 높이 16px 가정, 10px로 축소해 영역 전체 검색 |
| 색·임계 | 그레이스케일, 기본 0.8 | BGR, 감지 0.68 / 해제 0.58 및 일부 아이콘별 override |
| 재감지 | `_on_detected()`에서 미감지 타이머 즉시 초기화 | 0.3초 확정 전까지 미감지 대기가 계속 누적 |
| 보조 증거 | 앵커 미검출 시 상태 동결, 시간 표시 버프는 남은 시간 재판독으로 보완 가능 | 시간 판독 없음, 설정에 따른 보스 바 게이팅 |

근거: `detect/buff_detector.py:34`, `detect/icon_matcher.py:17`,
`tracker/buff_state.py:156`, `tracker/engine.py`의 앵커·시간 보완 경로,
`tracker/debuff_engine.py:28` 및 `:39`.

작은 아이콘을 10px로 축소하면 구분 정보가 줄고 위치·배율·부분 가림 차이에 민감할 수 있다.
하지만 이것은 **최초 미검출의 후보 요인**이며, 오늘 크기나 이펙트 때문에 점수가 떨어졌다고
확인한 것은 아니다. 제보는 '없는 아이콘을 있다고 잡는 오탐'보다는
'있는 디버프를 잠깐 놓침 + 미적용으로 재표시하는 상태 오류'와 부합한다.
버프가 정상이라는 사실만으로 이 디버프 경로의 결함이 배제되지 않는다.

## 아이콘 줄 높이를 좁히는 제안

사용자 제안은 타당한 검토 방향이다. '영역 높이가 어떻든 검색 가능'은 탐색 방식의 설명이지,
배경이 많이 포함돼도 정확도가 같다는 보장이 아니다. 코드도 화면 아이콘 높이는 16px로
가정한다. **캡처 영역 높이**와 **아이콘 자체의 렌더링 높이·DPI**는 서로 다른 조건이다.

- 아이콘 줄과 작은 여백만 매칭하면 무관한 배경에서 최고점을 찾는 기회를 줄일 수 있다.
  하지만 아이콘이 잘리거나 크기 가정이 달라지면 오히려 미검출이 늘 수 있다.
- 현 구현은 같은 디버프 캡처에서 아이콘 매칭뿐 아니라 보스 바·사라짐 경고도 판정한다.
  `ui/debuff_tab.py:405`의 자동찾기도 이를 위해 아이콘 띠와 바를 함께 포함한다.
  아이콘만 남기는 수동 조정을 해결책으로 요구하면 보스 바 증거를 잃을 수 있다.
- 독립 대조 테스트에서 두 모의 입력을 아이콘 높이 16px로만 잘라보면 정상 매칭은 유지되지만,
  같은 장면의 `_bar_present`는 `True`에서 `False`로 바뀐다. 사라짐 경고는 bar 조건을 쓰므로
  이 증거 손실을 별도로 다뤄야 한다. 임의 Windows 화면 전체에서 동일 결과를 보장하지 않는다.
- 개발 검토안: 전체 캡처·진단 입력과 아이콘 매칭 ROI를 분리한다. 매칭은 좁은 아이콘 줄만
  사용하고 보스 존재·사라짐 경고는 보존된 HP바 증거를 사용한다. 좌표·DPI·아이콘 크기별
  동일 입력 비교로 성능과 오탐·미검출을 측정한 뒤 채택한다. 현재 구현됐다는 뜻은 아니다.
- ROI 축소만으로 재검출 중 미감지 타이머가 누적되는 확인 결함은 해결되지 않는다.
  상태 전환 수정과 최초 미검출 원인 분석은 별도로 진행해야 한다.

## 요구사항과 추가 검증

- `docs/기획서.md:71`은 1.5~2초 연속 미감지 후 재표시로 기재되어 있으나,
  현재 구현 기본값은 0.4초다. `assets/release_notes.md` v0.3.28에는 빠른 재표시 설명이 있다.
  따라서 수치 차이만으로 변경 의도나 정당성을 단정하지 않는다.
  수정 전 최신 승인 사양과 문서를 맞추되, 이번 결함은 **재매칭이 회복됐는데도 그 기간을
  미감지로 누적해 가짜 재표시하는 실행 경로**로 독립적으로 재현했다.
- 재검출 대기와 미감지 재표시의 상호작용을 수정한다. 단발 거짓 매칭을 막는 검출 확정,
  실제 디버프 해제 시 빠른 재표시, 기존 사라짐 경고 동작은 함께 회귀 확인해야 한다.
- 임계값을 일괄 올리거나 '사용자 영역이 틀렸다'는 가정부터 적용하지 않는다.
  원본 영역 PNG, 매칭 점수, raw/확정 상태, `_detect_since`/`_absent_since`,
  보스 바 판정 및 재시작 사유를 시간과 함께 기록해 **최초 미검출 이유**를 분리한다.
- Linux offscreen에서 검증했으며, 대상 엔진·컨트롤러·버프 비교 소스와 두 PNG의 blob 해시를
  원격 기준 소스와 대조했다. Windows 게임 화면, 실제 창 깜빡임, GPU·DPI별 점수 변화는 미검증.
- **오늘 제보와 동일 원인이라고 확정하지 않는다.** 두 틱의 캡처 누락은 통제된 재현 입력이다.
  마법 방어력 보호 감소의 라이브 증상은 사용자 확인, 프라가라흐(마법)의 라이브 증상은 미확정이며,
  두 아이콘 모두에서 확인된 것은 위 상태 전환 결함이다.
- 관련 투아림 QA는 `docs/qa/투아림_반복_알림_검토.md` 참조.
  두 확인 결함이 미해결이므로 전체 라이브 QA 통과나 신규 배포 준비 완료로 보고하지 않는다.
