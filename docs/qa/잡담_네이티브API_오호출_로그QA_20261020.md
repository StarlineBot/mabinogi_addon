실패 원인은 아니다. 앱은 위 창의 전체 경계를 가림으로 남겨 표시를 거부했다.
다른 창의 실제 대상 픽셀이 불투명했는지, 어떤 제품 소유인지까지 로그로 확정하지 않는다.

## Confirmed Bug / P2: 존재하지 않는 region 생성 함수

- 조건: 대상과 경계가 겹치는 창이 전역 알파 0 예외로 제외되지 않아 region 확인에 진입한다.
- 영향: 실제 window region으로 가림 여부를 보완하는 기능이 실행되지 않아 전체 창 경계로
  계속 거부할 수 있다. 정상 클릭·자동 표시 모두 같은 판정을 사용한다.
- 원인: `src/mabinogi_addon/system/dialogue_visibility.py:53`은
  `gui.CreateRectRgn(0,0,0,0)`을 호출한다. pywin32 win32gui는
  `CreateRectRgnIndirect(rect)`를 제공하며 `CreateRectRgn`을 제공하지 않는다.
  생성 단계 AttributeError가 잡혀 None을 반환하고 기존 blocked 상태가 유지된다.
- 증거: 최신 실제 로그의 region_error, 제품 경로, pywin32의
  [win32gui.i](https://github.com/mhammond/pywin32/blob/main/win32/src/win32gui.i)
  export 선언을 대조했다. Linux에서 해당 export 계약을 모델링한 제품 함수 실행도 같은 오류다.
- 한계: 이 API 수정만으로 사용자 PC의 가림 판정까지 반드시 통과한다고 보장하지 않는다.
  region이 없거나 실제로 겹치면 여전히 보수적으로 거부될 수 있다. Windows 합성 검증은 별도다.

## Confirmed Bug / P3: 차단 프로세스 진단 함수 오호출

- 조건: 수동 클릭이 가림으로 거부되어 차단 프로세스 진단을 실행한다.
- 영향: PID 이후 실행 파일 식별에 실패해 필요한 원인 자료를 남기지 못한다.
  이것은 추가 진단 결함이며 표시 차단의 직접 원인과 구분한다.
- 원인: 같은 파일 `:84`의 `win32process.QueryFullProcessImageName`은 해당 모듈의
  export가 아니다. [win32process.i](https://github.com/mhammond/pywin32/blob/main/win32/src/win32process.i)
  및 실제 identity_error와 일치한다. PID 조회와 핸들 열기 이후 실패한다.
- 검증: export를 임의로 추가하지 않은 API 모델에서 실제 함수 호출 시 같은 AttributeError가
  기록된다. 열린 프로세스 핸들은 finally에서 닫히므로 이번 경로의 핸들 누수를 주장하지 않는다.
- 대안: 기존 `system/window_watcher.py`의 QueryFullProcessImageNameW 호출 패턴 등 실제
  지원 API를 사용하고, 핸들 타입·서명·PID 재사용 확인·경로 비공개·정리를 보존한다.

- 이전 통과는 만든 함수가 있다고 가정한 로직 검증이었다. 실제 네이티브 호환성을 보장하지
  못했고 QA에서도 이 경계를 놓쳤다. 이번 로그로 실제 배포 실패를 확인했다.

## 개발 전달

1. 두 오호출을 실제 pywin32/Windows API 계약에 맞게 수정하고 관련 테스트도 함께 바로잡는다.
   없는 함수를 fixture로 만들어 정상 환경처럼 검증하지 않는다.
2. Windows에서 실제 모듈 export와 실제 shaped/empty/no-region HWND 경로를 검증한다.
   호출 결과뿐 아니라 GDI region과 프로세스 핸들 정리도 확인한다.
3. 실제 CEF 창의 region이 없으면 API 수정만으로 해결 완료 처리하지 않는다.
   필요하면 해당 대상의 노출 근거를 보완하되 전체 화면 캡처 폴링, 클래스 이름 고정 허용,
   layered/입력 통과 플래그만 보고 무조건 허용하는 변경은 하지 않는다.
4. 실제 불투명 가림·잠금·화면 밖 차단과 기존 다른 기능을 보존한다.
5. 이번 로그로 클릭/대사/거부 경로를 이미 확보했다. 동일 로그 재제출이나 다른 앱 종료를
   사용자에게 먼저 요구하지 않는다. 제품 수정 후 독립 QA에서 재확인한다.

제품·설정·기존 테스트는 수정하지 않았다. QA 보고서와 미해결 재현만 공유하며,
이번 결과를 해결 완료나 배포 승인으로 표시하지 않는다.
