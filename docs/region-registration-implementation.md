# 영역 등록 기반 사용 및 지정 해제 구현

- 날짜: 2026-10-18 (Asia/Seoul).
- 명세: [영역 등록 기반 사용](region-registration-usage-spec.md).
- UI: 사용자가 승인한 같은 줄의 `자동 찾기 / 직접 지정 / 지정 영역 보기 / 지정 해제`.
  도르카·투아림은 영역별 상태 다음 줄에 명령을 모으고 독립 표시/알림 선택을 유지한다.

## 실행 및 대상 선택

- 버프·디버프·보스·체력바·단축바의 전체 사용 체크와 실행 차단 조건을 제거했다.
  기존 enabled=False만으로 등록 영역을 차단하지 않는다. 영역이 없으면 판독하지 않는다.
- 보스의 하드코딩 기본 영역 폴백을 제거했다. 지정 해제 후 재시작해도 이전 위치를
  자동 복원하지 않는다. 공유 영역 로더와 설정의 None이 미등록을 뜻한다.
- 자동설정의 체크는 general.setupSelection과 setupOrder에만 저장한다. 영역, 세부 옵션,
  기존 enabled 값, 현재 실행에는 쓰지 않는다. 선택하지 않아도 등록 상태는 등록됨이다.
- 첫 사용 안내와 사용 준비 페이지는 '이번 설정에서 제외'와 등록 상태를 구분한다.
  선택한 미등록 영역만 기존 승인 파이프라인으로 등록하며, 다음 단계 이동은 성공을 요구하지 않는다.
- 도르카 표시/투아림 표시/투아림 알림, 메모·커스텀, 개별 아이콘/소리/경고 기준,
  접근 권한 및 기존 전체 일시정지 범위는 유지한다.

## 해제와 실패 처리

- 확인창은 기본 취소이며 대상 영역과 현재 설정에 따른 공유 소비자를 안내한다.
  같은 bossPattern.box를 사용하는 보스/디버프 체력 판단/체력바 보스전 경고에 적용한다.
  디버프의 별도 아이콘 영역 및 자원 영역은 삭제하지 않는다.
- 최신 파일을 다시 읽어 대상 필드만 None으로 원자 저장한다. 확인 중 영역이 바뀌면
  새 영역을 삭제하지 않는다. 취소/권한 오류는 디스크와 메모리 동작을 유지한다.
- 저장 성공 뒤에만 이전 판독/미리보기/추적/오버레이를 정리한다. 도르카 탐색 epoch,
  선택/자동찾기/일괄 승인 세대를 확인해 해제 후 늦은 결과가 영역을 되살리지 않게 했다.
- 보스·디버프 동시 등록은 한 원자 저장으로 처리한다. 저장 전 메모리를 바꾸지 않는다.
- 단축바 기본 배치를 만드는 것만으로 설정을 저장하지 않는다. 등록 상태로 즉시
  동작하더라도 첫 화면 노출/미리보기로 사용자 설정을 변경하지 않게 한다.
- 실제 추적 워커에서 정지 전 이미 큐에 들어간 결과도 세대 검증으로 폐기한다.
  성공적으로 종료한 워커도 신호를 해제한다. 재시작 후 이전 결과/소리 적용을 차단하며
  새 워커 콜백이 UI 스레드에서 실행되는지 검사했다.

## 검증 기록

- 새 영역별 삭제/취소/권한 오류/선택 독립성/공유 영역/늦은 후보: 26 passed (5.25초).
- 자동설정·탐색·자원 통합·보스·체력바·단축바·조작 회귀의 중간 실행: 218 passed (105.94초).
- 워커 큐 폐기/UI 스레드/일시정지/종료/사라짐 경고: 17 passed (17.34초).
- 기본 및 20px 글꼴 실제 Qt 렌더: 2 passed (2.85초). 대상 6개 탭에 수평 스크롤이 없고
  각 '지정 해제' 명령이 스크롤 뷰포트 안에 들어오는지 확인했다.
- 기존 ON/OFF 왕복 검사는 지정 해제/재등록 왕복으로 바꿨으며 이전 값이 다시 표시되지
  않아야 한다는 assertion은 유지했다. 자동설정 테스트의 선택 API도 별도로 바꿨다.
- 등록 상태의 테스트가 이제 실제 실행 조건을 만족하므로 가짜 캡처 소스를 명시적으로
  주입했다. 외부 장치 차단/누수 검사/시간·숫자 판독 기대값은 완화하지 않았다.
- 새 검사 도구의 반복 MainWindow 준비/정리에서 Qt 네이티브 종료/해제 이벤트 오류가 있었다.
  영역별 저장 정책은 독립 컨트롤러로, 공유/탐색 통합은 실제 MainWindow로 나눠 검사하고
  창·선택기의 소유권과 DeferredDelete 정리를 명시했다. 이를 Windows 제품 결함이나
  Windows 검증 성공으로 집계하지 않는다.
- 초기 검사 명령의 없는 파일명, 개발 중 괄호 누락 수집 오류는 바로잡고 재실행했다.
  수정 중 실행한 전체 검사는 최종 결과로 사용하지 않는다. 최종 검증은 아래에 별도 기록한다.

## 추가 QA: 제작자 잡담

- `docs/qa/제작자_잡담_클릭무반응_독립QA_20261018.md`의 조건부 Windows 모델 결함을 반영했다.
- WS_EX_LAYERED이며 GetLayeredWindowAttributes가 LWA_ALPHA/alpha=0을 확인한 창만
  불투명 가림에서 제외한다. 입력 통과 플래그/반투명/색상 키/픽셀별 투명/조회 실패를
  같은 것으로 간주하지 않는다. 가림 판정은 여전히 캡처·포커스 변경 없이 수행한다.
- 원본 재현의 투명 노출/실제 얼굴 클릭/자동 잡담 조건을 일반 회귀에 포함하고,
  부분 알파 1/128/255, 비레이어드, 색상 키, 조회 실패 대조군을 추가했다.
- 클릭을 거절하면 사유 범주와 유효 대사 수를 로컬 로그에 남긴다. 자동 틱마다 창 목록이나
  대사 내용/캐시/비밀값을 로깅하지 않는다. API 모델 통과를 실제 사용자 PC 원인 확정으로 보지 않는다.
- 원본 QA의 '투명 창을 제거해야만 보임' 관측은 수정 후 의도적으로 맞지 않으므로 CI로
  가져오지 않았다. 원본 파일은 유지한다. 원래 정상 가림/클릭/자동 기대값은 그대로 검사한다.

## 최종 보완 검증

- 보스 영역 해제 후 같은 보스를 재등록해도 추적기가 다시 생성되도록 현재 보스와
  HP 안정화 이력을 함께 비운다. 단축바는 이전 셀 이미지를 비운다.
- 보스/디버프 동시 등록 저장은 한 번만 수행하며, 권한 오류 시 두 영역 모두 유지한다.
- 마지막 보완 후 영역 등록·워커 세대·보스·체력바 표시·흔들림·조작 일관성:
  103 passed (29.48초).
- 최종 기본/20px 글꼴 실제 Qt 렌더: 2 passed (3.41초).
- 같은 실행 순서로 정지한 워커 객체를 보존하고 큐를 배출하는 대조 실험에서,
  수정 전은 정지 뒤 콜백 1회, 수정 후는 0회였다. 일반 회귀는 네 신호의 폐기와
  다음 실행의 네 콜백이 UI 스레드에 도착하는 것을 검사한다.
- 위 결과는 Linux offscreen 및 명시적 외부 경계 대체 결과이며 Windows 통과가 아니다.
- 전체 격리 회귀: 1598 passed, 10 deselected, 3 warnings (773.51초).
  명령은 `OPENCV_FOR_THREADS_NUM=1 QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q -m 'not windows_integration' --tb=short --maxfail=8`.
  제외한 10개는 Windows 통합 검사이며 실패를 숨기기 위한 제외가 아니다.
  경고 3개는 기존 toast 테스트의 QMouseEvent 생성자 DeprecationWarning이다.
- 전체 검사 시작 뒤 추가한 보스 재등록 상태 초기화·단축바 셀 비우기·종료 중 승인 차단과
  회귀 2개는 위 103개 최종 보완 검사로 따로 확인했다. 전체 결과가 이 마지막 보완까지
  다시 실행한 결과인 것처럼 해석하지 않는다.
- 실제 루프백 네트워크 응답/중단/객체 정리 200회 반복도 별도 실행: 1 passed (2.70초).
- 최종 소스의 제작자 잡담·투명 가림·기존 가림 회귀: 75 passed, Windows 통합 2 deselected

## 미검증 및 전달

Actions 무료 한도 정책에 따라 Windows 실행을 새로 요청하지 않는다. 실제 Windows
캡처/알파 합성/혼합 DPI/장시간 부하/네이티브/exe 빌드는 미검증이다.
실제 Windows용 알파 0 HWND 검사는 별도의 windows_integration 단계에 남겨뒀다.
해제 상태의 재실행/게임 시작과 잡담 클릭은 라이브에서도 확인해야 한다.
태그·릴리즈는 하지 않는다. 이번 변경은 사용자 승인에 따라 검증 후 main에 함께 푸시한다.
