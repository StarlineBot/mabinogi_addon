## 2. 공통 화면 구성

### 2.1 정보와 명령 줄

판독 대상과 등록 상태는 명령 버튼과 항상 다른 줄에 둔다. 창이 넓어져도 다시 한 줄로 합치지 않는다.

```text
기능 이름
기능 설명

판독 영역 · 대상 이름
등록 상태 · 영역 정보
[자동 찾기] [직접 지정] [지정 영역 보기]    [지정 해제]

판독 미리보기
표시 관련 그룹
알림 관련 그룹
진단/참고 정보
```

- 자동찾기/지정 영역 보기 등 실제로 제공하는 명령만 둔다. 기능에 없는 명령을 형식상 추가하지 않는다.
- 좁은 폭에서는 상태 문구와 버튼 줄 내부를 줄바꿈할 수 있다. 버튼끼리 겹치거나 정보 줄로 섞이지 않는다.
- 지정 해제는 다른 명령과 구별되는 보조 명령으로 두고 기존 확인·저장 실패·세부 설정 보존 규칙을 따른다.
- 좌표와 크기는 기존 좌표 체계를 유지한다. 화면 정리를 이유로 저장 좌표나 DPI 변환을 변경하지 않는다.

### 2.2 그룹 표현과 동작

- 같은 작업의 설정은 제목, 얇은 테두리와 일정한 내부 여백으로 묶는다.
- 같은 수준의 그룹은 좌우 경계와 제목 위치를 맞추며 그룹 안에 또 테두리 그룹을 중첩하지 않는다.
- 단순 구분선이나 흐린 제목만으로 주요 그룹 경계를 대신하지 않는다.
- 표시를 바꾸는 조작과 판독 원본 확인을 구분한다. 미리보기만 보기 위해 설정이 변경되어서는 안 된다.
- 정상 설정 그룹은 펼쳐 두고 진단/수집/호환성 도구는 하단에서 접어 제공한다.
- 잠금 버튼은 대상과 현재 상태를 알 수 있게 한다. 여러 대상의 선택/전체 명령에는 대상을 생략하지 않는다.
- 잠금 안내는 현재 상태와 일치한다. 잠금 해제 후 이동 가능하며 잠그면 기존 클릭 통과 정책을 따른다.
- 기존 창 크기, 테마와 2단 가로 탭을 유지한다. 기본 글꼴을 줄여 억지로 맞추지 않는다.
- 전체 페이지 스크롤은 허용하되 의미 없는 빈 공간과 불필요한 내부 스크롤을 늘리지 않는다.

### 2.3 미리보기의 크기

- 미리보기는 실제 내용 크기와 필요한 최소 여백에 맞춰 왼쪽에 배치한다.
- 그룹이 페이지 전체 폭을 사용하더라도 내부 미리보기 틀까지 전체 폭으로 늘리지 않는다.
- 내용이 차지하지 않는 넓은 배경 띠, 빈 캔버스와 불필요한 고정 높이를 만들지 않는다.
- 표시 배율을 바꾸면 실제 예시 크기에 맞춰 높이를 조정한다. 내용이 없는 공간을 유지하려고 큰 높이를 고정하지 않는다.
- 가용 폭 안에 들어오면 스크롤 없이 전체 예시를 보여준다. 실제 내용이 폭을 넘을 때만 가로 스크롤 등 기존 확인 수단을 제공한다.
- 미등록/판독 불가에서도 작은 원본 자리와 상태 문구 또는 기존 크기의 출력 예시는 유지할 수 있으나 빈 상태 때문에 큰 틀을 만들지 않는다.
- 예시를 보기 좋게 채우려고 출력 배율을 임의로 확대하거나, 큰 배율을 맞추려고 미리보기만 임의 축소하지 않는다.

## 3. 보스 패턴 알림

### 배치

```text
보스 패턴 알림
보스 체력바를 판독해 패턴 시점에 화면과 소리로 알립니다.

판독 영역 · 보스 체력바
등록 상태 · 영역 정보
[자동 찾기] [직접 지정] [지정 영역 보기] [지정 해제]

[판독 미리보기]
  체력바 원본 이미지
  식별: 보스 이름                       HP: 현재 비율

[패턴 경고]
  [경고 위치 잠금] [알림 미리보기]
  현재 잠금 상태에 맞는 이동 안내

[남은 패턴 목록]
  남은 패턴 목록 표시
  [목록 위치 잠금]
  현재 잠금 상태에 맞는 이동 안내

> 진단 · 보스 HP바 수집
지원 보스 및 패턴 기준 목록
```

- 경고와 패턴 목록을 서로 다른 그룹으로 둔다. 각 잠금 조작은 해당 그룹 안에 둔다.
- 경고 미리보기는 경고 그룹에서 실행하며 기존 화면·소리 시험 동작을 유지한다.
- 판독 미리보기는 원본 이미지와 보스 식별/HP를 함께 보여준다. 원본 확인과 경고 시험을 혼동하지 않는다.
- 지원 보스와 패턴 기준은 모든 설정/진단 진입 아래 최하단으로 이동한다. 지원 목록 내용은 삭제하지 않는다.
- 기존 수집 기능/로그인 접근 조건, 두 출력의 독립 위치/잠금 및 공유 보스 영역 정책을 유지한다.

## 4. 체력바

```text
체력바
생명력·마나·스태미나를 별도 오버레이로 표시합니다.

판독 영역 · 생명력/마나/스태미나
등록 상태 · 영역 정보
[자동 찾기] [직접 지정] [지정 영역 보기] [지정 해제]

[판독 미리보기]
  원본 이미지 · 현재 판독 수치

[표시]
  표시할 바: 생명력 / 마나 / 스태미나
  표시 배율 / 수치 정렬
  [전체 잠금] [전체 잠금 해제]
  표시 미리보기: 생명력 / 마나 / 스태미나

[낮은 수치 알림 · 보스전]
  자원별 알림 선택과 기준
  소리 알림
  보스 체력바 영역: 등록됨 또는 지정 필요

> 진단 · 체력바 판독 / 수집
```

- 원본 미리보기와 현재 수치는 유지한다. 새로 그린 표시 예시가 이를 대체하지 않는다.
- 표시할 자원, 표시 배율, 수치 정렬, 잠금과 출력 미리보기를 하나의 표시 그룹으로 묶는다.
- '정렬'은 수치의 정렬임을 명시한다. 원본 바나 오버레이 묶음의 배치 정렬로 설명하지 않는다.
- 각 자원 알림 기준을 같은 열에 맞추고, 폭이 부족하면 자원 단위로 다음 줄에 배치한다.
- 보스 영역 등록은 실제 보스전 감지와 다르다. 등록만 확인했으면 '보스전 감지됨'으로 표시하지 않는다.
- 기존 보스전 경고 조건, 소리, 흔들림 및 각 자원 표시/알림의 독립 선택을 유지한다.

## 5. 도르카·투아림 공통 영역 설정

### 5.1 공통 설정의 의미

- 사용자는 같은 원형 UI를 한 번 찾아 도르카 숫자와 투아림 % 후보를 함께 확인한다.
- '공통 영역'은 사용자 관점의 설정 단위다. 도르카 숫자와 투아림 %를 같은 판독 사각형으로 합치는 뜻이 아니다.
- 공통 원형 장식과 해당 UI의 배치를 기준으로 두 위치를 도출하고 대상별 검증을 유지한다.
- 두 후보는 같은 원형 UI에 속해야 한다. 서로 다른 원이나 앱이 그린 복제본의 후보를 임의로 짝짓지 않는다.
- 현재 소스는 공통 장식 탐색 기반을 공유하지만, 두 검출기는 숫자 판독과 오른쪽 구조 확인 등 검증 조건이 다르다.
  사용자 조작 통합을 위해 이 검증을 없애거나 항상 두 후보를 찾을 수 있다고 보장하지 않는다.
- 특정 API, 템플릿 수, 클래스/스레드 구조 또는 저장 포맷을 기획에서 고정하지 않는다.

### 5.2 화면 구성

```text
도르카·투아림
도르카와 투아림을 오버레이로 표시하고 투아림 충전 상태를 알려줍니다.

판독 영역 · 도르카/투아림
공통 등록 상태 · 영역 정보
[자동 찾기] [직접 지정] [지정 영역 보기] [지정 해제]
> 개별 영역 조정

[표시]
  도르카 표시 / 투아림 % 표시 / 투아림 알림 사용
  표시 배율 / 위치 잠금
  원본·판독 확인
    도르카 원본 이미지       현재 판독: N/15 또는 판독 불가
    투아림 원본 이미지       최근 확정: P% 또는 판독 불가
  표시 미리보기
    기존 통합 오버레이를 실제 설정 크기로 표시

[투아림 알림]
  첫 알림 / 추가 알림 / 각 소리 선택

> 진단 · 도르카/투아림 판독 / 수집
```

- 공통 자동찾기 버튼은 하나만 기본 노출한다. 처음부터 두 개의 같은 자동찾기 조작을 요구하지 않는다.
- 공통 등록 상태는 둘 다 등록/도르카만 등록/투아림만 등록/미등록을 구분한다.
  하나의 좌표/크기를 표시한다면 두 판독 영역을 포함하는 원본 범위임을 명시하며, 기존 설정에서 공통 범위를 확정할 수 없으면 개별 정보를 보여준다.
- 문서 예시의 좌표와 크기를 고정 기본값으로 쓰지 않는다. 작은 원만 포함하고 투아림 %를 제외하는 크기를 공통 범위로 확정하지 않는다.
- 두 원본 이미지와 판독값은 작은 행으로 위아래 대응시킨다. 원본 이미지와 실제 새로 그린 오버레이 예시를 모두 표시 미리보기라고 부르지 않는다.
- 출력 예시는 기존 통합 오버레이의 실제 모양을 유지한다. 두 값의 원본 확인 행을 두 개의 새 출력 오버레이로 구현하지 않는다.
- 세 독립 선택은 사용자가 제시한 대로 표시 그룹 상단 한 줄에 모은다. 투아림 알림 그룹은 상세 기준과 소리를 담당한다.
  세 옵션의 독립 동작과 기존 기본값을 유지하며 좁은 폭에서는 선택 항목 단위로 줄바꿈한다.
- 표시 그룹 안에서도 미리보기 자체는 내용 폭에 맞춘다. 예시보다 훨씬 큰 전체 폭 배경/고정 높이의 틀을 두지 않는다.
- 진단 제목을 통합해도 도르카의 새로운 수집 엔진을 자동으로 추가하는 요구는 아니다. 기존 제공 도구와 접근 조건을 보존하고 대상 이름을 명시한다.
- 베타 접근 설명은 실제 제한이 있는 조작에 적용한다. 공통 설정으로 묶었다는 이유로 일반 투아림 알림을 로그인 필수로 바꾸지 않는다.

### 5.3 자동찾기 정상 흐름

1. 사용자가 공통 자동찾기를 실행한다.
2. 현재 게임 화면에서 공통 원형 UI를 찾고 도르카 숫자와 투아림 %의 후보를 구한다.
3. 한 확인 흐름에서 두 영역을 동시에 표시하고 각각 대상 이름을 붙인다.
4. 사용자는 숫자와 %가 각 영역 안에 포함되는지 확인한다. 현재 숫자를 읽었다는 사실만으로 전체 판독 신뢰도를 보증하지 않는다.
5. 승인한 후보만 저장하고 각 기존 판독 경로에 반영한다. 두 후보를 모두 승인할 때 별도 자동찾기나 두 번째 승인창을 요구하지 않는다.
6. 설정 반영 후 화면을 복원하고 기존 표시/알림 선택에 따라 동작한다. 다른 세부 옵션을 자동 변경하지 않는다.

### 5.4 부분 성공 및 실패 처리

- 둘 다 찾았으면 두 후보를 한 번에 승인한다. 한쪽이 맞지 않으면 전체 취소 후 개별 조정을 사용할 수 있다.
- 한쪽만 찾았으면 '도르카만 찾음' 또는 '투아림만 찾음'으로 표시하고 등록할 대상을 명시한다.
  찾은 쪽만 승인할 수 있게 하며 찾지 못한 쪽의 기존 영역은 보존한다.
- 두 후보가 서로 같은 원형 UI인지 확정할 수 없으면 둘 다 찾았다고 표시하지 않는다.
- 후보 없음/가림/복수 후보/일부 화면 밖/캡처 실패 등은 확인할 수 있는 이유만 안내한다.
  구체적인 원인을 모르면 추정 원인을 확정해서 설명하지 않는다.
- 취소, 후보 거절 또는 저장 실패 시 기존 영역과 세부 설정을 유지한다.
- 두 후보의 일괄 저장이 실패하면 일부만 바뀐 상태를 전체 성공으로 표시하지 않는다.
  사용자가 승인한 적용 단위의 변경은 일관되게 반영하거나 기존 값을 유지한다.
- 후보 확인 중 게임 UI가 움직여 어긋났다면 취소 후 다시 찾을 수 있다.
  자동 추종, 지속적인 화면 변화 검증 또는 새 전면 감시는 이번 개선에 추가하지 않는다.

### 5.5 수동 보정 및 해제

- 개별 영역 조정은 기본 접힘 상태로 두고 도르카/투아림 각각의 등록 상태, 직접 지정, 지정 영역 보기, 지정 해제를 제공한다.
- 기본 직접 지정도 한 번의 원본 UI 지정과 한 확인 흐름에서 두 판독 영역을 확인한다.
  사용자는 원과 오른쪽 아래 %가 포함되는 공통 원본을 지정하며, 두 내부 영역을 확인한 뒤 저장한다.
  자유롭게 지정한 사각형만으로 두 내부 영역을 안전하게 유도할 수 있는 범위는 구현 검증이 필요하다.
- 내부 위치를 확정하지 못했는데 두 영역 등록 성공으로 처리하지 않는다. 기존 개별 직접 지정은 수동 보정 경로로 유지한다.
- 한쪽 직접 수정/해제는 다른 쪽을 변경하지 않는다. 둘을 다 설정해야 한쪽 기능을 쓸 수 있는 구조로 바꾸지 않는다.
- 상단 공통 지정 영역 보기는 등록된 두 영역을 대상명과 함께 보여준다. 하나만 있으면 그 하나만 보여준다.
- 상단 공통 지정 해제는 두 영역을 해제하는 명령이다. 확인창에 도르카 표시/투아림 표시/투아림 알림에 미치는 영향을 명시한다.
- 공통 해제도 세부 옵션/위치/배율/잠금을 보존한다. 이후 늦은 판독/검색 결과가 해제한 영역을 되살리지 않아야 한다.

### 5.6 기존 동작 및 안내 연계

- 기존 두 등록 영역은 그대로 사용한다. 공통 UI 도입만으로 덮어쓰거나 재등록을 요구하지 않는다.
- 한쪽 미등록/판독 실패가 다른 쪽의 정상 표시·알림을 중단시키지 않는다. 두 값의 실패 표기와 투아림 알림 재무장/중복 억제 정책을 유지한다.
- 공통 등록 결과를 기존 영역 판독과 별도의 세 번째 실행 조건으로 만들지 않는다.
- 첫 사용 안내의 체크는 여전히 이번 설정 대상만 뜻한다. 표시·알림 사용 옵션을 변경하지 않는다.
- 안내에서 투아림만 설정 대상으로 선택했다면 도르카 등록을 필수로 요구하거나 도르카 영역을 자동 덮어쓰지 않는다.
- 동일 요청에 두 대상이 포함되어 있다면 공통 후보 확인 흐름을 재사용해 사용자에게 같은 원을 두 번 찾게 하지 않는다.
  이미 등록된 영역을 건너뛰는 기존 일괄 자동설정 정책은 유지한다.
- 판독 중 재탐색/복구 정책을 공통 자동찾기 UI 변경과 함께 임의 통합하거나 제거하지 않는다.

## 6. 커스텀 오버레이

```text
커스텀 오버레이
기능 설명
커스텀 오버레이 사용

[오버레이]
  현재 프리셋: 적용 중인 이름 또는 이름 없는 구성
  자동 저장 상태                       [다른 이름으로 저장...]
  [+ 복제 영역 추가]
  이름 / 원본 영역 / 표시 배율 / 위치 잠금 표
  [선택 잠금] [선택 잠금 해제] [선택 삭제]
  [전체 잠금] [전체 잠금 해제] [전체 삭제]

[프리셋]
  저장된 프리셋 목록
  [불러오기] [선택 프리셋 삭제]
  시작 시 불러오기 [대상 선택]

> 고급 · 캡처 호환성
```

- 오버레이 편집을 주 작업으로 먼저 보여주고 프리셋 관리를 그 아래에 둔다.
- 현재 편집 대상 이름과 자동 저장 상태는 오버레이 표 위에 둔다. 표를 편집하기 전에 저장 대상을 알 수 있어야 한다.
- 다른 이름으로 저장도 편집 대상 가까이 제공한다. 원본 보존용 분기를 만들기 위해 프리셋 목록 아래까지 찾아가지 않게 한다.
- 프리셋 목록 선택, 현재 적용 중인 이름 및 시작 시 불러오기 대상의 구분을 유지한다.
- 복제 영역 추가는 현재 오버레이 표와 같은 그룹 안에 둔다. 추가/이동/배율/잠금 편집의 자동 저장 정책은 변경하지 않는다.
- 삭제 대상을 명시하고 기존 확인을 유지한다. 프리셋 삭제와 현재 오버레이 삭제를 같은 명령으로 합치지 않는다.
- 기존 커스텀 사용 체크는 유지한다. 이번 작업을 이유로 새 영역 사용 정책을 커스텀 전체에 확대하지 않는다.
- 기존 저장 실패 표시/재시도를 유지한다. 저장 실패 안내가 그룹 배치 때문에 가려지거나 저장 성공처럼 보이면 안 된다.

## 7. 단축바

```text
단축바
기능 설명

판독 영역 · 원본 첫 칸
등록 상태 · 영역 정보
[자동 찾기] [직접 지정] [지정 영역 보기] [지정 해제]

[표시]
  표시 배율               [전체 잠금] [전체 잠금 해제]
  기본 배치
  [중앙 하단(기본)] [중앙 2단] [블록 분리]
```

- 판독 영역은 원본 첫 칸을 지정하는 조작임을 유지하며 등록 정보와 버튼 줄을 분리한다.
- 배율/잠금/기본 배치를 하나의 표시 그룹으로 묶는다.
- 저장 프리셋과 구분하기 위해 기존 배치 버튼의 제목을 기본 배치로 표현한다. 저장 기능을 새로 추가하지 않는다.
- 새 지정 영역 보기는 첫 칸을 기준으로 복제하는 전체 원본 범위와 기준 첫 칸을 구별해 보여준다.
  출력 오버레이의 위치나 배율을 바꾸는 조작이 아니며 원본을 임시로 강조한 뒤 정리한다.
- 등록 전에는 지정 영역 보기를 실행하지 않는다. 12개 그룹, 빈 슬롯 숨김, 원본 격자 및 배율 정책은 유지한다.

## 8. Acceptance Criteria

### 추가 승인: 메모

- 메모는 `표시 영역 · 메모 위치·너비` → 등록 정보 → 직접 지정/지정 해제 → 표시 →
  메모 내용 순서다. 화면을 읽는 판독 영역이나 자동찾기로 설명하지 않는다.
- 별도 메모 오버레이 사용 체크를 제거한다. 기존 enabled=False라도 표시 영역이 등록되면
  게임/앱 활성·잠금·전체 일시정지 조건에 따라 표시한다.
- 지정 해제는 표시 영역만 원자 저장으로 지우고 즉시 숨긴다. 메모 내용·글자 크기·잠금과
  마크다운 편집/미리보기는 유지한다. 취소/저장 실패는 기존 영역·동작을 유지한다.
- 늦은 위치 이동/영역 선택 콜백이 해제한 영역을 복원해서는 안 된다. 종료/설정 교체 중에는
  새 지정이나 표시를 시작하지 않는다.
- 보스 경고/목록·도르카·투아림·메모의 단일 잠금은 상태가 드러나는 토글 버튼을 쓴다.
  체력바·단축바·커스텀의 선택/전체 잠금 명령은 기존 버튼을 유지한다. 커스텀 표는 잠금
  상태를 텍스트로 보여주며 조작은 대상이 명시된 버튼으로 한다.

### 기존 검증 기준

| ID | 검증 가능한 기준 |
|---|---|
| GRP-01 | 대상 화면의 판독 대상/등록 정보와 영역 명령이 서로 다른 줄에 있고, 넓은 창에서도 다시 같은 줄로 합쳐지지 않는다. |
| GRP-02 | 기본 및 큰 글꼴/높은 DPI/작은 작업 영역에서 그룹 제목, 상태, 버튼이 겹치거나 잘리지 않는다. 필수 조작이 제작자 얼굴에 상시 가려지지 않는다. |
| GRP-03 | 보스 경고와 패턴 목록의 잠금 조작이 각각의 그룹 안에 있으며 지원 보스 목록은 설정/진단 뒤 최하단에 있다. |
| GRP-04 | 체력바의 원본 미리보기/현재 판독값과 출력 표시 미리보기가 구분되어 유지되고, 등록됨 표시만으로 보스전 감지 성공을 주장하지 않는다. |
| GRP-05 | 도르카·투아림 공통 자동찾기 한 번으로 두 후보를 같은 확인 흐름에서 볼 수 있고, 둘 다 승인할 때 두 번째 검색/승인창이 필요하지 않다. |
| GRP-06 | 공통 UI에 두 판독 영역과 세 독립 표시/알림 선택이 유지된다. 한쪽 판독 실패로 정상인 다른 쪽 동작이 중단되지 않는다. |
| GRP-07 | 두 후보가 서로 다른 원형 UI에 속하거나 쌍으로 확정할 수 없을 때 임의의 한 쌍을 성공으로 등록하지 않는다. |
| GRP-08 | 부분 성공 시 찾은 대상/등록할 대상이 명시되고 실패한 쪽의 기존 영역이 보존된다. 취소/거절/저장 실패는 승인 전 설정을 유지한다. |
| GRP-09 | 공통/개별 지정 해제는 안내한 범위에만 적용된다. 세부 옵션을 보존하고 지연 결과가 영역/표시/알림을 되살리지 않는다. |
| GRP-10 | 투아림만 선택한 안내 흐름은 도르카 등록을 요구하거나 그 설정을 자동 변경하지 않는다. 두 대상이 같은 요청에 포함되면 사용자 검색/확인 절차를 중복하지 않는다. |
| GRP-11 | 커스텀 표 위에서 적용 중인 프리셋과 자동 저장 상태를 확인할 수 있다. 다른 목록 항목을 선택한 채 편집해도 저장 대상은 바뀌지 않는다. |
| GRP-12 | 커스텀 영역 추가/선택·전체 조작이 오버레이 그룹 안에 있고 프리셋 삭제와 현재 항목 삭제가 구분된다. 저장 실패/재시도 동작을 유지한다. |
| GRP-13 | 단축바 지정 영역 보기는 저장된 첫 칸과 유도된 원본 범위를 구분해 강조한 뒤 정리하며 배율/배치/설정을 변경하지 않는다. |
| GRP-14 | 화면 배치 변경만으로 기존 영역·위치·배율·잠금·소리·프리셋 또는 접근 조건이 바뀌지 않으며 진단 접기가 판독/알림 실행 조건을 바꾸지 않는다. |
| GRP-15 | 기본 배율에서 미리보기 틀은 실제 내용과 필요한 여백에 맞춰 배치된다. 내용이 가용 폭에 들어오면 불필요한 전체 폭 빈 캔버스/고정 높이/가로 스크롤이 없고 배율 변경 후에도 잘리지 않는다. |
| GRP-16 | 도르카/투아림의 작은 원본 확인 행과 실제 통합 출력 예시가 구분되며, 두 값 중 하나만 등록되어도 공통 등록 완료로 오인 표시하지 않는다. |
| GRP-17 | 공통 직접 지정 한 번으로 두 내부 후보를 같은 흐름에서 확인할 수 있다. 내부 위치를 확정하지 못하면 성공으로 저장하지 않고 개별 보정으로 연결하며 기존 설정은 보존한다. |

## 9. 개발 및 독립 QA 인계

- 기능 정책의 추가 사용자 결정 사항은 없다. 이 문서를 구현 및 독립 QA 기준으로 전달한다.
- 세부 폭/간격과 그룹 높이, 미리보기 크기 및 진단 접기의 실제 모양은 렌더 후 사용자 확인을 받는다.
