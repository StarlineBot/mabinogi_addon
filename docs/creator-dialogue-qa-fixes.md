# 제작자 말풍선 QA 수정 기록

2026-10-16 개발 대응. 기준 보고서는 `qa/제작자_말풍선_및_체력바_수정_QA.md`,
원본 재현은 `scripts/qa_creator_dialogue.py`다. 보고서와 원본 재현을 수정하지 않았다.

## 원인과 수정

- 원본 독립 재현은 **2 failed, 4 passed (2.30초)**로 보고서의 두 실패를 재확인했다.
- `CREATOR-QA-01`: feed가 형식만 확인하고 표시할 수 없는 목록까지 정상 캐시에 저장했다.
  실제 말풍선을 먼저 만들고 현재 글꼴의 두 줄 측정을 feed 검증 함수로 전달한다.
  내장/캐시/원격 데이터 모두 같은 검증을 거치며, 사용할 수 있는 항목이 하나도 없으면
  메모리 목록과 캐시를 교체하거나 갱신 신호를 내보내지 않는다. 이미 불량 캐시가 있으면
  현재 글꼴에서 사용할 수 있는 내장 목록을 유지한다.
- 정상/불량 혼합 목록은 사용할 수 있는 항목만 세션에 전달한다. 캐시에는 검증된 응답
  원문을 원자 저장하며 다음 시작에서도 현재 글꼴로 다시 검사한다. 글꼴에 따라 동일
  문장이 실제 두 줄에 들어가면 사용할 수 있으므로 특정 문자열을 무조건 차단하지 않는다.
- 선택형 문장 전체 조합을 무제한 전개하지 않는다. 각 부분의 글꼴상 짧은 선택으로 실제
  표시 가능한 완성 문장을 가진 항목을 받는다. 원래 선택형 재료는 유지하고 실제 추첨한
  완성 문장도 표시 전에 측정한다. 32회 추첨에서 유효한 다른 문장을 얻지 못한 경우에만
  항목당 짧은 조합 하나를 유한하게 확인해 드문 유효 조합이 계속 탈락하지 않게 한다.
- `CREATOR-QA-02`: 새 문장 위치 준비 후 마지막 노출 검사가 실패했는데도 기존 보이는
  위젯을 그대로 남겼다. 최초/교체 요청 모두 실패 시 말풍선과 만료 타이머를 닫는다.
  거절된 문장은 직전 표시 기록/자동 횟수에 포함하지 않고 소리 콜백도 호출하지 않는다.
  다음 정상 요청이 성공하면 그 시점부터 새 3초 수명과 표시 기록을 시작한다.
- `CREATOR-CI-QA-01`: 128KiB 초과 bytes와 깊은 중첩 입력이 pytest 자동 ID에 포함되어
  Windows 환경변수 길이 제한을 넘었다. 두 매개변수 집합에 짧은 명시적 ID만 지정했다.
  대용량/손상 입력과 원래 assertion은 그대로다. 수집된 해당 모듈의 모든 node ID가
  1024자 미만인지 확인하는 회귀도 추가했다. skip이나 입력 축소로 숨기지 않는다.

## 검증 범위

```bash
QT_QPA_PLATFORM=offscreen uv run pytest -q scripts/qa_creator_dialogue.py scripts/qa_tracker_stability.py tests/test_creator_dialogue.py
```

- **80 passed (12.79초)**. 말풍선 원본 6개, 체력바 원본 15개와 제품 말풍선 회귀를
  함께 실행했다. 수정 전 실패 두 재현을 포함하며 원본 assertion을 바꾸지 않았다.
- 최종 전체 격리 회귀: `QT_QPA_PLATFORM=offscreen uv run pytest -q -m 'not windows_integration'`
  **860 passed, 4 deselected, 3 warnings (155.93초)**. 별도 Windows 통합 네 개는 실행 성공에
  합산하지 않았다. 경고는 기존 toast 테스트의 Qt 마우스 이벤트 생성자 폐기 예정 경고다.
  로컬 IPC/로그인 소켓을 허용했으며 실제 캡처/오디오/외부 통신은 테스트 경계로 대체했다.
- 별도 Linux 입력 상한 점검: 512항목(21,989 bytes)의 글꼴 검증 22.911ms,
  12항목·24,576선택지(124,021 bytes) 33.945ms. 한 번의 공유 환경 측정이며
  Windows UI 지연/장시간 자원 보장으로 확대 해석하지 않는다. 전체 조합을 전개하지 않는다.
- 렌더 명령 `QT_QPA_PLATFORM=offscreen uv run python -m scripts.render_creator_dialogue`는
  종료 0. 승인된 크기·꼬리·배치를 변경하지 않았다.

- 새 회귀는 정상 캐시 보존/갱신 신호 없음, 불량·정상 혼합의 저장과 재실행, 세 글꼴의
  실제 표시 가능성에 따른 캐시 채택/내장 복귀, 선택형 목록 보존과 유한 fallback,
  보이는 말풍선 교체 거절 시 만료/표시 기록/소리 처리, 다음 요청 복구를 검증한다.
- 공백뿐인 목록은 거절해 정상 캐시를 보존하고, 공백 선택지와 유효한 선택지가 함께 있는
  문장 틀은 표시 가능한 비공백 완성 문장을 유지하는 경계도 검증했다.
- 글꼴 테스트 초안에서는 60개 W가 모든 글꼴에서 세 줄이 된다고 잘못 가정했다.
  실제 monospace에서는 두 줄로 표시되어 통과해야 하므로 현재 글꼴의 실제 측정을
  기준으로 채택/복귀 양쪽을 검사하도록 테스트를 바로잡았다.
- 원래 체력바 QA도 함께 재실행한다. 실제 캡처/오디오/외부 HTTP는 통제 입력으로 대체하고
  기존 QThread 누수 assertion은 유지한다. Windows native 4개와 exe 빌드는 새 푸시 SHA로
  별도 확인한다. 이전 실패 SHA의 건너뛴 단계를 이번 수정의 성공으로 사용하지 않는다.
- 현재 개발 세션은 저장된 환경 설정과 달리 GitHub API 허용 도메인이 실행 환경에
  반영되지 않은 상태다. 실제 조회가 Forbidden이면 Windows 결과는 대기이며 QA 준비나
  릴리즈 가능으로 판단하지 않는다. 토큰 재발급/동일 실패본 수동 실행을 요구하지 않는다.
