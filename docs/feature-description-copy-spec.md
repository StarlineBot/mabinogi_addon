# 기능 설명의 단계 표기 및 중복 로그인 안내 정리

- 작성일: 2026-10-19
- 상태: 기획 확정. 기능 설명에서 베타 표기와 로그인 요구 문구를 제거한다. 설정의 Discord 로그인 구간에는 베타 기능을 먼저 사용할 수 있다는 짧은 안내만 둔다. 개발 및 독립 QA 전달용이며 구현 완료를 뜻하지 않는다.
- 소스 확인 기준: 원격 main `6c3ce3cce94e2f38c02e824854c28ee4817134aa`의 관련 UI와 첫 사용 안내 소스. 커밋 이력은 조회하지 않았다.
- 목적: 기능의 용도와 사용 조건을 설명하는 문구에서 개발 단계 표현을 분리한다.
- 후속 요청: 투아림 % 표시의 제작자 전용 알파 전환 및 다른 기능의 일반 공개 검토는 [기능 공개 단계 조정](feature-release-stage-review.md)을 따른다. 문구 제거와 실제 공개 정책 변경은 구별한다.

## 1. 적용 원칙

- 기능명, 기본 설명, 도움말 제목/본문, 툴팁, 기능 선택 항목, 버튼 및 관련 안내 팝업에서 `(베타)`, `BETA`, `Discord 베타` 등 공개 단계 표시를 제거한다.
- 개발 단계가 아니라 기능이 무엇을 하는지 설명한다. 각 기능의 기본 설명·도움말·툴팁에 `Discord 로그인 후 사용할 수 있습니다`를 반복해서 넣지 않는다.
- 시험관 아이콘 등 공개 단계를 나타내기 위한 장식도 해당 문구와 함께 제거한다. 기능 식별이나 일반 명령을 나타내는 아이콘까지 없애지는 않는다.
- 설정의 Discord 로그인 구간에는 `베타 기능을 먼저 사용해 볼 수 있습니다.` 정도의 짧은 안내만 둔다. 기능별 로그인 대상 목록이나 상세 접근 조건을 이 구간에 모아 나열하지 않는다.
- 개별 화면의 로그인 요구 문구와 배너는 제거한다. 접근 제한 자체를 없애는 변경과 구분한다.
- 알파/베타 접근 조건, 로그인 제한, 권한 플래그, 자동설정 대상, 실제 기능 동작은 변경하지 않는다.
- 공개 단계 표기를 뺐다는 이유로 기능이 정식 공개됐다고 판단하거나 접근 범위를 넓히지 않는다.
- 실제 제약과 주의사항은 유지한다. 예를 들어 지원 해상도 제한, 판독 실패 가능성, 등록 영역 조건이나 수집의 저장 범위를 베타 표기와 함께 삭제하지 않는다.

## 3. 로그인 안내의 위치와 유지할 동작

- 자동설정과 개별 기능의 로그인 조건은 서로 다를 수 있다. `베타`라는 표현을 빼더라도 모든 직접 지정이 로그인 없이 가능하다고 일반화하지 않는다.
- 설정의 Discord 로그인 구간은 베타 기능을 먼저 사용해 볼 수 있다는 짧은 목적 안내와 기존 로그인 조작을 유지한다. 상세 기능별 접근 조건을 한곳에 모으는 작업이 아니다.
- 도르카·체력바·단축바 등의 공개 정책이 바뀌더라도 개별 화면이나 설정에 로그인 필요 목록을 추가하지 않는다.
- 제작자 전용 알파가 일반 로그인만으로 공개되는 것처럼 쓰지 않는다. 짧은 베타 안내는 알파 공개 승인을 뜻하지 않는다.
- 상시 안내를 제거한 뒤 빈 배너 높이나 여백을 남기지 않는다. 로그인 상태별 기능 활성/실행 제한은 실제 공개 정책대로 유지한다.
- 개별 화면의 로그인 요구 문구를 지운 자리를 같은 요구의 팝업·툴팁으로 대체하지 않는다. 빈 팝업을 띄우거나, 로그인 여부와 무관한 캡처·저장 실패 등 실제 오류 안내까지 없애지 않는다. 권한 검사와 비활성 조건은 유지한다.
- 계정 연결·로그인 절차, 로그인 버튼 및 설정으로 이동하는 기존 명령은 삭제하지 않는다.
- 도르카·투아림에서는 표시 기능의 제한을 일반 투아림 알림까지 적용하는 것처럼 쓰지 않는다.

## 4. 헤일로 기획과의 관계

- [믿음의 균열 헤일로 알림](faith-rift-halo-alpha-spec.md)의 하단 구간 배치와 제작자 전용 알파 정책을 유지한다.
- 헤일로 기본 설명은 `게임의 남은 시간을 기준으로 다음 헤일로까지 표시하고, 발생 5초 전에 알립니다.`로 한다.
- 기본 설명과 제목에 알파/제작자 전용 배지를 붙이지 않는다. 기능 자체가 제작자에게만 노출되는 조건은 유지한다.
- 수집·진단 도구의 실제 용도와 저장 조건은 계속 설명한다. 내부 기능 단계 표기를 뺀다는 이유로 자료 수집 안내까지 숨기지 않는다.

## 5. 제외 범위

- 과거 릴리즈 노트, 과거 기획·QA 기록에 있는 당시의 베타 공개 설명은 소급 수정하지 않는다.
- 설정의 Discord 로그인 구간에 두는 `베타 기능을 먼저 사용해 볼 수 있습니다.`는 의도적으로 유지하는 공통 목적 안내다. 개별 기능의 베타 표기 제거 대상과 구별한다.
- `Feature.beta`, 로그인 검사, 설정 키와 저장 데이터 등 동작을 결정하는 내부 값은 제거하거나 이름을 바꾸지 않는다.
- 주석·개발 문서에서 공개 단계를 설명하는 용어는 그대로 둘 수 있다. 색상의 알파값 등 기술적으로 다른 의미인 단어도 대상이 아니다.
- 베타 기능의 정식 공개, 헤일로의 베타 승격, UI 재배치, 로그인 정책 변경은 이 문구 정리와 별도다.

## 6. Acceptance Criteria

1. 현재 기능명·설명·도움말·관련 툴팁과 팝업에 단순 공개 단계인 `(베타)`, `BETA`, `Discord 베타` 표기가 남지 않는다. 설정의 짧은 Discord 목적 안내와 과거 릴리즈 노트 등 5절 제외 범위는 실패로 세지 않는다.
2. 개별 기능 화면에 `Discord 로그인 후 사용할 수 있습니다` 등의 로그인 요구 안내와 배너가 없고, 설정에는 짧은 베타 선사용 안내만 있다. 기능별 로그인 필요 목록은 추가되지 않으며 설명 변경만으로 실제 접근 가능 대상이 바뀌지 않는다.
3. 첫 사용 안내의 기능명에서는 `(베타)`가 사라지지만 체크 가능 여부, 자동설정 실행 조건 및 직접 지정의 권한 조건은 유지된다.
4. 도르카·투아림 표시 기능의 안내 변경으로 일반 투아림 알림이 새로 로그인에 종속되지 않는다.
5. 헤일로는 제작자 외 사용자에게 노출·실행되지 않으며, 제작자에게 보이는 기본 설명은 공개용 기능 설명이다.
6. 짧아진 문구 때문에 도움말·로그인 이동·명령 버튼의 연결이 사라지거나 다른 기능으로 연결되지 않는다. 기본 크기와 배율에서 새 문구가 겹치거나 잘리지 않는다.
7. 기존 설정 파일과 내부 권한 값이 보존되고, 같은 계정/설정에서 문구 변경 전후 기능 실행 결과가 바뀌지 않는다.
8. 실제 제약·주의사항·저장 조건은 유지되고, 과거 릴리즈 노트는 수정되지 않는다.
9. 삭제한 로그인 요구를 반복 팝업이나 툴팁으로 다시 노출하지 않고, 빈 팝업·빈 배너 공간을 남기지 않는다. 실제 캡처·저장 실패 등 무관한 오류 안내는 유지된다.

이 문서 작성은 문구 수정 구현 또는 권한 회귀 검증 완료를 뜻하지 않는다.
