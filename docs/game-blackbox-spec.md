# 마비노기 블랙박스: 최근 영상 저장

- 작성일: 2026-10-21
- 상태: 사용자 동의에 따른 기본 동작 기획 확정. **0.16.0부터 디스코드 로그인 사용자(베타)에게 공개**(13절), 게임 화면만 저장, 1080p/60FPS, 사용 체크 기억, 게임 비활성 시 중단·복귀 시 재개, 실제 녹화 시간 기준 최근 구간 저장, 저장 위치 변경을 정의한다. 게임 소리는 가능한 경우 포함하는 것을 목표로 한다. 단축키·실게임 녹화·성능은 개발 중 검증하며, 구체적인 화면·기술 수치는 9절의 후속 확인 대상이다. 구현·QA 완료를 뜻하지 않는다.
- 목적: 사냥 중 실수와 전투 흐름을 나중에 복기하고, 전투 외 일상 플레이에서도 필요한 순간을 남긴다.
- 개발 전달: 아래 동작을 기준으로 단축키 선행 검증·녹화 기술 검토·목업·알파 개발을 진행한다. 실게임 미검증 항목과 세부 수치를 숨겨 확정하지 않는다.

## 1. 요청한 기본 방향

1. 앱이 항상 녹화하는 기능이 아니다. `블랙박스 사용` 체크로 명시적으로 활성화한다.
2. 활성화한 동안 최근 설정 시간만큼의 영상을 계속 유지한다. 오래된 임시 영상은 정리해 보관 범위가 무제한 증가하지 않게 한다.
3. 게임 안에서 저장 단축키를 누르면 그 시점을 끝으로 하는 과거 구간을 별도 영상 파일로 저장한다. 앱의 `최근 영상 저장` 버튼도 같은 저장 동작을 호출한다. 요청한 뒤부터 앞으로 N분을 녹화하는 기능이 아니다.
4. 저장한 영상은 임시 영상 정리와 분리해 보존한다. 사용 체크를 해제했다고 이미 저장한 영상을 삭제하지 않는다.
5. 저장 후에도 사용 체크가 켜져 있으면 최근 영상 유지를 계속한다. 저장 때문에 다음 장면의 녹화가 끊기는 것을 정상 동작으로 취급하지 않는다.
6. 최근 영상 유지 시간은 기본 5분이며 1~15분에서 변경 가능하다(0.16.0, 13절). 시간은 녹화한 영상 길이의 합으로 계산한다. Alt+Tab 등으로 보관을 중단한 시간은 포함하지 않는다.
7. 사용 구간에 `녹화 중에는 시스템 자원을 사용해요.` 정도로 짧게 안내한다. 매번 경고창을 띄우거나 정상 사용 중 반복 경고하지 않는다.
8. 보스 체력바 감지는 기본 녹화의 필수 조건이 아니다. 보스가 없거나 보스 패턴 알림을 사용하지 않아도 블랙박스를 사용할 수 있어야 한다.
9. 디스코드 로그인 사용자(베타)에게 공개한다(0.16.0, 이전 제작자 전용 알파). 미로그인 사용자에게는 진입점과 실행을 허용하지 않는다. 로그아웃 시 신규 녹화·저장 요청을 중단하되, 접수된 저장의 데이터 보호와 정리를 막지 않는다.
10. 녹화 대상은 등록한 마비노기 게임 화면이다. 기본 영상 품질은 1080p·60FPS다. 원본 종횡비·작은 창 처리·인코딩 품질 등의 세부 정책은 9절에서 확인한다.
11. **2026-10-23 사용자 결정: 원인 분석 우선, 소리 제외(선택 기능으로 추후 검토).** 블랙박스는 실수 원인 확인용이므로 화면만 저장한다. 0.13.1~0.13.6의 녹화·저장 실패가 모두 소리 경로에서 났다. 아래 소리 관련 항목은 추후 선택 기능 검토 때의 기준으로 남긴다. 게임 소리를 포함할 수 있는지 검토한다. 불가능한 환경에서 Discord·마이크·시스템 전체 소리를 임의 대체 녹음하지 않는다. 무음 진행·오류 안내의 세부 조작은 목업에서 확인한다.
12. `블랙박스 사용` 체크는 다른 기능의 사용 설정처럼 저장한다. 체크한 채 앱을 종료했다면 재실행해도 체크를 유지한다. 사용자가 직접 해제한 상태도 저장하며 다음 실행에서 임의로 켜지 않는다.

사용 설정과 현재 녹화 상태는 구분한다. 저장된 사용 설정이 켜져 있고 로그인 접근·게임 대상·녹화 조건이 충족되면 재실행 후 자동으로 보관을 시작한다. 게임이 없으면 실행 대기, 최소화·잠금 등에는 중단 상태이며 조건이 회복되면 대상을 확인한 뒤 재개한다. 게임 종료나 일시적인 캡처 실패 때문에 사용 체크 자체를 해제하지 않는다. 실제 준비·실패·중단을 정상 녹화 중으로 표시하지 않는다.

사용 설정을 기억하는 것은 과거 임시 영상을 복원하는 기능과 별개다. 앱 정상 종료 시 미저장 임시 영상은 정리하고, 재실행 후 새 구간은 새 녹화 실행으로 식별한다. 이전 앱 실행이나 다른 게임 실행의 영상을 무단으로 이어 붙이지 않는다. 저장 완료 영상은 유지한다. 비정상 종료 자료의 손상 확인·정리·복구 가능성은 개발 검증 대상이다.

게임 종료·사용 체크 해제 시에는 신규 녹화만 멈추고 이미 확보한 최근 구간은 앱을 닫기 전까지 저장 가능하게 유지한다. 체크가 꺼졌어도 해당 구간의 저장 버튼은 사용할 수 있다. 게임 재실행은 새 실행으로 구분하며, 이전 실행의 임시 구간을 새 실행과 자동 합치지 않는다. 저장 중 앱 종료를 요청하면 접수한 저장을 마친 뒤 정리·종료한다. 저장 실패나 작업 정체 시 성공으로 처리하지 않고 오류와 종료 선택을 안내한다.

이는 최근 구간을 순환 보관하는 기능이다. NVIDIA App 없이 마비노기 최근 영상을 남기는 것이 목표이며, NVIDIA의 모든 녹화·필터·방송 기능을 대체하는 기획은 아니다.

## 2. 포함·제외 범위

### 포함

- 사용 체크, 최근 보관 시간 설정, 현재 상태와 실제 확보 구간 확인.
- 게임 내 저장 단축키, 앱의 최근 영상 저장 버튼과 저장 성공·실패 안내.
- 기본 저장 위치는 Windows 동영상 폴더 아래 앱 전용 폴더다. 사용자가 위치를 변경할 수 있고, 현재 위치 확인·폴더 열기를 제공한다. 동영상 폴더 경로를 사용자 이름이나 C 드라이브 기준으로 하드코딩하지 않는다.
- 임시 영상과 저장한 영상의 분리, 제한된 임시 보관, 실패 시 데이터 보호.
- 게임·앱 종료, 중단·재개, 저장 중 상태 변화에 대한 안전한 처리.
- 기존 게임창 등록 기능과 연결한 녹화 대상 식별 검토.

### 이번 기본형에서 제외

- 자동 하이라이트 선정·자동 저장. (보스 체력바 기반 `전투 녹화`는 2026-10-23 결정으로 12절에서 진행)
- 전체 플레이를 하나의 장시간 파일로 계속 저장하는 일반 녹화 모드.
- 영상 편집·자르기 UI·타임라인·앱 내 플레이어·온라인 업로드·방송.
- NVIDIA App의 설치·실행·단축키 전달에 의존하는 구현.
- GPU 드라이버 프로필·전원·FPS 제한·CPU 배분·TCP 설정 변경.
- 게임 프로세스 주입·게임 메모리 접근·입력 자동화·보호 우회.

영상 캡처·인코딩을 위한 장치 사용과 그래픽 최적화 설정 변경은 다르다. 블랙박스를 켰다는 이유로 기존 최적화 기능이 함께 시작되지 않는다.

## 3. 최근 구간과 저장의 의미

- 설정 시간을 T, 저장 요청 시각을 S라 할 때 S까지 확보한 영상 중 실제 녹화 길이 기준 최근 T를 선택한다. 실제 시각 S−T 이후의 화면만 고르는 방식이 아니다. 내보내기가 끝난 시점으로 끝점을 미루지 않는다.
- 요청 후 들어오는 영상은 이번 저장 대상에 추가하지 않는다. 사용 체크가 켜져 있으면 다음 저장을 위한 보관은 계속한다.
- 기능을 켠 지 3분인 상태에서 최근 10분 저장을 요청하면 확보한 약 3분만 저장한다. 켜기 전 7분을 복원하거나 정지 화면으로 채우지 않는다.
- 정상적으로 확보한 구간이 없으면 저장을 시작하지 않고 이유를 알린다. 빈 파일을 성공 결과로 남기지 않는다.
- 의도적인 녹화 중단은 길이 계산에서 제외하고, 중단 전후의 유효한 게임 영상만 시간순으로 이어 저장한다. 중단 시간만큼 검은 화면·정지 화면·무음을 삽입하지 않는다. 이는 실제 시각이 연속된 영상이 아니라는 점을 설명·진단에서 구분한다.
- 예: 20:00~20:06에 6분 녹화, 20:06~20:11에 5분 중단, 20:11~20:15에 4분 녹화한 뒤 저장하면 약 10분 영상을 만든다. 중단한 5분은 재생 구간에 없다. 저장되는 마지막 영상은 요청 전에 확보한 최신 프레임이다.
- 보관 한도에서도 실제 유효 영상 길이를 합산한다. 중단 시간이 길다는 이유만으로 시간 기준 정리가 정상 구간을 오래된 것으로 삭제하지 않는다. 실제 용량 상한·오류·앱 종료 정책은 별도로 적용한다.
- 게임 소리가 포함되면 영상과 같은 구간을 선택·연결하고, 연결 후에도 입 모양·타격음 등 음성/영상의 시간 관계가 어긋나지 않아야 한다.
- 계획된 중단과 예상하지 못한 캡처·인코딩 누락은 구분한다. 누락 오류를 정상적인 Alt+Tab 중단으로 숨기지 않는다. 단, 게임이 60FPS보다 느리게 그려 생긴 250ms 이하의 짧은 프레임 공백은 직전 프레임을 반복해 실제 시간과 같은 속도로 재생되게 한다(2026-10-23 사용자 결정, 12절). 그보다 긴 공백은 채우지 않고 구간을 끊는다.
- 인코딩·파일 경계 때문에 요청 구간과 차이가 생길 수 있는지는 기술 검토로 확인한다. 시작·끝 허용 오차는 검토 결과를 제시하고 승인받으며, 고정밀도 확인 없이 정확히 T초라고 보증하지 않는다.
- 임시 영상 정리는 저장 요청이 참조하는 구간을 저장 도중 삭제해서는 안 된다.
- 완료 안내는 실제 파일 완성과 재생 가능한 구조의 검증 후 표시한다. 단축키·버튼 수신이나 작업 시작만으로 성공 처리하지 않는다.

## 4. 조작과 화면 구성안

이 절은 목업 준비용 권장 배치이며 최종 화면 승인이 아니다.

1. 제목 `블랙박스`와 설명 `최근 플레이 영상을 보관하고, 필요한 순간에 파일로 남겨요.`
2. `블랙박스 사용` 체크와 짧은 자원 사용 안내.
3. `최근 보관 시간`(기본 5분, 1~15분 스핀박스)과 품질·소리 설정. 미결정 항목을 숨은 기본값으로 적용하지 않는다.
4. 현재 상태와 실제 보관 구간. 예: `확보한 영상 3분 12초 / 설정 5분`.
5. `최근 영상 저장` 버튼, 저장 위치 변경과 `폴더 열기`.

- 게임 중 저장 단축키는 필수다. 버튼은 앱에서의 저장·진단을 위한 보조 동선이며 단축키 실패를 버튼만으로 대체해 기능 완료로 보고하지 않는다. 기본 키는 Ctrl+Alt+PrintScreen이며 `단축키 변경` 창에서 바꾼다(0.16.0 확정, 13.3절).
- 화면 배치와 별개로 사용 체크가 꺼져 있으면 신규 캡처·인코딩을 하지 않아야 한다.
- 녹화 중·대기·중단·오류·저장 중은 서로 구분한다. 기능 체크가 켜졌다는 이유만으로 실제 영상이 쌓이는 것처럼 표시하지 않는다.
- 저장 중 체크를 해제해도 이미 접수한 저장 요청을 임의 폐기하지 않는다. 신규 녹화를 중단하고 가능한 저장은 마친 뒤 결과를 알린다.

### 4.1 단축키 선행 검증

- 2026-10-22 사용자 지시: 기존 RegisterHotKey 실패 이력을 고려해 참고 앱의
  WH_KEYBOARD_LL 전용 메시지 스레드 방식을 우선 구현한다. API 기반 자체 구현이며,
  지정 조합·수식 키 상태만 관찰하고 키 로그·입력 소비·입력 생성·권한 상승·게임 주입은 하지 않는다.
  설정된 저장 키(현재 Ctrl+Alt+PrintScreen)와 제작자/게임 foreground/녹화 조건을 유지한다. 실게임 성공 승인은 아니다.

- 저장 단축키는 실제 마비노기에서의 수신을 선행 검증한다. 다른 앱에서 동작하거나 이벤트 관찰이 시작됐다는 사실만으로 지원 완료로 보고하지 않는다.
- Windows는 앱이 비활성이어도 단축키를 받을 수 있는 경로를 제공한다. 렘 부스터 `native/recorder-helper/main.cpp`는 전역 키 입력 관찰과 게임 포그라운드 판정을 사용한다. 구현 사례이지 우리 환경의 실게임 성공 증거가 아니다.
- 먼저 최소 검증 도구로 게임 포그라운드에서 단축키 수신·요청 시각·한 번 누를 때 한 번 발생·길게 누르기 중복 방지를 확인한다. 일반 앱에서 성공한 결과를 마비노기 성공으로 대신하지 않는다.
- 일반/관리자 권한 차이, 창 모드·전체 화면 모드, 게임 채팅·IME 입력 중, 다른 오버레이/녹화 도구의 키 충돌, Alt+Tab 전후와 재실행을 검증한다. 등록·관찰 시작 성공과 실제 키 수신은 구분한다.
- 단축키를 눌렀을 때 게임 포커스를 빼앗거나 본창을 강제로 띄우지 않는다. 저장을 위한 관찰만 하며 게임에 입력을 생성하거나 키를 대신 보내지 않는다.
- 충돌·미지원·수신 실패는 상태와 원인을 확인할 수 있어야 한다. 보호 우회·게임 프로세스 주입·커널 입력 드라이버를 도입하지 않는다.
- 선행 단축키 검증을 통과한 뒤 실제 최근 구간 저장까지 연결해 다시 확인한다. 단축키가 실게임에서 검증되지 않으면 핵심 조작 검증 대기이며, 완성된 블랙박스로 보고하지 않는다. 캡처·인코딩의 독립 기술 검토는 병행할 수 있다.
- Windows·마비노기에서 실제 실행하지 못한 검증은 미검증으로 남기고, 공식 문서·소스 검토와 실행 결과를 구분해 보고한다.

## 6. 부하·용량·프라이버시

- 목표는 게임을 방해하지 않는 최근 영상 보관이다. 체감 부하가 작을 수 있음을 인정하며, 부하가 0이 아니라는 이유만으로 사냥·보스전으로 사용을 제한하지 않는다.
- 하드웨어 영상 인코딩을 우선 검토한다. 지원하지 않으면 몰래 고부하 소프트웨어 인코딩으로 전환하지 않고 사용 가능 범위·제약을 알린다. 지원 GPU·Windows·화면 모드는 실제 검증 결과로 명시한다.
- 특정 캡처 API·라이브러리·프로세스 구조를 기획 단계의 정답으로 고정하지 않는다. 기존 검증된 캡처·인코딩 도구의 활용과 배포 라이선스를 검토한다.
- 임시 보관은 시간과 실제 용량을 제한할 수 있어야 한다. 메모리·디스크 중 어느 곳을 사용할지, 한도·여유 공간 기준은 기술 검토와 사용자 승인으로 정한다.
- 용량 상한 때문에 설정 시간보다 짧아졌다면 실제 확보 구간을 보여준다. 설정 5분이라는 이유로 5분 저장이 보장된 것처럼 표시하지 않는다.
- 임시 영상과 영구 저장 파일의 위치·정리 정책을 구분한다. 다른 기능·다른 앱의 파일은 정리 대상이 아니다.
- 앱 반응성과 기존 트래커·오버레이·소리 알림을 유지한다. 저장·정리·실패 처리 때문에 본창이 멈추지 않아야 한다.
- 체크 해제 후에는 신규 녹화 부하가 멈춰야 한다. 이미 요청한 내보내기·파일 정리는 진행 중임을 구분한다.
- 반복 활성화·중단·저장·게임 재실행에서 메모리·핸들·작업·파일 수가 무제한 증가하지 않아야 한다.
- 동일 게임 조건에서 블랙박스 꺼짐·보관 중·저장 중의 프레임타임과 CPU·GPU·메모리·디스크 사용을 확인한다. NVIDIA 동급 부하나 일정 FPS 손실 수치를 검증 없이 보증하지 않는다.
- 프레임 계측과 동시에 쓸 수 있는지 확인하되, 블랙박스를 켰다는 이유로 계측이나 CPU·TCP 최적화를 자동 실행하지 않는다. 비교 시 블랙박스 사용 조건도 함께 기록한다.
- 영상·음성을 서버로 전송하지 않는 로컬 저장을 권장한다. 소리 소스·애드온 오버레이 포함 여부를 사용자에게 정확히 설명해야 한다. 게임 소리만 분리하는 경로는 Windows 버전·지원 환경을 확인하며, 시스템 전체 소리 녹음으로 자동 대체하지 않는다.
- 기존 전투 보조 일시정지와 녹화 중단은 별개다. 해당 버튼에 블랙박스 중단·영상 폐기를 임의 연결하지 않는다.

## 7. 보스 감지 연동: 후속 후보

기본형 사용과 부하를 검증한 뒤 별도 선택 기능으로 검토한다. 이번 기획에서 구현을 확정하지 않는다.

- 일반 모드와 별개로 `보스전에서만 녹화`를 제공하는 방향이다. 보스 체력바 미등록·감지 실패가 일반 블랙박스 사용을 막지 않는다.
- 보스 패턴 알림의 판독 결과를 활용할 수 있는지 검토하되, 체력바 잠깐 가림·판독 실패·보스 처치와 전투 종료를 동일하게 처리하지 않는다.
- 감지가 끊겼다고 직전 영상을 바로 폐기하지 않아야 한다. 처치·실패 직후 복기용 저장이 가능한 흐름이 필요하다.
- 시작·종료 유예, 오탐·미탐, 보스 사망 후 저장 가능 시간은 후속 기획에서 결정한다.

## 8. Acceptance Criteria

아래는 기본 방향과 데이터 보호 기준이다. 미결정 사항에 의존하는 사례는 9절 승인 후 세부 기대값을 추가하며, 승인 전 임의의 동작으로 통과 처리하지 않는다.

1. 사용 체크가 꺼진 상태에서는 신규 녹화가 시작되지 않는다. 켠 후에도 대상·캡처 준비가 끝나야 실제 보관 중으로 표시된다.
2. 설정 시간이 5분이고 5분 이상 유효 영상이 확보됐을 때 저장 요청은 요청 시점까지 확보한 영상 중 실제 녹화 길이 기준 최근 5분을 대상으로 한다. 시작·끝은 승인한 허용 오차 범위에 맞는다.
3. 시작 3분 후 최근 5분 저장을 요청하면 확보한 약 3분만 저장하고, 존재하지 않는 과거 구간을 만들어 넣지 않는다.
4. 임시 영상 정리 후에도 이미 저장한 파일은 보존되고, 사용 체크 해제로 저장한 파일이 삭제되지 않는다.
5. 저장 중에도 보관은 계속된다. 요청 구간을 임시 정리가 지우지 않으며, 다음 저장을 위한 영상이 의도치 않게 누락되지 않는다.
6. 게임이 없거나 대상이 유효하지 않으면 임의로 바탕화면·다른 창을 대신 녹화하지 않는다. 영상이 없는 상태의 저장 요청은 이유와 함께 처리한다.
7. 보스 체력바가 없거나 보스 패턴 알림이 꺼져 있어도 일반 블랙박스의 유효 게임 녹화와 저장을 사용할 수 있다.
8. 사용 해제·게임 종료가 저장과 겹쳐도 파일을 성공으로 허위 표시하지 않는다. 완료·실패·남은 복구 가능 자료를 구분한다.
9. 저장 실패·공간 부족·폴더 권한 문제에서 기존 클립과 다른 앱 파일을 삭제하지 않고, 원인과 가능한 조치를 안내한다.
10. 반복 저장·중단·재개에서 경로 충돌·중복 녹화·무제한 파일·작업 증가가 없다. 저장한 파일은 지정한 재생 환경에서 열리고 정상적으로 재생된다.
11. 체크 해제 후 신규 녹화가 중단되며, 남아 있는 내보내기와 녹화 자체를 구분할 수 있다. 게임/앱 상태 전환과 음성·구간 처리도 승인된 정책과 일치한다.
12. NVIDIA App이 설치·실행되지 않아도 지원 환경에서 녹화·최근 구간 저장이 동작한다. GPU 설정 변경·최적화 실행·입력 자동화는 발생하지 않는다.
13. 블랙박스 꺼짐·보관 중·저장 중의 부하와 프레임 데이터를 구분해 보고한다. Windows에서 실행하지 않았다면 실게임 녹화·성능 검증 완료로 보고하지 않는다.
14. 미로그인 사용자는 녹화·저장에 접근할 수 없고, 디스코드 로그인 사용자(제작자 여부 무관)는 사용할 수 있다(0.16.0). 접근 해제가 데이터 보호·정리 경로를 막지 않는다.
15. 실제 마비노기 포그라운드에서 단축키 한 번으로 저장 요청이 한 번 접수되고 해당 시점의 구간이 저장된다. 채팅·권한·화면 모드·키 충돌 등 시험 조건과 제한을 기록한다. 본창에서만 동작하는 단축키는 통과가 아니다.
16. Alt+Tab·최소화·잠금·절전 중 신규 영상이 쌓이지 않으며, 다른 창이나 잠금 화면이 저장 영상에 섞이지 않는다. 복귀·재개 후 유효 게임 영상만 연결하고 의도적인 중단과 오류 누락을 구분한다.
17. 지원 환경에서 1080p·60FPS를 목표로 설정하고 실제 출력 해상도·프레임 누락 여부를 확인한다. 게임 자체가 낮은 FPS인 상황과 녹화기 성능 미달을 구분하며, 미달 상태를 정상 달성으로 보고하지 않는다.
18. 사용 체크를 켜고 앱을 종료·재실행하면 체크가 유지된다. 로그인 사용자이고 유효 게임이 녹화 가능한 상태라면 수동 재체크 없이 새 보관이 시작되며, 게임이 없으면 실행 대기로 표시된다. 사용자가 해제한 뒤 재실행하면 꺼진 상태가 유지되고 신규 녹화가 시작되지 않는다.
19. 사용 체크가 켜진 동안 게임 종료·최소화·잠금·캡처 실패가 발생해도 체크 자체는 바뀌지 않는다. 현재 대기·중단·오류 상태를 구분하고, 녹화 조건 회복 후 새 대상·구간을 확인해 재개한다. 재실행 후 체크 유지가 과거 임시 영상 복구로 잘못 표시되지 않는다.
20. 같은 게임 실행에서 6분 녹화·5분 Alt+Tab 중단·4분 녹화 후 최근 10분을 저장하면, 승인한 구간 오차 내 약 10분 파일로 재생된다. 중단한 5분의 바탕화면·검은 화면·정지 화면이 삽입되지 않는다. 소리가 있으면 각 구간의 영상과 동기화되어 이어진다.
21. 기본 보관 시간은 5분이고 사용자가 1~15분에서 변경할 수 있다(저장된 15분 초과 값은 15분으로). 기본 저장 폴더는 Windows 동영상 폴더 아래 전용 폴더이며, 변경한 위치를 사용하고 실패 시 기존 파일을 보호한다.
22. 게임 종료·사용 해제 후에도 앱 종료 전까지 확보한 구간을 저장할 수 있다. 앱을 정상 종료하면 사용 체크는 유지되고 미저장 임시 영상은 정리되며, 재실행 시 이전 영상이 새 실행과 자동 혼합되지 않는다. 저장 중 종료 요청은 완료·실패를 확인한 뒤 처리한다.

### 승인된 저장 방식과 남은 검증

2026-10-22 사용자 `1` 회신으로 다음 네 가지 추천안이 승인되었다. 최상위 탭 배치·문구와 후속 저장 내역·복구 화면도 사용자 승인됐으며 다시 묻지 않는다. 복구 화면은 우선 사용해보고 판단하는 승인으로 실제 피드백에 따라 조정한다. 화면 승인은 실제 자료 삭제 승인이 아니며 작업별 명시적 폐기 확인을 유지한다.

| 승인된 정책 | 구현과 한계 |
|---|---|
| 전용 디스크 임시 폴더 | 앱 실행별 새 전용 폴더와 소유 파일만 관리한다. 원본·내보내기·실패 자료의 합산 예산을 적용한다. 알파 초기 수치는 아래 승인 정책을 따른다 |
| 저장 1개 처리 + 1개 대기 | 요청 당시 끝점과 원본을 고정한다. 미인수 결과/실패 복구도 슬롯을 유지하며 무제한 요청을 받지 않는다 |
| 실패 자료 보존 후 재시도·명시적 폐기 | 검증된 partial 확정 재시도와 원본을 이용한 같은 계획 재인코딩을 구분한다. **앱 실행 중**(게임 종료 후 포함)에는 재시도할 수 있게 실패 파일을 명시적 정리 전까지 보존한다. 정리 실패와 저장 성공을 별도 표시한다. **앱 종료 시**에는 원본 버퍼가 사라져 재시도할 수 없으므로 실패·미완성 자료를 묻지 않고 자동 삭제하며(저장한 영상은 유지), 삭제 실패나 비정상 종료로 남은 자료는 종료를 막지 않고 다음 실행 시작 때 자동 정리한다(실패 시에만 안내). 2026-10-23 사용자 결정 |
| 정확한 구간을 위한 필요한 경계 재인코딩 | 키프레임 기준 단순 복사를 정확한 저장으로 취급하지 않는다. 합성 비교에서 3.5초 요청의 복사 결과는 4초였다. 현재 기술 probe는 전체를 재인코딩하며 경계만 재인코딩하는 최적화나 제품 성능을 보증하지 않는다 |

위 저장 방식 승인에 이어 2026-10-22 사용자가 다음 **제작자 알파 초기값 묶음**을 승인했다.
Windows 실측으로 조정할 초기값이며 실게임 품질/성능 보증이 아니다. 동일 값을 다시 묻지 않는다.

| 항목 | 승인된 알파 초기값 |
|---|---|
| 영상/소리 비트레이트 | H.264 12Mbps, AAC 192kbps. 기존1080p·60FPS·기본10분 유지 |
| 디스크 | 임시 전체8GiB, 최소 여유4GiB, 최근 버퍼2GiB. 원본/출력/실패 자료 합산 |
| 입력/RAM | 게임창 입력 최대3840×2160, 출력1080p 고정. 큰 창은 CPU 복사 **전 GPU에서** 1920×1080 안으로 비율 유지·짝수 크기로 축소(1080p 미만 창은 원본 유지·확대 없음). 녹화 중 창 크기 변경은 첫 출력 크기로 고정해 계속 축소. GPU 축소 실패 시 안내 후 중단(CPU 축소 대체 없음). CPU 이후 프레임1920×1080 이하·원시 큐512MiB 그대로. 너비/높이·바이트 수 모두 검사 (2026-10-23 사용자 결정, 0.11.1 2560×1440 즉시 중단 제보) |
| 구간 검증 | 시작·길이 오차 최대50ms. 초과 파일은 성공 처리하지 않고 복구 대상으로 보존 |
| 저장 키 | Ctrl+Alt+PrintScreen(0.11.4 사용자 요청, 이전 Ctrl+Alt+F10). 입력을 소비하지 않아 Windows Alt+PrtSc 창 캡처·PrtSc 캡처 도구가 함께 동작할 수 있음(실게임 확인 대상). 예약키/충돌 검증 별도 |
| 화면·소리 | 커서 제외. 소리는 저장하지 않음(2026-10-23 결정, 영상만) — 소리 분리 실패 시 중단 규칙은 해당 없음. 다른 앱 소리 대체 없음 |

제품 설정은 `packaging/blackbox-product.json`이다. 저장1개 처리+1개 대기는 유지한다.
12Mbps 영상+192kbps 오디오는10분 약914MB 예상이며 실제 크기/순간 bitrate는 달라질 수 있다.
내부 자원 한도는0.25초(15프레임) 구간/대기1개, 구간2MiB, 최대4096구간/16384임시항목,
출력2GiB, 처리시간1200초로 설정한다. 이 값은 게임 성능 합격 기준이나10분 확보 보장이 아니다.
큰 입력은 위 표의 GPU 축소만 사용한다. 전체화면 캡처로 바꾸거나 CPU 축소로 몰래 대체하지 않으며, 입력 상한 초과·GPU 축소 실패는 안내 후 중단한다. 저해상도 원본 확대는 하지 않는다. 단, 녹화 중 창이 첫 출력보다 작아지거나 종횡비가 바뀌면 고정된 출력 크기에 맞춰 늘이거나 비율이 달라질 수 있다(실측 확인 대상).
48kHz stereo 프로세스 오디오와 하드웨어 MF 지원 여부는 실제Windows에서 확인하며 실패 시 안내한다.
정상 종료는 기존 명세대로 저장 결과 확인 후 미저장 버퍼를 정리한다. 재시작 복구 manifest와
비정상 종료 복구 동선은 미구현이며 완전 복구를 보증하지 않는다.

현재 소스 어댑터는 **WGC CreateForWindow + FFmpeg 명시적 인코더 + WASAPI 프로세스 루프백**이다.
Windows API 코드는 `system/blackbox_capture.py`, `system/blackbox_events.py`와 `native/blackbox/`에 둔다.
캡처는 HWND/PID/생성 시각/foreground epoch를 확인하고 전체 화면으로 대체하지 않는다.
오디오는 해당 프로세스 트리만 포함하며 마이크/다른 앱의 시스템 소리로 대체하지 않는다.
FFmpeg는 명시적 절대 경로만 받아 실행한다. 패키징 수정 승인에 따라 frozen 앱은 검증한 번들 경로와 승인 제품정책을
사용한다. 앱 실행 시 다운로드하지 않는다. 공식FFmpeg8.1.3 최소 shared 구성의 정확한 소스/고지/빌드 설정을
함께 넣는다. 실제Windows 네이티브 빌드·frozen 실행 검증은 아직 완료되지 않았다.
Windows 자식 프로세스는 시작 전 Job에 들어간 codec host로 종료한다. FFmpeg `h264_mf`의 `hw_encoding=1`로 하드웨어만 요청한다. 직접 구현한 native MF 인코더는 없다.
이는 검증 가능한 소스 선택이며 Windows 실행 성공·GPU 지원·최종 바이너리 배포 채택이 아니다.
libx264는 작은 합성 검사의 외부 실행 파일에만 사용했다. 제품 바이너리의 빌드 옵션/라이선스와
하드웨어 인코더별 지원은 별도 확인하며 소프트웨어 인코더로 자동 전환하지 않는다.
프로파일에는 위 승인된 알파 수치를 사용한다. 하드웨어 MFT가 없으면 소프트웨어 인코더로 전환하지 않는다.
합성 A/V 검사에서 0.6초 영상의 AAC 스트림은 0.621333초였다. 후속 승인된 알파 오차는50ms이며 실제Windows A/V 경계 검증은 별도다.
현재 내보내기는 순차 concat 입력의 metadata로 유효 프레임을 선택하고 전체 재인코딩한다.
수천 입력을 명령줄/동시 디코더로 펼치지 않는다. 출력60FPS를 명시하고 오디오 경계를 재정렬한다.
경계만 최적화하는 경로와 1080p60 부하 보증은 없다.
Windows 로컬 빌드/실행의 다음 절차는 [Windows 검증](windows-validation.md#블랙박스-로컬-네이티브-검증-아직-미실행)에 둔다.

## 11. 기획 검수 후속 (2026-10-23 사용자 결정)

실사용 제보(단축키 체감상 무반응)와 코드 확인 결과를 바탕으로 사용자가 결정했다.
현재는 단축키 결과가 앱 탭 안의 글자로만 표시되고, 게임 화면 쪽 반응이 없다. 개발 전달용이며 구현 완료가 아니다. `시안값`은 개발 렌더로 확인한다.

### 11.1 게임 안 저장 반응: 오버레이 문구와 효과음

- 저장 단축키나 `최근 영상 저장` 요청의 결과를 게임 화면 위의 작은 오버레이 문구와 효과음으로 알린다.
  FPS·보스 패턴 알림처럼 기존 앱 오버레이 방식(항상 위, 클릭 통과, 포커스를 빼앗지 않음)을 쓴다.
- **단계별 문구** (시안)
  - 요청 접수: `영상 저장 중…`
  - 완료: `영상 저장 완료 · 3분 12초`
  - 거부·실패: `저장하지 못했어요 · 확보한 영상 없음` 또는 `… · 앱에서 확인해 주세요`처럼 짧은 이유를 붙인다.
  - 완료 표시는 3절의 기존 원칙을 따른다. 실제 파일 검증 후에만 표시한다.
- **효과음** (시안): 접수 즉시 짧은 효과음 1회(눌렀다는 확인), 실패에는 구분되는 효과음. 완료는 문구만 표시한다. 번들된 알림음에서 고르며 렌더·실사용으로 확인한다.
- **표시 시간·위치** (시안): 약 3초 뒤 사라진다. 기본 위치는 화면 상단 중앙이다. 다른 오버레이처럼 위치 이동과 잠금을 지원할지는 개발 렌더에서 확인한다.
- 이 오버레이는 블랙박스 녹화에 찍히지 않아야 한다. 게임 창만 캡처하므로 원칙상 포함되지 않지만 실게임에서 확인한다. 접근 범위는 블랙박스와 같다(0.16.0 로그인 사용자).
- 미정: 전투 보조 일시정지 중에도 표시할지. 권장안은 저장 확인이므로 일시정지와 무관하게 표시하는 것이다.

### 11.2 상단 상태 표시

- 상단 오른쪽 `● 전투 보조: 켜짐` 옆에 `블랙박스: 보관 중 3:12`, `일시정지`, `게임 대기`, `녹화 오류` 같은 상태를 짧게 표시한다. `블랙박스 사용`이 꺼져 있으면 숨긴다.
- 블랙박스를 쓸 수 있는 사용자(0.16.0 로그인 사용자)에게 표시한다.
- **0.16.0 눌러서 끄기**: 전투 보조 상태와 같은 모양(평평한 버튼·12px·`● ` + 상태 같은 색·밑줄 없음·손가락 커서).
  보관 중 초록 / 게임 대기·일시정지·전투 대기·전투 종료 대기 회색 / 녹화 오류 빨강. 누르면 오류가 아니면 `블랙박스 사용`을 끈다
  (탭 토글과 같은 경로·저장, 확인 창 없음 — 생산자만 멈추고 보관 영상·진행 중 저장은 유지). 오류면 블랙박스 탭으로 이동.
  툴팁: 켜짐 `누르면 블랙박스를 꺼요. 지금까지 보관한 영상은 앱을 닫기 전까지 저장할 수 있어요.` / 오류 `녹화 오류예요. 누르면 블랙박스 탭에서 내용을 볼 수 있어요.`
- 전투 보조 상태(`● 전투 보조: 켜짐/일시정지`)도 0.16.0부터 눌러서 일시정지·재개한다(별도 ❚❚/▶ 버튼 제거, 트레이 메뉴와 동기화).
- 최적화 상태 표시(제작자 전용)는 [최적화 명세 13.2](game-optimization-cpu-tcp-rss-alpha-spec.md#132-상단-상태-표시-제작자-전용)와 같은 줄에서 같은 기준을 따른다.
- 최적화와 함께 쓸 때의 코어 배치·실험 조건은 [최적화 명세 13.3](game-optimization-cpu-tcp-rss-alpha-spec.md#133-블랙박스와-함께-쓸-때-실험-조건)을 따른다.

### 11.3 사용 체크를 토글 버튼으로 (2026-10-23 사용자 결정)

- `블랙박스 사용` 체크박스를 기존 `위치 잠금` 버튼과 같은 토글 버튼(`LOCK_STYLE`)으로 바꾼다. 꺼짐은 `블랙박스 사용`(기본색), 켜짐은 `블랙박스 사용 중`(민트)이다.
  위치는 지금과 같고(최근 영상 보관 묶음 맨 위), 글자 크기만큼의 폭으로 왼쪽 정렬한다. 렌더 시안을 사용자가 승인했다.
- 동작은 그대로다. 켠 상태를 저장하고 재실행하면 자동으로 보관을 시작하며, 꺼도 저장한 영상은 지우지 않는다(1절 1·4·12항).

## 12. 녹화 범위·녹화 방식 (2026-10-23 사용자 결정)

### 12.1 뒤에 있어도 녹화, 짧은 공백 반복 채움 (0.14.0 구현)

- 게임 창이 뒤에 있어도(최소화 아님) 녹화한다. 최소화·잠금·절전·게임 종료 때만 중단한다. 저장 단축키는 게임 창이 앞에 있을 때만 받는다.
- 게임이 60FPS보다 느리게 그리면(무거운 장면 45~80FPS) 받은 프레임만 60FPS 칸에 넣어 영상이 빨리 재생됐다. 250ms 이하의 공백은
  직전 프레임을 반복해 칸을 채워 실제 시간과 같게 한다(일반 녹화 프로그램 방식). 250ms보다 긴 공백(로딩·멈춤)은 지금처럼 구간을 끊는다.
- 수용 기준 16·20의 'Alt+Tab 중 신규 영상이 쌓이지 않음'은 이 결정으로 '최소화·잠금·절전 중 쌓이지 않음'으로 바뀐다.

### 12.2 녹화 방식: 평소 녹화 / 전투 녹화 (렌더 확인 후 구현)

- 블랙박스 탭에 `녹화 방식`을 둔다. `전투 녹화`(기본, 2026-10-25 사용자 결정으로 앞에 배치)는 보스 체력바가 보이는 동안 녹화하고, `평소 녹화`는 12.1대로 상시 녹화한다. 저장값이 없는 사용자는 전투 녹화, 이미 고른 사용자는 그 값을 유지한다. 설정은 기억한다(`blackbox.recordMode` = `always` | `combat`).
- 신호는 보스 패턴 탭의 보스 체력바 존재 판정이다(등록 보스 식별 또는 영역 검증, 사라짐 1.8초 유예). 전투 녹화가 켜져 있으면 판정 소비자로 추가한다.
- 보스 체력바 영역이 등록되지 않았으면 전투 녹화를 고를 때 `보스 체력바 영역을 먼저 등록해 주세요`라고 안내하고 녹화하지 않는다. 평소 녹화로 몰래 대체하지 않는다.
- 보스바가 사라진 뒤 60초 더 녹화하고 일시정지한다(보스와 멀어짐·페이즈 전환·컷신·사망 대비, 2026-10-23 사용자 보정). 다시 보이면 이어서 녹화한다.
- 게임이 뒤에 있어 판정할 수 없는 동안은 직전 전투 상태를 유지하고, 앞에 오면 판정을 재개한다. 최소화·잠금·절전·게임 종료는 방식과 무관하게 중단한다.
- 보관 시간은 실제 녹화 길이 기준 그대로다(전투 녹화면 최근 전투 분량).
- 상태 문구: 전투 대기 `전투 대기 · 보스 체력바가 보이면 녹화해요`, 녹화 `보관 중 · 전투`, 유예 `보관 중 · 전투 종료 대기 n초`. 상단 상태도 같은 의미로 표시한다.

## 13. 공개·기본 5분·단축키 변경 (0.16.0, 2026-10-24 사용자 결정)

### 13.1 공개 범위

- 제작자 전용 알파 → **디스코드 로그인 사용자(베타)**. 판정은 다른 베타와 같은 로그인 여부(`feature_access.blackbox_available`).
- 미로그인: 탭·상단 상태·게임 화면 알림 없음. 로그아웃: 녹화 중지·탭 제거, 접수된 저장·실패 자료 보존, 종료 보호 경로 유지. 다시 로그인하면 탭이 돌아온다.
- 기본 꺼짐(저장된 사용 설정이 켜짐일 때만 켬). 베타 안내 문구는 넣지 않는다. 최적화·FPS 등 다른 제작자 기능은 그대로 제작자 전용.

### 13.2 보관 시간

- 기본 5분, 1~15분 스핀박스(`n 분`). 저장된 15분 초과 값은 15분으로 맞춘다.
  근거: 구간 수 상한 4096 × 0.25초 ≈ 17분이 실효 상한이라, 이전 자유 입력은 30을 넣어도 안내 없이 약 17분만 보관했다.

### 13.3 저장 단축키 변경

- 표시: `저장 단축키  Ctrl+Alt+PrintScreen(굵게)  [단축키 변경]` + 안내 `단축키는 게임 창이 앞에 있을 때만 저장해요. 키 입력은 게임에도 그대로 전달돼요.`
- 변경 창 `저장 단축키 변경`: 누른 조합을 큰 칸에 표시하고 판정(통과 초록 `사용할 수 있는 조합이에요.` / 실패 빨강, 저장 비활성),
  `[기본값(Ctrl+Alt+PrintScreen)] [취소] [저장]`, Esc는 취소.
- 규칙: Ctrl·Alt·Shift 중 하나 이상 + 수식 키가 아닌 키 하나. Win 키 조합 불가. 수식 키만 누른 상태는 미완성.
- 저장 위치: 설정 `blackbox.hotkeyModifiers/hotkeyVk`. 제품 프로필 값은 기본값. 규칙을 어긴 저장값은 기본값으로.
- 즉시 적용: 키보드 관찰 훅은 그대로 두고 감시 조합만 바꾼다(녹화·저장 진행 영향 없음). 변경 창이 떠 있는 동안 기존 조합 입력은 반응 없이 버린다.
- Windows에서 PrintScreen은 누름 없이 뗌만 오는 경우가 있어 변경 창은 뗌도 받고, 키 코드는 Windows 가상 키를 쓴다.

### 13.4 탭 정리

- 제목 옆 `블랙박스 사용법` 도움말. 알파 안내 문구 제거.
- 최근 영상 보관(사용 토글·자원 안내·녹화 방식·보관 시간·방식 설명) / 현재 상태(상태·확보 분·초·화면 정보·오류 줄) /
  영상 저장(저장 버튼·단축키·최근 저장 줄·저장 위치·폴더 버튼 한 줄·저장 내역·복구 안내).
- 상태·오류·최근 저장은 서로 다른 줄이라 갱신이 서로 덮어쓰지 않는다. 오류 줄은 한국어 요약 + `(자세한 내용: app.log)`, 원문은 app.log에만.
- 이전 `검증용 단축키 … 실게임 미검증`·`마지막 단축키 입력 …` 줄은 제거(반응은 게임 화면 알림으로 충분).

### 11.4 녹화 부하 관찰과 개선 방향 (2026-10-25, 사용자 실사용)

- 사용자 제보: CPU 쿨러 소리가 계속 들려 신경 쓰인다. 마을(약 400FPS)에서 작업 관리자 프로세스 탭: 마비노기 7.4%, **`ffmpeg.exe`(블랙박스 인코더) 6.0%**,
