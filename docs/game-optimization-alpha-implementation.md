# 안내·전투 제어와 제작자 최적화 알파 구현

2026-10-21 개발 기록. 후속 독립 QA 또는 Windows 실사용 통과 보고서가 아니다.
기준 main: `8b33d66`. 배포 준비 노트는 사용하지 않은 `v0.10.0`으로 묶었다.

## 적용한 승인

- [앱 안내·도움말·전투 제어](app-copy-help-combat-controls-spec.md)의 확정 문구,
  도움말 9종, 설명 14종, 자동 찾기 일반 공개와 전투 출력 일시정지를 적용했다.
- [CPU·TCP·RSS 알파](game-optimization-cpu-tcp-rss-alpha-spec.md)는 제작자가 명시적으로
  시작한다. 화면 배치는 사용자에게 실제 Qt 렌더로 보여주었으며, 기존 앱 톤에 맞추는 조건으로 승인받았다.
- [FPS 0단계](game-optimization-alpha-stage0-spec.md)는 설정의 제작자 도구에서 수동 시작한다.
  전투 보조 일시정지는 FPS 표시만 숨기며, 계측은 이어간다.
- 사용자는 기존 게임창 등록을 재사용하고 수집 도구를 앱에 포함하여 별도 실행 파일 선택 없이
  시작하는 방식에 동의했다. 처음 제안한 실행 파일 선택 UI는 제거했다.
- 강조색 개인화 백로그는 구현 범위에 포함하지 않았다.

## FPS 수집과 값의 의미

포함 도구는 Intel PresentMon **2.3.1 x64 콘솔**이며 MSI·서비스·드라이버·주입 오버레이는
포함하지 않는다. `assets/presentmon/`에 공식 실행 파일, MIT 라이선스, 원본 URL과 고정 SHA256이
있다. 실행 전 해시를 확인한다. PyInstaller의 기존 assets 묶음에 함께 포함한다.
공식 PE의 직접 import는 KERNEL32.dll이다. Windows에서의 실제 실행은 별도 검증 대상이다.

- 등록된 실제 게임창의 PID와 Windows 생성 시각으로 연결한다. 동일 PID의 재사용도 구분한다.
- `--process_id`, 고유한 `--session_name`, `--output_stdout`, `--v1_metrics`,
  `--qpc_time`, `--terminate_on_proc_exit`를 사용한다.
- 불필요한 GPU·입력·최종 화면 표시 추적과 콘솔 통계는 끈다. 게임 키·클릭·메모리는 읽지 않는다.
- 지표는 고정 v1 모드의 `QPCTime`에 기록된 **Present 제출 이벤트 빈도**다. 모니터에 실제 표시된 FPS,
  모니터 주사율, 입력 지연, 서버 통신 지연이 아니다.
- 대상별 최근 1초 범위의 `(이벤트 개수 - 1) / 첫·마지막 이벤트 시각 차이`를 사용한다.
  최초 유효 구간은 0.25초 이상이다. 2초 동안 새 프레임이 없으면 값 없음으로 처리한다.
  UI는 250ms마다 표시를 갱신하지만 Qt 타이머 횟수는 FPS 계산에 들어가지 않는다.
- 대상이 하나일 때만 자동 선택한다. 여러 swap chain을 합산하지 않으며 사용자가 대상을 선택한다.
- 대상당 최대 16,384개, 최대 8개 대상, 수신 데이터 최대 512KiB로 제한한다.
  한도 초과·형식 오류·다른 PID·시각 역전·중복·간격 불일치는 중단 또는 새 구간 대기로 처리한다.
- 자체 세션에 `ControlTraceW(QUERY)`를 호출해 ETW 이벤트·버퍼 손실을 확인한다.
  손실·수집기 경고는 정상 FPS로 숨기지 않고 중단한다. PresentMon 내부에서 이미 제외한
  개별 불완전 present의 상세 사유까지 CSV만으로 복원할 수는 없다.
- Alt+Tab·최소화·잠금·화면 크기 변경과 긴 UI 공백에서 구간을 초기화한다.
  복귀 전 대기열의 오래된 이벤트는 시각 경계로 거른다.
- 게임 종료 후 수집기를 정리하고 실행 대기로 돌아가며, 다음 게임은 새 식별·새 구간으로 연결한다.
  최적화 세션의 다음 게임 자동 적용 금지와 FPS의 게임 재연결 정책을 구분한다.
- 명시적 중단·접근 해제·앱 종료에서는 자신이 생성한 UUID 세션만 종료한다.
  다른 도구의 세션이나 프로세스를 종료하지 않는다. 정상 종료 요청 후 남은 자체 helper만 회수한다.
  자체 수집기는 Kill-on-close Job에 넣어 부모 종료 시 함께 정리하고, 소유 UUID를 같은 런타임
  폴더의 `fps-session.txt`에 저장해 다음 실행에서도 남은 자체 ETW 세션을 정리할 수 있게 했다.
  손상된 마커에서는 세션명을 추정하지 않으며 제작자 접근이 없어도 정리 버튼을 제공한다.

위 구간·갱신 수치는 초기 알파 구현값이다. 실게임 부하·전체화면·장시간 품질을 측정하여
검토해야 하며, 저부하 또는 실게임 FPS 정확도를 Windows 미실행 상태에서 확정하지 않는다.

## 최적화 및 복구

CPU 구조는 `GetLogicalProcessorInformationEx`의 실제 물리 코어·SMT 형제 관계를 사용한다.
단일 프로세서 그룹만 지원하며 알 수 없는 구조는 추정하지 않는다. 확인된 9800X3D 8C/16T는
기본 7+1, 다른 CPU는 기획의 P 코어 산식과 E 코어 백그라운드 배치를 사용한다.

일반 배경 프로세스는 같은 사용자·세션에서 선별하고, 앱·Windows·보호 프로세스와 보안·안티치트
경로/이름을 제외한다. 보호 수준을 확인하지 못하면 변경하지 않는다. Process Lasso Governor는
보호/관리자 프로세스의 상세 정보 조회와 별개인 프로세스 목록으로 감지한다. 실행 중이면 CPU·RSS를
보류하며 도중 시작된 경우 CPU를 원복하고 세션을 끝낸다. 우선순위는 변경하지 않는다.

네트워크는 사용자가 고른 물리 어댑터 GUID만 사용한다. TCP 두 DWORD와 전역 autotuning Normal은
항목별로 읽고 적용하며, 값 부재도 원본으로 저장한다. RSS가 선택한 배경 CPU를 정확하게 표현할 수
없으면 미지원으로 남기고 CPU 기능은 독립적으로 진행한다. 게임이 이미 실행 중이면 TCP·RSS는 미룬다.

복구 기록은 사용자 자산 폴더의 형제 디렉터리 `StarlineMabinogiAddonRuntime/recovery.json`에
저장한다. 설정 내보내기·가져오기에 포함하지 않는다. 개발 저장소에서도 Git에서 제외한다.

- 값 변경 전 원본을 임시 파일·fsync·원자적 교체로 저장한다. 기록 저장 실패 시 변경하지 않는다.
- CPU는 PID+생성 시각을 다시 확인한다. 이전 프로세스가 없으면 새 프로세스에 옛 원복값을 쓰지 않는다.
- 재시도에서도 원본을 덮지 않는다. 현재 값이 앱의 적용값/원래 값과 다르면 외부 변경으로 남긴다.
- 네트워크 재시작 대기도 기록한다. 값 원복 후 장치 재시작에 실패해도 다음 실행에서 대기가 남는다.
- 게임 종료·중단·접근 해제·앱 종료에서는 CPU를 원복한다. 다음 게임에는 자동 재적용하지 않는다.
- 네트워크 적용/원복은 연결 중단 확인을 거친다. 미루거나 실패하면 복구 기록을 유지하고 새 세션을 막는다.
- 손상된 기록은 추정값으로 원복하거나 삭제하지 않는다. 복구 경로는 제작자 접근이 없어도 제공한다.
- OS 명령은 단일 작업 스레드에서 수행한다. 종료는 작업 완료를 비동기로 기다린 후 정리한다.
- 앱 기본 실행의 `--uac-admin` 강제를 제거했다. 권한 부족 시 해당 작업을 실패로 안내하며
  자동 승격·서비스 설치·다른 앱 종료는 하지 않는다. 기존 자동실행 설정 자체는 바꾸지 않았다.

## 안내와 전투 출력

공통 일시정지는 저장하지 않는다. 기존 개별 설정과 위치·잠금·등록 영역은 그대로 유지한다.
보스·헤일로·투아림·사라짐 경고의 재생 중 소리를 멈추고 잠금 해제된 경고도 숨긴다.
헤일로 시계와 보스/투아림의 경과 관측은 계속하여 일시정지 중 지난 경고를 다시 재생하지 않는다.
파티 모집·계산기·설정의 일반 기능은 공통 일시정지 대상이 아니다.

일반 자동 찾기는 버튼뿐 아니라 캡처·후보·승인·저장 경로의 로그인 제한을 제거했다.
수집·진단·헤일로 실사용·투아림 %의 원래 제한은 유지한다. 로그아웃 중 후보 승인도 일반 경로에서
완료한다. 해당 기대값을 바꾼 기존 회귀는 수집 제한과 기존 설정 보존 검사를 그대로 유지한다.

기존 QA API 모델의 가짜 blocker HWND 22가 실제 offscreen 소유자 HWND와 충돌하는 문제는
소유자에 따라 별도 식별자를 선택하도록 수정했다. 가림 판정 assertion은 유지했다.

## 2026-10-21 독립 QA 후속 수정

[독립 QA](qa/최적화알파_전투제어_독립QA_20261021.md)에서 확인한 두 결함은
[수정·검증 기록](qa/최적화알파_QA수정검증_20261021.md)을 따른다. v1 콘솔의 실제 열은
`QPCTime`(원시 QPC 정수), `msBetweenPresents`(밀리초)이며 `TimeInSeconds`는 상대 시각이다.
이전의 `TimeInQPC,MsBetweenPresents`는 별도 출력 모드의 계약으로 구분해 유지한다.
네트워크는 원본 조회·복구 기록 저장 후 실제 쓰기, 각 재연결 직전에 게임/중단/접근 상태를
다시 검사한다. 중간에 보류된 배치는 원본·부분 변경·재연결 대기를 유지하고 CPU는 독립 처리한다.
이미 OS가 실행 중인 단일 명령을 원자적으로 취소하거나, 게임 실행과 시스템 변경을 하나의
트랜잭션으로 묶을 수 있다는 보장은 하지 않는다. 실제 Windows 전환·장치 검증은 여전히 필요하다.

## 네트워크 라이브 QA 후속 수정

장치 GUID의 중괄호/대소문자 표현 차이는 PowerShell 양쪽을 `[guid]`로 파싱해 비교한다.
장치 없음·중복은 안전하게 실패하며 기존 복구 기록은 유지한다. Windows 실패에는 단계/항목·분류·
반환 코드와 비식별 진단 지문을 남기며, TCP 자동 조정 결과는 다른 항목 실패와 별도로 안내한다.
[수정·개발 검증](qa/최적화네트워크_수정검증_20261021.md)에 재현 이관과 Windows 미검증 범위를 기록했다.
