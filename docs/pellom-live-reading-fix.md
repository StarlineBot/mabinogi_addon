# 펠롬 실화면 판독 수정

- 기준: [독립 QA](qa/펠롬_이름판독실패_독립QA_20261018.md)와 2026-10-18 원본 PNG 5장.
  개발 세션에서 재현/수정한 기록이며 후속 독립 QA 통과를 뜻하지 않는다.
- [Windows 폭 QA](qa/Windows_큰글꼴_줄바꿈수정_독립QA_20261018.md)는 이전 폭 assertion 9건의
  Windows 통과를 확인했다. exe 단계는 후속 데이터 푸시로 취소됐으므로 빌드 성공으로 재사용하지 않는다.

## 원인과 수정

### 이름

- 예전 펠롬 `name.png`는 28×15/흰 픽셀 30개, 새 화면은 32×17/186개다.
  단일 템플릿 점수 약 0.394가 기준 0.6에 못 미쳐, 정확한 기존 영역에서도 보스 추적이 시작되지 않았다.
- 원본 템플릿을 바꾸거나 임계값을 낮추지 않고 `name_live_20261018.png`를 추가했다.
  기본 identify와 실제 BossTab의 명시적 템플릿 주입 양쪽에서 변형 샘플을 사용한다.
  다른 보스와 회한 접두어의 긴 이름 우선 규칙 및 미등록 보스의 None은 유지한다.
- 같은 저장 영역에서 예전 47%, 새 87% 및 새 저HP 8%의 실제 `_tick`/stable HP/tracker를 확인한다.
  자동찾기를 반복하거나 영역을 바꿔 판독되는 것처럼 처리하지 않는다.

### 8.49% 숫자

- 회색 빈 바 배경 때문에 일반 저채도 마스크가 flooded되고, 기존 밝기 보조 경로도
  정답 8의 점수가 약 0.418로 0.45 미만이어서 거부됐다.
- 원본에서 추출한 밝기 전용 `bright_d8_0.png`를 추가한다. 일반 숫자 목록에는 섞지 않는다.
  정상 판독과 기존 저HP 보조 판독의 채택값은 먼저 반환한다. 두 경로가 실패하고 flooded인 경우만
  추가 밝기 샘플을 검사하며, 기존 강한 확신 기준 0.85 및 저HP 최대 20 조건을 적용한다.
  원본 새 8의 밝기 샘플 점수는 1.0이다. 전역 0.45나 이름 0.6 기준은 낮추지 않는다.
- read_percent와 read_percent_cached에 같은 경로를 연결한다. 기존 저HP ZIP에서 이미 읽히던 값이
  바뀌지 않는 대조 검사도 추가했다. 추가 샘플만 검사하므로 기존 모든 숫자를 다시 매칭하지 않는다.

### 별도 자동찾기 오선택

- 저HP에서 위쪽 바의 고채도 긴 씨앗이 사라지면 아래 에르그 바가 후보가 됐다.
  이름 글자와 숫자만 있는지 보던 검증에는 보조 바의 의미를 구분하는 처리가 없었다.
- `boss_auxiliary/erg.png`로 알려진 보조 바 이름을 높은 점수 0.8에서 배제한다.
  숫자 해석 전에 배제하며, 보스 이름 템플릿 등록 여부로 일반 보스를 제한하지 않는다.
- 알려진 보조 바를 찾으면 2단 UI의 위쪽 동반 바를 기존 높이 정규화 기준의 상대 간격
  34/1440로 후보에 추가한다. 이 후보도 실제 이름 글자와 HP 판독을 통과해야 하며,
  위가 비어 있으면 아래 에르그를 대신 성공 처리하지 않는다.
- 자동찾기는 사용자 실행 시 1회뿐이다. 실행 중 저장 영역을 계속 탐색/덮어쓰기하지 않고
  기존 후보 승인 절차와 오프셋/좌표 저장 정책을 유지한다. 다른 해상도/UI 배치 실기기는 별도 검증 범위다.

## 진단과 자산

- 원본 PNG는 재인코딩/교체하지 않았다. 파생 검출 템플릿 3개만 새로 추가한다.
  생성 근거와 절차는 `scripts/build_pellom_templates.py`다.
- 자동찾기 진단 ZIP에 에르그 배제 샘플과 밝기 숫자 샘플을 함께 저장하고, 재실행에도 이를 명시적으로 주입한다.
  현재 설치의 전역 샘플을 비워도 ZIP만으로 같은 상단 바를 재현하며 input.png 픽셀도 동일하다.
  새 필수 자산이 없거나 PNG가 저장되지 않은 경우 성공으로 가장하지 않는 기존 오류 분류를 유지한다.
- 원격 최신 v0.4.83 (`ec4a903`)은 이미 게시돼 있다. 미출시 UI/저장/폭/계산 변경과 이번 펠롬 수정은
  v0.4.84 노트로 분리했다. v0.4.83부터 이전 노트까지 게시본의 LF 정규화 SHA-256과 동일함을 확인한다.
  이는 노트 준비이며 태그 생성·푸시·릴리즈가 아니다.
