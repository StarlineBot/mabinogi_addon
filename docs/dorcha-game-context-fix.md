# 도르카 추적 영역의 게임 문맥 검증

- 날짜: 2026-10-17 (Asia/Seoul).
- 근거: `docs/qa/도르카_재탐색_수정후_독립QA_20261017.md`, `DORCHA-REACQUIRE-QA-03` (P2).
- 원본 QA 재현을 직접 실행해 **1 failed, 1 passed (2.06초)**를 확인했다.
  게임 이동 후 현재 값 0 대신 게임 밖 옛 숫자 15가 표시됐다. 옛 위치가 비면 정상 복구됐다.
- QA 원본·재현·스크린샷은 수정하지 않았다.

## 원인과 수정

숫자가 읽힌다는 사실만으로 추적이 성공했다고 판단했다. `_live_box`가 어느 HWND/PID/
창 경계에서 나온 좌표인지 유지하지 않아, 옛 영역이 게임 밖이 되어도 판독 성공 분기에서
재탐색을 건너뛰었다.

- 추적 좌표와 함께 `(HWND, PID, left, top, width, height)`를 메모리에 보관한다.
- 숫자 캡처 전 대상 동일성과 영역의 완전 포함을 확인하고, 캡처 뒤에도 대상 변경을 확인한다.
  위치/크기/창 식별이 달라지거나 조회가 실패하면 숫자를 즉시 미판독으로 바꾼다.
- 문맥을 잃은 상태에서는 저장된 옛 승인 영역으로 돌아가 숫자를 읽지 않는다. 새 게임 창
  재탐색과 현재 픽셀 검증이 끝날 때까지 `--/15`를 유지한다.
- 매 틱 무효화를 반복해 새 워커까지 취소하지 않는다. 기존 워커 하나/큐 없음/비용 대기는 유지한다.
- 새 재탐색 결과도 창 포함 여부와 최종 현재 게임 대상을 다시 확인한 뒤 적용한다.
- 수동 승인 영역을 새로 등록하면 기존 문맥을 해제한다. 저장 실패 시 기존 등록을 유지한다.
  게임 창 미등록 상태의 기존 수동 ROI 판독은 유지하며, 창 미확인 상태에서 전체 화면 자동 탐색은 하지 않는다.
- 정상 상태에서는 기존 HWND의 유효성/표시 상태/PID/실행파일을 재검증하고 현재 창 경계만 읽는다.
  동일 게임이면 EnumWindows를 다시 실행하지 않는다. 무효화되면 기존 등록 실행파일 탐색으로 돌아간다.
  캐시된 창의 소유 PID가 달라지거나 실행파일이 다를 때도 캐시를 신뢰하지 않는다.
- 재탐색 대기 중에는 사용하지 않을 옛 좌표를 위해 매 틱 창을 조회하지 않는다.
  전체 검출을 매 200ms 강제하거나 판독 임계값을 낮추지 않았다.
- 승인 영역·다른 설정·오버레이 배치는 저장하거나 이동하지 않는다. 색상/탭 순서/툴팁 요청은 계속 별도 대기다.
