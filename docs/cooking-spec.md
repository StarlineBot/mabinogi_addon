# 요리 계산기 명세 (확정 2026-11-19)

사용자 결정만 담은 최종 명세. 검토 과정·근거 자료는 [기획 초안](cooking-spec-draft.md)에 있다(이 문서와 다르면 이 문서가 우선).

## 1. 범위
- 편의기능 › 계산기(3단) 탭 줄에 `요리`. 요리를 찾고, 재료·비율·능력치를 보고, **비율 바를 게임 위에 띄워 손으로 요리창 바에 맞춘다.**
- 하지 않는 것: 요리창 자동 찾기(2단계, 7절), 실제 투입량 감지, 클릭·키 자동화(프로젝트 금지).

## 2. 데이터
- 원본은 **봇 저장소 `StarlineBot/discord_bot`의 `modules/cookings.js` 하나**. 앱 빌드 때 스크립트가 이 파일(공개 저장소 main)을 읽어 `src/mabinogi_addon/assets/cooking/cookings.json`을 만든다 → 봇 데이터를 고치면 **다음 앱 배포에 자동 반영**. 앱 실행 중 네트워크 없음.
- 넣는 요리: `isCatering === true`이고 **조리방법(`localCookingType`)과 레시피(`localRecipe`)가 있는 것**(387개, 11-19 기준). 조리방법이 빈 79개(레시피 없는 이벤트·NPC·상점 품목)는 넣지 않는다.
- 필드: 이름(`localName`), 조리방법, 레시피(재료 이름 + 비율 숫자, 원문 순서), 능력치(`status`). 썸네일(외부 사이트)은 쓰지 않는다.
- 생성 스크립트는 형식이 틀린 항목을 빼고 개수를 출력, 테스트가 JSON 형식·개수 하한(380)을 확인.

## 3. 화면
```
[검색 종류 ▼] [검색어                              ] [N개 요리]
[카테고리 16] [요리 목록(이름만)] [상세                      ]
```
- 카테고리 순서 고정: 혼합·굽기·삶기·반죽·끓이기·면 만들기·튀기기·볶기·파스타 만들기·잼 만들기·파이 만들기·찌기·피자 만들기·발효·수비드·저미기.
- 요리 목록: 이름순, 이름만. 첫 화면은 아무것도 선택하지 않음(상세는 '요리를 골라 주세요'). 개수 제한 없음.
- **검색 = 필터**: 검색 종류 `요리 이름`·`재료`·`능력치`(능력치는 데이터에 있는 이름 목록에서 고름). 검색해도 화면 모양은 같다.
  - 카테고리 옆 `(맞는 요리 수)`, 0개 카테고리는 회색·선택 불가.
  - 요리 목록은 그대로 이름만·이름순, 안 맞는 요리는 회색·선택 불가. 수치·조리방법 덧붙임 없음.
  - 상세에서 검색한 재료 줄 / 능력치 줄 강조.
  - 검색어를 지우면 숫자·회색만 사라지고 선택은 그대로. 지금 요리가 검색에 안 맞게 되면 선택은 두고 목록에서 회색.
  - 이름·재료 검색은 공백 무시·부분 일치.
- **상세**: 이름, 조리방법, 재료(재료 색 점 + 이름 + 원문 숫자), 비율(5절 그림), 능력치, `게임 위에 이 바 띄우기` 버튼.
- **재료 요리로 이동**: 재료 이름이 (공백 무시) 넣은 요리와 같으면 `▸` + 강조색, 누르면 그 요리로 이동(카테고리·목록 선택·상세·게임 위 바가 그 요리로). 상세 맨 위 `← <바로 앞 요리>`로 **들어간 순서를 거꾸로** 되돌아감(여러 단계, 되돌아가면 카테고리·목록 선택도 복원). 목록에서 직접 고르거나 검색으로 선택이 바뀌면 되돌아가기 기록 지움.
- 화면 규칙은 `docs/ui-rules.md`. 렌더 확인 후 사용자 피드백(CLAUDE.md UI 개발).

## 4. 비율 계산
- 원문 숫자는 상대 비율: 각 값 ÷ 합계. 예 50:20:40 → 45.45%·18.18%·36.36%, 경계 45.45%·63.64%. 원문 순서 유지.

## 5. 상세의 비율 그림
- 게임 기본 인터페이스(하늘 유리) 요리창 그림 `docs/assets/cooking-20261119/cook_ui_reference.png`를 앱 자산으로 넣어 가운데 표시(요리창 패널 부분만).
- 그림 안 게이지 바(기준 이미지 좌표: 안쪽 x 39~523, y 111~124)를 4절 비율로 재료 색 채움, 재료 경계마다 바 아래부터 버튼 줄 위까지 흰 점선. 재료 목록 색 점과 같은 색.
- 시안: `docs/assets/cooking-20261119/detail_gauge_mock.png`.

## 6. 게임 위 비율 바(첫 기능)
- `게임 위에 이 바 띄우기`로 켬/끔. 표시 내용은 **게이지 바 + 경계 점선만**(요리창 그림·버튼 없음). 상세의 요리가 바뀌면 오버레이도 그 요리로.
- **첫 크기: 바 245×10px**(테두리 포함, 실게임 측정 — 1920 창 두 크기·4K 추정 모두 같음), 점선은 바 위로 바 높이의 약 4배.
- 위치는 사용자가 끌어서 게임 요리창 바에 맞춤, 휠로 크기, 잠그면 클릭 통과 — 기존 오버레이(격자 맞춤·잠금·드래그)와 같은 조작. 위치·배율 저장(다음 실행에도 그 자리).
- 첫 위치: 화면 가운데 아래쪽(요리창이 뜨는 가운데 근처), 화면 밖이면 안으로.
- 게임이 꺼지거나 비활성이면 다른 오버레이와 같은 규칙으로 숨김. 전투 보조 일시정지와 무관(편의기능).

## 7. 2단계(이번 범위 아님): 요리창 자동 찾기
- 11-19 시험: 회색 스킨 1920 화면 2장에서 요리창(농도 조절 줄 + 바) 모양 대조로 정확한 자리를 찾음(일치 0.92·0.89, 요리창 없는 다른 스크린샷 최고 0.42). 분홍 화면은 1024로 줄여 저장된 것이라 판정 불가, 파란 기준 이미지는 0.61.
- 요리창이 뜨면 화면 위·아래가 어두워짐(사용자 관찰) → 찾기 시작 신호 후보.
- 필요: 인터페이스 색별 **원본 크기** 요리창 스크린샷. 그 뒤 자동 찾기 v2에 붙일지 기획.

## 8. 테스트
- 데이터: 생성 JSON 형식·개수, 79개 제외, 비율 합계 정규화(4절 예시).
- 검색 필터: 세 종류 × 카테고리 개수·회색·선택 유지, 공백 무시.
- 재료 이동·되돌아가기: 3단계 들어갔다 순서대로 복원, 직접 선택 시 기록 삭제, 순환(같은 요리 재등장) 없음.
- 상세 그림·오버레이 렌더(오프스크린), 오버레이 위치·배율 저장·복원, 잠금 클릭 통과.
- 사용자에게 보이는 새 기능 → 릴리즈 노트 다음 버전 헤드라인.
