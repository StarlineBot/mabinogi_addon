    - **제목 바로 아래에 `추천 채널` 상자**를 둔다(옅은 정상색 바탕·테두리).
      - 측정 전: `한 번 측정을 누르면 지금 가장 빠른 채널을 알려줘요`
      - 측정 중: `측정이 끝나면 알려줘요`

      - **추천 기준 = 가장 빠름 기준과 같다**: 중앙값, 실패 제외, 0.1ms 동점이면 번호가 낮은 채널을 크게 보여준다.
        - 사용자 결정으로 '추천' 단어를 쓴다. 근거는 잰 연결 시간뿐이며, 혼잡도나 게임 핑으로 추천하지 않는다(상시 안내 유지).
  - **사용자 결정 3차(2026-11-03) — `final-measuring.png`, `final-result.png`. 2·3절과 5절보다 우선한다.**
    - **측정 방식(경매장 시세 조회처럼)**
      - 탭을 열면 바로 한 번 측정한다.

      - 다른 탭으로 가거나, 앱이 최소화·트레이로 숨거나, 전투 보조를 일시정지하면 멈춘다. 다시 보면 바로 한 번 잰다.
      - 3절의 '처음 열어도 자동으로 접속하지 않음'과 `자동 측정` 스위치는 **없앤다**.
    - **위 줄**
      - 다른 시세 화면과 같은 **새로고침 아이콘 버튼**(`calculator_sidebar.refresh_button`, 툴팁 `지금 다시 측정`)
      - 상태: `● 측정 중 · 9 / 21` 또는 `마지막 측정 오후 9:41:08 · 다음 측정까지 24초`
    - 상시 안내: `TCP 연결 시간이며, 게임 안 핑이나 채널 혼잡도와 다를 수 있어요. 이 화면을 보는 동안 60초마다 다시 재요.`

    - 5절 1항(반복 접속) 정리: 화면을 볼 때만 60초 간격이라 분당 약 21번 이하. **공개 범위(제작자만 / 모두)는 결정 대기.**
    - **추정 표시 `*`와 그 안내 줄도 없앤다**(사용자: 필요하면 직접 잼). 관찰/추정 구분은 주소 데이터 파일에만 남겨 목록 관리용으로 쓴다.

## 1. 주소 (2026-11-03 사용자 직접 확인)

모든 주소는 `211.218.233.x`이다. 각 줄에서 채널과 포트는 적힌 순서대로 대응한다.

| 채널 | IP 끝자리 | 포트 |
|---|---|---|
| 1·2·3 | .31 | 11020 / 11021 / 11023 |
| 4·5·6 | .32 | 11020 / 11021 / 11023 |
| 7·8·9 | .33 | 11020 / 11021 / 11023 |
| 10·12·13 | .34 | 11020 / 11021 / 11023 |
| 14·15·16 | .39 | 11020 / 11021 / 11023 |
| 17·18·19 | .40 | 11020 / 11021 / 11023 |
| 20·21·22 | .41 | 11020 / 11021 / 11023 |

- **직접 관찰**: 1·2·4·7·8·9·10·12·13·14·15·16·17·20·21·22 (2채널은 2026-11-03 추가 확인: `211.218.233.31:11021`)
- **패턴 추정**: 3·5·6·18·19. 사용자 PC에서 TCP 연결은 성공했다. 하지만 연결 성공은 포트가 응답한다는 뜻일 뿐, **채널 번호와의 대응을 증명하지 않는다.**
- `.35~.38:11020`도 연결되지만 정체를 모른다. 목록에 넣지 않는다.
- IP 배정은 연속이 아니다(.34 다음 .39). 점검·증설 뒤에도 유지된다는 보장이 없다.
- 23채널은 없고 주소도 모른다. **새 채널을 추정해서 자동 등록하지 않는다.** 근거를 확보해 목록을 고친다.
- **목록 관리**
  - 주소 목록은 코드와 분리한 데이터 파일로 둔다. 항목: 채널·IP·포트·`관찰|추정`·확인일
  - 앱 업데이트로만 바꾼다. 원격으로 받아오지 않는다.
  - 주소가 바뀌면 그 채널의 이전 측정 이력을 지운다.

## 2. 화면 (최적화 › `하프 채널 연결`, 2단 네 번째 탭)

- **머리**: 제목 `하프 채널 연결` + 회색 요약 `내 PC에서 하프 서버 채널별 접속 주소까지 TCP 연결에 걸리는 시간을 재요.`
- **위 줄**: `한 번 측정` 버튼(측정 중에는 `측정 중지`), 상태(`● 아직 측정 안 함` / `● 측정 중 · 9 / 21` / `마지막 측정 오후 9:41:08`). 오른쪽에 `자동 측정` 스위치와 켰을 때 `다음 측정까지 24초`.
- **상시 안내**(회색): `TCP 연결 시간이며, 게임 안 핑이나 채널 혼잡도와 다를 수 있어요.`
  - **추천·쾌적 같은 판정은 하지 않는다.**
- **표**: 21줄. 1~22에서 11채널을 뺀 번호순으로 고정한다.
  - 열: `채널 | 최근 | 중앙값(최근 5회) | 상태 | 성공`
  - 추정 주소 채널은 `2채널 *`처럼 표시하고, 표 아래 회색으로 `* 표시는 다른 채널의 주소 규칙으로 추정한 주소예요. 채널을 고르면 주소와 근거를 보여줘요.`
  - **상태 글자와 색**: `연결됨`(정상 색), `시간 초과`(주의 색), `연결 거부`(위험 색), `측정 중`·`대기`·`측정 전`(보조 색).
    - 실패를 `999ms`나 `서버 점검`으로 쓰지 않는다.
    - 실패한 회차의 `최근` 칸에는 이유를 쓴다(`시간 초과(2초)`, `연결 거부`). 중앙값은 성공값만으로 계산한다.
  - `성공`은 `성공 회수 / 시도 회수`이다. **취소는 시도에 넣지 않는다.**
- **채널을 고르면 표 아래에 주소 상자**: `211.218.233.31:11021`과 근거를 보여준다.
  - 예: `패턴 추정 — 1채널(직접 확인, 2026-11-03)과 같은 주소의 다음 포트예요. 이 주소가 응답한다고 2채널이라는 뜻은 아니에요.`
  - 직접 관찰 채널은 `직접 확인 · 2026-11-03`이라고 쓴다.

## 3. 측정 동작 (제안값 — 실측으로 확정)

- **처음 열어도 자동으로 접속하지 않는다.** `한 번 측정`을 눌러야 시작한다.
- `자동 측정`은 기본 꺼짐이다. 켜면 한 회차가 끝나고 **30초 뒤** 다음 회차를 시작한다(제안).
- **회차 진행**
  - 채널마다 TCP 연결을 1회 맺는다(연결만 하고 바로 닫음. 데이터는 보내지 않음).
  - 제한 시간 **2초**, 동시 연결 **최대 2개**(제안).
  - 성공·실패·취소 모두 소켓을 정리한다. 회차가 겹치지 않게 한다.
- **화면을 떠나거나 전투 보조를 일시정지**하면 측정을 멈춘다. 취소는 실패 통계에 넣지 않는다.
- **실패해도 다른 주소 대역을 찾아보지 않는다.**
- **구현**
  - 화면 스레드를 막지 않는다(작업 스레드나 비동기 소켓).
  - 시간은 `perf_counter`로 잰다.
  - 일반 소켓이라 OS 의존 코드가 아니며, 맥에서 로컬 테스트 서버로 시험할 수 있다.

## 4. 측정값 해석

- TCP 연결 시간은 대략 **왕복 한 번(RTT)**이다. 게임 안 핑, 채널 혼잡도와는 다르다.
- 사용자 PC에서 1채널 주소에 연결하는 데 약 2ms가 나온 사례가 있다(1회 측정).
- 클라우드에서는 같은 추정 주소들이 연결 거부됐다. 실행 환경이나 중간 네트워크 영향일 수 있어 서버 이상으로 보지 않는다. 화면은 사용자 PC 기준이다.
- **연결 실패만으로 채널이 없거나 점검 중이라고 판단하지 않는다.**

## 5. 기획 세션 검토 의견 (결정 대기)

1. **게임 서버에 반복 접속하는 동작의 성격**
   - 앱 규칙(화면 읽기만, 입력 자동화·메모리 읽기 금지)에 직접 걸리지는 않는다.
   - 다만 게임 클라이언트가 아닌 프로그램이 **게임 서버 포트에 연결만 하고 끊는 동작을 반복**하는 것은 새로운 종류이다.
   - 자동 측정을 켜면 30초마다 21번(분당 약 40번) 연결한다. 서버나 보안 장비에서 이상 접속으로 보일 가능성을 배제할 수 없다.
   - 제안:
     - 자동 측정 기본 꺼짐(기획대로)
     - 간격을 더 길게(예: 60초 이상)
     - 자동 측정은 화면을 보고 있을 때만(기획대로)
     - 공개 범위(제작자만 / 모두)를 먼저 정함
2. **`?` 도움말**: 목업에는 넣었지만, 화면 규칙상 도움말은 어려운 화면에만 둔다. 상시 안내 한 줄로 충분하면 뺀다.
3. **주소가 바뀌었을 때**: 업데이트 전까지는 실패로만 보인다. 상태 줄에 `주소 확인일 2026-11-03`을 작게 보여줄지 정한다.

## 6. 개발 전 확인·테스트

- **렌더**: 첫 화면, 측정 중, 성공·실패 혼합, 추정 주소 상세, 자동 측정 상태를 기존 앱 틀에서 렌더해 확인받는다(위 목업이 1차).
- **테스트**: 가짜 연결과 로컬 테스트 서버로 다음을 검증한다.
  - 성공, 거부, 시간 초과, 취소
  - 회차 중복
  - 소켓 정리
  - 화면 이탈과 일시정지 때 중단
  - 중앙값(성공만)
  - 주소 변경 시 이력 초기화
- **Windows 실기**: 실제 연결 시간, 반복 측정 편차, 게임 중 CPU·네트워크 영향을 따로 확인한다.
