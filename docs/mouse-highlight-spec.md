# 마우스 하이라이트 베타 기능 명세

- 작성일: 2026-10-16
- 상태: 기획 확정. 기본값, 표시 조건 및 설정 저장/복원 정책 승인 완료.
- 대상: Windows 마비노기 사용자를 위한 원형 마우스 위치 강조 기능.
- 용도: 개발 및 독립 QA에 독립적으로 전달할 최종 명세.
- 이 문서 작성은 앱 구현, Windows 실게임 검증, 운영사의 사용 허가를 뜻하지 않는다.

## 1. 목적

게임 UI와 전투 이펙트 사이에서 마우스 위치를 쉽게 찾도록, 기존 커서를 유지한 채
마우스 위치를 따라 움직이는 원형 하이라이트를 추가한다.

커서 교체 프로그램을 재현하는 것이 아니라 간단한 시인성 보조 기능을 제공한다.
게임 조작, 클릭 위치, 원래 커서의 모양과 크기 및 Windows 커서 설정은 변경하지 않는다.

## 2. 기능 범위

### 2.1 원형 하이라이트

- 마우스 위치를 따라 움직이는, 내부가 채워진 원을 표시한다.
- 사용자가 원 크기, 내부 색상, 내부 투명도를 조절한다.
- 내부 투명도를 조절하여 불투명한 원, 반투명한 원, 내부가 완전히 투명한 원을 만들 수 있다.
- 원은 커서를 대체하지 않는다. 클릭을 가로채거나 게임 포커스를 가져가지 않는다.
- 실제 커서 크기 변경은 제외한다. Windows에서 사용자가 변경한 커서 크기도 앱이 다시 변경하지 않는다.

### 2.2 테두리

- 테두리는 기본적으로 없다. 테두리를 선택하지 않으면 내부만 채워진 기본 원이다.
- 테두리를 켜면 선 종류, 선 굵기 및 선 색상을 선택할 수 있다.
- 선 종류에는 실선과 점선을 제공한다.
- 굵은 실선과 굵은 점선을 모두 만들 수 있도록, 선 종류와 굵기를 독립적으로 조절한다.
- 테두리 색상은 기본 검은색이며 사용자가 변경할 수 있다.
- 내부 투명도와 테두리 표시는 분리한다. 내부가 완전히 투명해도 테두리를 표시할 수 있다.
- 별도 테두리 투명도 조절은 현재 요청 범위에 포함하지 않는다.

### 2.3 설정 미리보기

- 앱 설정 화면 안의 고정된 미리보기 영역에 마우스 아이콘과 하이라이트 원을 겹쳐 표시한다.
- 아이콘은 예시용 고정 아이콘이다. 현재 Windows 커서나 게임 커서 이미지를 가져오지 않는다.
- 실제 마우스를 움직여도 미리보기 속 아이콘과 원은 따라 움직이지 않는다.
- 원 크기, 내부 색상, 내부 투명도, 테두리 사용 여부, 종류, 굵기 및 색상 변경을 즉시 반영한다.
- 게임 실행이나 화면 영역 지정 없이도 설정한 모양을 확인할 수 있다.
- 게임이 없을 때 미리보기가 가능하다는 것은, 게임 밖 실제 마우스에 효과를 표시한다는 뜻이 아니다.

### 2.4 제외 범위

- 원래 게임 커서 교체, 확대, 숨김 및 커서 윤곽을 따라 붙이는 테두리.
- 점멸, 맥동, 회전, 이동 잔상 및 클릭 파동 등 추가 효과.
- 키보드 및 마우스 입력 자동 생성, 게임 메모리 접근, 게임 파일 변경 및 보안 우회.
- 마우스 전용 단축키, 프리셋, 사용자 이미지 업로드.
- 이 기능을 위한 게임 UI 자동찾기, 앵커 등록 또는 캡처 영역 지정.
- YoloMouse 등 외부 프로그램의 설정 변경이나 자동 연동.

## 3. 기본값 및 동작 정책

### 3.1 설정 위치와 기본값

| 항목 | 동작 및 기본값 |
|---|---|
| 설정 위치 | 편의기능 > 마우스 하이라이트. 기존 Discord 로그인 기반 베타 접근 조건 적용 |
| 최초 사용 | 기능 사용 체크는 꺼짐. 사용자가 켜야 실제 하이라이트 표시 |
| 원 크기 | 직경으로 조절. 범위 16~160, 초기 48. 단위는 논리 픽셀로 정의하여 화면 배율을 반영 |
| 내부 색상 | 초기 노란색 `#FFFF00` |
| 내부 투명도 | 0~100%. 초기 60%. 0%는 불투명, 100%는 완전히 투명 |
| 테두리 | 초기 없음. 켜면 초기 종류는 실선 |
| 테두리 굵기 | 1~8 논리 픽셀, 초기 2 |
| 테두리 색상 | 검은색 `#000000` |
| 테두리 투명도 | 별도 설정 없이 불투명. 내부 투명도의 영향을 받지 않음 |
| 크기의 기준 | 직경은 테두리를 포함한 전체 바깥 지름. 선은 원 안쪽으로 그려 전체 크기를 유지 |
| 미리보기 배치 | 조절 항목과 함께 표시. 최대 크기 원과 아이콘이 잘리지 않는 고정 영역 사용 |
| 미리보기 배경 | 내부 100% 투명 상태도 구분할 수 있는 고정된 밝음/어두움 배경. 추가 배경 선택 기능은 만들지 않음 |

크기와 굵기 범위의 조합은 표시 가능해야 한다. 최소 원에서 굵기가 최대여도 바깥 지름은
늘어나지 않고 잘림 없이 표시한다. 시안에서 극단 조합이 부적절하면 범위를 다시 승인받는다.

### 3.2 표시 및 중단 조건

- 게임이 실제 포그라운드이고, 포인터의 클릭 기준점이 등록한 게임창의 클라이언트 영역 안에 있을 때만 표시한다.
- 기존 일부 오버레이의 '게임 또는 자기 앱 활성'과 달리, 자기 앱에 포커스가 오면 실제 하이라이트는 숨긴다.
  설정 화면에서는 고정 미리보기로 모양을 확인한다.
- 원의 중심을 클릭 기준점에 맞춘다. 화살표 이미지의 바운딩 박스 중심에 맞추는 기능은 아니다.
- 게임창 밖이나 다른 모니터의 다른 앱으로 마우스를 이동하면 숨긴다.
- 원 중심이 게임 영역 안에 있으면 표시하며, 가장자리에서 원 일부가 게임창 밖으로 나오는 것은 허용한다.
- 기능 사용, 베타 접근 가능, 전체 오버레이 일시정지 해제 조건도 모두 만족해야 표시한다.
- 일반 데스크톱에서 포인터가 숨겨진 것으로 확인되면 하이라이트도 숨긴다.
  게임 자체 커서의 숨김 상태까지 같은 방법으로 구분 가능한지는 실게임 검증 항목이다.
- 포그라운드, 게임창 위치 또는 포인터 위치를 확인하지 못하면 마지막 위치에 원을 남기지 않고 숨긴다.
- Windows 잠금, 절전, 게임 최소화, 게임 종료 및 앱 종료에서는 실제 하이라이트를 숨긴다.
- 복귀 시 과거 위치를 복원하거나 지나간 이동을 재생하지 않고 현재 표시 조건과 포인터 위치를 다시 확인한다.
- 베타 로그아웃, 기능 끄기 및 전체 일시정지 시에도 실제 하이라이트를 숨긴다.
- 설정 화면이 아닌 트레이로 앱을 닫는 기존 동작은 유지한다. 창이 숨겨져도 앱이 실행 중이고
  표시 조건을 만족하면 하이라이트는 유지한다. 앱의 실제 종료와 구분한다.

### 3.3 설정 저장 및 복원

- 기능 사용 여부와 원/테두리 설정은 기존 앱 설정과 같은 수명으로 저장한다.
- 사용 여부를 껐다 켜거나 앱을 재실행해도 마지막 선택값을 복원한다.
- 사용 중으로 복원되어도 게임과 표시 조건이 확인되기 전에는 실제 하이라이트를 띄우지 않는다.
- 저장할 고정 오버레이 위치는 없다. 항상 현재 포인터 위치를 이용한다.
- 설정 파일에 새 항목이 없으면 이 기능의 기본값만 적용하며 기존 설정을 변경하지 않는다.
- 잘못된 타입, 알 수 없는 선 종류, 범위를 벗어난 값은 해당 항목만 검증하여 안전한 기본값으로 대체한다.
- 저장 실패 시 현재 세션의 표시와 재실행 후 복원 상태가 다를 수 있음을 기존 오류 안내 방식으로 알린다.
  저장 성공으로 오인시키거나 오류 알림을 반복해서 쌓지 않는다.

## 4. 사용자 흐름

1. 편의기능에서 마우스 하이라이트 설정을 연다.
2. 베타 접근 조건을 충족한 사용자가 원 크기, 내부 색상 및 투명도를 조절한다.
3. 고정 미리보기에서 아이콘과 원의 겹침, 내부 색상과 투명도를 확인한다.
4. 필요하면 테두리를 켜고 종류, 굵기 및 색상을 선택한다. 테두리가 미리보기에 즉시 반영된다.
5. 기능 사용을 켜고 마비노기로 돌아간다. 표시 조건을 만족하면 실제 포인터를 따라 원이 표시된다.
6. 설정 화면으로 돌아오면 실제 하이라이트는 숨고 고정 미리보기만 유지된다.
7. 기능 사용을 끄면 하이라이트는 사라지고 원래 커서만 남는다.

내부 투명도 100%에 테두리도 없으면 보이는 하이라이트가 없는 정상 조합이다.
임의로 투명도를 낮추거나 테두리를 강제로 켜지 않는다.

## 5. 상태 및 상태 전환

| 상태 | 사용자에게 보이는 동작 | 전환 |
|---|---|---|
| 사용 안 함 / 베타 접근 불가 | 실제 하이라이트 없음 | 사용 가능하고 켜면 조건 대기 |
| 조건 대기 / 일시정지 | 실제 하이라이트 없음, 설정값 유지 | 표시 조건 충족 시 추적 표시 |
| 추적 표시 | 현재 포인터 위치에 선택한 원 표시 | 조건 해제나 조회 실패 시 숨김 |
| 조회 실패 | 마지막 위치의 원을 남기지 않음 | 현재 정보를 다시 확인하면 조건에 따라 재개 |
| 종료 | 실제 하이라이트와 관련 작업 정리 | 다음 실행에서 설정만 복원 |

고정 미리보기는 실제 추적 표시와 독립적이다. 기능을 꺼 두었거나 게임이 실행되지 않아도
베타 접근 조건 안에서 미리보기를 확인할 수 있다.

## 6. 기존 기능과의 관계 및 유지 동작

- 원래 커서, 클릭, 더블클릭, 드래그, 휠 및 게임 포커스를 변경하거나 막지 않는다.
- 사용자가 원래 커서 크기나 Windows 포인터 설정을 바꿔도 이 기능이 이를 되돌리지 않는다.
- 다른 트래커의 등록 영역, 자동찾기 결과, 소리 알림, 오버레이 위치 및 잠금 상태를 변경하지 않는다.
- 하이라이트는 항상 클릭 통과 상태이다. 위치 편집이나 잠금 해제 모드를 추가하지 않는다.
- 전체 일시정지와 베타 접근 제어는 별도의 중복 설정을 만들지 않고 기존 동작에 연결한다.
- 하이라이트가 화면 캡처에 포함되어 기존 판독이나 자동찾기 결과를 바꿀 수 있는지 검증한다.
  인식 대상과 겹쳤을 때의 영향은 확인해야 하며, 구현 방법은 기획에서 고정하지 않는다.
- 최초 사용 안내와 일괄 자동설정 목록을 이 기능 때문에 확장하지 않는다.
  이 기능에는 자동으로 찾아 등록할 영역이 없다.

## 7. 화면 환경 및 예외 검토

- 창모드와 테두리 없는 창모드를 우선 검증한다. 독점 전체화면 지원 여부는 실제 Windows에서 확인한다.
  기존 일반 오버레이로 표시되지 않는 환경을 지원한다고 선전하거나 보안 우회로 해결하지 않는다.
- 게임 실행 전 앱 실행, 앱 실행 전 게임 실행, 게임 종료/비정상 종료/재실행 시 현재 창을 기준으로 동작해야 한다.
- Alt+Tab, 빠른 포커스 왕복 및 전체 일시정지 반복에서 중복 원이나 이전 위치의 잔상이 남지 않아야 한다.
- 게임창 이동, 해상도/DPI 변경, 멀티모니터 및 서로 다른 배율의 모니터 사이 이동을 검증한다.
- 게임창 밖 다른 모니터로 나간 포인터와, 게임창 자체가 다른 모니터로 이동한 상황을 구분한다.
- 관리자/일반 권한 차이 또는 Windows 조회 실패 때문에 정보를 얻지 못하면 입력을 방해하지 않고 숨긴다.
  이를 해결하려고 관리자 권한을 필수 조건으로 확정하지 않는다.
- 카메라 조작 시 포인터 숨김/고정 및 게임 내부 커서 표시와 Windows 커서 정보가 다른 상황은 실게임에서 확인한다.
  이 경우 정상 추적 여부가 불확실하면 지원 범위와 기대 동작을 별도로 결정한다.
- 앱 중복 실행 방지는 기존 정책을 유지한다. 두 번째 실행 때문에 원이 두 개 생기지 않아야 한다.
- YoloMouse 동시 사용은 보장하지 않는다. 원이 겹칠 수 있다는 사실과 독립적으로, 외부 앱 설정은 변경하지 않는다.

## 8. 성능 및 개발 확인 사항

- 포인터 위치를 표시하기 위해 게임 화면 캡처나 이미지 판독 주기를 추가하지 않는다.
- 현재 트래커의 판독 주기를 그대로 적용해도 부드러울 것이라고 가정하지 않는다.
  빠르게 움직이는 실제 커서와 하이라이트 사이의 지연을 별도 측정한다.
- 숨김, 사용 안 함 및 종료 상태에서는 표시 갱신 작업이 불필요하게 지속되거나 누적되지 않아야 한다.
- 고정 미리보기는 설정 변경 시 갱신하며, 마우스 움직임만으로 지속 갱신할 필요가 없다.
- 설정 변경, 모니터 변경 및 숨김/복귀 반복으로 창, 타이머, 워커, 핸들 또는 메모리가 계속 증가하지 않아야 한다.
- 기존 트래커의 캡처·판독·알림을 눈에 띄게 지연시키지 않아야 한다.
- 추적 지연과 CPU 사용량의 수치 기준은 베타 시험 구현에서 측정 결과와 함께 승인받는다.
  특정 주사율, Windows API, 라이브러리 또는 스레딩 구조는 이 문서에서 강제하지 않는다.
- 새 설정 화면은 기존 테마/컨트롤 규칙을 따르고, 작은 창과 높은 DPI에서도 미리보기와 조절 항목이 잘리지 않아야 한다.

## 9. Acceptance Criteria

다음 기준으로 개발 검증과 독립 QA의 성공/실패를 판단한다.
성능 수치 및 환경별 지원 범위는 10절의 검증 결과에 따라 구체화한다.

| ID | 구분 | 검증 가능한 성공 기준 |
|---|---|---|
| MH-01 | 원 | 원 크기를 변경하면 실제 하이라이트와 고정 미리보기 모두 같은 크기 설정을 반영한다. 실제 게임 커서 크기는 변하지 않는다. |
| MH-02 | 원 | 내부 색상과 투명도를 각각 변경하면 서로의 선택을 덮어쓰지 않고 표시와 미리보기에 반영한다. 완전 투명 상태에서 내부 채움은 보이지 않는다. |
| MH-03 | 테두리 | 최초 테두리는 없으며, 테두리를 켜면 초기 검은색 선이 표시된다. 다른 색을 선택하면 해당 색으로 변경된다. |
| MH-04 | 테두리 | 실선/점선 종류와 굵기를 독립적으로 바꿀 수 있고 굵은 실선과 굵은 점선을 각각 만들 수 있다. |
| MH-05 | 투명도 | 내부를 완전히 투명하게 해도 켜 둔 테두리는 남는다. 이 상태에서 테두리도 끄면 원이 보이지 않으며 임의의 보정이 없다. |
| MH-06 | 미리보기 | 게임 미실행 상태에서도 고정 아이콘과 원의 미리보기를 확인할 수 있다. 실제 마우스를 움직여도 미리보기 위치는 바뀌지 않는다. |
| MH-07 | 입력 | 하이라이트 표시 중 클릭, 더블클릭, 드래그 및 휠이 게임에 전달되고 하이라이트가 포커스를 가져오지 않는다. |
| MH-08 | 기본값 | 최초 진입 시 기능은 꺼져 있고, 직경 48/내부 노란색/투명도 60%/테두리 없음으로 미리보기된다. 투명도 0%와 100%의 의미가 반대가 되지 않는다. |
| MH-09 | 크기 | 허용된 최소/최대 직경과 굵기 조합에서 원이 미리보기나 실제 표시 창에 잘리지 않으며 테두리 변경으로 바깥 지름이 바뀌지 않는다. |
| MH-10 | 표시 | 게임이 포그라운드이고 포인터 기준점이 클라이언트 영역 안에 있을 때만 현재 위치에 원이 표시된다. 자기 앱/다른 앱 포커스 및 다른 모니터의 게임 밖 위치에서는 숨는다. |
| MH-11 | 경계 | 게임창 끝에 포인터 기준점이 있을 때 원 중심은 기준점과 일치하며, 원 일부가 바깥으로 나간다는 이유로 원 전체를 강제로 안쪽 이동시키지 않는다. |
| MH-12 | 중단/복귀 | 기능 끄기, 전체 일시정지, 로그아웃, 게임 종료/최소화, 잠금 및 절전 시 실제 원이 남지 않는다. 재개 시 현재 조건과 현재 위치로만 표시한다. |
| MH-13 | 오류 | 게임창/포인터/활성 상태 조회 실패를 주입하면 마지막 위치의 원이 사라진다. 복구 시 과거 이동을 재생하거나 원을 중복 생성하지 않는다. |
| MH-14 | 생명주기 | 앱을 트레이로 숨겨도 게임 표시 조건을 만족하면 동작하며, 앱을 실제 종료하면 원과 관련 작업이 남지 않는다. |
| MH-15 | 저장/복원 | 사용 여부와 원/테두리 설정을 바꾸고 앱을 재실행하면 마지막 선택값을 복원한다. 게임이 없으면 원을 띄우지 않는다. |
| MH-16 | 설정 오류 | 설정 항목 없음/잘못된 값/구버전 설정에서 기존 기능 설정을 훼손하지 않고 새 항목만 기본값으로 복구한다. 저장 실패를 성공으로 표시하지 않는다. |
| MH-17 | 검증 목표 | 서로 다른 DPI/음수 좌표의 보조 모니터/게임창 이동/해상도 변경에서 원 중심이 포인터 클릭 기준점을 벗어나 고정되지 않는다. |
| MH-18 | 검증 목표 | 하이라이트를 켜고 끄거나 판독 영역 위에 겹쳐 비교했을 때 버프·디버프·투아림·체력바·보스 판독과 자동찾기에 새 오인식이 생기지 않는다. |
| MH-19 | 검증 목표 | 빠른 이동 시 지연과 자원 사용을 측정하여 승인된 성능 기준을 충족한다. 숨김/복귀·설정 변경 반복 후 관련 자원이 계속 증가하지 않는다. |

## 10. 개발 전 검증 및 전달

1. 본 문서를 기능 동작과 독립 QA 기준으로 사용한다. 기본값, 표시 조건 및 설정 복원에 대한 재승인은 필요하지 않다.
2. Windows에서 클릭 통과, 커서 추적 지연, 게임 표시 호환성 및 기존 캡처에 미치는 영향을 작게 검증한다.
   독점 전체화면과 게임 내부 커서 숨김 지원 여부를 확인하고 지원 범위를 정한다.
3. 설정 화면은 고정 미리보기와 조절 항목이 보이는 렌더를 먼저 공유해 배치를 확인받는다.
4. 추적 지연과 CPU 사용량을 측정해 베타 성능 수치 기준을 정한다. 수치 확정 전에는 해당 성능 AC의 통과를 주장하지 않는다.
5. 본 명세의 범위를 구현하고 AC로 개발 검증 및 독립 QA를 수행한다. 실제 실행하지 않은 Windows 항목은 미검증으로 표시한다.

남은 확인 항목은 기능 선택의 미결정이 아니라, 실제 환경에서의 독점 전체화면/게임 자체 커서 숨김
호환성, 추적 지연과 자원 사용량, 설정 화면 배치이다. 확인 결과 본 명세의 동작을 바꿔야 한다면
제약과 변경안을 먼저 사용자에게 설명하고 승인받는다.

현재 소스의 참고 위치는 `system/window_watcher.py`의 게임 활성 구분,
`system/clickthrough.py`의 클릭 통과 및 `ui/overlay.py`의 비활성 투명 오버레이이다.
`ui/dpi.py`는 주 모니터 배율 기준이므로 혼합 DPI 추적에 그대로 사용해도 된다고 가정하지 않는다.
이는 현재 코드 위치 안내이며 구현 구조의 강제나 안전성 보장이 아니다.
