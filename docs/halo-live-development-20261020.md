# 헤일로 라이브 후속 및 자동설정 연동

## 요구와 구현

- 근거: `docs/qa/헤일로_라이브후속_개발전달_20261019.md` 및 후속 사용자 승인.
- 같은 HWND/PID에서 회한 보스와 감소하는 시간을 연속 확인해 동기화한 뒤에는 이름/HP 바만 사라져도 카운트다운과 예정 경고를 유지한다. 미확정 전투는 여전히 타이머만으로 시작하지 않는다.
- 다른 보스·게임 대상 변경·타이머 종료·영역 변경·권한 상실은 이전 전투와 구분한다. 시간 미판독·비활성 복귀에는 재확인하며 지난 경고와 같은 회차는 재생하지 않는다. 큰 시간 증가도 단일 오독만으로 회차를 초기화하지 않고 연속 감소 관측으로 재확인한다.
- 판독·표시·경고·직접 지정·자동찾기는 기존 Discord 로그인 베타 조건을 사용한다. 원본 자동 수집·수동 스냅샷·폴더 열기는 제작자 전용이며 최근 회한 식별을 계속 요구한다. 다른 제작자 전용 기능의 정책은 변경하지 않는다.
- 설정 화면은 판독 영역 → 판독 미리보기 → 다음 헤일로 표시 → 헤일로 경고 → 진단 수집 순서다. 기존 QGroupBox·잠금 스타일·오른쪽 위험 명령·줄바꿈·경로 표시 헬퍼를 사용한다. 경고에는 알림 미리보기를 추가했다.
- 두 헤일로 표시만 85% 크기·일반 굵기·완화된 노란색을 사용한다. 미저장 기본 위치는 기존 보스 경고 아래에서 카운트다운 위/5초 전 경고 아래다. 기존 개별 저장 좌표는 유지한다.
- 업로드 MP3를 제품 `assets/sounds/헤일로 알림.mp3`로 바이트 변경 없이 포함한다. 소리 기본 OFF, `haloTimer.sound`만 저장하며 회차 이벤트 또는 명시적인 미리보기에서만 재생한다. 별도 SoundNotifier를 지연 생성해 다른 알림 재생기를 교체하지 않는다. OFF·대기·권한 상실·종료에서 소리를 정리하고 오디오 실패는 화면 경고와 시계를 막지 않는다.

## 자동찾기와 첫 사용 화면

- 사용자가 누른 1회에만 등록된 포그라운드 게임 창을 캡처한다. 전후 HWND/PID/창 사각형/활성 창을 검증하고 데스크톱 전체로 폴백하지 않는다. 상단 중앙 절반·상위 1/4에서 분:초 글리프를 검증해 단일 후보만 제안한다.
- 기존 확인 UI에서 점선을 보고 승인해야 저장한다. 취소·복수 후보·미검출·게임 대상 변경·권한 상실·영역 교체·저장 실패는 기존 설정을 유지한다. 캡처 중 앱/오버레이를 숨기고 역할 상실 시에도 종료 중이 아닌 앱 자체는 복원한다.
- 원본·템플릿·검색 범위·점수 기준·후보·탈락 사유·좌표 오프셋을 기존 실행별 진단에 보관한다. `halo_timer` ZIP 재실행은 설치된 모델 대신 ZIP의 자산을 사용한다.
- 사용 준비·전투 기능 안내에서 보스 패턴 바로 아래에 헤일로 선택을 추가했다. 별도 기능 탭을 만들지 않고 기존 3차 `1분 헤일로` 탭으로 연결한다. 필요한 보스 체력바 → 시간 영역 순으로 자동설정하며 등록 상태가 각각 갱신된다. 기존 선택/좌표/세부 설정은 유지한다.

## 원본 재검토

- `0008.zip` 589쌍의 CRC·시퀀스·shape·재판독을 실행했다. recognized 584 / uncertain 5이며 재판독은 589쌍 모두 저장값과 일치했다. 이 수치를 독립 정답률로 취급하지 않는다.
- 캡처 간격 807.249956초, 저장 시각 대비 정수 시간 잔차 -0.777863~+0.663209초, 최대 저장 간격 약 22초다. 수 초씩 누적되는 판독 오차를 보정할 근거가 없어 판독 모델과 63초 일정은 유지했다.
- QA에서 원본을 시각 확인한 13:32 / 12:59 / 10:01 / 01:16 / 01:14 / 00:14 / 00:13 / 00:12 / 00:05를 고정 회귀로 추가했다. 실제 헤일로 등장 시각 정답 영상은 없으므로 01:15/00:13 제보를 임의의 새 주기로 환산하지 않는다.
- 실제 전체 게임 원본에서 상단 14:57을 찾아 판독 가능한 영역을 제안했고, 진단 ZIP만으로 같은 검출을 재실행했다. 가상 입력으로 값 변경·부재·복수 후보·하단 타이머 제외도 검증한다.

## 재현과 한계

- 수정 전 보스 미표시 독립 재현: 2 failed / 9.51초. 정식 위치는 `tests/test_halo_live.py`, 기존 QA 스크립트는 같은 검증을 가져오는 호환 진입점으로 이관했다.
- 저장 실패 주입 중 창 위치 저장 PermissionError가 Qt 종료 경로 밖으로 전파되는 문제를 추가 재현했다. 그 뒤 GC에서 종료 코드 139도 관측했다. 창 위치 저장의 OSError는 로그로 남기고 나머지 종료 정리를 계속하도록 수정했으며 독립 실패 주입 회귀를 유지한다. 누수 검사를 비활성화하지 않았다.
- 초기 테스트의 저장 실패 주입은 다음 창 종료까지 오염되지 않도록 scoped restore한다. 요구가 바뀐 기존 검증은 베타/제작자/비로그인, 미확정 전투/확정 전투로 분리했으며 실패를 skip하거나 assertion을 약화하지 않았다.
- Linux Qt offscreen·외부 캡처/오디오/네트워크 격리 환경이다. 실제 Windows 캡처, 혼합 DPI, 절전/잠금, 장시간 게임 병행, MP3 청취·출력 장치 변경 및 최신 exe 포함/재생은 미검증이다.
- 일반 푸시의 Windows Actions·태그·Release는 실행하지 않는다. 이전 v0.6.0 후보/배포 파일은 이번 변경의 검증 근거로 재사용할 수 없다.
