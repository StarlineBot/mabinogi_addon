# 도르카 자체 창 가림 복구 보완

## 범위와 방식

- 근거는 `4b37916`의 [후속 독립 QA](qa/Qt네트워크_테스트경계_수정_독립QA_20261017.md),
  `DORCHA-RESTART-SELF-CAPTURE-QA-02`다. 실제 사용자 --/15의 당시 원인은 미확정이다.
- Windows 10 2004(build 19041) 이상과 Windows 11에서 도르카 실행 중 캡처에
  `WDA_EXCLUDEFROMCAPTURE`를 잠깐 적용한다. 캡처와 교차하는 앱 소유의 보이는 최상위 창만
  대상으로 하며 실제 HWND의 프로세스와 물리 좌표를 검사한다. 게임 창의 속성은 바꾸지 않는다.
- 실제 창의 hide/show, 위치/크기 변경, 활성화/raise, 강제 포커스 이동은 하지 않는다.
  장식 문맥 검사, 전체 게임 재탐색, 현재 숫자 읽기, 검색 완료 후 최신 픽셀 재확인에 동일하게 적용한다.
- 캡처가 끝나면 기존 affinity 값을 역순으로 복원한다. 캡처 예외에도 finally가 실행된다.
  SetWindowDisplayAffinity 복원은 호출당 최대 3회 시도하고, 계속 실패하면 원래 위젯의 약한 참조와
  HWND/이전 값을 보존해 기존 타이머 틱에서 재시도한다. 추적 OFF/로그아웃/비활성에서도 먼저
  복원하며 정지·종료에서도 시도한다. 삭제된 위젯이나 다른 HWND에 이전 값을 적용하지 않는다.
- 원래 0/1/0x11 값을 보존하고 설정 파일에 캡처 제외 상태를 저장하지 않는다.
  새 타이머/스레드/워커/큐는 추가하지 않는다. 등록 영역, 게임 대상 재검증, 후보 거부 조건,
  작업 수 제한/backoff와 기존 위치·잠금·배율·투아림 알림 정책도 유지한다.
- 오래된 Windows에서는 0x11이 검은 사각형 처리로 내려갈 수 있으므로 사용하지 않는다.
  manifest의 호환 버전 대신 실제 플랫폼 빌드로 지원 여부를 판정한다. 미지원/네이티브 API 실패는
  기존 캡처로 동작하며 가림 복구를 보장하지 않는다. 오류 로그는 반복 누적하지 않는다.

## 테스트 경계

일반 테스트에서는 캡처 제외 기능도 기본 비활성화해 실제 사용자 창의 네이티브 속성을 변경하지 않는다.
새 API 단위 검사는 명시적으로 대체한 Windows API를 사용한다. 원본 판독/검출 재현 검사는
`tests/test_dorcha_self_capture.py`에서 OS 경계만 모사해 기존 5조건과 원본 assertion을 그대로 실행한다.
합성 캡처가 QWidget.isVisible로 화면을 만들기 때문에 테스트 경계에서는 숨김으로 제외 효과를
모사하지만, 제품의 Windows 구현은 창을 숨기지 않는다. 이 모사를 실제 Windows 증거로 사용하지 않는다.

`tests/windows/test_capture_exclusion_native.py`의 별도 두 조건은 일반 창과 layered 창에서 실제
HWND affinity와 MSS/GDI 픽셀을 검사한다. 덮기 전 픽셀과 제외 중 픽셀의 일치, 제외 전후 덮인
픽셀의 일치, 창의 가시성/위치/포커스 유지, 예외 발생 뒤 기존 affinity 복원을 직접 assertion한다.
Windows 단계에서 실행되어야 하며 Linux 수집 성공은 실행 성공이 아니다.

## 로컬 검증

- 최종 새 API/복원/원본 재현/테스트 경계 검사: **43 passed (10.91초)**.
  복원 실패 100회에도 최초 affinity 1개만 유지하며 타이머·워커가 추가되지 않는 검사도 포함한다.
- 추적/ROI/재시작/자원 통합까지 포함한 관련 검사: **102 passed (103.81초)**.
  플랫폼 지원 판정과 일반 테스트 경계의 최종 보완 전 실행이며 최종 새 검사는 위 43개로 재확인했다.
- 자동찾기/로그인 게이트/게임 대상/원본 통합 probe 등 초기 관련 검사: **86 passed (180.02초)**.
  반복 실행 간 중복이 있어 위 수와 고유 테스트 수로 합산하지 않는다.
- 일반 테스트 경계를 추가한 직후의 버전 지원 검사 2개가 대체 함수의 False를 읽어 실패했다.
  기대값을 낮추지 않고 원본 지원 판정 함수를 명시적으로 호출해 검증하도록 수정했다.
- 수정하지 않은 원본 `scripts/qa_dorcha_restart_after_move.py`의 Linux 실행:
  **1 failed, 4 passed (11.61초)**. Windows 캡처 제외를 수행하지 않는 원본 합성 경계의
  runtime-recovery 실패이며 이를 통과/skip으로 바꿔 집계하지 않는다.
- 최종 탐색/테스트 경계/CI 계약/도르카 컨트롤러/자원 통합: **90 passed, 2 skipped (48.51초)**.
  skip 2개는 위 실제 Windows 픽셀 검사이며 Linux에서는 실행하지 못했다.
- 이번 전체 Linux 회귀는 다시 실행하지 않았다. 이전 SHA의 전체 통과를 새 수정본의 통과로 재사용하지 않는다.
  main 푸시에서 새 정확한 SHA의 전체 Windows 회귀·네이티브 통합·exe 빌드가 자동 실행된다.

## 남은 검증

Windows의 실제 픽셀 검사와 새 SHA의 전체 회귀·exe 빌드 성공 전에는 P2 해결 확정이나 QA 준비 완료로
판정하지 않는다. 실게임 D3D/혼합 DPI/잠금·절전·Remote Desktop의 캡처 및 DwmFlush 지연은
현재 Linux 환경에서 직접 검증할 수 없다. API가 계속 실패하면 복원 시도와 경고를 유지하며,
앱 종료로 HWND가 파괴되면 해당 네이티브 속성도 사라진다.

동시에 사용하는 화면 녹화·화면 공유에서는 캡처 순간 앱 창이 빠질 수 있다. 속성을 유지하는 정책이
아니라 매 캡처 직후 복원하지만, 실제 다른 캡처 프로그램과의 동시 사용은 별도 라이브 확인 범위다.
새 릴리즈/태그는 만들지 않는다.
