# 단계별 첫 사용 안내 개발 기록

- 기준: `docs/auto-setup-v2-spec.md`, `f141d37`의 기획 문서 및 개발 요청.
- 상태: 사용자 화면 피드백을 반영하고 개발 검증을 마쳤으며, 사용자 요청으로 현재 배치를 우선 main에 공유한다. 최종 UI 확정이나 독립 QA 통과를 뜻하지 않는다.
- 독립 QA/실제 Windows 게임 검증 통과를 뜻하지 않으며 릴리즈·태그는 진행하지 않는다.

## 구현 범위

- 기존 준비 화면은 설정 현황·미등록 영역 재시도용으로 유지한다. 상위 탭을 추가하지 않고
  같은 메인 스택에 별도의 단계별 안내를 배치한다.
- 안내는 게임창 등록, 전투 기능(버프/디버프/보스), 추가 기능(투아림/체력바/단축바),
  하이라이트 앱 둘러보기의 네 단계다. 별도 결과 화면은 없으며 메모/커스텀 오버레이는
  선택 목록에 넣지 않고 앱 둘러보기에서 소개한다.
- 기존 체크 설정과 각 탭의 설정을 공유한다. 이전/다음/나중에 설정은 사용 체크와 영역을
  초기화하지 않는다. 신규 사용자 판별과 기존 설정의 기본값 해석도 앞선 구현을 유지한다.
- `pending(feature_keys=...)`는 기능 출처를 현재 단계로 제한하되 선택 기능의 공유 보스바
  의존성은 포함한다. 의존성 등록을 위해 보스 패턴 알림 자체를 켜지는 않는다.
- 기존 SetupFlow 하나를 재사용한다. 기존 준비 화면의 전체 순차 탐색과 안내의 단계별
  탐색은 중복 실행하지 않는다. 검출 워커, 실제 입력 진단 ZIP, 화면 위 승인 방식은 기존 경로다.
- 결과는 저장된 영역을 우선하고 현재 안내에서의 미발견/거절/저장 실패/중단과 미시도를
  별도로 기록한다. 캡처 실패 시 해당 항목만 기록하고 나머지를 거짓 실패로 채우지 않는다.
- 승인 전 후보는 저장하지 않는다. 이미 승인한 영역은 단계 이동·재시도·앱 재시작 후에도
  유지하고 탐색에서 건너뛴다. 미발견이나 거절이 있어도 다음 단계와 앱 진입이 가능하다.
- 외부 동선으로 기존 탭에 이동하면 로그인 상태에서만 '첫 사용 안내로 돌아가기'를 제공한다.
  돌아올 때 같은 단계를 유지하고 설정을 다시 읽는다. 명시적인 안내 다시 보기는 1단계로
  초기화하며, 프로세스 재시작 후의 안내도 1단계에서 저장된 등록 정보를 보여준다.
- 사용자 렌더 피드백에 따라 2/3단계는 기존 준비 화면과 같은 한 줄 체크 목록, 전체 너비
  자동설정 버튼, 독립 스크롤의 설정 필요/등록된 설정/사용 안 함 구역으로 바꿨다.
  안내 내부의 개별 설정 이동 버튼은 제외했다. 남은 직접 지정은 투어를 마친 뒤 기존 탭에서 진행한다.
- 최신 사용자 피드백에 따라 단계별 안내 자체를 로그인 사용자용 베타로 제한했다.
  안내의 모든 로그인 UI/유도 문구, 중복 '앱으로 이동'과 별도 결과 화면은 제거했다.
  2/3단계에서 승인/거절/실패가 즉시 상태 목록에 반영되고 3단계 다음은 4단계 투어다.
- 설정에 '첫 사용 안내 다시 보기'를 별도로 추가한다. '자동설정 다시 열기'는 기존 준비
  화면, '사용법 투어 다시 보기'는 앱 둘러보기 하이라이트를 열며 자동 탐색하지 않는다.
- 앱 둘러보기는 트래커/편의기능/개별 설정/잠금/전체 일시정지/다시 열기를 소개한다.
  기본 버프 추가나 일반 사용자가 이용할 수 없는 베타 조작을 필수로 안내하지 않는다.
- 하이라이트 대체/종료/메인 창 닫기 시 이벤트 필터를 제거하고 이전 창을 폐기한다.
  안내 종료와 영역 등록 완료는 별개다.

## 시작 및 기록 정책

- 베타의 기존 준비 화면 기본 노출과 `general.skipSetup`의 명시적 숨김을 유지한다.
- 최초 실제 창 표시 뒤 업데이트 노트가 끝난 다음, 기존 `tourShown`과 신규
  `firstUseGuideShown`이 모두 false이고 skipSetup도 false이며 로그인 상태인 경우에만 단계별 안내를 연다.
  기존 투어를 본 사용자에게 새 안내를 자동 강제하지 않으며 설정에서 명시적으로 열 수 있다.
- 3단계에서 4단계 앱 둘러보기로 이동할 때 `firstUseGuideShown`을 기록한다.
  잠깐 다른 탭에 이동하는 동작은 완료로 기록하지 않는다.
- 로그인 제한은 설정 진입점의 숨김뿐 아니라 자동/다시 보기/재개/탐색 경로에서 확인한다.
  로그아웃 이벤트에서 진행 중 탐색 및 안내에서 시작한 투어를 취소하고 안내를 숨긴다.
- `tourShown`은 하이라이트 완료/건너뛰기에만 기록한다. 어느 기록도 좌표를 등록됨으로
  바꾸거나 skipSetup을 초기화하지 않는다. 안내 중 종료하면 마지막 단계 번호는 저장하지 않는다.

## 검증 및 제약

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python -m scripts.render_setup_guide
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q -p scripts.qa_setup_audio_boundary tests/test_setup.py tests/test_release_notes_trigger.py tests/test_settings_preserve.py tests/test_settings_sync.py scripts/qa_setup_independent.py
```

- 렌더는 `/tmp/setup-guide-preview/stage-1.png`부터 `stage-4.png`까지다.
  1~3은 현재 안내 위젯이며 4는 실제 메인 창과 하이라이트 투어를 Qt로 합성한 렌더다.
  사용자 설정이나 실제 게임 화면 대신 샘플 입력을 사용한다. 첫 렌더는 사용자에게 보여줬고
  배치 수정 요청에 맞춰 다시 렌더했고, 최신 로그인 전용/단계 내 결과/4단계 투어 변경까지
  이미지를 공유했다. 사용자의 '일단 푸시' 요청에 따라 현재 구현과 문서를 함께 공유한다.
- 기능/생명주기 구현 후 첫 전체 회귀: **688 passed, 9 warnings in 146.42s**.
  로컬 IPC/콜백 소켓을 허용한 Linux 실행이다. 이후 사용자 피드백의 화면 재배치 후
  관련 회귀는 **102 passed, 7 warnings in 18.39s**였다. 두 집합은 중복이며 합산하지 않는다.
- 수정 렌더 이후 현재 단계 행만 표시됨, 반복 로그인 안내/개별 설정 버튼 없음,
  체크박스 문구와 하단 버튼의 실제 MainWindow 내 위치를 검증했다. 업데이트 노트 시험까지
  포함한 최종 관련 집합은 **108 passed, 7 warnings in 18.31s**다. 경고는 기존 mss API다.
  렌더는 단계 전환의 레이아웃/페인트 이벤트를 처리한 다음 캡처한다.
- 기존 V1의 `scripts/qa_setup_tour.py`는 '설정의 투어 다시 보기 = 준비 화면 안내'와
  '최초 실행 = 바로 하이라이트'를 전제로 한다. V2에서 요구사항으로 분리한 경로이므로
  해당 독립 QA 원본은 고치지 않았으며 이번 V2 통과 게이트로 간주하지 않는다.
  제품 회귀는 별도 첫 안내/준비 화면/앱 둘러보기와 최초 실행 정책을 새 명세대로 검증한다.
- Qt는 Linux offscreen이고 네이티브 오디오는 기존 QA 경계로 대체한다. 실제 Windows의
  혼합 DPI/게임 포커스/전체화면/트레이·절전·Explorer 복귀와 장시간 자원 사용은 미검증이다.
  안내 진입과 생명주기 경로가 바뀌므로 후속 독립 QA와 Windows 사전 검증 후 배포를 판단한다.

## 앞선 배포 차단 수정과의 분리

- 최신 독립 QA의 FIRST-USER-QA-01(종료 후 상태 타이머가 캡처를 재생성)은 별도 수정
  `f02cb23`으로 main에 푸시했다. 해당 커밋에는 V2 구현/테스트/문서 변경을 포함하지 않았다.
- V2 로컬 작업에 그 수정도 적용한 상태에서 `tests/test_setup.py`,
  `tests/test_main_shutdown.py`, 노트/설정 회귀와 독립 종료 재현을 함께 실행해
  **112 passed, 7 warnings in 21.06s**를 확인했다. V2 배치 확인과 푸시는 별도다.

## 최신 화면 피드백 반영 검증

- 로그인 사용자만 베타 안내에 자동/명시적 진입할 수 있고, 미로그인 사용자는 버튼 숨김뿐
  아니라 직접 진입/재개/실행 호출도 무동작임을 실제 MainWindow에서 확인했다.
- 안내 중/투어 중 로그아웃 시 화면과 진입점을 숨긴다. 승인 대화 중 로그아웃하면
  반환된 후보를 저장하지 않는 시나리오도 확인했다.
- 첫 항목의 승인 후 다음 항목의 승인 콜백 안에서 이전 항목의 상태가 '등록됨'이며 실제
  위젯이 등록된 설정 영역으로 이동했음을 확인했다. 별도 결과 단계 없이 각 단계에서 반영된다.
- 3단계의 다음은 실제 TourOverlay로 연결되고 표시 문구는 '첫 사용 안내 4 / 4'다.
  안내 내부의 로그인/앱으로 이동/개별 설정 버튼 및 별도 결과 위젯은 없다.
- 최종 관련 명령: 위 사용 준비/설정 회귀에 `tests/test_main_shutdown.py`,
  `tests/test_release_notes.py`, `scripts/qa_setup_closed_retry.py`를 포함해
  **119 passed, 6 warnings in 26.61s**. 앞선 688개 전체 결과는 재배치 전이며 이번 최종
  소스의 전체 재실행 결과로 바꾸어 표현하지 않는다. Windows 실측도 별도다.
