# 실화면 판독과 연장 알림 개발 검증

- 날짜: 2026-10-15. 개발 세션의 수정 기록이며 독립 QA 승인/실게임 검증이 아니다.
- 기준: `docs/qa/디버프_실화면_판독누락_QA.md`,
  `docs/qa/버프_시간연장_추가알림_제보.md`와 원본 재현 코드.
- 앞선 단계별 시작 화면 수정은 이미 main에 포함되어 있으며, 이번 수정과 누적 검증한다.
  제작자 대사 기능은 기획 확인만 한 상태로 이번에 구현하지 않는다.

## 디버프 경계 민감도

수정 전 원본 독립 재현은 **6 failed, 8 passed in 5.57s**였다.
16px 아이콘을 포함한 전체 영역을 0.625배로 줄이면서 영역 원점과 반올림된 크기에 따라
서로 다른 픽셀이 매칭에 들어갔다. 감지/해제 임계나 보스바 영역 높이만 바꾸어 해결하지 않았다.

- 캡처 영역은 재샘플링하지 않고 템플릿만 기존 화면 높이 16px로 준비한다.
- 원본 크기의 회색 영상으로 최대 4개 위치 후보를 찾고 해당 원본 컬러 패치로 점수를 검증한다.
  매 틱 회색 변환을 공유하고 템플릿 변환은 엔진 생성 시 한 번만 한다.
  흑백 유사도만으로 적용 여부를 확정하지 않으며 새로운 타이머/워커/캐시 큐는 없다.
- 기존 0.68/0.58 및 모모/방해 카드별 임계, 감지 확인 시간, 재표시 유예,
  보스바 게이팅/빈사 보호와 사라짐 경고는 유지한다.
- 원본 두 장 × 원점 49개 × 크기 5개, 총 **490개 영역**에서 대상 아이콘 픽셀 동일성과
  점수 안정성을 검사한다. 세 게이팅 모드, 원본 무축소, 컬러 검증 후보 수 상한도 고정한다.
- 두 사진의 프라가라흐 위치는 같다고 가정하지 않는다. 첫 사진 물리/마법 x=115/133,
  두 번째 x=133/151(영역 내 좌표)의 실제 패치에서 정답과 상대 색상 템플릿 점수를 비교한다.
  색상 점수 분리를 확인하는 시험이며 모든 유사 아이콘의 배타적 분류를 새로 보장한다는 뜻은 아니다.
- 기존 바닥 네 장에서 전체 **15개 번들 디버프**가 감지 임계를 넘지 않는지 확인한다.
  과거 '오탐이 하나 이상 있어야 함' 벤치는 과거 축소 판독을 test_support 기준선에 보존해
  샘플의 재현 신호를 유지한다. 현재 제품은 오탐이 없어야 한다는 assertion을 추가했다.
  원본 QA 스크립트/보고서/PNG를 바꾸거나 실패를 skip하지 않는다.

원본 PNG 두 장은 2556×1436이며 당시 사용자 DPI나 연속 라이브 입력을 복원한 것이 아니다.
캡처/자동찾기/저장 좌표를 바꾸지 않으므로 직접 지정 및 자동 등록 모두 같은 판독 수정을 사용한다.

## 버프 연장 후보의 알림

수정 전 원본 경계 재현은 **2 failed, 2 passed in 0.16s**였다.
일반 연장 및 기존 분 유실 방어는 통과했다. 제보자의 실제 버프/수단/버전/설정/시간을 알지 못하므로
라이브 제보 원인이 확정됐다고 해석하지 않는다.

사용자가 **최대 200ms 보류** 정책을 승인했다.

- 상향 후보를 처음 관측한 단조 시각을 기록하고 1차/2차가 같은 기한을 공유한다.
- 후보 확인 전에는 기존 시계 자체를 바꾸지 않는다. 새 판독이 일치하면 기존 확인 규칙으로 커밋한다.
- 후보가 바뀌거나 OCR이 멈춰도 기한을 연장하지 않으며, 포그라운드 복귀가 오래된 후보의
  200ms를 다시 시작하지 않는다. 정상 판독/미감지/리셋에서는 보류를 지운다.
- 첫 확인 대기 중 1차/2차 경계 알림은 보류하되 오독/기한 만료 후 정상 알림을 소비하지 않고 낸다.
  정상 연장 후 다음 1차/2차 재알림과 기존 분 유실 방어는 유지한다.
- 상태 머신에는 시각 하나만 추가했다. 실제 소리 재생이나 타이머 구조는 변경하지 않았다.
- 기존 알림 라우팅 시험은 첫 실제 OCR 후 내부 시계를 검증하도록 후속 OCR을 None으로 주입한다.
  25초 뒤 동일한 과거 121초 사진을 새 연장 입력으로 재사용하지 않으며 alerts/alerts2 assertion은 유지한다.

## 실행 및 성능

```bash
QT_QPA_PLATFORM=offscreen uv run pytest -q scripts/qa_debuff_live_detection.py scripts/qa_debuff_flicker.py scripts/qa_buff_extension_alert.py
QT_QPA_PLATFORM=offscreen uv run pytest -q -m 'not windows_integration'
uv run python -m scripts.benchmark_debuff_matching --iterations 50
```

원본 QA 및 기존 깜빡임 스크립트는 수정하지 않고 실행해 **32 passed in 5.77s**를 확인했다.
중간 관련 집합은 **115 passed in 18.61s**였으며 최종 전체 결과는 아래에 별도 기록한다.
테스트 집합은 중복이므로 합산하지 않는다.

- 최종 전체 격리 회귀: **780 passed, 3 deselected, 3 warnings in 162.03s**.
  별도 Windows 통합 3개만 제외했으며 실제 캡처·오디오·외부 통신 없이 실행했다.
  기존 QThread 누수와 종료 assertion은 유지했다. 경고 3개는 기존 Qt 마우스 이벤트 API다.
- 원본 PNG Git blob은 QA 문서와 같은 `ba46fe07e3d463a57e263c02368f24314f5d32bb`,
  `2919347c748fc7a99addff5ba1835d5f48a023f1`이다.
- 이번 묶음에는 사용자가 렌더를 확인해 확정한 단계별 시작 화면이 누적되어 있다.
  최종 커밋의 Windows 검증까지 확인하기 전에는 앞선 시작 화면의 개발 완료도 선언하지 않는다.

같은 원본/단일 OpenCV 스레드/엔진 틱 50회, 5회 워밍업 제외의 Linux 클라우드 비교다.
