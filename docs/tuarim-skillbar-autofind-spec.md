# 투아림 및 단축바 자동찾기 기획 초안

- 상태: 개발 세션 공유용 초안. 합의된 MVP 범위와 개발 검증 항목을 정리했으며, 전체 기획의 최종 확정 표시는 하지 않는다.
- 작성일: 2026-10-14
- 대상: 트래커 > 투아림, 편의기능 > 단축바
- 요청 범위: 기존 개별 자동찾기의 동작을 참고해 두 기능의 자동찾기를 추가한다.
- 사용자 결정, 기존 동작, 구현 검증 사항 및 제안을 구분한다. 미정 항목은 개발자가 임의로 확정하지 않는다.

## 개발 세션 전달

이 문서에 합의된 MVP 범위로 개발을 진행한다. 사용자 현재 화면에서 정상 동작을 먼저 확인하고, 매칭 기준과 경계 오차는 개발 중 검증해 기록한다. 다른 해상도/배율 대응은 후속 검증 범위이다. 별도의 기획 승인을 기다려야 하는 기능 조건은 남아 있지 않으며, 기능 범위를 변경해야 할 때만 기획 세션에 확인한다.

`docs/cooking-spec-draft.md`는 별도의 요리 기능 기획 기록이다. 이번 자동찾기 개발 범위에 포함하지 않는다.

## 1. 목적과 작업 순서

사용자가 투아림 퍼센트 영역이나 상단 단축바 첫 칸을 직접 맞추지 않고, 현재 게임 화면에서 해당 위치를 찾아 기존 기능에 적용할 수 있게 한다.

사용자가 합의한 개발 순서는 다음과 같다.

1. 투아림과 단축바의 개별 자동찾기를 완성하고 검증한다.
2. 기존 기능을 포함해 저장된 영역의 현재 정렬 상태를 검증하는 조건을 보강한다.
3. 별도 기획으로 메인 설정 화면 및 전체 자동설정을 연결한다.

이번 범위에는 메인 화면, 앱 시작 시 일괄 실행, 전체 자동설정, 이미 검증된 영역을 건너뛰는 로직 및 UI 이동의 지속적인 자동 추종을 포함하지 않는다.

## 2. 기존 자동찾기 현황

아래는 현재 소스에서 확인한 동작이며, 새 기능의 기술적 구현을 고정하는 요구사항은 아니다.

### 2.1 공통 캡처와 적용 흐름

- 공통 캡처는 `src/mabinogi_addon/ui/screen_grab.py`의 `capture_for_autofind`를 사용한다.
- 기획 작성 당시 `perform_autofind`의 제품 연결은 버프, 디버프, 보스, 체력바였다. 투아림/단축바의 후속 구현과 검증은 문서 끝의 개발 기록을 따른다.
- 앱 창과 앱 오버레이를 잠시 숨겨 대상 UI가 가려지거나 복제본이 검출되는 것을 줄인다.
- 등록된 게임 창을 우선 캡처하고, 게임 창 캡처를 사용할 수 없으면 가상 데스크톱 전체로 폴백한다.
- 캡처 좌표와 화면 원점 오프셋을 함께 반환한다. 검출 결과는 전역 물리 좌표에서 기존 설정이 사용하는 논리 좌표로 변환한다.
- 보스바, 디버프, 체력바는 점선으로 결과를 보여주고 사용자가 승인한 경우에만 저장한다. 거절하면 기존 설정을 유지한다.
- 버프는 결과의 위 경계를 사용자가 맞추거나 자동값 그대로 확정하는 별도 확인 흐름을 사용한다.
- 자동찾기는 현재 Discord 로그인 사용자 대상 베타이다. 수동 영역 지정은 별도로 제공한다.
- 현재 공통 캡처의 게임 창 미발견은 곧바로 기능 실패를 뜻하지 않는다. 실제 캡처 및 대상 검출 결과를 구분해 판단해야 한다.

### 2.2 기능별 검출 방식

| 기존 기능 | 현재 찾는 단서 | 기존 검증과 한계 |
|---|---|---|
| 버프 | 프리미엄 배틀 멤버십 아이콘을 크기를 달리하며 검색 | 기준 아이콘 존재를 확인할 수 있으나 목록 전체 경계는 추정하며 위 경계 조정이 필요 |
| 보스바 | 하단의 긴 채움 바 구조 | 이름 글자와 HP 퍼센트 판독으로 후보 확인. 판독 성공만으로 전체 경계가 정확하다고 보장하지 않음 |
| 디버프 | 보스바를 찾은 후 그 위쪽 띠를 유도 | 디버프가 없는 상황도 정상이다. 아이콘 존재 자체를 필수 조건으로 둘 수 없음 |

## 3. 공통 사용 흐름

### 사용자 결정: 기존 개별 자동찾기와 동일한 방식

미리보기 후 승인/취소 및 Discord 로그인 베타 접근은 사용자 결정 사항이다. 기능 전체는 기획 확정 전 초안 상태를 유지한다.

1. 각 대상 탭에 기존 수동 지정과 함께 '자동 찾기' 동작을 제공한다.
2. 기존 자동찾기와 같은 Discord 베타 접근 조건을 적용한다. 투아림의 기존 수동 추적 사용 조건을 바꾸지 않는다.
3. 자동찾기를 실행하면 현재 화면을 확인한다. 실행 중 중복 실행 요청은 새 작업을 겹쳐 시작하지 않는다.
4. 대상 앵커 또는 원본 구조를 찾으면 영역 후보를 제시한다. MVP의 최종 영역 정렬 확인은 사용자가 미리보기에서 수행한다.
5. 점선으로 적용 대상 영역을 보여주고 사용자에게 적용 여부를 확인받는다.
6. 승인하면 영역을 저장하고 기존 추적 또는 미러 동작이 새 영역을 사용하게 한다.
7. 거절, 취소 또는 실패 시 기존 설정을 유지한다.
8. 결과 확인이 끝나면 임시 표시를 정리하고 숨겼던 앱 화면과 오버레이를 기존 상태로 복원한다.

자동찾기 성공은 기능 사용 체크를 자동으로 켜거나 경고 임계값, 소리 및 프리셋을 변경하는 동작이 아니다.

## 4. 투아림 자동찾기

### 4.1 사용자 결정

- 투아림 UI는 사용자가 화면에서 이동할 수 있다. 중앙 왼쪽 등 고정된 화면 위치에 있다고 가정하지 않는다.
- 보라색 원형 UI를 앵커로 찾는다.
- 찾은 원을 기준으로 오른쪽 아래의 퍼센트 표시 영역을 찾는다.

### 4.2 앵커 식별 조건

- 원 내부 숫자는 바뀔 수 있다. 특정 내부 숫자나 원의 전체 이미지를 고정된 정답으로 요구하지 않는다.
- 보라색 픽셀만 있다는 이유로 앵커로 채택하지 않는다.
- 스크린샷에서 확인한 원 바깥 장식과 오른쪽 작은 버튼의 상대 배치를 식별 근거로 검증한다.
- 게임 스킬 아이콘, 전투 이펙트 및 다른 원형 게이지와 구별해야 한다.
- 대상이 없거나 가려졌거나 후보를 구별할 수 없으면 임의의 위치를 성공으로 제시하지 않는다.
- 특정 Windows API, 이미지 처리 알고리즘, 템플릿 개수 또는 매칭 점수는 이 문서에서 확정하지 않는다.

### 4.3 퍼센트 영역 조건

- 결과로 저장하는 영역은 원형 UI 전체가 아니라 기존 투아림 판독에 사용하는 숫자와 퍼센트 영역이다.
- 한 자리, 두 자리 및 `100%` 표시의 전체 글자가 영역에 들어가야 한다.
- 숫자 자릿수가 달라져도 영역을 다시 지정할 필요가 없어야 한다.
- 원 내부 숫자, 주변 스킬의 쿨타임 및 다른 퍼센트 표시는 대상에서 제외한다.
- 위치와 크기는 실제 앵커와 숫자의 배치에 맞춰 유도한다. 스크린샷 하나의 절대 좌표를 모든 사용자에게 적용하지 않는다.
- 퍼센트 숫자가 하나 읽혔다는 사실만으로 올바른 투아림 영역으로 인정하지 않는다.
- 자동찾기 시점에 게이지 변화나 숫자 판독 성공을 요구하지 않는다. 사용자가 점선 안에 현재 숫자와 `%`가 포함되는지 확인하고 승인한다.
- 실제 판독 신뢰도는 적용 후 게이지가 차는 동안 별도로 확인한다. 자동찾기 결과를 전체 0~100 구간의 판독 검증 완료로 표현하지 않는다.

### 4.4 기존 기능 연계 및 보존

- 현재 수동 영역 지정, 영역 보기 및 판독 미리보기를 유지한다.
- 자동찾기로 지정한 영역은 수동 지정한 영역과 동일한 저장/판독 경로를 사용한다.
- 기존 기능 사용 여부, 임계값, 소리 설정 및 주기별 경고 억제 정책을 보존한다.
- 새 영역 적용 시 이전 영역의 안정화 값이 새 영역의 판독 결과로 표시되거나 새 알림의 근거로 재사용되지 않도록 검토한다. 이 과정에서 기존 알림 정책을 임의 변경하지 않는다.
- 기존 숫자 판독기의 `100%` 판독 정확도와 자동찾기의 `100%` 영역 포함 여부를 구분해 검증한다. 영역 찾기만 성공했다고 숫자 판독까지 검증 완료로 보고하지 않는다.

## 5. 단축바 자동찾기

### 5.1 대상 정의

- 기존 단축바 미러가 입력으로 사용하는 게임 원본 상단 단축바를 찾는다.
- 결과 앵커는 블록 1, 윗줄, 첫 아이콘의 좌상단이다.
- 중앙에 배치한 앱 미러, 오른쪽 추가 단축바 및 다른 아이콘 목록을 원본으로 지정하지 않는다.
- 사용자별 스킬 배치와 빈 칸이 달라도 찾을 수 있어야 한다.

### 5.2 식별 조건 제안

- 특정 첫 번째 스킬 이미지에 의존하지 않는다.
- 반복되는 슬롯 테두리, 행/그룹/블록의 배치 및 주변 게임 단축바 조작 요소를 식별 근거로 검증한다.
- 화면 위쪽이라는 위치만으로 후보를 채택하지 않는다.
- 미러 오버레이가 켜져 있어도 공통 캡처 흐름을 통해 원본 검출을 방해하지 않아야 한다.
- 슬롯이 일부 비어 있거나 쿨타임 숫자 또는 강조 효과가 있어도 원본 구조를 확인한다.
- 후보가 여러 개이거나 원본 구조를 확인할 수 없으면 임의로 하나를 선택하지 않는다.

### 5.3 결과 영역과 현재 격자 제약

- 결과 확인에서는 첫 아이콘뿐 아니라 이후 복제 대상 전체가 맞는지 사용자가 확인할 수 있어야 한다.
- 저장은 기존 앵커 좌표 형식과 연계한다.
- 현재 미러는 12개 그룹을 고정 격자로 자른다. 기준은 아이콘 40px, 칸 간격 44px, 행 간격 49px, 블록 시작 오프셋 620px, 전체 소스 1168x89 논리 좌표이다.
- 위 수치는 현재 소스의 제약 설명이며, 새로운 검출 알고리즘의 필수 상수가 아니다.
- 첫 칸만 맞고 뒤쪽 그룹들이 틀린 경우는 자동찾기 성공으로 인정하지 않는다.
- Windows DPI 변화와 게임 자체 UI 배율 변화를 구분한다. 기존 미러 출력 배율은 원본 게임 UI 배율과 별도 설정이다.
- 게임에는 아이콘이 작아지는 '작게 보기' 모드가 있다. 해상도에 따라 원본 아이콘 크기가 달라질 가능성도 있다.
- MVP는 사용자의 현재 화면에서 원본을 찾고 12개 그룹이 올바르게 복제되는 것을 우선 확인한다. 현재 화면의 해상도, Windows DPI, 작게 보기 사용 여부를 개발 검증 시 기록한다.
- 현재 화면에서 격자가 맞지 않으면 MVP 완료로 보지 않는다. 다른 환경까지 일반화하는 격자/배율 대응은 이후 검증 단계로 분리한다.
- 다른 해상도, Windows 배율 및 작게 보기 모드는 후속 테스트 대상으로 남긴다. 사용자 현재 환경에 포함된 모드는 MVP 검증에 포함한다.

### 5.4 기존 기능 연계 및 보존

- 기존 수동 앵커 지정과 Discord 베타 접근 조건을 유지한다.
- 자동찾기는 원본 소스 위치만 갱신한다.
- 기존 12개 그룹의 화면 위치, 잠금 상태, 셀별 숨김, 사용 여부, 출력 배율 및 프리셋을 초기화하거나 다시 배치하지 않는다.
- 미러 사용 중 승인하면 이후 갱신은 새 앵커를 사용한다. 실패/취소이면 기존 앵커로 계속 동작한다.

| 후보 확인 | 앵커 또는 원본 구조를 찾아 영역 후보를 제시. 사용자가 미리보기에서 정렬 확인 | 사용자 승인 전 저장하지 않음 |
| 미발견 | 현재 화면에서 확인할 후보를 찾지 못함 | 기존 설정 유지 |
| 판정 불가 | 가림/복수 후보/정렬 불일치 등으로 신뢰할 후보를 정하지 못함 | 기존 설정 유지 |
| 미지원 배치 | 대상은 보이지만 현재 기능이 올바르게 사용할 수 없는 구조/크기 | 기존 설정 유지 |
| 캡처/리소스 오류 | 정상적인 검출 시도에 필요한 화면 또는 자료를 얻지 못함 | 기존 설정 유지 |
| 적용 | 사용자가 후보를 승인함 | 해당 기능 영역만 저장 |
| 취소 | 사용자가 후보를 거절하거나 확인을 취소함 | 기존 설정 유지 |

미발견은 대상 UI가 숨겨져 있다는 사실을 확정하는 결과가 아니다. 실패 이유를 알 수 없으면 추측한 원인을 단정하지 않는다.

## 7. 예외와 경계 조건

- 게임 미실행/최소화, 검정 캡처 또는 화면 가림: 없는 위치를 만들어 저장하지 않는다. 캡처 문제와 대상 미발견을 구분해 안내한다.
- 실패 안내에는 현재 대상 UI를 화면에 보이게 한 뒤 재시도하거나 기존 수동 지정으로 진행할 수 있음을 포함한다.
- 다중 모니터 및 음수 화면 좌표: 원본 게임 창이 있는 위치와 캡처 오프셋을 적용한다. 첫 번째 모니터를 게임 모니터라고 가정하지 않는다.
- DPI: 점선 표시 위치, 저장 위치와 실제 추적/복제 위치가 일치해야 한다.
- 캡처 후 확인 중 대상 이동/게임창 이동/크기 변경: 기존 자동찾기와 동일하게 캡처 시점의 결과를 보여준다. MVP에는 적용 직전 재검증이나 후보 자동 무효화를 추가하지 않는다. 사용자가 짧은 설정 과정에서 화면 배치를 유지하고 미리보기를 확인하는 사용 흐름을 전제로 한다. 화면이 바뀌었다면 취소 후 다시 실행한다.
- 자동찾기 실패 또는 취소 후 앱/오버레이가 계속 숨겨져 있거나 임시 점선이 남지 않아야 한다.
- 앱 종료/재실행: 승인된 설정은 기존 기능의 저장/복원 정책을 따른다. 승인 전 임시 후보는 저장하지 않는다.
- 자동찾기 반복 실행: 임시 창이나 캡처 자원이 누적되지 않고, 최종 승인한 결과와 실제 사용 영역이 일치해야 한다.
- 숨겨진 슬롯/특수 배치가 현재 미러 구조를 충족하지 않으면 부분적으로 잘린 복제본을 성공으로 제시하지 않는다.
- 전체화면 모드의 캡처 가능 여부는 실제 Windows 검증이 필요하다. 스크린샷 테스트 통과만으로 모든 창 모드를 지원한다고 선언하지 않는다.

## 8. 검증 계획 및 개발 완료 기준

### 8.1 검증 자료

- 원본 전체 화면 스크린샷을 기준으로 실제 앵커/판독 영역/전체 단축바 경계를 사람이 확인해 기대 위치를 기록한다.
- 투아림의 예: `tests/data/스크린샷 2026-10-10 190116.png`의 7% 화면과 `tests/data/스크린샷 2026-10-12 200511.png`의 100% 화면. 두 화면은 UI 위치와 원 내부 숫자가 다르다.
- 단축바의 예: 위 화면의 상단 원본과 중앙 미러/오른쪽 추가 단축바가 함께 보이는 상태.
- 4K 자료: `tests/data/2026-10-11_111640.png`, `tests/data/2026-10-11_123333.png`.
- 기존 `tuarim_samples`, `tuarim_hi`, `tuarim_shots` 및 `raw_7603.zip`은 숫자 판독 검증에 활용한다. 잘린 숫자 자료만으로 전체 화면 위치 검출의 정확도를 평가하지 않는다.
- 원본을 변형한 이동/크기/가림 자료는 보조 테스트로 사용할 수 있으나 실제 사용자 화면에서의 성능과 동일하게 보고하지 않는다.

### 8.2 MVP 필수 비교

- 투아림: 위치, 원 내부 숫자, 한/두/세 자리 퍼센트, 배경 밝기 및 주변 UI가 다른 화면.
- 단축바: 스킬 교체, 빈 슬롯, 쿨타임/강조, 미러 켜짐 및 주변 추가 단축바.
- 두 기능 모두: 대상 없음, 부분 가림, 여러 유사 후보, 잘못 이동한 영역, 일부 잘린 영역.
- 사용자의 현재 화면에서 점선 표시, 승인 후 저장 영역 및 실제 판독/복제 위치가 일치하는지 확인한다.
- 투아림 영역은 사용자가 숫자와 `%`의 포함 여부를 확인한다. 자동찾기 중 실시간 판독 성공을 승인 조건으로 요구하지 않는다.
- 실제 투아림 판독은 적용 후 게이지가 차는 동안 별도로 점검하고, 자동찾기 위치 확인 결과와 나누어 보고한다.
- 단축바는 승인 후 12개 그룹의 복제가 현재 원본과 일치하는지 확인한다.

### 8.3 후속 환경 검증

- MVP의 현재 화면에서 정상 동작을 확인한 뒤 다른 해상도, Windows DPI 및 작게 보기 모드로 검증 범위를 넓힌다.
- 투아림 원의 형태가 같더라도 렌더 크기와 퍼센트의 상대 배치가 같은지 확인한다.
- 단축바 아이콘 크기, 칸/그룹/행 간격과 실제 복제 결과를 함께 확인한다.
- 다중 모니터와 다른 배율에서 캡처-표시-저장 좌표의 일치 여부를 확인한다.
- 후속 환경의 성공을 MVP 완료 조건으로 요구하거나, 미검증 환경을 이미 지원한다고 표시하지 않는다.

### 8.4 완료 보고에 포함할 항목

- 실제 검증한 자료 목록과 기대 위치.
- 위치 검출 성공/실패 및 잘못된 후보 채택 사례.
- 지원하는 게임 UI 구조와 배율 범위.
- 경계 허용 오차와 선택한 근거. 아이콘/숫자가 잘리는 오차는 허용하지 않는다.
- 오프라인 스크린샷 검증과 Windows 실행 검증의 구분.
- 미검증 환경과 남은 제약.

### 8.5 최신 공통 진단과의 연결

- 새 두 검출기도 기존 자동찾기 진단 경로에 연결하여 실패한 실행의 원본 입력과 후보/결과를 확인할 수 있게 한다.
- 실행에 사용한 자산과 검출기 정보를 기록하고 기존 ZIP 재실행 경로에 등록한다. 구체적인 연동 지점은 `docs/자동찾기_진단.md`를 따른다.
- 진단 기록의 검출 결과와 사용자 승인/취소를 구분한다. 확인 취소가 원본 입력에 대한 검출 결과를 바꾸지 않게 한다.
- 기존 진단 보관 상한과 개인정보/비밀값 제외 정책을 유지한다. 별도 진단 저장 체계를 만들지 않는다.

기존 관련 테스트 85개가 통과한 것은 기존 동작의 기준선이다. 새 위치 검출과 영역 정렬 검증이 준비됐다는 근거로 대신 사용하지 않는다.

## 9. Acceptance Criteria 초안

| ID | 성공/실패 판정 기준 |
|---|---|
| C-01 | 자동찾기를 승인하지 않은 상태에서 실패하거나 취소하면 해당 기능의 저장 설정이 실행 전과 같다. |
| C-02 | 사용자의 현재 화면에서 점선 결과 위치와 승인 후 실제 판독/복제 위치가 일치한다. 해당 환경의 해상도, DPI 및 단축바 모드를 기록한다. |
| C-03 | 확인 종료/실패 후 임시 점선이 제거되고 앱 및 기존 오버레이가 이전 표시 조건에 따라 복원된다. |
| C-04 | 자동찾기 반복 실행 시 겹친 작업이나 오래된 결과가 마지막 승인 설정을 덮어쓰지 않는다. |
| T-01 | 투아림 UI가 서로 다른 화면 위치에 있는 검증 자료에서 보라색 원형 앵커를 찾고 실제 퍼센트 영역을 제시한다. |
| T-02 | 원 내부 숫자가 달라도 앵커를 찾으며, 원 내부 숫자를 투아림 퍼센트로 지정하지 않는다. |
| T-03 | 현재 화면에서 사용자가 숫자와 `%`가 점선 안에 들어가는지 확인하고 승인할 수 있다. 한 자리, 두 자리 및 100%의 영역 포함 여부는 실제 화면 또는 기준 스크린샷으로 확인하며, 자동찾기 중 모든 값을 판독할 것을 요구하지 않는다. |
| T-04 | 투아림 없는 배경이나 유사한 보라색 스킬 아이콘에서 숫자가 판독되어도 투아림 후보로 채택하지 않는다. |
| T-05 | 대상이 가려지거나 후보가 모호한 경우 기존 영역을 유지하고 재시도/수동 지정이 가능하다. |
| T-06 | 승인된 영역에서 기존 미리보기/추적을 사용할 수 있고 임계값/소리/사용 여부 설정은 바뀌지 않는다. 실제 숫자 판독은 게이지가 차는 동안 별도로 검증하고 위치 찾기 결과와 구분해 보고한다. |
| S-01 | 특정 스킬 아이콘에 의존하지 않고 상단 원본 단축바의 첫 칸 좌상단을 찾는다. 검증 자료에는 첫 슬롯 교체와 빈 슬롯이 포함된다. |
| S-02 | 앱 미러와 오른쪽 추가 단축바가 있는 자료에서 이들을 원본 앵커로 저장하지 않는다. |
| S-03 | 승인 후 12개 그룹의 모든 활성 셀이 원본 대응 위치에서 복제된다. 첫 칸만 맞고 후속 그룹이 어긋난 결과는 실패이다. |
| S-04 | 자동찾기 승인 전후 그룹 위치/잠금/숨김/출력 배율/프리셋은 유지되고 소스 앵커만 갱신된다. |
| S-05 | 사용자 현재 환경에서 원본의 아이콘 크기와 간격에 맞게 12개 그룹이 복제된다. 다른 해상도/배율/작게 보기 모드의 미검증 상태는 MVP 완료 보고에서 명시한다. |
| R-01 | 기존 수동 지정과 기존 자동찾기 및 관련 판독/미러 회귀 테스트가 계속 통과한다. |
| D-01 | 새 자동찾기 실행의 원본/자산/결과를 기존 진단 ZIP으로 내보내고 동일 입력으로 해당 검출기를 재실행할 수 있다. |

베타 접근은 기존 자동찾기와 동일하게 검증한다. 승인 직전 화면 변화 재검증은 MVP의 QA 합격 조건에 포함하지 않는다.

## 10. 사용자 결정 및 개발 검증 항목

| 항목 | 결정 또는 검증 범위 |
|---|---|

| 베타 접근 | 결정: 기존 자동찾기와 동일한 Discord 로그인 조건. 기존 수동 기능 접근은 유지 |
| 원본 크기/배율 | 결정: MVP는 사용자 현재 화면 기준. 단축바 작게 보기와 다른 해상도/배율은 현재 환경 검증 후 확장 테스트. 투아림도 같은 환경 검증 순서 적용 |
| 신뢰 및 오차 | 결정: MVP는 사용자가 미리보기로 영역 포함 여부 확인. 세부 앵커 기준 및 현재 환경의 경계 오차는 개발 실험으로 검증. 모든 환경의 자동 신뢰 판정을 선행 요구하지 않음 |
| 투아림 숫자 판독 | 결정: 자동찾기 중 판독 성공을 요구하지 않음. 적용 후 게이지가 차는 동안 별도 검증 |
| 확인 중 화면 변화 | 결정: 기존 자동찾기 수준 유지. MVP에 승인 직전 재검증/후보 무효화 추가 없음 |

사용자의 현재 기준 화면 환경과 기술적인 매칭 기준은 개발 검증에서 기록한다. 전체 기획은 아직 초안이며, 구현 완료 시 UI 렌더와 실제 검출 영역을 보여주고 사용자 검토를 받는다.

## 11. 개발 기록 (2026-10-15)

### 구현 범위

합의된 두 개별 자동찾기를 탭에 연결했다. 기존 지정 행 오른쪽의 자동찾기 버튼 배치는
오프스크린 렌더를 보여준 뒤 사용자 확인을 받았다. 요리·전체 자동설정·시작 시 자동실행·
영역 추종·승인 직전 재검증은 구현하지 않았다. 실제 사용자 Windows에서의 MVP 완료 확인은 남아 있다.

- 투아림: 원 장식·오른쪽 버튼의 BGR 마스크 템플릿으로 위치를 찾는다. 내부 숫자와
  퍼센트 판독 성공을 검출 조건으로 쓰지 않는다. `100%`가 들어갈 숫자 영역만 저장한다.
- 단축바: 원본 두 줄의 페이지 조작부를 찾고, 두 블록·두 행·세 그룹·네 셀의 격자를 검사한다.
  특정 스킬 이미지나 화면 상단 좌표로 성공을 판단하지 않는다. 한 후보만 통과할 때 제시한다.
- 전체 단축바 점선은 소스 범위 확인용이다. 미러는 기존 `slice_group()`으로 12개 그룹의
  총 48셀을 각각 자르는 방식 그대로이며 통째 복제하거나 그룹을 재배치하지 않는다.
- 승인 전에는 저장하지 않는다. 중복 실행을 막고 탭 타이머를 잠시 멈추며 확인 후 복원한다.
  종료 중에는 적용/타이머 재시작을 차단한다. 확인 점선은 응답까지 유지하고 종료 후 닫아 수거한다.
- 투아림 영역 변경은 이전 raw/stable 값과 연속 판독 증거를 비우되 이미 발화한 기준은 보존한다.
  사용 여부·임계값·소리 설정은 바꾸지 않는다. 단축바 저장은 `anchor` 필드만 갱신한다.
- 점선은 가상 데스크톱 전체를 덮어 음수 좌표도 표시한다. 저장 좌표는 기존 물리→논리
  변환을 재사용한다. 단축바의 논리 소스 크기가 1168x89와 1px 넘게 다르면 적용하지 않는다.
- 두 검출기와 필수 자산을 공통 진단/ZIP 재실행에 등록했다. 검출 결과와 적용/취소는 별도로 기록한다.

### 앵커와 검증 좌표

템플릿/마스크는 `scripts/build_autofind_anchors.py`로 첫 기준 PNG에서 생성한다.
런타임은 화면 전체를 검색하며 아래 절대 좌표를 사용자의 위치로 하드코딩하지 않는다.
검색은 긴 변 1280px 이하의 거친 입력에서 시작하고 원본 해상도로 재정렬한다.
마스크 CCORR_NORMED 후보 탐색 0.90, 원본 재정렬 채택 0.97을 사용한다.
검색 배율은 0.75/1/1.25/1.5/2이며 모든 배율의 실제 지원을 의미하지 않는다.
단축바는 48셀의 경계 점유율을 기록하고 각 그룹 평균 0.60·전체 평균 0.80 미만은 거절한다.

| 실제 기준 자료 | 물리 크기 | 투아림 결과 `(x,y,w,h)` | 단축바 결과 `(x,y,w,h)` |
|---|---|---|---|
| `스크린샷 2026-10-10 190116.png` | 2560x1440 | `(742,920,42,16)` | `(2,12,1168,89)` |
| `스크린샷 2026-10-12 200511.png` | 2556x1436 | `(965,974,42,16)` | `(0,10,1168,89)` |

원본 두 자료에 서로 다른 내부 숫자·7%/100%·중앙 미러·추가 단축바·빈 슬롯이 있다.
실제 Windows DPI와 작게 보기 설정은 PNG에서 확정할 수 없어 미확인으로 기록한다.
검출 오차는 위 기준 좌표와 일치했고, 합성 150% 입력은 반올림 차이 1px 이내였다.
그 밖의 경계 오차를 일반화하지 않는다. 48셀의 QPixmap 픽셀을 원본 대응 영역과 비교한다.

### 투아림 판독 범위 구분

사용자 검토 중 기존 판독기의 두 자리 처리와 넓은 입력 영역의 위험을 확인했다.
초기 60x20 후보는 두 기준 화면을 모두 `1`로 오독했다. 숫자/% 주변의 여백을 줄인
42x16으로 보정해 기준 7%는 `7`, 100%는 `None`(판독 보류)임을 확인했다.
100%의 밝기 배율 0.6/0.8/1/1.1/1.2/1.4에서도 `None`이었다. 이를 저값으로 반복 전달해
거짓 재무장하지 않는다. 기존 90/95/98/99 글자를 새 격자에 배치한 합성 입력도 비교한다.

**기존 일·십의 자리 판독기를 세 자리 판독기로 바꾸지 않았다.** 100%를 정확히 읽거나
모든 전투 이펙트에서 오독하지 않는다고 주장하지 않는다. 숫자를 모두 포함하는 위치 검출과
게이지가 차는 동안의 판독 신뢰도는 다른 검증이며 실제 게이지·음성은 후속 라이브 확인 대상이다.

### 제약과 재검증

- 4K 보조 자료의 초기 비교에서 `2026-10-11_111640.png`의 투아림만 검출됐고
  단축바는 미발견, `2026-10-11_123333.png`는 둘 다 미발견이었다. 후속 환경 지원 완료로 표시하지 않는다.

  혼합 DPI 저장/실제 판독·복제 위치가 검증됐다고 하지 않는다.
- Windows 실게임 캡처·전체화면·사용자의 현재 모드·12그룹 출력·반복 음성의 실제 확인은 남아 있다.
